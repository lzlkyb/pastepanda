远程电脑设置区 · 分组折叠（方案甲）

设计稿基线：真实组件源码 RcSection.tsx(307 行) / RcAllowPanel.tsx(265 行) / RcSettings.module.css / Settings.module.css。左栏是现状忠实复刻，右栏是拟改后；两栏同为 550px 主窗、同一套卡片 CSS。页脚自动量高，不靠估。

主题（<link> 的是真 theme.css，换档＝整页跟着换，和真 app 同一批变量）：
本稿要解决的三件事，按重要性排：
  1. 一行只剩 72–96px 放控件，平铺档位装不下。（这组数字是 link 真样式之后现场量的，不是推算）主窗 550 → 右栏滚动容器 .settingsContent 实测 420px 宽 → .sRow 扣左右内边距 32 ＝ 388 → 彩砖 40 ＋ 间隙 12 → label/desc 实占 189–213 → 右控件列（.sRow > :last-child，min-width:72）只剩 72–96px。而画质档表 RC_QUALITIES 有 11 个档（能力门控后可见 6–9 个），现状那排满宽 rcChoiceBtn 折在 349px 的面板里实测 3 行（页脚 JS 数的是真 getBoundingClientRect().top），「画面范围」4 档刚好 1 行。结论：≥5 档的选项在设置页只能是「当前值 + 菜单」，2 档才配平铺。
  2. 现在这块搜索搜不动。lanPanel 整块是右栅容器的一个 child，而 rowLabel() 只认 .sRowLabel、highlightSearchKw() 只标 .sRowLabel/.sRowDesc ⇒ 搜「固定密码」会显示「命中 1 项」但没有任何底纹，scrollIntoView 只滚到整块顶部。改成真 .sRow 行即可一并修好（右栏的搜索框可以真打字试）。
  3. 体量。现状整块 2701px ≈ 4.4 屏（视口 620）、42 个可点元素、首屏只露出 4 个：8 个组标题 + 10 段 11–12px 说明文 + 6 个满宽按钮 + 最多 20 行会话记录，全在一层里。折叠只解决"看不见"，减法才解决"一次要处理多少决策"——所以本稿是 丙(减法) 打底 + 甲(折叠) 收口。
    改口径要更正一句：减法省的是决策数（可点元素 42→25、首屏可见 4→7），省高度主要不靠它——行式布局本身只少 6%（排版税被"说明文下沉 + 满宽按钮缩小"抵掉了，见 §2 末行）；−75% 全是折叠给的（2701→669px）。上一版稿子写「行式反而 +21%」是手抄 CSS 抄出来的假数，link 真样式后翻案，详见 §5 ⑦。

§3 结构映射（现状 → 拟改，一行不漏）

现状那块去哪了取舍理由
主开关 ToggleRow 允许被远程协助原样，仍是整块第一行、永远在折叠之外开关是这块的入口；收进组里会变成"找不到总闸"。它的三行 detail 里「会话制 / 不做 shell」两句是安全告知，保留在 ? 的 detail 里但措辞一字不改。
rcFpLine（3 行说明 + 指纹）指纹值上提到组 1 的摘要行（指纹 7F2C·A91B）；两句说明拆给两行的 ?「与知识库同步配对分开」「发起远程不需要打开开关」是答疑不是操作，不该占 3 行常驻高度。
按钮「＋远程配对设备」组 1 · 行「远程配对设备」右列小按钮「配对」满宽按钮 → 行内按钮，宽度从 389px 降到 ~52px；文案「配对」在行标题里已经出现过一次，右列不用重复整句。
rcJoinBlock 一次性帮助（标题+credTag+hint+2 按钮）组 1 · 一行两钮；credTag 徽标不进设置行，语义由行标题＋desc 承担credTag 是为工作台大卡设计的（带色点的一整枚 chip），右控件列实测只有 72–96px，塞进去要么截字要么把按钮挤没。语义色在弹层里照样有。"用完默认保留配对"这句隐私相关，挪进行标题的 ? 与 SETTING_ALIASES，不删。
rcJoinBlock 无人值守码（含"生效中"状态行 + 撤销全部）组 2 · 「限时接入码」一行：状态并进 desc 与组头摘要，「撤销」按钮常驻右列撤销入口不能因为收起就消失——摘要显示「2 个生效中」的同时给按钮，规则 15.1「反馈与触发同可见性域」。
rcJoinBlock「我有对方的无人值守码」组 2 · 一行 + 「粘贴连接」—
rcJoinBlock 固定密码（含 🟢 状态行 + 立即关闭）组 2 · 一行：状态写进 desc「当前：可控 · 仅限局域网」，右列「修改 / 关闭」安全态必须在收起态也看得见，所以同时进组头摘要。
joins 待确认列表（条件渲染）组 1 · 一行「待确认请求」，有请求时自动展开组 1这是唯一"会过期、要点头"的被动入口，静默收起来等于漏单。计数也进组头摘要。
RcAllowPanel 能力上限 / 画质档 / 画面范围组 3 三行，档位控件按档数分流：2 档用 .sSegGroup（现有），≥3 档用「当前值 ▾」菜单菜单项直接吃 lib/rcQuality 的 label + meta（4K · 60fps），与工作台同源；auto 的 solo 标志在菜单里占整行 + 分隔线——这套语义现成，只是设置页此前没用。
RcAllowPanel「设备级限制」设备列表（禁止 / 免确认）搬到组 1：它是逐台的属性，跟"谁能连进来"是同一件事；行「已配对设备」点开现状把它留在 RcAllowPanel，与设备列表隔了两块面板，改一台的免确认要上下滚着找。
rcSubTitle 最近会话 + RcSessionHistory compact 最多 20 行组 4：默认 3 行 + 「展开全部 20 条」；收起态只有摘要一行compact 变体现在把 source.list 整份渲染（RC_HISTORY_MAX=20），是单块最大的体量来源。给组件加一个 limit prop，工作台 page 变体不受影响。
rcErrLine（rc.error）不折叠：紧跟主开关行下方常驻规则 15.3：失败路径不能藏进收起的组里。
RcPairLayer（弹层）不折叠：留在 RcSection 顶层规则 15.2：组收起会卸载 children，弹层必须挂在不会被卸载的层级。

§4 四种状态（都是要实现的，不是画着好看）

状态表现判据
默认只展开「谁能连进来」，其余 3 组收起只见摘要localStorage 记忆上次开合；首次进 = 这套默认
搜索中四组全展开，命中行加底纹 + 左侧色条，不命中的行整块隐藏（现状就是这样，不是新行为），滚到第一条命中filter 非空即强制展开（open = 用户态 || filter !== ""）；退出搜索回到用户态——右栏实测搜完清空后开合＝g1:开, g2/g3/g4:关。GeneralTab 已持有 search，透传一层 prop 即可。
🔴 但要动 hook 一行：hook 第二遍用 textContent 当节名（useSettingsSearch.ts:159），组头的 textContent 含摘要数字 ⇒ 横幅会变成「分布在『谁能连进来已配对3 · 待确认1…』」。改法：组头带 data-label="谁能连进来"，hook 取 el.dataset.label || textContent；兜底不能省（本稿第一版就是这么漏掉「搜『远程电脑』时整节展开」的）。导航那边 findNavEl 用全等，组头带摘要也抢不走落点，不用动。
搜索的两处已知限制（现状同款，本轮不修）① 搜「远程电脑」这类小节名：本节会展开但横幅写「没有匹配项」——因为 hits 只数 direct，sectionHit 撑开的行不计（实测：shown=1 · 没有匹配项）。② 搜「办公室台式机」：命中 2 项、零底纹，因为命中的是设备子表与会话记录两块续面板，而 highlightSearchKw() 只往 .sRowLabel/.sRowDesc 注 <mark>。同族的还有一条：设备子表有自己的开合位，搜索强展组时它仍收（右栏实测搜「免确认」= 命中 2 项、可见 1 行），所以「已配对设备」这一行入口必须在搜索态可见可点，别跟着摘要一起藏。右栏可直接复现（搜这两个词各看一眼）。修法要么动 hook 的选择器、要么给设备名/会话行套 .sRowLabel 语义，都会牵别的分区，所以单独立项，不混进这次折叠。
主开关关四个组头 + 摘要照常可见、不可点（.rcGated 的 pointer-events:none + .rcPanelOff 的 opacity:.55）沿用现有两个类；不再需要 lanPanel 外壳承载变灰
从托盘/浮条跳进来openSettingsTab("general","rc") 仍滚到「远程电脑」小节标题；组开合不改锚点匹配的是 .sSection 文字，而且是 === label 全等 ⇒ 组头（名字 + 摘要）永远抢不走落点，小节标题也必须在容器直接子节点层。SETTINGS_SUBSECTIONS 的 rc 条目不用动。

§5 拍板记录（2026-09-30 全部按默认通过，照 §3 落地）

  • ① 搜索时强制展开全部组，而不是"只展开命中的那个组"。✅ 已拍：强制全展开 理由：命中判定在 DOM 里做，逐组判要不要开会和 hook 打架；全展开的代价只在搜索期间。未采用：只展开命中组
  • ② 组头摘要只在收起态显示。✅ 已拍：收起显示、展开隐藏 展开时组里每行都写着现状，摘要是重复信息；收起时它是"一眼看清现状"的唯一来源，所以安全类计数（生效码 / 固定密码 / 待确认）必须进摘要，不能只写在被藏起来的行里。附带好处：展开的组头退回成"▾ + 名字"，和设置页其它分区标题一个长相。
  • ③ 画质 / 画面范围 换成「当前值 ▾」菜单。✅ 已拍：换 这是右控件列 72–96px 约束下的唯一解（11 档平铺实测 3 行）。未采用：保留按钮组、折成多行——那条只适合 2–3 档，本稿的「能力上限」就还在用它。
  • ④ 最近会话展开后默认给几条？✅ 已拍：3 条 + 展开全部 再连按钮在这 3 条里必须可见（高频路径）。

§6 实施要点与守卫（写下来是为了落地时不返工）

  • DOM 约束（最容易踩）：折叠组不能用 <details> 或 wrapper div 装行——.settingsSections 的 children 必须是「标题 + 行」一层扁平（useSettingsSearch 的遍历前提，settingsSectionsFlatTree.test.tsx 钉着）。做法：组头是带 .sSection 类的可点 div，行是该组件返回 <></> 片段里的兄弟节点，收起时不渲染那些行（同 AiSection 的「折叠即不挂载」范式）。这也顺带把现状 lanPanel 外壳干掉，§2 表里那行搜索缺陷一并修好。
  • 卡片闭合不用新写一行 CSS——但要知道它是谁干的：本稿实测四条既有规则自动接住：.sRow:has(+ .sSection)（组头跟在某行后面 ⇒ 上一行补下圆角＋阴影，收起态的接缝就是这么闭合的）、.sSection ~ .lanPanel:has(+ .sSection) 与 .settingsSections > .lanPanel:last-child（设备子表 / 会话记录两块续面板）、.settingsSections > *:last-child:not(.lanPanel)。所以收起的面板必须整个不渲染或 hidden——CSS 里没有「最后一个可见子节点」这种选择器，用 display:none 之外的方式藏（例如只藏内容留外壳）就会露出一个方角。
    🔴 hidden 属性单独用没效果：UA 的 [hidden]{display:none} 优先级低于作者的 .sRow{display:flex}，本稿靠显式补一条 .sRow[hidden]{display:none} 才隐得掉；落地走「不渲染」就没这个坑。
  • 收起不渲染 ⇒ 三件事要跟着上提：弹层 RcPairLayer 留在顶层（已经是了）；设备子表的展开态提到组组件（不能存在会被卸载的行里）；RcAllowPanel 里 rcListMonitors/rcEncodeCaps 的读取提到不受折叠影响的位置——否则每次展开组都重读一次本机能力。另外「待确认请求 ≥1 ⇒ 自动展开组 1」这条只能在父级编排层做：组 1 收起时它自己的 join 列表根本不在 DOM 里，自己判不了。
