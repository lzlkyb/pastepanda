顶栏三模式 + 名位复用

设计稿 v1.0 · 2026-08-31 · 对应规划 v3.7 / D15 / §9 #13（作废 §9 #3 #5 #7）｜ 尺寸与层级对齐真实代码：TopBar.tsx / TopBar.module.css

本稿只管顶栏。 知识库内部的弹窗与视图在 kb-a-note-dialog.html / kb-b-library-view.html， 那两张是「知识模式里面长什么样」，本稿是「怎么切到那个模式」——不是同一层，故另立一张。

1. 三处改动

改动内容为什么
① 应用名缩小 .headerTitleText 从 15px / 700 降到 12px（字重不变） 腾宽度给模式切换器。480px 窗宽下这一行本来就紧
② 三模式切换器 记录 ｜ 工具 ｜ 知识（纯文字、无图标），放在应用名右侧 页签是「筛选同一批内容」，模式是「切换不同的东西」。 把知识库当筛选项从一开始就是语义错位
③ 版本徽章名位复用 平时显应用名；有新版 / 下载中 / 待重启时接管同一个位置；重启后名字回来 首页干净了，而且省下的宽度正好给模式切换器——一个位置两个占用者
⚙ 为什么不能直接删掉版本号（这是本稿最重要的一条）
顶栏那个 v6.18.5 不是纯显示，它是 UpdateBadge（TopBar.tsx:195）—— 更新链路的唯一主动入口：有新版可点击下载、下载进度环、就绪后的重启按钮。
直接删 = 用户再也收不到更新提醒。而这与规划 §10 已登记的 Gitee 镜像跨境上行风险（镜像失败会让国内用户静默看不到新版）叠起来，就是真的发不出去。

不接管名位的三种情况

状态名位显示为什么不接管
checking 检查中应用名 用户没有发起这件事，也没有可做的动作——闪一下又消失只是噪音
error 检查失败应用名 同上。失败信息归设置页，不占首页最显眼的位置
uptodate 已是最新应用名 原实现会显示 4 秒后自动消失——名位不承担这种瞬时反馈，改由 toast 或设置页承担
「未读更新说明红点」不进名位（已定）
曾考虑让它也占名位（「看完说明名字才回来」），否决。理由不是口味，是它与现有入口重复：
  • 设置页「关于」tab 已经有独立的未读红点（SettingsDialog.tsx:52-56 hasUnseenEntries，打开即自动标记已读）；
  • UpdateNotesDialog 在有新版时本来就会自动弹（App.tsx:1159）。
再占一个名位是同一件事的第三个入口。删掉后副作用正好是想要的：重启后名字立刻回来。

切换动画

两个占用者用淡入淡出交接，不能硬跳——否则应用名突然变成一个绿色胶囊会像界面出错。
UpdateBadge 已经在用 AnimatePresence + key 做状态切换，直接把应用名也当成其中一个 key 即可，不用新建机制。
建议：opacity + 小幅 y 位移，150ms，与现有 tab 切换动画同参数。
宽度核对（480px 下真实需要关心的事）
“PastePanda” @12px 约 70px；“🔄 v6.18.6” 胶囊约 78px；“◔ 45% · 1.2MB/s” 约 108px（最宽）。 名位按最宽态预留空间，避免下载开始时模式切换器被顶得跳一下。

4. 三个模式各自的主体区

模式主体区工作量
记录 就是现在的主界面：☰ 侧边栏（分组/智能分类/来源）+ 搜索 + 5 页签 + 卡片列表。默认模式 零 只是被包起来，一行布局不改
工具 现有 TOOLBOX_GROUPS（2 组 9 个工具）从下拉面板变成主体区 真实工作量 不是挪位置，是重做布局
知识 A 阶段：待沉淀区 + 笔记列表；B1：填入文件夹树 + 标签双维度 本规划主体（详见 kb-a / kb-b）

5. 480px 宽度压力测试

定稿形态：纯文字二字名，约 138px。下载显示（含速率）完整保留。

模式切换器形态宽度结果（含完整下载显示）
图标 + 三字名~200px❌ 常态就溢出
图标 + 二字名~170px❌ 下载态溢出
纯文字三字名~162px❌ 下载态溢出（约 457px）
纯文字二字名（定稿）~138px✅ 常态与下载态都装得下
二字名是这一轮的关键。 它同时满足了两个硬约束： 三个名字全显（不用下拉、不用 tooltip、不用首次引导）与 下载显示完整保留（含 · 1.2MB/s）。三字名只能二选一。
为什么第一个叫「记录」而不是「剪贴」或「主页」
· 剪贴——中文里不单用（说「剪贴板」），单独成词生硬；
· 主页——是位置词，而「工具」「知识」是内容域，三个标签不同维度， 会让人误以为「主页」是概览页、另两个是子功能；
· 历史——自然但有归档/过去式暗示，而它其实是用户每天干活的地方；
· 全部——❌ 硬冲突：页签第一个就叫「全部」（TopBar.tsx:20）。
「记录」中性、自然、无归档感，且与「工具」「知识」同为二字名词域——三个念一遍很齐。
① 常态 — 应用名 + 三个模式，占约 395 / 448px
🐼 PastePandaAI 记录工具知识 ⬒⚙ ─👁

富余约 53px。三个名字直接写出来，不需要 tooltip 也不需要首次引导——这就是去掉图标换来的。

② 下载中（名位最宽态 108px） — 占约 433 / 448px
🐼 45% · 1.2MB/s 记录工具知识 ⬒⚙ ─👁

紧但装得下。名位要按这个最宽态预留空间，否则下载一开始模式切换器会被顶得跳一下。

③ 最坏情况：下载中 + 未配置 AI（AiStatusCap 在场） — 约 493 / 448px
🐼 45% · 1.2MB/s 记录工具知识 ✦ 配置 AI ⬒⚙ ─👁

这一行溢出了（看右边被截掉的窗口按钮）。未配置 AI 时 AiStatusCap 胶囊会占约 60px， 叠上下载中的名位最宽态，480px 不够。这是本方案剩下的唯一真风险。

③ 这个溢出的解法：下载中暂时隐藏 AiStatusCap
它是一个引导型元素（未配置 AI 时才出现，意在拉用户去配），而下载更新是一个正在发生的、有时限的过程。 两者撞上时让引导让位是对的——用户此刻注意力在更新上，配 AI 可以等下载完。 下载结束后胶囊自动回来，用户什么都没少。

⚠ 这是本稿建议的解法，但 493px 这个数字是估算值——开工时先拿真实组件量一遍这个组合， 确认真的溢出再做；若实测不溢出，这条就不用做。
为什么模式切换器不用图标（不只是省宽度）
核对真实代码后发现两个图标冲突：
  • 📋 已被「全部」页签占用（TopBar.tsx:20）——记录模式也用 📋 的话， 同一屏会出现两个 📋（一个在模式行、一个在页签行）；
  • 📝 已被「文本」页签与「片段库」占用（TopBar.tsx:21,47）——知识模式用不了。
纯文字同时解掉了宽度和图标冲突两个问题。

6. 行为细则

场景行为理由 / 注意
默认模式记录 它是产品本体；用户为了剪贴板每天打开几十次
模式记忆记住上次模式（写 localStorage） 与现有 tabStyle 同一做法。例外：热键唤出弹窗强制回剪贴板—— 那个场景用户要的一定是剪贴板
切换热键Ctrl+1 / 2 / 3 开工前先 grep 确认不与现有快捷键冲突
搜索框每个模式独立搜索域，切换时清空 对应规划 §7 L1「搜索按模式隔离」。「工具」模式 A 阶段不给搜索框
☰ 侧边栏仅「记录」模式可用，其余两个置灰 它是「记录」模式内容的分组导航，不是全局导航——这也是否决左侧竖栏方案的原因
「知识」角标待沉淀区有候选时显小圆点 沿用「永不打扰」闸门：不弹 toast、不报数字
右侧工具箱图标撤销 否则一个功能两个入口，而且两者形态不一样（下拉 vs 主体区）
栈模式 / 设置 / 窗口按钮三个模式下均常驻 它们是全局的，不属于任何一个模式
AiStatusCap仅未配置 AI 时出现（不变） 但它与模式切换器可能同时在场——480px 下要实测不溢出
开工前必验的一个真实风险（本稿画不出来）
未配置 AI 时，AiStatusCap 胶囊会出现在右侧图标区。 这时候如果同时在下载更新（名位最宽态 108px）+ 模式切换器（96px），480px 可能不够。 实现时拿真实组件跑一遍这个组合，别信本稿的估算值。

对应规划 §8.1 的 0️⃣ 顶栏改造与三模式框架。它与 1️⃣（抽 MarkdownEditorCore）相互独立、可并行—— 本项决定笔记 UI 挂在哪里，1️⃣ 决定笔记怎么编辑。

8. 不做清单

不做为什么
模式占独立一行（两层导航） 层级最清晰、能带文字标签，但顶栏从三行变四行，480px 下直接砍掉约 36px 列表可视高度——「记录」模式的主体就是那个列表
左侧竖排 Activity Bar 不占垂直空间，但会与现有 ☰ 侧边栏并排成两条竖栏，480px 下内容区只剩约 340px； 而且那条侧边栏是「记录」模式内部的导航，与全局模式并排会让两个层级看起来平级
版本徽章整个移进设置页 最干净，但更新提醒失去主动性。与规划 §10 已登记的 Gitee 镜像风险叠加，两层叠起来就是真的发不出去
未读说明红点占名位 与设置页「关于」tab 的红点 + 自动弹窗重复，是同一件事的第三个入口
「工具」模式加搜索 / 收藏 / 新工具 A 阶段只做最小搬运。它与知识库无关却被拉进 M1，再加治理就会拖住主线
模式改下拉菜单 切换从一次点击变两次，而模式只有三个——得不偿失
第四个模式 三个是上限。第四个就得重新评估布局（可能真得走竖栏）

9. 验收口径

  • 三个模式可切换，切换后主体区、搜索行、页签行、侧边栏可用性均正确；
  • 480px 窗宽不溢出（含本稿第 5 节那个最坏组合：下载中 + AiStatusCap 同时在场）；
  • 名位复用五个状态都对，且 checking/error/uptodate 不接管；
  • 有新版时能从名位直接点击下载，下载完能重启，重启后名字立刻回来；
  • 切换为淡入淡出，不硬跳；
  • 三个主题（Ocean / Midnight / Forest）下均无对比度问题。
本稿与其他两张的关系
topbar-modes（本稿）= 怎么切到「知识」模式 · 全局导航层
kb-a-note-dialog = 卡片转笔记的弹窗 · 知识库内部
kb-b-library-view = B1 知识库三栏视图 · 知识库内部
后两张里出现的「笔记页签」字样已被本稿作废，它们下次更新时需跟着改成「知识」模式。
