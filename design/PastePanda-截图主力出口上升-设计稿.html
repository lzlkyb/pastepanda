一、现状与两个硬 bug

「⋯」是工具栏 17 个按钮里唯一没有中文标签的，而“更多”这个词零语义。它后面藏了 9 个出口，至少 4 个是产品主力。

bug ① result 态键盘完全无响应。onKey 只有 p === "select" 与 p === "annotate" 两个分支，没有 result 分支。所以出口面板上印着的 Ctrl+C / Ctrl+S / Ctrl+Enter 三个快捷键全都不存在—— 界面写着快捷键，按了什么都不发生（规则 15.3）。

bug ② saveToGallery / pinImage 开头都是 if (!resultPath) return。 标注态 resultPath 是 null（它由 ensureResultPath() 在 finish/copyImage 里才生成）， 所以这两个函数直接搬到工具栏会静默无反应——就是之前那一整轮“点了没反应”的同一个坑。

四、三个新按钮的行为（关键：不能静默）

三个出口都需要已落盘的结果图，而标注态 resultPath 是 null。所以每个都走同一套：

setBusy(true)                    ← 整条栏变淡且不接点击
  → await ensureResultPath()     ← 幂等，已有则直接返回
  → 实际动作（存盘 / 开贴图窗 / 开 AI 面板）
catch → showToast("保存失败：" + errText(e))
finally → setBusy(false)
按钮成功后失败时
保存弹另存对话框 → toast “已保存”→ 关窗toast 报错，窗不关（否则提示没地方显示）
贴图等贴图窗真的开起来再关本窗toast 报错，窗不关
AI进 result 态并直接开 AI 面板toast 报错，停在标注态

绝不能写成if (!resultPath) return ——那就是把旧 bug 搬到了工具栏上，且更显眼。

六、补齐 result 态键盘分支

面板上印着的快捷键必须真存在，否则就是写了一个假承诺（规则 15.3）：

按键行为备注
Ctrl+C / Enter复制图片并关窗面板已印 Ctrl+C，Enter 与标注态保持一致
Ctrl+S保存到图库面板已印
Ctrl+Enter插入到当前文档仅 editorTarget 非空时生效（与行的可见条件一致）
Esc退回标注态规则 17.6 两级取消：先退一步，再按才关窗
Ctrl+R展开/收起文字面板已有，不变

注意新分支要复用 copyImageRef 这类 ref，不能直接调闭包里的函数——这个 effect 的依赖盖不全 busy/resultPath，拿到的会是陈旧值（annotate 态的 Enter 已经踩过这个坑并用 ref 解了）。
