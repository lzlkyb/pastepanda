知识库 MCP 服务 · 设置面板 设计稿

把用户的笔记以 MCP 工具的形式只读开放给 Claude Code 这类客户端。 默认关闭，只绑 127.0.0.1，默认端口 17650。

本稿的骨架不是新发明的。它和设置页里的「局域网同步」是同一套： sSection 标题 → 一行 ToggleRow → 开了才展开一张 lanPanel 同款卡片。 用户已经在上一节学会的东西，这一节不该让他再学一遍。

1 · 放在哪里

插在「局域网同步」之后、「快捷键」之前。设置页现有分节顺序是： 数据统计 → 外观 → 通用 → 局域网同步 → 快捷键 → 数据管理。

理由：局域网同步和 MCP 是这个页面上仅有的两个「把本机数据交出去」的功能。 挨在一起，用户才建立得起「这一片是对外暴露，要小心」的心智； 塞进「数据管理」会和导入导出混成一堆本地操作，风险感被稀释。

2 · 关态（默认）—— 只有一行

没开的时候不展开任何东西，和局域网同步一致。这一行的 desc 必须同时说清「什么」和「边界」，因为大多数用户不会点开就再也见不到别的文案。

4.1 状态行

圆点跟随真实状态，绝不恒亮——这是 LanSyncPanel 已经修过一次的坑 （原来无设备时也亮绿，注释里写着「不再恒亮假绿」）。三态：

状态圆点文案由什么决定
运行中绿 + 呼吸运行中 · 端口 17650status.running === true
已停止灰 · 不动已停止开关关（面板此时根本不渲染，仅在切换瞬间可见）
启动失败橙 + 呼吸未能启动 · 端口 17650 可能被占用开关为开但 running === false，或收到 mcp-start-failed

「刷新」按钮用 .lanRefreshBtn 同款。轮询频率照局域网那节的 5s， 且必须照抄它的 useWindowVisible 门控——窗口 hide() 后 WebView 还活着，不停轮询就是白烧 CPU （LanSyncPanel 里那段注释直接引用了规则 8）。

4.2 令牌

  • 默认遮蔽，固定 42 个 •。不按真实长度渲染圆点——长度本身也是信息。
  • 「显示 / 隐藏」是瞬时切换，不做倒计时自动隐藏：设置页是用户主动打开的，倒计时只会让人复制到一半失效。
  • 令牌不进 mcp_get_status（后端已经这么设计了，很好）。前端也别缓存：点「显示」或「复制」时才现调 mcp_get_token。
  • 「复制」用全项目唯一出口 copyToClipboard()（lib/utils.ts）。见下方红框，这里有个真问题。
❗ 复制令牌会被 PastePanda 自己记进剪贴板历史。
本产品是剪贴板管理器，监听器不区分「谁复制的」。用户点一下「复制令牌」，那 43 个字符就会 变成一条剪贴板历史，出现在主界面的时间线里、参与搜索、并且——如果他开了局域网同步—— 被同步到局域网内的其他设备。

appStore.ts 里确实有 skip_sensitive（「不记录匹配密钥/凭证模式的内容」）， 但我没有验证过 43 字符的 base64 串会不会命中那套模式，而且它是一个用户可关的开关—— 把令牌的安全性挂在一个用户可能关掉的偏好上，不成立。

需要一个「复制但不记录」的路径（后端复制前打一个抑制标记，或把这一次的哈希加进忽略集）。 这是待拍板 ②，且它不只影响这个面板——AI 页的 API Key、局域网配对密钥大概率是同一个洞。

5 · 启动失败必须看得见

端口被占是最常见的失败，而且服务不会自动换端口——所以失败绝不能只是一个转瞬即逝的 toast。 设计上做两层：

  1. 瞬时：收到 mcp-start-failed 事件时弹一次 error toast（payload 原样带上）。
  2. 常驻：面板顶部挂一条橙色横幅，只要还没成功启动就一直在。用户切走再回来照样看得见。

并且开关停在「开」不弹回——用户的意图确实是「我要开」，弹回去会让他以为自己没点上， 然后再点一次，再失败一次。开关表达意图，横幅表达现实。

9 · 待拍板（需要你或用户定）

#问题我的倾向
①首次开启的确认弹窗，「本机上任何持有令牌的程序都能读你的全部笔记」这句要不要视觉加重？ 加重就得新写一个弹窗组件（confirmDialog 只吃纯字符串）。要。这是整个功能唯一的风险点，纯文本会被划过去。新组件成本不到 80 行。
②复制令牌会被自己记进剪贴板历史（甚至经局域网同步到别的设备）。要不要这一轮就做「复制但不记录」？要，而且它比这个面板更重要。同一个洞大概率也在 AI 页的 API Key 和局域网配对密钥上。 如果这轮不做，面板里至少要加一句明写的警告。
③端口 setter 命令（mcp_set_port）谁来加？现有 4 个命令改不了端口，而需求 #5 要求端口可配置。你正在改 src-tauri，顺手加最省事。本稿按「会有」画。
④令牌以什么方式送给服务端——Authorization: Bearer 头，还是别的？引导里的命令行/JSON 必须与后端实际实现一致。需要你给准信。我按 Bearer 头画的，但那是猜的，没有验证。
⑤开关状态要不要持久化？重启 PastePanda 后 MCP 服务是自动起来，还是回到关？倾向持久化（重启后自动起）——不然用户每次开机都要来点一次，接入配置形同虚设。 但这意味着「开一次 = 长期开着」，确认弹窗的文案就得说清这一点（现在的版本没说）。
⑥要不要显示「当前有 N 个客户端连着」/ 最近一次访问时间？很想要，但这轮不做。后端 McpStatus 现在没有这个字段。 它是「本机上任何程序都能连」这句话的唯一事后验证手段——用户要能看出「除了我配的那个，还有别的东西在读我笔记」。 建议记进下一轮。

10 · 明确不做

  • 不做局域网暴露开关。只绑 127.0.0.1，不给「允许局域网访问」的选项——那是完全另一个量级的风险， 真要做得单独设计，不能当一个复选框塞进来。
  • 不做写入能力的开关。全部只读是这个功能的承诺，不给它留一个「高级」入口。
  • 不做剪贴板历史的开放。范围就是笔记，声明里写死。
  • 不做二维码 / 配对码。局域网同步那套是给多设备用的，这里只有本机，复制粘贴就够了。
