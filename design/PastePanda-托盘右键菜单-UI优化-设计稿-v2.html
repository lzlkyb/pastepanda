托盘右键菜单 · UI 优化建议 + 设计稿 v2

右键托盘打开的是自绘弹层（tray-popup 窗口 → popup.html → TrayPopup.tsx）， 不是 Win32 原生菜单 —— 所以 UI 完全可改，没有系统控件天花板。本稿与今天 11:53 那版共用同一套结论方向， 增量在三处：① 补上「设计稿画不出、但真实渲染会走样」的三个问题（圆角 / 阴影 / 高度溢出）； ② 找到一份死代码与它带来的双份菜单定义；③ 把单一方案扩成 A / B / C 三档供拍板。

结论先行：推荐 方案 A（信息压缩型）。理由不是审美，是高度账 —— 现状内容实测 593px， 而 Rust 给弹窗定位用的是 470px，这个差值让弹层底部约 100px 溢出到任务栏下面（详见 §2）。 方案 A 把内容压到实测 449px，落回定位预算以内，顺手把溢出问题一起修掉。 方案 B 更快（383px）但砍掉统计；方案 C 最保守（516px）但不解决高度问题。 所有高度都是 headless 按 280px 宽真实渲染量出来的，不是估的。

§2 · 设计稿画不出来的三件事（本版增量 · 按优先级排）

这三条不是审美问题，是「稿子画成 A、落地渲染成 B」的根因。不先修，任何视觉稿都只能停留在稿子上。

① 高度账对不上：内容实测 593px，定位按 470px 算 → 底部被任务栏吃掉 P0

位置代码事实
弹窗定位尺寸tray_manager.rs:317popup_h = 470.0，calc_popup_position() 用它算 y，并钳制到工作区
窗口真实高度TrayPopup.tsx:489–505渲染后 setSize(LogicalSize(innerWidth, root.scrollHeight))，把高度撑到内容高
两条路径的交点—setSize 之后 位置从未重算。窗口变高只会向下长，底边突破 max_y 钳制范围
后果：任务栏在底部时，窗口底边仍以 tray_y - 470 - 4 为基准，实际高度 593 → 向下多出约 123px， 减去任务栏自身高度（100% 缩放约 40–48px），仍有约 55–65px 落在任务栏之下 —— 正好是「退出」和库体积条所在的区域。
修法（两选一，建议先做 A）：
  • A · 把内容压回预算内：方案 A/B 实测降到 449 / 383px，不动一行 Rust，问题自然消失。这是推荐路径。
  • B · 让定位跟着真实内容走：前端把 root.scrollHeight 通过 invoke 回传，Rust 用真实高重算 calc_popup_position。多一次窗口移动，可能看到"先出现再跳位"。
为什么建议走 A 而不是 B：改定位时序意味着每次打开弹窗都可能"先出现在旧位置再跳一下"， 是对"快进快出"的伤害。把内容压进预算内则没有任何时序副作用 —— 而且顺带把 §4 的信息密度问题一起解决了。

② 圆角两层：DWM 切成 8px，CSS 写着 14px，中间那圈是 body 底色 P1

DWM ROUNDSMALL
≈8px（真实窗口）
CSS border-radius
14px（稿子画的）
实际叠加：
外 8px 裁掉 14px
链路：tray_manager.rs:454 设 DWMWCP_ROUNDSMALL = 2（Win11 小圆角）； popup.css:35 写 border-radius: 14px； tray_manager.rs:381 用 .shadow(false) 且 popup.css:10 给 body 铺了实色底 var(--app-bg)。
三者叠加的结果：① 窗口四角被 DWM 按 8px 切掉，CSS 的 14px 只在窗口内部生效，视觉圆角实际是 8px； ② 窗口本身是直角矩形 + shadow(false)，.tray-popup-root 向外扩散的 --glass-popover-shadow 全部落在窗口之外 → 阴影实际不可见； ③ 14px 圆角与 8px 窗口圆角之间夹着一圈 body 底色，在浅色主题下表现为「描边内缩、外面留一圈白」。
建议：把 CSS 圆角对齐到 8px（与 DWM 一致，一了百了），阴影改走 ROUNDSMALL 之外的 DWM 原生投影， 或干脆接受无阴影并用 1px 描边 + 内高光承担立体感（当前 inset 0 1px 0 已经在做这件事）。

③ 状态点是颜色唯一通道 P1 · 无障碍

TrayPopup.tsx:528 只有一个 <span className="tray-popup-status-dot" />： 无文字、无 title、无 aria-label。监听中 #11813A / 已暂停 #CCC， 整个界面判断「是否在监听」就靠这一颗 8px 圆点的颜色。色觉障碍用户看到的是两个灰度相近的点。 方案 A/B 里把它改成「点 + 文字」（监听中 / 已暂停），顺带省掉一行。
