顶栏名位微动效

2026-09-06 · UpdateBadge.tsx / app.css / UpdateBanner.module.css · 用户反馈：「名字切换要加微动画，点击更新没有任何手感」
这个组件不是装饰：UpdateBadge 是更新链路的唯一主动入口（弹窗之外用户能自己点的只有这里）。 所以这次改动的验收标准不只是「好看」，而是点下去用户知道自己点上了、并且知道结果是什么。 下面 §0 第 5 条会说明：现在点「检查更新」等于点了个空气——这比按压反馈缺失更严重。

§3 无障碍与开关（已查证，不需要新增任何东西）

「减少动态效果」已经有四通道兜底，新加的动效自动跟随，一行都不用写：
  • main.tsx:72 / editor-main.tsx:57 / popup-main.tsx:60 / quickpaste-main.tsx:59 四个入口都套了 <MotionConfig reducedMotion="user"> → framer 的位移/缩放自动关掉，只留淡入淡出
  • globals.css:66 有全局 * 兜底，把所有 animation/transition 压到 0.01ms !important → 覆盖 CSS 侧的 :active 过渡与箭头点头
🔴 不挂到「窗口动画」开关（config.window_animation）下。 那个开关自己的说明写的是「弹框与全屏窗口打开/关闭时的过渡动画」 （WindowSystemRows.tsx:33，tooltip：「玻璃浮升效果；关闭后弹框与全屏编辑器即时显隐」）。 把顶栏按压反馈塞进去 = 偷偷扩大它的语义：用户为了「别再玻璃浮升了」关掉它，结果连按钮的按压反馈一起没了， 而设置项上没有任何地方提示过这件事。按压反馈不是动画偏好，是控件的基本可用性——它跟着系统无障碍偏好走就够了。

§4 配套行为：把「点了检查更新」这件事说完（§0-5 / §0-8）

这一节不只是动效，是行为变化，所以单列。可以单独砍掉，但砍掉的话 §0-5 就还在。

问题：现在点名字 → checkForUpdate() → status 变 checking， 而 checking 按设计不接管名位，于是：
  • 名位原地不动，用户不知道点上了没有；
  • 更糟：nameClickable 在 checking 下是 false，按钮直接被换成裸 nameSlot， 连正在悬停的那个徽章都缩回成名字了——反馈是「负的」，像把提示点没了；
  • 查完不管是「已是最新」还是「查失败」，名位都一声不响。
改法：区分不是 checking 与否，而是这轮 checking 是谁发起的。 加一个组件内的 manualCheck 标记（点击时置位，status 离开 checking 时清）：
  • 后台自动轮询的 checking → 照旧不接管名位。文件头那条原则原样保留：用户什么都没做，名字不该闪。
  • 用户手点的 checking → 名位显 .header-badge-checking「检查中…」（图标转），并且不许缩回名字。
  • 查完 uptodate → 显 .header-badge-uptodate「已是最新 v6.18.6」约 1.8s 后淡回名字。
  • 查完 error → 显 .header-badge-error「检查失败，重试」约 3s（红色，可点重试）。
后两个类今天是死代码（app.css:108/140，UpdateBadge 从不渲染），这一条正好把它们用起来，不新增样式。

§5 实现要点

为何不做宽度动画。名字（PastePanda 12px/700 + AI 上标 ≈ 82px）与徽章（v6.18.6 10px mono ≈ 75px）宽度不同， 交换时会推动右边的 ModeSwitcher。看着像该给它加个平滑过渡，但不要： framer 的 layout 动画是靠 transform: scaleX 实现的，套在文字容器上会让 12px 的应用名在中间帧被横向拉伸发虚。 用 mode="popLayout" 把退场节点弹出文档流，宽度瞬变（与今天完全一致，零回归），视觉上的交换由 opacity 承担—— 眼睛跟的是透明度，不是那 7px。
实现时的修正（落地后回填）：popLayout 只用在内层。 mode="popLayout" 会把退场节点改成 position:absolute，因此它需要一个 position:relative 的直接祖先； 没有的话退场的那 130ms 里节点会去找更外层的定位祖先，徽章会飞到别处。
  • 名字 ↔ 悬停提示（最频繁、用户抱怨的那一个）→ 用 popLayout，锚点就是 .nameCheckBtn 自己（加一行 position:relative）。
  • 名字 ↔ 接管态徽章（外层）→ 保留 mode="wait"。它的父节点是 TopBar 的 .headerTitle， 要用 popLayout 就得去改别人的布局（或者在这里多包一层 wrapper）；而它的触发频率是「出了新版本」「下载完了」这种量级， 130ms 空档无人察觉。为一个一天触发不到一次的转场去动别的组件的定位，不划算。
「叠加渲染」这条路走不通。另一个思路是把名字和徽章用 grid 叠在同一格里（容器宽度 = 两者较大值 → 宽度永不变化， 本演示 ② 用的就是这招）。但那要求名字节点永久留在 DOM 里（只是 opacity 0）， 于是「悬停时名字不显示」这条断言就再也没法用 queryByText 表达了，只能去查内联样式—— 把一条行为测试降级成实现细节测试。不换。
按压加在哪available / ready 两个 motion.button 直接加 whileTap； 名字按钮 .nameCheckBtn 不是 motion 组件 → 改成 motion.button（UpdateBadge.tsx:184） 点击即刻反馈isStarting 从「只用来 disabled」升级成一个外观：图标换 Loader2 + spin-icon，文字换「启动中…」。 不等后端，点下去那一帧就变 不要动的badge-pulse 的归属（-check 变体不给呼吸，见 app.css:124 的红字）、 aria-label="检查更新" 写死、nameSlot 由 TopBar 传入的结构、未读说明红点不要加回来

§6 不做清单

  • 不加常驻动画（流光 / 常态呼吸 / 悬停翻牌）——顶栏是常驻区域，见 §1-C
  • 不新增设置开关，也不复用「窗口动画」开关——见 §3
  • 不动 UpdateBanner（设置页那个横幅）：它已经有一整套 y:±6 / 0.2s 的进出动画，且不是用户抱怨的地方
  • 不给百分比数字做补间——会出现回跳感，见 §1-③
  • 不碰 DownloadRing 的不确定态（整体旋转）：那套已经对了

§7 落地顺序

  1. 按压 + 启动中外观（§0-3、§0-4）— 用户明说的那一条，最小、独立、可单独验收
  2. 名位交叉淡入 + 接管态统一到同一套（§0-1、§0-2）— 含那条测试的改法
  3. 进度环补间 + 入场/成功脉冲（§0-6、§0-7）
  4. §4 配套行为（§0-5、§0-8）+ 两条新测试 — 这一步动的是行为，建议单独一次提交
