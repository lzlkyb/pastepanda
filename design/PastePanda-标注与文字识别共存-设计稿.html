标注与文字识别共存 · 选字模式可切换

方案 A 升级版：不切工具、零额外点击。把「智能意图(B3)」与「Ctrl 修饰键(B2)」做成设置项，默认智能意图。事件唯一入口收回标注画布，字层永不抢事件。

零步共存 智能意图（默认） Ctrl 修饰键（可选） result 态不变

一、冲突根因（为什么必须改）

标注画布 .annot-canvas 与逐字文字层 .ocr-line 同容器、都无 z-index，按 DOM 顺序 .ocr-line 盖在画布之上。且 .ocr-line 默认 pointer-events:auto、onOcrCharDown 无条件 stopPropagation。

tool 默认是 "rect" —— 所以 进标注态默认就在文字上画矩形时，mousedown 被字层吞掉，标注画不出来。本质是系统里没有「绘制 vs 选字」的区分维度。

文字 bbox（字层） 标注图形 选字橡皮筋 / 高亮

二、方案总览：事件收口到画布

把字层改成 pointer-events:none（只显示「哪有字」+ 选中高亮，永远不抢事件）。所有 mousedown 先到 onAnnotMouseDown，再按 ocrSelectMode + 落点命中测试分流。标注与选字永不抢事件。

// onAnnotMouseDown（唯一入口，annotate 态） const hit = wordAt(px, py); // rectsOverlap / 点包含，排除隐私行 if (hit && mode === "smart") startSelect(hit); // 落字内 → 起手选字 else if (hit && mode === "modifier" && e.ctrlKey) startSelect(hit); // Ctrl+字内 → 选字 else startDraw(tool); // 其余 → 画标注

三、设置页切换（持久化）

src/store/appStore.ts 新增字段，沿用 auto_frame_window 同款持久化：

ocrSelectMode: "smart" | "modifier" // 默认 "smart"

设置页新增一组单选，文案说明两种模式区别：

智能意图（默认）

落在文字上拖=选字；拖出文字框或移动超 4px 自动转画标注。最直觉，纯鼠标零步。

修饰键 (Ctrl)

按住 Ctrl + 在文字上拖=选字；裸拖一律画标注。选字手势更明确，不误触。

三·b、截图内快捷切换（工具栏末尾 toggle）

除设置页正式入口外，annotate 态工具栏右侧加一个紧凑双态 toggle，零步可达、显当前模式。状态写回 appStore，与设置页双向同步——截图内切了即全局持久化，设置页改了截图内默认即用。

智能意图 Ctrl

仅 annotate 态显示（选字共存逻辑只在标注态生效）。视觉上与绘制工具区分（分段控件而非工具图标），不污染工具语义。

七、边界与守门（必守）

  • 仅作用于 annotate 态：result 态无标注画布抢事件，保持原 ⑤「点字复制」逻辑不变，不受 ocrSelectMode 影响。
  • 默认 tool="rect" 不变：smart 下压字拖=选字（不画矩形），符合「在文字上拖就选字」直觉；压空白拖=画矩形。
  • 隐私行：两种模式都跳过选字（isRowMasked 已有逻辑保留，命中测试排除）。
  • Esc 链不变：选字中 Esc 先清 ocrSel，再 Esc 回选区态（两级取消）。
  • 字层视觉保留：pointer-events:none 不影响显示，hover/选中高亮由 ocrSel state 驱动（indigo/cyan）。

八、与微信一致性

微信截图标注时，文字识别是「独立模式 + 智能落点」。本方案把「智能意图」作为默认，且保留 Ctrl 修饰键给追求明确手势的用户——既零步共存，又给用户切换权，与微信「轻预览优先」思维（规则 18）一致：标注与选字互不影响、误触低成本（拖出即转标注 / 无 Ctrl 即画标注）、两级取消保底。
