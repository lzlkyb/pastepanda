一处顺带查明的细节：项目里没有全局 button 重置（globals.css 只有 *{margin:0;padding:0}），而 <button> 不继承 font-family —— 所以修法后的三键字体仍是浏览器默认的 Arial，字号 12px。 这与同排的全屏 / 详情 / ⋯ 键完全一致（它们本来就是 Arial 12px），不引入新的不一致。 若要把整排按钮统一到界面字体，需要补 font-family: inherit，那属于样式收口（P2-4）的范围。

实施时会带出一个坑，写在这里免得踩。 .capBtnOn 的两条声明带 !important（:1391）， 这不是随手写的：.capBtn:hover:not(:disabled) 的特异性是 (0,3,0)，高过 .capBtnOn 的 (0,1,0) —— 没有 !important， 鼠标一悬停在当前档上，蓝底就会被灰白 hover 底盖掉，选中态在指针下"消失"。
若不改 hover 规则、直接去掉 !important（不推荐）
推荐：hover 规则排除选中档 :not(.capBtnOn)

左边那颗是「选中 + 悬停」的退化形态：底色落到 rgba(255,255,255,.1)，与未选中档几乎无异，只剩白字撑着。 右边是推荐写法 —— 把规则拆成 .capBtn:hover:not(:disabled):not(.capBtnOn)，去掉两条 !important： 既解决冲突，也与 A2 那张表「禁 !important」的守卫口径一致（会话侧目前没有这条守卫）。

守卫单测：钉住这一类，不是这一个。 断言对象必须是渲染出的 className，不是源码字符串 —— 
// RcSessionCapsule 的 FIT 三键：每颗都必须落在 .capBtn 上，当前档再叠 .capBtnOn
for (const label of ["适应", "1:1", "填充"]) {
  expect(screen.getByRole("button", { name: label })).toHaveClass(styles.capBtn);
}
expect(screen.getByRole("button", { name: "1:1" })).toHaveClass(styles.capBtnOn);

价值在于：把 styles.capBtn 从 JSX 里删掉它会红；而 tsc / eslint / lint:ui / lint:css 四个工具对此全都是绿的。

P1-3 · 四处被读屏丢弃的名称

RcWindowControls:132 / RcHud:246 / RcPageFiles:69 / RcA2Sidebar:166

共同的病：aria-label 挂在 role="generic" 的 div / span 上。ARIA 规范不允许给 generic 命名， 浏览器与读屏直接忽略这个属性 —— 属性在，名字不在。左边是读屏实际播报，右边是修法后。
