远程电脑 · 全屏与画面高度 UI

实测痛点：工作台里远程画面被 chrome 压小 →「必须点全屏才能看到」；画面越小，绝对坐标映射的放大比越大，远程鼠标越「飘」。 本稿只做 UI 方案对比，不改传输（鼠标数据报 / 版本提示已另案 R3）。 仿真对齐真实组件：RcWorkbench + RcSessionView + RcSessionTop + RcSessionBar + RcViewTools + RcHud。

保留全屏按钮必须在画面区内（RcViewTools）——底栏不进全屏，放底栏会消失 保留浮现式工具条（上缘唤出 / 2.5s 淡出） 本稿画面高度 · 非全屏提示 · 底栏密度 · 顶栏瘦身

B案 B · 会话沉浸态（chrome 自动后撤）

优点

  • 画面高度最大化，接近「未点全屏也够看」
  • 身份/链路/结束与 HUD 同层，全屏前后信息不丢
  • 符合 Chrome RDP / Moonlight 心智

缺点 / 风险

  • 结束会话从常驻按钮变成浮层内操作——U1 破坏性操作可达性下降，需确认是否接受
  • 底栏控件藏进「⋯」后，L2/L5 可学性变差（要多一次点击才知道有什么）
  • 与 v4/v5 工作台设计稿的「顶栏常驻」叙事冲突，改动面大
  • 浮层 HUD 加字后更挤，chip 换行可能挡画面上缘

C案 C · 可控会话默认进全屏（产品策略）

会话 capability=control 且用户手势允许时，建立后自动 requestFullscreen()；失败则回落案 A 提示条。

优点

  • 一步到位解决「被挡 + 速度放大」
  • 实现最小（调用已有 toggleFullscreen）

缺点 / 风险

  • 浏览器/WebView 对无手势 fullscreen 有限制，可能静默失败
  • 多屏办公时用户常要对照本机文件——强制全屏反而烦
  • 与规则 17「用户可控」冲突，除非提供「总是/从不/本次」偏好
  • 偏好项又增加设置面（S3 类复杂度）
不推荐单独用 C。 若做，仅作为「案 A 提示条上的主按钮旁」可选记忆：「本次会话结束后记住我的选择」——默认不自动全屏。
