交互
· CodeMirror SQL 高亮（项目已用 CodeMirror，零新增）；底部校验结果条。
· 校验：Rust 新增 sql_validate 命令 → SQLite :memory: 建临时库 EXPLAIN 只读校验，返回 错误行号+消息；写操作（INSERT/UPDATE/DROP…）直接拦截提示（红线：只读）。
· 有错时错误行红底标出 + 红色结果条显示错误信息。
· 全屏：走现有 FullscreenLaunchButton 三态（编辑/分屏/预览）。

AI 联动
· ai-sql-generate 结果 → AI 结果区「✏️ 打开编辑器」→ 预填 SQL 编辑器，改完复制/粘贴。闭环补齐。
注意
· EXPLAIN 校验不保证"能跑通"（表结构未知），只保证语法正确——文案写「语法校验」，不夸大成"可执行"。
· 仅识别 DML/SELECT/DDL 语句；函数/方言（如 MySQL 特有语法）可能误报，提供「忽略错误」开关。

④ AI 生成结果「✏️ 打开编辑器」按钮（TransformCard AiResult 区）

变换中心 · ai-sql-generate 结果卡
SELECT u.name, COUNT(o.id) AS cnt
FROM users u
LEFT JOIN orders o ON o.user_id = u.id
WHERE u.status = 'active'
GROUP BY u.name
实现
· AiResult.tsx 按钮区：对 ai-sql-generate / ai-regex-generate 两个动作额外渲染「✏️ 打开编辑器」（其余动作不显示，最小侵入）。
· 点击 → 构造 HistoryItem（type:text, content_type:sql|regex, text: 结果）→ openEditor(item) 打开对应编辑器。
· 正则：编辑器打开时自动把当前剪贴板/来源内容作为测试文本预填。

内容类型路由
· sql：ContentClassifier 识别（analyzer.ts 已有 SqlFeatures 检测，Rust 侧标签映射）→ 双击/右键自动进 SQL 编辑器。
· regex：自动识别不可靠（易误判），主入口 = AI 结果「打开编辑器」 + 手动「以正则打开」菜单（右键 → 打开方式 → 正则测试器）。
