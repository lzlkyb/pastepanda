§0结论先行（四条核心决策）

D1 · 逻辑层全复用：rcStore / useRc / rcCommands / rcShortCode 原样 import
状态轮询、设备列表、配对、会话发起的状态机桌面早已写好且是纯逻辑层——手机端只新写 UI 壳。后端 0 行改动。
D2 · P1 配对 = 短码互输（与桌面 A2 同一条流），扫码 P2
双方各显示 8 位码（PP-XXXX-XXXX）、互输对方码即配对——桌面 A2 已是这条流，手机贴着走。扫码要相机权限 + 解码库 + Tauri 权限配置，P2 再上（邀请码本就支持粘贴）。
D3 · 会话发起点设备卡 = 底部动作面板（控制 / 只看），非模态
点卡弹动作面板两键（规则 18 轻交互：高频一步、非模态不挡视野、点外部收回）。控制是默认色，只看次级。
D4 · 会话态直接换屏：outbound_active ⇒ 全屏 RcMobileSession
pending（等对方确认）与 active（已连上）是两屏：pending 是可取消的等待卡；active 全屏切会话壳（触摸语义已验收那套）。会话断开自动回设备页。

错误呈现红线（规则 15.3 / U3.5）：配对失败、请求失败、取消失败——全部走设备页内的常驻错误条（不是 toast 一闪），文案说人话（「对方电脑没响应，确认电脑端 PastePanda 开着」级别），技术细节进日志。store 的 error/statusError 已区分两类失败，手机端沿用同一判据。
