一、五个问题

#问题现状本轮
①四个工具全是拖矩形遮三处要拖三次，且矩形必然连带遮住不该遮的内容。QQ / 微信的马赛克都是涂抹式修
②高亮叠加变黑globalAlpha=.35 + fillRect，叠三层接近不透明色块，底下文字看不见修
③模糊边缘羽化没真修好注释说用不透明临时画布解决了，但问题不在 tmp 内部透明——在 tmp 外部没像素修
④模糊可被还原卷积数学上可逆（去卷积）；马赛克格子够大时不可逆。这是安全问题提示

乘法混合的物理意义就是“透明彩色滤镜”（MDN 原词），这正是荧光笔的行为
// 改前
ctx.globalAlpha = 0.35;
ctx.fillRect(x, y, w, h);

// 改后：白底×黄 = 黄；黑字×黄 = 黑字（文字始终可读）
ctx.globalCompositeOperation = "multiply";
ctx.fillRect(x, y, w, h);

坑globalCompositeOperation 在 ctx.save()/restore() 里，而 drawAnnot 首尾已有 save/restore，所以不会泄到下一个标注。但合成时是按顺序逐个画的，高亮必须只与底图相乘、不能与先前的标注相乘——否则高亮盖到红框上会把红框染成橙色。实现上高亮要先于其他标注绘制（按 type 分两轮）。

三、③ 模糊：补 padding

改前 · 四周一圈发虚透出原图
改后 · 边缘实实在在
左图是示意（用遮罩模拟），实际现象是模糊块四边 alpha 下降

根因：blur 卷积在 tmp 边界处要采样边界外，那里是空的。与 tmp 内部是不是不透明无关。

const pad = Math.ceil(radius * 2);           // 业界标准：外扩 2 倍半径
// 采样时连 padding 一起从底图取（底图是全屏，周围真的有像素）
tctx.drawImage(baseImg,
  offX + x - pad, offY + y - pad, w + pad*2, h + pad*2,
  0, 0, w + pad*2, h + pad*2);
octx.filter = `blur(${radius}px)`;
octx.drawImage(tmp, 0, 0);
// 贴回时把 padding 裁掉，只要中间那块
ctx.drawImage(out, pad, pad, w, h, x, y, w, h);

边界选区贴屏幕边缘时 x - pad 会负。drawImage 对超出源图的部分按透明处理，所以那一侧仍会羽化——得先把采样矩形钉到底图边界内，再按实际钉住的量调整回贴偏移。这一步是纯计算，抽成函数可以配单测。

形状选择每个工具各自记住（与现有属性记忆一致）：高亮习惯涂抹、马赛克偶尔想用矩形遮一大块，两者不应互相影响。

实现：遮罩合成（不是逐笔重算）

// 关键：马赛克/模糊的内容按**整个包围盒**一次算好，笔刷只决定可见区域。
// 若每笔单独算，重叠处的马赛克网格会对不齐（格子错位）。

const box = 笔刷路径的包围盒（外扩 笔宽/2）

A = 离屏画布；A 上画好 box 范围的马赛克 / 模糊
B = A 同尺寸；在 B 上用 lineWidth = 笔宽 描笔刷路径

A.globalCompositeOperation = "destination-in";
A.drawImage(B, 0, 0);        // A 只剩笔刷覆盖到的部分
ctx.drawImage(A, box.x, box.y);

好处马赛克格子始终对齐全局网格，来回涂不会出现格子打架；模糊也只算一次。

注意Annotation 要新增两个字段：shape?: "rect" | "brush" 与复用现有的 points。旧数据兼容：shape 缺省按 "rect"（现有行为），不会影响已存的标注。

五、④ 模糊可还原的提示

模糊是卷积、数学上可逆（去卷积），半径小时能相当程度还原；马赛克格子够大时信息真的丢了。

不做成弹窗、不做成拦截——那是干扰。只在模糊工具的 tooltip 里多一句：

data-tip="模糊（遮密码/证件请用马赛克，模糊可被还原）"

理由：本产品有 detectSensitiveText，已经在意敏感内容；这条提示成本为零、只在悬停时出现，不干扰任何人。

六、⑤ 橡皮擦正名

不改行为，只改名字和图标。当前行为（路径划过去删除整个标注）本身很好用，问题只是名字在骗人。

改前改后
标签橡皮擦删除
图标橡皮形状划除线 + 标注元素（表达“划一下删掉”）
tooltip橡皮擦（按 0）划过标注将其删除（按 0）
ToolId"eraser"不改——改了要动 types / 快捷键 / 默认值 多处，风险大于收益

不做真橡皮擦（路径切分）。工作量接近前两项之和（要动 undo 栈语义、切分后的 id 分配），而用户想删整个标注的场景其实更多。
