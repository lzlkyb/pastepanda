粘贴栈「循环粘贴」· A / B 方案设计稿

共同前提：会话态、不落盘 config、只在本次开栈内生效，下次开栈默认关闭。落点唯一 = 栈横幅「⋯」菜单。

✅ 已实施（A 方案，2026-09-17）：下面 A 区的三态就是上线后的长相。 B 区保留作对照（未实施）。实施中推翻/补充了本稿三处说法，已在文末「改动清单」逐条标注 —— 读那份清单时请以标注后的版本为准，不要照抄初稿。
先看这条：两个方案的区别不在开关长相，而在「谁决定贴下一条」。
A 是你按一次热键贴一条，队列自己绕回开头；B 是程序每 300ms 自己贴一条，你只负责喊停。 前者贴合你原本描述的用法（「我每次粘贴，从前往后」），后者复用现成的「全部粘贴 + 中止」基础设施、几乎零成本。

文案刻意不同：A 是「开启循环粘贴」——它是个状态，开关两态各一个词（开启 ↔ 关闭）， 与隔壁「开启 Tab 推进」完全同构；B 是「循环粘贴全部」——它是个动作，动词开头、没有关闭态， 和上面「合并粘贴 / 存为模板」同一类。菜单里混着两种语义而不在文案上区分，是同类功能最容易踩的坑。

二、方案 A · 会话态开关

用户视角：开栈 → ⋯ 菜单点「开启循环粘贴」→ 照常按 Ctrl+Alt+P 逐条贴 → 贴到最后一条时自动回到第一条继续， 永不贴完，直到退出栈模式（Ctrl+Alt+K）。

A-2 · 横幅：贴到最后一条之后 → 自动回到第 1 条（第 2 轮）

这才是你报的那句「贴完 ROUND( 就 /10000,0)，接着又回到 ROUND(」。 差别是：现在它有轮次、有计数器、有终止出口，不再是无迹象的死循环。

轮次为什么放脚注行，不放标题里：420px 面板下横幅内容宽只有 364px， 状态行被「逐条粘贴 / 全部 / ⋯ / ✕」四个控件占掉约 203px，标题只剩 ≈153px。 往标题里塞「第 2 轮」会连同后面的徽章一起被 text-overflow:ellipsis 吃掉 （本稿第一版就是这么被截没的，放大截图才发现）。 脚注行的进度条是 flex:1，文字永远排得下 —— 所以轮次归脚注行， 标题只留一个短徽章。

三、方案 B · 一次性动作

用户视角：开栈 → ⋯ 菜单点「循环粘贴全部」→ 程序每 300ms 自动贴一条，贴到末尾绕回开头继续， 横幅上出现红色「中止循环」按钮，按 Esc 或点它停下。写完关掉菜单，菜单自己恢复原样——没有开关要记得关。

B-1 · 运行中的横幅：直接复用现有「中止」形态

U58 的「全部粘贴」已经有 stackPasteAllActive + abortStackPasteAll（进度条 + 红中止按钮 + Esc）， B 方案**原样复用**这套基础设施，只是 while 循环的终止条件从「队列空」换成「用户中止」。

「中止之后队列留不留」是个真决策，不是细节。循环粘贴存在的理由就是「这一批我要反复用」， 所以中止时不出栈、不清空：队列复位成完整一批、回到你攒它的原始顺序， 想再来一轮就再点一次菜单；若按普通出栈语义把已贴项丢掉，第二轮一开始就得重新攒一遍， 这个功能就白做了。顺带解决了另一个观感问题 —— 环转了好几轮之后， 若保留旋转后的顺序，横幅上第一条会变成「*1.13」而不是你最先复制的「ROUND(」，看着像顺序乱了。 （A 方案的出口是退出栈模式、栈整体清空，不受这条影响。）

为什么 B 的浮标能省掉「下一轮提示」：它是自动连发，用户不需要知道「该我按了」； 唯一需要告诉他的是「还在跑」和「怎么停」，所以主行换成动作状态、副行固定给停止手段。

四、A / B 逐项对照

维度方案 A · 会话态开关方案 B · 一次性动作
触发方式你按一次热键贴一条（与现在完全一致）程序每 300ms 自动贴一条
匹配你的描述完全匹配——「我每次粘贴，从前往后」不匹配，但少按很多次键
状态新增 1 个 store 字段（会话态）+ 复位逻辑零新增状态（复用 stackPasteAllActive）
结束方式退出栈模式（Ctrl+Alt+K）/ 菜单里关掉开关点中止 / Esc / 退出栈模式
「忘了关」风险存在，但退栈即复位，下次开栈默认关不存在——它是动作不是状态
代码成本中：新字段 + 轮转语义 + 复位点 + 横幅/浮标两处展示低：改 stackPasteAll 的终止条件 + 菜单加一项
风险点stackMarkPasted 语义分叉（出栈 ↔ 轮转），要守住两条路径的回归连发期间抢占剪贴板，贴错窗口时是连续贴错（现有中止机制兜底）
适合场景对着固定几个字段来回填，人工控制节奏一串内容按顺序灌进表单/单元格，不想一次次按键
两者不冲突，但不要一起上。同一份队列同时存在「手动循环」和「自动循环」两套推进入口， 会让「我按了热键但什么都没发生（因为在自动跑）」变成新的困惑源——正是你们历史上「提示已粘贴却没内容」那类事故的形态。 先上一个，观察一阵再决定要不要另一个。

问题现状必须改成
队列轮转 appStore.ts:812 stackMarkPasted 是出栈，贴一条少一条 循环态把它移到队尾。这样 stackItems[0] 恒为「下一条」， 浮标预览 hudBridge.ts:66 与 chip「下一个粘贴」标签零改动

「全部粘贴」无限循环 lib/api/stack.ts:171 while 条件是 stackItems.length > 0 循环态下该条件永不为 0，会变成贴不停。改成「▶ 全部」在循环态下只贴完本轮就停 （本轮贴空 = 停，不进下一轮）—— 把无限循环变成有界动作，按钮也保住了可用性。 这也正是你最初描述的那个现象

半路关掉开关
实现时审出的真 bug		 关闭分支只翻布尔；循环态贴过的条目不出栈，仍留在 stackItems 里 关闭时必须把本轮已贴的出栈（.filter(未在 doneIds)）并清 doneIds —— 否则它们 既被待贴列表过滤掉（看不见）、又会被出栈逻辑照常贴一遍。 实测（3 条队列，循环态贴过 a 后关开关）：粘贴序列变成 a,b,c,a， 且横幅说「剩余 3」而 toast 说「剩余 2」。
配套：stackPasted 在循环态取本轮口径（整轮复位归零）， 否则关循环那一刻脚注会是 10/11 这种没人能解释的数字
进度语义 横幅与浮标都是 stackPasted/stackCollected 循环态换「第 N 轮 · 本轮 x/y」；stackCollected 冻结不增
复位点 setStackMode(true) 清 5 个字段、exitStackMode() 清 6 个 两处都加循环字段。❗ appStore.ts:867 stackLoadTemplate 绕过 setStackMode 直接置 true，是漏改点，必须补
最容易被漏掉的一条：循环态让「栈空自动退出」（lib/api/stack.ts:61-68 与 :92-97）永远不触发。 栈永不清空 ⇒ 栈模式与浮标常亮、热键按一次贴一条永远贴不完，而屏幕上没有任何异常迹象—— 这就是你最初问的「什么时候结束」。所以「退出栈模式即结束」必须在浮标上写出来， 不能指望用户自己猜到「原来退出就停了」。
