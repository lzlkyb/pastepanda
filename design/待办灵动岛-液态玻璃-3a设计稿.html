0 · 探针结论（先给三句话）

① 材质真生效且行为可预测：胶囊内部随配方精准变化——本机浅蓝桌面 (187,208,224) 上， dark150 实测内部 (80,90,99)（线性理论 88.8，误差 9%）、white110 (207,220,227)（理论 216，误差 4%）、white150 (214,224,231)（理论 227）。

③ 文字对比度由「玻璃极性 × 主题极性」决定：实测深磨砂上深字（浅色主题）2.6:1 ❌、白磨砂上深字 12.9:1 ✓——物理与 §2.2 的轴完全一致：模糊救不了平均亮度。

1 · 标定与四背景外推（关键表：浓度到多少才全绿）

模型：玻璃输出 = α×tint + (1−α)×背景均值（实测标定误差 ≤9%，下表用理论 α 计算）。 深色主题文字 #f4f4f5 / 次要 66% #f4f4f5；浅色主题文字 #18181b。 ❗ 极性规则：深玻璃只配深色主题（浅字）、白玻璃只配浅色主题（深字）——主题适配层 data-island-mode 现成，正好绑定。

读法：清透档（α .43–.59）在本机这类中亮桌面上实测非常好（8–13:1），但它有两个必然出现的失效场景： 浅色主题 + 近黑壁纸/终端（3.5:1）、深色主题 + 白文档（次要文字 2.8:1）。 要四背景全绿，浓度必须上到 α ≈ 0.78——透光 22%（现状实色 D 档透光 8%，仍是从「板」到「玻璃」的一步）。 这就是 §2.2 那条对立轴在真实材质上的再次显形：透与读只能选偏向。

3 · 形状代价：四角月牙（实测 ~5 逻辑px，无法消除只能接受/掩盖）

材质按窗口矩形铺（radius 参数 macOS Only），CSS 胶囊裁不到窗口层 ⇒ 圆角外的月牙是玻璃。 实测对角线剖面：月牙宽 k=0..5 物理px（≈5 逻辑px），与岛体同色（同 tint）—— 所以它只在「玻璃色 ≠ 背景色」时以形状轮廓可见：白玻璃压暗壁纸 = 四个亮方角；深玻璃压白文档 = 四个暗方角。 探针 PNG 人眼复核：本机桌面上两配方都不扎眼（月牙只有 5px 且带模糊质感）。 唯一干净的消除手段 SetWindowRgn 无抗锯齿（胶囊会有阶梯），不采用。这条是接受项。

4 · 其余边界（全部有据）

① 岛体 vs 纯黑壁纸：dark200 岛体 rgb(16) 对纯黑只有 ~1.05:1——和 §2.2 里 B 档的「消失」问题同源；对策沿用 D 档结论：描边 + 外投影恒在，任何背景至少一样起作用。
② hover 不动材质：材质 tint 不能每次穿透翻转都走 Rust 调 set_effects（60ms 轮询 × 每次重合成）——hover 视觉保持 CSS 层（微调一层洗色），材质恒定。
③ 主题切换：材质 tint 跟主题走 ⇒ Rust 侧要监听 theme-changed 重施加材质（create 时读 config 定极性；前端广播事件 Rust 用 Listener 接）。
④ 成本：RSS 探针实测 +29 MB（含材质）；Acrylic 在背后内容变化时重采样——岛是静态小窗（260×47 物理），远小于全屏用法，可接受；若实测 CPU 异常再降 blur 半径。
⑤ 回退链：任何一步不满意 → 摘 set_effects + 恢复 tint 变量 = 今天的线上形态（探针已验证这个复原路径）。
