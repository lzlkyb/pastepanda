四个方案在做什么

方案规则时间轴打开时代价
现状卡片永远占满整宽左侧让出 86px2560px 屏上一行文字横跨全屏，眼睛要横扫；右侧「时间/类型」离正文极远
A 居中封顶超过封顶值就居中，两侧留白改为左对齐（否则卡片飘到中间、离时间轴很远）开/关时间轴时卡片会横向跳一下
B 只封顶超过封顶值就停止变宽，始终左对齐照旧让出 86px，无冲突宽屏下右侧一大片空白，看着像没铺满
C 渐进留白不封顶，左右内边距随宽度增长照旧让出 86px，无冲突超宽屏仍然很长，只是没那么贴边

我的建议：A，封顶 860

理由：卡片是单行预览，一行超过约 80 个汉字之后，右端的「时间 · 类型」离正文太远， 视线要横扫整屏才能把一条记录看完整——这是长度问题，不是留白问题，所以 C 解决不了。 B 能解决长度，但宽屏下右半屏彻底空着，不如居中自然。

A 唯一的代价是「开关时间轴时卡片横向跳一下」。这个可以接受：时间轴本来就是个显式开关， 而且已有 transition: padding-left .3s，加上 margin 过渡就是同一条动画。

落地位置（不再放全局 CSS）

规则写进 CardList.module.css，不放 app.css—— 原来那两条断点写的是 .card-list，而实际渲染的是 CSS Module 的 .cardList， 从未生效（与 .app-shell 同一个坑，已删）。

另外不照搬旧值：旧规则里的 padding: 14px 16px 24px 会把底部留白从 80px 压到 24px， 而那 80px 是滑到底时给最后一张卡片的空间——BackToTop 是 fixed; bottom:16px（高 38px）， 压小了就会盖住卡片。新规则只动左右与最大宽度，不碰 padding-bottom。
