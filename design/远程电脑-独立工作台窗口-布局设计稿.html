远程电脑 · 独立工作台窗口（布局重设计）

背景：主窗口只有 550×700（tauri.conf.json:17），会话 Dialog 的 960px 视图实际被压到约 534px 宽——远程画面区只有巴掌大。本稿把「远程电脑」从主窗内对话框改为独立大窗口，并按大窗口重新分栏。样式全部取自真实源码令牌。前一份稿子的 1A（开关行）/2A（自动档）成果原样并入新布局。

§0 窗口形态选型

方案做法结论
A 独立工作台窗口 新建 rc.html 入口 + Rust 命令建窗（label rc-workbench），照 md-editor 先例（commands/system.rs:949）：按主窗口所在显示器算尺寸居中。主窗内原 Dialog 保留为精简入口或直接替换 推荐
B 会话时才弹大窗非会话留在主窗 Dialog，发起会话时再开窗。两段式：设备管理与会话分裂在两个窗口，配对流程跨窗跳否
C 主窗临时放大点远程时把 550×700 主窗拉大，关闭还原。破坏主窗状态，且主窗其余面板（栈、知识库）被拉伸错版否
窗口参数（方案 A）：默认逻辑尺寸 1200×780（本稿 1:1 按此画），最小 960×640，resizable(true)，decorations(true)（系统标题栏——md-editor 用 false 是因为自定义标题栏，工作台无此需求），位置居中于主窗所在显示器。用户手动拉大后记住尺寸与位置（存 config，P2 可先不做）。
职责划分（关键边界）：工作台窗口专注「你去控别人」——设备列表、发起、观看画面、画质。主窗口保留「别人控你」的通知面——被控确认横幅（RcControlBanner）、入站申请条、rc-session-changed 全局监听不搬家。理由：被控是被动事件，人不在工作台时也必须能看到；发起是主动意图，才需要大画面。会话进行中关闭工作台 → 沿用现有确认逻辑（结束会话并关闭 / 保持会话仅关窗）。
