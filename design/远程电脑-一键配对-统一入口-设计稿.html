远程电脑 · 一键配对（统一入口）设计稿

一个入口，一种码，不做网络判断。用户分不清内网/外网，所以界面也不许出现这个判断： 附近设备自动出现，能点就点；看不到就生成一份凭证——同一份凭证同屏显示为二维码和 8 位码， 对方手机扫码、对方电脑敲码，走的是同一个秘密，用户不用选方式、不用选网络。 全程只有一个 8 位「配对码」，只有一个动作：两端显示同一个码，一样就各点确认—— 同网点邻居时它是系统从两端密钥算出的核对值；走凭证时它就是你输/扫到的那一个（连上后原数回显，不会变）。 所有路径末尾都是同一套 ed25519 身份落库，配对只发生一次，之后打开即连。

§0 一张入口：用户做什么 / 系统自动做什么

用户看到的用户动作系统自动做的事
主区常驻「附近的设备」卡打开远程电脑就看，邻居出现就点 局域网 UDP 发现（2s 刷新，窗口隐藏即停）；通道未启动/无邻居时卡照渲但不列项
点一个邻居 → 8 位配对码核对看一眼数字一样 → 各点确认 QUIC 密钥交换，从两端密钥算出 8 位核对值，两端都确认才写库
没看到对方 →「配对新设备」点卡上主按钮 → 出示给对方 生成一次性凭证（secret 派生：二维码票据 + 8 位码两种编码，10 分钟、单次有效）
对端扫码 / 对端敲码（对方侧）核对同一个 8 位码 → 各点确认 连上后两端回显凭证本身（扫到的/敲的就是那个数）——码被换过=两端对不上；不允许出现第二个数
手里有对方的凭证「我拿到了对方给的配对码」→ 输入 直连该 secret 的临时端点（走公共中继也不改信任链）
整个流程里用户只需要回答「我是出示方还是输入方」——这件事他天然知道（谁先打开谁出示）。 「内网/公网」不进界面，只作为系统内部自动切换的传输路径（LAN 直连优先，跨网回落中继）。 全程一个 8 位码、一个动作：两端一样，各点确认。

§1 电脑端 · 主页主区：常驻卡 = 单一入口

§4 手机端 · 同一套入口，多了「扫一扫」

手机是「有摄像头、键盘烂」的一端：统一屏里多一个扫一扫动作（电脑没有这个硬件，不放）。 凭证出示时把 8 位码放大为主、二维码缩小为辅——因为对着手机出示的对端大概率是电脑，敲码更顺。

§5 与现状的差异（只列变化）

位置现状本稿
配对入口 侧栏「这台电脑」卡 → 折叠「更多方式与设备号」→「其他配对方式」；空态时另有「开始配对」 唯一入口：主区常驻卡 +「＋ 配对新设备」按钮（折叠入口保留给高级）
跨网方式 8+8 双向搬码 / 长邀请码 一份凭证双形态：二维码（手机扫）+ 8 位码（电脑敲），同一 secret；单向、10 分钟、单次有效
用户要判断的事 内网还是外网？用二维码还是配对码？ 都不用判断：附近自动出现；凭证双形态全给；只区分「出示 / 输入」
侧栏 8 位互换卡 内联 RcA2PairExchange（双向 8+8，本次真机痛点） 保留原位不动（桌面自用/兜底），但不再是对配对的唯一路径
配对弹层 「远程配对」对话框（附近主路 + 高级码路） 不删：设置页入口与其共用；工作台主页改走常驻卡。两者后端状态同源（useRcNearbyPair）
手机端 设备页只有 8 位码卡 附近卡 + 统一屏（扫一扫/出示/输入）+ 8 位配对码核对屏（后端命令现成，只做 UI）
码的位数 附近配对 6 位核对、互换码 8 位、邀请码一长串——三种长度并存 全程只用一个 8 位「配对码」：附近核对 6→8（研磨成本 ×64），扫码/敲码路径连上后 回显凭证本身（扫到的/敲的就是那个数），取消二次 SAS——不引入第二个数

§6 实现要点（确认后实施用）

项做法
常驻卡 + 核对屏新 rc/RcNearbyPairPane.tsx：卡 + 卡内 8 位配对码核对态（展开现成 RcNearbyList； 核对组件由 RcPairPin 泛化出 8 位形态或直接换新组件）。RcWorkbench 已 299/300 行——主文件只加一行包裹，不写逻辑。
配对码统一 8 位附近链路的 SAS 从 6 位改 8 位：short_pair/nearby 两侧取位宽度一起改（错开版本=两端码长不同，必须同发）； 扫码/敲码路径连上后回显凭证本身，取消二次 SAS；统一「配对码」展示组件（断位 4+4、等宽、字距）三路复用：附近核对 / 凭证出示 / 输入预览。
一份凭证两个编码新命令 rc_pair_issue：生成一次性 secret（10 分钟单效）→ 同回 { code: 8 位, ticket: 二维码票据 }。二维码=ticket 的编码，8 位码=同一 secret 的另一种人类编码， 后端只存一份。新增单向 secret 派生（acceptor=出示方），short_pair 增加单向模式，旧双向流兼容保留。
统一屏新 settings/RcPairUnified.tsx：附近列表 + 出示（双形态）+ 输入 + 高级折叠。 手机端同组件 Mobile 版式（多一个扫一扫 action，相机用现成扫码头）。
传输路径界面零感知：LAN 直连优先、跨网回落公共中继，由 iroh 自己选路。UI 不展示「中继/直连」字样， 只在设备详情留一行「上次·局域网直连」的事实回放（现有行为）。
轮询沿用 useRcNearbyPair（2s、窗口隐藏即停）。常驻后加一条：无配对进行中时退到 5s 节流 （量一下再定，不在注释里宣称「开销极小」）。
安全不变量8 位配对码核对不允许跳过（三条路径同一个组件、同一套「一样/不一样」）；名字一律视为对端自报； 凭证 10 分钟过期 + 单次；「允许」弹窗是信任成立点；配对成功即消费凭证并关门（现有行为）。
规则符合U1（>1s 出等待态）/ U3（四态齐全）/ U5（间距 4/8/12/16、圆角 4/8/12）/ U6（语义色）/ L1（「这台手机」「书房那台台式机」全用户语言，不提内网/外网/中继）/ L2（图标常驻文字）。实施后跑 npm run lint:ui。

配套落地顺序建议：① 常驻卡 + 核对屏（内网零输入，当天可验）→ ② 统一屏 + 凭证双形态 + 单向 secret → ③ 手机端三屏。每步独立可用，不等待全部完成。
