知识库问答雏形 · B2 #8.3 #10 设计稿

拍板形态：搜索框升格「搜 / 问」双模 ＋ 回答下方列「参考笔记」（不解析 [n] 脚注）。 受 ai_enabled 门控（规则 #16）；关掉 AI 时切换器整个不渲染，搜索行退回今天的样子。

不新开 AI 通路。注册成内置动作 ai-kb-qa 走现有 ai_run—— 那条路上已经有开关门控 / 出网闸 / 预算 / 缓存 / 用量日志五件套（与 B1 轻量 AI 同一条路，↩A-39）。 本设计不碰 ai_run 的既有顺序（出网闸 → 参数校验 → 缓存 → 预算 → 真实调用）。

知识库中没有相关笔记。
未发送任何请求。当前范围：文件夹「运维」
范围是白送的。问答的检索直接走刚做完的 note_search_view（↩A-45）， 所以当前文件夹 / 标签 / 筛选 chips 自动成为问答范围——等于零成本拿到「只问这个文件夹」。 回答卡底部必须把范围写出来：否则筛着一个文件夹去问，没命中时用户会以为全库都没有。

§2 数据流与出网边界

🔴 开工后修正：不能用 note_search_view 检索。 本稿初稿写的是「本地检索 = note_search_view(问题文本, …)」，那样做出来的功能会永远回「没有相关笔记」： to_ngram 把一句话切成每个单字＋每个相邻 bigram 后 join(" ")，而 **FTS5 的隐含运算符是 AND**—— 一句 10 字的问题 = ~19 个词全部 AND，要求一篇笔记同时含问题里的每个字与每对相邻字。 句末的「？」还会被切成一个裸 term，可能直接让 MATCH 语法报错、退到 LIKE '%整句问题%'，同样零命中。 → 另写 note_search_relevant：bigram OR + BM25 相关度，标题权重 10 倍、pinyin 列权重 0， 停用字 bigram（「这个」「目的」「的部」）丢掉。已由 tests_qa.rs 里一条对比用例钉住（旧路 0 条 / 新路命中）。

🔴 问题必须拼进 text，不能走 opts。 ai_run 的出网闸只扫 text（加标签名）： if !force && !spec.is_local() && classifier.is_sensitive_for_egress(&egress_probe)。 把问题放 opts 里就绕过了这道门——用户在问题里打一个手机号或一把 Key 就直接出网了， 而且不报错、不提示。拼进 text 后问题与片段一起过门，代价只是占长度额度。

8000 字符预算怎么分

ai::actions::MAX_INPUT_CHARS = 8000，超了 check_input 直接 Err("内容过长（…），请先截取需要处理的部分"）——在问答场景下这句报错根本无法执行（用户没有“内容”可截）。 所以拼之前就得卡住，不能拉到报错才发现：

项预算为何
TOP_K5 篇与模型能认真读完的量匹配；再多就是把噪声当依据
每篇截断1200 字5×1200 = 6000，留 2000 给问题 + 标题 + 编号模板
问题上限500 字超长当场拦，不到后端才报
截断提示必须可见规则 #15.3：片段被截了就在参考行标「已截断」，不静默

§3 钉死的口径

项定义不这么定的后果
语料边界只检 notes，不含历史卡片§8.5 已定：剪贴流水噪音大、敏感度高。卡片入语料是 C 阶段的显式开关且默认关
轮数单轮，不存会话多轮要管上下文窗口与会话表，那是 C 阶段；雏形存会话 = 白建一张表
回答去向不落库，关卡/切回搜就没「存为笔记」是通路 #6 第 9 行，明确标 C——现在做就是越前
零命中不发请求，直说没有发了 = 模型无依据可编、用户白花钱，两头都输
禁止编造system 硬规则：只能用给定片段，片段里没就说没有§7 RAG 规范已定；雏形先把这条建起来，C 阶段直接继承
参考来源前端自己知道送了哪 5 篇不解析模型输出 ⇒ 模型编不出不存在的引用
AI 关闭切换器整个不渲染，不是置灰规则 #16：未启用 = 零可见零请求零费用

§4 四种返回全得接（漏一个就成静默失败）

ai_run 返的是枚举而不是单一结果，它自己的注释写得很清楚： 「需要确认」与「超预算」不是错误，是需要前端分支处理的正常结果。当成错误弹一个红 toast 就是把可恢复的事变成死路。

status回答卡里的表现
ok回答正文 + 参考笔记行
needsConfirm卡内展示原因与「仍要发送」按钮 → 带 force=true 重试。 不能自动 force：这道门存在的意义就是让人拍板
budgetExceeded卡内说清预算情况，不假装成网络错误
Err真错误（网络 / 鉴权 / 解析）——原文展在卡内，带重试
已核完：缓存键含载荷，无需改动。 cache_key = cache::make_key(&cache_id, &opts, text.trim())——**text 本身就在键里**。 而我们把问题与片段全拼进 text，所以笔记一改 payload 就变、缓存自动失效。 （这正是不预先假设的理由：结论恰好是好的，但得核过才算。）

§5 不做（划界，免得重新争论）

  • 不做多轮对话与会话历史（C 阶段）；
  • 不做语义检索——雏形就是 L1（FTS5 + 拼音）。note_chunks 与本地 embedding 是 C 阶段的事（§1.4 已定）；
  • 不解析 [n] 脚注（本次拍板）；
  • 不做「存为笔记」（通路 #6 第 9 行，属 C）；
  • 不把历史卡片入语料；
  • 不动搜模式的任何行为——切回搜就跟今天一字不差。

§6 验收清单

  1. AI 关闭时搜索行与今天完全一致（切换器不出现，不是置灰）；
  2. 开着 AI 但停在搜模式：搜索结果、排序、分组、加载更多全与 #9 一致；
  3. 切到问模式→回车：出回答卡，参考笔记可点开且点开的就是那篇；
  4. 零命中不发请求：问一个库里肯定没有的词，看用量页次数不增；
  5. 筛一个文件夹再问：回答卡底部写着该文件夹名（范围可见）；
  6. 问题里包含手机号 → 弹出网确认（证明问题真的过了出网闸）；
  7. 造一篇超 1200 字的笔记：参考行标「已截断」，而不是报「内容过长」；
  8. 问一个片段里没答案的问题：回答应说「片段里没有」，不能自己发挥；
  9. 关卡 / 切回搜：回答消失，库里没多出任何行；
  10. 480px 窗宽：[搜|问] + input + 三图标 不换行、不溢出；
  11. 长回答（人工验收转来的）：卡片高度不超 40vh、正文自己出滚动条， 头部✕与底部参考链接始终可见，且下方笔记列表不被挤没；拉短窗口卡片跟着变短。
🔴 首版就错在这里（已修）。回答卡初版写的是 flex-shrink: 0 且不限高： 回答一长就把下面 .list（flex:1）压到 0，而卡片自己又不滚——后半截回答和整个笔记列表同时看不到。 另外 margin: 0 20px 也错：横向留白本来由 .wrap 的 12px 内边距给，再自己缩一层就比搜索框窄一圈。 修法：display:flex; flex-direction:column; max-height:40vh; min-height:0， 只给 .body 加 overflow-y:auto（头/尾 flex-shrink:0）。 40vh 而不是固定 px，才叫自适应；项目里 QuotaDialog 的 .body 就是 66vh + overflow-y:auto 同一写法。
