2026-08-12 · 虚线格子区 = max-height:78vh 的可用高度（取 900px 屏 → 702px）· 尺寸取自真实代码

根因：整个弹窗没有任何滚动容器。
ChainRunnerDialog.tsx:209 写的是 className={`dialog-box w460 ${styles.wrap}`}—— .wrap 就是 dialog-box 本身，不是内层容器。而它只写了：
display:flex; flex-direction:column; gap:10px

于是：
① 没有子项是 flex:1; overflow-y:auto——变换中心有 .cards{flex:1;overflow-y:auto} 所以没事，这里缺这一层；
② .dialog-box 没有 overflow:hidden（dialog.css:21 可查）， 所以 max-height:78vh 只管住了盒子自己的高度，内容照样画到盒子外、直到屏幕外；
③ flex 子项默认 min-height:auto，即使加了 overflow 也不会收缩，必须配 min-height:0；
④ gap:10px × 8 个子项 = 白吃 80px，小屏上雪上加霜。

子项最多能到 8 个：header / SequenceDiscover / chainRow / inputCard / runRow / aiConfirm / steps / failBox / finalCard / idleHint。 每一步展开后是 “头 42 + 输入框 64 + 箭头 + 输出框 64 + 耗时” ≈ 200px，四步链就是 800px——单此一项就超过 702px 的全部预算。

现状复现：四步链跑完、步骤全展开

这是真实默认行为——ChainRunnerDialog.tsx:141 跑完后 setExpanded(new Set(r.stages.map((_, i) => i)))，所有步骤默认全展开。

方案 A：上区固定 + 结果区滚动 · 推荐

把内容分两区：上区固定（链选择 + 输入 + 运行按钮，flex-shrink:0）， 下区滚动（步骤流 + AI 确认 + 失败提示 + 最终结果，flex:1; min-height:0; overflow-y:auto）。

上区固定高度 ≈ 48（header）+ 44（chainRow）+ 130（inputCard）+ 45（runRow）+ 30（gap）= 297px， 702px 下给结果区剩 ~405px（刚好两步展开），剩下滚——比现在“根本看不到结果”好得多。
顺带修两个真问题：① gap:10px 在滚动区内改成 8px（八个子项时能省出一整步的高度）； ② .dialog-box 补 overflow:hidden，否则 16px 圆角会被滚动内容的方角顶破。

方案 B：整体滚动（最小改动）

header 下面所有东西包一层 .body{flex:1;min-height:0;overflow-y:auto}。只动 CSS + 一个 div，不拆结构。
代价：运行按钮会随内容滚走。跑完一条四步链之后，想改输入重跑、或换另一条链， 得先往上滚 500px——而“跑一次看看、不对再换一条”正是这个面板最常见的用法。

方案 C：运行后切换视图

运行前只显示配置（链/输入/运行），运行后整面切成结果页 + 一个「← 返回」。空间利用最大化。
两个代价：① 看不到输入了，而步骤里的“输入→输出”需要跟原文对照； ② 多一个视图状态要管（何时重置、换链时要不要退回），而现在的 bug 只是“少了一个滚动容器”。
