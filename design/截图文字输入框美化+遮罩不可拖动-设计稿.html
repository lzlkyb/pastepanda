截图 · 文字输入框美化 + 遮罩元素不可拖动

设计稿 · 2026-08-19 · 对应 .text-draft / .text-toolbar 与 onAnnotMouseDown 命中检测
⚠ 先说不能动的部分。输入框的盒模型是硬约束，改了就会「框里看到的位置」和「落到画布上的位置」错开：
  • padding: 0 —— 加内边距文字整体偏移几像素
  • 用 outline 不用 border —— border 占布局，outline 不占
  • line-height: 1.3 必须等于 draw.ts 的 TEXT_LINE_HEIGHT
  • font-family 必须与 measureTextExtent 同款，否则换行点和落字宽度对不上
  • white-space: pre + wrap="off" —— 关软换行，逻辑行数 = 画布行数
所以本次美化只用不影响文字盒模型的属性：outline / box-shadow / 背景 / 圆角 / placeholder / caret / 焦点态。

四、遮罩类元素不可二次点击移动

现在拿马赛克工具去涂第二块、只要碰到第一块，就变成选中并拖走它。 onAnnotMouseDown 里注释写的是「非绘制工具：先做命中检测」， 但代码只排除了 number： 

if (tool !== "number") {
  const hit = [...annotations].reverse().find((a) => pointHitAnnot(px, py, a));

而笔刷型遮罩的命中容差是 maskBrushWidth / 2（笔宽 40 就是 20px），误命中面积很大。 更要紧的是语义：移动一块马赛克 = 把遮盖挪开 = 重新暴露刚遮住的隐私内容， 这不是普通图形误拖一下的代价。

方案行为取舍
A 完全不可选中推荐 mosaic / blur 不参与命中检测，点它等于点空白，继续画新的遮罩 最安全，微信截图同款心智：涂上就是涂上了。删除仍有两条路——Ctrl+Z 撤销、橡皮擦擦除
B 可选中不可移动 能点中（高亮 + Delete 删除），但拖拽不生效 保留了「精确删除某一块」的能力；代价是仍会打断连续涂抹——点中就中断了画新遮罩
C 仅中性工具下可选中 拿着 mosaic/blur 工具时不命中，切回 rect 才能选中移动 兼顾两者，但「同一个元素有时能拖有时不能」需要用户先理解模式，规则更绕

顺带修掉注释与代码不一致：命中检测应显式列出「可选中的类型」，而不是反向排除 number —— 否则下次新增工具又会默认落进可拖动集合。
