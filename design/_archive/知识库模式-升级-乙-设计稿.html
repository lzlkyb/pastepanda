§3洞 3：网格卡片的材质归属，C 稿没定

C 稿 §2 的网格卡片是自画的：background:#161a21 / border:1px solid / radius:14。而真实的 .row 是 glass token / radius 16 / 双层 shimmer / spring 抬升。

照 C 稿实现的结果是「列表形态有玻璃、网格形态没有」——比现状更不统一。§3 只说了「不复用 CardActionBar 组件，只照搬形态与尺寸」，网格卡片的材质归属通篇没写。

❗ 有一对坑不能照抄结论。.row 的 overflow:hidden 与 flex-shrink:0 是一对——因为 .list 是 flex column + overflow-y:auto，而 flex 项的自动最小尺寸只在 overflow: visible 时等于内容高，一加 hidden 那个下限就变 0，行会塌成细缝（源码注释说知识列表真撞上过一次）。
网格里卡片是 grid 项而不是 flex 项，自动最小尺寸的规则不同。这里必须实测重验，不能把 flex-shrink:0 照抄过去当护身符（它在 grid 项上根本不生效）。

§6token 收口：补 §1 只做了一半的那半

C 稿 §1 承诺「全部收口到 KnowledgeView.module.css 顶部的一组 --kb-* 变量（规则 #11）」，但实际只覆盖字号。已核实：

  • 全项目没有 --radius-* token。硬编码出现过 4 / 5 / 6 / 7 / 8 / 10 / 12 / 16 / 20 / 999
  • --card-gap 只存在于 CardList.module.css:7 内部。KnowledgeView.module.css:521 是抄了个 10px，注释里声称「同记录模式的 --card-gap」——一改就分叉，而注释会继续说它们相同
/* KnowledgeView.module.css 顶部，与 --kb-fs-* 并列 */
--kb-r-sm: 7px;    /* 侧栏行胶囊 / 小按钮 —— 现存值 */
--kb-r-md: 11px;   /* 34px 图标槽 —— 现存值 */
--kb-r-lg: 16px;   /* 笔记卡片 / 网格卡片 —— 现存值 */
--kb-sp-1: 4px; --kb-sp-2: 6px; --kb-sp-3: 8px; --kb-sp-4: 10px; --kb-sp-5: 12px;
🔴 关键：不新增任何数值，只给现存数值起名字。这一条零视觉风险——改完截图应当逐像素一致。它的价值不是变好看，是让后面三批不再各写一份。
--card-gap 单独处理：提到 theme.css（一个变量，两处引用），或者退一步——把 KnowledgeView.module.css:521 那句注释改成「这是 --card-gap 的副本，改动要同步」。装作它们共享一个变量，比明说是副本更危险。

§7排版层次：这才是「更美观」的主力

C 稿 §1 的字号阶梯把小字抬上去了，方向对。但它留下 7 档字号，而层次仍然只靠字号一个维度——颜色只有 primary/secondary/muted 在用，字重几乎没参与。

tabular-nums 值得单独说。元信息里「2 小时前 / 1.2k 字」是数字，比例字体下 1 比 8 窄，一列的右边沿会参差。侧栏 .count 已经用了 font-variant-numeric: tabular-nums（源码注释：「不加的话 1 比 8 窄，一列数字的右边沿会参差不齐」）——照抄同一句到 .rowMeta。
不引入任何新颜色。--text-secondary / --text-muted 已过那 28 处对比度改进，直接用。
