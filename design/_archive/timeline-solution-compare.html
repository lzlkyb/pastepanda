方案 A · CardList 统一控制

⭐ 推荐
CardList → 管理唯一 timelineVisible → 通过 prop Timeline (visible prop)
单一数据源 · 无状态冲突
Timeline 移除内部 state，纯展示组件
CardList 统一处理所有触发源

forwardRef + useImperativeHandle

时间轴内部 state: ● 隐藏
桥接: ref.show()
🖱️ 鼠标移到左侧 → 时间轴滑出 📜 滚动 → ref 调用 show() ⚠️ 注意：可能状态不一致
核心逻辑：Timeline 内部保留 visible state 和 show()/scheduleHide()。CardList 通过 forwardRef 获取 Timeline 实例，滚动时调用 timelineRef.current.show()。问题：onVisibilityChange 回调和 CardList 自身的 setTimelineVisible 仍然存在，两处都可能修改状态。

方案 C · 合并判断

最小改动
CardList → scrollForcedVisible
Timeline → 内部管理 visible state
最终 = scrollForcedVisible || visible
两个 boolean OR · 边界情况多

📊 三方案对比

维度 方案 A（推荐） 方案 B 方案 C
数据源数量 1 个 2 个 2 个
状态冲突风险 无 有（ref 调用 vs 回调） 有（两个 boolean OR）
改动量 中等（Timeline + CardList） 较多（forwardRef + 双逻辑） 最小（仅 CardList）
React 模式 受控组件 ✅ 非受控 + ref 命令式 混合式
可维护性 高 · 逻辑集中 中 · ref 间接调用 低 · 逻辑分散
调试难度 低 中 高
扩展性 好（易加新触发源） 中 差（每次改需考虑两个变量）
