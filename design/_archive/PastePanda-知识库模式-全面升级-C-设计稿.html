网格形态。无图的卡片不留封面位（右卡）——摆一排灰色占位框比不摆更难看。

何时能用网格

中栏可用宽行为
< 520px强制列表，网格按钮置灰 + 提示「当前宽度放不下网格，把窗口拉宽一些」
520 ～ 779px2 列
≥ 780px3 列
置灰而不是隐藏——直接照搬 NoteViewModeSwitch 里 splitDisabled 那段现成的论据：「拉窗口时按钮数量跳变比一个置灰的按钮更迷惑」。文案也照那个句式。
❗ 实现量的是中栏自身宽度（ResizeObserver，照 useCanSplitPane 的现成范式），不能用 useMediaQuery：中栏宽度受侧栏开合与第三栏拖拽（split.ratio）影响，窗口宽根本代表不了它。

封面图怎么来

// 纯前端，note.content 本来就是全文
const COVER_RE = /!\[[^\]]*\]\(\s*(<?)([^)\s"']{1,512})\1[^)]*\)/;
//                                        ↑ 限长 512：正文里可能嵌着 base64 巨串，
//                                          不限长会把几百 KB 塞进 img src
  • 每行跑一次正则，必须 useMemo 挂在 note.id + updated_at 上；
  • 只在网格形态算——列表形态不需要封面，白跑正则就是白花钱；
  • 图加载失败（路径失效 / 不是图）→ onError 直接降级成无封面卡，不摆碎图图标；
  • 懒加载：loading="lazy" + decoding="async"。

§9风险与不做清单

风险

风险应对
中栏三栏下只有 ~300px，控件放大后撑爆§1 的命中区扩展法（视觉尺寸不变）
命中区重叠，后定义的盖住前一个相邻小控件间距 ≥ 12px；逐个手验回收站那两个
封面正则碰到 base64 巨串限长 512 字符；只在网格形态算；useMemo
行高/字号全面抬高 → 一屏能看的条数变少真实代价，接受。扫得动比装得多重要
新增三个悬停按钮破坏 roving tabindex全部 tabIndex={-1}，靠快捷键可达
四个文件同时大改，回归面大分四批，每批单独验收可发；每批跑完整 vitest run

不做清单

  • ❌ 卡片上显「来自图片卡/文件卡」类型徽标——需给列表查询补 source_kind，是本轮唯一要动 Rust 的项，不值
  • ❌ 推翻三栏骨架 / 面包屑 / 搜问切换——作废 6 张已定稿，且不是「平庸」的成因
  • ❌ 自定义主题/配色——颜色全走 theme.css 现有 token，不另调一套（本来就是 9/02 那轮要消除的东西）
  • ❌ 虚拟滚动——网格形态会让一屏 DOM 变多，但分页（LoadMoreSentinel）已在，不提前优化
  • ❌ 笔记封面手动指定——要新字段 + 新 UI，自动取第一张先跑一阵

验收

  • 知识模式内所有可点目标命中区 ≥ 24×24（WCAG 2.2 AA §2.5.8），28 为基准
  • 知识模式内无小于 11px 的字号
  • 320px 最窄窗下不溢出、不出现横向滚动条
  • 网格形态：拖拽第三栏分隔线至中栏 <520px 时自动退回列表且按钮置灰
  • 无图笔记在网格里不出现空封面框；图路径失效时降级而非碎图
  • vitest run 全绿；tsc / eslint --max-warnings=0 为 0
