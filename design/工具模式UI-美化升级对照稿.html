3 · 三档升级方案

P0 微调对齐 半天

  • 静止态改 --card-bg + --elev（不再「空框」）
  • hover 影改 --float-card-shadow
  • 瓷砖 9→10，内圈按 V4 对齐卡 12
  • desc 两行截断；快捷键从 desc 拆出 kbd 芯片
  • 禁用：半透明 + title 说明原因

优点：改动只在 module.css + 少量 tsx，立刻和查找/菜单同语言。
缺点：无主次、无搜索，条目多了仍平。

P1 卡片体验 推荐

  • P0 全部
  • 高频双卡 hero 行（依次粘贴 / 片段库）+ 顶光
  • hover 出现 chev「›」，暗示可进
  • 分组标题带数量胶囊
  • 顶部筛选输入（本地 filter，无后端）
  • 瓷砖 hover 色相柔环

优点：一眼看出主次，扫描成本低；扩展性好。
缺点：要动 ToolboxView.tsx 结构；hero 要维护「常用」列表。

P2 重度产品化 暂缓

  • P1 + 收藏置顶 / 最近使用
  • 分组 chips 与搜索联动
  • 空态教学（搜不到时给「清除筛选」）
  • 与设置页「工具」权限/开关打通

优点：工具会继续多，先有壳。
缺点：和 D15「最小搬运」原则冲突，应等工具清单真的膨胀再做。

建议落地顺序：先 P0（一次 CSS 收口，风险最低、观感立刻齐）， 你点过觉得「还不够有主次」再上 P1 的 hero + 筛选。 P2 等工具数量或使用频率上来再说——现在 10 个工具做收藏/最近，收益小于复杂度。

不建议做的：给每张工具卡加 backdrop-filter（规则 8.3）；把 emoji 瓷砖全换成 lucide（会丢掉与顶栏工具箱历史一致的色相身份，且改动面大）。
