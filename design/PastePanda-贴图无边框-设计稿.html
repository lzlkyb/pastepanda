为什么描边要画在 fill_buffer 里，而不是用画笔画一个框
窗口是 WS_EX_LAYERED 且只设了 LWA_ALPHA，DIB 的 alpha 通道被系统忽略， 所以任何"半透明描边"用 GDI 画笔都画不出来 —— 只能画不透明像素。 而 fill_buffer 本来就是我们自己往 DIB 写像素的地方， 在那里把边缘一圈按 alpha 与底下的图混合，才能得到真正的"极淡"。

交互改动

操作现在改为
裸拖 平移图片（offset_x/y）。但窗口尺寸恰好等于图，没有可平移的余量， 拖出去的部分露纯黑（alpha 被忽略）。 移动窗口。移动超过 4px 才交给系统拖动循环 （ReleaseCapture + WM_NCLBUTTONDOWN/HTCAPTION）， 顺带白拿贴边吸附。
Ctrl + 拖— 平移图片。只有放大到超出屏幕、窗口被钳住时才用得上。
滚轮 只改图的缩放比，窗口不变 → 放大被裁、缩小露黑边。 缩放同时同步 resize 窗口（绕中心），图永远严丝合缝，黑边不可能出现。
鼠标移到顶部 —（关闭靠系统标题栏的 ✕） 右上角浮出关闭按钮：圆底 + 白色 X，压上去变红。 只在顶部条带（≈ 41 逻辑 px）内出现——X 是盖在图上的，一直挂着会挡内容。 窗口太小（装不下按钮 + 两侧边距）时不出现，避免盖掉整张图。
双击回截图窗重新编辑不变（纯击不进拖动循环，所以双击不受影响）
右键菜单：复制图片 / 重新编辑 / 旋转 / 翻转 / 关闭 / 关闭全部 位置与行为不变，新增「复制文字」：对贴图跑 OCR、全文进剪贴板。 后台线程跑（否则占着消息循环会让贴图假死），结果用底部 HUD 报 「已复制 N 字」；同一张图第二次点命中库里的 OCR 缓存，瞬时返回。
Esc / T / R / F / V / 0关闭 / 透明度 / 旋转 / 翻转 / 复原不变
要如实说明的两点
1. 阴影靠 CS_DROPSHADOW（窗口类样式）。它是给 WS_POPUP 这类窗口设计的， 但对分层窗口是否生效各版本行为不完全一致 —— 上图的阴影是预期效果，需要实测确认。 万一不生效，1px 描边仍然独立承担边界可见性，不会退化成"完全找不到边"。
2. 去掉 WS_THICKFRAME 后没有拖边缩放了。缩放统一走滚轮（本来就有， 且滚轮改的是图的缩放比，比拖边框改窗口尺寸语义更对）。

顺带收敛的东西

上一轮为了让"贴图 1:1"而加的那段 GetClientRect/GetWindowRect 差值修正 （CreateWindowExW 收的是外框、要减掉标题栏和边框），在 WS_POPUP 下差值恒为 0， 逻辑自动变成恒等式。代码保留（万一以后又加回边框，它仍然是对的），但不再有实际工作要做。
