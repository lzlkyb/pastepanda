1 · 写文件的活在哪边干

方案怎么做代价
甲·前端 fs 插件 TS 拼 frontmatter，逐个 writeTextFile N 篇笔记 = N+ 次 IPC；建子目录还得补 fs:allow-mkdir； 而且导入必然在 Rust，于是 frontmatter 会有两份实现
乙·后端 Rust 全包 选它 前端只用 dialog 选目录，把路径交给一个命令；std::fs 写完全部 一次 IPC；不碰 fs 插件权限；生成与解析天然坐在一起
选乙带出一个顺带改动（规则 #11）：frontmatter 的生成收口到 Rust 后， 前端「复制为 Markdown」也改调同一个命令，而不是自己再拼一遍。 否则“复制出去的格式”与“导出的格式”会慢慢漂成两种。代价：复制多一次 IPC（无感）。

2 · 导出的目录形状

你选的目录/
  工作笔记/                 ← 文件夹树原样铺开（B1 #1 才有的东西）
    NC 二开/
      单据模板要点.md
  未分类的笔记.md          ← folder_id 为空 ⇒ 直接放根目录
  _PastePanda导出说明.md    ← 一页：这是什么 / 怎么导回去 / 哪些东西没导
问题怎么处理为什么
标题里有 \ / : * ? " < > |换成 _ Windows 直接拒绝这些字符；不换就是导一半报错
同一目录下标题重复第二个起加 (2) (3) 笔记标题本来就不唯一（库里没唯一约束），不编号就互相覆盖、静默丢笔记
标题空 / 全是非法字符用 无标题-<id 前 8 位> 空文件名写不下去
标题很长截到 80 字符 Windows 路径总长 260，三层文件夹加长标题很容易碰到
文件名不可逆，所以导回来不靠文件名认人。 清洗过的标题、加了 (2) 的重名、截断的长标题——都回不到原标题。 身份靠 frontmatter 里的 pastepanda_id（见 §3）。

3 · frontmatter 字段与 YAML 转义

---
title: "会议纪要: 8/29 发布评审"      # 含冒号 ⇒ 必须加引号
tags:
  - 工作
  - NC 二开                              # 块式列表，不用 [a, b]
created: 2026-08-29 14:32:07
updated: 2026-09-01 09:10:44
pastepanda_id: 7c1f…                     # 回写靠它，不靠文件名
---

正文原样，[[wiki-link]] 一字不改。
决定理由
tags 用块式列表而不是 [a, b] 现有 noteToMarkdown 写的是 [a, b]：标签名里有逗号或方括号就直接碎。 块式每行一个，只需处理行首特殊字符
字段名用 tags / created Obsidian 的约定就是这两个；叫 note_tags 它不认
多写一个 pastepanda_id Obsidian 对不认识的字段是原样保留的，所以它能安全地跨软件往返一趟
不写 aliases 库里根本没有别名这个概念。写一个恒为空的字段是噪音

转义规则（就这三条，不引 YAML 库）

  1. 值含 : # " '、首尾空白、或首字符是 [ { - ? & * ! | > % @ ` 之一 ⇒ 加双引号，内部 \ 与 " 转义
  2. 值含换行 ⇒ 也加双引号，换行写成 \n（标题里不该有，但不能假设没有）
  3. 空值字段直接不输出这一行，不写 tags: []
为什么不引 serde_yaml：写只需要这三条；读也只需要认 5 个已知字段（其余行直接忽略）。 引一个完整 YAML 解析器去读 5 个字段，换来的是它对错误缩进 / 错错缩进的整套语义——而那些情况我们反正都要降级处理。

4 · 导入：三级匹配

顺序条件动作
①有 pastepanda_id 且库里还在 更新那条（走 note_update，因此自动留下一份版本快照，#4 白送的）
②有 id 但库里已删 / 没有 id 按【目标文件夹 + 标题】找；找到就更新
③都没找到新建（按目录层次自动建文件夹，超过 3 层的就平接到第 3 层）
导入永远不删库里的任何东西。 它是「合并」不是「同步」： 目录里没有、库里有的笔记原封不动。 双向同步要处理删除传播，而一次选错目录就能把整个知识库清空——不值。
边界处理
没有 frontmatter 的纯 .md（Obsidian 里随手建的） 照收。标题 = 文件名（去 .md），标签空，正文全文
frontmatter 坏了 / 不闭合 当成没有 frontmatter，整个文件当正文。不报错中断整次导入
非 .md 文件 / .obsidian/ 等隐藏目录跳过，计入「已跳过」
单个文件读失败 / 非 UTF-8跳过并记下文件名，结果里列出来（规则 #15.3：不静默）

5 · 入口与反馈

放设置 → 数据管理，紧跟在现有的「导出数据 / 导入数据」（那两条是历史记录的 JSON）之后， 新增两行：导出笔记为 Markdown 目录 / 从 Markdown 目录导入。

两组文案必须能一眼分开。现有那两条只写「导出数据 / 将历史记录导出为 JSON 文件」， 新增的写清楚是笔记与目录——否则用户会以为导了一份就什么都备份了。

完成后用 toast 报真数字，不报「完成」：

导出：已导出 46 篇笔记到 12 个文件夹
导入：新增 8 篇、更新 3 篇、跳过 2 个文件

6 · 不做清单

不做理由
附件 / 图片导出根本没有附件通路（§0）。归 D9 note_attachments
双向同步 / 监听目录变化那是 D10（云同步）的活，且是将来的付费项
导出时按文件夹 / 标签筛选第一版就是全量。部分导出的 vault 打开后 wiki-link 会断，反而像坏了
导入时认 [[wiki-link]] 建关系D7：解析归 C 阶段。现在只是字符串
冲突时逐条问用户几十个弹框没人能认真回。规则固定（§4），而且更新都有快照可回退

7 · 验收

  1. 导出后把那个目录当 vault 直接用 Obsidian 打开：文件夹层次一致， 标签在右侧面板里能被识别成标签（不是一堆纯文本）
  2. 标题里带 : 与 / 的笔记：文件能建出来，且 Obsidian 不报 frontmatter 错误
  3. 同一文件夹两篇同名笔记：导出成两个文件，一篇不丢
  4. 导出 → 在 Obsidian 里改一篇 → 导回来：改动生效，且那篇笔记的 历史里多了一份导入前的版本（#4 联动）
  5. 同一个目录连导两次：第二次新增 0 篇（全部走到①更新），不会翻倍
  6. 拿一个不是 PastePanda 导出的 Obsidian vault 直接导：能进来， .obsidian/ 被跳过，一个都不报错
  7. 导入一个有坏掉 frontmatter 的文件：它以「整文为正文」进来，其余文件不受影响
  8. 导入永远不删：库里有但目录里没有的笔记，导完还在
