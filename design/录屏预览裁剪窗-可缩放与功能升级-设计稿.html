窗口缩放 / 最大化不可 mod.rs:163 的 .resizable(false) 直接掐死。改 true + min_inner_size(720,480)，保留 decorations(false) 自绘三键（复用 rc_window_* 三条命令，它们取注入窗口，不限 label）。 Rust 1 行
记住窗口尺寸不可 tauri-plugin-window-state 已全局装（lib.rs:206），窗口一旦 resizable(true) 就自动持久化；需确认 MAXIMIZED 位恢复行为符合预期，必要时在 open_preview_window 里恢复「上次尺寸但非最大化」。 验证
缩略帧时间轴无 前端 canvas 从 <video> seek 抽 N 帧（N=10–16，按时长定），一次性画成一条 <canvas> 底图。大文件首帧 seek 慢时可先出 4 帧再补齐。 纯前端
逐帧 / 倍速 / 音量 / 循环 / 全屏无 全部走 HTMLVideoElement。逐帧精度取决于能否取到 fps：没有 fps 只能按 1/30s 近似，所以这里挂一个后端小命令返回真实 fps（moov 的 stts 解析，scan.rs 已有 moov 读取）。 fps 需后端
I / O 标入出点只能拖 播放头处一键设起点/终点，复用现有 snapTrimRange 吸附。 纯前端
导出 GIF后端已有 rec_gif_start/status/cancel 四期已实现，但预览窗没有入口（只在最近录制列表）。这里补入口 + 进度 + 取消。注意：GIF 当前只导出整段，不接受 in/out——入口文案必须写「整段」，否则是假承诺。 纯前端
文件信息（编码 / 码率 / 音轨）无 分辨率与时长前端可读；编码与码率读不到，需后端解析 moov 后返回。 需后端
多段裁剪 / 转码压缩无 不进本轮：多段需要重封装修复时间戳与 sidecar，压缩需要引入编码管线，量与风险都不是「界面升级」的范畴。 不做
