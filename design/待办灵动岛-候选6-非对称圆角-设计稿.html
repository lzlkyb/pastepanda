候选判读
顶 6 / 底 12方感过强——差 6px 时顶角明显「缺了一块」，且与底部差距大到第一眼像 bug，不像设计
顶 8 / 底 12✅ 采用——差 4px：单独看顶角只觉得「利落」，与底角并排才读得出层次；8 与 12 都是 U5 token，不新增档位
顶 10 / 底 12差 2px 不可辨——做了等于没做
V4 同心自查：头部 seg（8px）与顶角不在同一角点（seg 在 40px 头条内部、距顶 12px+），不构成嵌套同心；列表行 8px、输入框 8px 与顶角同值属「同值复用」而非嵌套，合规。

四 · 落地账（❗ rgn 必须跟着改，否则顶角月牙复发）

现在的窗口形状由 SetWindowRgn 裁剪（追月牙时加的），而 CreateRoundRectRgn 只支持统一圆角。 若只改 CSS（顶 8）而 rgn 仍是 12：顶角在 8–12px 弧之间的窗口级材质会裸露出来——3a 之前那个「材质月牙」在顶角复发。 所以 rgn 要拼一个非对称形状：整卡 r=12 ∪ 顶部圆角条 r=8（CombineRgn(RGN_OR)）， 条高取 12×scale 即可（中部由整卡全覆盖，条的底边圆角被盖住）。 
// CSS —— TodoIsland.module.css（展开两态一行改掉）
.root[data-st="list"], .root[data-st="compose"] {
  border-radius: 8px 8px 12px 12px;  // 原 12px
}
// 过渡不用动：border-radius 四角独立插值，999 → 非对称照常过渡

// Rust —— todo_island_stage.rs::apply_stage_region（展开两态分支）
// 原：CreateRoundRectRgn(0,0,w+1,h+1, r12, r12)
// 新：r12 整卡  OR  CreateRoundRectRgn(0,0,w+1, 12*scale, r8, r8)
//     全部经 CombineRgn(RGN_OR) 合并后 SetWindowRgn —— 一次 set，无逐帧成本
动画中间帧：舞台动画起止各 set 一次 rgn（现状），动画中窗口矩形逐帧变、rgn 不逐帧跟随—— 顶角 4px 差异在 200/300ms 动画里不可辨，不为中间帧做非对称（照旧走 apply_stage_region，组合形状收口在这一个函数里，起始帧/终帧/on_page_load 三个调用点自动继承）。

五 · 影响面与不做的

项说明
CSS 改动1 行（.root[data-st] 展开块）；折叠三态、列表行、seg、输入框圆角全部不动
Rust 改动仅 apply_stage_region 展开两态分支（+CombineRgn 导入）；折叠三态的胶囊 rgn 原样
探针PP_TODO_ISLAND_PROBE=1 形态回归照跑；本轮加一张展开态抓图核对顶角无材质裸露
测试现有舞台尺寸/交互测试不受影响（rgn 是纯 Win32 侧，无新可测纯函数——形状正确性靠探针抓图判定）
明不做折叠三态非对称（破形）；中间帧逐帧非对称 rgn（不可辨 + 逐帧 set rgn 是新成本）；顶部方于底部只此一档，不做配置项
