无人值守出码首屏减负：一键默认 + 高级折叠

对标 Chrome Remote Desktop 的无人值守设置（一台设备一个 PIN，零选项）与 AnyDesk「Accept unattended access」一键语义。 现状问题：生成前要先做 5 个决定（时效 2 选 1 + 能力 2 选 1 + 免确认勾选），而 90% 的使用场景就是「帮人修一次电脑」—— 默认值已按此设定（15 分钟 · 限 1 次 · 可控），但界面强迫用户逐行扫过才能点按钮。

二、为什么这样切

  1. 「预览默认值」而非「隐藏默认值」：Chrome RD 是零选项（PIN 制），但我们安全语义更多（时效/能力/免确认），全藏会误导——所以把默认值升格成一句加粗承诺放在按钮正上方，规则 17「高频路径一步到位」+ 规则 9「边界透明」的折中。业界完全零选项不适用于「可撤销时效码」这种模型。
  2. 高级区保留全部既有 radio/checkbox：不是砍功能，是换可见性层级。装机/挂机（24h）、代看（只看）、常用搭档（免确认）各归其位。
  3. 未开「允许被远程」的 noteWarn 条位置不变（规则 15：反馈与触发同域），仍在承诺句下方、按钮上方。

三、落地要点

  1. 单文件改动：RcUnoGeneratePane.tsx（147 行 → 约 170 行，仍 <300）。state 与 generate() 零改动——只是渲染分层：未折叠时按默认值生成，radio 组原样搬进 <details>。
  2. 样式：新增 .unoDefaultLine（加粗承诺行）与 .unoAdv（details 壳，background: var(--panel-2) 级别、圆角 8、无 backdrop-filter——规则 8.3），大按钮复用 .miniBtnPri 扩一个 .unoBtnBig（padding 9px 20px）。
  3. 键盘可达：<details> 原生可聚焦可展开，不写 JS 开关；符合规则 17「鼠标全流程可达、键盘是加速器」。
  4. 文案审读（改前过 UI 规则 L1–L6）：承诺句「将生成：15 分钟 · 用 1 次 · 可控的接入码。」——句号结尾、无黑话；summary「高级：改时效 / 只看画面 / 免确认」列出内容物而非「更多选项」。
  5. 验证：RcUnoDialog 既有测试改 2 条断言（默认首屏不出现「24 小时」文本 → 改为在 details 内 query）；新增「不展开直接生成 ⇒ payload 为默认三值」。
