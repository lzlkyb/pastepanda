0 · 先说成本重估（比上一稿评估的便宜）

上一稿 §6③ 写的代价是「需要改 SetWindowRgn 拼新形状 + Rust 舞台加新分支」。读完 stage.rs 后修正： rgn 拼装函数 build_top_rounded_region(dst, w, h, r_card, r_top) 本来就支持顶/底两个半径 （list/compose 的四角统一 12 就是走它），顶平方角 = r_top=0、r_card=高/2，拼装代码零新增。 真实的改动点收口为三处同步账（本稿 §2–§3）+ 一条真实风险（§2 过渡期 rgn 与 CSS 的错拍），总体是 小批量、可独立回退的一档改动。另有一条「免费正确」：hide/show 后的自愈重放 reapply_stage_region 按 current_stage() 现算形状——形变落地后它自动按 HalfCapsule 重裁，零代码改动，也堵住「重放会不会裁回旧形状」的疑问。

2 · 角部放大 3×：这条缝就是本稿要消灭的东西

壁纸缝
（上圆角外） 现行：距顶 4px 处缩进 ≈5.4 逻辑px，缝里透出壁纸
本稿：上缘满贴屏幕边，缝消失；下缘半圆帽收尾
几何账：上圆角 = 高度一半的半圆帽，顶部两侧各让出 r−√(r²−(r−y)²) 的缝

32px 高的胶囊上圆角 r=16，顶部两条缝在距顶 4px 处各宽 ≈5.4 逻辑px（y=1 处 10.4px、y=8 处 2.1px，随行递减到 0；口径：缝宽 = 16 − √(16²−(16−y)²)，y=1 精确值 10.43）——单看很小，但它们正好位于「吸附感」最敏感的 顶边接触线上：缝在，岛读作「贴在墙上的胶囊」；缝没，岛读作「从墙里长出来的」。 iOS 灵动岛 / 刘海系应用全都是「方顶 + 下缘圆」或「完全嵌入」，没有悬浮留缝的先例（吸附设计稿 §1 共识③）。

3 · 形状账（三处同步，一份清单钉死）

处现行本稿改动
① CSS 圆角
TodoIsland.module.css		.root 恒 999px停靠态（pill/clear 且非 hover）border-radius: 0 0 16px 16px（= r=h/2；不可写 999px——上角为 0 时那个值会被 CSS 缩放规则拉成 r=h，实测成「拱门」形）；peek/list/compose 不变新增一个选择器块；200ms 圆角过渡 .root 已有，无需新增
② 窗口 rgn
stage.rs::apply_stage_region		Pill/Clear/Peek → stadiumPill/Clear → build_top_rounded_region(r_card=高/2, r_top=0)；Peek → stadium（不变）；list/compose 不变拼装函数零新增；但要动两处 match——radius（GDI 兜底参数）与 hrgn 分支现在都把 Pill|Clear|Peek 并在一起，需拆出 Peek 单走 stadium。GDI 兜底 CreateRoundRectRgn 只有统一半径，HalfCapsule 的退化形态指定为退 stadium（radius=floor(h/2)，参数来源不变）——统一半径的胶囊比 12px 整卡在轮廓上更接近目标形状，且兜底路径零改动。逐行像素中心判据现成（月牙守卫测试直接复用口径）
③ 命中形状
hover.rs::shape_hit		Stadium / Rounded 二值新增 HalfCapsule（上缘平、下缘 r=h/2 半圆帽）变体，把 shape_hit 的参数化从「统一半径」扩成「上下角半径可不同」：等距外扩后仍是同族凸形 ⇒ 上角半径 pad、下角半径 h/2+pad，直接套现成的圆角矩形含点判定纯函数小改 + 守卫单测（上缘外 1px 命中、上角 45° 径向带内/带外、下弧与 stadium 同口径）。不可写成「上缘 y∈[−pad, r) 也算核心带」——那等价于上角按直角算，比正确值多拦 ≈pad(1−1/√2)≈0.6px，破坏「命中边界 = 可见形状 + pad」不变量

🔴 同步规则与既有口径一致：改形状必须三处一起动（module.css 文件头、stage.rs rgn 注释都有这条账）。 漏掉③的失败方式很隐蔽：视觉是方的、命中还是胶囊——上缘两角的光标点了没反应（401 式静默错位）。 漏掉②的失败方式：CSS 方角但窗口 rgn 还是胶囊 → 上缘两角被裁成透明方角缺口。

4 · 过渡：形变怎么动（含一条要实测的风险）

期望动线：停靠（方顶）→ 停 240ms → peek（圆顶）——宽度 208→300、高度 32→40、顶角 0→半圆， 三个属性在窗口弹簧 + CSS 圆角过渡里同时发生，「方角冒出圆头」是这条动线的卖点。试玩下方演示感受手感。

真实风险（网页模拟测不出来）：窗口 rgn 不逐帧插值，只在动画起始 / 终帧两次切换 （stage.rs 现有口径）。胀出方向 rgn 比窗口大 = 不裁、无副作用 ✅；收回落向时 rgn 立即按目标形状裁 → CSS 卡片还在 200ms 圆角过渡的中途，rgn 永远赢（窗口裁剪是最外层），视觉上形状立即切方、 内容圆角随后跟上——预判是「可接受的小错拍」，但必须真机验证两方向都不露材质月牙 （rgn 与 CSS 半径错拍的月牙机制，stage.rs 有过两轮实拍教训）。若露，兜底是收回落向的 rgn 延到终帧再切 （具体位置已标注在 §7①）。

演示与真实链路的差异（诚实声明）：演示的 mouseleave 立即回落；真实链路是 60ms 轮询采样 + 6px 离开外扩 + 200ms 过渡，回落比演示「钝」一拍。方向上演示偏乐观，量级无害——手感以真机为准。

5 · 边界清单（每条有归属）

场景处理
全清 clear 态（同停靠）同样方顶（同一选择器/同一 rgn 分支）；勾 + 「今天没有待办了」照旧
提醒态（铃 + 到点了）同样方顶——提醒更需要「长在上面」的醒目感，不另开形状
浅色主题只动圆角不动材质令牌；白玻璃方顶压亮壁纸靠描边 + 投影保边（既有结论）
命中上缘（y≈0 一线）HalfCapsule 上缘平直：上缘外 pad 带内命中。行为变化：顶部两上角由「穿透死角」变「拦截」——stadium 时代这两块（各约 55px²）穿透到下层（标签栏高度），方顶后 208px 整条拦截。语义自洽（可见即命中）但改变已养成的点击习惯，有意行为变化，随形变生效，特此留账（原「与死角不拦不变量一致」的表述作废：上角现在没有死角）
减少动态效果CSS 圆角 200ms 过渡现行未被 reduced-motion 门控（与 list 态 300ms 现状一致，非本稿引入）。但本稿把形变变成主角：系统开启减少动效时，建议形变走「快切」（圆角过渡压缩到 ≤80ms 或直接禁用），与窗口侧 ease_progress 回退路径同拍——已入 §7③
多屏 / DPIrgn 的 r_card=高/2 按物理尺寸现算（stadium 同款），无新账
列表/输入态完全不变（12px 卡，与方顶无关）
回退三处改动可单独摘除：CSS 选择器块 / match 分支 / shape_hit 变体，互不牵连

6 · 得失与推荐

得：顶边接触线零缝隙，「长在屏幕上」的吸附感补完最后一块（TOP_MARGIN=0 解决了纵向间隙， 本稿解决横向圆角缝）；停靠「方」↔ 浮起「圆」的形变对比让两态区分更明确。
立项口径（critique 后调整）：消灭缝优先、形变语义为附带表达。理由：「方=吸附 / 圆=浮起」 的二分在展开态就不成立（list/compose 顶边同样贴死 y=0 却是四角全圆的卡），把立项押在语义叙事上 等于背一笔未验证的账；而「消灭缝」是纯视觉收益、无需验证即成立。语义若要做实，条件是 3 人快测 （方顶岛截图混入其他顶部 UI 截图，问「这是什么」）——列为可选条件，不作为前置。
失：三处同步账（有守卫测试兜底）；收回落向的 rgn/CSS 错拍需真机验证（有兜底方案 + 判据，见 §7①④）； 与既有「候 6 非对称圆角已收回」的决策表面相似——注意那条收回的是展开卡的顶 8 底 12（观感理由）， 本稿是停靠胶囊的 0 / 半圆（消灭缝），不构成推翻。
推荐：值得做，按 §7 顺序一小批落地（rgn → shape_hit + 单测 → CSS → 真机验证错拍）， 与吸附双态已落地部分合并验证。

7 · 落地清单（拍板后执行）

① stage.rs::apply_stage_region：Pill/Clear 分支改走 build_top_rounded_region(r_card=h/2, r_top=0)（Peek 不动，两处 match 拆分）； GDI 兜底退 stadium（floor(h/2)，参数来源不变）；新增 rgn 守卫测试（复用 test_stadium_region_hugs_css_cap 口径：上缘满行、下弧贴 CSS 圆）。
❶ 终帧切兜底的位置（预写，不等翻车才找）：收回落向若真机见月牙，把 animate_window 里 growing == false 情况下「动画起始处的 apply_stage_region 调用」跳过、只保留 std::thread::sleep(120ms) 后终帧那次按实测尺寸的精裁——改动范围 = 一个 if 分支，无新账。
② hover.rs：IslandShape::HalfCapsule 变体 + shape_hit 参数化扩成上下角半径可不同 （上角 pad、下角 h/2+pad）；单测：上缘外 1px 命中、上角 45° 径向带内/带外、下弧与 stadium 同口径。
③ TodoIsland.module.css：停靠态圆角块 border-radius: 0 0 16px 16px （❗ 不能写 999px：上角为 0 时那个值会被 CSS 缩放规则拉成 r=h，与 rgn 错配；Pill/Clear 恒 208×32）； 选择器与停靠态投影块同口径（pill/clear 且非 data-hover）； reduced-motion 门控：系统减少动效开启时圆角过渡压缩到 ≤80ms； aria 一行：collapsedLayer 的 aria-label 扩为含状态（如「待办列表，已吸附在屏幕顶部」）——形状是纯视觉通道，语义层一行兜底（键盘可达性是基线既有缺口，单独立项不混入本批）。
④ 真机验证（dev），含 critique 补的可判定验收线：
・验收线 A：peek→pill 收回落向，前 3 帧（≤50ms）内无可见形状撕裂 / 月牙（rgn 起始即切 vs CSS 200ms 追赶的错拍窗口）；
・验收线 B：peek↔pill 快速往复 5 次（鼠标在进/出带间晃动）无轮廓方↔圆闪烁感（两态同形的现行版本闪的是尺寸，本稿闪的是形状，显著性高一档）；
・掠过顶部边缘（y≈0）穿透无拦截；上角由穿透变拦截的行为变化实际点一遍确认无碍；
・提醒态 / 全清态各看一眼；浅色主题亮壁纸看一眼；100% / 125% / 150% 三档缩放下顶缘与屏幕边无缝（方顶对 y±1px 定位误差比 stadium 敏感，直边一旦离边就是通长缝）。
