远程电脑 · 会话页布局重构 — 方案对比

起因：用户指出「画质这个功能重复了」。核实后确认——同一屏里确实同时存在两组同构的画质控件， 而且它们改的不是同一个东西。本稿先定性问题，再给业界基线，最后给三个方案与 1:1 复刻。

一、问题：一屏两组「画质」，且它们改的不是同一个对象

一句话：侧栏那条改的是「本机被控时推给别人的档」（空闲态配置）， 底栏那条改的是「要求对方推给我的档」（会话中操作）。 两者档位名完全一样（自动/流畅/均衡/清晰/超清/原生）、外形完全一样、出现在同一面屏幕里 —— 只有一行 11px 小字在区分。

二、别人怎么做

查了 4 家（含官方文档）。没有一家在会话页里同时摆两组同构控件，也没有一家把"本机配置"常驻在会话页。

AnyDesk
画面（占满）
小工具栏 · 文件 / 截图 / 显示▾
画质与视图默认值在 Settings → Display；会话中改则走工具栏的 display 菜单。官方原话：工具栏「stays relatively unobtrusive」。
RustDesk
画面（占满）
顶部工具栏（可 collapse）
有 collapse-toolbar 设置：连接后自动收起工具栏。画质/视图/滚动样式都是 Settings 里的默认项 + 按对端记忆。
Chrome 远程桌面
画面
▸
屏幕边缘一个可折叠的小浮条，hover 才展开。设计目标写明是「designed to stay out of the way」。
TeamViewer
画面（占满）
顶部功能栏：聊天/文件/录制/…
主窗口左侧是导航面板（连接/远程控制/会议）—— 但那是连接前的界面，会话开始后不跟着进会话页。
三条共识
  1. 会话页只服务画面。控制项收进一条工具栏，且普遍可折叠/可收起（RustDesk、CRD 都是显式特性）。
  2. "配置"与"会话操作"分属两个空间。画质、视图这些默认值放设置窗口；会话中改它们属于"临时覆盖"，走菜单而不是平铺。
  3. 连接前的界面不进会话页。ToDesk / 向日葵 / TeamViewer 的主界面（左导航 + 设备区）在会话开始后就让位了。

三、三个方案

共同前提：同一时刻只允许一条画质控件存在。差别在于这条落在哪、以什么形态出现、侧栏要不要让位。

方案 A｜同屏互斥（最小改动）

只加一条规则：出站会话进行中，侧栏不再渲染画质/画面组；空闲与入站（别人控我）时照旧渲染 —— 因为那时它是唯一入口，且入站时它改的正是当前生效的档。底栏保持现在的平铺形态不动。

推荐：A 先落地，B 作为目标形态排期；C 不做

A 直接解决用户报的"重复"，且几乎零风险 —— 它只是让两条互斥，顺手把 RcWorkbench.tsx 的 301 行债务还掉。做完这一版，"重复"和"撒谎级语义错配"就都消失了。

B 解决的是"然后呢"：画面被侧栏压窄 272px、底部三条横条各自带边框。 这是本产品「用户视角指标」上最划算的一步（画面 +220px 宽），但涉及会话内布局重排， 建议单独一批做，并配一次真机双机手测（会话中改档的链路要重跑）。

C 不建议做：多出一个"模式"概念，就得回答"我在哪个模式""怎么回设备列表"， 而这套产品的会话本来就是从工作台发起的低频动作 —— 收益（再宽 52px）撑不起这个复杂度。

五、口径声明

  • 复刻稿的尺寸取自实现：侧栏 272px（.wbSide）、 胶囊 11px / 3px 10px / radius 20px（.pill）、 画质条 padding 8px 10px（.qBar）、 顶栏 padding 8px 12px（.viewTop）， 配色取 [data-theme="ocean"] 的值。会话内深色叠层用的是 .viewShell 后代那套半透明规则，不是浅色基类。
  • 业界四家形态来自官方文档与帮助中心（AnyDesk Display settings、RustDesk 高级设置、 Chrome 远程桌面会话工具栏说明），线框是特征示意，不是 1:1 复刻。
  • 画面宽度三个数字都是 headless Edge 实测（量 .fakeScreen 的 getBoundingClientRect().width）：现状 / 方案 A 892px、方案 B 1112px、 方案 C 1198px。⚠️ 别用「1200 − 侧栏宽」直推 —— 主区还有 padding 14px 16px 与 1px 边框，这次初稿直推出 1148px，实测 1112px， 多算了 36px（已按实测改）。侧栏画质条在 247px 可用宽里实测高 161px。
  • 本稿只做方案，未改任何产品代码。

落地时改了稿子的五处（都有具体理由）

  • ① 侧栏收起只在「有画面」时生效（出站会话）。 被控会话时主区是信息卡、没有画面，把侧栏收窄换不来任何东西，反而把 「允许被远程」这类本机状态藏起来。
  • ② 侧栏轨只放「展开按钮 + 状态图标」，不是稿里那三个（设备 / 配对 / 设置）。 会话中点开配对框、跳主窗设置页都会打断会话；这条轨的语义应该是「侧栏的收起态」， 而不是第二套导航。状态用图标（盾 + 对勾 / 盾 + 斜杠）而非色点——「允许被远程」 是个开关状态，只靠颜色对色觉障碍用户等于没有信息。
  • ③ 键盘 / 指针 / 全屏留在画面内的浮层（RcViewTools），不进底栏。 全屏按钮必须在 .fakeScreen 内部：全屏的是画面元素本身， 底栏不会被一起全屏，按钮放底栏等于全屏后消失、只剩 Esc 能退出。
  • ④ 结束会话只留顶栏一处。稿里顶栏与底栏各画了一个（重复）。而且它是危险操作， 放在最容易触达的底栏右端反而增加误触；顶栏右上角是它的常规位置。
  • ⑤ 顶栏的「键盘：未捕获 / 已捕获」胶囊删除。同一状态原来在顶栏是一个胶囊、 在底栏 statusBar 是一句话，这就是重复；现在只留底栏状态区一处，并按能力分档 （「只看」会话不摆这条——按键本来就发不出去）。

顺带的改动（不在稿子里，但落地时必要）

  • RcStatusBar.tsx 删除——内容并进底栏状态区。
  • RcQualityBar 删掉 mode="remote" 那一支： 它现在只剩「本机被控画面」一个语义，localNote 由可选变必填。 会话中改对方画质归 RcSessionBar 的下拉（失败回滚）。
  • RcWorkbench.tsx 301 → 282 行：发起链路（能力档 / 上次设备 / 重试目标）抽成 useRcLaunch.ts。这一节本来就是方案 A 要还的债， 方案 B 还要往里加「侧栏收起」状态，不抽必撞 .tsx ≤ 300 红线。
