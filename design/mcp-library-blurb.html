2026-09-04 · 后端已完成（576b439），本稿只定这一块设置页的交互。

这个功能的危险不在实现错，在于用户以为自己在填一个「库简介」，实际上在授权一份常驻的系统提示。
MCP 的 instructions 是一条推通道：内容不经任何工具调用就到了模型手里， 每次连接都付一遍，因此也不进调用记录——旁边那个「调用记录」面板看不到它。 所以这一块的每个交互决定都要按「用户会不会误以为这只是备注」来审。

2. 三条反直觉的交互约束

约束为什么
不提供「全部采用」 建议内容是「顶层文件夹名 + 篇数」。一个全选按钮就把「展示 ≠ 推送」那道墙拆了—— 用户点一下，整份文件夹名就推给了每一个连上来的客户端。只能逐条勾选或手打。
建议区默认折叠，且折叠态不读文件夹名 不点开就不去查库。这样「我只是路过设置页」不会让敏感名字被渲染出来， 也让「点开」成为一个明确的动作。
顶部必须写重话 「每次连接」「不经工具调用」「不进调用记录」三个词一个都不能省。 省掉任何一个，用户对这段文字的心理模型就退回成「一条备注」。

还有两条来自后端的既定行为，界面要如实反映

  • 超长按字符截断，不报错。用户粘一大段进来，报错让他自己数字数是把麻烦丢回去。 界面给实时字数 + 超限变色，保存时静默截到 500。
  • 留空 = 不推，而不是推一段占位说明。占位说明同样是「每次连接都付」的开销。 所以空态下上面的预览区应当明确显示「不推送任何内容」。

3. 放在哪

MCP 设置区现在的顺序是：连接字段 → 写权限 → 调用记录 → 接入指引。

建议插在 写权限之后、调用记录之前。理由不是排版： 写权限回答「它能对我做什么」，库简介回答「我主动给它什么」，两者是一对； 而紧挨着「调用记录」放，正好让用户在读到「这些调用都有记录」的前一屏， 先看到「这一段没有记录」。
