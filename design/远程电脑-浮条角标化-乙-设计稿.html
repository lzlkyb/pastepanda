# 残留 甲之后还剩多少 乙的对策
R1 收起态没有任何出口 2.5s 淡出后画面上一条 UI 都不剩。想知道「连着没 / 画质 / 结束会话」必须先靠 顶缘 3px + 站住 180ms 或 F10——第一条对远端内容仍有残留风险， 第二条没有可发现性（没人知道 F10）。 顶缘正中留一枚 24×12 的把手角标：常驻、可点、点一下才展开胶囊。
R2 顶缘仍有一段「经过即可能触发」 3px × 180ms dwell 已经把误触压到很低，但机制还在（本稿提供开关演示）。 把手出现后，hover 唤出从「唯一出口」降级成「加速器」，可以关掉； 关掉后顶缘零触发，与 RustDesk 新版同构（待拍板 ①）。
R3 异常只剩一条 3px 微光 链路异常时靠 .capAlarm（3px 红渐变）+ 浮条锁显；但 .capAlarm 在 .capZone 里，胶囊一旦收起就一起被 visibility:hidden 带走（规则 15.1 的同源问题）。 把手就是那个不被卸载的常驻载体：绿点=正常，整枚染红=链路异常，整枚染橙=有等你处理的事。

    3. 新增控件申报（几何 / 色值 / 命中区）几何

    量 本稿取值 为什么是这个数 来源
    把手可见尺寸 24 × 12 px 刚好容下一枚 8px 状态点 + 上下各 2px；12px 高 ≤ 胶囊的 margin-top， 于是把手落在遮挡带之外（y 0–12，遮挡带是 12–46），展开胶囊时两者不打架。 新提
    命中区 40 × 15 px（::after 左右各 -9、下 -4；实测见 §1 演示区读数） 贴屏幕顶缘的目标在 Fitts 里高度算无限，宽度补到 40 就够点；仍小于 24×24 的 WCAG 目标档，用 F10 等价键盘操作兜（AA 的 equivalent-control 例外）。 2026-09-29 C 项改口：下探从 -9 收到 -4，吃进遮挡带（y 12–46）由 8px 降到 3px—— 那 8px 全屏时正压在远端标签 ✕ 那一行，与甲方案「别在往上够标签的路上吃点击」相抵。 新提
    位置 top: 0; left: 50%; translateX(-50%) 正中避开 Chrome 标签（靠左排）与「新建标签 +」（右移），也避开 Windows 窗口三键（最右）。 新提
    底色 / 描边 / 模糊 rgba(13,16,22,.82) + blur(14px) + 描边 rgba(255,255,255,.12)（顶边不描） 与 .capCapsule 同一块深玻璃，不新造视觉语言；顶边不描边因为贴住屏幕边缘。 真值
    圆角 / 投影 下沿 0 0 8px 8px（本稿原写 7px，落地归到 U5 的 4/8/12 档）；0 4px 12px rgba(0,0,0,.32) 「从顶缘拉出的一小格」的形状，读起来是把手而不是圆点。 新提
    状态色 绿 var(--green,#2f9e5f) / 异常整枚 rgba(214,69,69,.9) / 待处理整枚 rgba(224,128,58,.92) 沿用 .live / .liveBad 现成语义色，不新增色。2026-09-29 F 项改口： 原先「待处理」是右上角 var(--warning) 的 7px 外挂橙点（top:-3px）， 在全屏态（.capZone 贴 top:0）被窗口上缘裁掉 3px、只剩半个点； 本稿演示区在页面里没有真窗缘，这处暴露不了。改成与异常态同构的整枚染色后， 四档 idle/bad/ask/dim 各一块整色，没有任何可被窗缘裁的元素。 电点在两档里方向相反（红底转白、橙底转深），判据都是与底色拉开 3:1（WCAG 1.4.11）。 真值
    层级 z-index: 6（胶囊 .capZone 是 5） 展开时的让位**不在层叠上**（同级胶囊是 z-index:auto，正数一律压不过）， 而是把 ::after 下探收回（.capHandleBehind::after{bottom:0}）， 命中盒从 40×15 收到 40×12，不再抢胶囊上沿那一击。 真值+新
    指针锁定态 opacity:0 + visibility:hidden + pointer-events:none 锁指针时本地根本没有光标，常驻把手只会白白占像素（与甲里「锁指针不唤出」同口径）。 沿用现规则
    焦点环 outline: 2px solid var(--accent); outline-offset: 2px（:focus-visible） 不新造环：这就是 globals.css:103 那条零特异性兜底给所有 button 的画法。把手常驻 Tab 环（§6），所以必须看得见焦点。 真值
    胶囊几何 不动（margin-top: 12px / height: 34px / --rc-session-chrome-h: 36px） 2026-09-28 方案 A 已拍板（文档 §5 不可重开）。 保留
    甲的四条（3px / 隐形胶囊不算目标 / 180ms / 200ms 穿透） 不删 把手只是补出口，不是替代 hover。是否保留 hover 见待拍板 ①。 保留

    4. 为什么是「顶缘正中」而不是角落

    候选位 会撞上什么 结论
    顶缘正中（本稿默认） Chrome/Edge 标签靠左排、新建标签「+」在标签组右端、窗口三键在最右——正中通常是 标签栏空白；y 0–12 又高于遮挡带起点 12，不压任何按钮。 建议
    顶缘 35–65% 随机钳位 躲开正中，但每次会话位置会跳，肌肉记忆建立不起来；正是 RustDesk #3842 的处理对象（它钳位是为了避开折叠钮自己，不是为让路给内容）。 作为演示开关保留，不作默认
    右上角 Windows 的「关闭 ✕」就在这（最大化窗口 12–16px 宽、贴顶缘）——把遮挡缺陷搬了个家。 否
    右下角 / 底部中央 右下角是 Windows 的「显示桌面」热角；底部中央是被控端任务栏（开始按钮/搜索框）。 否
    画面外（窗口标题栏 / 系统托盘） 窗口态没有自定义标题栏（文档 §6.7），托盘红环六家无先例且 grep tray src-tauri/src/rc/ 零接线。 属于丙档，不在乙里做

    5. 状态表（把手要承接什么）

    会话状态 把手外观 胶囊 现在的等价物
    已连接、正常 深玻璃 + 绿点 收起 无（甲之后顶缘零 UI）
    链路异常 / 未连通 整枚染红 + .capAlarm 微光条常显（收起态也在） 自动展开一次 → 2.5s 后收起（不再永久锁显，见 §8 待拍板⑥） 现在微光条随胶囊一起被卸载 → 乙把它挂到把手上（新 prop alarmOnHandle）
    有等你处理的（文件请求 / 对端改画质 / 扬声器被静音） 整枚染橙（外挂橙点 2026-09-29 已退役：全屏态会被窗缘裁，见 §3 状态色行） 自动展开一次（沿用甲-②的 prevNoticeSig 判据） 现在只有胶囊上的 .ctrlBadge，收起态看不见
    指针锁定 隐形（不占像素、不可点） 收起 沿用「锁指针不唤出」
    菜单 / ⋯ / ⓘ 详情展开中 收起命中盒下探（40×15 → 40×12，让出胶囊上沿） 锁显 沿用 menusOpen / moreOpen / detailOpen
    会话结束 整块卸载（把手随 RcSessionCapsule 一起消失，不留残影）

    规则 15.1 的对账：把手是常驻可见的触发口，所以它的结果（展开/收起/状态）也常驻可见； 「结果出口」（甲-② 的失败提示）仍挂在胶囊里，收起态只以整枚橙色提示「有事，点开看」， 不在把手上写字——一格里写不下也不该写。

    6. 键盘与可发现性

    路径 行为 备注
    鼠标 点把手 ⇄ 展开/收起胶囊 把手是 <button aria-expanded>，不是 div
    F10 同义切换（已落地） 把手给它提供「可见的落点」，解决甲之后 F10 没人知道的问题
    Tab 把手常驻在 Tab 环（不随胶囊的 tabIndex=-1 纪律） 隐藏态三重纪律只约束胶囊本体
    Esc 胶囊展开时先收胶囊（registerRcPanel 现成口径），收起后 Esc 才轮到结束会话 两级取消，规则 17.6
    首显 15s 照旧展开 15s，收口时收成把手而不是收进零 把手因此永远有「第一次见到它」的教学窗口

    8. 拍板结果（六条全按本稿默认执行，2026-09-29）

    # 问题 本稿建议 理由
    ① 保留顶缘 hover 唤出吗 保留（默认开），设置里可关成「顶缘零触发」 关掉才是「和 RustDesk 新版同构」，但会让所有习惯鼠标的人多一次点击；有把手之后 hover 只是加速器，不再是唯一出口——风险面比甲之前小得多。
    ② 把手尺寸 24×12 / 命中 40×15（下探已在落地后自查从 -9 收到 -4，见 §3 C 项） 先按此值落地，真机看手感再定 12px 高正好在遮挡带之上；再小就点不动，再大就吃回内容区。
    ③ 微光条挂把手还是随胶囊 挂把手（收起态也看得见） 现状胶囊一收起，异常只剩一个看不见的灯——规则 15.1 的直接违反。
    ④ 被控端（别人控我）要不要同款把手 不要 被控端胶囊 .ctrlPill 挂在页面上、不压远端画面，遮挡问题不存在； 它的常驻提示已经在 RcOverlay 里解决了。搬过去只会多一处要维护的状态。
    ⑤ 把手能不能拖 不做 正中避得开所有热点，收益小；要拖就得存位置（配置写盘）+ 处理窗口态/全屏态两套基准，成本不成比例。
    ⑥ 链路异常还要不要永久锁显整条（甲现状 linkLocked） 不要，改成展开一次 + 把手常驻染红 永久锁显等于让 12–46 那条遮挡带一直到会话结束都在——正是甲要修的原点。 乙有了不被卸载的把手（染红 + 微光条），提示职责已经满足，不必再拿遮挡换告知。 ⚠️ 这条改的是 2026-09-23 那轮拍过的「异常锁显」，所以要单独点头；演示区按默认档走。
