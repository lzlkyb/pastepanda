录屏 UI 重做 · 材料、层级与动效

重做的不是流程，是「看得见的那一层」：玻璃条从 13 个元素挤一行变成分组材料浮层；控制条从硬编码 260×36 变成会形变的胶囊；反馈从「点了没反应」变成一条弹簧带着关系走。 全部落在 docs/PastePanda-UI规则.md 的 U/L/V 判定内。

结论：现在的录屏界面「不丑，但廉价」。廉价感不来自配色，来自四件事： ① 所有信息同字号同字重平铺，没有主次；② 分隔靠 | 和 · 字符而不是间距； ③ 实色强调滥用（一屏 2–3 个）；④ 状态切换没有连续性，元素直接出现 / 消失。 本稿逐条改掉，并补上缺失的反馈动效。
00

设计语言：材料、深度、字阶、动效

参考 Apple HIG 的三条原则落地：语义化材料（材料只用于浮层与控制层，内容层不透明）、 vibrancy 是对比度保险而非装饰（材质之上必须保证文字可读）、 用深度而非颜色/大小建立层级。同时受本项目 U5 约束：圆角 4/8/12、字号 11/12/13/15/20、间距 4/8/12/16/24。

01

这一屏改了什么

  • 分隔改用间距与分组：删掉 2 处 <span class="muted">|</span> 与 1 处 ·，改为 sep 竖线（只用在「主动作 / 目标 / 设置」三级之间）+ 8px 间距。原版一行 12 个元素齐平，外加一整行常驻说明，靠字符当分隔符。
  • 读数只留「图标 + 数字」：删掉「将录制」标签（位置与上下文已经说明）与「改录整屏 ↔」动作文案（整枚可点即切换），窗口 / 整屏改由图标区分——窗口区域已给 #i-win，整屏那枚显示器图标实施时新增（第二态除图标与数字外与本态完全一致，故不另画）。这条读数从 22 字降到 0 字，仍满足「读数即控制」的既有不变量。
  • 教学行不再常驻：原来条底一整行 11px 灰字说明撑成第二行；改为条右端 ? 就地点开（L4 就地解释 / V7 删元素测试）。选区底部那条同样只报状态——3 扇窗口可录，「单击采纳」这个动作交给悬停时出现的预览框自己说明。
  • 音源胶囊开关：状态交给点本身（开 = accent 20% 填充 + 描边 + 实心点；关 = 空心点 + 低对比描边），文字只留名字，不再写「开 / 关」两个字，全状态由 title 与 aria-pressed 兜底（原版靠把字调到 40% 变虚，6 个主题全不过 AA）。
  • 框的语义分两级：预览=虚线 + 四角 crop mark；采纳=实线 + 加粗描边。两者同用 accent（同一屏只有一个强调色），靠线型而不是颜色区分。原版预览框与悬停高亮框都是 3px accent 实线，用户分不清「现在会录谁」。
  • 每屏一个实色：「开始录制」是全条唯一实色按钮。
02

倒计时：环形进度 + 数字换帧动画

原来只有一个 72px 白数字，换帧是「啪」地替换，也读不出「还剩多久」。新版加一圈 3 秒走完的环， 数字每次换帧做一次 200ms 的缩放入场。

这一屏改了什么

  • 环形进度：3 秒一圈，剩余时间一眼可读；原版仅靠数字，且没有「正在倒数」的持续感。
  • 数字换帧动效：tickPop 200ms cubic-bezier(.05,.7,.1,1)（scale .82→1 + 透明度），替代原来的硬替换。
  • 主次分开：原来「取消」和「将录制」共用同一套胶囊样式；新版取消是描边按钮（唯一鼠标出口，给足命中区），读数降为一枚只报尺寸的小胶囊。
  • 取消按钮仍是唯一的鼠标逃生口（规则 17 / §18 P4 两级取消不变）。原来下面那行 按 Esc 回到选区 删掉——键位由 ? 与全局快捷键承载，不值得在倒计时里常驻。

控制条的关键改动

  • 尺寸不再硬编码：控制条用 width:max-content + 固定高 44px（收起 32px），由内容决定宽度。原版在 TS 里维护 260/288/80/104 × 36/28/280/192 六个数并逐次调原生窗口——任何视觉改动都要动代码。
  • 形变走弹簧：展开⇄收起⇄更多用 --ease-spring（k=130/c=16，过冲 4.5%，800ms 落定）做宽高形变；颜色与透明度不参与弹簧（U2 弹簧条款）。原版是尺寸突变 + 原生窗口重设。
  • 一屏一个实色：录制中唯一实色是「停止」（danger）。「暂停」「更多」是描边/文字级。原版 .stop 用 accent 实底、异常/丢弃再用 danger 实底——同时 2–3 个实色。
  • 呼吸替代闪烁：红点由 recBlink 1.2s opacity 改为 breathe 1.8s（点保持实体 + 一圈扩散），与选区脉动同族。原版闪烁与 2s 脉动两条节奏互不相关。
  • 「更多」改成信息卡：三行「11px 标签 + 值」，动作区独立；不再是三行灰字 <p> 加四个按钮堆叠。每行不重复画图标——标签已经是该行的名字，图标只会让「名字」在一行里出现两次（画质 旁的胶片、声音 旁的喇叭）。
  • 异常不打断：异常时状态点变红 + 提示条出现在控制条同域，提示条只说事实（麦克风已断开），收起走 ✕ 而不是第四个样式的「知道了」按钮（规则 15.1 触发与反馈同一可见性域）。
  • 命中区达标：抓手 24×32、更多 30×30、音源胶囊 30 高——U7 要求 ≥24×24（原版 .rec-glass-lnk 的 padding 只有 0 4px）。

这一屏改了什么

  • 状态头用图标 + 文字：26px 圆形成功/失败图标替代「15px 绿色加粗文字」的单色表意（U7：不能只靠颜色）。
  • 指标成组：时长 / 体积 / 画质三格等距，label 11px + value 13px/600 tabular。原来是 2:44 · 22.7 MB · 高清 一行里五个点号。
  • 路径与动作同行：保存到：D:\… 之后那个孤立的「打开文件夹」按钮，改成路径行内的就地动作（L5：不用记住「保存到哪」再去别处找）——因此动作区里那枚重复的「打开文件夹」一并删掉，同一个动作在一屏里只出现一次。
  • 「关闭结果」降级：从与主操作同款的实心按钮，改为标题行右端的 30×30 图标按钮。
  • 入场动效：rise 300ms 上滑 10px 淡入；原来结果卡是直接出现。
  • 卡里不放「说明书」：异常行只说事实（未检测到系统声音 / 保存目录不可写），怎么办由旁边那枚按钮回答；尾部「可在『工具 → 最近录制』找回」「失败原因已写入日志」删掉——一个和路径行重复，一个用户此刻不需要知道。只留 录制内容不会保留 这条后果。
05

预览与裁剪：自绘时间轴

原来是「文字按钮 + 原生 <input type=range>」×3：一条播放位置、两条起止点。 原生滑块的外观与整站的玻璃语言不搭，是这一窗廉价感的主要来源。新版把三条合一：一条自绘轨道， 双端手柄 + 播放头 + 关键帧刻度；键盘可达性用视觉隐藏的原生 range 承接，不牺牲无障碍。

  • 三条原生滑杆 → 一条自绘轨道：播放头 + 保留段 + 斜纹裁掉段 + 关键帧刻度共存，一眼看懂「保留哪一段」。

减少动态效果

本稿整体在 prefers-reduced-motion: reduce 下把所有动画压到 0.01ms（全局兜底口径）。 需要留意的是「红点呼吸」承载了「正在录制」这一信息——按 U2 的要求，压掉动画后必须仍有静态态： 红点本身保持实色不动，所以信息不丢；不要把红点做成透明度 0 的脉冲（那会在减少动效下彻底看不见）。

09

减法：删掉哪些字与元素

全稿最一致的一处改动是「减」。判据只有一条：凡是文字在解释一个已经看得见、或者本来就能点的东西，就删掉它—— 状态交给形状、实心与否和位置。这条判据筛字，也一样筛元素：一个信息只留一个载体，一个动作在一屏只出现一次。 下面这些是删掉的，没有一处是靠「加一句说明」补回来的。

窗口所在区域四枚字 → #i-win 一枚窗口图标

字和元素用同一条判据筛：一个信息只留一个载体，一个动作在一屏只出现一次。 图标与标签并存、两个「打开文件夹」、用文字报「开 / 关」，都是同一个信息占了两个位置—— 删掉的那一个不会让界面变难懂，只会让它变短。

没动的（这些不是噪音）
  • 画质 高清——设置名 + 当前值，点开才是菜单，缺任一项都会歧义。
  • 确认丢弃这段录像？——不可逆动作的确认语，一个字都不能省。
  • 失败原因 / 录制内容不会保留——后果与出口，属于用户必须知道的。
  • ? 里的操作说明——按需展开，不是常驻噪音。

判据的另一半：删掉的信息如果仍然有用，就换一个更便宜的载体——图标、点的实心 / 空心、控件自身的可点态， 以及 title 与 aria-pressed。既不加字，也不让它只有悬停才能用。

为什么删的是这些

  • 提示的成本是常驻的，收益是一次性的：教学、解释、复述，用户学会之后每次都要再读一遍，而它占的宽度与行数永远都在。原来的录前条就是被这类文案撑到两行。
  • 状态不该用文字报：「开 / 关」是二值状态，一个点的实心与空心能在同一位置表达同一件事，不参与换行、不随语言变长、也不受主题对比度拖累。
  • 同一份数据 / 同一个动作在一屏里只说一次：预览里起点 / 终点已各有一枚芯片，右侧再复述区间是纯冗余；结果卡里两个「打开文件夹」是同一个动作说了两遍；「更多」每行标签与图标并存，是同一个名字占两个位置。
  • 「提示」与「状态」分开判：告诉用户「现在是什么情况」的句子可以留（麦克风已断开）；教用户「该怎么操作」的句子一律降级——由控件自己、? 或全局键位承担。
  • 删字之后条宽自然缩短，「开始录制」「停止」这些真正的动作才浮出来——这是最省力的层级手段：不加大动作，而是把替它说话的字拿走。

三个方向，选一个

主要的分歧只有一处：录制中的控制条该有多安静。三个方案的录前、结果、预览、最近列表都一样， 差别只在录制态。

推荐：甲，可在录制态局部叠加乙

甲覆盖了用户抱怨的全部来源，而且不牺牲可达性。如果「演示时控制条出现率」是硬指标， 可以把乙的「自动收起」做成甲的可选设置（默认关）——两者不是互斥方案， 是两个可组合的开关。丙不建议单独做：它修的是症状。
