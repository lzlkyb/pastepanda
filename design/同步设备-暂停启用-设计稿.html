同步设备 · 暂停 / 启用

PastePanda · 设计稿 · 方案 A · 知识库同步 + 剪贴板局域网同步 · 保留配对与游标，只停这一台

一、要解决什么

配对完成后设备行上只有「忘记」。忘记会删记录（KB 还要重配），用户想「暂时别跟这台同步」时没有更轻的出口。

方案 A 语义：暂停 = 保留身份 / 同步游标 / 历史，只停这一台；恢复不用重新配对。
忘记 = 从名单移除（KB 需重新配对）。两者并存，暂停是高频可逆，忘记是低频破坏性。

二、UI 变更（对照真实组件）

位置现状改后
LanPairedList（剪贴板） 在线点 +「忘记」 在线点 + 启用开关 +「忘记」；暂停时状态行写「已暂停」
KbSyncPanel 设备行 徽章 + ⇅ + 忘记 徽章（暂停时换「已暂停」）+ 启用开关 + ⇅（暂停时禁用）+ 忘记
列表底部说明 只解释「忘记不吊销密钥」 补一句暂停语义；LAN 必须写清「暂停只是本机不收不发」

交互规则

  • L2 常驻标签：开关旁有「启用」小字，不靠 hover 认出这是开关。
  • 高频一步：点开关即切换，无确认（可逆）。
  • 忘记仍二次确认；暂停中的设备忘记文案不变。
  • 暂停中：⇅ 禁用；LAN 无手动同步则忽略。
  • 乐观更新失败必须回滚并 toast（规则 #15）。

「暂停」只停本机与它的收发，配对与密钥都还在，点开关即恢复。
⚠ 局域网同步是单一群组密钥：暂停后对方仍能解密本机广播（它手里还有同一把钥匙）。 要真正断开得重新生成密钥，那会踢掉所有设备。
「忘记」只清本机记录，不会吊销配对密钥。

暂停后：停止与该设备的同步循环，对方拨过来也拒；同步游标保留，恢复后接着传。
「忘记」才会删记录并要求重新配对。

五、忘记确认（不变，可对照）

剪贴板忘记文案继续强调「不吊销密钥」；知识库忘记强调「需重新配对」。暂停不进这个弹层。

忘记「Home-Laptop」？

它会从本机名单里移除，并重新出现在「附近的设备」里（可以重新配对）。

⚠ 这不会吊销配对密钥：对方手里还有同一把密钥，仍然能解开本机的广播。

六、后端契约（实现清单）

知识库（SQLite devices）

-- 迁移：追加列，老数据默认启用
ALTER TABLE devices ADD COLUMN paused INTEGER NOT NULL DEFAULT 0;

-- Device 结构追加 paused: bool（serde default false）
-- COLS 末尾追加 paused（只能追末尾，防下标错位）

device_set_paused(node_id, paused) -> bool
  UPDATE devices SET paused = ?2 WHERE node_id = ?1

device_list() 返回含 paused
spawn / add_peer 时跳过 paused=1
入站握手若 node_id paused=1 → 拒绝并 log

命令：
  kb_sync_set_paused { node_id, paused }
  恢复时 svc.add_peer(node_id)；暂停时 svc.drop_peer(node_id)

剪贴板 LAN（config lan_paired_devices）

PairedDevice 增加：
  #[serde(default)]
  pub paused: bool

remember_device：名字与 paused 都未变则零写入
收包 / 发送：paused 的设备不写入剪贴板、不作为目标
online 点：paused 时灰点 + 「已暂停」，不报在线

命令：
  lan_set_device_paused { device_id, paused }
  与 lan_forget_device 并列注册
LAN 文案红线：暂停做不到「对方收不到」。群组密钥模型下对方仍能解密广播。 界面必须写「只停本机收发」，禁止写成「已断开」。

七、验收清单

  • 暂停后 KB：无新拨号；对方入站被拒；游标不丢；恢复后能接着同步。
  • 暂停后 LAN：本机不应用该设备消息；列表显示「已暂停」；重启仍在暂停。
  • 重启应用后 paused 状态保持。
  • 忘记不受暂停影响；暂停中可直接忘记。
  • 开关失败回滚 UI + toast。
  • npx tsc --noEmit / npm run lint / vitest / cargo test 全绿。
