远程电脑 · 一次性协助通道（方案 C）

「帮别人一次」不该先付一套配对成本。本稿回答三件事：现状到底要走多少步、 为什么跨网做不到「6 位码」、以及在不动后端的前提下能改到什么程度。 全稿数字均为 headless Edge 实测（见 §七 口径声明）。

结论先行
  • 现状不是「码太长」，是入口深 + 结果残留：被协助方拿到码要 3 步、 协助方连上要 5–6 步，而且配完就在双方设备列表里永久留一条。
  • 🔴 跨网做不出 6 位码：没有中心服务器，短码无法自描述「对方在哪」。 这条约束把方案空间砍掉一半，不要按快速助手那套设计。
  • 推荐 方案甲（入口一等公民 + 用完即忘，纯前端）先落地； 方案丙（后端一次性来源）排期，它解决的只是崩溃残留这个边角。

被协助方（出码方）：① 工作台侧栏 / 设置页找到「配对」→ ② 第一屏选「生成邀请码」→ ③ 点「生成并复制」 = 3 步（填设备名可选，已被本机名预填）。

走完这些，双方设备列表里各多一条永久记录（要 rc_forget + 二次确认才能去掉）。

二、业界基线：都是「输码即连」，都不预先配对

产品建连方式免确认机制连完留设备吗
AnyDesk输 9–10 位 ID → 对方 AcceptUnattended Access + 密码不留
TeamViewerID + 密码 → Accept无人值守密码不留
ToDesk / 向日葵设备代码 + 密码；或同账号设备列表点一下安全密码 / 绑定后免密留（绑定那条路）
Windows 快速助手6 位一次性码（1 小时） → 对方允许无（每次允许）不留
Chrome 远程桌面账号 + 一次性码账号级不留

三条共性：① 输码即连，不预先配对 ② 码是短的 ③ 用完不留设备条目。 第 ①②两条 PastePanda 现在都不满足，第 ③ 条也不满足。但 ——

三、一条约束把方案空间砍掉一半：没有中心服务器

短码 = 短在「寻址」，不是短在「字符」。

AnyDesk 的 9 位 ID、快速助手的 6 位码之所以能短，是因为有中心服务器把 「ID → 公钥 + 地址」查出来。PastePanda 是点对点、无中心：码必须自带 node_id（32 字节公钥）才可能跨网找到对方 ⇒ 53 字符起步（本稿实测）。

这正好解释了现状为什么是两条路，而不是一条：

路径谁承担寻址码的角色结果
局域网（现有） presence 组播包（同网段听得见） 只承担核对（6 位数字） 可以做到「点一下 + 对一眼」
跨网（现有） 码自己（内嵌 node_id） 同时承担寻址 + 核对 必然 53+ 字符，搬字符串无法避免

所以方案 C 能改的是「入口 + 残留」，改不了「码长」。 要让跨网码变短，需要引入 rendezvous 服务 —— 那是另一条产品线 （见 docs/P2P通道-产品定位与可做方向-2026-09-18.md），不在本稿范围。

推荐：甲先做，丙排期，乙不做

  • 甲 把「一次」与「长期」两种意图在入口层就分开，顺带消掉 2–4 步； 全部落在前端，rc_forget 本就是现成命令 ⇒ 可以本轮之后单独一批做。
  • 丙 只在「崩溃残留」这一条上比甲强 —— 属于加固，不是体验问题。等甲上线后再看 rc_devices 里真实的 adhoc 残留量决定要不要做。
  • 乙 不做：「一次性」如果只是配对框里的一个勾，它救不到最需要它的人。

七、口径声明（这些数字怎么来的）

  • 步数是按源码里的必经交互点数的（见 §一 表里的 file:line），不是主观估计； 填设备名、blur 自动解析这类「可省但仍在」的动作不计入。
  • 码长不是估的：本稿按 sync/invite.rs 的同一套算法 （base58 字母表 + CRC32%58⁴ 校验位）在 Node 里跑了一遍，量得 空名 53 / 3 汉字 65 / 6 汉字 78 / 8 汉字 86 字符； 与 sync/invite.rs:21 的注释口径（空名下限、3 汉字约 65）一致。 稿子里那串示例码就是按 3 汉字名生成的同一串（65 字符，校验位自洽）—— 正文、表格、图里的数字同一个口径。
  • 「跨网做不到短码」是架构推论 + 现状两条路的分工互相印证： 局域网那条把寻址交给组播、码只做核对；跨网那条没有广播可达 ⇒ 码必须自带 node_id。
  • 框体尺寸：.dialog-box 480px 是 RcPairDialog 的 min(480px,94vw) 在常见屏幕下的实际值； 内边距、间距、字号全部照 RemoteComputer.module.css / RcPair.module.css 的真实值。
  • 渲染数字是量出来的，不是按盒模型算的：headless Edge 开 CDP， 页面内 Runtime.evaluate 取 getBoundingClientRect() / scrollWidth·scrollHeight， 固定视口 1374 × 1000、DPR 1。本环境下 --dump-dom 不回放脚本执行结果， 所以不用它取证。
  • 本稿未改任何产品代码，也未改任何 Rust。
