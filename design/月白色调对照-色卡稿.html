月白 · 色调对照色卡稿

只换 accent 一族（含吃同一族的两层背景氛围与徽章渐变），灰阶 ramp（slate）一个字不动 —— 上次那条已被你否掉，这里不再碰。 每一列用的是同一段真结构：侧栏选中项与 3px 指示条、搜索框聚焦态、普通卡与选中卡、搜索命中标、Toast info、确认圆钮、筛选激活项、版本徽章， 每条规则都逐字抄自真组件并在样式里标了出处。所有对比度由 canvas 逐像素合成读色 + WCAG 相对亮度当场量出，不是注释里的历史数字。 ② 是四族横排（含现状基线），②b 是蓝系 12 列（同样带现状基线）。

背景氛围层（theme.css:348-350 两层 radial + 底色渐变）

① 色带：每族五个档（light / accent / solid / strong / 信息底 14%）

② 同屏四列（第一列 = 现状真 theme.css，零覆盖）

②b 蓝系横排（11 档 + 现状基线 · 每档头部一排五个色卡 = light / accent / solid / strong / 信息底 14%）

和 ② 完全同一段结构、同一套门槛、同一个派生器，只是列宽压到 150px 好并排比眼睛（窄列里被裁掉的字是排版副产物，量色只读计算样式与合成像素，不受裁剪影响）。 不换色相族，只把天蓝那个坐标挪走：hue 仍在 195°–232°，chroma 从 197 掉到 54–80、亮度往下压。 第一格是现状列（零覆盖），用来当同排标尺。最后一档 雾蓝 是故意留在里面的反例——它白字压不住 4.5:1， 所以那一列末行会显示「两档都得留」，证明这套门槛真的在筛东西，不是排好队全绿。

②c 蓝系横扫小结（运行时直接从每列读数表抓，不是另一套数字）

③ 落地清单：换色族要一起动的令牌，和它们现在被谁吃

④ 三档各自的代价（本稿量不到的，写在明处）

A 黛青与「深海 ocean-dark」同族冷青，两列并排看会像同一主题的深浅两版；侧栏选中项与命中标的可辨度靠 12% 淡底，比现状的 #e0f2fe 更弱一点（见 ② 第 7 行），要靠字重补。
D 松烟墨蓝改动最小、风险最低，但它是"把现状降饱和"，蓝的身份还在——你要的"换个色调"它其实没换，只是换成熟一点。
B 石墨最耐看，代价最实在：色相线索整条消失。本稿只演示了 8 处吃 accent 的元素，而全仓 var(--accent*) 引用实测 1464 处 / 133 个文件（CardList 102、RemoteComputer 68、FullscreenEditor 58、dialog 57…）——换色组件代码一行不用改（纯令牌工程），但这一套里 1464 个点的观感会一起变，靠蓝区分的状态要改由「亮度差 + 字重」承重，等于交互层重做而不是换色。
蓝系横排（②b）代价最小的一档：只挪 --accent 的坐标，hue 仍在蓝区、灰阶与组件一行不动。本稿实测：选中底可辨度并没有变好——现状 1.05，蓝系 1.04–1.10，基本持平（我早前一版口头表里的"1.08 升到 1.10–1.16"是按别的底色算的，这里以读数为准），所以亮度差接不了色相的班，选中态仍然要靠字重和边框承重。真正的收益在别处：chroma 从 197 掉到 54–80，白字从 4.10 涨到 4.58–12.50（雾蓝 4.19 除外）。门槛结果分三档看：8 档五道全过（普鲁士蓝 / 天青灰 / 钴蓝压灰 / 石板蓝 / 藏青靛 / 墨蓝 / 牛仔靛 / 群青灰），2 档只卡在 Toast 信息底（钢蓝灰 4.48、薰衣草蓝灰 4.50——都比现状的 4.33 好，但过不了 4.5），1 档连白字都不过（雾蓝，故意留的反例）。所以「换个色调」它只满足一半：远看还是蓝，只是从天蓝变成深蓝灰。
共同收益达标的档 --accent 本身都能直接托住白字 ≥4.5:1，意味着 --accent-solid 和 --accent-strong 两个补丁档可以砍掉——这两个令牌存在的唯一理由就是"天蓝太亮，白字只有 4.10:1"（注释原话见 theme.css:363,365）。
量不到真 GPU 上背景两层 radial 的采样开销、切主题时的过渡观感、以及六套主题并排时新色族会不会和「森林/晨曦」打架——这些要跑 dev 用眼睛判，本稿只给静态色等价物。

⑤ 本稿自检（运行时逐表核对，不靠人眼）

几何申报：② 每列舞台 262×430、②b 每列舞台 150×430（全为定宽，headless 视口可以是 0；窄列里被裁掉的字是排版副产物，量色只读计算样式与合成像素）；色带 262×30（②b 150×30）；指示条 3×16；确认圆钮 20×20。 读数时机：首帧同步量一次 + 两层 requestAnimationFrame 后再量一次，另配不依赖帧的 setTimeout 兜底通道。
