一、Esc 毁标注：把「放弃」做成可反悔的

现状cancelAnnot() 一次清 6 项：annotations、undoStack、redoStack、textDraft、maskPreview、ocr 状态，然后 setPhase("select")。 调用点是标注态 Esc 的唯一出口（:1015-1018），工具栏上的「取消」按钮也走它。

代价不对称：画 12 个箭头 + 一段马赛克是几十秒，销毁是 0 次确认、0 秒、0 反馈——而且窗口是透明全屏， 按完 Esc 用户看见的是自己刚框的区域又变回暗遮罩，没有任何一句话告诉他标注没了。规则 17.6 要求两级取消， 做到了「不一步关窗」，但没做到「误触低成本」（规则 17.5）。

甲方案（默认）：暂存槽 + 找回条

  • 暂存槽单格：discardedRef: {annotations, undo, redo} | null。只留最近一次，不做历史——找回的语义是「我按错了」，不是「版本管理」。 按 规则 15.2 的要求，它挂在 overlay 顶层 ref 上而非子组件里（面板是条件渲染的，会被卸载）。
  • 进 select 态即失效：用户一旦重新拖框（finalizeSelectDrag）或按 Enter 进新标注，槽清空——旧标注对新选区没有意义，留着就会「找回一批画在别处的箭头」。
  • 找回 = 还原三栈 + setPhase("annotate")，选区不变（第一次 Esc 没动 sel）。
  • 键盘可达：6 秒内 Enter 与点击找回等效。选区已存在且未重新框选时，Enter 的原语义本来就是「确认选区进标注」（:3392 的提示条在讲这件事），所以这里不新增键位、也不与既有键位冲突。
  • 不弹确认框：确认框是模态，违反规则 18「非模态不挡视野」；找回条是回执，不拦截。

实现代价：showToast(text, ok) 现在不支持动作（:799-803，3s 自动收）。找回条要走它，就得扩成 showToast({text, tone, action, ttlMs})；同时 ocrToast（:3976-3993，用 .picker-bar 当按钮、手写 bottom:64） 应一并并入，否则底部带就出现第三套自制变体——这正是 §3 要收的口子。

二、OCR 抽屉三态：别再对失败说谎

现状抽屉体只有一个分支：ocr.lines.length === 0 ? "未从图片识别到文字" : 行列表（OcrDrawer.tsx:88-92）。 而 ocrStatus 有 idle / running / done / empty / failed 五值（:349），失败路径写的是 setOcr({lines:[],fullText:""}) + setOcrStatus("failed")（:1576-1577）。

三个后果，都能在代码里指出来：

  1. 文案是假的：failed 时抽屉说「未从图片识别到文字」——用户会以为那张图没字，实际是引擎超时。首次加载模型慢、超时常见，这条路径不是边角（:3166-3167 的注释正是为这件事写的）。
  2. 重试在 result 态不可达：唯一的重试入口是工具栏「取文字」按钮的 failed 分支（onOcrButton，:1986-1989），而 AnnotToolbar 的渲染条件是 phase === "annotate"（:3801）。 进了 result 态，工具栏已经不在了，抽屉却自动打开（4004：phase === "result" || ocrDrawerOpen）——于是唯一挡在用户面前的面板，恰好没有他需要的出口。
  3. 下游跟着一起假：onAiButton 在无文字时提示「图中未识别到文字，AI 没有可处理的内容」（:2004-2006）——失败时也说这句，原因给错。
