三态与徽标规格（全变体共用）

  • 选中态：白底 + 左缘 3px 蓝竖条（渐变 --blue2→--blue，上下各内缩 8px 随圆角），替代 A 稿的 1px 描边——UU 学，玻璃底上对比强且不引入新边框。
  • 活会话徽标：行 meta 尾部小胶囊。蓝「连接中…' = 我发起的握手/会话建立中；橙「被控中」 = 对方正在控制本机（与标题栏橙横幅同族色）。补上横幅进标题栏后「哪台在连」的定位缺口（规则 15.1）。数据源是 rcStore 的会话态，不新增探测。
  • 离线灰：🔴 只由新增显式 offline 字段驱动——设计系统提炼时发现 rcDeviceStatus 的 unknown tone 混着「暂时连不上（真离线）」「最近在线·未实测（只是没证据）」「需完成远程配对（结构性不可连）」三种语义，直接按 tone 灰会把「未实测」误判成「连不了」（L1 撒谎）。落地：rcDeviceStatus 返回值补 offline: boolean 收口 + 守卫单测（规则 11.1），「未实测」行不灰、钮不锁。
  • 排序稳定性：A 稿注释有硬约定「列表顺序不随探测结果跳动」。在线优先/分组的重排只在列表级刷新时发生（进页 / ⟳ 重新检查 / 设备增删），探测回调只改行内文字不改位置——否则鼠标追着行点会跳。
  • 头部计数：meta 从「5 台设备 · 状态自动更新」改「5 台 · 3 台可连」——黑话测试的 5 秒判据直接写进标题区。

对比与推荐

扫读效率（哪几台能连）设备数扩展（8~20 台）实现成本风险
A 单列表在线优先好（在线聚在上半区）中——在线/不在线交界处要逐行读最低：排序 + 选中条 + 徽标无新增语义
B 显式分组（推荐）最好——组标题直接回答好——「不在线」组可折叠，默认收起时列表只剩可连设备A 之上加分组标题 + 折叠态（一个 boolean，展开态存 useRcDeviceUi 同款位置）组名措辞：用「不在线」不用「离线」——「未实测」台进「不在线」组不算撒谎（它确实现在没在线证据），灰态仍只跟 offline 字段
C 紧凑单行差——点色要教（绿=能连？黄=？）最好（行高 30px 多放 50%）中——行结构重排违反 L1（状态字不常驻）+ L6（点色一词多义）；title 悬浮不算常驻。不推荐

推荐 B：黑话测试判据「新人 5 秒说出哪几台能连、哪台正在被用」——B 用组标题 + 徽标两个常驻元素直接命中；A 是 B 去掉组标题的退化版，若嫌分组重可先落 A 再升 B（行结构完全一致，不返工）。C 仅存档。

实施备注（选定后）

  • 改动集中在 RcA2DeviceList.tsx：删 query（A 稿已定）、行加 offline 类名与徽标节点、（B）分组渲染 useMemo 两桶 + 折叠 boolean。行数预算 ≤300（规则 7），超了就把徽标/分组标题抽 RcDeviceRowBadges.tsx。
  • rcDeviceStatus 补 offline 字段属跨端契约变更面最小的纯函数改动，同文件补守卫单测：「tone=unknown 且 offline=false 的行不得灰、钮不得禁」。
  • 徽标文案单源：连接中/被控中 两个词进 rcRequest.ts 或新 rcLiveBadge()，禁止在 JSX 里写字面量（规则 11）。
  • 落地后跑 npm run lint:ui；竖条/徽标色全走语义 token（U6/V3），行无 backdrop-filter（8.3）。
