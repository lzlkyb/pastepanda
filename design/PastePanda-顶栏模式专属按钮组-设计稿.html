顶栏模式专属按钮组

方案 B ·「每个模式在顶栏显示自己的东西」· 2026-09-06

一句话：顶栏右侧那组按钮拆成「模式专属段」+「全局段」。模式专属段随模式换内容——记录放粘贴栈，知识放「⋯ 更多」，工具留空；全局段（AI 胶囊 / 设置 / 最小化 / 隐藏）三模式恒定。

现状（实测，非推断）

顶栏是两层，第二层早就按模式分了，第一层没分：

层内容现在的模式判断
headerTop 标题行☰ · 图标 · 名位 · 模式切换器 ‖ 栈模式 · AI胶囊 · 设置 · │ · 最小化 · 隐藏无——三模式完全一样
headerControls 控制区搜索行 · 5 页签 · 标签筛选行已是 appMode==="record" && !settingsOpen

所以要改的只有标题行右侧那一组。其中唯一与模式有关的是粘贴栈（收集模式）按钮——它在工具、知识、设置四个界面下全都在，但那三个界面里它无所指。

队列条不用管。StackBanner 挂在 CardList 里，而 CardList 只在记录模式渲染——它本来就是记录模式专属的，没问题。

关键决策

① 粘贴栈：记录模式常驻，其它模式「开着才出现」

这条不能写成单纯的 appMode==="record"。粘贴栈是全局后台状态，不是记录模式的局部 UI：

  • 有全局快捷键 ctrl+alt+k，主窗口关着也能开；
  • 一旦开着，用户复制的每一条都进队列（stackPush），跟当前在看哪个模式无关。
直接隐藏会造出一个真实的坏情况：栈开着 → 切到知识模式 → 按钮和队列条同时消失 → 东西还在往队列里堆，但屏幕上零线索、零关闭入口，只剩用户未必记得的快捷键。
这与本轮早些时候修的组播 bug 是同一类错误：把状态的唯一出口藏起来。

② 架构：顶栏插槽 + createPortal

知识模式的按钮不提升状态。handleNew / moreItems / q.newFolderId 全长在 KnowledgeView 的四个 hook 上，而那个文件头部明写：

它自己不持有任何业务状态（A-60 拆分）：
  useNoteQuery → useNoteDetail → useNoteActions → useKbQaPane

把这些搬进 store 是正面撞这个架构。改用插槽：

TopBar.tsx
  <div className={styles.modeSlot} id="topbar-mode-slot" />   ← 空容器，永远在

KnowledgeView.tsx
  <ContextMenu>                    ← Provider 还在这里
    ...
    {createPortal(<KbTopBarActions moreItems={moreItems} />, slotEl)}
  </ContextMenu>
createPortal 顺手解掉了 CtxMenuCtx 的问题。portal 只改 DOM 落点，不改 React 树位置——按钮在 React 树上仍然在 <ContextMenu> 内部，useContext(CtxMenuCtx) 照常拿得到。
如果不用 portal 而是把按钮直接写进 TopBar，它就在 Provider 外面，⋯ 菜单永远弹不出来（同 KnowledgeToolbar 头部记的那个已知坑）。

③ 宽度：净增量为零

默认窗宽 550，minWidth 320；TopBar.module.css 里没有任何 @media，标题行与图标组也没给 flex-shrink——顶栏在窄窗下是硬挤的，容不下随手加按钮。

测试

  • 记录模式：栈按钮在 → 与今天一致
  • 工具 / 知识 / 设置 + 栈关：栈按钮不渲染
  • 工具 / 知识 / 设置 + 栈开：栈按钮仍渲染，点击后 stackMode 变 false（这条守的就是「状态失联」）
  • 知识模式：插槽内出现 ⋯；离开知识模式后插槽清空
  • 非知识模式下插槽为空（portal 卸载）
