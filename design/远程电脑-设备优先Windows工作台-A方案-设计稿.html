这份方案删掉了什么

  • 不再分“远程电脑主页”和“设备列表页”。
  • 不再用欢迎插画、极光、扫光和卡片悬浮填充空闲态。
  • 不再把延迟、码率、编解码全部常驻铺在画面上。
  • 不再在设备页、设置页和被控卡里维护多份同义状态。

视觉 token

窗口底设备栏主文字唯一强调在线/成功远程画面
  • 字体：Segoe UI / 微软雅黑；遥测数据用 Cascadia Code。
  • 圆角只用 4 / 8 / 12；动效只用 150 / 200 / 300ms。
  • 没有渐变主按钮，没有固定青色/紫色装饰。

职责收口

主页 + 设备页→设备工作台
左导航 + 顶栏→标题栏 + 底部工具
HUD + 状态条→连接详情
多处文件面板→传输中心
多处免确认→设备权限

实施备注 · 2026-09-21 对账

  • 被控卡保留两份，不合并：主窗口那条常驻横幅不能删——它要在「人不在工作台」时依然可见，而工作台内的被控卡只覆盖已经打开工作台的人。两者分工不重叠：横幅 = 一行摘要 + 立即结束，工作台被控卡 = 完整事实（对方身份 / 能力档 / 指纹 / 范围 / 画质 / 文件请求）。上面「不再维护多份同义状态」不适用于这一对。
  • pair 屏不按本稿改成内容区三选项面板：现有配对弹层已含「附近的设备」（同网 6 位码核对）与「邀请码」（跨网）两条路径，另有一次协助入口。信息等价，弹层复用成本更低，不重造一页。
  • inbound 屏：本稿的 4 行权限清单已实现为 facts 四格 + 一句话说明，信息等价，不再单列清单。
  • 额外保留：侧栏「允许别人连接本机」开关（本稿只把它放在设置页）。该开关是高频操作，留在侧栏更顺手，设置页同款仍在。
  • 会话态收标题栏（批2 已落地）：本稿 .window[data-state="session"] .titlebar{display:none} 已实现——会话进行中不再渲染那条 58px 内嵌栏，画面铺满整个工作台；连接中 / 等待同意 / 被控三态仍保留标题栏（那三态还要用它的「检测设备」「启动远程通道」）。待办：改自绘窗口控制（decorations(false)）时，会话态需补一条可拖拽细条。
  • 「连接详情」落点与本稿不同（批2 已落地）：本稿把入口放在会话工具条（session-tool 里一枚按钮），实现放在画面左上角原 HUD 位置——一个按钮 + 点击浮层，画面上的常驻死区从「最多 10 格信息条」缩到一个按钮。面板数据比本稿多：链路 / 路径 / 往返 / 画面龄 / 四段拆解 / 操作延迟 / 指针锁定。链路异常的常驻可见性由会话顶条的红黄胶囊承担，按钮上不重复播报。
  • 等待态用「确定」进度条（批3 已落地）：本稿画的是游走的不确定条（.wait-progress::after 44% 宽来回跑）。实现改为确定条——后端有确切的确认窗口（src-tauri/src/rc/service.rs:2138 的 120_000，超时以 confirm_timeout 拒绝），所以进度条能直接表达「还剩多久」，文案同步成「已等待 12 秒 · 1 分 48 秒后自动取消」。起点不可用时（started_ms 缺失）不渲染进度条、也不编倒计时。注：本机起点是申请发出时刻，对端是收到时刻，中间隔着几秒拨号差，故归零后显示「等待超时，正在收尾…」而不是「已取消」——取消是对端的行为，前端不提前收尾。
  • 设备列表分三组、不是两组（批4 已落地）：本稿画「在线 / 最近使用」两组，而后端可达性是四档（live / recent / seen / never）。实现按语义分三组：在线（live）/ 最近使用（recent + seen）/ 尚未连接（never）——never 是「配对后从没连上过」，塞进「最近使用」等于把「还没用过」说成「用过」，而文案如实正是这四档存在的意义。空组不渲染（不摆一个「在线 0」的空标题）；搜索过滤后仍按组渲染，不拆散「这台在不在线」的语境。
  • 设备行第二行给路径还是时间，取决于在线与否（批4 已落地）：本稿在线行 meta 是「局域网直连 · 8 ms」、最近使用行是「昨天 22:16 连接过」。实现沿用同一分工——在线给实测路径（分组标题已经写了「在线」，行内再写一遍是纯重复，位置让给「现在连它快不快」这个真问题），离线给上次时间（路径是上次的、可能早已失效）。被让位的那条信息进 title 补回。延迟（8 ms / 42 ms）不在本次范围：设备列表不携带延迟字段，属批6 后端补字段后再回填。
  • 记录页侧栏换成「按设备筛选」（批5 已落地）：本稿 history 屏的侧栏是设备筛选列表（全部设备 12 条 / 各设备 N 条），实现照做——设备列表在记录页点一下会跳回设备页，等于给了一个「不该按的按钮」。筛选与内容区的方向 pill 是两个正交维度（同一份记录要同时满足），不是二选一；两处计数取自同一份快照，所以「全部 N 条」与各设备之和恒等。
  • 「管理此设备」用内联展开，不是浮层菜单（批5 已落地）：本稿在区块标题右侧摆了 section-link。实现是点开后在标题下方展开原来那 4 个权限按钮——详情面 body 是滚动容器，绝对定位浮层会被 overflow 裁掉（本项目已有两次同类事故：主窗导出下拉、格式栏菜单），而内联展开只是把下方 facts 推下去，无副作用。收起时不再常驻占掉一行半的宽度。
  • 「最近会话」只摆会话记录，不摆文件传输（批5 已落地）：本稿第 3 行画的是「文件传输 · 3 个文件」。rc_session_history 只记画面会话（control / view），没有文件传输记录——宁可少一行也不摆假数据。取 3 条、按 node_id 过滤（不是按名字，名字会改），右上角「查看全部」跳记录页。
  • 延迟口径改成「最近实测」（批6 部分落地）：本稿写「8 ms」「预计延迟 8–12 ms」。设备列表不带时延字段，「预计」没有数据源，编一个数就是假信息。已实现的是从会话历史取该设备最近一次实测 RTT（详情面 facts 的「上次连接」补一行「最近实测 ~12 ms」，采不到样本就整段不显示）。探测时延不做——probe_peers 的语义是「拨通确认可达」，连接建立耗时不是会话延迟，摆出来会误导。
  • 设备系统挂在 Accept 帧上（批6b 已落地）：本稿「在线 · Windows 11 · 局域网直连」中间那一格，由被控端在 Accept 里自报本机系统（rc/protocol.rs 的 Accept::os），控制端收到即写设备行 rc_devices.os，详情标题行渲染成「状态 · 系统 · 提示」三段。选 Accept 而不是配对握手，是因为所有会话——敲门 / 邀请码 / 无人值守码 / 固定密码 / 免确认自动接受——都必经这一处 Accept（全仓只有一处构造）；而 sync::presence::Extras 是 rc 与笔记同步共用的结构、配对又有三条路径，改一处必漏一处。代价照实说：只有建立过一次会话后才有值，「尚未连接」组显示不出——空串整段不渲染，不编一个「未知系统」摆出去。
  • Windows 版本判据不能读 ProductName（批6b）：Win11 机器上该注册表键照样返回「Windows 10」（微软为兼容保留的已知行为，至今没改）。判据取 CurrentBuildNumber，≥ 22000 才是 Windows 11。这条写反会让所有 Win11 用户在自己的设备行上看到「Windows 10」，已用边界单测（21999 / 22000）钉住，并加了源码守卫禁止出现 get_value("ProductName")。
  • 自绘标题栏（批7 已落地）：rc 窗口改 decorations(false)，标题栏照本稿 48px 三格「品牌 | 通道状态 | 窗口按钮」自绘。三条落地判据：① 拖拽与双击拖动区最大化不必自己写——Tauri 注入的 drag.js 打 start_dragging / internal_toggle_maximize，属性三档语义（裸值 = 仅自身可拖、deep = 子树任意点、false = 阻断），而可点击元素（button / input …）不带该属性时自动阻断拖动 ⇒ 用 deep 时按钮天然豁免，不必逐个标 false；② 本稿那格「通道状态」做成自适应——已启动是只读一行，未启动时同一格变成可点的「通道未启动 · 点击开启」。正常路径由 rc_boot 与「打开工作台自动启动」拉起，这里是两条都失败时的补救入口，压成纯只读就再没地方能把它开起来；③ 设备行右格的两种形态照做：在线给「连接」、离线给「检测」，探测只拨单台（不是把整列全拨一遍），探通后 presence 变 live、那一格自动换回「连接」。
  • 会话态没有标题栏，顶条得顶上（批7）：本稿 .window[data-state="session"] .titlebar{display:none} 收掉标题栏后，那一态既拖不动也关不掉窗口——RcSessionTop 挂 data-tauri-drag-region="deep" 兼作拖拽区，最右补一枚关闭键（只补关闭：最小化 / 最大化另有系统替代——任务栏、双击顶条、Win+方向键）。关闭一律走 close() 而非 destroy()：useRcWorkbenchClose 拦的是 onCloseRequested，直接 destroy 会绕过「有会话先问」那道守卫，表现为窗口没了而会话还在对面跑。
  • 顺手清掉的死代码：A2 换顶栏后 RcWorkbenchHead / RcTopBar / RcPageDevices（416 行）无人引用却还在仓库里，其中 RcHistoryClearButton 被它们「接走」导致工作台的「清空记录」入口一度消失（只剩设置页有）。三个文件已删，「清空记录」挪回记录页说明行右侧常驻——删除入口就该在日志自己的页面上。
