截图选区状态机重构

方案 B（固定区域直接进标注态）+ 长截图移入工具栏 · 对照微信截图的两态模型
一句话：微信截图只有「未确认选区」和「已确认选区」两个状态，未确认态没有任何按钮。 PastePanda 的 annotate 态其实已经等于微信的已确认态（工具栏内容一一对应）， 错位的只是 select 态上挂的那两个按钮——它们要求选区稳定，而未确认态按定义就是选区跟着鼠标跑。

1 · 病根：一个错位，三个症状

draggedRef 为 false 时，hover 吸附每 90ms 无条件改写选区。而它被置为 true 的三处 （拖选有效 / 选区内原地单击 / 双击）都紧跟着 setPhase("annotate")—— 也就是说 select 态下它恒为 false，hover 永远活跃。

症状机制
固定区域形同虚设恢复出的选区被 hover 覆盖；扫到桌面空白还会 setSel(null) 清空
平移选区留不住onSelectMouseUp 的 m.moved===true 分支既不置位也不进标注，直接 return
两个按钮点不到按钮位置 left: css(sel.x)+css(sel.w)/2 跟着选区走，选区一直被改写，按钮就一直在跑
还有个死锁：「记住为固定区域」需要稳定选区才点得到，而稳定选区需要先有固定区域。第一次根本进不去。

5 · 固定区域流程（方案 B）

有固定区域

1按 Ctrl+Alt+A
2直接进 annotate 态，选区就是记住的那块，工具栏已就位
3直接标注，或 Enter / 双击空白 = 完成并复制
4要换区域 → Esc 回 select 态（hover 恢复）
少一步。固定区域的场景本就是「反复截同一块」——规则 17.2 高频路径一步到位。

无固定区域（不变）

1按 Ctrl+Alt+A
2自动框选光标下的窗口；移动鼠标 → 选区跟随（hover 吸附）
3选区内单击 / 选区外拖选 / 双击 → 进 annotate 态
4在 ⋯ 里点「记住为固定区域」，下次就走左边流程
方案 B 之所以比「停在 select 态 + 锁住 hover」自洽：固定区域语义上就是「这块区域我已经确认过了」， 应当落在已确认状态。把它塞回未确认态再想办法不让它被覆盖，是在跟状态机较劲。

6 · 配套改动

#改动原因
a平移结束（m.moved===true）时置 draggedRef = true否则挪好的选区 90ms 后被 hover 冲掉
bdraggedRef 更名 selFixedRef真实语义是「选区已确定」，不是「拖过没」；加了固定区域后更不符
c补右键：annotate 右键 → 回 select；select 右键 → 关窗截图窗口目前完全没有 onContextMenu；这正是规则 17.6 的两级取消，也给「解除固定」一个可发现的出口
d新增 .tool.disabled CSS.tool:disabled 是死规则——.tool 是 <div>，div 没有 disabled 状态
/* 新增：div 版禁用态。原有 .tool:disabled 对 div 无效 */
.tool.disabled { opacity: 0.35; cursor: not-allowed; }
.tool.disabled:hover { background: transparent; }

7 · 不做什么

不做原因
拖选松手后停在 select 态等二次确认那是最高频路径，多一步就是全局变慢（规则 17.2）
给固定区域加独立锁定开关方案 B 之后没有「需要锁定的未确认态」了，这个状态不存在
把「选区外原地点一下 = 解除固定」当解锁主路径零视觉提示，不看文档发现不了；改由右键 + ⋯ 里的清除项承担
