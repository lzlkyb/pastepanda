① 问题诊断（为什么会「点了没反应」）

根因 A — 大纲只滚隐藏的编辑区。 jumpToLine → scrollToLine 只对 CodeMirror view.dispatch(scrollIntoView)。 仅预览时编辑区是 display:none，滚动发生在看不见的节点上；分屏时预览靠比例滚动同步，长文档对不齐。 与 U1/规则 15 直接冲突：常驻可见的大纲按钮，结果反馈却在不可见域。
根因 B — 预览正文目录锚点从未实现。 marked 默认不给标题写 id；DOMPurify 虽默认放行 id，但源头就没有。 CSS 里 hover 的 " #" 是纯装饰、不可点；文档里手写的 [标题](#锚) 点了也不会滚预览容器。 即便以后有了 id，原生 hash 跳转会滚 window 而不是预览滚动容器——仍需点击拦截。
场景现状用户感知
大纲 · 仅编辑 能跳（CM 顶到行首） 正常
大纲 · 仅预览 滚了 display:none 的编辑区 点了没反应
大纲 · 分屏 只精确滚编辑区；预览比例同步易漂 像失效 / 对不齐
正文「## 目录」链接 无 heading id + 无点击拦截 点了没反应
标题 hover「#」 CSS content 装饰，不可点 以为能点，点了没反应
