2 · 四个方案

推荐		 同样是 150ms / opacity 0→1 / translateY 4px→0， 但不挂在面板上，挂在面板里透明的内容层上—— 真实 DOM 里就是 .editorBody / .previewBody。 载底色的 .editorPane / .previewPane 恒定不动 不会
面板底色即垫底		 低
+1 段 keyframes
+1 个类		 位移 4px 被面板 overflow 裁掉，不留缝； 面板标题（「Markdown 源文」/「预览」）也保持恒定。 与 B 同参、同成本，只是换了挂点
为什么推荐 D：页签切换是唯一会被连点的高频动作，动效必须短到「不挡手」—— 150ms / 4px 刚好够让人感到「换了一份内容」，又不至于被读成「过场动画」。这一条 A / B / D 都能满足。

真正把它们分开的是「底色透不透」。我把三个方案各冻在动画 20ms 处截了图（同页面、同参数， 只换方案的冻帧对比）：A / B 因为动画挂在整块面板上，面板半透明期间内容区会整体发白—— 这正是你上次反馈的「闪」的另一种形态，只是从「重播入场」换成了「底色透出」。 D 把同一段动画降到面板里那层透明内容层上，载底色的面板恒定不动，于是既不透色、也不重叠， 而且与 B 同参数、同档成本，只差一个挂点。

C 同样不透色，但换来约 70ms 的两屏文字重叠，且这 150ms 内两份文档同时挂在 DOM 上。综合下来 D 最省。

4 · 实现形状

件改什么
fullscreen/useDocumentView.ts 一次性标记的触发条件从「viewMode 变化」扩为「viewMode 变化 或 active false→true」（用 prevActiveRef 判边沿，避免首帧 active=true 也播一次）；
驱动 effect 由 useEffect 改 useLayoutEffect——见 §5 第 ③ 条
FullscreenEditor.module.css 新增 @keyframes tabInA / tabInB（两段内容逐字节相同，只为能重启）+ .tabEnterA / .tabEnterB；
D 的写法和现有 paneIn 不共用一套选择器 —— paneIn 打在 .editorPane / .previewPane 上， D 要打在 .editorBody / .previewBody 上；
各配一条 :global(.no-anim) … { animation: none }
fullscreen/DocumentChrome.tsx 把标记从「布尔 paneEnter」换成「自增 tick」，class 在两段 keyframe 间交替 —— 见 §5 第 ② 条
覆盖面（必须说清）：这条链只走到 CodeMirror 家族（md / txt / code / json / csv / log / html / sql…）。 rich（Tiptap，RichFullscreen 的 .fullscreenWrap）、diagram（React Flow 画布）、 diff（.main 双栏）三类没有 .editorBody 这一层，不在这条链上 —— 要不要各自接一根，是这一稿要你拍的一个点。 另：D 的挂点要求「面板底色不透明」，这三类里若哪一类的底色原本就透（例如画布类）， 需要先给它垫一层不透明底色，否则 D 会退化成 A / B。

5 · 四个顺带要定的

#事结论 / 做法
① 新建页签后立刻显示，要不要播？ 不播。仅认 false→true 这条边沿。开机/新开就看到自己淡入，像加载慢。
② 240ms 内连切两次 现在的 paneEnter 是布尔：第二次 setPaneEnter(true) 时它已经是 true，React 不重渲染 ⇒ 动画不会重播。
做法：换成自增 tick，class 在 tabEnterA / tabEnterB 之间交替 （两段 keyframes 内容完全相同）。纯 CSS 方案，no-anim 与 prefers-reduced-motion 的既有兜底继续免费生效。
③ 首帧时序 useEffect 在 paint 之后才跑 ⇒ 会先画出「最终态」一帧， 下一帧才从 opacity:0 重播，用户看到的是闪一下再淡入。 必须改 useLayoutEffect（paint 前），动画与「显示」同帧成立。
这是现值里就有的隐患 现在 paneEnter 用的正是 useEffect， 视图模式切换时同样有这个一帧闪。
④ 跨类型切换时
格式栏行高跳		 markdown / csv 有格式栏（36px），code / json 没有 ⇒ md ⇄ json 互切时内容区会 整体跳 36px。这是内容动画盖不住的另一种「跳」，属于本次范围外。 要么本次不动（记进已知问题），要么给格式栏固定占位 —— 见下方选择题。

6 · 合规

项判定
U2 时长150ms / 200ms 均在 [150,200,300,400] 四档内 通过
U2ease 缓动取 M3 常规 cubic-bezier(0.2, 0, 0, 1)，在两条许可曲线内 通过
「窗口动画」开关沿既有惯例补 :global(.no-anim) .tabEnterX { animation: none } 通过
系统「减少动态效果」由 globals.css 的全局兜底处理（animation-duration: 0.01ms !important）， 不需逐文件补 @media 通过
U2「位移动效是否承载信息」不承载——纯装饰，切换结果本身已由页签高亮与工具栏文件名表达，无需静态替代 通过
三个要你拍的点： ① 选 A / B / C / D 哪一个（推荐 D：与 B 同参数同成本，但不会透出 --app-bg）； ② rich / diagram / diff 这三类要不要一起接（默认不接，只保 CodeMirror 家族）； ③ §5 第 ④ 条的格式栏跳（36px）本次是否顺带处理。
