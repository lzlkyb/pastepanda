定位算法（两版共用）

坐标系节点位置是 flow 坐标，浮岛是 .root 里的绝对定位元素。用 flowToScreenPosition() 转屏幕坐标，再减容器 getBoundingClientRect() 的原点。浮岛不能放进 .react-flow__viewport——那层带 transform，会跟缩放一起缩小
竖向优先上方：top = nodeTop − islandH − 10；若 < 8 则翻到下方 nodeBottom + 10（小尖角跟着调方向）
横向居中于节点：left = nodeCenterX − islandW/2，钳制到 [8, canvasW − islandW − 8]
重算时机选区变、节点拖动、视口变（onMove）三个时机。就一个 div，每帧重算不心痛
浮岛的档位已修正（实现后推翻了本稿原先的写法）：原写“紧凑档不用浮岛”是错的——把两个无关的门槛当成一个开关了。760px 管的是“三块并排”；浮岛实测只约 338px，402px 画布都装得下。按 760 一刀切的后果是：600px 窗口（弹框画布 512 / 全屏 568）下浮岛永远不出现。现在分成两个阈值：COMPACT_MAX_WIDTH=760 管三栏并排，ISLAND_MIN_WIDTH=380 管浮岛。紧凑档同样渲染浮岛，抽屉改由「⋯」控制

二、紧凑档：抽屉随选中节点翻面

默认显露程度按空间递进（实现时补的规则）： 画布 ≥760 → 浮岛 + 右侧面板默认展开；380–760 → 浮岛 + 抽屉默认收起（点「⋯」）； <380 → 无浮岛，只有抽屉且展开。量不到容器尺寸时什么都不画——不能把测量失败态 当成“极窄”而自动展开全属性，否则弹框（有入场动画、测量比全屏晚）会比全屏露得还多。

节点在画布上半 → 抽屉贴底（左）；节点在下半 → 抽屉贴顶（右）。 零新布局，只是 bottom:12 与 top:12 二选一，但抽屉从此永远不盖住选中的节点，鼠标行程也短一半。

四、④ 形状拖拽新建

形状库按钮加 draggable；拖到画布落下就在鼠标处建节点。原有的“点一下加到画布中心”保留（触屏与习惯兼容）。

传的什么dataTransfer.setData("application/pastepanda-shape", key)。自定义 MIME 而不是 text/plain：否则从外部拖任意文本进画布也会被当成建节点
落点onDrop 里 screenToFlowPosition({x: e.clientX, y: e.clientY}) → addNodeAt(pos, shape)。这个函数已经收形状参数，不用改签名
必须阻默认onDragOver 里 preventDefault() + dropEffect = "copy"，否则浏览器不允许 drop
落点预览虚框 ghost 跟随鼠标（上图）。用 pointer-events:none，否则它自己会吃掉 dragover
吸附落点走同一个 22px 网格（第一批加的 snapGrid），才不会拖出来就偏半格

五、不做的事

连线上的浮岛选中连线时不弹浮岛：连线只有“说明 + 线型 + 删除”三项，右键菜单已经盖全，再加一层重复
多选时的浮岛当前模型只支持单选改属性（selectedId 是单值）。多选批量改属性是另一个题，不塞进本批
拖拽时的自动平移拖到画布边缘自动滚屏（React Flow 的 auto-pan）——402px 画布上容错空间太小，容易误触，往后单独评估
