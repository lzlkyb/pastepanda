全部来自源码核对，不是猜测。修复方式与方案 A/B/C 无关，三个方案都必须做。

二半、图标重绘与中文标签（用户反馈：看不懂是干什么的）

先说结论：图标再怎么画也解决不了"看不懂"。马赛克 / 模糊 / 高亮 这类概念本来就没有公认图形， 纯图标方案下用户只能猜。所以两件事一起做：每个按钮加常驻中文标签（QQ 截图走的就是这条路，微信是纯图标但它只有 6 个工具）+ 图标统一重绘。

图标为什么"不好看"：四个具体原因

问题旧实现新做法
粗细不一stroke-width 混用 1.4 / 1.5 / 1.6，11 个图标并排时轻重不一致全部统一 1.5，抽成共用常量
端点尖刺默认 butt 端点 + miter 拐角，16px 下有毛边统一 round 端点与拐角
序号图标位置飘内嵌 <text> 画数字 1，字体由系统决定，不同 DPI 下对不齐数字用 path 手画，不依赖字体
图形与含义无关模糊 = 三个半透明圆点；高亮 = 一个实心矩形（和"矩形"工具几乎一样）；箭头头是两条细线拼的直角模糊 = 水滴（Photoshop 同款）；高亮 = 荧光笔斜笔头 + 色带；箭头头改实心三角

常驻标签的代价与应对

按钮从 30×30 变为 38×42（图标 17px 在上、标签 9px 在下），主栏横向约 620px。 一个高频后果是：窄选区时工具栏比选区宽得多。这正好是 §3.5 里定位规则要处理的第四条（工具栏宽于选区 → 改为左对齐选区左边缘）。 快捷键角标从按钮右下角移除（标签占了那个位置），改到 tooltip 里说。

✓ 已复制到剪贴板

复用已有的 .picker-bar 位置（底部居中），成功走绿色、失败走红色，3 秒自动消失。覆盖点：finish / copyImage / ensureResultPath / saveToGallery / pinImage / copyText 六个出口的 catch 分支。

3.4 长截图状态条（对应问题 4）

长截图中 · 已拼 7 屏 · 高度 2140px 停止并出图 放弃

这是之前那份长截图设计稿的 §1–3。两个按钮语义必须分开："停止并出图"= 用已拼的内容出图；"放弃"= 什么都不留。

❗ 实施时发现的硬约束，比原来估计的严重

后端 hide_screenshot_window 走的是 Tauri 的 window.hide()。 窗口一旦 hide，WebView 收不到任何输入事件（键盘 / 鼠标 / 右键全部无效）。两个直接后果：

① 状态条没地方显示（整个窗口都不可见）；
② 更要紧的：现有代码里的"长截图中 Esc / 右键中止"（abortLongRef）是个死功能 —— 设计上它要求用户在窗口隐藏期间按键，而那时候根本没人接收这个按键。长截图一旦开始就无法中途停下，只能等 40 帧跑完。

所以"停止并出图 / 放弃"两个按钮不是画上去就行，先得解决窗口可见性。三条路子见下表。

✅ 已采用乙：独立小窗口（已实现）

新增窗口 longshot-status（300×48 逻辑像素，无边框、置顶、不抢焦点），入口 longshot.html。

位置选择是关键：后端 pick_status_pos 按优先级试六个候选位（右下 → 左下 → 右上 → 左上 → 底部居中 → 顶部居中）， 取第一个完全在屏幕内且与选区不相交的。不相交就不会被每帧的 BitBlt 拼进长图 —— 这是确定的几何事实，不靠透明度赌。 六个位置都不行（选区占满屏幕）则宁可不开窗，并在隐藏前弹 toast 告知"本次无法中途停止"。配了 7 条 Rust 单测。

通信链路：主窗每拼一帧 emit("longshot-progress")（帧数/高度/26×40 缩略图）； 状态窗点按钮 emit("longshot-control") 回主窗设 stopLongRef / abortLongRef。 这条链路只依赖一件已被现有代码证明的事：隐藏的 WebView 仍能执行 JS 与收发 IPC（长截图循环本身就在隐藏期间跑并持续 invoke 后端）。零未知假设。

路子做法风险
甲 不隐藏窗口长截图期间只隐藏遮罩/选区框/工具栏/画布，窗口本身保持可见但选区内完全透明；再给窗口开鼠标穿透（set_ignore_cursor_events）让滚轮能打到目标窗口依赖两个未实测假设：① 完全透明区不会被 BitBlt 截进去；② 鼠标穿透后 WindowFromPoint 能拿到下层窗口。错了就是长图里夹一层遮罩，或者完全滚不动
乙 独立小窗口新建一个 260×44 的无边框 Tauri 窗口放屏幕角落（必然在选区外，不会被截进去），主窗照旧隐藏要改 Rust 端 + 新 HTML 入口 + capability 配置；我无法在本会话实测，但逻辑上没有未知假设
丙 只做结果反馈过程中不显示，结束后用 toast 报告（已拼 N 屏 / 未捕获到内容 / 失败原因）零风险，已实现。但解决不了"中途停不下来"

3.5 定位修复（对应"离选区太远"和"钻进选区"）

场景新规则
正常工具栏右边缘对齐选区右边缘，位于选区下方 8px
下方放不下翻到选区上方 8px，同时给根元素加 top-attached 类 → tooltip 改为向上弹（修死规则）

3.6 取消按钮（用户点名要的）

位置在"完成"左边，.tool.cancel-btn 样式已存在直接复用。语义：等同标注态右键 / Esc —— 清空标注回到选区态，而不是关窗（两级取消，规则 17.6）。data-tip 写"取消标注，回到选区（Esc / 右键）"。
