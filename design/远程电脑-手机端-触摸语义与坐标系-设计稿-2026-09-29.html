§0结论先行（四条核心决策）

D1 · 手势集抄 RustDesk 移动端最小集（7 个）
点按=左键、快速双击=双击、单指拖动=移动、长按=右键、长按拖拽=左键拖拽、双指滑动=滚轮、双指捏合=本地视野缩放。不做三指、旋转、双指点按等扩展。
D2 · 坐标换算零修改，复用 mapNormFromCanvas
桌面链路全程 CSS 像素口径（clientX/Y → rect → 0..65535 归一化），天然 DPR 无关。双指缩放用 CSS transform，getBoundingClientRect() 返回 transform 后包围盒，几何公式自动吸收——「点不准」的最大风险已被现有设计覆盖。
D3 · 软键盘走打字档（Text 整串注入），修饰键条 sticky 挂起
手机 IME 必走组串：compositionend 后发 {kind:"text"}（乙-①已有通道），逐键 key 只作直传档。修饰键点按=挂起一次，组合后自动解除。Win 键手机端可直接用——桌面端拦 Meta 是防本机被劫持，手机没有这个问题。
D4 · fit 三档语义保留，pinch 是另一层「本地视野」
适应/填充/1:1 决定 canvas 布局基准（与桌面 RcCapsule 同语义）；双指捏合是 canvas 容器上的 transform 缩放（0.5×–4×），不碰远端、不影响归一化坐标。两层独立，高频路是 pinch，fit 档收进画质浮条。

为什么「长按拖拽」映射左键而不是右键拖动：高频需求是拖文件、框选、移动窗口，全部是左键拖拽；右键拖动（Send to / 右键菜单拖动）是极低频操作。RustDesk 同此判。④⑤共享「按住不动 550ms」入口的分支设计：不动松手=右键，动了=左键拖拽，一次判定两个语义，无需额外开关。

§4坐标系与 DPR（「点不准」的技术判书）

4.1 全链路只有一种像素口径：CSS 像素

结论：手机端不需要任何 DPR 换算代码。桌面端在物理像素屏幕上跑同一套函数已经是对的；手机 DPR 2.5–3.5 只是「CSS 像素更小、物理点更密」，链路上没有任何一处出现 DPR。Pinch 缩放用 CSS transform 后，getBoundingClientRect() 返回 transform 后包围盒（均匀 scale 无旋转时），mapNormFromCanvas 的 rect.width / nw 公式自动吸收缩放系数——缩放中点按依然准。唯一红线：不允许旋转 / 非均匀缩放（§1 手势⑦已锁）。

4.2 fit 三档在手机竖屏（393×852 看 1920×1080）的表现

适应 fit（默认）：整画面可见，上下 letterbox。画面小 → 高频靠 pinch 放大看，这是手机与桌面最大的体验差
填充 fill：左右裁切，无黑边。内容不全，坐标仍准（几何同 contain 的 max 分支，函数已支持）
1:1 actual：canvas CSS 尺寸 = 帧物理像素，手机上≈放大 3 倍只看局部，配 panBox 滚动。低频，收进浮条「画面」档

⚠ 与桌面的一个语义差：桌面「1:1」= 物理像素对物理像素；手机 DPR≈3，「1:1」实际观感是放大三倍。但坐标语义完全一致（canvas 内部像素 ↔ 远端像素一一对应），不引入第四档「真实物理 1:1」——P1 不做，列 §6。

4.3 横竖屏旋转

  • 机制零新增：旋转 = Android WebView resize → getBoundingClientRect() 现算自校正（桌面「窗口 resize 后下一次移动鼠标即自校正」同机制，rcCanvasStyle.ts 注释原话）。
  • 旋转瞬间正在按住（拖拽中转屏）：触发 releaseTracked() 等价逻辑全量松开——按键不跨布局存活，防「松手在旧几何、UP 发到新坐标」的错位点按。
  • 会话不重连：旋转只影响布局，WebCodecs 解码器与帧泵不销毁（surface 尺寸变化由 canvas width/height 重设承接，与解码解耦）。
  • 横屏建议：会话中首次旋转到横屏时给一次轻提示「横屏画面更大」（L4 就地一句话），不自动旋转锁定——尊重系统旋转锁。

§5软键盘 + 修饰键条

5.1 文字输入主路：打字档（Text 整串注入）

手机 IME（拼音/手写/语音）必然走组串，桌面乙-① 的通道原样可用：隐藏 <input> 聚焦唤起软键盘 → 监听 compositionend → 发 {kind:"text", text}（对端 KEYEVENTF_UNICODE 逐码元注入）。逐键 key 转发（keyToVk）只服务直传档（密码框/游戏/快捷键场景，用户在浮条显式切换，同桌面两档语义）；手机默认打字档。

5.2 修饰键条：sticky 挂起（点按 = 挂一次）

操作行为线上事件
Ctrl 点按挂起：高亮青色；键盘条上该键呈粘滞态key vk=0xa2 down:true（立即发，远端光标可见 Ctrl 生效）
挂起后按任意键（软键盘字符 / 功能键 / 点画面）组合完成，自动解除挂起后续键的 down/up 正常发，随后补 ctrl up
挂起后Ctrl 再点取消挂起补 ctrl up（零副作用）
多颗修饰键连点组合挂起（Ctrl+Alt+Del 场景）各 down 依次发，组合键完成后逆序 up
Win 键是手机端与桌面端行为唯一不同的一颗键：桌面 shouldForwardToRemote 拦 Meta（rcKeyMap.ts:93）是防止本机 Windows 被真实 Win 键劫持；手机上没有本机桌面可劫持，Win 键走同一条 sticky 挂起，Win+D / Win+E / Win+Tab 手机直达。这是移动修饰键条的核心价值之一。
