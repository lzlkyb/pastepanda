B3 · 搜索结果高亮

🔴 我提议时说「FTS5 自带 snippet()/highlight()，能直接用」——错了。
notes_fts 里存的**不是原文**，而是 to_ngram() 变形后的文本： 中文被拆成「单字 + bigram」并用空格连接（history.rs:45）。 snippet() 返回的会是被空格切碎的 ngram 串，根本不能给人看。

所以高亮必须在**前端对原文**做。这反而让这一项变成**零后端改动**。
搜「会议」
周一会议纪要
…上周的会议结论是先做 MVP…
  • 只高亮**标题与列表摘要**两处，不碰第三栏正文（那里是 CodeMirror，改它是另一件事）。
  • 摘要优先**截到命中处附近**而不是固定取前 120 字——否则命中在第 300 字时什么也看不到。
  • ❗ 模糊匹配的那部分（拼音首字母、bigram 部分命中）**高亮不了**。 只高亮原文里的字面命中，匹配不上就不高亮——不编。

B4 · 时间范围筛选

NoteViewOpts 加一个 updatedWithin，与现有三态筛选同一个面板。

""     不筛
"7d"   最近 7 天改过
"30d"  最近 30 天
"90d"  最近 90 天
❗ 必须保住 push_view_filters 「不带参数」的不变式。 那个函数的注释写着「全是字面 SQL、不带参数，所以可以随意拼在哪一步， 不会扰乱位置绑定的序号」，而项目里刚因为位置绑定错位踩过坑（bump_search_hits）。
做法：在 Rust 里把白名单枚举算成一个日期字符串，**内联成字面量**。 值完全由我们自己生成（枚举 → 天数 → 格式化），不碰用户输入，无注入面。

B5 · 专注写作（全屏）

🔴 我提议时说「壳是现成的」——估少了。 FullscreenEditor 是一个**独立 OS 窗口**，它的整个模型是「剪贴板内容」： open_fullscreen_editor({ sourceId, content, contentType, language }) 里的 sourceId 是 **history id**，窗口内都写着 sourceId ? "剪贴板内容" : …。 接笔记进去需要：新 contentType + 传标题 + 一条 note_update 回写路径 + 跨窗口保存事件——而那个文件已经 974 行、本身就超规则 #7。

改成应用内全屏：第三栏临时铺满整个知识库区（侧栏与列表让位）。

独立 OS 窗口应用内全屏（采用）
后端改动新 contentType + 回写路径零
保存/历史/AI/脏数据守卫得在新壳里重接一遍直接复用 NoteDetailPane，全部现成
双屏摊开能不能

实现：KnowledgeView 加一个 zenMode state，为真时不渲染侧栏与中栏。 入口：第三栏顶部一个图标 + Esc 退出。 ❗ 第三栏的 key={note.id} 不能因为切全屏而变，否则 CodeMirror 重建、 未保存的草稿会没——全屏只能改外层布局，不能重挂载面板。

补：查看笔记默认预览 + 三形态统一

需求：知识库里看笔记应该**默认预览**，并与全屏 Markdown 编辑器的三形态统一。

要对齐的那套（真实定义）

fullscreen/types.ts:16   type ViewMode = "edit" | "split" | "preview"
TRI_MODES = [
  { key: "edit",    title: "仅编辑", Icon: PanelLeft },
  { key: "split",   title: "分屏",   Icon: Columns2 },
  { key: "preview", title: "仅预览", Icon: Eye },
]

知识库原来**根本没有「形态」这个概念**：NoteEditorPane 直接渲染一个写死的 .split，没有切换器、没有仅预览。

决策做法
定义来源把 TRI_MODES 从 registry.tsx 移到 types.ts，两边 import 同一份（规则 #11）。不能为三个按钮把整个全屏注册表拉进知识库
切换器位置顶部（第三栏标题行 / 弹窗标题行），对齐全屏编辑器的工具栏
默认形态打开**已有**笔记 → preview
新建 / 转卡片→ edit。那时正文是空的或刚粘进来的，预览一片空白没意义；且这一次的 edit **不写进偏好**
记忆localStorage（形态是稳定偏好，与筛选那种一次性意图相反）
❗ 编辑区在仅预览时靠 display:none 隐，不能不渲染。 CodeMirror 的初值只在挂载时读一次，卸掉再挂会丢掉刚敲还没提交给 state 的那一小段， 而且每次切形态都会丢光标与滚动位置。全屏编辑器用的也是 display:none。
❗ 分屏在窄的第三栏里不可用，所以会置灰。 阀值 620px，用 ResizeObserver 量**本栏**而不是 window.innerWidth—— 侧栏可以收起，收起后同一窗口宽度下第三栏会宽 180px，拿窗口宽猜会在那个区间里猜错。 分屏下把窗口收窄会**自动退到预览**，而不是留一个每边 150px 的碎屏。

红线与不做

  • 七项**全部无 AI**，不受 ai_enabled 门控，也不等 C（M3）的 embedding 选型。
  • 全部走本机 SQLite，不出网。
  • 不动搜索框位置（A-56 已拍板）；不加自动保存（A-58 已拍板）。
  • A4（回收站搜索）与 A5（单篇另存）**不在本轮**——它们不在推荐顺序里。
