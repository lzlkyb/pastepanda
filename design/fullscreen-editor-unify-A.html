目标架构

一句话：外壳（工具栏 / 主题 / 全屏 / 关闭守卫 / 状态栏）只写一次 → 按 spec.variant 把「中间内容区」交给类型主体。

// FullscreenTypeSpec 新增字段
variant: "single" | "dual" | "canvas" | "rich";

// FullscreenEditor 渲染层：删掉 if-else，改 variant 分发
<FullscreenShell spec={spec} onClose={handleClose}>
  {spec.variant === "single" && <FullscreenInner spec={spec} .../>}
  {spec.variant === "dual"   && <DualPane spec={spec} .../>}   // diff 挂这里
  {spec.variant === "canvas" && <DiagramBody spec={spec} .../>} // diagram 挂这里
  {spec.variant === "rich"   && <RichBody spec={spec} .../>}    // rich 挂这里
</FullscreenShell>

FullscreenShell（新增，复用层）

  • Toolbar：styles.toolbar + tbBtn/tbBtnPrimary/tbBtnIcon/tbSep
  • 主题：THEMES.find().dark 查表（消除三类硬编码）
  • 全屏切换 / 关闭守卫（脏 → ConfirmDialog，统一一处）
  • 状态栏：styles.statusBar（类型注入 left/right 统计）
  • SkinScene 背景层
  • 把 onClose / isDirty / fileName / dark 等经 props 下传

类型主体（保持原内核）

  • single 现有 FullscreenInner 不变
  • dual 复用 useDiff/DiffPane/DiffAiMenu，仅挂到壳
  • canvas 复用 DiagramCanvas + AI 面板
  • rich 复用 RichContentEditor
  • 三类不再各自写工具栏/主题/状态栏

registry 变更（让死代码活起来）

// registry.tsx — 给三类补 variant，删掉「最小占位」注水的字段
markdown/json/html/text/csv/log/code → variant: "single" (现有)
diff    → variant: "dual"    // 双栏对比
diagram → variant: "canvas"  // React Flow 画布
rich    → variant: "rich"    // Tiptap 图文
注册表现在被 真正消费：FullscreenEditor 只按 spec.variant 分流，不再有 if (contentType===) 分支；新增类型只需加一个 Spec 项 + 一个主体组件。

diff 双栏形态（variant:"dual"）落地后的外观

复用统一工具栏与状态栏（styles 一套），中间双栏挂 DiffPane。主题跟随 THEMES 查表。

验收标准

  • 一致 切任意主题，diff / rich / diagram 全屏明暗与 single 类同步（无漏判）
  • 一致 四类工具栏按钮、间距、状态栏样式视觉无差异
  • 一致 diff 全屏 Esc 有关闭守卫（脏 → ConfirmDialog），与 single 同口径
  • 无回归 diff 双栏对比、同步滚动、AI 菜单、全屏深编入口全部正常
  • 架构 FullscreenEditor.tsx 无 if (contentType===) 分支；FULLSCREEN_TYPES 全部被消费
  • 测试 现有 FullscreenEditor 相关 vitest 通过；新增 variant 分发单测
范围边界（本方案不做）：
  • 不改 diff 算法/AI 能力（复用现有内核）
  • 不动 Rust（open_fullscreen_editor 已支持 contentType）
  • 不把单栏 CodeMirror 与双栏 diff 强行合并（语义不同，用 variant 区分而非塞进 Preview 槽）
  • PPDIFF 编码二期再统一（可选）
