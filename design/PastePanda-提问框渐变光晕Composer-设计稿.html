提问框渐变光晕（Composer）· 交互实测稿

参考图是 ChatGPT/Claude 那类「输入条」：暖→冷渐变描边光晕 + 半透玻璃体 + 下一行左工具右发送胶囊。 本页把它拆成四层，只借其中两层，并且只在 3 个真·提问框上试（知识库追问 / AI 追问 / 变换中心指令条）—— 顶栏搜索框等 20+ 处是 32–38px 的定位控件，不是 composer，本页不给它们改。

✅ 本页可交互可验：主题 6 套可切、静息/焦点/禁用三态可切、光晕强度两根滑杆可拖（公式与将来写进代码的那一条完全相同）、 所有高度与对比度都是 getBoundingClientRect() / getComputedStyle() 现量，不是手填。

⚠ 首版有两个坑，你遇到的「滚不动 / 卡」就是它们，现已修：① 本页 link 了产品的 globals.css， 它里面写的是 body { overflow: hidden; user-select: none }（App 是单屏窗口，这两条在产品里是对的）， 直接把这个近 3000px 高的文档钉死不滚、还选不中文字 ⇒ 本页显式反接了 overflow: auto，并把它做成自检条上的一条机械判据； ② §4 的「反解达标档」原本是 6 主题 × 71 档，每档都写一次 CSS 变量再读回来 = 426 次强制样式重算， render() 单次 735ms，滑杆挂在 input 上就是 1.4fps 假死 ⇒ α 改成纯数学推导（每主题只读 3 个端点， 并逐主题回对一次 CSS 真解析值），且拖动中只改变量（0.3ms/步）、松手才重算表格。

已拍板三条（本轮问答确定）：① 先出稿看效果再定投入；② 圆角用现有 12 顶格，不为 composer 单开一档、不改 U5 与 lint 规则； ③ 光晕静息淡、焦点亮，不做常驻强渐变。

怎么读这一页（30 秒版）
  1. 先只看 §2：左边一列是软件现在的样子，中间和右边是两种改法。上面那排按钮能切 6 套主题、切「静息/焦点/禁用」，两根滑杆调光晕浓淡。哪一栏顺眼，就选哪栏。
  2. 再对 §3 一个数：中间那栏（完整解剖，跟参考图一模一样）每处要多占 34~41px 高；右边那栏（只换边框和按钮）只多 2~9px。多出来的高度就是从正文区抢走的可视区。
  3. §4 不用细看，它只回答一件事：这条边框亮起来的时候，键盘用户看不看得出来焦点在这儿。结论是「光晕负责好看，实色环负责看得出来」，两种职责不混。
  4. 最后看 §6：四个待拍选项，每个都写了我的默认。你只回「P1 用默认」也行。

§4光晕在 6 套主题下的实际取值与焦点可见性

判据：焦点指示器按 WCAG 2.2 非文本对比 ≥ 3:1，比较对象是它两侧相邻色里更关键的那一侧——卡底 --card-bg（内侧是 --dialog-bg，两侧都量的话取严的看结论不变）。 静息档故意远低于 3:1——它只是「有条边」，不承担可达性职责。 颜色由 canvas 逐像素读出（getComputedStyle 会把 oklch() / color(srgb …) 原样吐回来，正则抠 rgba() 会全读成 NaN——本轮第二处翻车）。
