对比与建议

方案学自 ThreeUI优点代价 / 风险建议
A1 现状渐变—零改动，浅色下可读性已达标无对照组
A2 液态玻璃Animated Top Dock深色主题质感提升明显；不动物理布局，只换 header 背景 + 边框 + 内高光，纯 CSS；沿 --glass-card-* 变量体系走backdrop-filter 每帧重算 × 常驻顶栏；ocean-dark 背景有动画时按现规则必须关模糊（theme.css 已有此纪律），需退化为半透明底色；浅色主题下收益小推荐，但仅对无动画场景主题开启
A3 悬浮 dock同上（悬浮形态）视觉最「炫」，内容穿底效果强顶栏是 data-tauri-drag-region 拖动区 + 无边框窗唯一窗口控制位，改成 margin 浮动后拖动热区、贴边吸附都要重新验证；高度多占 ~20px，挤压 480px 竖向空间不推荐：风险/收益比最差
B1 环形Performance Gauges一眼读数，conic-gradient 零依赖零 JS4 格并排在 452px 内宽下每格仅 ~106px，标签字号受限可用
B2 条形同上最贴现有紧凑行式风格；可无线上下加行；对齐 M 系列 / 成就卡既有密度冲击力弱于环形推荐
B3 趋势卡Gauges 变体思路带趋势方向，信息量最大；sparkline 静态 SVG 成本为零2×2 网格占高最高；「七日」需要新查询二期，等统计查询地基

实现边界（与既往结论一致）：不引 npm 包、不引 three.js——本体全 Canvas2D 零依赖，且 three 运行时 ~600KB 顶撞 exe ≈14MB 体积预算。A2 仅抄 CSS 手法；B1/B2/B3 均为纯 CSS/静态 SVG。三条红线无涉：无 AI 行为、数据本地。

另一条零成本可学的：variant 控件系统

ThreeUI 每个组件 = 母组件 + 变体 + 实时控件 + 源码 tab。对应我们 design/ 流程：以后 mockup 统一带顶部控制条（本稿即示范），替代「一方案一个 html 文件」；参数用滑块实时改 CSS 变量，评审时当场看边界值，不用来回改稿重发。
