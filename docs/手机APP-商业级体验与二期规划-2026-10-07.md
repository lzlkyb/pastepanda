本轮进一步只读核对：`src-tauri/src/lib.rs` 已注册 SyncService；`commands/rc.rs` 有用户明确授权的 `kb_sync_allow_from_rc`，因此 M6 后端并非空白，远控配对不能自动等同于知识库同步许可。`sync/attach.rs` 的本地图片路径识别存在 Windows 盘符假设，需要验证移动图文附件往返。`dpapi.rs` 的 Android 身份保护目前依赖应用沙箱，iOS 分支尚不支持该存储契约；二期需补平台身份存储和生命周期验证，不能仅加 iOS 页面。系统分享接收处理也尚未出现在当前 MainActivity，需补原生载荷、URI权限有效期和草稿恢复。

## 三条路线

| 路线 | 改动 | 优点 | 代价 |
|---|---|---|---|
| A：现有界面精修 | 保留胶囊导航和整页横滑，统一字号、间距、控件及状态 | 变化小，使用习惯延续 | 跨页手势与独立任务之间仍需仲裁，二期扩展后复杂度增加 |
| **B：统一移动工作台，推荐** | 统一页面、导航、工具、提示、动效；顶级页面点击切换；二期按能力加入 | 一期与二期共用一套规则，画面/内容优先，减少手势冲突 | 顶级页面横滑改为点击导航，需要用户确认这项习惯变化 |
| C：原生界面重建 | Kotlin/Compose 重建 Android 界面，iOS 另建对应界面；复用 Rust 引擎 | 更直接使用平台控件与导航能力 | Rust 桥接、两套 UI、测试及迁移成本大；不能仅凭换框架保证流畅 |

B 不重写引擎；需平台能力的系统栏、返回、IME、安全区、系统分享和触觉走原生桥接。保留四种操作方式与触控板首选默认。C 只作技术路线对照，HTML 不模拟或宣称原生运行性能。

## 建议借鉴什么

- [AnyDesk Android 官方说明](https://support.anydesk.com/docs/anydesk-for-android)：会话工具按输入、显示、操作与退出组织。本项目保留文字入口，不照搬长按 Logo 才能发现菜单。
- [Jump Desktop Controls and gestures](https://docs.jumpdesktop.com/viewer/session/controls-and-gestures/)：输入方式可选择，手势说明与模式在同一入口。借鉴“选择方式 + 就地学习”，不改变本项目现有四种方式的语义。
- [Android 自适应导航](https://developer.android.com/develop/ui/views/layout/build-responsive-navigation)：根据可用窗口切换底部导航/侧栏，并保持同一目的地的状态。
- [Android 窗口尺寸等级](https://developer.android.com/develop/ui/compose/layouts/adaptive/use-window-size-classes)：同时考虑窗口宽高，横屏短高度与平板不等价。本项目用 WebView CSS/布局 Hook 对应，不直接引入 Compose。
- [Android 沉浸模式](https://developer.android.com/develop/ui/views/layout/immersive)：隐藏系统栏并允许系统边缘临时唤出；普通页面恢复。
- [Android 短消息](https://developer.android.com/develop/ui/views/notifications/snackbar)：短反馈与操作共存，可带动作。远控内仍使用独立工具区域，避免遮挡远程目标。
- [Apple Motion](https://developer.apple.com/design/human-interface-guidelines/motion)：动效解释状态与空间关系，短、可取消、可减少；为二期 iOS 保留平台差异。

这是官方资料研究，未亲自操作竞品，不据此宣称竞品帧率或动画参数。

## 视觉系统

推荐“清爽、克制的专业工具”：保留蓝色品牌关系，以实底白/深色表面、清楚字阶、统一 SVG 图标和分组建立质感。降低大面积渐变与玻璃的比重；只在必要的悬浮工具体现层级，不给每张卡片模糊。

- 语义令牌：背景、表面、次级表面、主/次文字、强调、分隔、成功、警告、错误、遮罩。映射现有主题变量，避免另建一套冲突主题。
- 字体：中文优先平台系统字体，不额外下载仅支持拉丁字符的展示字体。普通正文建议 16，次要说明 14，页标题 20，分组标题 15–16；远程工具紧凑标签可为 12–13。用角色令牌与可缩放单位实施。
- 间距：4/8/12/16/24/32；手机边距 16；分组 16，浮层 24，内层圆角随内边距递减。
- 可交互区域：Android 至少 48dp、iOS 至少 44pt。WebView 中不能直接把 CSS px 当 dp/sp，须核验 viewport 与系统字体缩放的映射。
- 一屏一个主要行动，图标配常驻文字，状态不只靠颜色。已选/正在请求/禁用/失败视觉可区分。
- 深色单独定义表面和对比，不做简单反色。正文对比 ≥4.5:1，关键非文本控件 ≥3:1；需在最终主题实际合成色上测量。

## 全 APP 信息架构

一期：**设备 / 文件 / 设置**。

二期知识库交付后：**设备 / 文件 / 知识库 / 设置**。导航目的地以稳定 id 配置，允许根据能力追加；不在一期露出点不动的“即将上线”空入口。系统分享是系统动作与 App 内流程，不占第五个主 Tab；离线是知识库/文件内容状态，不另造一个离线 Tab。

顶级页面是不同任务，B 建议点击导航配短淡入，不整页左右滑动。列表纵向滚动；文件筛选、知识库分类等局部 Tab 如需滑动，限制在明确区域。二级页面返回尊重 Android 系统返回；iOS 边缘返回做平台实现。远程画面的所有触摸只服务远控，不允许触发 App 翻页。

按目的地保存滚动位置、筛选、草稿及选中设备；未就绪的后台页面暂停动画和请求，不能靠每次切换重建页来“清状态”。文件收发在后台页运行的边界取决于已实现的原生服务与系统约束，UI 不承诺无限后台运行。

## 逐页升级

| 页面/流程 | 统一后的行为 |
|---|---|
| 设备 | 紧凑标题；列表优先。在线电脑主要动作“连接”，查看详情/文件/授权为次级；离线或未知状态明确说明，不能只灰掉按钮。多人/多设备时不新增常驻横幅占首屏。 |
| 添加电脑 | 扫码优先，输入配对码为明确备选；显示扫描权限、码校验、等待电脑、SAS 核对、成功/失败；关闭保留合理草稿，不重复开相机。 |
| 连接等待 | 位于画面区域的居中状态，有阶段说明和取消；首帧到达后撤掉占位，禁止顶上加整块公告挤小画面。 |
| 远程竖屏 | 紧凑身份/状态栏 + 最大可用画面 + 独立底部工具区；四种方式从“触控板/当前方式”入口选择。 |
| 远程横屏 | 无常驻 Android 状态栏；画面占可用全高，窄工具列可收起；故障/请求入口在工具区，不在电脑按钮上方悬浮。 |
| 输入与键盘 | 显示当前输入方式，输入法/修饰键/工具互斥关系清楚；按下/抬起成对，打开面板释放按键，关闭动作不穿透。中文字与快捷键模式分别解释。 |
| 设置面板 | 竖屏底开、横屏侧开；标题关闭固定、正文滚动、结果保留在面板底部；电脑接受设置与实际画面应用区分。 |
| 文件 | 目标设备 + 发/取动作 + 任务列表。取回仍明确由电脑选择文件，不设计未实现的远程文件浏览器。失败按任务重试，批量部分成功给出具体数量。 |
| 设置 | 外观、操作习惯、历史、安全/授权、帮助/更新分组；不在首页放开发调试入口，已有触控测试按开发环境处理。 |
| 知识库（二期） | 紧凑列表、搜索与文件夹；手机列表→详情，足够宽时双栏；首版建议阅读/搜索/缓存，编辑能力与同步冲突处理独立确认。 |
| 分享（二期） | 系统分享接入→内容预览→明确选择“发送到电脑”或“保存到知识库”（仅在对应能力就绪时）→目标/保存位置→真实结果。取消不发出，切换接收设备不误用上一设备。 |
| 离线（二期） | 已缓存内容可读，显示缓存时间与“离线副本”；管理容量/清理；离线分享可选“稍后发送”，必须明确用户授权及队列状态，恢复网络不静默发送。 |

## 提示系统与动效系统

复用上一轮 `MobileNotice`、`MobileSheet`、`SessionSettingFeedback`、`SessionFeedback`，补全跨页面一致性，不另写第二套 toast。提示只描述失败原因、下一步和真实状态，技术细节进入“详情”。

| 状态 | 位置/动作 |
|---|---|
| 按下/选择 | 控件即时响应；无成功弹窗 |
| 字段无效 | 字段旁具体原因；保留输入 |
| 设置等待/接受/拒绝/未确认 | 原设置区；关闭后在对应会话入口可找到；失败可重试 |
| 一般短结果 | 独立提示区，单条、可读、不会挡操作；读屏/焦点/系统可访问性时长设置应考虑延长 |
| 持续网络/权限问题 | 就地持久状态 + 明确恢复动作；同因去重，不自动消失 |
| 多任务失败 | 一个摘要保留数量，各任务详情不丢失 |
| 删除授权/断开等决策 | 必要确认；明确影响对象 |

动效用已有项目令牌：150ms 颜色/按压恢复、200ms 局部淡入、300ms 面板、400ms 大范围转场上限。位移弹簧复用 `mobileSpring.ts` 的定参，不另加动画库。

主导航避免整屏横移；面板进入退出沿同一方向。手势位置实时跟随，松手结算可中断；用户再点另一目标直接进入新动作，不能等前一动画结束。有限按压/完成反馈，禁止常驻装饰动画。触觉只用于少量重要动作，并遵从系统偏好。

减少动效保留文字和选中态，删除非必要位移。后台/隐藏页停止动效和延时任务。对动画性能先记录真机帧时间，再评价是否达到原生体感；网页设计稿无法证明 60/120Hz 达标。

## 响应式与平台适配

以可用窗口宽高、安全区和输入法为依据，不通过“设备叫手机/平板”或固定 UA 判布局。

| 条件 | 普通页面 | 远程 |
|---|---|---|
| 窄竖屏 | 底部 3/4 目的地；单列；短页头 | 小页头、底部工具、等比画面 |
| 宽且短的横屏 | 左侧导航；页头收紧；可用空间足够才双列 | 画面全高、右侧窄工具；面板侧开 |
| 平板/折叠展开 | 左导航 + 列表/详情双栏；读取内容有最大行宽 | 根据可用高宽分配面板，保留等比画面 |
| 分屏/IME | 重新计算当前窗口，不把键盘弹出当旋转 | 键盘避让、工具可达、光标定位不漂移 |
| 大字号 | 按钮/列表允许增高和换行，不固定卡片高 | 工具可滚动，关闭/恢复入口不能裁掉 |

CSS px 的原型断点仅用于展示。正式实现复用 `useMobileViewport` / `useMobileLayout` 与 Android insets；窗口尺寸、安全区和文字缩放各自只有一个来源。系统分享/预测返回/iOS 手势由平台 adapter，业务导航及数据状态复用。

## 分批落地与验收

1. **基础系统与全局导航**：主题角色、字号/控件、导航配置、返回/滚动状态。验收：3/4目的地、重复切换、返回、后台恢复，320宽和短横屏无遮挡。
2. **一期全流程精修**：设备→配对→连接→远控→退出；发送/取回文件；权限/失败。验收：每个动作可见反馈，同一可见性域，四种输入方式不回退。
3. **动效与平台收边**：面板可中断、IME/旋转/沉浸/预测返回、读屏/减少动效。验收：真机完整任务、取消期间按键释放、隐藏时不持续动画；60Hz/高刷分别记录。
4. **二期按依赖交付**：知识库查询/阅读和缓存→分享入口→iOS。各项需要单独核对后端能力，缓存失效/授权撤销/冲突、iOS解码与签名通过后才开放对应入口。

先固定系统和导航，再改页面，再接二期。每批都形成可运行 APK 和验收记录，不一次性替换所有页面后才发现交互退化。

验收矩阵：320×640 / 390×844 / 430×932；640×320 / 844×390；平板、分屏；浅深色、130%与200%文字、读屏、减少动效、IME；加载/空/错误/部分成功/超时；弱网、旋转、回到前台、旧电脑端。Web尺寸是布局样本，原生窗口与字体仍须真机验证。
