# 二期知识库：手机端产品与实施规划

日期：2026-10-07。状态：**详细稿已确认，查阅与独立记录首版已接入；真机同步探针待验收**。实施范围及检查结果见 [首版实施与验收](二期知识库-首版实施与验收-2026-10-07.md)。

本稿记录产品范围和分批发布门槛，基于桌面组件、Rust数据与同步源码、手机B导航。下面的目标及早期设计验收记录保留为规划依据；当前交付状态以首版实施与验收文档为准，设计稿演示能力不自动等于App已实现。

## 1. 产品定位与成功标准

**手机知识库是随身查阅、快速记录和资料再利用入口。电脑负责长文创作与集中整理。**

首批优先 Android，之后让 iOS 复用业务和数据契约，再分别实现系统分享、身份存储、返回、安全区与生命周期。

优先服务三个实际场景，暂不按职业创建另一套知识库：

| 场景 | 用户真正要完成的事 | 首批能力 | 成功标准 |
|---|---|---|---|
| 外出办事、会议中 | 找到电脑上整理过的配置、步骤、联系人资料或会议结论 | 本地搜索、常用、文件夹/标签、全文阅读、复制选中内容 | 已同步文字不依赖电脑在线；从知识库进入搜索只需一次点击 |
| 临时想到内容 | 先记住一句话，回电脑再整理 | 快速新建、可靠草稿、本机保存、同步状态 | 未连接电脑也能保存；退后台、旋转、应用重开不丢已落盘草稿 |
| 地铁、出差或弱网 | 带走需要的资料，知道图片是否完整 | 本地正文、附件状态、离线完整性检查 | 有文字但缺图时明确显示；不把部分完成称为“可完整离线阅读” |

后续场景：从其他 App 收集链接/文字；在手机补充或修正一篇现有笔记。前者依赖原生分享，后者依赖版本检查与冲突保留，不能只加按钮。

目前没有真实手机知识库使用数据。这些优先级是产品假设，需通过任务测试验证，不能以“商业级”代替验收。

## 2. 桌面已有能力核对与手机取舍

表中“已有”指已发现组件/命令/数据路径；不代表本次执行了桌面或双机运行验收。

| 桌面能力与源码入口 | 手机价值 | 手机形态与取舍 | 排期 |
|---|---|---|---|
| 笔记列表、标题/正文/拼音检索；`useNoteQuery.ts`、`data_store/note.rs` | 很高：找资料最常用 | 搜索占优先位置，结果显示命中片段；不加 AI 才能搜的依赖 | 首批 |
| 文件夹树、标签、多条件筛选；`FolderTree.tsx`、`NoteFilterPanel.tsx` | 高：缩小查找范围 | 文件夹/标签放选择面板；显示当前条件并可一键清除，默认不摆整棵树 | 首批读取；后续简单归档 |
| 置顶；`note_toggle_pin`、`Note.pinned` | 高：常用资料快捷到达 | 首批“常用”是手机本地快捷标记，按笔记 id 保存；不宣称修改/继承电脑置顶 | 首批；共享置顶另审协议 |
| 最近访问排序；`NoteViewOpts.sort=accessed`、`note_touch` | 高：继续刚才阅读 | 最近阅读采用本机行为记录，回到上次阅读位置；不把它变成全设备行为追踪 | 首批 |
| Markdown 阅读、代码复制、链接、图片、表格；`MarkdownRenderer.tsx` | 很高：内容真正可用 | 默认阅读；标题层级、正文、图片占主要区域，代码/表格局部横滚；复制有同处结果 | 首批基础阅读 |
| 新建、改标题/正文；`notes.ts`、`commands/notes.rs` | 新建很高；长文编辑较低 | 新建先用适合手机的文本输入；现有笔记编辑后置；不直接嵌桌面 CodeMirror 工具栏 | 首批新建；后续轻编辑 |
| 今日速记、日历、待办追加；`noteDaily.ts`、`note_daily.rs` | 快速记一条很高；复杂日历较低 | 首批新建独立笔记；可以按本机创建日期浏览，但不直接追加电脑当天的速记 | 后续验证每日合并 |
| 双向链接、反链；`NoteBacklinks.tsx`、`note_backlinks` | 中高：沿资料关联阅读 | 能点击正文笔记链接；“相关笔记”收在详情；首批不提供关系图和批量关系编辑 | 首批链接；后续反链面板 |
| 修订历史、冲突副本；`NoteHistoryView.tsx`、`NoteConflictView.tsx`、`sync/engine.rs` | 冲突保留很高；手机逐字比对较低 | 冲突版本可读、可复制、保留；完整比较/恢复先留电脑。不能假定历史快照跨设备可见 | 写入上线的安全门槛 |
| 软删除、恢复、回收站；`TrashPanel.tsx`、`note_delete` | 恢复误操作有价值；永久清空低 | 后续支持单条移入回收站/恢复；首批无删除；永久销毁/清空留电脑 | 后续 |
| 手动摘要/标签与知识库问答；`NoteAiActions.tsx`、`useKbQa.ts` | 可能有帮助，非核心 | 已有摘要可以阅读；首批不接 AI 调用。未来单独评估“依据库内资料回答”及引用/成本/失败 | 再评估 |
| 待沉淀、星标自动草稿、今日蒸馏；`KbInboxPanel.tsx`、`KbAutoConfirmBar.tsx`、`DailyDistillSection.tsx` | 基于电脑剪贴板，手机缺输入事实 | 阅读已生成笔记；不复制桌面采集候选、评分、自动沉淀或后台监听剪贴板 | 不搬迁 |
| 导入/导出 Markdown 目录、MCP；`kbMoreMenu.tsx`、`note_vault.rs` | 手机整库管理收益低、授权复杂 | 后续可分享单篇文本/Markdown；目录导入导出、MCP Server 配置留电脑 | 不搬迁整套 |
| 库体检、批量移动、网格/多栏/拖拽、复杂排序分组；`KbHealthBar.tsx`、`BatchBar.tsx`、`KbThirdPane.tsx` | 手机成本高、干扰阅读 | 不做首页入口；平板最多列表+阅读两栏，手机默认单列 | 不搬迁 |
| 待办岛、提醒解析/任务回写；`todo_tasks.rs` | 手机打勾可能有价值 | 首批按正文阅读；后续单独加入带版本/行内容校验的勾选，不顺带造项目管理 App | 再评估 |

“手机本地常用”与“桌面置顶”必须用不同文案和契约，不能让用户误以为它们已同步。AI 开关关闭或未配置可用 key 时，未来所有 AI 入口仍须零可见、零请求、零费用；展示已有笔记内容不触发模型。

## 3. 可选范围及推荐

| 路线 | 范围 | 优点 | 代价与限制 |
|---|---|---|---|
| A：只读随身资料库 | 同步、搜索、阅读、常用、离线 | 写入风险低，能较快验证用户是否真的查资料 | 不能记录临时内容；手机价值不完整 |
| **B：随身资料库 + 快速记录，推荐** | A + 草稿/独立新建；随后系统分享与轻编辑 | 同时满足查资料和捕捉内容，规模可控 | 新建必须可靠落盘，并验证双端同步；现有笔记编辑不能一起抢跑 |
| C：桌面功能完整迁移 | 完整编辑器、批量整理、AI、历史管理、目录与关系工具 | 能力数量多 | 页面复杂、学习成本高，平台和同步风险叠加，不推荐作为二期首版 |

推荐 B 的两条主线是“查到并用上”和“记下且不丢”。不以桌面按钮数量作为完成度，也不通过减少必要异常处理来缩小首版。

## 4. 页面结构与操作路径

### 4.1 知识库主页

导航继续使用已经确认的 B：设备 / 文件 / **知识库** / 设置。真实读写和授权流程可用后才开放知识库目的地。

首屏从上到下：紧凑标题“知识库”及“新建”文字入口 → 搜索框 → 三个视图“最近 / 常用 / 全部” → 笔记列表。文件夹、标签与同步状态是次级入口，不增加整屏欢迎横幅、统计看板、日历或 AI 推荐区。

列表行：标题、约两行纯文本摘录、文件夹/最近修改信息；只有异常时出现“缺少图片”“待同步”等必要状态。不是每行同时摆来源、字数、标签、按钮、同步图标。首批单列，不提供列表/网格切换。

新用户没有电脑也可以新建本地笔记。空态分别是“还没有笔记”“尚未完成首次同步”“没有匹配结果”“读取失败”，不能统一显示“暂无内容”。

### 4.2 搜索

- 搜索当前已在手机落盘的内容，不偷偷请求云端或把问题当关键词发送 AI。
- 输入后更新结果；显示命中片段，保留关键字与筛选条件。中文、单字、英文前缀、拼音、标点均以真实 FTS 行为验收，不先承诺模糊语义检索。
- 首批筛选仅文件夹/标签；其他条件不铺开。文件夹可逐层进入，并始终显示路径。
- 初次同步尚未完成时提示“已同步内容中的结果”，不能声称搜遍电脑整个库。
- 点结果进入阅读；系统返回恢复原关键词、结果与滚动。正文内查找是详情的独立动作，不修改全库搜索条件。
- 历史关键词仅保存在本机且可清除；不为搜索增加遥测。

### 4.3 阅读详情

- 默认阅读。顶栏返回、短标题和更多；正文尽量占可用空间。不因底部工具常驻遮住最后一段。
- 复制、分享与修改放在清楚的操作入口。优先支持系统选中复制与代码块复制，长文正文不因点击误入编辑。
- 长文目录按需展开；恢复本机阅读位置。若版本改变导致定位失效，退到附近标题并提示内容更新，而非跳到错误段落。
- 图片按需解码，点开独立查看并可退出；代码/表格只在块内横滚，不触发主导航。缺图保留说明与恢复动作。
- 笔记链接按稳定笔记身份优先导航；旧标题链接沿用现有解析规则。重名、已删除、未同步三种状态分开，不自作主张打开第一篇。
- 不直接复用桌面渲染器的 Mermaid“编辑”入口；无手机编辑能力时给读取/放大与源码降级。流程图延迟加载，不为普通文字提前加载图库。

### 4.4 快速记录

路径：新建 → 输入 → 保存到本机 → 继续当前任务。分类可不选，默认未分类；不要求先取一个文件夹或配置同步才能记。

- 首批是独立笔记，沿用通用笔记 id/正文数据；新建文本可以简单使用 Markdown，但不要求用户理解语法。
- 标题可后填；默认标题按首个非空文本行确定，规则明确、非 AI。正文原样保留。
- 编辑中定期可靠保存草稿，在返回/退后台前提交最新内容；应通过写入完成状态判断，不能把内存 setState 称为保存。
- 明确区分“草稿已保存”“笔记已保存到手机”“等待与电脑同步”。本机提交成功即可结束编辑，电脑关机不算保存失败。
- 双击保存或中断重试使用同一创建身份，不生成两篇。存储空间不足时保留输入和恢复动作，不关闭编辑器。
- 草稿恢复按 note id / draft id、时间和版本进行，不依靠一个通用 localStorage 字符串覆盖所有笔记。

首版不与电脑“今日速记”自动合并。手机与电脑离线创建当天速记可能产生不同 id；同时追加同一正文仍是整篇版本竞争。将它说成天然 append-only 跨端合并会给用户错误保证。

### 4.5 轻编辑、归档与恢复（后续）

- 先交付更正文字、追加一段、改标题；格式工具仅按需求提供。不同屏幕默认不并排源文和预览，切预览不丢光标/输入。
- 保存前核验读取时的基础版本；已变更时保留手机草稿和最新正文，允许“另存一篇”或稍后到电脑比较，不能覆盖后才提示。
- 同步到已被删除的笔记时不能静默复活。保留编辑草稿，明确提供“另存为新笔记”。
- 分类只提供单篇文件夹选择、已有标签选择。树重排、批量改标签、批量删除留电脑。
- 删除采用软删除与恢复；永久销毁不作为手机常用操作。对可能已同步出去的变更，不能只撤销页面 DOM 假装数据已恢复。

### 4.6 系统分享收集（第二批）

其他 App → 系统分享 → PastePanda → 内容预览 → 新建笔记 → 本机保存。无需先开远控或等待电脑开机。

- 首批收文字和链接；保留链接来源与用户备注。保存链接不自动下载网页全文，不声称“离线已保存网页”。
- 图片单独追加阶段：先复制到 App 私有目录并取得完整校验，再保存引用；不能将临时 content URI 当长期地址。
- 先落本机，再同步。系统授予的 URI 权限过期、App 被杀、用户取消或重复分享均需有恢复契约。
- 不后台扫描手机剪贴板。用户明确点“粘贴”或主动系统分享才收内容。
- 分享笔记给外部 App 时，系统分享面板的打开/返回只能称“已打开分享”，无法验证对方 App 的接收或发送，不写“发送成功”。

## 5. 同步与离线：必须先讲清的数据规则

### 5.1 当前代码事实

1. `SyncService`、`kb_sync_*` 命令已注册，`kb_sync_enabled` 独立于远控/剪贴板开关。Rust 数据库与同步不需要把 UI 改成 Compose 或 Flutter。
2. 远控已有设备可通过 `kb_sync_allow_from_rc` **显式**加入知识库同步；远控配对不是自动授权笔记。当前邀请/会话未发现按文件夹或只读范围的授权契约。
3. 同步将笔记导出为 Markdown，搬图片并便携化引用，按 HLC/游标进行对账；冲突保存另一版普通笔记，**不是自动文字合并**。
4. `ParsedNote`/Markdown 导出主要携带 id、标题、标签、摘要和正文等；未发现置顶、`daily_date`、完整修订历史的跨端序列化契约。不能因手机能调用本地命令就假设这些字段会同步到电脑。
5. 附件目前以本机 images 内容寻址文件为基础，单个搬运上限 10MB，跳过与缺失有报告；图片引用匹配仍带 Windows 盘符条件，Android 发出本机图片需补跨平台往返验证。
6. 同步已有失败退避与休眠；桌面 Hook 仍有可见窗口中的状态轮询。Android 后台持续运行、电量与网络条件尚不能据此得到保证。
7. Android 身份保护当前采用 App 沙箱与版本头，并非系统密钥库加密。iOS 身份存储契约尚需补齐。面向正式知识库交付时须审计备份/恢复、身份与设备撤销行为。

### 5.2 同步范围路线

| 数据路线 | 适用 | 限制 | 建议 |
|---|---|---|---|
| **沿用整个当前知识库同步** | 愿意将此库资料保存到手机的个人用户 | 无文件夹授权隔离；正文与附件规模需预检，现有附件非按需协议 | 首批兼容路线；授权页清楚说明范围、可取消初次同步 |
| 选择文件夹/笔记同步 | 含私密分区、大库或需要节省空间的用户 | 必须扩展同步授权、清单、删除/移出范围、对账与旧端协商；不是给列表加筛选即可 | 后续独立里程碑；有硬性需求的用户首批不建议使用全库路线 |
| 仅连电脑远程查询 | 不愿保留资料在手机、且电脑长期在线 | 断网/电脑关机失去核心价值，需新查询协议 | 不作默认；确有用户需求再评估 |

**不把“常用”“已下载”筛选包装成隐私隔离**。全库同步已经落盘的笔记，即使不在列表展示，也仍在手机。首批没有可靠选择性同步就不要画出对应开关。

初次授权流程：选择已配对电脑 → 展示知识库身份、当前范围、数据量预检结果 → 明确同意 → 开启同步 → 显示真实进度/错误 → 验证内容。多台电脑只展示已授权的同一知识库参与设备；不同库/工作空间的合并禁止默认发生，需确认当前后端身份语义后再开放。

### 5.3 离线定义与清理

- 正文同步并持久化后即可本地搜读，不需要一个“再缓存正文”的按钮。UI 可以显示最后成功同步时间，提示离线内容可能不是最新版。
- 图片/附件独立表示：完整、处理中、失败/缺失。全文有图片占位时不得称“完整可离线”。Web 外链只保存地址，访问目标仍需网络。
- 第一批沿用现有附件策略，在同步前展示范围与体量。**按需附件下载/仅 Wi-Fi/缓存淘汰不是当前能力**，只有补能力协商与传输协议后才开放。
- 后续“离线包”是明确笔记集合及附件清单、版本校验、完成/部分失败结果；“保留离线”不等于共享置顶。
- 清理同步副本绝不能调用 `note_delete`，否则墓碑会影响电脑。临时传输文件、可重取附件、本机草稿、未同步笔记必须分开处理；无法保证重取时不自动回收内容。
- 撤销配对阻止后续访问，不能远程保证已经保存或分享的数据被抹掉。手机取消配对时明确选择是否移除本机副本；有未同步记录先给保留/导出路径，清理范围不得影响其他已授权库或草稿。

### 5.4 保存、同步与冲突状态

最小反馈语义：编辑草稿 → 本机笔记保存成功 → 等待同步 / 同步中 → 上一次成功同步；失败、部分附件失败、版本冲突分别显示。

现有同步报告是按设备/轮次，不能直接推导每篇笔记已被电脑持久化。首批只报告真实的本机保存和设备同步时间；要标记单篇“电脑已收到”，须先补 note id + 内容版本与对端落盘确认的契约。

快速新建使用稳定 id 与持久化版本，超时重试不得再次创建。现有笔记的轻编辑上线前增加基础版本检查，写入与状态提交保持一致；冲突版本不能只藏在设置日志里。

网络恢复不代表授权仍有效；拒绝/撤销时保留本机新内容并停止向被撤销设备写入。关闭同步不清空本地知识库，不弹连续失败 Toast。正常等待不使用错误色，不阻塞阅读。

## 6. 手机布局、交互与动画约束

- 复用已经确认的手机 B：实底表面、语义主题色、16px 正文角色、可缩放单位、常驻文字标签、48px 操作区域、安全区与系统键盘避让。
- 竖屏单列：列表 → 全页阅读 → 全页编辑，按系统返回逐级退出。不要将长文装进底部弹层；底部弹层用于筛选/更多等短任务。
- 短横屏保持正文优先，左主导航紧凑，阅读头收紧。不能单凭横屏就复制桌面三栏。
- 平板/折叠展开在实际剩余宽高足够时用“列表 + 阅读”两栏；大字号/IME/分屏压缩后回单列，保留当前笔记、查询与草稿。初步设计按列表至少260 CSS px、阅读至少400 CSS px核算，需实测调整，不以设备型号判断。
- 局部转场/选中态沿用150/200ms，页面/面板按项目300/400ms档位与已有弹簧；选择新目标可中断，不排队等待装饰动画。减少动效时保留导航和状态。
- 长文加载后不自动滚顶；同步更新正在阅读的正文时保留位置，并给查看新版的选择。编辑草稿不得被后台列表刷新覆盖。
- 反馈与触发同一可见域：保存结果在编辑器；同步问题在可展开状态；复制结果在复制动作处；常规提示不压在正在阅读或选择的文字上。
- 手势只做增强。不能要求长按才能找到菜单、横滑才能换页、拖拽才能分类；筛选和更多必须点击可达。

## 7. 技术复用与必须新增的部分

### 7.1 可以复用

- Rust Note / DataStore、SQLite FTS、文件夹/标签、软删除、链接解析和已有同步/HLC。
- 手机 MobilePage、MobileSheet、MobileNotice、稳定目的地配置、系统返回与 viewport/IME来源。
- Markdown 的安全解析/清理和代码复制基础逻辑，但抽出阅读能力，不能带入桌面专属事件与入口。
- 现有配对身份与设备展示信息作为候选来源，知识库授权仍走独立确认。

### 7.2 不直接复制的桌面层

- `KnowledgeView`、CodeMirror分栏、FolderTree拖放、右键菜单与28px命中尺寸。
- `src/lib/api/notes.ts` 中写入桌面 Store 角标与桌面 Toast 的副作用。共享命令/类型，手机错误返回自己的可见状态；不要重复两份数据规则或出现桌面 Toast 不可见的失败。
- `useKbSync` 的桌面窗口生命周期假设。手机单一同步控制层使用App生命周期/网络事件，避免每个页面各自5秒轮询。

### 7.3 先解决的数据契约

1. 列表/搜索摘要 DTO 与分页：现有 note_list 返回带正文的 Note，不能让万篇库每次打开拉全篇。首批20条渐进加载，搜索请求带身份，丢弃迟到结果；读正文单独加载。
2. 本机草稿可靠落盘、稳定创建id与失败恢复；必要记录留SQLite/App私有数据，不把大正文放localStorage。
3. 基础版本检查与冲突保留；与同步应用事务、删除状态配套。新增笔记和修改笔记分开验收。
4. 跨平台附件引用、Android URI复制、Hash校验与可重取/不可重取内容定义；协议无按需能力时不画按需按钮。
5. 同步范围/库身份/协议版本协商；不能把多个电脑视为随时可切的远程查询目标。
6. 原生生命周期、身份保护、备份排除策略与系统分享载荷；iOS另补Keychain等平台实现，未验证前不宣称Android策略可原样迁移。

建议目录为 `src-mobile/knowledge/{components,hooks,lib}`；数据/协议仍在共享Rust与API层。单TSX遵守300行限制，纯工具遵循项目单一来源规则；不为未来假定需求建通用插件框架。

## 9. 验收矩阵与体验目标

以下均为目标，不是本次已测结论。

| 类别 | 场景 | 应看到的结果 |
|---|---|---|
| 查找 | 3,000/10,000篇，中文短词、英文、拼音、组合筛选 | 内容分页，迟到搜索不覆盖新搜索；无结果与失败分开；无全库正文拉取 |
| 阅读 | 长文、表格、代码、重名链接、断链、缺图 | 页面无整页横溢出，局部块可横滚；链接错误可恢复；最后一段无遮挡 |
| 离线 | 首次同步未完成/已完成；电脑关机；网络有但对端离线 | 已有内容先显示；标明范围与最后成功同步，不刷连续错误 |
| 新建 | 双击保存、应用退后台/被杀、午夜、无空间 | 无重复，恢复已落盘草稿；日期不作为跨端唯一身份；失败保留输入 |
| 编辑 | 手机电脑同时改；读后正文变；同步期间被删除 | 基础版本检查、保留两版；不能误覆盖或静默复活 |
| 附件 | 超10MB、源图丢失、Android私有路径、URI失效 | 明确部分失败，不出现假完成；正文可继续使用 |
| 授权 | 未同意知识库同步、同步关闭、撤销设备、多库 | 零越界同步；新记录本地保留；清理本机副本不发远端删除 |
| 兼容 | 旧电脑端、新手机端、元数据缺字段 | 能力明确降级；不伪造同步置顶/历史/每日身份 |
| 适配 | 320/390宽、640×320/844×390、平板、分屏、200%字体/IME | 关闭、保存、返回可达；正文为主；降单列保留状态 |
| 无障碍/动效 | 读屏、减少动效、旋转、系统返回 | 标签/选中/错误可读；无只有手势的入口；动画可中断 |

体验目标：已落盘内容无需等待网络；关键输入立即视觉响应；耗时超过1秒有可见状态，超过10秒有取消或可解释的进度；搜索/首屏在中档Android真机记录P50/P95与库规模，满足后再写“流畅”，不虚构固定性能值。

用户任务测试建议先约5名实际用户，每人完成“找一份资料并复制一段”“断网读一篇带图资料”“关电脑记一条再核对电脑”“分享链接到本机”四项。记录点击数、错误恢复与需要指导的地方，优先修阻断点；不开默认内容上报或采集用户笔记。

## 10. 下一版详细设计稿应展示什么

现有 `mobile-commercial-upgrade-2026-10-07.html` 的知识库/分享是概念稿，本方案不要被它的“已缓存”标签限制：首批正文已经本地化，完整离线状态还要看附件。

范围确定后，详细HTML应至少有这些可切换状态：

1. 未授权/仅本机笔记/初次同步/正常主页。
2. 搜索命中、筛选、无结果、读取失败与返回恢复。
3. 全文、目录、图片缺失、链接歧义/失效、局部表格/代码。
4. 独立新建、草稿恢复、本机保存、待同步、存储失败。
5. 同步部分失败、对端离线、授权撤销、版本冲突与另存。
6. 系统分享文字/链接预览、取消、重复载荷与本机结果；图片流程作为后续。
7. 320/390窄屏、短横屏、平板双栏、深色、200%字号、键盘与减少动效。

概念稿不得写“电脑已收到”而没有相应回执设计，不画未实现的文件夹隔离权限，也不让分享系统返回冒充发送成功。
