## 一、威胁模型（先说清楚商业方案的坑）

固定密码模式的攻击面，恰恰是商业产品被爆过袱的地方：

| 风险 | 说明 |
| --- | --- |
| 离线爆破 | 密码长期有效 → 攻击者可无限次慢速试（ToDesk/向日葵类产品都出过弱口令批量入侵事件） |
| 密码即永久后门 | 泄露一次（肩窥/聊天记录/主机被入侵读取）= 永久失守，除非人工换密码 |
| 授权范围模糊 | 「知道密码」与「这台设备可信」被混为一谈，无法按设备管理/撤销 |

我们已有的资产可以直接复用：设备白名单（rc_devices）、指纹核对、被控横幅/会话历史、
禁用优先级、「免确认」逐台开关、iroh 端到端加密、本地数据不上云。

## 二、方案：**一次性接入码**为主，固定密码为辅（二期）

### 方案 B（本期推荐）：无人值守接入码 —— 时效性、一次一码

被控端（或代操作的人电话里指挥）生成 **接入码**：8 位分组 `XXXX-XXXX`，
主控端在「远程电脑 → 发起」里粘贴即可，被控端**自动同意**并落白名单。

关键设计，全部针对上表三行：

1. **时效**：默认 **1 次有效、15 分钟过期**；可放宽到「24 小时内不限次」（给装机场景）。
   过期即作废——离线爆破的窗口被压到分钟级，且每次生成都是新码。
2. **无长期秘密**：接入码不落库、不写配置，只在内存里挂一个待验条目（哈希存放，
   见下）。关机即全作废。泄露的损失上限 = 一个码、一段窗口。
3. **比对仍是摘要**：码本身 128 bit 熵（base32 去歧义字符集），内存中只存
   SHA-256 摘要；验证常数时间比较，防时序侧信道。
4. **落点是我们已有的白名单**：接入成功 = 该设备写入 rc_devices（与现场配对同一
   张表、同一套横幅/历史/禁止/免确认管理）。**不新增任何常驻后门**；
   生成时可勾「同时开启这台设备的免确认」，不勾则下次仍要码或现场确认。
5. **被控端全程知情**：生成时被控端屏幕明确提示「在 X 分钟内，任何拿到接入码的
   设备可以远程本机（可控/只看）」；接入发生时横幅照常出现、历史照常记录。
6. **带外传递即安全假设**：码通过电话/微信等渠道给对方——这和商业产品抄密码是
   同一信任级别，但我们多了「码会过期」这一层。

### 方案 C（二期可选）：固定接入密码 —— 给「自家服务器」这种真长期需求

- Argon2id 存哈希（不存明文）；尝试**每对端指数退避 + 连续 5 次失败锁 10 分钟**；
- 被控横幅常驻升级为「无人值守模式中」+ 一键全局关闭；
- 默认建议仅局域网可用，跨网需显式打开。
- 明确定位：B 覆盖 90% 场景（帮人、装机、临时运维），C 只服务少数长期挂机需求，
  且必须带着上面的限速/可见性设计一起上。

## 三、与现有机制的衔接（改动面）

| 模块 | 改动 |
| --- | --- |
| 协议 | knock/accept 帧 add `uno_code` 字段（或复用现有邀请码验证通道，倾向后者——邀请码验证管线已在） |
| 被控端 | 设置页/会话横幅入口「生成无人值守接入码」；内存待验表（哈希 + 过期 + 次数） |
| 发起端 | 发起对话框加「有接入码？」输入位；成功后按普通配对设备处理 |
| 不变 | rc_devices、横幅、历史、禁止、免确认、加密传输全部复用 |

## 四、需要你拍板的点

1. **只做 B，还是 B+C 一起**（推荐先 B，C 等真实需求出现）。
2. B 的默认时效：**1 次 / 15 分钟**，还是更宽（24h 不限次）？UI 是否提供两档可选？
3. 接入码是否加第二因子：被控端屏幕显示 4 位 PIN，主控端要输——商业产品都没有，
   但我们有「被控端在场时才生成」的优势，加上可以防「指挥过程中码被截图外传」。
   倾向**不加**（码本身 15 分钟一次性已够），你定。
4. 接入码授予的能力档固定「可控」还是生成时选（可控/只看）？倾向生成时选。
