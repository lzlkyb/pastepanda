> 2026-09-19 · 状态：**对比清单（本轮基线 = v7.2.x + 09-19 高帧率轮）**。

## 3. 我们领先或独特的点（诚实清单）

1. **延迟透明度**：HUD 分段显示 采/编/网/解 四段 + 跨机时钟校准（pong hts EMA）+ 操作延迟。商业产品几乎不给用户这个颗粒度——这对「体感靠拢本机」的目标是真正的差异化。
2. **诚实能力门控**：fps120 跑不到就不卖（单屏 + D3D11-aware 硬件 MFT + ≥100Hz 三重门槛），自动降频兜底。商业产品普遍虚标（ToDesk 宣称 360fps 即一例）。
3. **隐私面设计**：范围切换被控端可见、配对数字现场比对、无账号不上云。对手要么没有，要么放在企业审计后台。
4. **传输架构**：QUIC + 数据报视频 + XOR FEC + 输入/视频分通道，设计上与游戏串流派同构，领先企业派（TCP 为主）一代。
5. **渐进刷新探测**：GradualIntraRefresh 在同类产品里少见（游戏派走参考帧路线，不需要）。

| G3 | ~~音频~~ **✅ 已实现（2026-09-20 落地）**：被控端 WASAPI 环回采默认播放设备 → **收件箱 AAC-LC 编码器**（MF，128kbps 立体声；采样率跟设备混音格式、不重采样，多声道缩混立体声；实测编码器前瞻 2 帧 ≈43ms）→ 被控端**另开一条 QUIC 单向流**（与视频流分开，互不队头阻塞；AAC 帧独立，丢一帧不扩散）；发起端 WebCodecs `AudioDecoder` + 游标排播（欠载重蓄水、过载弃积压，端到端 ~150ms）。会话底栏「声音」开关（默认开，只看会话也有声），被控端横幅可见「对方开始/停止接收本机系统声音」。无播放设备时静默无声、绝不影响视频。**零新依赖零体积**（Windows 自带能力）。**被控者本机静音（2026-09-20 补）**：被控横幅「不发送声音」，一票否决（对端自己开着也听不到），跨会话保持、不落盘、status 上报按钮态；判据 = `对端申请 && 对端未关 && 本机未静音`，已用单测钉死（含「对端再关再开也解不开本机否决」）。**G3-B / G3-C（2026-09-20 补，上面那条限制已收口）**：①「不发送声音」**会回传**了——被控者一关就推一条 `host_audio` 状态帧，发起端底栏如实显示「对方已静音」（这一派业界**没有一家做**）；②新增**反方向控制**：底栏「对方外放」一键静音对方**主机扬声器**（对齐 Parsec / GameStream 的 mute host speakers），**要求可控会话**（改的是对方物理输出环境，「只看」不摆该按钮）；被控端**看得见**且可一键恢复，串流不受影响。按钮态以对端回帧的真实值为准、执行失败随快照带回。（注：这里的「本机静音」是被控者按的 `audio_local_mute`，**不是** Windows 系统音量静音；且 WASAPI loopback 抽头在端点静音之前，系统静音改不了采到的数据）。**行业做法调研（09-20）**：四派＝①不管（RustDesk / Chrome RD / AnyDesk，与我们同）②虚拟声卡（Sunshine `virtual_sink` / TeamViewer 自带驱动 / RDP 会话端点；要装驱动，与「零新依赖」冲突）③**反方向指令**：控制端下发「把主机扬声器静音」（GameStream / Parsec `Ctrl+Shift+M`）④状态回传——**没有一家做**。详见 `docs/远程电脑-会话音频-静音做法-行业调研-2026-09-20.md`。剩余=双机手测确认（清单 11.13） | 所有 9 家都有 | ~~远程「用电脑」没有声音就不完整~~ 已补齐 | ✅ |

## 5. 结论

- **局域网个人用途的体感维度**（帧率/零拷贝/输入通道/延迟透明度）：架构与实现已进入第一梯队，缺的是双机实测确认与 G1/G2 两个修复。
- **跨网弱网**：传输层设计先进，但自愈闭环有实缺陷（G1），修完才算兑现 P2 的承诺。
- **功能完备度**：音频（G3）、文件（G6）、移动端（G10）与商业产品差距大——它们大多不在「体感」主线上，但音频是其中唯一「没有就算不完整」的项，建议优先。
- **隐私与诚实度**是现有产品里几乎没人占的位置，应作为产品叙事持续加码。
