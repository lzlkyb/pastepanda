# 侧边栏布局方案对比 — 基于 p0-sidebar-below-topbar.html

## 两种布局策略

### 策略 A：全高侧边栏（之前的 p0-auto-source-sidebar.html）

```
┌──────────────────────────┐
│ ☰ PastePanda      🔧 ✕  │ ← TopBar 被侧边栏挤窄
├────────┬─────────────────┤
│ 侧边栏  │ 搜索 + Tabs     │ ← 搜索栏也被挤窄
│ 200px   ├─────────────────┤
│        │ 卡片列表         │
│        │                 │
└────────┴─────────────────┘
```

**问题：** 侧边栏占据整列高度，TopBar 的搜索框和 Tabs 需要适应缩窄的空间（680px 窗口 - 200px 侧边栏 = 480px 给 TopBar）。

### 策略 B：侧边栏与列表平齐（p0-sidebar-below-topbar.html）⭐

```
┌──────────────────────────┐
│ ☰ PastePanda      🔧 ✕  │ ← TopBar 始终全宽，不受影响
│ 搜索框                    │
│ [全部][文本][图片][文件][⭐]│
│ 筛选栏                    │
├────────┬─────────────────┤
│ 侧边栏  │ 卡片列表         │ ← 从这里开始平齐
│ 200px   │                 │
│        │                 │
│        │                 │
└────────┴─────────────────┘
```

**优势：** TopBar 保持全宽不动，侧边栏只影响卡片列表区域。

---

## 详细对比

| 维度 | 策略 A（全高） | 策略 B（平齐）⭐ |
|------|-------------|-------------|
| TopBar 宽度 | 被压缩 200px，搜索框变窄 | **不变**，始终全宽 |
| 搜索体验 | 搜索框变窄，可能截断 placeholder | **无影响** |
| Segmented Tabs | 5 个 tab 挤在 480px 内 | **无影响** |
| 筛选栏 | 两个 dropdown 挤在一起 | **无影响** |
| 实现复杂度 | 需要调整 TopBar 布局 | **只需改 App.tsx 结构** |
| 行业惯例 | 少见 | **VS Code / Figma / Notion** |
| 窗口宽度变化 | 480→680px (+200px) | 480→680px (+200px) |
| 侧边栏可见高度 | 全窗口高度 | 窗口高度 - TopBar(约160px) |
| FAB 位置 | 需要跟随侧边栏偏移 | 在 cardPanel 内，自然跟随 |

## 方案 B（平齐）的具体实现方案

### 改动的文件

1. **App.tsx** — 添加侧边栏状态、布局结构调整
2. **App.module.css** — 新增 body-row 布局
3. **新建 SourceSidebar.tsx + SourceSidebar.module.css** — 侧边栏组件

### App.tsx 结构变化

```tsx
// 现状（单列布局）
<div className={appStyles.appShell}>
  <TopBar />
  <ScrollProvider>
    <CardList />
  </ScrollProvider>
</div>

// 新布局（TopBar 全宽 + 下方双列）
<div className={appStyles.appShell}>
  <TopBar onToggleSidebar={toggleSidebar} />
  <div className={appStyles.bodyRow}>       {/* ← 新增 flex row */}
    <SourceSidebar open={sidebarOpen} />     {/* ← 新增侧边栏 */}
    <div className={appStyles.mainArea}>     {/* ← 包裹 CardList */}
      <ScrollProvider>
        <CardList />
      </ScrollProvider>
    </div>
  </div>
</div>
```

### CSS 核心改动

```css
/* App.module.css 新增 */
.bodyRow {
  flex: 1;
  display: flex;
  overflow: hidden;
  min-height: 0;
}
.mainArea {
  flex: 1;
  display: flex;
  flex-direction: column;
  overflow: hidden;
  min-width: 0;
}
```

### SourceSidebar 组件

- 从 `useAppStore` 获取 `history`，聚合 `source` 字段
- 自动生成分组列表（全部 → 收藏 → 分隔线 → VS Code / Chrome / ...）
- 点击分组设置 `sourceFilter` 状态
- 200px 宽，`open` prop 控制显示/隐藏动画
- 默认折叠（`sidebarOpen = false`）

### 交互逻辑

| 操作 | 效果 |
|------|------|
| 点击 ☰ 按钮 | 切换侧边栏 + 窗口宽度 480↔680px |
| 点击"全部" | 清除来源筛选 |
| 点击"收藏" | 等同于筛选 pinned |
| 点击具体来源 | 设置 sourceFilter |
| 按 Esc | 关闭侧边栏 |
| 侧边栏底部"收起"按钮 | 关闭侧边栏 |

### 数据流

```
history[] → 聚合 source 字段 → SourceSidebar 渲染分组列表
         ↓
sourceFilter → CardList 过滤 → 仅显示匹配来源的卡片
         ↓
筛选栏"来源应用"按钮同步更新显示
```

### 工作量估算

| 文件 | 改动量 |
|------|--------|
| 新建 SourceSidebar.tsx | ~80 行 |
| 新建 SourceSidebar.module.css | ~120 行 |
| App.tsx | ~20 行（结构调整） |
| App.module.css | ~15 行（新增 bodyRow/mainArea） |
| TopBar.tsx | ~5 行（新增 onToggleSidebar prop） |
| appStore.ts | ~5 行（sourceFilter 状态） |
| **合计** | **~245 行** |

## 推荐

**采用策略 B（侧边栏与列表平齐）**，理由：
1. TopBar 不受影响 — 搜索框、Tabs、筛选栏体验一致
2. 行业惯例 — VS Code 的资源管理器、Figma 的图层面板都这样
3. 实现简单 — 不需要调整现有 TopBar/CardList 内部逻辑
4. 打开/关闭动画干净 — TopBar 纹丝不动
