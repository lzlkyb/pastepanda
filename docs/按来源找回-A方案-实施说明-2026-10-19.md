# 按来源找回 A 方案

依据 `design/按来源找回-A方案-来源分布与悬停预览-2026-10-19.html` 实施。入口沿用顶栏来源位置；浮层与按时间找回使用相同主题色、尺寸、进入和退出动效。

## 行为

- 横向柱状图按记录数降序排列，显示现有统一解析的应用名与图标。悬停或键盘聚焦只更新下方的内容构成与最近记录时间，移开恢复已选来源；单击才改变来源筛选并收起。
- 搜索来源只过滤应用选项，不改变主列表关键词。清除来源保留时间、关键词、类型、空间、分组和标签。
- 分布随时间、关键词、类型、当前空间、分组和标签变化，排除来源自身限制，保留其他来源用于切换。
- 来源使用原始键精准筛选，不把显示名相同的不同原始来源静默合并。来源为空的记录计入总数并提示，不提供会误选为“全部”的未知来源选项。
- 已选来源在当前范围为零时保留选中名和清除入口。加载、失败和空范围分别展示；失败不显示为零条。
- 来源列表使用虚拟滚动。高度不足时列表先缩短，内容构成保持可见；极矮窗口可滚动面板内容，底部清除入口仍可见。

## 查询与性能

`history_source::distribution` 共用 `history_search::search_where`，包括文本、富文本、文档类型分组、OCR、检索摘要和字面量转义。通过独立只读 SQLite 连接聚合，不带列表 1000 条上限、不把卡片正文传回前端、不新增索引或迁移。

仅面板打开且窗口可见时读取，150ms 合并输入和历史变化，关闭或隐藏取消后台读取，迟到结果不覆盖新条件。同一份聚合同时提供全部来源及各来源的类型和时间详情，悬停不另发统计请求。来源组件拆至 `src/components/history-source/`，不再扩展 TopBar 内联下拉。

仅选来源也必须使用数据库查询，避免“统计有记录、列表却只筛已加载卡片”。统一门控 `isHistoryQueryActive` 的来源参数为必填；查询 Hook、列表分页开关与 store 数据源均传入该参数。

## 验证记录

- 数据库时间及来源统计测试 11 项通过：包含 1212 条记录、8 个来源、类型分组、原始来源键、未知来源、时间右开边界、空间/分组/标签/收藏、OCR/摘要搜索、只读与取消。
- 来源筛选前端测试覆盖悬停/聚焦恢复、单击与 Esc 收起、应用搜索、清除、失败重试、空范围、请求合并/取消和迟到响应隔离。
- 时间、来源、主列表数据源相关前端测试共 63 项通过；其中 1000 个来源的用例验证只挂载可见行，搜索仍能定位未挂载的来源。
- 仅选来源的旧记录找回及快速切换/清除两条回归，修复前 2 条失败，接入统一查询门控后通过。改前输出保存在本地 `.cache/source-query-before.log`。
- 实际组件以样例数据进行浅色与深色、680px 与 480px 宽度校验；组件截图不代表用户数据库内容。原生 dev 使用 `npm run tauri dev` 编译启动。

## 复查修正

- 搜索框聚焦双重边框：面板通用焦点规则覆盖了输入框的 `outline: none`。焦点反馈改由搜索框外层负责，按钮保留键盘焦点环。CSS 回归修复前失败、修复后通过，改前输出在 `.cache/source-style-before.log`。
- 切换来源后的旧结果：store 在查询 effect 执行前就校验结果签名，拒绝不匹配的旧数据；列表同时订阅签名，复用同一数组时也会重新校验。两条回归修复前失败、修复后通过，改前输出在 `.cache/source-stale-before.log`。
- 本轮相关前端测试 12 个文件、86 项通过，包含列表 Hook、store、恢复删除与时间/来源交互。独立代码复核未发现上述问题之外的确定性缺陷。
