## 1. 要解决的问题（一句话）

被控电脑锁屏后，手机画面还在出帧（DXGI 不受锁屏影响，用户实测），但所有键鼠注入都打在
`Winlogon` 桌面外（§11 已实测判 H1），**表现为「点了没反应」且无任何提示**——违反规则 15.3
（失败路径必须有可见出口）。S1 把这个静默失败变成手机上的常驻明示，并禁掉必然无效的打字。

**S1 不解决解锁**（那是 S4+S6 的事）；它的验收口径是：锁屏瞬间手机 1 秒内出现「远端已锁屏」，
打字被拒且有说明；解锁瞬间自动恢复，无需用户做任何事。

## 2. 跨端契约（单一数据源）

### 2.1 被控端 → 控端：会话内控制帧（JSON，走既有 `write_frame` 流）

```json
{"t": "wts", "locked": true}
{"t": "wts", "locked": false}
```

- 通道与 `{"t":"cursor"}`（`rc/inbound_tasks.rs:295-315`）、`{"t":"clip"}`（`rc/inbound.rs:420`）同一条
  会话半流；`t=wts` 是新 tag，`protocol.rs:217-234` 的会话流 tag 守卫清单要扩。
- `locked` 语义：**「远端输入桌面不在 `Default`，键盘/注入不可达」**。来源只有两个：
  1. `WM_WTSSESSION_CHANGE` 的 `WTS_SESSION_LOCK` / `WTS_SESSION_UNLOCK`（变化驱动，权威）；
  2. 会话建立时的一次**初始探测**（见 §3.3）：`OpenInputDesktop(READOBJECTS)` + `UOI_NAME` 读不到
     名字 ⇒ 视为 locked（§11 实测：解锁态 203/203 能读到 `Default`；读不到 = 桌面已换成 Winlogon）。
- 已知误报窗口（接受并写进文案口径）：初始探测时若被控端恰好停在 UAC/安全桌面，也会读不到名字。
  此时提示「键盘暂不可用」仍然为真；且 UAC 下注入本来也进不去（同一道 UIPI/桌面闸）。不发第三种
  状态来区分（YAGNI），文档记录即可。
- **不补发、不重传**：断线重连会重建会话 ⇒ 初始探测天然补上当前态。中间丢失的 LOCK/UNLOCK 由
  「下一条事件」纠正；最坏情况（解锁事件丢了）= 手机多显示一会儿「已锁屏」，用户一打字被拒才察觉
  ——这比现在好一个量级，不做心跳（规则 8：常驻轮询零收益）。

### 2.2 控端 Rust → 前端：Tauri 事件

```ts
emit("rc-lock-changed", { locked: boolean })   // lib.rs，与 rc-cursor-changed 同款接线
```

- `outbound.rs handle_control` 加 `wts` 分支（`cursor` 在 :419，同款写法）→ `RcService` 新
  `set_lock_notify(Option<bool>)`（镜像 `set_cursor_notify`，`src-tauri/src/lib.rs:961-975` 的
  转发模式）→ lib.rs 统一 emit。
- 桌面控端 UI 本批不消费（事件已备好，后续一条 `listen` 的事）。

### 2.3 手机端状态

- 新 hook `src-mobile/session/useRemoteLockState.ts`：`listen("rc-lock-changed")`（照
  `useRemoteCursor.ts:112` 的挂载/卸载纪律），返回 `locked: boolean`（初始 false；事件没来过 =
  未锁，这与初始探测兜底后实际可达的误差一致）。
- 会话结束/断线：hook 随组件卸载自灭，无需清理协议（`unlisten` 照既有模式）。

## 3. 被控端 Rust：`src-tauri/src/rc/wts_watch.rs`（新模块）

### 3.1 形态：抄 `keep_awake.rs` 的线程纪律，抄 `clipboard_monitor.rs` 的窗口纪律

- `pub struct WtsWatch`（RAII），是 `InboundVideo` 的字段 `_wts_watch`（照 `_keep_awake`
  `rc/inbound.rs:196`），push-start 时构造（`rc/inbound/video.rs:305-309` 的 `if svc.keep_awake()`
  同位判断 `if svc.lock_notice()`）。
- 专用命名线程（为什么必须专用线程：注册绑窗口、窗口归线程，清也要同线程清——`keep_awake.rs`
  文件头已论证过同一件事，照抄结论不重推）：
  1. `RegisterClassW`（独立类名 `pastepanda_rc_wts`，不与 clipboard_monitor 共类）；
  2. `CreateWindowExW` 一个**不显示的普通顶层窗**（`WS_OVERLAPPEDWINDOW` 不调 ShowWindow）。
     🔴 不用 `HWND_MESSAGE`：WTS 通知要求窗口属于交互会话，message-only 窗是否收
     `WM_WTSSESSION_CHANGE` 无官方背书 `[待实测]`——直接用普通隐藏窗，一次到位；
  3. `WTSRegisterSessionNotification(hwnd, NOTIFY_FOR_THIS_SESSION)`；
  4. **构造时（同线程）做一次初始探测**并把结果塞进 `mpsc`，然后 `GetMessageW` 泵循环，
     `WM_WTSSESSION_CHANGE` → `WTS_SESSION_LOCK`/`WTS_SESSION_UNLOCK` → `mpsc::send(bool)`；
  5. `Drop` 只发 `PostMessageW(WM_QUIT)` 信号（照 `KeepAwake::Drop` 不 join 的纪律），线程自清：
     `WTSUnRegisterSessionNotification` + `DestroyWindow` 后退出。
- `mpsc` 消费端：`InboundVideo` 推流循环里已有的事件循环侧用 `try_recv`/`blocking_recv` 折成
  `{"t":"wts",...}` 帧（照 `maybe_send_cursor` 的 `serde_json` → `write_frame`，不发帧失败沿用
  现有错误路径）。

### 3.2 Cargo features

`src-tauri/Cargo.toml:173` 的 `windows` features 增两条：
`Win32_System_RemoteDesktop`（WTS 系列）、`Win32_System_StationsAndDesktops`（探测用
`OpenInputDesktop`/`GetUserObjectInformationW`）。均为本地 crate 已有 API（§2.4 已 grep 确认）。

### 3.3 初始探测（纯函数化以便无环境单测）

```rust
/// 返回 Some(true)=读不到输入桌面名（锁屏/UAC）；Some(false)=读到 Default；None=API 异常（按未锁处理）
fn probe_input_desktop() -> Option<bool>
```

- 探测失败（`OpenInputDesktop` 返回 err≠5 等 API 异常）按 **None=未锁** 处理：宁可漏报不可谎报，
  S1 的可信度就是它的全部价值。
- 读到名字但不是 `Default`（如 `ScreenSaver`）按未锁处理——屏保桌面 DACL 与 Default 同级，注入可通。

### 3.4 开关接线（照 keep_awake 六点，默认**开**）

`rc_lock_notice`（`rc/service/mod.rs:86` 旁注册 `CFG_LOCK_NOTICE`，默认 `true`）。
默认开的理由与 keep_awake 默认关相反：keep_awake 改机器电源行为，S1 **零副作用、零常驻开销**
（只在状态变化时发一帧），不开等于白做。六点：CFG 常量 / default 常量 / `cfg_lock_notice(store)`
单读点 / `RcService::lock_notice()` / lifecycle 传递 / `rc_set_lock_notice` 命令 +
invoke_handler 注册（守卫测试 `rc/tests/guards.rs:777-889` 照抄一条）。

## 4. 手机端：明示 + 门控

### 4.1 门控口径（已与用户对齐：**禁键不禁鼠**）

- `useRcMobileInput` 增参 `keyboardBlocked?: boolean`；内部把 `allowed` 拆成两把：
  `pointerAllowed = canControl && hasFrame`（不变）与
  `keyboardAllowed = pointerAllowed && !keyboardBlocked`。
- 门只下在 **key / text 两类**：`sendKeyDown` / `sendKeyUp`（防卡键的 up 例外：已按下的键仍允许
  补发 up，见下）/ `sendKeyPair` / `submitText`。鼠标 move/click/drag/wheel 一律放行——锁屏界面
  上的鼠标操作（点「辅助功能」、关机菜单）在 S4 落地后是真的能用的，今天点不动也只是「现状如实」。
- 🔴 up 例外：`sendKeyUp` 若该 vk 在 `pressedKeys` 里，**必须放行**（组合键卡死的兜底不能被门挡死）；
  门只拦「新按下」。
- `keyboardBlocked` 并入 hook 的自动 `releaseAll` effect 时要**拆函数**：现在 `releaseAll()` 连鼠标
  按键一起清（`useRcMobileInput.ts:239-254`），锁屏时鼠标还在用，不能清——提取 `releaseKeys()`
  （只清 `pressedKeys` + 取消键相关），锁屏触发走 `releaseKeys()`；`releaseAll()` 保持原语义给
  卸载/失能用。

### 4.2 UI（设计稿另附，三处）

1. **常驻 pill**（`SessionModeNotice` 扩展，`SessionScreenNotices.tsx`）：locked 时最高优先级，
   文案「远端已锁屏 · 打字暂停」。样式在 `modePill`（`RcMobileSession.module.css:278`）基础上
   加 **warning 底**（`var(--warning-bg)`，对齐 `RcConnectionDetails.module.css:16` 的 `.warn`
   语义色用法）——它是持续状态不是瞬时手势提示，`card-bg` 的 modePill 视觉权重不够。
2. **键盘自动收起**：`RcMobileSession.tsx:125-127` 的既有 effect 加一个条件
   `remoteLocked && keyboardOpen ⇒ toggleKeyboard()`——与 `canControl=false` 时收键盘完全同款，
   用户不需要学新交互。收起后 reason 由 pill 常驻承载（规则 15.3）。
3. **工具条打字钮**：`SessionToolbar` 的键盘钮在 locked 时仍可点（点了会打开键盘再被 effect 收起？
   🔴 不行，这是打架）。改法：`toggleTyping` 前置判断——locked 时点键盘钮**不打开**键盘，pill
   抖一下/不变（pill 已解释原因）。即门在入口而不是「开了再关」。

### 4.3 文案（L1–L6 口径自查）

- pill：`远端已锁屏 · 打字暂停`（**9 字，单行实测 173×39px**；说状态不说原因链；UAC 误报场景该句依然为真）。🔴 9 字不是拍脑袋：`modePill` 的 `left:50%` 让绝对定位收缩适配的可用宽只剩容器一半（设计稿实测 185px 就折行）——文案超 9 字会折成两行，这是真组件的既有怪癖，新文案按单行反推长度。「暂不可用」改「暂停」同时避开「承诺何时恢复」的措辞（恢复是自动的，文案不承诺时间）。
- 不出现「解锁后…」承诺（S4 没做，解锁仍做不到；文案不许比能力强）。

## 5. 守卫单测（规则 11.1：钉不变量，喂反例）

## 6. 风险与待实测（落地后第一次真机点验的清单）

1. 普通隐藏窗收 `WM_WTSSESSION_CHANGE` `[待实测]`——备选：真隐藏窗失败再试 message-only。
2. `WTSRegisterSessionNotification` 在**多会话/快速用户切换**下只报本会话（`NOTIFY_FOR_THIS_SESSION`）；
   被控端切用户 = 本会话 LOCK，行为正确，但**远端画面会变成另一会话的桌面**（DXGI 跟控制台会话），
   S1 不处理这种漂移，文档记录。
3. 手机连上时被控端已在锁屏 ⇒ 初始探测兜底；被控端在 UAC ⇒ 误报为锁（可接受，§2.1）。
4. dev 双实例 / 孤儿进程：WTS 注册绑在推流会话的 `InboundVideo` 上，孤儿 dev 实例无会话即无线程，
   不会出现「旧实例还在发 wts」。
5. 性能：零常驻（线程只活在会话期、只在状态变化发一帧）；无定时器、无轮询（规则 8 自查通过）。

## 7. 明确不做（本批）

- 桌面控端 UI 消费 `rc-lock-changed`（事件已 emit，一行 `listen` 的后续）。
- 「解锁」按钮 / SAS / CAD（S4+S6，必须同批另做）。
- 乙档压自动锁来源（S2，独立小批）。
- wts 事件的服务端持久化/重放（重连=重建会话=初始探测，见 §2.1）。
