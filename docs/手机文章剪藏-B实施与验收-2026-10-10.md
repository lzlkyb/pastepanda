# 手机文章剪藏 B：实施与验收

2026-10-10。用户确认实施「文章剪藏 B」并创建 PR。分支 `codex/mobile-article-ui`，基线 `origin/master` 的 `3818de7e`。本轮没有升级版本、构建 EXE 或 APK、安装到手机。

## 已实施的用户流程

知识库「新建」统一为写笔记、收藏文章、收集图片。收藏文章采用全页正文预览：用户复制微信公开文章链接，粘贴后读取；手动输入可点击读取。系统分享提供单个文章链接时进入同一流程，普通长文字和图片仍走原收集流程。不假设微信自带转发菜单支持第三方 App。

标题、文件夹、标签和收藏原因可选，默认收起。正文取得后保存至本机笔记并打开现有阅读器；原文、目录、常用、搜索、分享与同步沿用现有能力。失败可重试或明确选择仅存链接，不把网页请求成功当成全文保存成功。

文章任务独立于普通编辑草稿，SQLite 保留来源、正文、用户输入、图片报告和提交回执，最多20条未完成任务。返回知识库后可继续；进程被终止后没有保证后台下载，重新进入可读取已持久化任务。保存成功后才消费系统分享；清理失败可以针对同一笔记重试。

按保留必要参数的 URL 身份及最终重定向地址去重；保存事务再检查一次，并绑定成功笔记。两个待收集链接先指向同一原文、随后分别保存，也不会创建两篇或覆盖已有备注。仅存链接后补正文更新同一笔记；若笔记已被用户修改，拒绝覆盖并提供查看已有笔记的入口。

## 图片与资源边界

复用桌面的公开网页抓取、公众号正文定位及前端 HTML→Markdown 清洗；图片输出手机已有的 `pp-asset:`，不搬桌面弹窗和文件路径。复用本机图片校验：单图10MB、文章图片合计60MB、最多128张，初次配图处理最多30秒，两项读取任务并发。无法取得图片时正文可先保存，阅读中可逐张或补齐剩余图片。

补图只替换当前笔记中对应的 Markdown 图片 token，保留用户当前正文、标题和分类。事务提交时保存索引化图片引用，公共剪贴板清理函数检查这些引用；下载到图片但尚未提交文章元数据时，用短期内存引用保护，提交或读取结束后释放。没有新增常驻动画、轮询或后台任务调度。

基础收藏不调用 AI。请求使用现有公开 URL 闸与重定向客户端；拒绝本机/内网/非 HTTP(S)/携带凭据的地址；正文验证页及过长内容拒绝作为文章保存。Markdown 阅读器继续阻止原始 HTML 执行及自动请求外部图片。

## 布局与操作反馈

沿用移动端语义色、按钮、通知与字号。正文独立滚动；短横屏在可用宽度≥520px、高度≤500px时，将保存动作和结果放在右侧。侧栏随字体增大，宽度不超过45%；更窄的页面使用底部操作区。长错误反馈可以单独滚动，主要动作保持可达。分类默认收起，缺图说明缩短，不增加遮挡正文的浮层。

浏览器用真实 `KnowledgeArticleView` 和真实收集 Hook 检查390×844竖屏、844×390横屏、568×320小横屏、320×568小屏以及24px字体。网络与存储由本地夹具模拟；无横向溢出、保存动作在视口内，存储错误与按钮同区可见。截图在 `.cache/article-qa/`，夹具和截图不纳入生产资源。
