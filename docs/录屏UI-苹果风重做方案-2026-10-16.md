# 录屏 UI 重做方案（苹果材料派）

2026-10-16。状态：**待用户确认方向**，未改动任何产品代码。配套设计稿 `design/录屏UI-苹果风重做-设计稿.html`（可直接浏览器打开，含可点的五态控制条、动效演示、减法清单与浅/深两套主题）。

不改流程与文案承诺（沿用 2026-10-16 已确认的「办公清晰版 B」交互结论），只重做**看得见的那一层**与反馈动效。
2026-10-16 追加两轮**减法**：先减提示文案（§5.1），再减重复元素（§5.2）。减的是 UI 里替用户解释自己、复述已知信息的东西，不动任何对外承诺。

---

## 0. 一句话

现在的录屏界面「不丑，但廉价」——廉价感的四个来源：**① 所有信息同字号同字重平铺；② 分隔靠 `|`、`·` 字符而不是间距；③ 实色强调滥用（一屏 2–3 个）；④ 状态切换没有连续性，元素直接出现/消失**。本方案逐条改掉并补上缺失的反馈动效。

## 2. 外部依据（Apple HIG，已核原文）

| 原则 | 原文要点 | 本方案怎么用 |
|---|---|---|
| **Materials 是语义化的** | 不是「统一一种玻璃」；不同 surface 用对应 material | 区分「材料浮层」（控制条/卡片）与「内容层」（面板，不透明）。**不给内容区上玻璃** |
| **Vibrancy 是对比度保险** | 保证材质之上的文字图标在不同背景下仍可读，不是装饰 | 材料底色不动对比度基线，文字仍走 `--shot-bar-text`；新增顶部高光只做厚度暗示、不改变字色基线 |
| **Hierarchy through depth** | 层级用 translucency / 厚度差表达，而不是颜色或大小 | 三层阴影（贴地/浮起/悬浮）+ 更少的边框（V1：边框是最后一手）|
| **Concentricity** | 内圆角 = 外圆角 − padding | 12 外 / 8 内（V4），全稿遵守 |
| **Motion** | 界面元素可随状态收起与展开；动效解释空间关系 | 控制条的三态（正常/更多/收起）做成**同一条的形变**，而不是三个不同的条 |

参考样本（同类产品的做法，用于对照而非照搬）：CleanShot X 的悬浮捕获条 + 最小化控制、Loom 的一键起录、macOS 自带截图的屏幕录制条。

## 3. 三个方向

主要分歧只有一处：**录制中的控制条该有多安静**。其余四个界面三案相同。

| | 甲 · 材料派（**推荐**）| 乙 · 极简 HUD | 丙 · 保守整理 |
|---|---|---|---|
| 录制中 | 状态点、计时、暂停、停止常驻；画质/声音/丢弃进「更多」 | 默认只留呼吸点 + 计时；鼠标靠近或快捷键才展开，离开 2s 自动收回 | 保持 260×36 布局与原生窗口逻辑，只统一按钮层级/曲线/命中区/材料 |
| 优点 | 零学习成本，纯鼠标全流程可达（规则 17.1）| 演示时几乎不占画面 | 改动面最小、回归风险最低 |
| 代价 | 常驻约 230px 宽 | 暂停/停止变两步可达；自动收起会让用户找不到按钮，与规则 17.2 有张力 | 廉价感的根因（尺寸硬编码、信息密度）不动，观感提升有限 |

**推荐甲**，并支持把乙的「自动收起」作为甲的一个可选设置（默认关）——两者不互斥。丙不建议单独做，它修的是症状。

### 5.1 文案减法（横切全部场景）

判据一条：**凡是文字在解释一个已经看得见、或者本来就能点的东西，就删掉它**——状态交给形状、实心与否和位置。

| 位置 | 现状 | 改成 | 载体 |
|---|---|---|---|
| 录前条目标 | `将录制` + `窗口所在区域 1536×1100` + `改录整屏 ↔` | `[窗口图标] 1536 × 1100`，整枚可点 | 图标 + 数字（22 字 → 0 字）|
| 框上 / 倒计时读数 | `窗口所在区域 · 1536×1100`、`将录制：窗口所在区域 1536×1100` | `1536 × 1100` | 只留读数本身 |
| 音源胶囊 | `电脑声音 开` / `麦克风 关` | `电脑声音` / `麦克风` | 实心点 = 开、空心点 = 关 |
| 「更多」声音行 | `电脑声音 开 · 麦克风 关` | `● 电脑声音　○ 麦克风` | 同上的点 |
| 选区常驻教学行 | `移动预览窗口 · 单击采纳 · 拖拽自选区域。按当前位置录制；移动或遮挡窗口会改变录到的内容。`（`RecOverlayParts.tsx:275`）| 整行删掉，收进 `?`；覆盖层底部只留状态 `可录 3 扇窗口` | 操作说明按需展开（L4、V7）|
| 倒计时键位提示 | `按 Esc 回到选区` | 整行删掉 | 键位由 `?` 与全局快捷键承载，不占倒计时一行 |
| 三处异常行 | `麦克风已断开，之后的人声不会录入。` / `未检测到系统声音。请预览核对画面与声音。` / `保存目录不可写，请检查磁盘空间或换一个保存位置后重试。` | `麦克风已断开` / `未检测到系统声音` / `保存目录不可写` | 只报事实，「怎么办」由旁边那枚按钮回答 |
| 预览保留段 | `实际保留 0:03.2 – 0:14.6（11.4 秒）` | `共 11.4 秒` | 起止已各有一枚芯片，只留差量 |
| 预览进度 | `正在另存 · 42%` | `正在另存 42%` | 分隔靠间距，不靠 `·` |
| 结果卡尾注 | `关闭后，可在「工具 → 最近录制」找回这段录像。` | 整条删掉 | 路径行已经说了文件在哪 |
| 结果卡失败尾注 | `录制内容不会保留；失败原因已写入日志。` | `录制内容不会保留` | 日志去向用户此刻不需要知道 |
| 最近录制范围 | `当前录屏目录 · 最近 5 个 MP4` | 整条删掉 | 一个上限说明不改变任何动作 |
| 最近录制空态 | `还没有录制。按 Ctrl+Shift+R，或点击上方「屏幕录制」开始第一段。` | `还没有录制，按 Ctrl+Shift+R 开始` | 后半句在指一个已经看得见的按钮 |
| 「更多」面板动作 | `收起为小计时` | `收起` | 按钮名不用把结果描述一遍 |

**不动的**（这些不是噪音，实施时别一起删）：`画质 高清`（设置名 + 当前值，缺任一项都会歧义）、`确认丢弃这段录像？`（不可逆动作的确认语）、失败的**事实**（`保存目录不可写`）与「录制内容不会保留」、以及 `?` 里按需展开的操作说明。

两条推论：

1. **删掉的信息如果还有用，就换一个更便宜的载体**——图标、点的实心 / 空心、控件自身的可点态。既不加字，也不让它只有悬停才能用。
2. **同一份数据 / 同一个动作在一屏里只说一次。** 预览里的「实际保留 0:03.2 – 0:14.6」是这条的典型反例；结果卡里路径行与动作区各放一枚「打开文件夹」，是同一个反例的第二种形态（§5.2）。

⚠️ 实施注意：音源不写「开 / 关」之后，**`title` 与 `aria-pressed` 必须一并带上**（前者补充、后者给读屏状态语义），二者都只是兜底，视觉上一律不加字；原版音源关闭态那套 40% 弱态写法一并废弃（本来就 6 个主题全不过 AA）。

### 5.2 结构减法（元素级）

判据与 §5.1 同一条，只是筛的对象从字换成元素：**一个信息只留一个载体，一个动作在一屏只出现一次。**

| 删掉的元素 | 为什么 |
|---|---|
| 「更多」面板每行左侧的图标 | 标签（`画质` / `声音` / `已写入`）已经是该行的名字，图标让名字在一行里出现两次 |
| 结果卡动作区里的「打开文件夹」 | 路径行内已有一个同名动作，同一动作保留一处即可 |
| 读数胶囊（框上 / 倒计时）前的小圆点 | 选区边框已经用强调色表示「就是它」，点是同一个信息的第二个载体 |
| 异常条的「知道了」按钮 | 换成各处的 ✕，全稿只剩一种关闭样式 |
| 控制条演示区的长注解 | 45 字 → 8 字（`↑ 点击切换五态`），按钮自己说明自己 |

删除这些元素不改变任何可达性：被删掉的那个载体所承载的信息，另一个载体本来就在说，且都是视觉可辨（不依赖悬停）。

### 🔴 必须同步处理的既有资产

1. **`src/__tests__/recGlassContrastGuard.test.ts`** 现算的是「`--shot-bar-*` 上的文字对比度」。若把玻璃底的 alpha 从 0.92/0.94 降到 0.76，它量的底色就不再是真实呈现色。
   **建议：不降 alpha**，观感提升全部来自「顶部高光 + 细描边 + 双层阴影 + 更少边框 + 更好的层级」。守卫不必改。
2. **Tauri 独立小窗 `transparent(true)` 下 `backdrop-filter` 穿不出窗口**（tauri#10064，2024-06 至今）——设计稿里的模糊在浏览器里可见，在产品里看不到窗口外的桌面。**不要把方案的收益押在 blur 上**；真正有效的是半透明底 + 高光 + 阴影。这一条与规则 6（构建/环境）无关，是渲染事实。
3. **`--ease-spring` 目前全库无人使用**（U2 里写的是「预防性判据」）。本次要用，须先在 `globals.css` 定义该令牌（`linear()` 采样自上面那组参数）。
4. 新增的材料令牌要登记进 `docs/PastePanda-色彩规范.md`；改完跑 `npm run gen:design-index` 刷新 `design/README.md`。
5. `RecOverlayParts.tsx`(296) 与 `RecPreview.tsx`(293) 都贴着 300 行红线，**按规则 7 先拆再改**。

## 6. 实现顺序

1. 令牌与按钮基类（`recsel.css` + `globals.css` 的 `--ease-spring`）——零行为变化，可独立落地并跑 `lint:ui`。

4. 控制条（DOM 量尺寸上报 + 弹簧形变 + 更多面板）。
5. 结果卡。

8. 给新增动效补守卫（红点在减少动效下仍为实色可辨；控制条窗口尺寸 = 可见浮条尺寸）。

## 7. 验收

- **黑话测试**：录前条截图给没用过的人，能逐块说出「这是干吗的」。
- **去色测试**：截图转灰度，层级仍然可辨。
- **删字测试**：录前条、结果卡、预览里，**每个字都要能指到一个可点元素或一个真实读数**；指不到的就是 §5.1 里该删的那类提示。
- **删元素测试**：每个视觉元素承载的信息，都要在**别处**有且只有一个更便宜的载体；同一个动作在一屏里只出现一次（§5.2）。典型反例：图标与标签并存、同一屏两个「打开文件夹」、用文字报「开 / 关」。
- 每屏实色 ≤ 1；所有可点元素有一致的 hover/active 反馈（150ms）。
- 纯鼠标可完成全流程；键盘只是加速器。
- 减少动效下「正在录制」仍有静态表达（红点保持实色，不做透明度脉冲）。
- 控制条原生窗口尺寸与可见浮条一致（禁止留下透明大窗拦桌面操作）。
- `npm run lint:ui` block 级 0 处 + `npm run lint:css` + `npx tsc --noEmit` + 录屏相关 vitest 全绿。

## 8. 不做

- 不改流程与文案承诺，不新增必经向导。
- 不做乙案的自动收起（除非用户要），不引入摄像头/字幕/多轨。
- 不在内容层使用材料（Apple HIG 明确 Liquid Glass 不用于 content layer）。
- 不引入 Inter / Roboto / Arial 等 Web 字体（V8.2，本项目走系统字体栈）。
