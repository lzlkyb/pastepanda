# 手机端页签滑动体验调研

日期：2026-10-03。范围：设备／文件／设置主页之间的滑动。本文是源码检查与官方资料调研，尚未修改应用，也未通过手机真机测量手感。

## 结论

建议使用「连续拖动的分页容器 + 松手吸附」，保留现有玻璃导航栏。现在的实现更接近识别一个滑动动作后换内容，缺少页面之间连续的空间关系。仅降低切页距离能提高触发率，但不能解决页面不跟手和切换断裂。

## 当前实现的具体问题

检查文件：`src-mobile/ui/useMobileTabSwipe.ts`、`src-mobile/ui/useMobileTabMotion.ts`、`src-mobile/App.tsx`、`src-mobile/App.module.css` 及现有手势测试。

1. **方向过早判死**：位移达到 12 CSS px 后，只要横向位移不超过纵向的 1.3 倍，就立即取消整次手势。自然拇指弧线可能在方向尚未明确时被取消；后续再向横向移动也不会恢复。明确的纵向滚动仍应交给系统，不能在浏览器已经接管后强抢回来。
2. **页面跟随不足**：有相邻页时页面移动仅为手指位移的 35%，最大 64 px；相邻页面不显示。手指滑动 100 px，页面只移动 35 px。视觉反馈容易被理解成阻力而非翻页。
3. **速度取值不符合最后甩动**：短滑切页要求至少 32 px、速度至少 0.5 px/ms，但速度使用总位移除以从按下开始的总时间。先停留再快速甩动会被停留时间稀释；拖动后停住也不能准确反映松手时速度。
4. **拖动与切换不连续**：提交时清零拖动位移并切换内容，随后由另一套 Hook 播放 12 px／200 ms 的进入动画。它没有接着手指松开的位置完成整页位移。
5. **底部导航不在滑动区域**：手势只绑定到 main。用户在底部玻璃导航上左右滑动没有切页响应。这里是否增加导航内滑动需要明确设计，避免与按钮点按争抢。

现有测试覆盖了横滑、纵滑、系统边缘、输入控件、弹层、取消、多指、短甩和减少动态效果；主要使用少量模拟坐标。它们没有证明连续轨迹、停留后甩动、回拉、浏览器滚动接管或实际设备帧表现。

## 成熟实现的做法

- **Apple**：强调直接操作、即时反馈、手势结果可预测；快捷手势应补充可见按钮，并避免和系统手势冲突。标签栏还需要保留各分区导航状态。因此继续保留底部点按入口，不能把横滑作为唯一入口。Apple 并未要求所有顶层标签都支持全屏横滑。[手势规范](https://developer.apple.com/design/human-interface-guidelines/gestures/)、[标签栏规范](https://developer.apple.com/design/human-interface-guidelines/tab-bars/)
- **Android Pager**：提供真实横向分页、拖动位置及目标页／落定页状态；默认一次甩动最多跨一页，支持动画滚到目标页。可借鉴其连续分页与吸附模型；本项目是 WebView，不能直接照搬 Compose 组件。[官方 Pager 文档](https://developer.android.com/develop/ui/compose/layouts/pager)
- **Ionic**：将方向、起手阈值、可接受角度、当前速度及手势生命周期分别建模。它的默认起手阈值 10、最大角度 40 是该框架的默认值，不是本项目必须照抄的标准。[官方手势文档](https://ionicframework.com/docs/utilities/gestures)
- **WebView 的限制**：浏览器接管滚动／缩放时可以取消 Pointer Events 流。必须合理使用 touch-action 和取消路径，不能用 preventDefault 或 pointer capture 保证任意手势都不被系统取消。[W3C Pointer Events](https://www.w3.org/TR/pointerevents3/)

## 两个可选方案

| 方案 | 改动 | 收益与代价 |
| --- | --- | --- |
| A：修正现有判定 | 方向未定时继续观察，改用末段速度，校正松手坐标 | 修改范围较小，可缓解难触发；仍缺少相邻页预览和连续翻页 |
| B：连续分页，推荐 | 真实相邻页跟随拖动；统一松手完成／回弹与导航选中状态 | 能同时解决触发和手感；需要处理页面生命周期、独立滚动位置及隐藏页面开销 |

## B 方案的交互目标

1. 起手先处于「未定方向」，只有横向或纵向意图足够明确才锁定；明显竖滑继续原生滚动。方向锁定后不在同次手势中来回变更。
2. 普通区域横向拖动近似 1:1 跟手，同时露出真实相邻页。首页／末页才施加轻阻力，不循环。
3. 慢拖按页面宽度比例决定完成或回弹；短甩按最近一段轨迹的方向与速度决定。初始候选：慢拖约 20%–25% 页宽，短甩至少约 24–32 CSS px；这些是待真机调校的设计值，不是 Apple 官方数值。
4. 松手后从当前位置和当前速度继续运动，一次最多切一页；支持松手前反向拉回，也支持动画中重新触摸接管。
5. 导航选中背景跟随分页进度，落定后提交页签与可访问状态；保留图标及文字，移除频繁变化的「继续滑动／松手切换」文字。
6. 每页保留滚动位置；文件选择／传输流程与未完成设置不会因滑到下一页而丢失。只渲染必要页面，隐藏页面暂停计时和动画，不能为预览复制业务实例或制造额外网络轮询。
7. 输入框、滑块、文本选择、横向控件、弹层和远控画面各自保留手势；系统左右边缘不抢返回。底部导航优先保持点按切换；若增加导航内滑动，应作为单独测试的补充入口。

## 落地验收

- 单手拇指轻微斜向横滑、连续拖动、停留后短甩均能合理识别。
- 快甩只切一页；慢拖不够距离回弹；反向拉回和中途打断不跳页。
- 纵向长列表、按钮点击、输入、系统边缘返回、弹层拖动及远控触摸不受影响。
- 切页后文件操作和各页滚动位置保留；隐藏页面无持续动画和新增轮询。
- 低性能 Android 手机及高刷新率设备实测页面跟手；浏览器鼠标测试不替代真机手势验收。
- 开启「减少动态效果」时仍可切页，并减少大幅页面位移。
