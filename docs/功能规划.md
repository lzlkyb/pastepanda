# PastePanda 功能规划（详细方案）

---

## 一、智能化方向

### 1. AI 智能分类 ⭐⭐⭐

**目标**：剪贴板内容自动识别类型并打标签，无需手动整理，大幅提升查找效率。

**识别分类维度**：

| 类别 | 识别规则 | 示例 |
|------|----------|------|
| 代码 | 编程语言特征（关键字/语法结构） | JavaScript、Python、Rust、SQL、CSS、HTML |
| 链接 | URL 正则 | `https://github.com/user/repo` |
| JSON | 合法 JSON 格式 | `{"name": "test"}` |
| 配置文件 | YAML/TOML/INI 格式 | `server.port=8080` |
| 日志 | 时间戳前缀 + 级别标识 | `2024-01-01 ERROR ...` |
| 表格数据 | CSV/TSV 格式 | `name,age,city` |
| 命令行 | 命令 + 参数结构 | `git commit -m "msg"` |
| 密钥/Token | Base64 编码 + 长度特征 | `eyJhbG...` |
| 纯文本 | 自然语言 | 普通段落文字 |
| 数字 | 纯数字 | `12345` |

**实现方案**：

**方案 A：纯本地规则引擎（推荐）**
- 在 Rust 后端实现分类引擎，启动时编译一次正则规则集
- 优点：零网络依赖、零成本、响应快（<1ms）、隐私安全
- 缺点：无法识别复杂语义（如自然语言主题分类）
- 规则优先级：正则 → 语法验证（JSON/YAML）→ 统计特征（代码行/关键字密度）→ 默认 fallback

**方案 B：本地小模型**
- 集成轻量级 NLP 模型（如 onnxruntime + 小型 BERT）
- 优点：语义理解能力更强
- 缺点：增加包体积 50-100MB、首次加载慢、维护成本高

**方案 C：云端 API**
- 调用 OpenAI/Claude API
- 优点：最准确
- 缺点：需要联网、有费用、隐私风险、延迟高

**推荐方案 A**，实现细节：

1. **数据库扩展**：`history` 表新增 `auto_tags TEXT` 字段（JSON 数组，如 `["代码","JavaScript"]`）
2. **分类引擎**（Rust `src-tauri/src/content_classifier.rs`）：
   - 规则链式匹配，命中即返回
   - 代码类进一步识别语言（用 `syntect` 或正则关键字密度）
   - 所有规则编译为静态常量，启动时零开销
3. **前端展示**：
   - Card 卡片右上角显示标签徽标
   - TopBar 筛选栏新增"智能标签"下拉筛选
   - 支持按标签搜索
4. **性能**：每条记录分类 < 1ms，不阻塞主线程（`tokio::spawn_blocking`）

### 2. AI 内容摘要 ⭐⭐

**目标**：长文本（>500 字）自动生成一句话摘要，在卡片列表中快速浏览。

**实现方案**：

**方案 A：本地提取式摘要（推荐）**
- 基于 TextRank 算法：提取原文中最具代表性的 1-2 个句子
- Rust 实现，无外部模型依赖
- 优点：零成本、隐私安全、速度快

**方案 B：云端 LLM 摘要**
- 调用 LLM API 生成抽象式摘要
- 优点：摘要质量最高
- 缺点：需要联网和费用

**推荐方案 A**，实现细节：

1. **触发条件**：文本长度 > 500 字符时自动生成
2. **算法**：
   - 分句 → 构建句子相似度矩阵（TF-IDF + 余弦相似度）→ TextRank 迭代 → 选 top-1 句子
3. **存储**：`history` 表新增 `summary TEXT` 字段
4. **展示**：卡片中文本预览替换为摘要（原内容前 100 字 → 摘要），hover 或展开显示原文
5. **手动触发**：右键菜单 "生成摘要"

### 3. 智能合并 ⭐⭐

**目标**：检测连续复制的相关片段（如同一函数的多个代码块、同一篇文章的多个段落），提示合并为一条。

**实现方案**：

1. **检测规则**：
   - 时间窗口：连续 3 条记录在 30 秒内产生
   - 内容相关性：同一代码语言、同一自然语言、同源应用
   - 代码类：前一条末尾 + 后一条开头没有明显的语法断点（如函数结尾 `}`）
   - 文本类：段落语义连续性
2. **提示方式**：
   - 卡片列表中相邻条目显示"合并提示"分隔线（蓝色虚线 + "↑ 以上 3 条可能相关，点击合并"）
   - 支持一键合并或忽略
3. **合并操作**：
   - 前端调用 `merge_items(ids: Vec<String>)` → 后端合并为一条新记录
   - 自动使用 `\n` 或 `\n\n` 拼接，保持原格式
   - 原记录保留（不删除），新记录置于顶部

## 二、效率增强

### 4. 剪贴板栈 ⭐⭐⭐

**目标**：类似"收集模式"，按顺序复制多段内容后一次性粘贴到不同位置。

**使用场景**：填写表单时，需要从多个来源依次复制姓名、电话、地址、备注，然后逐个粘贴到表单各字段。

**实现方案**：

1. **栈模式**：
   - 全局快捷键进入/退出栈模式（默认 `Ctrl+Shift+K`）
   - 栈模式下，每次 `Ctrl+C` 不覆盖剪贴板，而是追加到栈队列
   - 托盘图标变色（橙色圆点），表示处于栈模式
2. **粘贴行为**：
   - 每次 `Ctrl+V` 粘贴栈顶元素并弹出（FIFO 出栈）
   - 栈为空时自动退出栈模式
   - 主窗口显示栈队列可视化管理
3. **UI 展示**：
   - 主窗口顶部出现"栈模式"横幅（带计数 `[3/5]`）
   - 卡片列表中栈内条目标记特殊样式（橙色边框）
   - 支持拖拽调整顺序
   - 支持"全部粘贴"（依次粘贴所有栈项）
4. **数据模型**：`appStore` 新增：
   ```typescript
   stackMode: boolean;
   stackItems: HistoryItem[];
   stackPointer: number;  // 当前粘贴位置
   ```
5. **兼容现有功能**：栈模式独立于依次粘贴（sequential_loop），互不干扰

### 5. 历史对比 (Diff) ⭐⭐

**目标**：选中两条文本记录，对比差异并高亮显示，类似 Git diff。

**实现方案**：

1. **触发方式**：
   - 按住 `Ctrl` 选中两条文本记录 → 右键菜单 "对比差异"
   - 对比对话框左右分栏显示
2. **Diff 算法**：
   - 前端使用 `diff` 库（`diff-match-patch` 或 `jsdiff`），按行/按词对比
   - 绿色高亮新增、红色高亮删除、灰色表示未变
3. **对比模式**：
   - 行级对比（默认）
   - 词级对比（精确到单词/字符）
   - 忽略空白差异
4. **操作**：
   - "复制左侧" / "复制右侧"
   - "合并到新记录"（选择保留的内容）

### 6. 正则过滤/替换 ⭐⭐

**目标**：粘贴前对内容执行正则替换，实现格式化、脱敏、提取等操作。

**实现方案**：

1. **预设规则**（内置）：
   | 规则名称 | 正则 | 替换 | 说明 |
   |----------|------|------|------|
   | 去除空行 | `^\s*$\n` | `` | 删除所有空白行 |
   | 去除首尾空格 | `^\s+|\s+$` | `` | 多行分别 trim |
   | 合并连续空格 | ` {2,}` | ` ` | 多余空格变单空格 |
   | 去除 HTML 标签 | `<[^>]+>` | `` | 剥离 HTML |
   | 去除 Markdown 语法 | 多规则 | 原文本 | 剥离 `**`/`#`/`[]()` 等 |
   | 移除行号 | `^\s*\d+\s*` | `` | 复制代码时常带行号 |
   | Base64 解码 | — | 解码后文本 | 自动检测并解码 |
   | URL 解码 | `%20` 等 | 解码 | 百分号解码 |
   | 手机号脱敏 | `(\d{3})\d{4}(\d{4})` | `$1****$2` | 138****1234 |
   | 身份证脱敏 | `(\d{4})\d{10}(\d{4})` | `$1**********$2` | 前4后4 |
2. **自定义规则**：
   - 设置面板新增"正则规则"页
   - 用户可添加/编辑/删除自定义规则（名称 + 正则 + 替换 + 启用状态）
   - 存储在 `config` 表，key = `regex_rules`
3. **触发方式**：
   - 右键菜单 → "粘贴并变换"子菜单中新增"正则替换"分组
   - 粘贴前预览替换结果（弹出预览对话框）
4. **安全限制**：ReDoS 防护 — 超时 100ms 自动中断，禁止嵌套量词

### 7. 文本模板 ⭐⭐

**目标**：预定义常用文本模板，一键插入剪贴板并粘贴。

**实现方案**：

1. **内置模板**：
   - Git Commit 模板（`feat: xxx\n\n- 变更1\n- 变更2`）
   - 邮件签名（`Best regards,\n{name}`）
   - 当前时间戳（`2024-07-04 12:51:00`）
   - UUID v4
   - 随机密码（16 位）
2. **自定义模板**：
   - 设置面板新增"模板管理"
   - 支持变量：`{date}`、`{time}`、`{datetime}`、`{uuid}`、`{clipboard}`（当前剪贴板内容）
3. **触发方式**：
   - 全局快捷键（默认 `Ctrl+Shift+T`）弹出模板选择器
   - 主窗口工具栏新增"模板"按钮
   - 选中模板后自动复制到剪贴板并粘贴

### 8. 内容脱敏 ⭐

**目标**：一键对剪贴板内容中的敏感信息进行脱敏处理。

**实现方案**：

1. **脱敏规则**：
   | 类型 | 识别 | 脱敏方式 |
   |------|------|----------|
   | 手机号 | `1[3-9]\d{9}` | `138****1234` |
   | 身份证 | `\d{17}[\dXx]` | `3301**********1234` |
   | 银行卡 | `\d{16,19}` | `6222****1234` |
   | 邮箱 | `xxx@xxx.xx` | `t***@example.com` |
   | IP 地址 | `\d+\.\d+\.\d+\.\d+` | `192.168.*.*` |
2. **触发方式**：
   - 右键菜单 → "脱敏处理"
   - 生成脱敏后的新记录（保留原始记录）
3. **实现**：纯前端 JavaScript 正则匹配替换，无需后端

## 三、内容扩展

### 9. Markdown 实时预览 ⭐⭐

**目标**：检测到 Markdown 内容时，提供渲染后的预览视图。

**实现方案**：

1. **检测规则**：内容包含 `#` 标题、`**粗体**`、`` `代码` ``、`- 列表`、`[链接]()` 等 Markdown 语法特征
2. **预览组件**：
   - 新增 `MarkdownPreview` 组件
   - 使用 `marked` 或 `markdown-it` 渲染（约 30KB gzipped）
   - 支持 GitHub Flavored Markdown（表格、任务列表、代码块高亮）
   - 代码块使用已有的 `shiki` 进行语法高亮
3. **触发方式**：
   - 检测到 MD 内容时，Card 预览区显示渲染后的摘要
   - 双击打开 MD 预览对话框（左右分栏：源码 | 预览）
   - 工具栏按钮 "复制为 HTML" / "复制为纯文本"
4. **依赖新增**：`marked` 或 `markdown-it`

### 10. 颜色值拾取预览 ⭐

**目标**：自动检测剪贴板中的颜色值，显示色块预览。

**实现方案**：

1. **识别格式**：
   - Hex：`#FFF`、`#FFFFFF`、`#FFFFFFFF`（含 alpha）
   - RGB：`rgb(255, 0, 0)`、`rgba(255, 0, 0, 0.5)`
   - HSL：`hsl(0, 100%, 50%)`、`hsla(0, 100%, 50%, 0.5)`
   - CSS 命名颜色：`red`、`dodgerblue` 等（140 种）
2. **展示**：
   - Card 卡片左侧显示色块圆点（16×16px）
   - hover 显示颜色值复制按钮
   - 支持点击色块在不同格式间切换（HEX ↔ RGB ↔ HSL）
3. **实现**：纯前端正则匹配 + CSS 色块渲染，零依赖

### 11. Base64 编解码 ⭐

**目标**：右键菜单一键对剪贴板内容进行 Base64 编解码。

**实现方案**：

1. **自动检测**：内容仅包含 `[A-Za-z0-9+/=]` 且长度 > 20，可能为 Base64 编码
2. **操作**：
   - 右键菜单 → "Base64 解码"（检测到可能是编码时显示）
   - 右键菜单 → "Base64 编码"（始终显示）
   - 操作后生成新记录，保留原记录
3. **实现**：纯前端 `btoa`/`atob`（或 Rust 后端 `base64` crate）

---

### 12. 二维码生成 ⭐

**目标**：对 URL/文本一键生成二维码图片。

**实现方案**：

1. **触发条件**：内容是 URL 或短文本（< 300 字符）
2. **展示**：
   - 右键菜单 → "生成二维码"
   - 弹出对话框显示二维码图片 + 原始内容
   - 支持 "复制二维码图片"（复制到剪贴板）
   - 支持 "保存二维码"（另存为 PNG）
3. **实现**：
   - 前端使用 `qrcode` 库（约 15KB gzipped）Canvas 生成
   - 或 Rust 后端使用 `qrcode` crate 生成 SVG/PNG
4. **依赖新增**：前端 `qrcode` 或 Rust `qrcode`

### 13. 截图标注 ⭐⭐

**目标**：图片预览时支持画笔标注、箭头、文字注释。

**实现方案**：

1. **标注工具栏**（图片预览对话框新增）：
   - 画笔（自由绘制，可选颜色/粗细）
   - 箭头（拖拽绘制方向箭头）
   - 矩形框（拖拽绘制）
   - 文字（点击添加文字标注，可选字号/颜色）
   - 马赛克/模糊（拖拽区域模糊化）
   - 撤销/重做
   - 清空标注
2. **实现**：
   - Canvas 叠加层绘制标注
   - 标注数据存储为独立 JSON（不修改原图）
   - 导出时合成标注到图片
3. **操作**：
   - "复制标注后图片"（合成标注后复制到剪贴板）
   - "保存标注后图片"
   - "仅复制标注数据"（JSON，可分享给他人叠加）
4. **性能**：Canvas 离屏渲染，不影响原图显示

### 14. HTML 转纯文本 ⭐

**目标**：检测 HTML 内容，一键剥离标签保留纯文本。

**实现方案**：

1. **检测规则**：内容以 `<!DOCTYPE` 或 `<html` 或 `<div` 等标签开头，且包含闭合标签
2. **操作**：
   - 右键菜单 → "剥离 HTML 标签"
   - 使用 DOM parser 或正则提取 `textContent`
   - 生成新纯文本记录
3. **实现**：纯前端 `DOMParser` API 或 Rust 后端正则

## 四、数据管理

### 15. 自定义分组/文件夹 ⭐⭐⭐

**目标**：手动创建分组，将剪贴板记录归类整理，替代简单的收藏标记。

**实现方案**：

1. **数据模型**：
   - 新增数据库表 `groups`：
     ```sql
     CREATE TABLE groups (
       id TEXT PRIMARY KEY,
       name TEXT NOT NULL,
       color TEXT DEFAULT '#3B82F6',
       icon TEXT DEFAULT 'folder',
       sort_order INTEGER DEFAULT 0,
       created_at TEXT NOT NULL
     );
     ```
   - `history` 表新增 `group_id TEXT` 字段（可为 NULL）
2. **UI 交互**：
   - 左侧新增分组侧边栏（可折叠，宽度 200px）
   - 默认分组：全部、未分组、收藏
   - 右键菜单 → "移动到分组" 子菜单选择目标分组
   - 支持拖拽卡片到侧边栏分组
   - 分组支持重命名、改颜色、排序、删除
   - 筛选栏分组选择器
3. **筛选**：`filterType` 扩展 `group:{groupId}` 格式
4. **存储**：分组删除时，其下记录 `group_id` 置为 NULL（不级联删除）

### 16. 标签系统 ⭐⭐⭐

**目标**：为剪贴板记录添加多个自定义标签，支持多标签交叉筛选。

**实现方案**：

1. **数据模型**：
   - 新增 `tags` 表：
     ```sql
     CREATE TABLE tags (
       id TEXT PRIMARY KEY,
       name TEXT NOT NULL UNIQUE,
       color TEXT DEFAULT '#3B82F6',
       created_at TEXT NOT NULL
     );
     ```
   - 新增关联表 `history_tags`：
     ```sql
     CREATE TABLE history_tags (
       history_id TEXT NOT NULL,
       tag_id TEXT NOT NULL,
       PRIMARY KEY (history_id, tag_id),
       FOREIGN KEY (history_id) REFERENCES history(id) ON DELETE CASCADE,
       FOREIGN KEY (tag_id) REFERENCES tags(id) ON DELETE CASCADE
     );
     ```
2. **UI 交互**：
   - Card 卡片底部显示标签徽标（彩色圆角小标签）
   - 右键菜单 → "编辑标签" → 弹出标签选择器（支持搜索、创建新标签）
   - 筛选栏新增标签筛选（多选下拉，AND 逻辑）
   - 标签管理面板：创建/编辑/删除标签、选择颜色
3. **快捷操作**：
   - 点击标签直接筛选该标签
   - 批量选择多条记录 → 批量添加/移除标签
4. **与 AI 智能分类协作**：AI 自动识别的类型自动创建对应标签（`#代码`、`#链接`）

### 17. 定期自动备份 ⭐⭐

**目标**：按设定的时间间隔自动导出数据库到指定备份目录。

**实现方案**：

1. **配置项**（设置面板新增）：
   - 备份开关（默认关闭）
   - 备份间隔：每天/每周/每月
   - 备份时间：如每天 02:00
   - 备份目录（默认 `Documents/PastePanda/backups/`）
   - 保留最近 N 份备份（默认 10 份）
2. **备份格式**：JSON 文件（与手动导出格式一致），文件名为 `backup_{datetime}.json`
3. **实现**：
   - Rust 后端 `backup_scheduler.rs`：`tokio::time::interval` 定时检查
   - 应用启动时读取上次备份时间，判断是否需要立即备份
   - 备份在后台线程执行，不阻塞 UI
4. **自动清理**：超出保留数量的旧备份自动删除
5. **通知**：备份完成/失败后托盘通知

### 18. 数据加密 ⭐⭐

**目标**：对敏感剪贴板内容进行 AES 加密存储。

**实现方案**：

1. **加密范围**：
   - 用户手动标记"加密"的记录（右键菜单 → "加密此记录"）
   - 或按标签自动加密（如标签 `#密码`、`#密钥` 的内容自动加密）
2. **加密方案**：
   - AES-256-GCM 加密（Rust `aes-gcm` crate）
   - 密钥派生：用户设置主密码 → PBKDF2 派生 256-bit 密钥
   - 加密后存储：`text` 字段替换为 `{iv}:{ciphertext}:{tag}` base64 格式
3. **交互**：
   - 首次使用加密功能时设置主密码
   - 查看加密内容时输入主密码（会话内缓存，关闭窗口后失效）
   - 加密记录卡片显示 🔒 图标 + "已加密" 占位文本
   - 导出时加密内容需要输入主密码才能导出明文
4. **安全注意**：
   - 主密码不存储在任何位置，仅内存中保留（会话期间）
   - 忘记主密码 = 数据不可恢复（明确提示用户）

### 25. 插件系统 ⭐

**目标**：开放插件 API，允许社区贡献内容处理器。

**实现方案**：

1. **插件类型**：
   - **内容处理器**（Processor）：接收原始文本 → 返回处理后的文本（如格式化、翻译、加密）
   - **内容检测器**（Detector）：接收文本 → 返回类型标签（如检测到"快递单号"）
   - **渲染器**（Renderer）：接收文本 → 返回自定义 JSX 预览（如地图坐标渲染为地图）
2. **插件格式**：
   - JavaScript/TypeScript 文件
   - 放置在 `%APPDATA%/PastePanda/plugins/` 目录
   - 标准导出接口：
     ```typescript
     interface PastePandaPlugin {
       name: string;
       version: string;
       type: "processor" | "detector" | "renderer";
       process?(text: string): string | Promise<string>;
       detect?(text: string): string[] | Promise<string[]>;
       render?(text: string): React.ReactNode;
     }
     export default myPlugin;
     ```
3. **插件管理**：
   - 设置面板 → "插件管理"
   - 列表显示已安装插件（名称/版本/类型/状态）
   - 支持启用/禁用/卸载
   - "从文件安装"按钮
4. **安全**：
   - 插件运行在沙箱 iframe 中（`sandbox="allow-scripts"`）
   - 通过 `postMessage` 通信，限制可调用 API
   - 插件无法访问文件系统、数据库
5. **加载机制**：
   - 应用启动时扫描插件目录
   - 动态 `import()` 加载，错误隔离（单个插件崩溃不影响主程序）
