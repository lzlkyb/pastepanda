# 远程电脑 · 操作流程与画质 · 对标清单

> 2026-09-19 · 状态：**对比清单（基线 = v7.2.x + 09-19 三轮改造后）**，差距立项待确认。
> 范围：**只对比操作流程与画质**。音频、文件传输、移动端等功能完备度见《对比商业顶尖远程桌面-清单-2026-09-19》；帧率专项见《高帧率与本地体感-对比方案》；弱网传输见《画质与流畅度-对齐超越清单》。
> 对比对象：Chrome Remote Desktop、AnyDesk、TeamViewer、RustDesk、ToDesk、向日葵、Parsec、Moonlight+Sunshine、mstsc。
> 我们的数据全部来自代码现状；端到端画质观感（偏色/清晰度）**需双机实测确认**，表中如实标注。

## 一、操作流程

### A · 连接动线（首次信任 → 发起 → 确认 → 接入）

| 环节 | 我们 | 商业主流 |
|---|---|---|
| 首次信任 | ①附近设备：同网段发现 → 双方显示**同一个 6 位数字** → 各点一次「两边一样，确认」；②邀请码 `PP1`（30 分钟、一次性） | 账号登录 + 设备绑定（TeamViewer/ToDesk）；ID + 临时密码（AnyDesk/RustDesk/向日葵）；Google 账号 + PIN（Chrome RDP） |
| 信任强度 | 6 位数字是现场协商密钥的摘要，**防中间人**；不上云、无账号 | 账号体系信任（云端背书）；临时密码一次性但无中间人检测 |
| 发起 | 设备列表点设备 → 申请「只看 / 可控」 | 输入 ID/从列表选 → 直接连 |
| 每次确认 | 默认**每次申请**被控端都要点头；可**逐台**开「免确认」；「禁止」优先级最高；**能力上限**（对方申请不能超过所设档） | 默认每次弹窗接受；可设白名单/黑名单 |
| 无人值守 | ✗ **没有**：被控端不在场时无法完成首次授权（免确认必须先在场配对+授权） | ✓ 全员标配：被控端设**固定密码** → 主控端 ID+密码直连，无需任何人在场（AnyDesk/RustDesk/ToDesk 同构） |
| 发起入口 | 工作台设备列表；附近的设备一点配对后可「立刻发起」 | 桌面快捷方式 / 开机自启常驻 / 移动端 |

### B · 会话内操作

| 环节 | 我们 | 商业主流 | 评价 |
|---|---|---|---|
| 画质切换 | 底栏下拉 8 档 + 自动；乐观 UI + 失败回滚；立即生效（无新信令） | 普遍有画质菜单 | **领先**：档位更细 + 能力门控（跑不到的档不卖） |
| 画面范围 | 整屏 / 主屏 / 逐屏（monitor:N），会话中切换，被控端即时收到可见通知 | 普遍支持多屏 + **快捷键轮换** | 持平偏上；缺快捷键轮换 |
| 键盘 | 点击画面开启捕获；Esc 两级退出；自动重复去洪泛；失焦/退出补发释放 | 普遍等同 | 持平 |
| 指针 | 锁定指针（相对位移）+ 本地光标即时回显 + 远端光标形状同步 | Parsec 招牌体验 | **接近 Parsec**（对齐超越清单已确认） |
| 剪贴板 | 双向**文本** + 自动同步开关 + 64KB 明确报错 | 文本 + 图片 + 文件 | 落后（文件另列） |
| 全屏 | ✓ 内嵌全屏，Esc 退出；工具条浮现式跟随 | ✓ | 持平 |
| 结束会话 | 确认对话框 → 双方收口；按键/鼠标状态补发释放；进会话历史 | 普遍等同 | **持平偏上**（补发释放细节多数产品没有） |
| 断线恢复 | 收流错误拼出真实原因展示 + 手动「重连」；重连重新走申请（免确认设备近似自动） | 普遍**自动重连** + 进度提示 | 落后半步 |
| 状态透明度 | HUD：编码·fps / 延迟 / 画面延迟（时钟校准）/ **采编网解四段** / 操作延迟 / 丢包 / 码率 / 路径 | 商业只给连接质量笼统标识 | **独特领先** |

### C · 被控端知情权与控制

| 环节 | 我们 | 商业主流 |
|---|---|---|
| 被控提示 | 顶部横幅 + 信息页（对方指纹 / 当前范围 / 画质 / 免确认管理） | 弹窗确认后多数无持续提示 |
| 范围变更 | 被控端**即时可见通知** | 少见（企业审计走云端） |
| 会话历史 | 本地历史（对端/能力/时长/结束原因） | 云端后台（企业版） |
| 远程改画质/编码 | 仅日志，无 UI 提示 | — | 小差距 |

### D · 操作流程小结

- **领先**：6 位数字现场比对、能力上限、被控端知情权三件套、状态透明度（HUD）、结束时的状态收口。
- **落后**：①**无人值守接入缺失**（远程协助的核心场景：帮不在场的家人/服务器排障）——所有商业产品都有，我们完全没有；②断线自动重连；③多屏快捷轮换；④剪贴板只有文本。

## 二、画质

### E · 档位与上限

| 维度 | 我们 | 商业主流 |
|---|---|---|
| 档位 | 自动（4 档梯子）/ 流畅 / 均衡 / 清晰 / 超清 / 原生 / 高帧率 60 / 高帧率+ 120 | 通常 3~5 档 + 自动 |
| 帧率上限 | 1080p120（单屏零拷贝·能力门控）；普通档拖动提帧 | Moonlight 4K120；Parsec 60-120；ToDesk 宣称 360（营销） |
| 分辨率上限 | uhd = 硬编**原生 4K**（20~30fps）；超清 = 2560（JPEG 路径） | Moonlight 4K120；RDP 4K |
| 能力门控 | fps120 三重门槛（单屏 + D3D11-aware 硬件 MFT + ≥100Hz），跑不到不卖 | 普遍虚标或无门控 | **领先** |

### F · 编码与码率

| 维度 | 我们 | 商业主流 |
|---|---|---|
| 编码器 | 硬件 H.264 High（NVENC/AMF/QSV，async MFT）+ JPEG 脏矩形兜底 | Moonlight/RustDesk/向日葵 H.265；RTX40+ AV1；AnyDesk DeskRT |
| 码率 | 宽度 × 帧率系数（1080p60≈13M、120≈21M、4K30≈22M）+ RTT/丢包 25-100% 缩放 | Moonlight 手动 1~100+ Mbps 滑条；普遍动态 |
| 用户可调 | ✗ 档位即一切 | Moonlight/Parsec 可调 |
| 弱网画质稳定 | 数据报 + 帧内 XOR FEC + corrupt→request_key 快速自愈（D1/D2 已修） | 游戏派参考帧编码不花屏 | **架构领先，已闭环** |

### G · 清晰度与色彩

| 维度 | 我们 | 商业主流 | 评价 |
|---|---|---|---|
| 文本清晰度 | 4:2:0 + JPEG 静态 q95 精修补偿 | Parsec 4:4:4 专档、AnyDesk DeskRT、RustDesk VP9 | 落后：文档/代码场景文字边缘发糊 |
| 静态优化 | 静止跳帧 + 300ms 后 q95 整帧回补（一次性、不计码控） | AnyDesk 同款思路 | **持平领先** |
| 色彩 | 编码矩阵 **BT.601**（CPU/GPU 两路一致）；未保证 VUI 标注 | 高清串流业界标准 **BT.709**；NVENC 默认假设 601 输入 | ⚠️ **疑似整体偏色**：未标注 VUI 的 HD 流，浏览器解码按 **709** 解释（Doom9/NVENC 论坛口径），601 编码 × 709 解释 = 红/绿偏移（发橙发灰）。**需双机实测确认**，确认后统一 709 |
| HDR / 10bit | ✗ | ToDesk 真彩/HDR；Moonlight 4K HDR | 落后（长线） |
| 渐进刷新 | GradualIntraRefresh 已探测设置（随驱动支持度） | 少见 | 持平偏上 |

### H · 自适应画质

| 维度 | 我们 | 商业主流 |
|---|---|---|
| 自动档 | 按链路（RTT/丢包/近帧字节）在 4 档梯子自动换档，防抖滞滞 | 普遍动态但黑盒 |
| 弱网策略 | 丢包 ≥2% 挡升档、≥5% 参与降档；码率 25-100%；自动降频兜底 | 普遍动态 |
| 抖动缓冲 | 自适应微缓冲 ≤60ms，空闲不污染（M3 已修） | 普遍固定缓冲 | **持平偏上** |

## 三、差距清单（只含操作流程与画质，按优先级）

| # | 差距 | 对比基准 | 影响 | 预估 |
|---|---|---|---|---|
| Q1 | **色彩口径核对与统一 709**：实测确认 601 编码 × 浏览器 709 解读的偏色；统一 CPU/GPU 两路 + VUI 标注 | 全员高清内容用 709 | 每一帧的颜色保真——「更高清晰」的前提 | 0.5-1 天 |
| Q2 | **无人值守密码模式**：被控端设固定/临时密码 → 主控端 ID+密码直连（与免确认白名单并存，密码只绕「确认弹窗」不绕配对加密） | 全员标配 | 不在场帮人排障的核心场景 | 2-3 天 |
| Q3 | **HEVC 实际串流**（探测已就位）：同码率清晰度 +30-50% | RustDesk/向日葵/Moonlight | 4K 清晰度的钥匙 | 2-3 天 |
| Q4 | **4K60 硬编**：uhd 档零拷贝化 + 60fps + 码率联动（≈33Mbps） | Moonlight 4K60 | 清晰度天花板 | 2-3 天 |
| Q5 | **码率用户可调**：档位内画质上限滑条（高级设置或每档 tip） | Moonlight/Parsec | 「清晰 vs 流畅」的自主权 | 0.5-1 天 |
| Q6 | **断线自动重连**：免确认设备断线自动重连 + 连接进度反馈 | 全员 | 弱网会话连续性 | 1 天 |
| Q7 | **多屏快捷轮换**：会话内快捷键/按钮循环显示器（数据层已有 monitor:N） | 全员标配 | 多屏高频操作 | 1 天 |
| Q8 | **文本清晰模式**：4:4:4 实验（HEVC 落地后评估）或文档场景自动提高 JPEG 精修频率 | Parsec/AnyDesk | 代码/文档场景体验 | 2 天 |
| Q9 | **首帧速度实测与优化**（向日葵 0.81s 基准；我们先测再立项） | 向日葵 | 「连得快」的第一印象 | 先实测 |
| Q10 | 远程改画质/编码的被控端可见提示（现只有日志） | 少数有 | 知情权补全 | 0.5 天 |

## 四、我们领先或独特的（操作流程与画质内）

1. **信任模型**：6 位数字现场比对防中间人 + 本地配对不上云——商业产品要么账号信任要么裸密码。
2. **被控端知情权**：范围变更即时通知、持续横幅、会话历史——同类产品几乎空白。
3. **状态透明度**：四段延迟 + 操作延迟 + 诚实门控——商业产品只给「连接良好」。
4. **弱网画质稳定**：QUIC 数据报 + FEC + 快速自愈闭环（本轮已修完）——领先 TCP 系一代。
5. **静态 q95 精修**（AnyDesk 式「越看越清晰」）+ 自动档防抖——持平偏上。
