## 2. 保存与平台边界

- 快捷保存的回执绑定原收集草稿 ID。提交回复丢失后，从编辑器重试保存会同步修正回执；后来新建的另一份草稿不会被旧收集重试保存。底层保存函数再检查预期 ID。
- 直接选图只写入选择时的原草稿；目标变化或部分失败转为独立待处理预览。队列清理失败不重复追加图片。
- 分类采用附加表，不改旧草稿表结构；旧 JSON 与无分类记录可读。分类删除时事务拒绝写入，保留草稿供用户修正。
- 原生接收文件只接受已完成接收任务，校验文件状态和长度，拒绝最终符号链接；使用 app cache 中受控副本交给 Android。导出取消不删除原文件，不申请全盘权限。
- 本机保存、电脑接受设置和电脑同步继续使用不同回执，不能相互替代。

## 6. 提交前审查补充

第二次自定义 `codex review` 检查未提交源码，确认快捷保存的原稿归属修复通过独立内存验证，发现一项 P2：远控“更多 → 画面”拖动返回时，Sheet 保持打开，但弹簧仍停在释放位置。220px 的偏移可令来源面板的操作不可见。

修复在 `useSheetDrag` 中统一处理：每次完成返回手势都触发一次状态协调；父级实际关闭时保留退出动画，父级仍保持打开时将位移回到 0。不依赖面板标题变化，设备管理等同标题子步骤也使用同一机制。横竖屏回归先复现失败（220px），修复后通过。另删除反馈组件的未使用布局参数绑定。
