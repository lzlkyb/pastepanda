### 2.5 录屏后端（`rec/timeline.rs` 新增、`trim.rs` +275、`session.rs` 636 行改动）— 逻辑严谨
- `timeline.rs`：墙钟轴设计有实测依据（MF 把样本间隙写进前一样本的 stts duration），5 组测试覆盖静止跟钟、不补帧、10 分钟空洞不追帧、tail_hold 收尾、时间戳单调。`slot/stamp/duration_ms` 无溢出（10h × 30fps ≈ 1e9 远小于 i64）。
- `trim.rs`：关键帧**向前**吸附（`find(|pb| *pb <= in_ms).or_else(first)`），音频轨按视频实际入点 `eff_in` 同点切开（防音画漂移）；`end` 取第一个 `media_time >= end_ts` 的样本并排除（区间半开正确）；样本读不满即 `Err`，不静默截断；取消后走 `PendingOutput` 的 Drop 清理临时文件，不 commit；`off > u32::MAX` 前置拦截 4GB。MP4 解析有 box 数上限、样本越界、`checked_add`、溢出 `try_fold` 等一层层边界。
- `session.rs`：时间口径收口到纯函数 `session_clock::elapsed_ms`。核对无双重扣减——`paused_total_ms` 只累计**已完成**暂停段（resume 时 `+= t.elapsed()` 后清 `paused_since`），当前暂停段单独减；`begin()` 在真正开录（`axis_t0`）时校准起点，编码器准备时间不计入。

### 2.6 rc 链路调度（`link_sched.rs` 新增 479 行）— 状态机自洽
- epoch fencing：`attach` 永远 `Applied` 并 `session+1`（重挂覆盖崩溃残留），旧世代事件一律 `RejectedEpoch`——防「迟到的探测结果写回已销毁会话」。
- `Degraded` 无自动退出是**刻意分工**：收口权在 `link.rs` 的看门狗（`peer_bg_watchdog` / `LINK_STALE_KICK_MS`），状态机只消费 `EvidenceLost`；`RECOVER_HOLD_MS = 10s` 远小于 relay 宽限 30s+。
- `poll()` 用查询式升 Stable（时间推进不是事件），`phase_age_ms` 有回拨防护（`.max(0)`）。

### 2.9 补充审查（22:20 追加：上一轮标为「未逐行读」的三个大块头）
- **Card 拆壳层叠（判据 11）— 查过但排除**。`.cardWrap` 每行都是 `position:relative; z-index:1`，popover 的 `z-index:100` 只在行内有效，`flipDown`（`top < 360` 时向下弹）会盖到下一行——而下一行 DOM 在后、同为 z-index:1，本应反过来盖住 popover。实测已有正确处理：`useCardHover.ts:33-38` 在 `hovered` 期间把 `cardRef.parentElement.parentElement`（即 `CardList.tsx:652` 的 absolute 行容器）`style.zIndex` 提到 **50**，其他行仍是 auto ⇒ popover 必然在最上；hovered 结束即恢复。层级推导：`.card` → `.cardWrap(z1)` → 行容器(absolute, z auto)，提升的正是需要提升的那一层。
- **RecPreview 裁剪 UI 与后端吸附一致性 — 一致**。前端 `trimSnap.ts:snapTrimRange` 与后端 `trim_types.rs:snap` 规则等价：入点取「最大 ≤ in 的关键帧」、出点取「最小 ≥ out 的关键帧」、越界钳 duration、`out = max(out, in)`；无关键帧时两边都原值返回。差异仅在前端用显式循环（不依赖数组升序）、后端用 `rev().find()`（依赖 `scan_keyframes` 按样本序产生升序，成立）。`KeyframeIndex.fps` 取样本时长**中位数**而非平均（静止期 MF 会把空隙写进前一样本 duration，均值必被拉低）——正确。
- **`mobile_article.rs` URL 归一化 — 无问题**。`article_url_key` 只收 http/https、拒绝带 username/password、限长 2048、去 fragment、query 按 (k,v) 排序后重建（`extend_pairs` 保持键值对应），用于同一文章的存储去重键。query 排序改变顺序语义的假设极端罕见（签名 URL），对「文章链接」场景可接受。该函数只做去重键、不负责抓取，无 SSRF 面。

## 三、发现的问题

### P2-1 `link_sched.rs:198` 注释与实现相悖（低危，文档缺陷）— **已修**
注释写「事件里带来的 path 值**只在 Detached 时精确对账**」，但 `detach()` 用的是 `same_lineage()`（只比 `network` + `session`，**不比 path**）；同文件测试 `test_路径变化递增path世代…` 的注释也写成「新 path 语境内 detach 仍需同 network+session」。
- 行为本身合理：会话边界（network+session）才是权威，path 允许滞后；测试钉住的正是这个语义。
- **处置（2026-10-19 22:20）**：注释改为「事件里带来的 path 值一律不参与比较——所有事件（含 Detached）都允许 path 位滞后」，并补一句说明为什么 Detached 也放宽（迟到的 detach 若被 path 拒掉，会把已换路的会话漏成 Unbound）。改后 `cargo clippy --lib -- -D warnings` EXIT=0。

### P2-2 `rec/trim.rs` 1398 行，超 `.rs ≤ 600` 红线（存量恶化）— **已修**
v7.2.11 时约 1191 行（已超），本批 +275 → 1398。
- **处置（2026-10-19 22:50）**：按解析/重写边界拆成四个子模块，全部落回红线内——`trim.rs` 166 行（对外接口 + 源文件模型）、`trim/boxes.rs` 75 行（字节级盒子工具）、`trim/parse.rs` 349 行（顶层盒子定位 + trak 表展开 + 安全上限）、`trim/rewrite.rs` 395 行（mdat 重写 + moov 四表重建）、`trim/tests.rs` 453 行（夹具往返）。
- 纯位移无行为改动：21 条 trim 单测全过、`cargo test --lib` 2463 全过、`cargo clippy --lib -- -D warnings` EXIT=0。

### 待确认的设计取舍（非缺陷）
**预览里填的表单值不随导出**：导出路径 `renderMarkdownForExport(input.text)` 从源码重渲染，不采集 DOM 当前值 → 用户在预览填完点导出，得到的是空白模板（填写内容靠导出页内的 localStorage 自动保存）。
- 代码注释明确这是刻意（「业务人员拿到一份已经填好的表单」）。
- 但若用户预期是「导出我填好的那一份」，这里会有落差。发版前值得跟产品确认一次预期。
