# 首批 8 条视频偏白与 UI 一致性排查

日期：2026-10-13。范围：`videos/pastepanda-shorts/out/` 的 S01–S08。本次定位问题，没有修改软件样式、配音或覆盖视频。

## 结论

现有证据指向视频构图与演示宿主造成的整体观感偏白，而不是 MP4 编码把软件画面大幅提亮。真实组件确实被引用，但“真实组件”不等于“整幅画面就是软件实际页面”；之前验收没有覆盖这个区别。

本机软件保存的主题为 `ocean`，当前源码将其定义为「月白」浅色主题。因此，不能把此次问题直接判为“误用了浅色主题”，也不能用切到深海来冒充还原软件。

## 已确认的问题

### 1. 浅色宣传外框占据一半以上画面

`src/film.css` 的 `.film` 使用独立宣传背景，`.window` 使用白色卡片背景。`src/theme.css` 标记为 `Palette: light`，`--card: #fff`，背景为浅蓝灰渐变。

竖屏成片为 1080×1920，源码图显示区域为 880×1120，占整幅画面的 **47.53%**。剩余 **52.47%** 在源码图之外，由宣传背景、标题、窗口标题栏、字幕及页脚等构成。这个比例是矩形几何占比，不是纯白像素占比。

把软件的浅色变量铺到更大的宣传画布上，又以少量演示数据呈现功能，会增加浅色空白的视觉面积。即使核心控件颜色正确，整体也会比实际使用中的软件页面显得更白、更空。

### 2. 白色效果面板属于新写的示意 UI

`source/AuxEffect.tsx` 和 `source/source.css` 的 `.aux-effect` 在 S01、S02、S03、S07 的部分时段添加效果示意。面板背景为 `var(--card-bg)`；月白下该变量是 `#fff`。

这些示意面板用来表达复制后的用途，属于视频工程编写的辅助画面，不是软件已有页面。即使有“效果示意”标签，它们仍会增大白色区域，并让观众误以为软件内有这样的面板。对用户要求的真实源码 UI 宣传片，这部分应重新处理。

### 3. 演示宿主复用了组件，但没有完整保留软件页面结构

`source/SourceApp.tsx` 手工组装 TopBar、Card、ToolboxView 和弹窗；没有挂载真实 `App`。侧栏被固定收起，记录页没有真实 App 中的建议栏，卡片列表也由视频宿主直接排列。

宿主还固定 `theme: 'ocean'`，`source.html` 固定 `data-theme="ocean"`，笔记预览固定 `isDark={false}`。当前本机保存的主题恰好一致，但主题改变后视频不会跟随。

真实 App 挂载 `SkinScene`，视频宿主没有挂载。**月白主题的 SkinScene 返回 null，因此这不是当前月白偏白的原因**；若以后展示深海、午夜等主题，遗漏场景层会造成实际视觉差异。

`source.css` 为兼容混入的截图窗口和灵动岛全局 CSS，还给 html、body、root 强制设置背景。不能将这个统一宿主当作所有真实窗口外观的等价实现。

## 验证及排除项

- 只读查询应用配置数据库的 `theme` 字段，结果为 `ocean`；没有读取或导出密钥、历史内容。
- 核对 `src/lib/theme.ts`：`ocean` 为月白，`dark: false`；`ocean-dark` 才是深海。
- 对 provenance 中列出的 19 个组件／样式文件重新计算 SHA256，均与捕获时一致，包括 `src/styles/theme.css`。没有证据表明这些已记录文件因软件更新而与本批快照漂移。这不等于验证了全部源码文件。
- 每条视频取 9 秒处第 270 帧，将编码前 JPEG 与解码后的 MP4 帧按 RGB 比较。各通道平均绝对误差在 **0.597–1.119／255** 范围；各通道整体平均值略有下降，没有出现整体提亮。该结果支持排除这 8 个样本中的编码洗白，未直接验证聊天播放器的显示色彩管理。
- 未发现源码图被统一套上增亮或洗白滤镜。转场淡化只在指定交接时段使用，不能解释整体持续偏白。

测量原始数据：`videos/pastepanda-shorts/out/qa/theme-diagnosis.json`。对应解码样本：同目录的 `theme-decoded-S01-270.png` 至 `theme-decoded-S08-270.png`。

## 为什么之前没有发现

原检查将缓存图与同一个视频源码宿主逐像素比较，可以证明冻结截图忠实于该宿主；它不能证明该宿主的结构和宣传外框忠实于真实软件页面。非空、闪烁、帧连续性、音画同步检查也不包含这一判据。

因此，此次应补的是软件页面与视频宿主的视觉一致性检查，而不是放宽质量门或调整全片亮度。

## 修正方向与验收点

1. 用同一组无隐私演示数据和同一主题，对照真实页面结构；窗口宿主兼容处理之外，不新增软件内的示意面板。
2. 将软件画面与宣传字幕区域明确区分，缩减浅色外框和无信息留白，通过镜头聚焦真实操作区域提升占比。
3. 统一视频主题输入、宿主 DOM 主题和笔记亮暗判定，记录实际选用的主题；不凭主题名称猜颜色。
4. 对截图窗、主窗口和灵动岛分别保留对应的背景与材质规则，避免跨窗口全局样式污染。
5. 首先验证一条短片的关键画面。验收应比较同主题、同数据、同窗口尺寸下的结构、背景、卡片和弹窗颜色，再进行整批渲染；继续保留原有防闪烁和声音连续性检查。

## 后续执行结果（2026-10-13）

用户确认修正方案后，已完成 8 条 UI 校正版：软件区域保留月白，外围文案区使用独立深色衬底，软件画面占比提升到 61.38%，自写效果面板已移除。真实 App 源码与 S01 宿主的关键控件对照通过，209 个状态图非空，14 个缓存检查点逐像素一致，4200 帧通过原有质量门。

8 条原中文配音／音乐的编码音频哈希保持一致；本地正常速度播放中途缓冲、解码错误和掉帧均为 0。详细范围与报告路径见《PastePanda短视频-首批8条-制作说明-2026-10-13.md》。成片使用独立的 `-UI校正版.mp4` 文件名，避免复用旧版媒体缓存。
