# PastePanda 测试体系搭建方案

> 参考 CC Switch（`farion1231/cc-switch`）的测试架构，结合 PastePanda 现有基础设施制定。

## 一、CC Switch vs PastePanda 对比

| 维度 | CC Switch | PastePanda（当前） |
|---|---|---|
| Rust 集成测试 | `src-tauri/tests/` 6 个文件，~50+ 用例 | **0**（仅 `content_classifier.rs` 有 11 个单元测试） |
| 前端 Hook/组件测试 | `tests/hooks/` + `tests/components/` | **3 个文件**（`appStore.test.ts` 7 用例，`utils.test.ts` 14 用例，`ErrorBoundary.test.tsx` 3 用例） |
| MSW IPC 模拟 | 完整 MSW 层（`tauriMocks.ts` + `handlers.ts` + `state.ts`） | **alias mock**（简单空函数） |
| 测试环境隔离 | Rust: `support.rs` 临时 HOME 目录；前端: `afterEach` 清理 | **无** |
| 覆盖率 | 高（CI 强制） | **无** |

**关键改动**：`DataStore::new()` 目前强制使用文件路径，需要新增 `new_in_memory()` 方法：

```rust
impl DataStore {
    pub fn new_in_memory() -> Result<Self, String> {
        let conn = Connection::open_in_memory().map_err(|e| e.to_string())?;
        // 复用现有建表逻辑
        let store = Self { conn: Mutex::new(conn), db_path: PathBuf::new() };
        store.init_tables()?;
        Ok(store)
    }
}
```

#### 3.3 核心改造 — `tauriMocks.ts`

参考 CC Switch，把现有的 alias mock 改为 MSW 方案：

```typescript
import { vi } from "vitest";
import { server } from "./server";

const TAURI_ENDPOINT = "http://tauri.local";

vi.mock("@tauri-apps/api/core", () => ({
  invoke: async (command: string, payload: Record<string, unknown> = {}) => {
    const response = await fetch(`${TAURI_ENDPOINT}/${command}`, {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify(payload ?? {}),
    });
    if (!response.ok) {
      const text = await response.text();
      throw new Error(text || `Invoke failed for ${command}`);
    }
    const text = await response.text();
    if (!text) return undefined;
    try { return JSON.parse(text); } catch { return text; }
  },
}));
```

## 四、CC Switch 可借鉴的核心模式

1. **`support.rs` 模式**：临时 HOME 目录 + 全局互斥锁 + `reset_test_fs()` — 确保测试隔离
2. **`tauriMocks.ts` 模式**：`invoke()` → `fetch()` 转换 — 让 MSW 能拦截所有 IPC 调用
3. **`afterEach` 清理模式**：`cleanup()` + `resetProviderState()` + `resetHandlers()` + `clearAllMocks()` — 每个测试完全独立
4. **内存状态管理**：`state.ts` 维护 providers/settings/sessions 的内存副本 — 模拟后端数据库
5. **`Connection::open_in_memory()`**：SQLite 内存数据库 — Rust 测试零副作用
