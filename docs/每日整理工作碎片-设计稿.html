每日整理工作碎片

把一整天散落的复制 / 粘贴碎片，自动聚合成一份可回顾、可沉淀的「今日简报」——行为级默认，授权后内容级准确。

0 · 调研参照：别人怎么做（2026-08-13 调研）

为让方案准确，调研了三类产品。核心发现：主流剪贴板管理器普遍不做日报/周报，只做记录+检索——PastePanda 做「日整理」是差异化蓝海；而「日报周报」做得最成熟的是时间追踪类与 AI 回顾类。

① 剪贴板管理器

CleanClip / Paste / Mac 系

能力集中在：自动记录、搜索、收藏列表（书签）、智能列表（按条件过滤）、粘贴栈、跟随当前 App。均无聚合日报/周报。CleanClip 仅有「无限收藏列表」让用户手动归类。

→ 竞品空白，本功能即差异化切入点。

② 时间追踪类

RescueTime / Rize / Dayflow

日报/周报结构最成熟：总时长+生产力分、按类别/应用/时段分解、最高效日、目标进度、每周邮件推送。Rize 可设追踪时段（非工作停追，护隐私）；Dayflow 时间轴卡片+环形图/热力图/周对比+导出 HTML 报告。

→ 直接借鉴「结构模板 + 邮件/推送 + 可视化」。

③ AI 回顾类

MineContext(字节) / SelfManager / Taskade

本地存储、主动交付：MineContext 自动生成日报+待办、周五推周报、关联相关聊天/资料，并可基于总结追问对话（"我这周时间分配合理吗？"）。SelfManager 走「review → 对话 → 下一步行动」闭环。Taskade 跨项目自动周状态。

→ 借鉴「本地优先 + 主动交付 + 可追问 + 关联待办」。

④ 周回顾方法论

Notion / Obsidian / Todoist

Notion 可组合周控制面板，AI 把长笔记总结成行动清单；"Friday Packet"范式：亮点 + 决策 + 未决项，tag 到项目。强调回顾要影响「下周三大要务」才有效。

→ 借鉴「回顾必须落到下一步行动」。

维度剪贴板管理器时间追踪AI 回顾PastePanda 取法

对本案的 5 条修正

① 差异化而非跟风：剪贴板赛道无人做整理，重点不是"再做个统计"，而是把碎片变成可行动的洞察。
② 不硬凑生产力分：没有窗口时长数据，日报聚焦内容类型占比/来源App/主题簇，不做 RescueTime 式"效率分"。
③ 加"关联待办/延伸"：参照 MineContext，日整理应能从碎片里提取待办、关联工作区，而非仅描述。
④ 加"可追问对话"：参照 SelfManager，简报不应是一次性总结，应支持"就今天这些，我下周该优先做什么？"类追问。
⑤ 推送而非仅被动：参照 Rize/RescueTime，用托盘定时推送主动交付，避免"功能有了没人看"。
⑥ 护隐私的时段开关：借鉴 Rize「可设追踪/整理时段」，非工作时段不纳入，呼应本地优先定位。

1 · 背景与问题

PastePanda 当前被动记录用户每天的工作碎片，但缺失「每日自动聚合整理」。

能力状态粒度是否读内容
剪贴板历史 / 工作区 / 片段库✅ 已落地单条碎片是（本地）
周报（E，行为统计）✅ 已落地 v6.4按周 · 行为级否（仅统计）
AI 单条总结（ai-summarize）✅ 已落地单条是（用户选中后读原文）
每日整理 / 日记 / 日报❌ 未落地按天 · 聚合需设计（默认不读，授权读原文）
💡 用户真实诉求：「我每天复制粘贴几十条东西，下班前能不能帮我自动理一遍今天都干了啥 / 攒了啥，而不是让我自己翻历史？」——且要求内容层面也要准。

2 · 目标 / 非目标

✅ 产品目标

  • 每天结束（或随时）一键看「今日工作碎片整理」
  • 自动归类当天复制 / 粘贴的主题
  • 提炼高频任务 / 项目 / 关键词
  • 生成口语化「今日小结」——行为级默认，授权后内容级准确
  • 支持沉淀进工作区 / 片段库，成为长期资产

❌ 非目标（明确不做）

  • 宠物养成 / 情感陪伴 / 聊天式对话（H 系列边界）
  • 跨设备云端内容同步（仅局域网加密同步）
  • 自动替用户执行动作——只整理、不行动（守红线③）

3 · 用户场景

职场白领

多源复制

一天在群 / 文档间复制需求、链接、表格 → 看「今天主处理 X 项目，含 8 链接、2 表格」，自动归类。

开发者

Debug 流

授权后生成「今天 debug 了 Y，涉及这些报错与关键代码，下周优先收尾 Z」，可一键存工作区。

研究者/学生

资料收集

复制论文、网页、引用 → 生成「今日收集」清单，按来源分组，方便写笔记。

所有人

周期回顾

想回顾「这周忙了啥」→ 日整理是周报的内容素材，二者打通。

4 · 功能定义

日整理 = 自动聚合当天（默认 00:00–now）全部工作碎片 + 生成一份结构化「今日简报」。一份简报包含两层：

行为层
(永远可用)
零内容出网，复用周报统计能力：今日复制 / 粘贴次数、按小时分布；内容类型占比（文本/图片/文件/链接）；来源 App TopN、高频时段、常用动作；自动聚类「主题标签」（基于来源+关键词本地提取，非 LLM）。
内容层
(授权读原文)
产品已决策内容层也要准，主路径为用户显式授权后读取原文（参照 MineContext / SelfManager）： 行为级小结（默认兜底，零原文）：仅喂元信息/摘要 → "复制 X 次、60% 来自 VS Code"； 内容级小结（授权后·语义准确）：点"用全文生成"或"深入总结这簇"后临时读该范围原文送 AI → 能说出"今天在对接支付接口、修了 Y bug、与 Z 对接需求"； 另含「行动建议 / 关联待办 / 可追问对话」，让简报落到下一步行动。

触发方式

⏰ 定时

默认每天 20:00 托盘弹「今日整理好了」提示（可关）。

🖱 手动 / 随启

顶栏「工具箱」→「今日整理」；热键 Ctrl+Shift+D；启动发现昨天没整理则补「昨日简报」。

隐私红线（硬约束 · 2026-08-14 已调整）

守红线②（redlineGuard 测试覆盖），明确"内容级准确"边界：行为层绝不读原文；内容层默认不读，仅用户显式授权后才读指定范围原文，且须明示同意 + 仅本次发送不留存 + 总开关默认关 + 审计日志；未授权自动降级行为级。红线②从"绝不读"修正为"默认不读、授权才读、全程可审计"。

8 · 验收标准

  • 当天复制内容在「今日整理」里能聚合成可阅读简报
  • 行为层统计不读取任何原文，通过 redlineGuard 类隐私测试
  • 内容级小结在授权后能产出语义级准确总结（含具体项目/任务名，非仅行为描述）
  • 每次读原文前明示授权弹窗+用户确认，原文仅本次发送、不留存
  • 设置内含"允许读原文"总开关（默认关）+ 审计日志记录每次读取
  • 用户未授权时自动降级行为级小结，功能不中断
  • 主题簇可一键存入工作区 / 片段库
  • 日整理结果可被周报、年度报告复用
  • 定时 / 手动 / 随启补报 三种入口均可用
  • 冷启动（当天 < N 条）提示「再攒攒」，不硬出空报告

9 · 风险与开放问题

① 授权合规与隐私（已决策走 B）：产品要求内容级准确 → 采用"按需授权读原文"。落地须保证：① 每次读取前明示发送范围与去向+用户勾选同意；② 原文仅本次发送、不留存、不进同步流；③ "允许读原文"总开关（默认关）+ 审计日志可查；④ 不同 AI 提供商数据出境合规（尤其境外模型）；⑤ 未授权自动降级行为级，功能不中断。红线②修正为"默认不读、授权才读、全程可审计"。
② 聚类质量：纯本地关键词聚类可能不准，是否上轻量本地小模型？先规则版，AI 增强后置。
③ 通知疲劳：定时提醒可能烦，默认关 / 仅首次引导开启。
④ 与周报重叠：统计高度重合，需抽公共统计层，避免两套实现。
⑤ 存储膨胀：日整理长期留存需清理策略（保留 90 天 / 仅留统计）。

10 · 变通方案（上线前可用）

功能落地前，用户可用现有能力手动凑出类似效果：

  1. 一天相关碎片复制进同一工作区；
  2. 工作区内 Ctrl+A 全选 → 变换面板用 ai-summarize 汇总成一段（即现有"选中即读原文"的内容级模式）；
  3. 或导出工作区，丢给任意 AI 写「今日日报」。

⚠️ 现有 ai-summarize 已是"用户选中内容 → 读原文 → 总结"的内容级能力，已证明可行；日整理只是把它从"手动选"升级为"自动聚类 + 一键授权读"，复用同一授权信任模型。
