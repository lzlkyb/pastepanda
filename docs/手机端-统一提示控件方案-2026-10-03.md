# 手机端统一提示控件方案

设计稿经确认后已接入手机应用。`src-mobile/ui/MobileNotice.tsx` 是统一视觉核心，`MobileToast.tsx` 负责轻提示计时；设计预览中的设备、文件、错误和恢复结果仍为示例。

## 参考与选择

- [Tencent WeUI 官方 Toast 示例](https://github.com/Tencent/weui/blob/master/src/example/toast/toast.html)：同一组件体系覆盖成功、失败、文字和加载。
- [Ant Design Mobile 官方组件入口](https://github.com/ant-design/ant-design-mobile/blob/master/src/index.ts)：Toast、NoticeBar、ErrorBlock、Dialog、Result 分别承担不同反馈形式。借鉴一致的组件体系，保留按场景选择展示形式。
- [Android Snackbar](https://developer.android.com/develop/ui/compose/components/snackbar)：轻提示可带动作，持续时间可以调整。
- [Apple Alerts](https://developer.apple.com/design/human-interface-guidelines/alerts)：弹窗只用于重要且可行动的内容；一般连接状态可以在界面内说明。
- [Atlassian 错误文案](https://atlassian.design/foundations/content/designing-messages/error-messages)：明确结果、提供下一步，不猜测原因，不把技术信息作为主要文案。

采用统一视觉核心，展示形式和生命周期按场景配置。沿用现有手机页面、底部导航、工具栏和 MobileSheet。

## 统一控件

在 `src-mobile/ui/` 实施统一提示组件及 CSS Module，升级或兼容现有 MobileNotice，避免产生两套长期并行的样式。

控件输入：状态、标题、可选说明、可选主要动作、可选技术详情、可选关闭动作。状态是 info / success / warning / error / pending；展示形式是 inline / banner / toast。

展示位置由页面容器负责，组件不猜测网络、权限或文件系统问题，也不直接调用业务命令。业务操作决定是否重试、是否取消和何时更新结果。

| 场景 | 展示 | 生命周期 |
|---|---|---|
| 输入验证失败 | 输入附近的紧凑提示 | 输入修正或新验证结果替换 |
| 连接、剪贴板、文件操作失败 | 当前卡片或面板内 | 重试成功或主动关闭前保留 |
| 文件部分成功 | warning 汇总 + 失败文件记录 | 保留数量、文件名和恢复入口 |
| 持续连接问题 | 独立占位的 banner | 实际状态恢复或用户离开后清除 |
| 普通完成结果 | toast | 默认短暂显示，聚焦时暂停计时 |
| 处理中 | 同位置的 pending | 操作完成或取消后替换 |
| 无法继续的重大阻断 | 复用现有模态容器 | 明确处理动作，保留安全退出 |

一个动作产生一条主反馈。弹层正在显示自己的错误时，底层不再重复显示同一错误；关闭弹层后，仍需处理的状态可以转到页面。关闭提示不代表任务已成功或连接已恢复。

轻提示一次显示一条，同一事件去重；重要错误不能被成功消息替换。手机键盘、导航、安全区和横屏工具栏均需留出位置。远程会话中的持续状态独立占位，不遮住视频。

技术错误统一转换为标题和说明。保留已有权限分类的真实判断；未知原因只说明失败和可用下一步。可展示的技术详情需去除凭据、临时码和敏感路径，不直接暴露整个异常对象。

## 实施与验收

1. 创建统一控件和轻提示宿主；兼容现有 MobileNotice，让使用它的设备、设置与文件页面先共用同一视觉。
2. 收口剩余独立提示：配对提示、会话工具提示、文字提交错误、文件任务错误等。操作中的反馈优先跟随触发区域。
3. 修复剪贴板原始错误泄漏、四秒清除失败、提示优先级覆盖与连接错误重复展示。批量文件保留部分成功信息；不能可靠重用文件时提供重新选择入口。
4. 补控件与恢复行为测试：状态语义、关闭不改变结果、异步重试去重、失败不自动消失、成功提示计时、详情展开、错误文案兜底。
5. 浏览器验证浅色 ocean / 深色 midnight、窄屏、横屏、键盘展开与弹层打开。检查按钮可达、反馈可见、无横向溢出、视频不重叠。

预览代码里的共享核心位于 `design/MobileFeedback.preview.tsx`，应用实例位于 `design/mobile-error-feedback-2026-10-03.tsx`。预览使用独立构建，不改手机或桌面 dev。

## 当前实现

- 原有 MobileNotice 调用保持兼容，新入口可指定标题、说明、状态、动作、关闭与详情。设备、配对、扫码、无人值守、文件、历史和会话均使用这个组件。
- 剪贴板操作期间保留面板，错误持续显示；重试沿用原方向，并发点击被阻止。关掉面板后仍可从会话提示返回。
- 普通完成结果可短暂展示，聚焦、悬停和后台暂停剩余计时。错误、提醒、处理中均不自动清除。
- 会话提示和文件请求在画面外占位；横屏单独预留提示行，画面按剩余空间布局。
- 页面与设备／历史面板交接错误展示责任；同一后台故障合并显示，保留各操作的恢复入口。
- 文件、连接和更新的后台提示共用一个布局容器；长内容可滚动，避免浮层彼此重叠或覆盖导航。
- 文件部分失败显示已提交与未完成数量，并提供重新选择文件入口；「已提交」不代表电脑已接收。
- 未知技术错误使用通用中文说明，可信的中文业务提示与已有权限分类保留；原始异常不直接传到主提示。
