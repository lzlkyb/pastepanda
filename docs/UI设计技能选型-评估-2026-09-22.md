# UI 设计技能选型 · 评估

> 2026-09-22 · 起因：`npx skills add https://github.com/Leonxlnx/taste-skill`（一键装全部 13 个技能）
> 实测口径：GitHub API 取 star/fork/license/pushed（2026-09-22）；安装量取 skills.sh 榜单快照（2026-09-19，第三方统计，非官方）。

## 0 · 结论

1. **taste-skill 不是本项目该装的。** 不是质量差，是**场景不匹配**：它的 SKILL.md 第一句就自报「不覆盖仪表盘 / 数据表格 / 产品 UI」，而 PastePanda 全是这类界面。
2. **同类里最好的通用款是 `impeccable`（pbakaus），但它也不该是本项目的第一优先。** 它唯一比 taste-skill 强的地方是明确区分了 Persuade（营销页）与 **Operate（应用 UI / 仪表盘 / 编辑器 / 设置）**，正好对上本项目。它已上架 WorkBuddy 推荐市场，不用 `npx skills add`。
3. **本项目真正的缺口不是「缺一个审美技能」，是 `docs/PastePanda-UI规则.md` 没被接进「每次改 UI 都必读」的执行链。** 那份 551 行文档（U1–U8 / L1–L6 / V1–V6）比任何通用技能都更贴合本仓库，因为它带实测基线。再装第三个通用设计技能只会和已装的两个抢同一个触发。

---

## 1 · 为什么不匹配（三条硬证据）

### 1.1 它自己划的边界就把本项目排除了

`skills/taste-skill/SKILL.md` 第 8 行，原文：

> Landing pages, portfolios, and redesigns. **Not dashboards, not data tables, not multi-step product UI.**

PastePanda 的界面：主窗列表、远程电脑工作台（设备列表 + 会话记录 + 权限项）、全屏编辑器、快捷面板。全是「product UI + 数据列表」。**命中的正是它排除的那一类。**

它的 §0.A 还要求先做 "Design Read"（落地页 / 作品集 / 编辑型内容），本项目三个窗口都不落在这三类里。

### 1.2 默认技术栈与本项目三处冲突

| taste-skill 默认（§3.A） | 本项目实际 |
|---|---|
| Tailwind v4 | **CSS Modules**，无 `tailwind.config.*` |
| Next.js + RSC（`'use client'` 边界规则） | Tauri 2 + Vite，多 HTML 入口，无 Next |
| Motion / GSAP 动效骨架（§5 sticky-stack、horizontal-pan） | 自有动效规则：**只用四档时长 + 两条曲线**（UI 规则 U2） |

装了之后它的规则会持续与本项目既有约束打架，而且是它赢不了的那种打架——UI 规则 U2 是硬阈值，动效骨架是「建议模式」。

### 1.3 新装的 v2 是实验版且体量失控

| 文件 | 行数 | 字符 |
|---|---|---|
| `skills/taste-skill/`（v2，默认装这个） | **1206** | 87,253 |
| `skills/taste-skill-v1/`（逃生舱） | 226 | 21,195 |

1206 行、87KB 的单文件指令，一次性灌进上下文≈2 万 token 起。而这个文件的主体（§9 AI Tells 后半、§9.F、§9.G）是**营销页文案纪律**：禁用 em-dash、禁止 locale/天气条、禁止 "Quietly in use at" 式社会证明头、禁止图片上的标签 pill、禁止 hero 版本号水印……

PastePanda 没有落地页，这些规则**一条都用不上**。真正能用的只有 §4.1 排版、§4.2 配色校准、§6 性能与可及性——这三块恰好是你已装的 `ui-ux-pro-max` 覆盖得更细的部分。

> 补充：`npx skills add <repo>` 不带 `--skill` 会装**全部 13 个**，其中包含 `output-skill`（强制模型不许输出占位、必须全量输出）和 3 个 imagegen 技能。`output-skill` 会与本项目「体量红线 + 先出方案再动手」的纪律直接对着干。

## 2 · 候选对比（同类里谁更好）

| 技能 | ★ (09-22) | 安装量 (09-19 快照) | License | 定位 | 有 Operate/产品 UI 模式 | 需要跑脚本 |
|---|---|---|---|---|---|---|
| **`impeccable`** (pbakaus) | 69,777 | 未入前 10 | Apache-2.0 | 从 Anthropic frontend-design 出发，做深 | ✅ 明确 | ✅ 启动器 + 首次下载二进制 |
| `frontend-design` (anthropics/skills) | 177,581（仓库级） | **862k**（第 1） | 仓库未声明 | 通用基线，克制 | ✖（不区分场景） | ✖ 纯指令 |
| `design-taste-frontend` (taste-skill v2) | **89,200**（仓库级） | 451k（第 4） | MIT | 营销页 / 作品集 / 重设计 | ✖ **明确排除** | ✖（仓库 scripts/ 只有两个 README 配图脚本） |
| `ui-ux-pro-max` (nextlevelbuilder) | 129,744 | 347k（第 5） | MIT | 可检索知识库 | 部分（含 desktop 栈） | ✖ 纯指令 + CSV 数据 |
| `web-design-guidelines` (vercel-labs) | 31,454（仓库级） | 613k（第 3） | 仓库未声明 | 质量门禁，非生成器 | ✖ | ✖ 纯指令 |

**读法**：star 数在同一仓库内是「整个集合」的分，不能直接横比；安装量是同一个 CLI 统计出来的，可比性更好。结论：`impeccable` 是同类里口碑最集中的单仓库款，`taste-skill` 是热款之一但不是榜首。

### impeccable 为什么更强（如果你要装通用款）

它的 `skill/reference/craft-floor.md` 全是可以**验收**的判据，不是形容词：

- Contrast：正文 ≥4.5:1，大字号 ≥3:1；**彩色底上的次要文字用同色相，不许用灰**
- Depth：阴影必须带偏移和柔化；零偏移彩色光晕算装饰
- Spacing：读 computed 值，标题上方间距必须大于下方
- Type：正文 65–75ch，display ≤6rem，tracking 下限 −0.04em
- States：hover / disabled / loading / error / empty 五项 + 真实内容 + 键盘焦点
- **Browser surfaces**：文本选中色、光标、滚动条、focus ring、下划线偏移、表格数字——「没画的部分也要承载设计」，原文点名这是模型最常跳过的一项

而且它有明确的 **Operate 模式**定义：

> App UI, dashboards, editors, admin, settings, tools. Scanability, consistency, native expectations, and the real usage scene outrank expression.

**代价**：上游 v4.3.1 要跑 `<skill>/scripts/impeccable context`，启动器会在首次运行下载一个自包含二进制到 `~/.impeccable/bin/`，并且会往编辑器（Claude Code / Cursor / Codex / Copilot / Grok）写 hook 清单。WorkBuddy 走推荐市场那份（`impeccable` v2.0.0）可以规避这些，但那份是二次打包，**装之前要核一遍里面的 SKILL.md 到底是不是同一套**（版本号 2.0.0 vs 上游 4.3.1，对不上）。

## 3 · 为什么我建议先不装

### 3.1 已装的两个已经把「通用审美」这块重叠了

`~/.workbuddy/skills/` 里已有：

- `ui-ux-pro-max` —— 3.6MB、73 个文件，含 79 种风格 / 192 套行业配色与推理档案 / 74 组字体配对 / 119 条 UX 规则 / 17 组 GSAP 预设 / 25 类图表 / 22 个技术栈（含 `react.csv`、`react-native.csv`、`html-tailwind.csv`）。**这是通用款里数据量最大的一份，已在手。**
- `frontend-design` —— Anthropic 官方，862k 安装量，全行业基线。已在手。

再装 `taste-skill` 就是**第三个**同类技能。三者 description 覆盖的场景高度重叠，实际后果是触发权被稀释、`SKILL.md` 常驻上下文互相挤压，而本项目要解决的问题一个都不会因此变好。

### 3.2 本项目有自己的、更严的规则文档

`docs/PastePanda-UI规则.md`（551 行）不是那种「写得很漂亮但没人执行」的规范，它带 **2026-09-09 全库实测基线**：

| 项 | 实测 | 结论 |
|---|---|---|
| `1px solid` | 803 处 | 层级几乎全靠画线 |
| `box-shadow` | 283 个声明 / **191 种取值** | 没有高度尺度 |
| 硬编码 hex | **1953 处 / 395 种颜色** | 没有设计系统 |

三组规则的分工很清楚：**U 管好不好用（U1 反馈阈值 / U2 动效四档 / U3 状态四件套 / U5 尺度表 / U7 WCAG AA / U8 禁内联 style），L 管看不看得懂（L1–L6），V 管像不像专业做的（V1 留白优先于边框 / V2 阴影三档 / V3 颜色只许来自变量 / V4 圆角同心 / V5 先灰阶后上色 / V6 彩色底不用灰）。**

有意思的是 **V6 与 impeccable 的 craft-floor 重合**（"On colored surfaces tint secondary text from that hue; never gray"），**V4 同心圆角**和 **V2 阴影只表达高度**也对得上它的 Depth/Radius 判据。也就是说：**通用技能里最有价值的那几条，本仓库文档已经写得更具体了（带数字、带判定条件）。**

### 3.3 真正的缺口在别处

`AGENTS.md:246` 已经写了「改 UI 前读它，改完对它的自查清单」。但那是**文档指针，不是执行链**——今天上午审远程电脑工作台时，实际的偏离（11px 灰字用在说明文字上而非 meta、`--section-bg` 与 `--app-bg` 差值过小导致材质分层失效、`--card-selected-bg/shadow` 定义了却没用）**都不是「不知道规则」，是「改的时候没对着规则查」**。

这一层任何现成技能都补不上，因为它需要知道本仓库的 token 名和体量红线。

## 4 · 如果要装，怎么做

### 4.1 优先级建议

| 优先级 | 动作 | 理由 |
|---|---|---|
| P0 | 不装新技能；把 UI 规则接成「改 UI 必读」的执行链 | 零新增依赖，直接命中今天的实际偏离 |
| P1 | 装 `impeccable`（走 WorkBuddy 推荐市场） | 同类里唯一有 Operate 模式的；先核 SKILL.md 与上游是否同源 |
| P2 | 装 `web-design-guidelines`（vercel-labs） | 只做质量门禁（100 条 a11y/UX/性能），与生成类技能不冲突，适合当交付前的那道检 |
| ✖ | `taste-skill`（含 `npx skills add` 一键全装） | 场景排除 + 栈冲突 + 与已装重叠 + `output-skill` 副作用 |

### 4.2 `npx skills add` 的坑（写清楚，别踩）

- CLI 本身是 **Vercel Labs 开源**（实测 `vercel-labs/skills`：★32,229、MIT、pushed 2026-09-18，仓库描述 "The open agent skills tool - npx skills"），目录在 skills.sh，有安全审计流程。**工具可信，不代表每个技能可信。**
- 补一句可核性说明：`registry.npmjs.org` 在本机走不通（代理 127.0.0.1:26561 不稳，实测 HTTP 000），所以 CLI 的 npm 包元数据**没能直接核**，上一条结论来自 GitHub API 核实上游仓库 + skills.sh 官方文档，可信度足够。
- 它会往**它自己检测到的 agent 目录**写文件。本项目里 `ls -d .claude .cursor .codex .agents` **全部不存在**，WorkBuddy 的技能库在 `~/.workbuddy/skills/`。所以这条命令很可能写进 `~/.claude/skills/`（或装不上），**不会**进 WorkBuddy 的技能库 —— 装完在你当前会话里根本不生效。
- 默认带匿名遥测；要关设 `DISABLE_TELEMETRY=1`。
- 正确姿势二选一：① 走 WorkBuddy 推荐市场；② 手动把 `skills/<名字>/` 整个目录复制到 `~/.workbuddy/skills/<名字>/`（`impeccable` 那种带 `reference/` 的必须整目录复制，只拷 SKILL.md 会得到一份没有内容的目录）。

### 4.3 taste-skill 仓库本身的安全性（已查）

结论：**仓库里没有恶意内容**，但这不是推荐装它的理由。

- `scripts/` 下只有两个 `.mjs`：`convert-readme-assets-webp.mjs`、`process-readme-buttons.mjs`，都是作者用来处理 README 配图的本地脚本（依赖 `sharp`，其中一个还硬编码了作者自己的 `C:/Users/User/Downloads`）。**不参与技能运行，不是 postinstall 钩子。**
- 12 个技能全部是纯 `SKILL.md` 指令 + `stitch-skill/DESIGN.md`，无可执行载荷。
