# PastePanda 行业顶尖差距与规划（2026-09-05）

> 用途：回答「结合软件自身，做到行业顶尖还差什么」——按四根柱逐一对标，给出依赖序主线与拍板清单。
> 性质：**规划文档，不含代码**。所有差距均标注出处；本文不新增任何未经核实的事实。
> 数据来源：《PastePanda-AI架构与路线图》§2/§3、《知识库-总排期》、《个人知识库与笔记-规划》§12、《知识库同步-M6设计稿》§4/§10/§11、`kb-market-fit.md`、项目工作记忆（截图/结构治理条目）。

---

## 0. 一句话结论

**规划文档覆盖度已经很高，真正缺的不是「新功能规划」，而是三件结构性的东西**：
① 学习体系没有数据（AI 柱全链空转）；② 两处架构代差（截图硬限制 / 知识库块级模型——后者已裁决不追）；
③ 「每日整理工作碎片」这张独一无二的王牌，规划成熟但**零开工**。

补齐路径不是全面对标，而是把
**采集（剪贴板+截图+OCR）→ 沉淀（知识库+每日整理）→ 激活（检索+问答+Agent）**
这条竞品矩阵里不存在的完整链路，做到每一环都好用。

## 1. 「顶尖」的定义与战场选择

| 赛道 | 对标 | 我们的姿态 |
|---|---|---|
| 剪贴板管理 | Ditto / CopyQ / Paste (Mac) | 正面战场，AI 变换与 OCR 是超出对标的能力 |
| 截图标注 | Snipaste / PixPin / CleanShot X | 正面战场，OCR 管线已是差异化 |
| 个人知识库 | Obsidian / Notion | **错位战场**：不做生态/协作/移动端，打「本地优先 + 无服务器同步 + 采集原生」 |
| AI 执行 | NotebookLM / Notion AI / Mem | 错位战场：`ai_enabled` 门控 + 本地推理优先，隐私即卖点 |

**明确不追的（已裁决，防跑偏）**：插件市场（用 MCP 代替）、知识图谱（真实数据否决：1165 张卡片仅 1 个标签）、iOS/移动端（M6 §12）、块级模型、模型写代码执行（红线③）、DeepSeek Harness 打包进 app。

## 3. 三件结构性的事（比任何单项功能都重要）

1. **数据闭环没转起来**（G1）：AI 柱的一切个性化能力（推荐/风格/编排）共享同一个死因——`action_events` 没有数据。破锁是四因子、A/B、S1、评测集第一次「有意义」的总开关。
2. **架构代差两处**：截图端 G6a/G6b 是必修硬限制；知识库块级模型是**已裁决不追**的代差——用「采集原生 + 节级命中（AM-2 已做）」对冲，不再投入。
3. **王牌没出鞘**（G14）：每日整理是采集端（已近顶尖）与激活端（规划齐）之间唯一的断点，也是竞品矩阵里找不到对标的落点。

## 4. 规划主线（依赖序，非时间表）

```
第一优先  破锁验证（G1）         ← 重跑 action_events 计数，三岔口拍板
第二优先  每日整理工作碎片开工（G14） ← 规划/设计稿已成熟，纯执行
第三优先  M6 实连验收（G11）+ AM-5 标注（G10）
            → 解锁第 4 波：O-4 切片定案 → 向量层真跑探针 → 本地 embedding
第四优先  事件聚合开工（G3）      ← ②环境智能与③动态编排的共同前提
并行小额  Tier3 吸附（G5）、混合 DPI/长截图修复（G6）、
          mock 服务商 + 模型路由 + 结构化输出（G16）、Overlay 治理（G8）
堵点拍板  动态编排确认策略（G15）→ 拍板后才做 G16 的回归基建
后置待拍  N1–N8 知识库补录（D-7）→ 纳入后再插进本主线
贯穿约束  A1–A5（§2.6）不是排期项：对应功能开工/验收时必须执行
```

**顺序的依据**：G1/G14/G11 三件事互不依赖、可并行，且分别是「AI 柱去留」「差异化」「知识库大件」的闸门；G3 在破锁与每日整理之后收益才兑现；G15 是纯决策，先拍板再投入；N 系列未排期，等 D-7 拍板（其中 N1 建议随 M6 收尾同批考虑——附件打包是同步的天然依赖，N5 的预算挂在 O-4 上，N8 随 N3/N4 同批做最省）。A 系列不是排期项：A1 挂在 C 阶段验收、A2 挂在 M3-① 开工、A4/A5 挂在每日整理与 B2 #7 开工。
