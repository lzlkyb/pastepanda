# PastePanda 个人知识库与笔记 · 整体规划

> 版本：v1（2026-08-22）
> 状态：方案规划 · 待用户确认后按 A 阶段开工
> 路线：**A（收藏→笔记，最小闭环）→ B（独立知识库，主体验）→ C（知识库 RAG 智能体，AI 增强）**

---

## 1. 背景与目标

PastePanda 定位是"content in/out hub" AI Agent：内容进来（剪贴板采集、截图、OCR），经加工（动作链、AI 摘要/翻译/问答）后出去（复制、贴图、保存）。但目前**内容只停留在"历史卡片"层面**——流水的剪贴记录，缺少"沉淀为可长期组织、可检索、可被 AI 使用的个人知识"的能力。

本次规划把「个人知识库 + 笔记」融入现有产品：让剪贴板里的碎片内容可以**一键沉淀为笔记**，让笔记成为**可组织、可检索、可问答**的个人知识库，最终成为 AI Agent 的"第二大脑"。

**目标**：
- 用户能把重要的剪贴内容变成笔记（带标题、正文、标签、来源追溯）；
- 笔记可组织（文件夹/标签）、可编辑（Markdown）、可检索（关键词 + 语义）；
- AI（门控开启时）能基于笔记做摘要、自动标签、知识问答（RAG）。

---

## 2. 现状家底（融合直接复用的部分）

| 能力 | 现状 | 复用点 |
|---|---|---|
| 内容管道 | 剪贴板 → 历史卡片（`HistoryItem`：text/type/content/pinned/tags/group_id/workspace/content_type/ocr_text）→ 自动分类 | 笔记来源、卡片→笔记 |
| 关键词检索 | FTS5 全文搜索 | 笔记正文检索 |
| 语义检索 | `history_summaries` 摘要表 + `/embeddings` 向量（AI 门控、原文不出网、失败回退 FTS5） | 笔记语义检索、RAG 底座 |
| 编辑/渲染 | MarkdownRenderer、RichEditor、DocEditor、流程图、图片预览 | 笔记编辑器渲染预览 |
| AI 能力 | 动作链、摘要、翻译、问答（`ai_enabled` 门控、双端校验） | 笔记摘要/自动标签/RAG 问答 |
| UI 落点 | TopBar 筛选页签（全部/文本/图片/文件/收藏⭐）、卡片操作菜单、ContextMenu | 笔记页签、转为笔记入口 |

**红线**：原始内容绝不离设备；AI 能力受 `ai_enabled` 门控（未启用=零可见零请求零费用）；学习/摘要可见可删除。

## 3. 整体路线（A → B → C）

```
A 收藏→笔记（最小闭环）   → 验证"剪贴板沉淀为知识"的需求
   ↓
B 独立知识库（主体验）     → 完整笔记组织 + 双向融合 + AI 摘要/自动标签/RAG 问答
   ↓
C 知识库 RAG 智能体        → AI 第二大脑：问答增强、AI 整理、双向链接、知识图谱
```

**已确认的关键决策**：
- 存储：**独立 `notes` 表**（与历史卡片通过 `history_id` 关联，可追溯来源）——A 阶段即按此建模，B 阶段零迁移；
- 编辑器：**轻量 Markdown 编辑器**（标题 + 正文 + 分屏预览，复用 MarkdownRenderer 渲染），不套用面向文档编辑的重型 DocEditor。

---

## 4. A 阶段：收藏 → 笔记（最小闭环）

> 目标：一个卡片可以"转为笔记"，可编辑、可筛选、可检索。改动收敛、快速验证。

### 4.1 验收标准
- [ ] 任意历史卡片（文本/图片/富文本/文档）可「转为笔记」；
- [ ] 转笔记后卡片显示 📝 角标，进入「笔记」筛选页签可见；
- [ ] 笔记可编辑标题与 Markdown 正文（分屏预览）；
- [ ] 笔记正文被 FTS 检索命中；
- [ ] 隐私/AI 红线不破（本阶段 AI 仅做可选摘要，默认关）。

### 4.2 数据模型（notes 表，SQLite）

```sql
CREATE TABLE IF NOT EXISTS notes (
  id         TEXT PRIMARY KEY,          -- 笔记 id（uuid）
  history_id TEXT,                      -- 来源历史卡片（可空：B 阶段独立新建的笔记无来源）
  title      TEXT NOT NULL DEFAULT '',
  content    TEXT NOT NULL DEFAULT '',  -- Markdown 正文
  tags       TEXT NOT NULL DEFAULT '[]',-- JSON 数组（B 阶段正式用标签体系）
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_notes_history ON notes(history_id);
```

- 检索：笔记标题/正文并入 FTS（`notes_fts` 或复用现有历史 FTS 表附加索引）；
- `history_id` 可空：B 阶段独立新建的笔记不强制关联卡片。

### 4.3 交互设计（以真实组件为基础）
- **入口**：卡片悬停操作区 / 右键菜单（ContextMenu）新增「转为笔记」；
- **笔记编辑弹窗**（宽度 520px，复用 dialog 规范）：
  - 头部：标题输入 + 关闭；
  - 主体：Markdown 编辑区（左） + 渲染预览（右，复用 `MarkdownRenderer`），或 编辑/预览 Tab 切换；
  - 底部：标签（复用 TagEditor）+ 「保存」/「取消」；
- **笔记标识**：卡片角标 📝（复用 NEW/badge 的视觉体系）；
- **筛选**：TopBar 页签新增「笔记」；`FilterType` 增加 `note`，后端/前端过滤逻辑复用 pinned 模式。

### 4.4 改动清单
| 层 | 改动 |
|---|---|
| 后端 Rust | `notes` 表 + `note_*` 命令（save/get/list-by-history）；FTS 附加笔记内容；`history_summaries` 可选补充笔记摘要（AI 门控） |
| 前端存储 | `HistoryItem` 增加 `note?: { id, title, content }` 轻量缓存；笔记页签过滤 |
| 卡片层 | 「转为笔记」入口 + 📝 角标 + 笔记页签（CardList / TopBar） |
| 编辑器 | 新增轻量 `NoteEditor`（标题 + 分屏预览，复用 MarkdownRenderer） |

### 4.5 范围边界（A 阶段不做）
- ❌ 文件夹层级 / 独立知识库视图（B）
- ❌ 语义检索笔记 / RAG 问答（B/C）
- ❌ 双向链接 / 知识图谱（C）
- ❌ AI 自动标签（B，随语义索引一起）

---

## 5. B 阶段：独立知识库（主体验）

> 目标：完整的个人知识库——笔记可组织、可编辑、可检索，并与剪贴板工作流双向互融。

### 5.1 模块
1. **知识库视图**（顶级入口，侧边栏/顶栏）：
   - 笔记列表：文件夹树 + 标签双维度（或先标签后文件夹，视 A 反馈定）；
   - 新建笔记（`history_id` 为空）；
   - 打开/编辑/删除/移动。
2. **笔记编辑器增强**：标题 + Markdown 正文 + 标签 + 来源追溯（关联卡片跳转）+ 全文检索框。
3. **双向融合**：
   - in：历史卡片「存入知识库」一键转笔记（A 阶段入口升级，自动带标题/标签/来源）；
   - out：笔记「复制 / 贴图 / 送动作链」回到 in/out hub 工作流。
4. **AI（`ai_enabled` 门控，默认关）**：
   - 笔记摘要（写入摘要索引）；
   - 自动标签（语义聚类）；
   - 知识问答：`semantic_search` 扩展到 notes 表 → 命中笔记作为上下文（RAG 雏形）。

### 5.2 验收标准
- [ ] 知识库视图可浏览/搜索全部笔记（文件夹 + 标签过滤）；
- [ ] 剪贴板卡片 → 存入知识库 → 可在知识库编辑 → 可复制回剪贴板；
- [ ] 笔记语义检索命中（AI 开启时），失败回退 FTS；
- [ ] AI 问答能引用相关笔记作答（门控开启时）。

---

## 6. C 阶段：知识库 RAG 智能体

> 目标：知识库成为 AI 的"第二大脑"，差异化护城河。

- **问答增强**：用户提问 → 自动检索相关笔记（RAG）→ 结合笔记作答并标注来源；
- **AI 整理**：笔记自动摘要、扩写、结构化（表格/清单）;
- **双向链接**：笔记内 `[[引用]]` 语法 + 反向链接列表；
- **知识图谱**：标签/引用关系可视化（可基于现有 DiagramCanvas 能力）。

### 验收标准（概要）
- [ ] 问答引用笔记并给出来源；
- [ ] AI 生成的笔记/摘要可回溯、可删除；
- [ ] 双向链接与图谱可用。

---

## 7. 红线与约束（贯穿三个阶段）

1. **隐私**：原始内容绝不离设备；笔记正文本地存储（SQLite），语义索引只出摘要与搜索词；
2. **AI 门控**：所有 AI/云端能力受 `ai_enabled` 双端校验；未启用 = 零可见零请求零费用；AI 产物（摘要/标签/回答）可查看、可删除；
3. **本地优先**：笔记默认纯本地，云端同步为 opt-in（后续单独立项）；
4. **版本与发布**：阶段里程碑可独立发版；发 tag 由用户指令触发。

## 8. 待确认 / 风险 / 里程碑

### 待确认
- [ ] A 阶段「转为笔记」入口的交互形态（悬停操作 vs 右键菜单 vs 两者）；
- [ ] 笔记筛选页签与"收藏"页签的关系（并行独立 vs 收藏即笔记）；
- [ ] B 阶段知识库入口位置（顶栏页签 vs 侧边栏分组区）；
- [ ] 是否本轮先出 `design/` HTML 设计稿（按项目流程：UI 改动先出稿、基于真实组件）。

### 风险
- **范围蔓延**：A 阶段易被"顺手加功能"拖大——按 4.5 边界收口，B/C 另起；
- **笔记与历史卡片边界**：A 阶段"卡片即笔记"心智 vs B 阶段"独立笔记"心智需要平滑过渡（`history_id` 关联已铺路）；
- **检索口径**：笔记正文进 FTS/语义索引时，与历史卡片的去重/排序需明确（笔记命中优先级）。

### 里程碑（建议）
| 里程碑 | 内容 | 依赖 |
|---|---|---|
| M1（A 阶段） | 卡片转笔记 + 编辑 + 笔记页签 + FTS 命中 | 无 |
| M2（B 阶段） | 知识库视图 + 双向融合 + AI 摘要/自动标签/RAG 问答 | M1 |
| M3（C 阶段） | 问答增强 + AI 整理 + 双向链接 + 知识图谱 | M2 |
