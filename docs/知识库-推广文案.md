## 0. 先定定位（所有渠道共用这一句）

> **PastePanda 知识库：你复制过的东西，本来就该是你的知识。**

差异化不在「又一个笔记软件」，而在于**采集这一层别人没有**：

| 主流 PKM 的路径 | PastePanda 的路径 |
|---|---|
| 想记下来 → 打开 App → 新建 → 粘贴 → 整理 | 已经复制了 → 一键转为笔记 |
| 采集靠「你主动去记」 | 采集靠「你本来就在复制」 |

剪贴板是唯一一条**你在所有应用里都在用**的通道。把它接进知识库，省掉的不是一步操作，是「决定要不要记下来」这个心理成本。

**三条信任支柱（RTB）——写文案时至少带一条具体证据，别只喊口号：**

1. **本地优先**：内容全程存在本机；截图的 OCR 识别走本地离线模型；AI 能力默认关闭，不开就是零请求、零上传。
2. **AI 真能用**：内置问答（流式回答 + 引用标注 `[n]` + 多轮追问）；也可以通过 MCP 一键接给 Claude Code、WorkBuddy 等外部 AI 工具，让它们检索、引用、写入你的笔记。

## 4. 知乎 / V2EX / 少数派

### 4.1 知乎回答体（适合「有哪些相见恨晚的效率工具」「个人知识管理怎么做」类问题）

**开头（前 3 行决定折叠与否）：**

> 说一个反常识的判断：个人知识库的门槛从来不在「怎么整理」，在「怎么开始记」。
> 我自己装过 Notion、Obsidian、Logseq、Joplin，最后留下的是一个剪贴板工具里的知识库。原因值得展开说说。

**正文骨架：**

**一、为什么笔记软件会被闲置**

不是功能不够，是采集摩擦太高。
一条值得记的内容从出现到入库存，中间要跨过：切换窗口 → 新建 → 命名 → 归类。这四步任何一步都会让人放弃。
而剪贴板是唯一一条你在所有应用里都在用的通道——你其实**已经复制过了**，只是它 10 分钟后就没了。

**二、把采集层接进知识库之后**

（此处贴功能表，见 §6.2）

关键不是「一键转笔记」这个动作，是它改变了你的行为：
你不再需要先决定「这个值不值得记」——复制本身已经是决策了。

**三、本地优先不是口号，是架构选择**

- 内容存本机 SQLite/Markdown，可整库导出为目录结构
- 截图 OCR 走本地模型，离线运行
- AI 能力默认关闭（`ai_enabled`），不开即零请求零上传
- 使用日志不出本机，可见可删

对比云端阵营：你换来的不是「更安全」这种形容词，而是**你的工作内容根本没离开过这台机器**。这在我所在的场景里是硬要求。

**四、让 AI 用上它，而不是把内容交给 AI**

两条路：
1. 内置问答：直接问，流式回答 + 引用 `[n]` + 多轮追问
2. MCP 接口：一键接给 Claude Code / WorkBuddy 等外部工具，让它们检索、引用、写入

这里有个工程细节值得说：**节级定位**。
我们实测库里笔记平均 9043 字，如果按「篇」返回，命中一篇 9000 字的笔记只回 200 字摘要，等于什么都没给。
所以检索和读写都下沉到 section 层——AI 拿到的就是相关的那一节，写回去也只改那一节。

这直接决定了「AI 能不能真的用起来」，而不是 demo 好看。

**五、多设备同步：没有中间服务器**

基于 iroh（QUIC）的 P2P 同步：
- 同一局域网自动发现，6 位数字双边确认配对
- 不在同一网络时尝试打洞直连，失败才走公共中继
- 指纹双边核对（两边各确认一次，防中间人）
- 冲突留副本，不静默覆盖

顺便说个我们踩过的坑（也算自查）：7.1.3 之前，配对其实是**单边**的——生成邀请码的那一台不记对方，于是把对方每一次连接都拒掉。界面上却写着「已配对 · 离线」。
这不是设计缺陷，是「看起来能用」比「不能用」更危险。现在修了。

**六、它不适合谁**

诚实说：
- 需要移动端 → 目前只有 Windows
- 需要多人协作 → 这是个人知识库，不做团队 Wiki
- 需要双向链接图谱 → 有反链面板，但我们刻意没做图谱（超过 200 条图谱就是毛线球）
- 需要会议转录 / 邮件自动入库 → 没做，也不打算做

**结尾：**

> 如果你已经有一套跑得顺的 PKM 系统，没必要换。
> 但如果你跟我一样，收藏夹里堆着几百条「当时觉得有用」的东西——那问题可能不在你的整理方法，在采集那一步。

### 4.2 V2EX 帖（短、硬、忌营销腔）

**标题**：做了个把剪贴板接进知识库的功能，说说思路和两个踩坑

**正文**：

PastePanda 是个 Windows 剪贴板工具（Tauri 2 + Rust），7.0 加了知识库模块。
不是「又一个笔记软件」，出发点是：**个人知识库的门槛在采集，不在整理。**

你在所有应用里都在用剪贴板，所以「复制过」这件事本身已经是一次筛选了。把它一键转成笔记，省掉的是切换窗口+新建+命名+归类这四步。

几个可能有人感兴趣的点：

**1. 节级定位是必须的**
实测库里笔记平均 9043 字。按篇检索，命中一篇只回 200 字摘要 = 什么都没给。
检索、切片、AI 读写全部下沉到 section 层。实测节长中位数 331 字（p90 1185，max 28997），约 70% 的节直接落在窗口内。

**2. 笔记正文会伪造成 AI 指令**
返回给 AI 的正文原本包在固定标记里，正文里写一行那个结束标记就能提前收尾，后面的内容就跑到「数据」边界外了。
而知识库里的东西大量是从网页、聊天窗口复制来的——那正是能被塞进这种句子的地方。
现在每次返回的标记都带随机数。

**3. 同步配对曾经是单边的**
生成邀请码那台不记对方，把对方每一次连接都拒掉。界面上写「已配对 · 离线」。
两台机器从来没连通过，但界面看起来一切正常。7.1.3 修的。

**4. 同步的内容里有路径，路径能删文件**
增量清单的**文件名**做了路径校验，**内容**里的路径没有——而内容里的路径会被用来删文件。
对方写一行指向同步目录外的路径就能删掉它。7.1.4 修的，两处走同一道校验。

### 9.2 事实边界（别说过头）

| 说法 | 能不能用 | 说明 |
|---|---|---|
| 「端到端加密」 | ❌ 不要用 | 实际是加密传输 + 指纹核对，别用 E2EE 这个有特定含义的词 |
| 「秒级同步」 | ❌ 不要用 | 首次同步大量内容可能要几十分钟（CHANGELOG v7.1.4 明写） |
| 「离线 AI」 | ❌ 不要用 | 问答走云端 AI，受 `ai_enabled` 门控；本地离线的是 **OCR** |
| 「自动打标签 = AI」 | ❌ 不要说 | 自动标签是**纯本地规则**，不是 AI |
| 「双向链接图谱」 | ❌ 不要用 | 只有反链面板，图谱刻意没做 |
| 「支持 Mac / 手机」 | ❌ 不要用 | 目前 Windows only |
| 「AI 默认开启」 | ❌ 不要说 | 默认关闭，这是卖点 |
| 「30 天自动清理」 | ⚠️ 谨慎 | 周期**用户可配置**（`note_trash_days`），写死会误导 |
