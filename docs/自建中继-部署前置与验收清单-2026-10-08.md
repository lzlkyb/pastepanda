## 0. 口径与取证边界（先读，否则行号会骗你）

**版本钉死**：客户端 `iroh 1.1.0`、服务端 `iroh-relay 1.1.0`
（`src-tauri/Cargo.lock:3365`、`:3486-3487`，来源 `registry+https://github.com/rust-lang/crates.io-index`）。
本文所有 `iroh/…` 与 `iroh-relay/…` 的 `文件:行` 都是从本地注册表副本
`C:/Users/19145/.cargo/registry/src/rsproxy.cn-e3de039b2554c837/{iroh-1.1.0,iroh-relay-1.1.0}` 逐条 grep 出来的。

**GitHub 上的四个社区范例只当「形状」参考，不当配置字段的依据**——它们各自钉的版本是
`1.0.0`（rayfish/ansible-iroh）、`v1.2.0`（arachne-systems/arachne-relay）、`v1.3.0`
（baisuipingan/iroh-relay-install），都**不是**我们的 1.1.0。字段一律以本地 1.1.0 源码为准。

🔴 **纠正我上一轮的口头结论**（写在最前面，怕被继续引用）：
我说过「客户端 RelayMap 必须给中继填 `quic.port`，否则 QAD 整条静默失效」。**这句是错的**。
`relay_map.rs:232-240` 的 `quic` 字段带 `#[serde(default = "quic_config")]`，
而 `quic_config()`（`:282-284`）返回 `Some(RelayQuicConfig::default())`；
`RelayMap::try_from_iter`（`:64-79`）走 `RelayConfig::from(url)`（`:272-277`）同样给 `Some`。
⇒ **只要正常构造 relay map，客户端默认就会对每个中继尝试 QAD，端口默认 7842**
（`reportgen.rs:648-656`：`port == 0` 也回落 `DEFAULT_RELAY_QUIC_PORT`）。
真正会关掉的只有一种情形：显式 `RelayConfig::new(url, None)` 或 JSON 里写 `"quic": null`。
所以**唯一的决策点在服务端**：`enable_quic_addr_discovery` 默认 `false`（`main.rs:133-134`、`:375`）。
服务端不开，后果不是报错，是**这台中继对候选地址的贡献为零**——客户端往 7842 探测失败，
其余中继照常，表现为「装了的和没装的一样慢」。

## 1. 买 VPS 的判据（硬性 4 条）

| # | 判据 | 为什么是硬的 |
|---|------|--------------|
| 1 | **有独立公网 IPv4** | 我们家庭侧无公网 v4、路由器层已穷尽（`公网直连-双层NAT最佳方案调研-2026-10-06.md` 的 🔴 更新：上游不给 Prefix Delegation ⇒ 本机无 GUA）。中继必须是「外面能拨进来的地址」。 |
| 2 | **入站可放行 443/tcp + 7842/udp，安全组自定义** | 中继走 HTTPS/443，QAD 走 QUIC/7842（`iroh-relay/defaults.rs:7`）。只有 TCP 的中转（frp / ngrok / bore / SSH -R 那一档）套上去等于「中继之上再叠一层 TCP 重传」——10-06 那篇已判定。 |
| 3 | **上行带宽对称，且月配额够用** | 中继每路会话在 VPS 上占约 2× 视频码率。真实瓶颈往往不是 VPS 下行而是家庭侧上行——这条本文不重复算，见配套篇。 |
| 4 | **有一个能把 A/AAAA 指过去的域名，最好有 DNS API** | 决定 §3 第 5 步能不能自动续期。IP 直连不行：`RelayUrl` 从 URL 解析，而 TLS 证书要匹配 hostname。 |

⚠️ 两条买前必须问客服、我查不到的：国内厂商对**入站高位 UDP** 的实际放行策略；
以及非 80/443 端口的对外服务是否触及备案要求（若 443 要求备案，就改用 `[tls].https_bind_addr = "[::]:15443"` 这种高端口，
baisuipingan 那份配方正是「不占 80/443、不占任何 UDP」的路子）。

## 2. 三种落地形状（GitHub 上真实存在的就这三种）

| 形状 | 代表 | 可抄的部分 | 适不适合我们 |
|------|------|------------|--------------|
| **Ansible role + systemd（二进制来自官方 release）** | `rayfish/ansible-iroh` ★5 | **加固 unit 清单**（见 §3.4）；`install_release.yml` 用 `get_url` 下 release tarball → `unarchive` → `/usr/local/bin`；独立用户 `iroh-relay`、数据目录 `/var/lib/iroh-relay` | ✅ **推荐**。不依赖镜像仓库，版本可控，加固项照抄 |
| **docker run + 高端口映射** | `arachne-systems/arachne-relay`（DEPLOYMENT.md，钉 v1.2.0） | 容器内监听 8080/8443、宿主 `--publish 80:8080 --publish 443:8443`；`--user 65532 --read-only --cap-drop ALL --security-opt no-new-privileges`；config 只读挂载 + certs 单独卷；验收 `curl https://<host>/healthz` | ⚠️ 取决于镜像存在性——官方镜像 `n0computer/iroh-relay` 我**没能定性**（一次 401、一次连接超时，按「无法判定」处理，不代表不存在）。自己 build 要引 Rust 工具链进生产机。 |
| **Cloudflare Workers 上的兼容中继（免 VPS）** | `baisuipingan/iroh-relay-install` ★1（acme.sh DNS-01 + 容器）、`thibmeu/iroh-relay`（TypeScript 重写） | DNS-01 免端口签发 + 续期后热重读；它注释里写的理由值得记：「raw.githubusercontent.com 有自己的 CDN 缓存，改完脚本几分钟内仍是旧版」 | ❌ 方向相反：立项动机是**近处**中继，Cloudflare 边缘仍是跨境。只当 VPS 挂了时的应急位 |
| （另）`cwxsss/iroh-relay` | n0 官方仓库的 fork | 唯一价值是**它自己加了 Dockerfile**（官方 crates 打包里没有） | 参考，不依赖 |

**一条省事的硬事实**：官方 release **直接发预编译中继二进制**，不必 cargo build——
`gh api repos/n0-computer/iroh/releases/tags/v1.1.0` 的资产里有

## 3. 服务端准备清单（按顺序，逐项可执行）

### 3.1 装二进制

- 资产名 `iroh-relay-v1.1.0-x86_64-unknown-linux-musl.zip`（**钉 1.1.0**，与客户端同版本；
  跨小版本兼容性我未验证，见 §7）。
- 落 `/usr/local/bin/iroh-relay`；专用账户 `iroh-relay`（rayfish 用同名，组同）；
  数据目录 `/var/lib/iroh-relay`，子目录 `certs/`。

### 3.2 CLI 的三条硬约定（先记住，否则「配置没生效」会白查半天）

1. 参数名：`iroh-relay-1.1.0/src/main.rs:58-59` 是 `#[clap(long, short)] config_path: Option<PathBuf>`
   ⇒ **`--config-path` 与 `-c` 都合法**（clap derive 默认 kebab-case）。
   rayfish 写 `--config-path=`、arachne 写 `-c` 都没错；**官方 docker README 的 `--config` 在 1.1.0 上不成立**。
2. **没有默认配置文件路径**：`:537-546`——不给 `--config-path` 就直接 `Config::default()`。
   所以「文件写了但没读到」的第一嫌疑是路径拼错或它不是普通文件（`:557` `bail_any!("config-path must be a file")`）。
3. `--dev`（`:55`）会把 TLS 降级成 http-only（`:588-600`），并与 `cert_mode="LetsEncrypt"` **明确不兼容**
   （`:718` `bail_any!("--dev is incompatible with cert_mode LetsEncrypt")`）。生产机**不要**带 `--dev`。

### 3.3 `relay.toml`（字段逐条来自 1.1.0 源码）

```toml
# 中继本体：默认 true（main.rs:104-105 + cfg_defaults::enable_relay）
enable_relay = true

# HTTP 监听：默认 [::]:80。配了 [tls] 之后，除 captive portal 外都走 https_bind_addr
# （字段注释 main.rs:106-118）
http_bind_addr = "[::]:80"

# 🔴 这条默认是 false（main.rs:133-134 / :375），不开就等于装了个只转流量的代理，
#    候选地址（observed 公网地址）这条收益完全为零
enable_quic_addr_discovery = true

# 指标：默认 true（main.rs:143-144），metrics_bind_addr 默认 = http_bind_addr 换端口 9090
# （main.rs:144-150 + defaults.rs:16）。不要暴露公网。
enable_metrics = false

# 限流：整节不存在即关闭（main.rs:136-139）。
# [limits] / [limits.rx] 的字段名是 accept_conn_limit / accept_conn_burst / rx{bytes_per_second,max_burst_bytes}

[tls]
https_bind_addr = "[::]:443"
quic_bind_addr  = "[::]:7842"        # 默认 = https_bind_addr 换 7842（main.rs:401-406）
hostname = ["relay.example.com"]     # main.rs:407-409，支持字符串或字符串数组（string_or_seq）
cert_mode = "Reloading"              # Manual | Reloading | LetsEncrypt
cert_dir = "/var/lib/iroh-relay/certs"
# Manual / Reloading 读的默认路径是 <cert_dir>/default.crt 与 <cert_dir>/default.key
# （main.rs:417-429 + :471-485）；要别的路径就填 manual_cert_path / manual_key_path
```

**三条启动即失败的组合（都已核对到行）**：`enable_quic_addr_discovery = true` 而 `[tls]` 缺失 ⇒ bail
（`:585`、`:597`、`:721` 三处都有）；`cert_mode = "LetsEncrypt"` 而没有 `hostname` 或没有 `contact` ⇒ bail
（`:642`、`:644-647`）；`access.shared_token = []` ⇒ 启动失败（`:160` 附近文档写明「列表不得为空、元素不得为空串」）。

⚠️ **改端口的连带义务**：如果把 `quic_bind_addr` 从 7842 挪走（比如厂商只给高端口），
客户端侧的 map **必须显式给出该端口**（`RelayConfig::new(url, Some(RelayQuicConfig::new(port)))`，
`relay_map.rs:250` / `:292-299`），因为客户端默认填的是 7842。这是本次调研里唯一一条「一改就两边都要动」的字段。

### 3.4 systemd unit（加固项逐条抄自 rayfish，非我发明）

```ini
[Service]
Type=simple
User=iroh-relay
Group=iroh-relay
WorkingDirectory=/var/lib/iroh-relay          # cert_dir 缺省会读 cwd（main.rs:472），别留空
ExecStart=/usr/local/bin/iroh-relay --config-path /var/lib/iroh-relay/relay.toml
Restart=on-failure
RestartSec=5
NoNewPrivileges=true
ProtectSystem=strict
ProtectHome=true
ReadWritePaths=/var/lib/iroh-relay
ReadOnlyPaths=-/etc/letsencrypt
PrivateTmp=true
AmbientCapabilities=CAP_NET_BIND_SERVICE      # 只有绑 80/443 才需要；用高端口就删掉
CapabilityBoundingSet=CAP_NET_BIND_SERVICE
```

> LetsEncrypt 内置 ACME 需要写 `cert_dir`（`cache_path` = `tls.cert_dir()`，`main.rs:656`），
> 所以 `ReadWritePaths` 必须覆盖它；否则证书拿不下来，而且失败发生在**首次签发**、容易误判成「网络不通」。

### 3.5 入站放行表

| 端口 | 协议 | 用途 | 是否必须 |
|-------|------|------|----------|
| 443/tcp | TCP(TLS) | relay 本体 + `/healthz`（路由存在：`server.rs:740` 注册 `GET /healthz`） | ✅ |
| 7842/udp | QUIC | QAD（observed address 上报），`quic.rs:111`/`:495` `send_observed_address_reports(true)` | ✅（开 `enable_quic_addr_discovery` 就必须） |
| 80/tcp | HTTP | 仅 captive portal 探测；不参与主链路 | 可省 |
| 9090/tcp | HTTP | metrics | ❌ 不放公网（建议 `enable_metrics = false`） |

### 3.6 证书：为什么「自签」在我们这儿不是选项

`src-tauri/Cargo.toml:70-74` 的 iroh 是 `default-features = false`，只开
`tls-ring`、`portmapper`、`unstable-net-report`——**没开 `platform-verifier`**
（iroh `Cargo.toml:79`：`platform-verifier = ["iroh-relay/platform-verifier"]`）。
⇒ 中继证书走 `iroh-relay/src/tls.rs:57-59` 的默认档 `Mode::EmbeddedWebPki`，
即**编译进二进制的 Mozilla root bundle**（`:176-181` 用 `webpki_roots::TLS_SERVER_ROOTS`）。

结论（这条比「要不要备案」更硬）：**中继必须用公共可信证书**（Let's Encrypt 或任何 Mozilla 收录的 CA）。
自签 / 私有 CA 会被客户端直接拒绝连接；且 `tls.rs:165-175` 那个「Android 分支忽略 extra_roots」的坑
在我们这儿不适用（feature 根本没开）。⇒ 若厂商不给 443/80，用高端口 + **DNS-01** 签发（不需要任何入站端口），
这正是 baisuipingan 那份配方的动机；`cert_mode = "Reloading"` 配合续期后重读文件。

### 3.7 访问控制（可选，但建议开）

`AccessConfig` 五档（`main.rs:160-200`）：`Everyone`（默认）/ `Allowlist([EndpointId])` /
`Denylist` / `Http{…}`（回调要返回 `200` + 文本 `true`，带 `X-Iroh-Endpoint-Id` 头）/ `shared_token`。
`shared_token` 的 token 从 `Authorization: Bearer <token>` 读，回落 `?token=`；
环境变量 `IROH_RELAY_ACCESS_TOKEN` 可覆盖且**优先于配置文件**（单值，避免字符集限制）。
客户端侧接口：`RelayConfig::with_auth_token`（`relay_map.rs:266`）、`RelayMap::with_auth_token`（`:154`）。

⚠️ 两条要说清的：① `RelayMap::with_auth_token` 的文档自己写明**对它之后 insert 的条目不生效**（`:151`）
⇒ 必须在全部条目加完之后再调用；② token 存在于每个客户端二进制里，可被提取——
**它只挡白嫖流量，不挡有意滥用**。诚实口径：这一档的价值是「别人不能拿我的中继当免费出口」，不是访问隔离。

## 4. 客户端接线（唯一落点 + 三种档，本文不落代码）

**生产接线点只有一个**：`src-tauri/src/shared_ep.rs:129-140`
（`Endpoint::builder(presets::N0)` → `.secret_key` → `.alpns` → `.transport_config` → `.bind()`）。
`presets::N0` 的定义在 `iroh-1.1.0/src/endpoint/presets.rs:116-140`：设 crypto provider + 三个 address_lookup
（PkarrPublisher/PkarrResolver/DnsAddressLookup，全指向 n0 的 `iroh.link`）+ `relay_mode(default_relay_mode())`。
`Builder::relay_mode`（`endpoint.rs:557`）是**普通 setter，后写覆盖**（`N0DisableRelay` 自己就是这么实现的，
`presets.rs:178-182`），所以在 `.builder(presets::N0)` 之后追加一次 `.relay_mode(..)` 就能改，不需要换 preset。

| 档 | 做法 | 代价 |
|----|------|------|
| 甲 **全替换** | `.relay_mode(RelayMode::Custom(map))`，map 只放我们那台 | relay 流量全走单点，**它挂 = 全断**（现在 n0 是 4 台：`defaults.rs:27-33` 的 `use1/usw1/euc1/aps1`）。另注意 `Custom` 空 map 会**bind 直接报错**（`endpoint.rs:550-553` 注释明写） |
| 乙 **并存**（推荐先从这里验） | `let map = iroh::defaults::prod::default_relay_map(); map.insert(我们的, ..)` | 保留 n0 兜底与 QAD；但 iroh 自己在多台 relay 间选，**可能仍选欧洲**——本仓现状正是「30 条会话里 23 条 relay」，并存档不保证改判 |
| 丙 **只做 QAD、不搬流量** | 服务端 `enable_relay = false` + 客户端仍保留 n0 relay | 服务端字段注释原话支持这个用法（`main.rs:96-100`：「helps with NAT traversal by reporting observed addresses but does not relay any data. This is useful for holepunching-only relay servers」）。带宽费用几乎为零，风险最低，但**收益也只在打洞成功率**，不通时仍然绕欧洲 |

**行为边界（必须先对齐再动手）**：共享端点同时服务 `sync/`（文件传输）与远程电脑，
`shared_ep.rs:19-20` 有「端点一经绑定永不关闭」的不变量 ⇒
① 换 relay map **只能重启生效**，不能运行中改；
② 这一改动**同时改变文件传输的选路**，不是远程电脑局部行为——与 `远程电脑-RustDesk对标-…-2026-10-04.md`
里 A4「仅局域网」被判押后是同一个理由。
（`sync/transport.rs:103` 那个也带 `relay_mode` 的 `bind()` 是 `#[cfg(test)]`，不是第二个生产落点。）

## 5. 验收清单（分三层；第三层才是重点）

**A. 服务端起得来**
1. 先**前台**跑一次：`sudo -u iroh-relay iroh-relay --config-path /var/lib/iroh-relay/relay.toml`
   —— §3.3 列的三类 bail 都在这一秒暴露，比看 systemd 日志快。
2. `curl -fsS https://<域名>/healthz`（路由确实存在，`server.rs:740`）。
3. `ss -lntup | grep -E '443|7842'`：应同时看到 TCP/443 与 **UDP/7842**。
   只有 TCP 没有 UDP ⇒ `enable_quic_addr_discovery` 没生效，回到 §3.3。
4. `openssl s_client -connect <域名>:443 -servername <域名>`：看签发者是否公共 CA、链是否完整、到期日。
   **自签链在这里就注定失败**（§3.6）。
5. metrics 未公网暴露。

**B. 中继本身能用**：从**第二张网络**（不是家里那条）另起一台机器跑 A.2/A.4，排除「只有本机 DNS 能解析」的假绿。
QAD 侧服务端**没有 CLI 自检**（`iroh-relay` 只有服务端上报，探测由对端发起）⇒ 只能在 C 层验。

**C. 端到端（本仓可观测的只有两处，都已在源码里核对存在）**
1. **地址侧**：`src-tauri/src/shared_ep/diagnostics.rs:9-17` 打的
   `[IROH-ADDR] local={addr:?}`。判据：地址集合里出现我们的 relay host，
   且**公网 IPv4 候选不再是家庭内网/无候选**。这是 QAD 是否真在工作的直接读数。
2. **路径侧**：`config` 表 `rc_session_history` 的 `path_kind`（写入点 `rc/history.rs:73`，
   判定复用 `crate::sync::path_kind`，见 `rc/link.rs:28`）。判据：同一对设备，
   新中继档下的 `rtt_ms` 显著低于绕欧洲时的读数。

🔴 **验收前必须先修的判据缺陷**（否则会把结论读反）：
`sync/path_kind.rs` 的 `is_lan_ip` 对 v6 只认 ULA/link-local ⇒ 同家庭 /64 内两台设备用 GUA 互访
会被记成 `direct`、界面显示「公网直连」（10-06 那篇 §6 记的待修项）。
⇒ 在修好之前，**`direct` 档不许当「公网直连成功」的证据**，只有 `relay` 档可信。

另外两条诚实边界：本仓**没有上报通道**，线上占比拿不到，历史数据只在用户本机；
被控端侧 `rtt_*` 结构性恒 0（RTT 只在观看端 `rtt_ms > 0` 才采样，前端按「未测」处理是有意设计）。
⇒ 「够不够用」最终只能靠**多网络各实测一次记档位**，不是自建统计。

**本文列的全部验收项均未执行**（没有服务器）。这份清单的价值是把「要测什么」钉死，不是「已测过」。

## 6. 风险与回滚

- **回滚成本极小**：改动收在 `shared_ep.rs` 一处 + 一个配置开关；删掉那行 `.relay_mode(..)` 就回到 `presets::N0`。
- **单点故障**：甲档下中继挂 = 远控完全不可用（现在至少 4 台 n0）。⇒ 甲档必须先把乙档验通再收紧。
- **费用失控**：流量按配额计费，`limits` 节（§3.3）是唯一的服务端兜底旋钮；但**我们没有任何线上用量可见性**。
- **隐私口径**：中继会看到两端公网 IP:port，QAD 更是让端点**主动把公网地址上报给中继**。
  自建只是把这信息从 n0 转到我们自己的 VPS，**不减少对外暴露面**。
  ⇒ 若要在产品文案里宣称隐私改进，必须先改隐私说明，否则是假话。
- **不变量**：别破「端点永不 close」（§4）；破了的症状是「空闲一阵掉回中继」，不是当场报错。
