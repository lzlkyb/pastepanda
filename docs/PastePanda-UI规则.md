## U1 · 反馈时序：三个硬阈值

来源：NN/g 三条响应时间界限（自 1993 年至今未变，因为它取决于人的知觉而不是机器）。

| 耗时 | 必须做什么 |
|---|---|
| **< 100ms** | 必须有即时视觉响应（hover / active / 选中态）。不给就是用户眼里的「点了没反应」 |
| **100ms – 1s** | 不需要额外指示器。弹一个一闪而过的 spinner 反而更吓人 |
| **> 1s** | 必须出进度指示（按钮变态 / skeleton / 进度条）|
| **> 10s** | 必须能**取消**或给出**进度/预计**，否则用户会去干别的事 |

**判定**：任何用户触发的 `await` 路径，若可能超过 1 秒而界面零变化 → 违反 U1。

本项目的真实例子：
- ✅ `runAi`：按钮变「写作中…」，批量时变「成文中 2/5」
- ❌ `adoptAll`：串行建 N 篇笔记，过程中**没有任何指示**——这是欠账，下次碰到要补

## U2 · 动效：只用四档时长 + 两条曲线

按 Material 3 的 duration token 收敛成四档：

| 档 | 时长 | 用在 |
|---|---|---|
| 快 | **150ms** | 颜色 / 透明度 / hover 反馈 |
| 标准 | **200ms** | 小元素位移、展开收起 |
| 中 | **300ms** | 面板 / 抽屉 / 弹窗 |
| 慢 | **400ms** | 全屏或大面积转场 |

❗ **快档于 2026-09-09 从 100ms 改成 150ms。** 初版写 100 是从 M3 的四档里挑错了一档：
实测全库 transition 时长 **150ms 有 330 个、第二名 300ms 只有 80 个**，150 是事实标准；
而 M3 的 `short3` 本来就是 150ms。按旧版判，**430/581 处时长都是「违规」**——
任何人碰任何组件、只要改到 hover 就违规，于是这条规则会被整体无视。
**一条在 58% 情况下都判错的规则，比没有规则更糟。**
（100ms 不再是一档；真需要更快的纯颜色反馈写 150 也不会有人看出来。）

曲线只两条（M3 官方值）：
- 常规：`cubic-bezier(0.2, 0, 0, 1)`
- 元素**进入**视野（减速）：`cubic-bezier(0.05, 0.7, 0.1, 1)`

原则：**元素越大、位移越远，时长越长**。一个 24px 按钮用 400ms 会显得拖沓。

### 弹簧（2026-09-25 修订：位移动变可用一组定参弹簧）

四档时长 + 两条贝塞尔都是「出发→到位」的单程缓动，数学上不可能过冲；
灵动岛窗口动画要 Apple 那种「过冲再回弹落定」的液体感，弹簧是唯一路径。
补四条判定（与上面时长/曲线并行，不动它们）：

1. **弹簧只许一组定参**：k=130、c=16（m=1；≈阻尼比 0.70，过冲 ~4.5%，~800ms 完全落定——尾部 0.1% 由终帧精确落位兜掉）。
   参考实现 `todo_island_stage::spring_progress`。**判定**：任何实现用了别的弹簧参数 → 违反。
   开放自定义 = 回到「基线 191 种阴影」的老路。
2. **弹簧只许作用在位移/尺寸形变上**（窗口尺寸、位置、transform 位移）。
   **颜色 / 透明度禁止弹簧**——透明度过冲没有意义且会闪。**判定**：opacity/color/filter 的
   动效用了弹簧（CSS 侧即 `linear()` 弹簧近似，见下）→ 违反。
3. **弹簧与时长档互斥分工**：位移/形变走弹簧，**不再标 150–400ms**（弹簧有自然时长；
   此条指 Rust 侧真弹簧——积分自己出时长）；颜色、透明度、hover 反馈仍走 150ms 快档贝塞尔。
   CSS 的 `linear()` 近似**仍需标时长档**（linear() 的采样区间就是那条时长）。
   **判定**：Rust 侧位移动效标了弹簧又标时长档（或给透明度标弹簧）→ 违反。
4. **reduced-motion 兜底对弹簧同样生效**：弹簧实现必须读系统「减少动态效果」
   （Windows `SPI_GETCLIENTAREAANIMATION` / Web `matchMedia('(prefers-reduced-motion)')`），
   开启时回退贝塞尔缓动或瞬时——**不许**以「弹簧是 JS 驱动的」为由绕过全局兜底。

CSS 侧若需要弹簧近似，只许经由**单一令牌** `--ease-spring`（`linear()` 采样自上面那组参数，
首次需要时在 `globals.css` 定义）——CSS 里裸写 `linear(...)` 弹簧曲线 → 违反
（`scripts/ui-rules` 的 U2spring 判据拦它）。目前无人使用，属预防性判据。

### 减少动效：已经有全局兜底，**不要逐文件补**

🔴 **本小节于 2026-09-09 重写。** 初版写的是「`prefers-reduced-motion` 必须写」+
基线表里一个「9 / 88」的数字，两者合起来把人往「去给 36 个文件补 @media 块」引——
**一个都不需要。**

`src/styles/globals.css` 里有全局兜底（`*, *::before, *::after` 把
`animation-duration` / `transition-duration` 压成 0.01ms），而它被 **6 个入口全部 import**；
framer 那侧又有 `<MotionConfig reducedMotion="user">`，Lenis 平滑滚动也按 PRM 关掉。

所以判定变成：**默认已覆盖，只在下面两种情形才需要写局部规则**：

1. **兜底会把信息一并删掉时。** 典型是“两端关键帧都是透明”的脉冲引导：
   压成 0.01ms + 迭代 1 次后直接停在 100%，等于什么都不显示——
   开了「减少动态效果」的用户从此**拿不到那个功能的发现路径**。
   这种要补一个**静态替代**（如一圈不闪的描边），而不是任它消失。
2. **真正要去掉位移与缩放时。** 兜底只能把动效变瞬时，去不掉 `transform` 本身；
   而本条要求的是去掉位移与缩放、只留透明度。前庭疾患者看到的不是「好看」而是真会不舒服。

❗ 反过来也成立：**状态不能只由动画表达**。停掉一个持续脉冲前，先问它说的是什么；
如果它是唯一的「正在收集」信号，就得同时给一个静态态。

**判定**：新写的 CSS 出现四档之外的时长 → 违反。
**判定**：新写了位移/缩放动效，且它承载了信息，却没给静态替代 → 违反。
光是「本文件没写 `@media (prefers-reduced-motion)`」**不算违反**。

## U3 · 状态四件套（最常漏的是第四个）

任何列表 / 面板 / 异步区块，**四个状态都要显式写出来**：

1. **空** —— 说清「为什么空」与「怎么让它不空」。禁止光写「暂无数据」
2. **加载** —— 形状已知用 skeleton（列表/卡片），未知用 spinner；遵 U1，< 1s 不要闪
3. **错误** —— 说人话 + 给重试入口。`Error: ECONNREFUSED` 不是人话
4. **部分成功** —— 🔴 最常被漏。「5 篇存了 3 篇」必须说出来，而不是报成全成功或全失败

**判定**：读组件源码，四个分支缺任一个 → 违反。

### U3.5 · 🔴 `catch` 不许落到空态

❗ **本条于 2026-09-09 新增，来自一次全库审计：四个分块扫描各自独立地撞上了同一个写法。**
它不是六个 bug，是同一个反模式的六个实例：

```ts
try { setData(await fetchSomething()); }
catch (e) { logger.warn("…失败", e); }   // 只写日志，data 保持 [] / null
…
{data.length === 0 && <空态 />}          // 于是失败被渲染成了「空」
```

实际撞到的六处（当时均为真实代码）：

| 失败的事 | 用户看到的 |
|---|---|
| 搜索报错 | 「没找到匹配的笔记」 |
| 片段读库失败 | 「暂无片段，点击右上角新建」 |
| 清理计数查询挂了 | 「0 条记录符合条件」+ 按钮置灰 |
| 8 个文件读不出来 | 「共 12 处匹配」（那 8 个静默消失） |
| 编码探测失败 | 文件直接从列表里消失 |
| 画像预览失败 | 无限重试 + toast 刷屏 |

**把「查询失败」渲染成「查询结果为空」，是两件相反的事共用同一屏。**
🔴 而且它有个反直觉的放大器：**空态文案写得越好，骗得越彻底**。
那句「暂无片段，点击右上角『新建』添加」是全仓 L3 写得最好的空态之一，
也正因为写得好，存了几十条片段的老用户读到它会**当场以为数据没了**。

发布版没有控制台，`logger.warn` 等于什么都没留。

**判定**：一个 `catch` 块里只有日志（或只有一闪而过的 toast），
而失败后的渲染结果与「真的没数据」不可区分 → 违反。

正确写法是多一个状态，不是多一句 toast：
```ts
const [loadError, setLoadError] = useState<string | null>(null);
…
{loadError ? <错误条 onRetry={load} /> : !data ? <加载中 /> : data.length === 0 ? <空态 /> : <正文 />}
```
❗ toast 不能代替错误态：它 4–5 秒就没了，而那屏空态会一直在。

❗ 与规则 15.3 联动：错误态若只 `setState` 而不弹 toast，必须确认承载它的元素在**任何折叠状态**下都可见。

## U4 · 撤销、确认、破坏性操作

1. **可撤销 > 二次确认**。能撤销的**不要**弹确认——确认框拦住的是每一次正确操作，而撤销只成本在出错那一次
2. **撤销条 4–10 秒自动消失**（Material snackbar 口径）。本项目取 **6 秒**，
   常量 `UNDO_AUTO_HIDE_MS`。**hover 时暂停倒计时**——正把鼠标移过去要点撤销、
   条却自己没了，是最气人的一种交互
3. **只有不可逆才弹确认**：彻底删除、清空回收站、覆盖本地文件。
   「删到回收站」不算不可逆，不该弹
4. **破坏性按钮不能是默认焦点**，也不能与安全按钮同色同形
5. **花钱 / 出网的批量操作必须串行且可中断**，任一步失败就停，不接着烧

## U5 · 视觉尺度：三张表，只许用表里的值

现在圆角有 8 种、间距基本靠拍。新代码收敛到：

| | 取值 | 用在 |
|---|---|---|
| 圆角 | **4 / 8 / 12** | 小控件徽标 / 卡片按钮输入框 / 大面板弹窗 |
| 间距 | **4 / 8 / 12 / 16 / 24** | 元素内 / 元素间 / 组间 / 区块间 / 大块间 |
| 字号 | **11 / 12 / 13 / 15 / 20** | 微文注 / 正文次 / 正文 / 小标题 / 标题 |

8px 圆角已经是事实标准（233 处），本表只是把它定下来。

**判定**：新写的值不在表里且说不出理由 → 违反。

## U6 · 语义色单一来源

现在两套并行：`--danger` 与 `--red-bg`、`--success` 与 `--green`、`--warning` 与 `--orange`。

**新代码只许用语义名**：`--danger` / `--warning` / `--success` / `--accent` / `--text-muted`。

🔴 **色名变量（`--orange` `--green` `--red-bg`…）不得在新代码里出现。**
色名描述「是什么颜色」，语义名描述「表示什么」——只有后者能跟着主题走，
也只有后者能在换主题时不把「警告」变成「装饰」。

❗ 例外：已有的功能色语义（如蒸馏统一用 `#8B5CF6` 紫）写成变量并在注释里说明它代表什么，
不算违反——它是「机器拟的」这个语义的颜色，不是「紫色好看」。

## U7 · 可及性底线（WCAG 2.2 AA）

| 项 | 要求 | 来源 |
|---|---|---|
| 正文对比度 | ≥ **4.5:1** | SC 1.4.3 |
| 大字 / 图标 / 边框 / 状态色 | ≥ **3:1** | SC 1.4.11 |
| 点击目标 | ≥ **24×24 CSS px**（或间距满足例外）| SC 2.5.8 |
| 焦点 | 每个可聚焦元素都要有 `:focus-visible` 样式 | SC 2.4.7 |
| 颜色 | **不能只靠颜色**传达状态，要配图标或文字 | SC 1.4.1 |

实例：撤销条那个 `×` 按钮（`fontSize: 13, padding: 0`）**不达标**，下次碰到要撑到 24×24。

## U8 · 不许再加内联 `style={{}}`

新组件一律用 CSS Module。已有的 133 个**不强制迁移**，但碰到就顺手改。

理由不是「不好看」，是**内联 style 根本写不了这些东西**：
- 拿不到伪类（`:hover` / `:focus-visible`）→ U7 守不住
- 拿不到媒体查询（`prefers-reduced-motion`）→ U2 守不住
- 无法被主题覆盖 → U6 守不住

也就是说，**内联 style 是上面三条规则集体失效的根因**，不是风格偏好。

# L1–L6：可学性（小白一看就懂）

> U 与 L 是**正交**的两组：
> **U 管「好不好用」，L 管「看不看得懂」。**
> 一个全部守住 U1–U8 的界面，完全可能新用户一眼看去不知道在干什么。

## 验收方式（比规则本身重要）

🔴 **黑话测试**：把界面截图给一个没用过的人，让他逐块说出
「这是干吗的、点了会怎样」。**说不出来的那块就是不合格**，不用争论。

不允许用「用久了就懂了」辩护——那句话对每一个没活到「久」的用户都不成立。

## L1 · 说用户的话，不说我们的话

界面上每个名词，都要能在**用户已有的概念**里找到对应。找不到 = 自造词。

自造词两条出路，必选其一：
1. 换成用户语言里已有的说法；
2. 在**首次出现处**用一句话说清它是什么（不是帮助文档里说，是就地说）。

**判定**：新增界面文案出现产品内部黑话且无就地解释 → 违反。

❗ **待办**：现有的「待沉淀」「可蒸馏」「采纳」「找回」都是自造词，
该不该改名**尚未拍板**（它们是产品语言，不是技术选型）。
在拍板前，这几块走第 2 条出路：就地一句话解释。

## L2 · 图标必须有**常驻**文字标签

NN/g 的结论：图标标签应当**始终可见、无需任何交互**；
不要靠 hover 揭示文字——它既抬高交互成本，在触屏上也根本不生效。

**判定**：可点图标的文字只在 `title` / tooltip 里 → 违反。

例外一（只限全球公认的）：`×` 关闭、放大镜搜索、`⚙` 设置、`←/→` 前进后退。

🔴 **本条修订了 CLAUDE.md 规则 17.3**。那条写的是「hover 即有即时提示」，
方向对（禁止裸图标），但把 hover 当成了答案。
正确的关系是：**常驻标签是底线，hover 提示是加速器**（补充快捷键等细节）。

### 例外二：**行内悬停操作**

上面那条对**常驻的**图标按钮（顶栏、侧栏、工具栏）成立。
但它套不到「列表行右侧、hover 才出现的那一排小按钮」上：
那一排**本身就不常驻**，要求它挂常驻文字是自相矛盾的；
真挂上去，四个按钮加四段文字会盖住半张卡片——为了守规则把内容遮了。

这一类改用三条**可判定**的替代要求，三条全中才算过：

1. **图标必须与同一动作在别处的图标完全相同。** 同一个动作只能有一张脸。
2. **必须存在一条带文字的路径**（右键菜单 / 命令面板），且叫法**一字不差**。
3. **图标不得在本应用内一词多义。**

第 3 条不是空话，本仓正好撞了：`📋` 同时是
侧栏「全部」的图标（`App.tsx:402`）、卡片上的「复制」、
变换菜单里的「粘贴为 Base64」与「粘贴为文件列表」——
**同一张脸在同一个屏幕上表示四件事**。
而且在一个**剪贴板应用**里，它甚至分不清「复制这条」还是「这是剪贴板条目」。
已改成与右键菜单同一批 lucide 图标（Pin / Copy / Pencil / Trash2）。

❗ **本条于 2026-09-09 补**。初版把「常驻标签」推到了**所有**图标上，
包括那些本身就不常驻的——在那一类上它不是严格，是没法执行。
分界线是一个事实问题：**这个图标自己是不是常驻的**。
常驻的走上面，悬停才出现的走这三条。

❗ 这是第二条被自己改写的规则（前一条是 L3），两次错得一模一样：
把一个在**某一类场景**里正确的结论写成了无条件的。
写新规则时先问一句：**有没有一类界面，它字面上做不到？**

---

## L3 · 空态是教学位——**前提是它能给出可执行的下一步**

空态必须回答两件事：**这里会出现什么**、**怎么让它出现**。
只写「暂无数据」= 违反。

🔴 **但第二问必须答得出来。答不出来就不该用空态教学。**

| 情形 | 用哪条 |
|---|---|
| 空列表，用户**有动作能让它不空**（新建 / 清筛选 / 导入）| **L3** 空态教学 |
| 内容由**系统在合适时机产出**（待存候选、可合成笔记、通知）| **L4** 首次真出现时多说一句 |

正例（本仓已做对）：`NoteListEmpty` 给的是「新建一篇」「清掉搜索」——
下一步就在眼前，点了立刻不空。

反例（**判定为不该改**）：`DailyDistillSection` / `KbInboxPanel` 都是

```tsx
// 没草稿就整个不渲染。一个写着「今天没有可蒸馏的」的空区比没有更差。
if (drafts.length === 0 && !lastAction) return null;
```

这两块空的时候，用户**没有任何「点了就不空」的动作**（内容靠系统产出）。
露出来只会在顶部常年挂两个空壳，所以那句注释是对的。
它们的发现性问题由 **L4** 解决，不是 L3。

❗ **本条于 2026-09-09 当天修订**：初版写的是「没用过的用户必须至少露一次」，
一刀切且漏了「可执行的下一步」这个前提。照那个版本做，产出的就是两个空壳。

## L4 · 在第一次出现的地方解释，不做开屏教程

没人看教程，但人人会读眼前那一行。渐进式披露：
信息出现在**需要它的那一刻**，而不是开头一次性倒给你。

**判定**：新功能靠「首次引导弹窗 / 帮助文档」才能说清 → 违反（改成就地一句话）。

---

## L5 · 不靠记忆（recognition rather than recall）

用户不应当为了完成当前一步去回忆上一屏的内容。

**判定**：操作需要记住别处的信息（路径、名字、上一步选了什么）才能完成 → 违反。
批量条上那句「以上 3 篇」就是本条的落地：把按钮与它操作的东西绑在一起，
而不是让你记住它管的是上面哪几条。

---

## L6 · 一眼看出「能点」

可点与不可点的元素，在**静止状态**下就要有视觉差异（边框 / 底色 / 光标）。
只靠 hover 变色告诉人「它能点」= 违反——鼠标没路过去之前，他不知道那里有东西。

反例（已修）：`.distillHead` 曾经是个 `<div>`，长得像横幅却点不动。
正反两面都要防：**能点的要看得出能点，点不动的不要长得像能点**。

# V1–V6：视觉质感（高级感从哪里来）

> 三组的分工：
> **U 管好不好用，L 管看不看得懂，V 管看上去像不像专业做的。**
>
> 「高级感」听起来不可判定，但它大部分能拆成可量的代理指标。
> 拆不出来的那部分（真正的审美）**不写进本文**——那是设计稿该解决的。

## 现状基线（2026-09-09 实测）

| 项 | 实测 | 意味着 |
|---|---|---|
| `1px solid` 出现次数 | **803** | 层级几乎全靠画线分割 |
| `box-shadow` 声明 | 283 个，**191 种不同取值** | 几乎每写一次就新配一个，没有高度尺度 |
| 硬编码 hex 色 | **1953 处，395 种** | 调色板失控 |

🔴 **395 种颜色**。专业产品的调色板通常在两位数以内。
这一项已经不是「不够高级」，是**没有设计系统**。

---

## V1 · 建立层级：留白 > 背景对比 > 边框

边框会把界面弄得拥挤。同一个分隔目的，优先级是：
① 加间距 → ② 换背景色 → ③ 才是画一条线。

**判定**：新写 `1px solid` 时说不出「为什么间距和背景色都不行」 → 违反。

不是禁止边框，是**边框是最后一手**。基线 803 处说明我们把它当成了第一手。

---

## V2 · 阴影只有三档，且只表达高度

阴影是用来说「这东西离你多近」的，不是装饰。同一高度必须用同一个阴影。

| 档 | 用在 |
|---|---|
| 贴地 | 卡片 hover、轻微抬起 |
| 浮起 | 下拉、气泡、悬浮卡 |
| 悬浮 | 弹窗、浮层 |

每档的阴影都是**两层叠加**：一层紧而深（出轮廓）+ 一层大而柔（出氛围）。
只写一层的阴影看起来总是「脏」。

**判定**：新写的 `box-shadow` 不在三档里 → 违反。（基线：191 种）

---

## V3 · 颜色只能来自变量；一屏只一个强调色

**判定一**：新代码里出现硬编码 `#xxxxxx` → 违反（只有 token 定义处允许）。

**判定二**：一屏之内用实色强调的地方超过一个 → 违反。
两个实色按钮并列，用户就不知道该点哪个——**强调一切等于不强调**。

基线 395 种颜色，这一条是三组里欠账最重的。

---

## V4 · 圆角同心：内圆角 = 外圆角 − padding

嵌套容器用同一个圆角，四个角的间隙会一处厚一处薄，看起来就是「歪」。

```
外层 radius 12px + padding 4px  →  内层 radius 8px
结果 ≤ 0（padding 比外圆角大） →  内层直接用直角
```

**判定**：嵌套容器内外圆角相同 → 违反。

---

## V5 · 先灰阶，后上色

先用间距、字重、对比把层级做出来，最后才加颜色。
否则颜色会变成拐杖：一去色就分不清主次。

**判定（去色测试）**：把界面截图转成灰度，层级还看得出来吗？
看不出来 = 层级是靠颜色撑的 → 违反。

---

## V6 · 彩色底上的次要文字，用同色相低饱和，不用灰

在彩色背景上把文字调成灰色，结果是「脏」而不是「次要」。
正确做法：取**同一色相**、降饱和度或改亮度。

**判定**：彩色背景上用中性灰（如 `--text-muted`）做次要文字 → 违反。

❗ 这条看着小，但它是**业余感最常见的单一来源**。

---

## V7 · 不填内容（内容密度）

来源：baoyu-design 的 Content Guidelines ——「Do not add filler content」/「Avoid 'data slop'」。
原文一句话概括：**一千个 no 换一个 yes**；每个元素都要挣得它的位置。

这条针对的是**加法惯性**：空态、引导卡、成就卡这类「有地方可以放东西」的位，
天生诱导人往里塞，而塞进去的东西没人会删。

**判定（删元素测试）**：删掉某个元素后，用户完成这块要传达的任务所需的**信息量不变**
→ 该元素是 filler → 违反。

两个高频子类，都可单独判：

1. **假数字**（data slop）：界面上出现的数字 / 统计 / 进度，若用户看完**不会据此做任何决定** → 删。
   例：「已为你优化 3 次」——看完不改变任何行为，它只是让界面显得「有内容」。
2. **无目标链接**：`了解更多` / `查看详情` / `敬请期待` 而**没有明确去向** → 违反本条，
   同时按 L4 走（就地一句话说清，而不是挖一个链接坑）。

❗ **判不了的不写**：「要有信息量」「不要太空」都不是判据。本条只有删元素测试这一个判据。

❗ 与 U3 / L3 的分工：那两条管「空的时候怎么说话」，本条管「不空的时候别多说话」。
空态文案写得再全，也不该顺手再加一句「小提示：…」。

## V8 · 两个「生成味」特征（机器判定）

来源：baoyu-design「Avoid AI slop tropes」，原文点名两类——
`containers with rounded corners and left-border accent color`、
`overused font families (Inter, Roboto, Arial, Fraunces)`。

这两条是**从生成式设计里长出来的默认套路**：模型在缺设计约束时，
默认产出「圆角卡片 + 左边一条彩色竖线」，默认把字体设成 Inter。
所以它们反过来是这个味道**最好认的两个探针**——而且都能机器判。

### V8.1 · 四角圆角不得配左侧色条

**判定**：同一条规则里同时出现
① `border-radius` **四角皆非 0**（单值或四值全非零），且
② `border-left*` 有宽度 ≥ **2px** 且颜色是**彩色**（非中性灰）→ 违反。

**豁免**（这三类是**语义性**用法而非装饰，静默放行、不进报告）：

| 豁免 | 理由 |
|---|---|
| 选择器含 `blockquote` | Markdown 引用块的通用表达，GitHub 与各渲染器一致 |
| 选择器含 `note` / `warn` / `alert` / `callout` / `tip` / `danger` | 警示条的行业惯例 |
| `border-radius` 左侧为**直角**（如 `0 8px 8px 0`）| 这恰恰是色条的**正确**做法：色条贴直边、其余三角逐圆角，两者不打架 |

⚠️ 第三条是整个判据的关键：baoyu 点名的是「**四角圆角** + 左色条」。
一旦左侧改成直角，色条就从「AI 味装饰」变成了「引用/警示的正确写法」——
判据必须贴着这个原文，否则会把正确写法一起判死。

2026-09-25 实测基线：全库 **8 处**「圆角 + 左侧彩色 border」，**8 处全部落在上面三类豁免**里
（3 处 `blockquote` + 4 处警示条 + 1 处左直角箭头），真反模式 **0 处**。
所以本条是**预防性判据**（与 U2spring 同类）——它拦的是以后新加的那种。

### V8.2 · 字体黑名单

**判定**：`font-family` 声明里出现 `Inter` / `Roboto` / `Arial` / `Fraunces` → 违反。

2026-09-25 实测：全库 **0 处**。本项目走**系统字体栈**
（`inherit` + `SF Mono` / `Consolas` 这一组），这是桌面对齐原生观感的前提。
换 Web 字体在中文环境下既增包体、又只能回落到系统字，
只会平白多一层不一致——而且正好落在「生成味」上。

### ❗ baoyu-design 清单里**没搬**的三条（2026-09-25 判定，避免以后重复讨论）

| 它说什么 | 本仓实测 | 为什么不搬 |
|---|---|---|
| 禁用 emoji | **826 处 / 161 个文件** | emoji 是本项目的**品牌元素**（来源图标 `📋⭐📂📸`、引导卡 `🎁🔥`）。baoyu 原文本身带例外「unless explicitly part of the brand」——总禁令在这里自相矛盾 |
| 禁用激进渐变背景 | **260 处声明**，其中 217 处在 `background`，涉及 47 个文件 | 渐变是玻璃拟态设计语言的**核心**（`--glass-shimmer`、`--version-badge-gradient`、卡片洗色）。禁掉等于禁掉视觉方向本身 |
| 别用 SVG 手搓图像 | 内联 SVG data URI 仅 **2 处** | 桌面工具没有实拍图需求。那条针对的是「该用真图却画了个 SVG 代替」的场景，本仓不存在 |

🔴 这三条**不写进规则**，但也不该被遗忘：下次再有人（或未来的自己）
拿通用设计规范来套时，先看这张表，别把已经判定过的东西重新搬一遍。

## 10 · 落地方式：不搞大扫除

🔴 **本文只约束新写的代码，以及你本来就在改的那一块。**

不允许为了合规发起专项重构：133 个内联 style、12 种 transition 时长这些存量，
一次性改完的风险远大于收益（而且改完没人能逐页验证）。

正确的节奏是：**碰到哪块改哪块**。改一个组件时顺手把它的内联 style 搬进 CSS Module、
把时长归到四档、把色名换成语义名——一次一个，每次都能当场验证。

### 10.1 这份文档有机器检查器（2026-09-22 加）

上面那句「只约束新写的代码」不是靠自觉，已经落实成命令：

```bash
npm run lint:ui        # 只查本次改动的行（默认）
npm run lint:ui --staged   # pre-commit 用的模式
npm run lint:ui:all    # 全库基线，只报告不拦（加 --strict 才当门禁）
npm run lint:ui:selftest   # 校验器自己的守卫测试
```

判据表在 `scripts/ui-rules/rules.mjs`，**本文是它的唯一来源**——改判据先改这里，再改代码；
两份对不上时以本文为准。

覆盖范围：U2 / U5 / U6 / U8 / U3.5 / L2 / L3 / V1（计数）/ V2 / V3 / V6 / V8.1 / V8.2 / + CSS 解析失败。
**V1 的计数也按 `ui-rule-ok` 过滤**——它此前是直接 `++`，于是写了理由照样计数，与本节「说不出理由
→ 违规」的判定句对不上（2026-09-26 修，并在 `self-test.mjs` 补了「豁免确实压住计数」的断言）。
**U1 / U3 四状态 / U4 / L1 / L4 / L5 / V4 / V5 / V7 以及「黑话测试」「去色测试」「删元素测试」判不了**，
机器每次跑完会把它们打出来，逐条过人眼（就是本节的清单）。

确有理由时在那一行写 `/* ui-rule-ok: <理由> */`——**理由必写**，只写标记会被当成违规报出来。
🔴 标记必须与违反项**同行或紧邻上一行**，写成多行注释块时标记会落到「上两行」而失效。

V1 这类**计数型**判据只报总数、不报行（全库基线 800+ 处，逐行会把报告淹掉）。要查「这几处到底在哪」
用 `npm run lint:ui:dump`（`scripts/ui-rules/dump-counters.mjs`）——它与门禁同口径：同 diff 作用域、
同「只扫 `src/`」、同 `ui-rule-ok` 过滤，输出的条数与 `lint:ui` 的数对得上。

❗ 豁免的价值在于它强制「说出理由」这一步。本文好几条规则本身就是「说不出理由就违规」
（V1、U5），所以「说不出理由」这件事必须由机器拦，否则它就成了万能洗白开关。

**首次全库基线（2026-09-22 实测，765 个文件 / 163276 行）**，与 §1 / 可学性 / 视觉质感三张

| 判据 | 命中 | 与本表对照 |
|---|---|---|
| V3 硬编码颜色 | 1659 | §1 记 1953 处 hex（按出现次数）|
| U5 圆角不在 4/8/12 | 716 | §1 记 39 种取值 |
