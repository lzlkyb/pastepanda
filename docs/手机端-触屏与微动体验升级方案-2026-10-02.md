# 手机端触屏与微动体验升级

## 范围与方向

延续用户已选 C 方案的苹果简洁风、R2 触控板模式，以及桌面端语义色、设备图标与文案。此稿是下一轮交互提案，尚未修改生产手势逻辑。HTML 中设备、画面、发送与手势结果都是本地演示。

| 方向 | 优点 | 局限 |
| --- | --- | --- |
| A：轻量反馈 | 改动少，按钮和面板更有响应 | 无法解决手势起手误判 |
| B：稳定触控，推荐 | 保留现有习惯，补齐识别、预告、结束与取消 | 需要调整手势状态机并真机验证 |
| C：直接点击优先 | 进入即可点目标 | 小目标易遮挡，需要频繁缩放 |

## 源码核查结果

- `useSessionPointer.ts` 的 `onCharge` 与 `onChargeCancel` 为空；充能环已存在但没有接入当前手势回调。长按触发右键或拖拽前缺少明确预告。
- `touchClassifier.ts` 双指分类比较相邻事件的间距与中点差，超过 4px 就锁定，且未分类时也更新基准。慢动作累计位移可能无法触发；两根手指的事件先后到达可能导致起手误判。需改为累计意图、稳定识别后锁定，并补覆盖真实事件顺序的测试。
- `useSessionPointer.ts` 的点击回调未使用 `isDouble`，双击与单击视觉相同；建议第二次点击有轻量差异，不能为了动效推迟远端发送。
- `MobileSheet.tsx` 只在拖把手松开超过 48px 时关闭，移动时面板不跟随；把手高度 28px，触屏命中偏窄。
- 当前会话按钮已有 150ms 按压和缩放反馈，不能误称“没有动效”。应把同一反馈体系覆盖到通用按钮、设备列表、面板内选项，并处理取消与禁用状态。
- `PinchViewport.tsx` 缩放支持平移但没有视野边界约束；需验证极端缩放、旋转、键盘打开后是否能找回画面。

## B 方案实施顺序

1. 手势可靠性：累计双指意图；双指结束不能补发单击；取消、失焦、旋转和权限变化释放远端按键。保持触控板 / 直接点击语义明确。
2. 操作反馈：长按识别提示“松手右键，移动拖拽”；拖拽与滚动保持状态及可见结束按钮；本地触发与远端实际完成不能混称成功。
3. 跟手弹层：扩大把手命中至至少 44px，拖动实时位移，距离不足回位；正文仍正常滚动；有未保存输入的关闭遵循现有数据保留策略。
4. 通用微动：按压反馈即时开始、150ms 恢复；模式切换 200ms；面板 300ms；输入、发送、连接等待和失败结果留在触发处。指针和滚动不加缓动。
5. 视野与键盘：缩放和平移约束、适应屏幕与回到指针；键盘出现不遮住输入和发送按钮，面板切换保留草稿。

不用持续装饰动画，不增加每个列表项的模糊层。手势热路径继续用命令式位移，避免每次移动触发 React 渲染。震动仅在平台能力确认后补充，视觉提示必须独立成立。支持系统减少动态效果。

## 验收

- 单击、连续双击、轻微手抖、长按原位释放、长按移动、手势中第二指加入均有对应测试，不遗留鼠标按键。
- 慢速双指同向滚动、两指交替事件、捏合及其中一指先抬起不误点击，识别结果在本轮稳定。
- 面板拖动跟手、取消回位、正文滚动互不抢占；点击关闭、系统返回、键盘关闭层级一致。
- 操作目标至少 44px，按下和取消都有可见状态；失败结果在当前层可见。
- Android 与 iPhone 真机分别检查纵向 / 横向、键盘展开、只看模式、断网恢复；浏览器设计稿不能代替这项验收。
- 跑相关手势与组件测试、类型检查、UI 规则检查；生产实现前确认此设计稿。
