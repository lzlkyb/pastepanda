# 录屏三期实施与四五期规划（2026-10-06）

> 本文是**规划承诺**（对标调研只做差距分析：`docs/录屏功能-行业对标调研-2026-10-06.md`）。
> 三期当日开工；四五期按本文范围推进，每项落地前仍按规则 1/4 出方案与设计稿确认。

## 1. 三期（补正确性，2026-10-06 开工）

范围四项，按依赖排序：时间轴 → 指针 → 码控 → 暂停。

### 1.1 录制时间轴修复（实施中新发现的 P0）

- **现象**：`rec/session.rs` 把每个视频包按 `p.at_ms` 写入 SinkWriter，而 `at_ms`
  由 `H264SessionEncoder::stamp_packets` 从 `capture_times`/`next_capture_at` 取——
  这套「帧龄时间轴」只有 rc 推流在驱动（`set_capture_at` 是 `pub(in crate::rc)`），
  **rec 从来没调过它** ⇒ 所有帧的时间戳都是 0，产物时长/拖动全坏。
- **修法**：`set_capture_at` 放开为 `pub`；rec 主循环在每次 `encode_bgra` 前按
  **提交帧号**驱动：`set_capture_at(已提交帧数 × 1000 / fps)`，同一帧的所有包
  （SPS/PPS+IDR）落同一时刻。时长 = 提交帧数 × 1000 / fps，与编码器时间轴一致。
- **验收**：产物在播放器里时长正确、可拖动；`rec-done` 的 duration 与播放器一致。

### 1.2 鼠标指针进画面（P0）

- **现状**：DXGI Desktop Duplication 的指针是独立元数据（`DXGI_OUT_DUPL_FRAME_INFO`
  的 PointerPosition + `GetFramePointerShape`），`rc/dxgi.rs` 完全没取 ⇒ 录出的视频没有光标。
- **修法**：
  - `dxgi.rs`：`acquire()` 在 AcquireNextFrame 与 ReleaseFrame 之间取指针元数据
    （输出相对坐标 + 输出桌面坐标 = 桌面坐标），形状数据进每输出复用缓冲；
    新增 `grab_rec()`（虚拟屏口径）：**指针状态变化也算有帧**——静屏上只动鼠标
    也能录出光标移动；指针快照随帧返回。**`grab()` 行为一字不动**（rc 推流共用）。
  - `rec/pointer.rs`（新，纯函数可单测）：三类指针绘制——MONOCHROME（AND/XOR 双掩码）、
    COLOR（alpha 混合）、MASKED_COLOR（α=0 走 XOR 掩码语义），热点偏移 + 越界裁剪。
  - `session.rs`：画在**裁剪后、缩放前**——指针跟内容一起缩放，坐标系一致。
- **验收**：教程式录屏全程可见光标；静止页面上只动鼠标，回放能看到指针移动。

### 1.3 码控切质量导向（P0）

- **现状**：`encode_h264/mf.rs` 对所有会话硬编码 CBR + 低延迟——推流参数，
  录本地文件时码率被钉死（原画 56Mbps 恒定），静态画面也照付码率。
- **修法**：
  - MF：新增 `open_for_file`——码控切 **PeakConstrainedVBR**（mean = 档位码率，
    peak = 2×mean），跳过滚动帧内刷新与参考帧限制（文件录制不受解码恢复约束）。
  - FF 兜底同构：file 模式 `rc_max_rate = 2×bitrate`，qsv 不再强落 CBR。
  - **低延迟标志保留**（与调研文档「去低延迟」的分歧，原因写进代码）：异步收包
    循环依赖「一进一出」（`collected == 0` 即报错），去掉低延迟 MFT 会流水线缓冲
    数帧，整条提交循环报「一进未出」。质量收益来自码控，不来自延迟标志。
  - rc 推流路径（`open`/`open_gpu`/`open_chain`）行为不变；rec 走新入口
    `try_open_for_file`。
- **验收**：同档位主观画质不降（文字锐度），静止内容体积显著下降（实测口径，
  按 PT-8 性能准则不预写数字）。

### 1.4 暂停 / 续录（P0）

- **修法**：
  - `session.rs`：`Active` 增 `pause: Arc<AtomicBool>` + 暂停累计簿记；
    `set_paused()` 幂等切换并 emit `rec-paused`；`status()` 的 elapsed 扣除暂停段。
  - **视频暂停 = 不提交帧**：时间轴是提交驱动的（1.1），停提交 = 时间轴自然冻结，
    续录下一帧接在原时间轴上，**无需补帧**（静屏续录画面冻结本就是真实内容）。
  - **音频暂停 = 泵掉不编码**：AAC pts 按已喂样本数累计，停喂 = 时间轴同冻结，
    与视频轴锁步；设备缓冲持续泵空，续录无陈旧音频涌出。
  - 命令 `rec_pause(paused)`（收尾中拒绝、幂等）；前端 `recSetPaused`。
  - 控制条：暂停/继续按钮 + 计时冻结 + REC 点变琥珀停闪；事件 `rec-paused`
    同步真相（后端权威，前端乐观更新失败回滚）。
- **热键不在三期**：录制中热键（暂停/停止/标记）连同快捷键面板录入归四期。
- **验收**：暂停期间不计时、不录内容；续录后音画对齐；产物时长不含暂停段。

## 2. 四期（补体验，三期验收后开工）

全行业标配欠账，单量从轻到重排序；UI 项按规则 4 先出设计稿。

| 项 | 内容 | 依赖 | 验收草案 |
|---|---|---|---|
| 4.1 录制中热键 | 暂停/继续、停止、标记时刻；快捷键面板录入 + 全局注册 + 冲突提示 | 无 | 录制中热键全程可用（选区窗已关、控制条无焦点） |
| 4.2 控制条信息量 | 已录体积实时显示（fd/metadata 轮询或编码字节计数） | 无 | 体积随录制增长，暂停时冻结 |
| 4.3 点击高亮 + 按键显示 | 点击涟漪/圈选特效、按键 KEA 水印；**以元数据轨道记录，控制条开关** | 1.2 指针管线 | 教程回放能看到点击位置与按键 |
| 4.4 完成后预览 + 首尾裁剪 | done 后轻预览窗（§18 范式），只做首尾 trim，不引剪辑器 | 无 | 预览可播放；trim 落新文件，原文件不动 |
| 4.5 GIF 导出 | 最近录制条目一键导出（帧抽稀 + 调色板量化 + 高度钳制） | 无 | GIF 体积/帧率有上限档，导出可取消 |

## 3. 五期（做差异化，四期后按需排期）

| 项 | 内容 | 备注 |
|---|---|---|
| 5.1 两段式元数据架构 | 指针/点击/窗口事件记 JSON 轨道随 mp4 旁存；导出时渲染指针平滑、点击动画、自动缩放 | 对标 Screen Studio；是 1.2 的终局形态（指针不烧进画面才有后期）；三期先按「短期合成」交付，元数据轨道从三期指针管线平滑演进 |
| 5.2 GPU 全链路零拷贝 | 复用 rc 的 `encode_texture` D3D11 路径：DXGI 纹理 → VP 裁剪缩放 → 硬编，一帧不过 CPU | 4K60 的性能上限；单屏场景先行（多屏拼接无 GPU 直通） |
| 5.3 即时回放 | 内存环形缓冲 + 热键落盘 | 游戏场景；体积预算与档位联动 |
| 5.4 摄像头画中画 | 设备枚举 + 合成管线 | Loom/Bandicam 标配 |
| 5.5 WGC 评估 | 混合 DPI 多屏 / HDR / 24H2 去黄边 / 按窗口捕获 | 技术预研，不承诺 |
| 5.6 麦克风降噪 | 单列评估 | 不承诺 |

## 4. 节奏与边界

- 每期开工前按规则 1 出方案确认；UI 项按规则 4 出设计稿（`design/`）。
- 性能相关不预写结论，按 `docs/性能实现准则.md` 实测口径回填。
- **不做**：不引全量剪辑时间线；不做云上传/分享链接；不改四档画质档位结构。
