# PastePanda 短视频系列整体规划

日期：2026-10-12  
修订：2026-10-13，按用户要求将 46 条统一为源码 UI 生成方式  
阶段：首批制作准备；生成方式已修订，尚未交付本系列成片  
范围：15 秒为主，复杂操作使用 25–28 秒；每条只围绕一个功能解决一个用户痛点。

## 1. 系列定位

让观众先认出自己的麻烦，再看到 PastePanda 如何把这件事做完。

系列主张：**电脑上的这些小麻烦，可以少折腾一步。**

整体软件能力由系列逐步覆盖，单条视频不承担介绍整个软件的任务。每条都有独立的起因、操作和结果，不要求观众先看上一条。

本规划依据当前源码、README 和已完成宣传片的核验记录制定。真实 UI 指直接渲染软件已有组件、样式、图标和文案；演示数据与系统状态由视频工程驱动。源码页面生成视频展示功能使用过程，不作为原生执行、识别准确率、网络传输或实际性能的证明。选题优先级是本次策划判断，尚无本账号的播放数据支撑。

### 默认制作方向

- 面向中文用户，先覆盖日常办公，再穿插开发者场景，后续进入知识积累和设备互联。
- 主版本使用 9:16 竖屏、1080×1920、30 fps、中文配音和轻背景音乐。这是本系列的制作默认值，具体发布平台尚未指定。
- 15 秒用于一个输入到一个结果；25–28 秒用于需要展示多个操作步骤的单一功能。
- 延续已认可的月白视觉、产品字体和标识。竖屏镜头聚焦当前操作区域，不直接把原有横屏左右布局缩小塞进手机屏幕。
- **46 条全部沿用原来的 `agentic-product-demo` / Remotion 源码生成方式**：读取真实 TSX、CSS、状态结构与处理逻辑 → 在浏览器中渲染源码组件 → 用确定性的帧时间线驱动状态 → 导出 MP4。
- 不采用桌面实拍、系统窗口录制、Computer Use 采集或双设备实拍，不要求启动 Tauri dev 作为视频素材来源。
- 原生 IPC、文件选择、数据库、设备连接和 AI 接口在视频工程内通过演示适配层替代。适配层只存在于视频工程，不修改软件生产代码，不访问个人数据库，不发起模型或设备请求。
- 本地纯计算优先复用真实代码；无法在浏览器直接执行的能力使用注明来源和用途的冻结演示数据，并在画面中标明相应结果为示意。
- 首批 8 条继续按原有选题和时长推进；只调整生成方式、分镜表达和验收条件，不额外改成软件实机测试项目。

### 全系列唯一制作管线

1. **读源码**：读取本条相关组件、对应 CSS、数据结构和处理逻辑，列出真实入口、按钮和状态。
2. **建演示数据**：准备公开或自制材料；固定日期、记录 ID、文件名称等，保证每次渲染一致。
3. **挂载原组件**：直接引用产品组件和样式。必要的浏览器兼容封装只处理窗口宿主、接口和布局边界，不重画一个相似界面替代原组件。
4. **驱动状态**：按帧控制输入、选择、弹窗、处理进度、列表变化和结果；文字输入逐字推进，点击目标取自渲染后的真实控件位置。
5. **配音对齐**：依据状态可见区间安排动作句，逐词核对关键词出现时的画面。
6. **逐帧导出**：Remotion 单并发渲染 JPEG 序列，FFmpeg 编码画面；再合成中文配音、字幕和背景音乐。
7. **验证交付**：检查源码一致性、状态连续性、结果示意标注、声画同步和完整播放表现。

这里的逐帧图像来自源码页面的浏览器渲染，不是拍摄或录制 Windows 桌面。片头、字幕和镜头运动由视频工程生成；软件界面仍来自真实源码。

## 2. 每条视频的内容约束

一条视频只回答四件事：

1. **谁在什么场景遇到了什么麻烦？** 例如，复制了新内容，把刚才那段覆盖了。
2. **这条只展示哪个功能？** 例如，剪贴板历史找回。
3. **画面如何让观众看懂它有用？** 例如，搜索找到旧内容，并展示明确标注的粘贴效果示意。
4. **结果有什么变化？** 例如，旧内容重新出现在输入框里。

每条设一个主要动作和一个结果，不在结尾顺带介绍另外三项功能。必要的打开窗口、切换模式、选择材料属于操作前提，不另起功能介绍。

### 开头与收尾

开头先讲痛点，避免“今天给大家介绍一款功能强大的软件”。可采用不同句式，防止全系列都像同一个模板：

| 开头类型 | 示例 | 画面必须给出的证据 |
|---|---|---|
| 具体失误 | 刚复制那段，被新的内容盖掉了。 | 演示历史中已有旧内容，当前内容是另一段 |
| 重复劳动 | 这句话，你每天要打多少遍？ | 同一段常用回复需要再次输入 |
| 看得见的障碍 | 图片里的字，又得手打一遍？ | 原材料确实是一张图片 |
| 直接展示变化 | 这团 JSON，排开就能读了。 | 同一份数据格式化前后对照 |
| 操作困境 | 三个字段，还在来回切窗口？ | 源码队列与辅助演示表单的三条内容对应 |

品牌名可以在角落持续出现，收尾用 1–2 秒保留结果和软件名。不放多秒独立 Logo 片头。每条只设一个轻量收尾动作，例如“下次复制，留一份历史”，不同时要求点赞、关注、评论和下载。

## 3. 两种时长模板

### 15 秒：一个小麻烦，当场解决

| 时间 | 内容任务 | 画面任务 |
|---|---|---|
| 0–2 秒 | 点出痛点 | 先出现问题材料，不先展示功能清单 |
| 2–4 秒 | 给出解决方向 | 进入对应真实界面，功能名称简短出现 |
| 4–10 秒 | 只做主要动作 | 点击、选择、输入或变换；鼠标与状态变化一致 |
| 10–13 秒 | 证明结果 | 保持结果可读，必要时做同一材料的前后对照 |
| 13–15 秒 | 收尾 | 结果继续可见，加入软件名与一句提示 |

配音初稿控制在约 40–55 个汉字量级，英文、数字和停顿另算。该范围只是起稿预算，最终以实际合成或录音时长为准。结果至少留 2 秒阅读；不通过逐句突然加速来塞进 15 秒。

### 25–28 秒：一个完整操作流程

| 时间 | 内容任务 | 画面任务 |
|---|---|---|
| 0–3 秒 | 交代痛点 | 展示一个具体工作场景 |
| 3–7 秒 | 建立方法 | 展示材料和功能入口，省略与本条无关的设置 |
| 7–18 秒 | 完成操作 | 保留关键步骤与反馈，复杂过程可延续至 20 秒 |
| 18–23 秒 | 展示结果 | 展示源码结果面板、冻结演示文件或双端状态示意 |
| 23–25/28 秒 | 解释价值并收尾 | 只复述这件事的收益，不扩展功能列表 |

配音初稿约 70–95 个汉字量级；仍以实测时长为准。无法在 28 秒内清楚说明的选题，缩小本条的目标，而不是增加语速。最终文件总时长不超过 30 秒。

处理进度与等待由帧时间线控制，系统、网络和 AI 状态须标为演示，不把视频中设定的处理时间当作软件实际耗时。若复用已有媒体，裁切或时间压缩也要在素材说明中记录。

## 4. 整体选题池

共 46 个核心选题，覆盖八组使用场景。这是持续制作的选题池，不代表一次全部开拍。功能相近的条目使用不同的输入和结果，避免只是换标题重复同一个演示。

表中生成方式均属于同一源码管线，差别只在驱动哪类数据：

- **组件＋状态序列**：原组件接收按帧计算的输入、选择、进度和反馈。
- **组件＋本地运算**：直接复用软件纯函数或组件处理逻辑，核对计算前后结果。
- **组件＋数据快照**：视频适配层模拟保存、恢复、导入等接口，演示模型按动作更新；不写入真实数据库。
- **组件＋媒体示意**：原工具条、结果面板或播放器结合冻结图片、长图、视频、动图等演示素材。
- **组件＋双端状态**：在同一视频工程内渲染两份源码界面，用一致的设备和材料数据展示流程；不连接真实设备。
- **组件＋AI示意**：复用 AI/MCP 相关组件及门控，加载冻结回答、引用或工具结果；不请求模型、不产生费用。

普通片常驻“演示数据”；粘贴、OCR、录屏、同步、远程和 AI 等效果在对应区间补充“效果示意”“识别结果示意”“会话示意”或“回答示意”。辅助输入框只承担效果展示，标为“粘贴效果示意”，不冒充产品新增页面或真实第三方软件窗口。

## 7. 视觉、配音与声音规范

### 竖屏镜头

- 产品 UI 是主角。每个镜头只聚焦一个按钮、输入区或结果区；需要上下文时短暂拉远，再回到操作位置。
- 直接渲染原组件与 CSS；裁切和镜头运动作用于源码渲染区域，不用桌面截图或重画的相似界面替代软件 UI。
- 软件名常驻小标识，痛点标题靠上，操作区居中，字幕与结果错开；关键内容不紧贴画面边缘。具体遮挡区在选定发布平台后做预览确认。
- 字幕通常一行，必要时两行；每句只强调一个词。保留真实 UI 的字段名、提示和结果，不用大字遮住证据。
- 镜头移动用于让观众看清操作，不在每个点击后无目的地缩放。鼠标先移动到真实控件，再点击；切换目标时保留连续轨迹。
- 弹窗、标签页和结果切换保留短的过渡，不使用单帧换屏营造操作卡顿。
- 将源码中的动画转换为可按帧定位的进度；适配原 CSS / Framer Motion 时保留入场、退出和状态过渡的意图，不直接丢弃动画属性导致硬切。时间线不依赖真实时钟或无法重放的定时器。

### 声画对齐

- 每条先确定操作时间线，再写配音，最后依据实际发音时长调整镜头停留。
- 将旁白拆成“输入、点击、处理、结果”等动作句，分别绑定可见画面区间。
- 解说格式化时必须出现原组件及计算结果；解说粘贴时必须出现一致的内容和粘贴效果示意；解说同步时必须出现对应的双端状态示意。不能把帧驱动状态说成本次原生操作或网络传输实测成功。
- 配音中的动作顺序与画面一致，不用一段笼统功能说明覆盖多个不相关镜头。
- 相同系列使用同一中文声音与基础语速；超过时长时先删字或缩小演示目标，不逐句改变速度。
- 英文缩写和产品名先试听，确保读法稳定。正文字幕可使用标准写法，配音输入可使用便于发音的形式。

### 混音

- 背景音乐只承担节奏和留白衔接，人声出现时降低音乐。
- 系列保持同一响度口径，沿用现有约 -16 LUFS、约 -2 dBTP 的目标，再检查最终编码后的实际值。
- 点击音只在源码时间线对应点击发生的帧出现，不靠密集音效掩盖生硬的 UI 切换。
- 不把已经断开的句子用音乐包装成“声音连续”；允许自然停顿，但避免每句都像重新开始一个广告。

## 8. 演示素材与源码一致性要求

| 场景 | 可使用的演示材料 | 制作时必须保存的内容 |
|---|---|---|
| 历史、片段、待办 | 虚构会议地址、常用回复、普通任务 | 初始数据、帧状态序列、内容对应关系、效果示意标签 |
| OCR、打码、长截图 | 自制清晰文字图片、虚构手机号、代码生成页面 | 原图、冻结文字/坐标、绘制逻辑、媒体示意说明 |
| JSON、SQL、Diff、日志 | 小型公开或自制样例；只设一个核心差异 | 输入、调用的真实本地逻辑、输出与正确性核对 |
| 文件转换与导出 | 虚拟文件清单、公开测试内容 | 演示接口响应、内容预览、实际编码素材或结果示意说明 |
| 版本、回收站、笔记 | 视频工程内的数据模型 | 保存/删除/恢复前后快照、动作与数据变化的映射 |
| 设备互联 | 一组虚构设备和同一份材料 | 两份源码组件、对应的双端状态、同步或会话示意标签 |
| AI、MCP | 公开材料、冻结回答与演示笔记 | 来源说明、配置状态、引用映射、回答/工具结果示意标签 |

软件能力以当前源码为依据，视频状态以演示时间线为依据，两者要分清。格式化等确实在工程中执行的本地逻辑可以展示计算结果；OCR、数据库、剪贴板、网络、远程会话和 AI 等未执行的系统能力必须展示为示意，不编造实测成功或性能数字。

不访问个人数据库、不读取真实密钥、不连接真实设备。原生接口在视频适配层内返回符合源码契约的演示值；云端调用入口被阻断。只有 AI 选题展示演示开启状态并走原组件门控，其他选题维持 AI 关闭。AI 镜头也只使用冻结数据，不更改产品的可用性判定代码。

不宣传“所有功能离线”“从不联网”或“百分之百识别正确”：本地 OCR、本机存储、可选 AI、同步和更新应按各自能力准确表述。敏感内容防护仅演示当前代码支持的虚构模式，不宣称覆盖全部秘密数据。

## 11. 发布后的观察与调整

先用首批八条建立本账号的实际基线。平台有对应数据时，记录开头留存、观看时长、完播、收藏、功能相关评论和实际下载入口点击；没有数据就留空，不自行推算。

| 观众表现 | 优先检查 | 下一条如何调整 |
|---|---|---|
| 开头就划走 | 标题是否具体，第一帧是否看得出麻烦 | 将材料和痛点提前，不增加功能清单 |

| 收藏和功能提问较多 | 哪个具体场景引起兴趣 | 制作同一功能的另一个真实场景，不原样重发 |
| 质疑效果或真实性 | 原组件与流程是否对应，示意标注是否清楚 | 补完整源码状态流程，核对本地计算结果，改正过度表述 |
