# PastePanda 文档页：拆分双路径 + 手册任务化改造

日期：2026-08-22
状态：已实施（文案待用户复核）

## 背景

`docs/manual/index.html` 是一个 355KB / 3926 行的自包含单文件，同时承担两个角色：宣传落地页（首屏 + 8 个动态演示 + 场景 + 下载区）和完整功能手册（19 个分区、10,483 字）。

起因是「首页改成亮白色风格」。该需求已由用户在本轮会话中自行完成并经核验通过，**不在本设计范围内**：

- `src/lib/theme.ts:21` `DEFAULT_THEME` 已为 `"ocean"`
- 三处深色假设已同步修正：`DiagramFullscreen.tsx:55`、`fullscreen/RichFullscreen.tsx:55` 去掉了 `theme === ""` 判暗分支；`FullscreenEditor.tsx:241` 注释已更新
- 文档页 `<html data-theme="ocean">`，`.hero`（第 327 行）与 `.dl`（第 776 行）基样式改为走主题变量，深色主题由 60 个 `[data-theme="ocean-dark"]` 覆盖块还原
- 对比度已扫描：基样式中 28 处 `#fff` 全部位于强调色/渐变底之上，`.hw-toast` 的 `#E6EDF7` 位于 `rgba(10,20,36,.92)` 深底之上，行内亮色文字零残留

白化收尾后暴露出三个更深的问题，是本设计要解决的：

1. **入口错配。** `src/components/UpdateNotesDialog.tsx:29-30` 的 `MANUAL_URL` 指向 `.../manual/index.html`，**不带锚点**。刚升级完的老用户在更新弹框点「全部功能详解」，落点是宣传首屏，要滚过约 5 屏营销内容才够到「快速开始」。他最不需要看的就是「立即下载」。
2. **手册是功能目录，不是任务文档。** 目录分组为 入门/核心功能/进阶/智能/其他，19 个分区名全是功能名。用户带着任务来（「我想把截图里的文字抠出来」）得先猜它归在哪个功能名下。宣传区已有 4 个人物场景卡（程序员/设计师/产品运营/日常办公），手册完全没继承——场景思维停在营销层就断了。
3. **零渐进披露。** 19 个分区、10,483 字全程展开：`<details>` 数量为 0，手册内无搜索，19 个分区里 9 个纯文字无演示，全手册仅 3 处提示框，表格只有「快捷键一览」有。

## 已确认的决策

| 议题 | 选定 |
|---|---|
| 为谁优化 | **C**：两条路径分开，两类用户都不将就 |
| 文件层面 | **方案 2**：拆两个文件 + 共享样式表 |
| 手册信息架构 | **方案 A**：加任务索引层，保留 19 个功能参考区 |
| 文字处理 | **②**：改写最枯燥的几节，其余不动 |

## 前提已验证：CSS 归属足够干净

| 归属 | 类数 |
|---|---|
| 只在宣传区使用 | 306 |
| 只在手册区使用 | 171 |
| 真正共享 | **37** |
| 页面内无引用（死样式） | 7 |

37 个共享类中，多数是嵌套小助手（`c` `d` `n` `p` `t` `on` `ic` `lb` `dot` `hint` `note`）和色片（`blue` `green` `pink` `purple` `cyan` `amber`）。有一簇是真组件：`annot-toolbar` / `tool` / `tsep` / `ocr-head` / `ocr-body` / `ocr-row` / `ocr-foot` / `ocr-drawer` / `copy-all` / `fbtn`——截图标注 UI 在宣传演示和手册截图章节**都出现**，必须共享。

## 架构：三文件

部署目标是静态站（Cloudflare Pages + GitHub Pages），多文件无成本。

```
docs/manual/
├── shared.css     6 套主题令牌、reset/base、排版刻度、色片、
│                  截图标注簇（annot-toolbar/tool/tsep/ocr-*）、
│                  .top 顶栏、.cta 按钮、主题切换器样式
├── shared.js      主题切换 + localStorage("pp-manual-theme") + 目录高亮
├── index.html     宣传页：hero / statband / featrow×4 / bento×4 /
│                  粘贴栈 / pp-grid / scenes / download
│                  + 8 个演示舞台的 CSS 与播放引擎（宣传独占）
└── manual.html    手册页：吸顶头 + 搜索 + 任务索引 + 19 个参考分区
                   + 手册 mock 的 CSS（.win/.app/.set-app/.snip/
                     .menu/.tray/.hub/.dlg 等，手册独占）
```

演示播放引擎只服务宣传区的 8 个舞台，留在 `index.html`，不进 `shared.js`。

主题切换器两页都有且共用同一个 `localStorage` 键，所以切换逻辑必须进 `shared.js`——否则两页主题会不同步。

两页互链：宣传页的 `.manual-bridge` 指向 `manual.html`；手册页顶栏加一个回宣传页的链接。

## 手册页设计

### 1. 任务索引层（新增，置于手册页顶部）

替代原先「滚 5 屏营销内容」的落点。每条任务是一个可点的卡片，锚点直达参考区的确切位置。任务措辞用用户的话，不用功能名：

| 任务 | 落点 |
|---|---|
| 把截图里的文字变成可编辑文本 | `#screenshot` OCR 段 |
| 刚复制的东西找不到了 | `#clipboard` |
| 连续填表，全程不碰鼠标 | `#paste` 粘贴栈段 |
| 把 Excel 一列拆成多次粘贴 | `#paste` 粘贴栈段 |
| 把 JSON 格式化后再贴出去 | `#transform` |
| 两份配置对比差异 | `#dev` |
| 把设计稿钉在屏幕上对照 | `#screenshot` 贴图段 |
| 给截图打码再发出去 | `#screenshot` 遮罩段 |
| 让 AI 解释这段报错 | `#ai` |
| 常用话术模板存起来 | `#snippets` |
| 批量提取链接 / 邮箱 / 电话 | `#dev` |
| 不想让某条被自动清理掉 | `#clipboard` 置顶段 |

人物角色（程序员/设计师/产品运营/日常办公）退化成任务卡上的标签，用于筛选，不单独开轨——避免同一功能在多个角色下重复，也避免程序员做设计类任务时找不到路。

### 2. 参考区渐进披露

- 长清单、菜单逐条枚举、边缘选项一律包进 `<details>` **默认收起**，摘要行写「共 N 项」让用户知道里面有多少。
- 每个分区保留一句 `.lede` 常驻可见，收起的只是细节。
- 9 个纯文字分区（`snippets` `dev` `editor` `menu` `sync` `report` `clipboard` `paste` `hotkeys`）优先补一张已有 mock 或提示框；不硬凑，补不出来的就靠折叠降密度。

### 3. 手册内搜索

纯前端、无依赖：把各分区标题 + `.lede` + 任务索引条目建成一个内存索引，输入即过滤，命中项高亮并折叠无关分区。吸顶放在手册页头部。

### 4. 改写最枯燥的分区

按「什么时候用 → 怎么做 → 注意什么」三段式改写，范围限定三节：

- **`menu`（576 字，零列表零演示）** 最差。现状是「以下为真实结构」+ 把菜单项逐条抄一遍 + 一段跑句罗列「其他右键弹窗（真实）：深度清理、内容提取、编码转换、文本对比…」。读完知道有哪些菜单项，不知道什么时候该用。
- **`transform`（1160 字，全手册最长）** 16 个列表项平铺。
- **`clipboard`（640 字，12 个列表项）** 同样是平铺枚举。

改写纪律：每条陈述必须对回源码或既有文案，不新增未经核实的行为描述。原文中的溯源注释（如「尺寸取自 TopBar.module.css」「这五个数字全部核过源码」）一律保留——那是这份手册准确性的凭据。**改写属于内容变更，需用户复核文案。**

### 5. 修正 mock 与真实 UI 的偏差

审计发现的确凿偏差（均已对源码核实）：

- **相对时间。** 真实卡片走 `src/lib/utils.ts` 的 `relativeTime()`：刚刚 / N分钟前 / N小时前 / 昨天 / N天前。mock 写的是绝对钟点（`12:31` `10:05`）。改为相对时间。
- **臆造的「内容类型」徽标。** mock 每张卡挂 `.hw-c-type`（代码/文本/图片）。真实 `Card.tsx:403-417` 副行只渲染：置顶 → 来源 → 尺寸 → OCR → 颜色格式 → 标签，**没有内容类型徽标**；`src/components` 全局无 `cardTypeTag`/`contentTypeTag`。这个徽标是照 `Card.tsx:399` 一句过时注释臆造的。删掉徽标，并顺手修正 `Card.tsx:399` 那句注释（它是偏差的源头）。
- **图标形态。** 真实顶栏与卡片图标是自绘 SVG / lucide（`Icon size={18} strokeWidth={2.2}`），mock 全用 emoji 替身。**本轮不改**——页脚已声明「界面演示为手工复刻」，全量换 SVG 工作量与收益不成比例。记录为已知取舍。

`TABS` 已核对一致（`TopBar.tsx:19-28`：全部📋/文本📝/图片📸/文件📁/收藏⭐），无需改动。

### 6. 修正入口

`src/components/UpdateNotesDialog.tsx:29-30`：

```
MANUAL_URL        → https://pastepanda.pages.dev/manual/manual.html
MANUAL_BACKUP_URL → https://lzlkyb.github.io/pastepanda/manual/manual.html
```

老用户点「全部功能详解」直达手册页顶部的任务索引，不再落在宣传首屏。`src/__tests__/UpdateNotesDialog.test.tsx` 若断言了 URL 需同步更新。

## 实施记录（2026-08-22）

产物：`docs/manual/` 下 `shared.css`（18.7KB）、`shared.js`（1.7KB）、`index.html`（220KB，宣传页）、
`manual.html`（140KB，手册页）。拆分与折叠都由一次性脚本机械完成，不是手抄。

### 与本设计不一致的地方

1. **死样式只清了 4 条，不是 7 条。** 设计稿列的 `active` `show` `cur` 是 **JS 动态加的**类
   （目录高亮 `nav.toc a.active`、演示引擎的 `.hw-sugg.show` / `.pstep.cur`），HTML 里搜不到
   不等于没用，删掉会静默坏掉功能。实际清掉的是 `.tbox` `.tag.cfg` `.tag.cmd`
   `.pe-line.pasted`——这四条确实只有定义、零引用。另外 `.layout` 不是死样式，拆分后
   它是手册页的 toc+main 布局容器，转为手册页独占。

2. **第 5 项「修正 mock 与真实 UI 的偏差」在本设计写成之后已由上一轮完成。** 现文件里卡片时间
   已是 `3分钟前 / 1小时前 / 2小时前`，臆造的 `.hw-c-type` 徽标已删（副行只剩
   pin/src/size/ocr/tag，与 `Card.tsx` 一致），图标也已从 emoji 换成内联 lucide SVG
   （`.lc-ic`）——所以第三条「本轮不改 emoji」这个取舍已不存在。本轮只补了偏差的源头：
   `Card.tsx:399` 那句写着「→ 内容类型 →」的过时注释。

3. **渐进披露做的是整节收起，不是只折长清单。** 按「≥5 项的清单」折只能折 7 块，对
   「19 个分区 10,483 字全程展开」这个问题基本无效。改成每个分区 `h2` + 一句 `.lede`
   常驻可见、其余正文进 `<details>` 默认收起，摘要写「N 张演示图 · N 小节 · 共 N 项」。
   `#start`（快速开始）例外，常驻展开——新用户落地第一眼不该还要点一下。
   另配「全部展开 / 全部收起」，照顾要 Ctrl+F 全文查的人。

4. **`#dev` 与 `#paste` 的两个落点微调。** 「把 Excel 一列拆成多次粘贴」落到 `#paste-seq`
   （依次粘贴）而不是粘贴栈段——「表格自动拆行入栈」这句原文就写在依次粘贴那一节。

5. **`UpdateNotesDialog.test.tsx` 没有断言 URL**，所以入口改动不需要同步改测试
   （已跑 `npx vitest run src/__tests__/UpdateNotesDialog.test.tsx`：9 passed）。

### 拆分对手册页唯一的排版影响（有意接受）

脱掉 `.manual-bridge` 外壳后，两条**后代选择器漏下来的**样式失效，手册回到自己的设计值：

- 段落与 `.lede`：13.5px → **14px**（原先被 `.manual-bridge p` 压着，连 `section > .lede`
  显式写的 14px 都被它盖掉）
- 分区标题字重：800 → **700**（`section > h2` 的设计值，原先被 `.manual-bridge h2` 盖掉）

横向位置**完全没变**（`.layout` 在两边都是 x=110 / w=1180，外壳那 28px padding 被居中吸收了）。
用一个「把这两条加回去」的对照版验证过：除此之外零漂移。

### 顺手修掉的三个 bug

1. **分区级锚点不展开正文**（本轮引入）。`revealTarget` 只往上找祖先 `details`，而分区的
   `details` 是 `section` 的**子元素**——左侧目录的每一条都是分区级锚点，等于整个目录点了没反应。
2. **`nav.toc` 在 ≤860px 横向溢出**（拆分前就有）。基样式的 `align-self: flex-start` 在
   `.layout` 变成纵向 flex 后管的是横轴，目录按 max-content 收缩到近 1900px，
   `overflow-x: auto` 因为盒子从没被约束过而永不生效，整个手册页在手机上出横向滚动条。
   加 `align-self: stretch` 修掉。
3. **页脚新增的两页互链吃浏览器默认链接蓝**（本轮引入）。`#0000EE` 在午夜主题 `#0B0B13`
   底上对比度只有 2.09。已在 `shared.css` 给 `footer.page a` 显式配色。

### 已知的既有问题（不在本轮范围）

对比度扫描发现**基线本身**有 132 种不达标配色组合、约 1200 处实例，集中在两处：
手册 mock 里的徽章与按钮（`.tag.api` / `.btn.p` / `.cs-n` 等，白字压在强调色上，比值 2.8–4.2），
以及 4 套渐变底主题下 `--text-muted` 压在渐变最深色标上（约 3.3）。这些拆分前后一样，
本轮一处未动。要治的话是一轮独立的设计令牌调整。

### 验证手段上踩过的两个坑（写下来免得重踩）

- **用 `#锚点` 让无头 Edge 滚过去再截图会拿到纯白图**：它在目标位置光栅化完成前就截，
  与 flag 无关。可行做法是注入 `body{position:relative;top:-Npx}` 把目标区顶到首屏。
- **把窗口开到 `1440x34000` 一次截全页也不行**：页面里大量 `vh` 单位（hero `min-height`、
  氛围层 `translateY(-112vh)`）会被超高视口整体拉变形，比出来的差异是量测手段的假象。
- 另外测主题时不能靠 JS 切换后读 `getComputedStyle`：`body` 有 `transition: background .3s`，
  读到的是**过渡中间值**，同一页面跑两次能得出两种颜色。要在 HTML 里钉死主题 + 全局禁过渡。

## 追加一轮：亮色主题下的残留暗色（2026-08-22）

反馈是「页面默认亮白，但还有一些显示为暗色，要统一跟随主题」。先程序化扫出亮色主题下
**自带**暗背景（亮度 < 0.18）的元素，宣传页 31 类、手册页 10 类，再逐类对源码定性。

### 结论：绝大多数暗色是忠实还原，不能改

| 暗色元素 | 为什么必须留 | 出处 |
|---|---|---|

### 另一个量测坑（第三个了，一并记下）

读 `getComputedStyle` 验状态机时，元素上的 `transition` 会让你读到**过渡中间值**：

和之前测主题时踩的是同一个坑 —— 凡是用计算样式做断言，都要先注入
`*{transition:none !important;animation:none !important}`。

## 产品端修正：--orange-solid（2026-08-22）

上一节报的问题（深色主题下栈序号角标白字只有 2.26:1）已在产品端修掉。

### 根因

`--orange` 一个令牌被当两件事用，而这两件事需求相反：

- **深底上的文字色** → 深色主题必须给偏亮的 `#FB923C`
- **实色填充**（配 `color: #fff`）→ 需要足够暗，白字才够对比度

深色两套主题里 `--orange` 是 `#FB923C`，白字压上去 2.26:1。浅色四套是 `#C54A0A`，
白字 4.82:1 本来就没问题 —— 所以这个 bug **只在深海 / 午夜两套**。

代码里对 `--accent` 早就有现成分工：文字色用 `--accent`，实色填充用 `--accent-solid`
（例：ocean-dark 的 `--accent` 是 `#3B9EFF`，`--accent-solid` 是压暗的 `#2D78C2`）。
橙色缺了对应的那一半。

### 改法

`src/styles/theme.css` 那个「只声明一次、6 主题自适应」的 `:root` 块里新增：

```
--orange-solid: #C54A0A;
```

取值就是浅色主题的 `--orange`：白字 4.82:1 达标，且在深海 `#0A1628` / 午夜 `#18181B`
的卡片底上仍有 3.76 / 3.68 对比度（图形元素门槛 3.0）。6 套主题同值所以只写一次，
**浅色四套零视觉变化**。

同类候选对比（白字压上去的对比度）：`#FB923C` 2.26 ✗｜`#EA580C` 3.56 ✗｜
`#C2410C` 5.18 ✓｜`#B45309` 5.02 ✓｜`#C54A0A` 4.82 ✓（在深底上最醒目，故选它）。

### 改到的 5 处

用脚本按「规则块里同时有 `background: var(--orange)` 和白字」扫全部 CSS，不靠肉眼找：

| 文件 | 规则 | 是什么 |
|---|---|---|
| `CardList.module.css` | `.stackBadge` | 卡片左上角的栈序号角标（本次反馈的那个） |
| `StackBanner.module.css` | `.primaryBtn` | 栈横幅的「逐条粘贴」主按钮 |
| `StackBanner.module.css` | `.chipNext .ord` | 队列里「下一个要贴」那颗序号 |
| `StackBanner.module.css` | `.nextTag` | 「下一个」小角标 |
| `ChainRunnerDialog.module.css` | `.aiGo` | 动作链里的 AI 确认按钮 |

剩下 6 处 `background: var(--orange)` 是纯色圆点 / 装饰条，上面没有文字，不动。

手册页的 `.sk-n` 同步跟上（`shared.css` 也补了 `--orange-solid`），两边保持一致。

- `npx tsc --noEmit`：通过

## 收尾：统一亮色（2026-08-22）

用户明确要求「都要统一亮色」。前面两轮为了对齐产品实现，刻意把一批 mock 钉死深色；
本轮按用户决定改为**视觉一致优先于像素级还原**，全部改成跟随主题。

### 这一批原本为什么是深色（以及现在改了）

| 元素 | 原本的依据 |
|---|---|
| `.annot-toolbar` + `.tool` 簇 | `screenshot.css:132` 写死 indigo 玻璃渐变 |
