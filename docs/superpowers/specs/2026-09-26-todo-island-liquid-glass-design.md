# 待办灵动岛材质与形变设计（B 方案）

## 目标与基准

用户已选择“材质与灵动同等重要”，并确认 `design/待办灵动岛-B方案-材质与形变对照-设计稿.html` 的目标方向。保留现有五舞台、待办数据来源、主屏顶部居中与顶部 10px 锚点。目标是让胶囊到卡片的形变、内容切换、单层受光玻璃成为一个连续反馈，同时保证任意桌面背景下的文字与点击可用。

原始 `design/待办-灵动岛交互-设计稿.html` 是视觉参考；后续实测和当前源码优先。当前直接给 Tauri WebView 窗口加 Acrylic 的路线已实测在胶囊四角漏出方形材质，不再重复该实验。HTML 中的 `backdrop-filter` 只用于预览模拟。

## 材质架构与探针门槛

岛始终只有一层玻璃承载面；列表行、分段控件与按钮只用轻量洗色、文字和边缘反馈，不叠加 `backdrop-filter`。先保留现有 CSS 四档作为可靠基线。原生探针仅验证一个新假设：独立的 Windows Composition 背景视觉或宿主位于透明 WebView 内容下方，通过圆角蒙版采样窗后内容，并能与现有舞台几何同步。不采集桌面像素到应用内存，不引入持续屏幕捕获。

探针只覆盖 208×32 胶囊和 420×240 卡片，不接待办业务。先用高饱和 tint 与动态棋盘背景查方角，再用移动文字验证真正的实时背景模糊。两种形状的圆角外像素应与窗外一致（仅允许 1px 抗锯齿边）；岛内应随着背后内容实时变化且高频细节被模糊；WebView 内容、层级、焦点、鼠标穿透正常。任一形态出现方角、矩形闪帧、只显示静态染色或阻断窗外点击，原生路线即 no-go，正式产品继续使用 CSS 四档。

不为探针增加默认常驻线程、额外 WebView 或重复采样层。若需要新 Windows API，先确认本项目支持的 Windows 11 build 22000 与现有 `windows` crate 功能；不能靠只支持更高系统版本的 DWM 属性作为唯一实现。

## 形变与内容

尺寸仍是 `pill 208×32`、`peek 300×40`、`list 420×240`、`compose 420×280`、`clear 208×32`。现有 Rust 弹簧参数 `k=130,c=16` 保持唯一；快速改变目标时连续接续当前位置与速度，避免每次从静止重新起跳。宽、高、水平中心、裁剪轮廓必须来自同一舞台几何，不在两端分别猜测。若原生材质探针通过，其蒙版也使用同一几何。

内容以“形体先响应、内容随后出现”为时序：展开时折叠内容先退，卡片有足够空间后列表在 150–200ms 内淡入并轻微向上就位；收起时列表先退，再显折叠内容。`compose` 与 `list` 共享列表，只变底部输入区。频繁悬停、点击或 Esc 期间只保留最后目标，不出现旧计时器把新状态覆盖的情况。系统减少动态效果开启时使用无过冲/直接切换，信息与操作仍完整。

勾选操作维持当前乐观写回和失败提示；先让勾圈在 150ms 内明确变成完成态，再让行在 200ms 内退场并更新计数与进度环。输入草稿继续保存在不卸载的父级。展开态失败信息不得被折叠或动画隐藏。`peek` 显示当前任务的真实到期信息，没有真实到期时不填演示文案。提醒态不得把两条任务文字拼接。

静止态无常驻装饰动画。悬停只让受光边缘随输入短暂响应；窗口隐藏时停止新增计时器、帧循环与背景采样。列表内没有逐行玻璃层。

## 视觉与可用性

设计稿右侧的受光方向、单层边缘、内侧暗边及两层投影是目标观感；材质透明度是试值，须按真实背景与系统能力校准。深浅主题均要在白文档、深色应用和彩色壁纸上检查：主文字至少 4.5:1，非文字图形至少 3:1；触点至少 24×24，键盘焦点可见。视觉统一遵守 `docs/PastePanda-UI规则.md` 的 U/L/V 条文。高对比度、透明效果关闭或系统减少动态效果时保持可读的实色/低动效回退。

## 验收与范围

验证 100%、125%、150% DPI，亮暗主题和上述三类背景；连续 `pill→peek→list→compose→list→pill`、快速反向切换、全清延迟、鼠标穿透、窗外点击、截图/远程会话隐藏和多屏主屏锚点。记录探针像素对照、常驻内存与动画 CPU 相对现状的变化，不在未测量前宣称性能改善。

本轮只调整灵动岛材质、舞台动画和相关内容反馈。不改待办存储协议、设置项含义、版本号；不构建 exe。当前工作树已有相关未提交变更，实施应保留这些变更并只提交本任务明确修改的文件。
