# 手机端统一体验升级方案

日期：2026-10-06。状态：调研与可点击设计稿，等待范围确认，尚未修改产品实现或安装新 APK。

## 目标与边界

沿用用户已确认的画面优先、A 融合页头、四种操作方式和现有 React / Tauri 架构。将手机远程会话的全屏、反馈、提示位置、操作状态和响应式规则收口，再扩展到设备、文件、设置页。商业级体验以可验证的行为为目标，不以增加装饰或动画数量为验收。

当前证据来自源码审查、用户报告及设计稿浏览器验证。本轮 `adb devices -l` 未发现手机，未复现真机状态栏、输入法或帧率表现。设计稿中的电脑画面、延时、设置确认是模拟数据。

## 已确认的问题

| 优先级 | 证据位置 | 问题与影响 | 修正方向 |
|---|---|---|---|
| P1 | `src-mobile/session/useOrientationLock.ts` / `ui/useMobileLayout.ts` / Android `MainActivity.kt` | 点击横屏才请求 DOM 全屏；系统旋转只改变布局。Activity 仅开启 edge-to-edge，没有会话级原生沉浸控制。横屏布局不代表系统栏隐藏。 | 独立管理原生会话显示状态，进入/退出/前后台/方向变化均同步。浏览器全屏仅作网页回退。 |
| P1 | `session/RcMobileSession.tsx` 的 `pickQuality` | 先 `setQuality`，再用无返回值的 `sendRaw` 发送；失败不回滚选中项，没有此操作的等待、成功、失败与重试状态。 | 分开已确认值与请求值；请求期间不把新值标成已生效。 |
| P1 | `session/sendChannel.ts` / `useRcMobileInput.ts` | 设置与连续键鼠输入共用一个最近发送健康位；下一次任意发送成功就会清除失败。不能据此判断画质应用成功。 | 手势健康与设置结果分开；设置持有操作标识和独立结果。 |
| P1 | `src-tauri/src/rc/inbound.rs` 的 `SetQuality` / `rc/notify.rs` | 被控端设置成功只调用本机前端通知，失败写日志。此路径没有向手机回传对应请求的应用结果。 | 新增兼容的设置结果回执；区分送出、本机配置已接受、远端已应用。旧端明确显示未确认。 |
| P1 | `session/SessionFeedback.tsx` / `RcMobileSession.module.css: feedbackSlot` | 多个错误可同时渲染；绝对定位反馈层最多占画面 40%/240px，内有按钮，会覆盖远程目标并截获该区域触摸。 | 普通结果就地；持续异常聚合；可操作摘要置于独立区域，详情由用户打开。 |
| P1 | `SessionFeedback.tsx` / `ui/MobileSheet.tsx` | 横屏失败等反馈放在会话根反馈槽，工具面板打开时其背后反馈不可见。 | 面板触发的结果放面板内；收起后未完成操作由常驻会话状态承接。 |
| P2 | `session/useImmersiveCapsule.ts` | 每场会话首次横屏均展开 15 秒教学，然后保留提示气泡/脉冲直至用户操作。重复远程的用户仍被重复教学。 | 保留可见工具入口；提示按功能版本记忆，首次就地一次性教学，可立即跳过。 |
| P2 | `session/useOrientationLock.ts` 的 `exitLandscape` / `SessionToolbar.tsx` | “切换到竖屏”实际调用解锁方向；手机仍横放时不保证进入竖屏。全屏成功但锁方向失败时，卸载清理仅检查 lockedRef，可能漏掉已进入的 DOM 全屏。 | 锁方向、沉浸状态和资源所有权分别跟踪；按钮行为与文案一致。 |

其他已见到的同类路径：声音开关和键盘模式也会先改本地状态再发送，需要同一轮纳入设置结果机制。`qualityHint` 来自当前服务 `status.quality`，`service/lifecycle.rs` 明确从本机 CFG_QUALITY 取值，这是手机本机推流偏好，不是电脑编码器确认；应随回执或远端媒体配置元数据对齐。已有注释“手机就是编码端”与 outbound 控制电脑场景不符，应随修复纠正。

仍需真机验证：刘海/挖孔和系统导航避让、中文上屏、预测返回、旋转期间拖拽键释放、弱网断流后的恢复、120Hz 手势跟手度、大字号和深色对比。未测试前不宣称有 bug 或已经达标。

## 对照成熟产品与官方规范

- [AnyDesk Android 官方说明](https://support.anydesk.com/docs/anydesk-for-android)：会话菜单集中管理输入方式、显示、操作和退出，并可进入/退出全屏。借鉴按任务分组的工具入口；保留本项目常驻文字“工具”，不引入依赖长按 Logo 才能发现功能的入口。
- [Jump Desktop 手势配置官方说明](https://support.jumpdesktop.com/hc/en-us/articles/216423963-General-Jump-Desktop-file-formats)：iOS 手势配置有标准、触控板和直接触摸等模式。这支持现有四种方式的选择思路；不能由此推断其 Android 布局或动画表现。
- [Android 沉浸模式](https://developer.android.com/develop/ui/views/layout/immersive)：通过 WindowInsetsControllerCompat 管理系统栏，边缘滑动可临时唤出并自动隐藏。远程横屏会话适用，普通列表页恢复系统栏。
- [Android 短消息规范](https://developer.android.com/develop/ui/views/notifications/snackbar)：短反馈要清晰可见且界面仍可操作，可附加行动入口。远程画面里采用独立状态区或工具区内反馈，而非大块叠加提示。

以上是官方文档调研，未实际安装或亲自操作竞品，动画速度不按猜测复制。

## B 的行为规则

### 原生全屏与适配

- 远程会话横屏：隐藏状态栏和系统导航栏；允许边缘滑动临时唤出。退出会话恢复；普通设备/文件/设置页正常显示系统栏。
- 系统旋转和显式切换走相同显示状态；前后台恢复重新应用当前状态。方向锁与是否沉浸分开，避免把 DOM fullscreen 等同于 Android 系统栏隐藏。
- 画面按比例显示，可捏合缩放和回到指针；不为了铺满而拉伸、裁掉远端内容。系统栏隐藏后不再保留状态栏空白，但刘海和返回手势危险区仍保护交互控件。
- 横屏：窄工具列，画面占剩余区域的全部高度；竖屏：紧凑页头和底部工具；面板横屏侧开、竖屏底开，标题/关闭固定、正文滚动。
- 输入法变化单独处理，不以可视窗口缩小判断方向。短横屏内容不足时允许面板内部滚动，不裁掉关闭和重试入口。

### 真实操作结果

- 设置状态：已确认值 → 请求中 → 电脑确认成功 / 明确失败 / 超时未确认。网络写入成功只算已发送，不能直接显示已生效。
- 对端回执包含请求标识、设置键、接受值或失败原因；并明确区分配置接受与编码器重配置完成。若只做到配置接受，文案说“电脑已接受设置”，不可声称画面已经换档。
- 请求中显示目标档位，已生效标记继续指向旧值；失败保留旧确认值并可重试。超时仅表示未确认：不自动向远端回滚，也不保证旧配置仍生效；后续回执/元数据需重新对齐。
- 连续选择只采纳最新请求结果；按会话隔离，避免上一会话迟到消息污染当前界面。相同值无需重复发送。
- 自动档分别显示“自动策略”和已知的实际档位；不把高档未知值静默显示成自动。声音、键盘模式、显示调整使用同一设置反馈模型。
- 兼容旧端：回执能力协商缺失时明确显示“已发送，电脑尚未确认”；不根据本地状态轮询假造成功。

### 提示信息与返回

| 类型 | 默认位置 | 持续与操作 |
|---|---|---|
| 选中/按下 | 操作控件本身 | 即时可见，不弹成功提示轰炸用户。 |
| 设置等待/结果 | 对应设置区域 | 不随面板关闭丢失；关闭后由会话状态接续。 |
| 短结果 | 独立紧凑状态区 | 普通结果约 4 秒；有焦点/按住/屏幕阅读需求时延长；无焦点抢占。 |
| 持续连接故障 | 一个状态入口 + 必要摘要 | 不自行消失；停止远程输入并可查看/重试。多个同因故障去重。 |
| 文件请求 | 工具或文件入口角标 | 点击处理，不自动打开面板，不遮挡远程画面。 |
| 需选择的危险操作 | 确认面板 | 只在确实需要决定时打断。 |

返回顺序：系统输入法 → 当前面板/编辑态 → 断开确认 → 退出会话。取消手势不留下鼠标 down 或修饰键状态；面板打开时冻结远程输入，关闭恢复，不把关闭面板的触摸穿透给电脑。

### 动效与细节

- 按下/选中及时响应；轻反馈 150ms、局部状态变化 200ms、面板 300ms、整页转场最多 400ms，使用项目统一曲线。
- 手势驱动的位移跟随手指，松手后的动画可中断；动画期间按钮仍能响应。减少动态效果时取消位移/缩放，静态文本状态保留。
- 触控目标至少 48 CSS px（需结合 Android WebView 缩放映射验收），关键操作有文字；选择性触觉反馈遵从系统设置，不在每次鼠标移动或滚轮上振动。
- 不增加常驻装饰动画或多层模糊。文件长名、空/加载/失败/部分成功、权限拒绝、重复提交、草稿保留均进入验收。

## B 实施记录（2026-10-06）

### 已实现

- Android 原生会话显示桥接：远程横屏隐藏状态栏和导航栏，系统边缘手势临时唤出；旋转、恢复前台和焦点重新应用；退出会话恢复原方向和系统栏。原生使用设备 Configuration 判横屏，避免输入法缩小 WebView 被误判。迟到的旧会话关闭不会清掉新会话的显示状态。
- `rc_apply_setting`：画质、声音、键盘模式使用请求 ID 和电脑回执，校验会话、请求、设置键及接受值；设置发送路径与既有输入共用权限和身份检查。电脑拒绝、会话结束、发送失败均不报成功。回执只代表电脑配置接受，文案不声称编码器已重配或声音已送达。
- 兼容旧电脑端：原输入 JSON 增加可忽略的 request_id。总等待上限 8 秒，未收到确认显示“已发送，电脑尚未确认”；不伪造成功，也不假定电脑已经回滚。当前实现采用回执超时识别未确认，尚未增加显式回执能力协商。
- 手机设置状态按键分别保存；快速选择按同一设置串行并合并被替代的待发选择，旧回执不覆盖新选择。重复点击请求中或已确认值不再发送；失败/未确认仍可重新发送。质量确认不读取手机本机推流配置。
- 画质、声音及扩展键盘的结果固定在面板底部，短屏可以滚动控件而保持结果入口可见；失败保留最后确认值。面板关闭后多个设置结果进入一个摘要，详情按操作分别保留，并可回到对应设置。
- 多个会话提示只显示一个紧凑摘要，错误优先；详情由用户主动打开，暂停远程输入，关闭恢复。清空最后提示同时清掉详情展开状态，后续通知不会自动弹出。摘要放在画面之外，不覆盖远程目标。
- 普通反馈共用约 4 秒可见阅读时间，后台、其他面板打开、焦点停留时暂停计时；错误不自动消失。文件请求移到工具入口，不自动抢占画面。
- 工具引导按安装只展示一次，提示会结束；把手动效有限次数。保留已有工具、四种指针方式和手机页面布局，不新增常驻装饰动画。查看键盘设置保持已打开键盘，不再反向关闭。
