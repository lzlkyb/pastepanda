# PastePanda UX 审查与修复（2026-10-17）

本轮按关键操作路径与公共交互机制排查，以已有 B 方案和当前 UI 为基线。重点是操作结果真实、失败可恢复、草稿不丢失、中文输入不误触、首次操作可理解。没有新增常驻动画、轮询或云端调用。

## 已修复的问题

| 范围 | 原行为 | 修复后 |
|---|---|---|
| 剪贴板搜索 | 慢请求覆盖新搜索；清空后旧结果重新出现 | 每次输入递增请求代次，只接纳当前结果 |
| 搜索取消 | 切走页面后防抖仍触发；外部清空会被待执行输入覆盖 | 卸载与外部清空同时取消定时器、使旧请求失效 |
| 搜索与 AI | AI 未就绪仍发送语义搜索 IPC | 使用统一 AI 可用性判定；不可用时只做关键词搜索 |
| 中文输入 | 搜索框、输入弹窗、工具筛选回车选词时触发业务动作；确认框 Esc 收候选时关闭 | 合成期间把按键交给输入法，工具不会被误启动 |
| 设置保存 | 保存失败仍注册快捷键、启动同步/远控服务，甚至提示恢复默认成功 | 保存返回明确结果，依赖落盘的后续操作仅在成功后执行 |
| 主题失败 | 本窗口回滚，其他窗口仍显示失败的主题 | 预览与回滚共用主题应用和广播机制 |
| 系统设置 | 置顶、自启系统操作失败，配置开关仍为开启 | 回写原值；回写失败也明确说明，不声称已恢复 |
| 快捷键失败 | 注册失败后的原值回写若也失败，仍提示“已恢复” | 根据回写结果显示真实反馈 |
| 数据导入 | 重复备份新增 0 条，被误报为全部导入；导入已提交但刷新失败，被报成导入失败 | 分别说明新增、已存在、格式跳过；刷新失败明确无需重复导入 |
| 统计加载 | API 返回 null，错误态不触发，永久加载；旧空间数据覆盖新空间 | null 显示现有重试入口；切空间使旧请求失效 |
| 文件关联检测 | 查询失败一直“检测中”，没有恢复入口 | 明确错误状态，提供“重新检测”；状态不明时禁止误切换 |
| 笔记查询 | 旧文件夹结果覆盖新结果；旧分页追加到新搜索 | 统一请求代次，防抖开始前使旧结果失效 |
| 笔记分页 | 同一渲染帧重复触发加载，重复取页 | 同步请求锁，重置查询时释放旧锁 |
| 笔记草稿 | 正文改动不足 10 字时切换会静默丢弃 | 任何实际修改都经过现有未保存保护；改回原文直接放行 |
| 笔记保存 | 连续保存可能重复创建同一篇笔记 | 同步保存锁，并在 finally 释放 |
| 笔记批量删除 | 删除失败的当前笔记也被关闭，草稿与失败选择丢失 | 只关闭真正删除的笔记，保留失败项与草稿供重试 |
| 笔记移动 | 批量或拖拽失败仍清空选中并闪出成功落点 | 两个入口共用结果回执，保留失败选择，仅真实成功时显示落点 |
| 公共输入弹窗 | Esc 把自身误判成更高层而不能关闭 | 层判定排除自身，仍向嵌套确认框让路 |
| 可理解性与辅助技术 | 知识库新建仅有“＋”；部分公共对话框和关闭按钮无名称 | 常驻“新建”文字；补齐对话框、输入、关闭、清空搜索的可访问名称 |
