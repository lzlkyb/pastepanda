## 1. 结论

手机端已经有共享组件，但还缺少共享的反馈政策。建议先确定每类事件的影响范围、恢复方式和注意力级别，再统一视觉、生命周期和动效。

核心判断：**错误的严重程度不等于打扰程度。只阻断受影响的操作；需要立即决策或无法安全继续时，才升级反馈。** 阻断当前任务与用模态弹窗是两件事。

本轮为源码和官方规范审查。两份独立审查分别检查设计和机械证据；没有可用的手机 Web 预览监听，未启动 Tauri、未做真机截图、帧率或流畅度测量。以下视觉判断基于现有 TSX、CSS 和状态逻辑，不冒充真机实测。

## 3. 当前实现的具体问题

1. `src-mobile/ui/MobileNotice.tsx` 已有五种 tone 和 inline/banner/toast，但没有统一规则决定各调用点该选哪种。所有 error 都用 `role="alert"`；颜色语义与立即播报的紧迫性混在一起。
2. `MobileToast.tsx` 直接挂载和卸载；`MobileNotice.module.css` 没有通知本身的进入、退出阶段，只有等待图标的呼吸效果。普通提示统一 4 秒，未区分长文案和操作机会。
3. 设备页、设置页部分成功反馈使用 `placement="flow"`，插入和移除会改变页面排布。控件状态已能表达的成功结果仍使用横幅，注意力偏重。
4. `devices/RcUnoJoinCard.tsx` 在接入码非空但还未解析、密码尚未输够时显示 error。正常输入过程过早变成报错，应先中性提示，失焦或提交后校验。
5. `App.tsx` 已按翻译后的文字去重，`SessionFeedback.tsx` 已聚合会话反馈；但传输页、单任务和跨页镜像还各自决定反馈方式。批量失败可能产生多个同等重量的信息块。

值得复用：语义色与图标、错误脱敏、人话翻译、暂停阅读计时、固定弹层操作区、Radix 焦点管理、现有 `mobileSpring.ts` 和弹层拖拽。

不应把这些基础全部推倒，也不应把“弹层已有弹簧”误说成“所有动画都没有”。

独立机械检查补充：`impeccable detect --json src-mobile/ui` 返回 `[]`（exit 0）；只表示本次没有触发该扫描器的规则，不能证明交互或动画已合格。排除测试后，共 106 个业务 `MobileNotice` 渲染点和 10 个 `MobileToast`，分布于 36 个文件；没有生产代码的原生 `alert/confirm/prompt` 调用。源码盘点显示现有 Toast 调用均为 flow，尚未使用浮动形态。知识库阅读页还存在多个 Notice 可并列渲染的条件，这属于需要真机复核的可能态，不是已观察到的截图问题。

## 4. 统一分级：六种处理方式

| 级别 | 判据 | 组件/呈现 | 生命周期 | 阻断范围 |
|---|---|---|---|---|
| 0 状态反馈 | 已可从控件或内容看出结果；后台短暂失败可自动恢复 | 状态文字、勾选、任务进度 | 随真实状态更新 | 无 |
| 1 轻反馈 | 用户主动操作，结果不能从当前内容明显看出 | Snackbar，最多一个主要动作 | 普通 4 秒；带撤销建议 6 秒；暂停阅读沿用现有机制 | 无 |
| 2 局部问题 | 单字段、单任务或局部区域失败，用户可修正 | 字段提示、任务错误态、局部 Notice + 重试 | 问题解决或任务被明确移除前保留 | 仅相关提交/任务 |
| 3 持续受限 | 某能力持续不可用，用户需要知道影响 | 所属区域的持久 Banner；全应用受影响才全局展示 | 恢复后收起；关闭摘要不代表故障已解决 | 仅不可用能力 |
| 4 必须决定 | 用户正要进行不可逆/敏感操作，或离开将丢失未落盘内容 | 模态确认；多项恢复选择可用 Sheet | 等待明确选择 | 当前决策流程 |
| 5 安全停止 | 当前任务无法安全继续，如身份校验失败、落盘失败、画面失效不能可靠输入 | 任务停止态/会话恢复页 + 明确退出或恢复 | 验证恢复前不能继续该任务 | 当前任务；极少需要锁住整个应用 |

不按“warning → 黄条、error → 弹窗”机械映射。先判断事件是否相关、能否恢复、继续操作的后果，再选择呈现方式。

## 5. 具体场景分类

| 场景 | 建议反馈 | 可以继续什么 | 应阻断什么 |
|---|---|---|---|
| 开关偏好、常规自动保存成功 | 控件状态/“已保存”短状态 | 全部操作 | 无 |
| 复制成功 | 按钮短暂变为“已复制”；跨区域触发才 Snackbar | 全部操作 | 无 |
| 用户主动取消、拒绝接收 | 中性“已取消/已拒绝”，通常行内即可 | 全部其他操作 | 被取消的任务结束 |
| 对方拒绝连接或文件请求 | 请求结果 + 重新请求入口；不是系统崩溃警报 | 浏览、编辑、其他任务 | 本次请求 |
| 后台在线检查/同步短暂失败 | 自动恢复期间不浮层；持续失败在所属区域保留状态 | 本地数据浏览和编辑 | 不应假装已经同步成功 |
| 长时间同步失败 | “内容已保存到手机，尚未同步”——仅本地落盘已确认时可这样写 | 本地任务 | 受影响的同步动作 |
| 配对完成 | 一次短 Snackbar；列表立即体现结果 | 全部操作 | 无 |
| 正在连接、等待电脑同意 | 设备行/连接阶段卡 + 取消；跨页只保留紧凑状态 | 浏览其他区域 | 同一目标重复发起 |
| 会话断流、画面过期 | 会话内持久提示 + 恢复状态，保留返回设备 | 返回、其他页面 | 对过期画面继续发送输入；恢复后不补发过期点击 |
| 密码错误、接入码无效 | 提交后字段级错误 + 修改；输入期间中性约束 | 修改、取消、其他页面 | 当前连接提交 |
| 目录授权缺失/失效 | 接收位置附近说明 + 重新选择位置 | 发文件、浏览和其他任务 | 依赖该目录的接收任务 |
| 单文件失败 | 该任务行失败 + 可行的恢复动作 | 已成功文件和其他任务 | 失败的那项 |
| 批量部分失败 | “5 个文件已完成，2 个未完成”摘要 + 逐项状态 | 已完成项和其他任务 | 未完成项；不把整批标为成功 |
| 草稿未能落盘 | 编辑区持久提示 + 重试/复制备用 | 继续编辑、复制 | 会丢失内存内容的离开/放弃动作，需先决策 |
| 保存结果无法确认 | “结果待核对” + 幂等核对/重试；保留内容 | 查看和安全退出路径 | 重复创建或覆盖等不确定操作 |
| 删除可恢复内容 | 仅当确实实现撤销时给 Snackbar + 撤销 | 全部操作 | 无二次确认 |
| 彻底删除、清空不可恢复记录 | 显式后果 + 模态确认，安全按钮优先 | 取消后继续 | 执行删除直到明确确认 |
| 有未完成传输时主动结束相关会话 | 先核实传输是否依赖此会话；确实会中断才确认后果 | 取消结束、保留任务 | 有实际损失的结束动作 |
| 普通新版本、后台检查更新失败 | 设置入口标记/更新区域状态 | 全部原有功能 | 无 |
| 用户主动更新失败 | 更新 Sheet 中保留问题和重试 | 原有功能 | 本次安装流程 |
| 收到授权/文件请求，用户在其他页面 | 角标 + 必要的轻提示；打开后才显示接受/拒绝 | 当前任务 | 未获同意的敏感操作不得执行 |
| 连接身份校验失败 | 停止连接，说明原因并提供重新核验/退出 | 其他应用功能 | 当前连接；不提供绕过校验的继续按钮 |

“不打扰”不等于吞掉失败：系统必须保留真实状态、必要的恢复入口和脱敏诊断。影响落盘、费用或安全的失败不能只写日志。

## 6. 三个可选视觉方向

分级规则三者相同；以下只比较组件形态和视觉方向。

| 方向 | 外观与交互 | 优点 | 代价 |
|---|---|---|---|
| A Android 原生感 | 紧凑实底 Snackbar、局部字段错误、标准确认面板，动效简洁 | 熟悉、清楚，Android 使用习惯匹配 | 品牌辨识度相对低 |
| B Panda 精致浮层（推荐） | 保留现有系统字体和实底表面；轻反馈用小型浮层，持久问题用紧凑状态条，决策用统一 Sheet/确认组件 | 延续现有手机视觉，有质感且能复用代码 | 需统一生命周期、层级和消息调度，不能只换 CSS |
| C 内容优先 | 大部分反馈直接在按钮、字段、设备行和文件任务内完成，浮层只服务跨区域结果 | 干扰最少，远控和文件任务更连续 | 需逐页面调整落点，离开页面后结果可发现性要单独设计 |

推荐以 B 为组件外观，采用 C 的低打扰政策。并不是所有结果都弹 B 的浮层。

B 的具体质感：

- 普通成功：中性表面、清晰一行文字、语义色小图标；避免整块绿色大面板。
- 局部失败：短标题 + 影响/内容是否保留 + 一个恢复动作。红色用于状态识别，不铺满页面。
- 持续受限：稳定落点、短摘要；不要因为每次重试不断插入新横幅。
- 确认：明确动作名，如“清空记录”，避免“确定/知道了”承载破坏性操作；最多两个主要选项，多项恢复选择进 Sheet。
- 字体沿用系统栈，主要文字沿用 `--mobile-font-body`，次要文字用 `--mobile-font-secondary`；触控入口延续至少 48px 的现有做法。
- 圆角、表面、阴影与语义色复用手机 token。通知可以有轻阴影区分浮层，不恢复每张卡片的持续模糊，也不另建一套颜色。

## 7. 动效建议

目标是让出现、更新、离开有因果关系，不让用户多等一段动画。

- Snackbar：建议 8–12px 短位移进入；位移复用现有单一弹簧，透明度使用项目 150ms 贝塞尔。退出要先执行动效，再卸载。
- 状态更新：同一任务在原位从等待变成功/失败，文字与图标短交接；不要重新推入整张通知。
- Banner：只在状态真正变化时展开/收起，遵守项目时长档；避免每次重试引起页面跳动。
- Sheet：复用现有弹簧与拖拽，不另设一组参数；错误和不可逆确认不做抖动、夸张回弹或庆祝。
- 等待态：有真实进度就用真实进度，没有百分比就显示阶段/等待原因，不伪造进度。
- 后台、隐藏页面、锁屏时停止常驻动效；减少动态效果时去掉位移/缩放并保留静态状态。
- 文本长度、系统放大和辅助功能可能需要更长阅读时间。关键恢复动作必须另有持久入口，不能只有短暂 Toast 才能点到。

以上是设计参数建议，流畅度和性能要在真机验证后才下结论。

## 8. 组件和政策的收口边界

建议沿用 `MobileNotice / MobileToast / MobileSheet`，补齐职责，而不是新建平行组件库。

- 状态文字：按钮和任务状态，处理最低级反馈。
- 字段错误：绑定具体字段和校验时机。
- Snackbar：轻结果和确实可执行的单一动作。
- Banner/局部 Notice：持续问题与恢复。
- Confirmation：安全焦点、明确后果、取消与确认。
- 任务停止态：限制相关能力，保留恢复/返回。

统一政策只保留必要判据：事件来源/任务、影响范围、用户是否主动触发、恢复动作、是否必须决定。不要只凭异常字符串自动推断是否弹窗。

同一事件只设一个主要可见落点：

- 活跃 Sheet 的操作反馈放在该 Sheet 的固定反馈区，不藏在遮罩下面。
- 同一事件的任务行可以保留状态，但全局摘要不重复详细报错。
- 浮动 Snackbar 同时最多一个；重复事件按任务和错误原因合并，限制待显示数量和过期时间，避免恢复后补播陈旧消息。
- 优先级更高的状态不被普通成功覆盖。关闭提示仅影响展示，不能把失败任务伪装成成功。
- 普通错误使用温和播报；只有需要立即关注的关键变化才用 assertive alert，不抢输入焦点。
- 应用内反馈与系统通知分开。前台已经看见任务结果就不双重提醒；后台仅对用户期待的任务完成、需要及时处理的请求等提供系统通知，并遵守用户授权和隐私设置。
- AI 能力关闭时不显示 AI 反馈或诱导入口；本方案不改变 AI 门控。

## 9. 实施顺序与验收

先确认方向，再在 `design/` 做 HTML 预览，预览通过后才改产品代码。

1. 列出全部反馈入口并分配类别 → 验收：每项都有范围、生命周期和恢复动作；不能只换通用错误文案。
2. HTML 演示普通成功、字段错误、会话断流、批量部分失败、保存失败、不可逆确认 → 验收：能看出不同重量，操作与反馈在同一可见性域。
3. 统一组件契约、通知生命周期与动效 → 验收：普通反馈不推挤页面；浮层不挡导航、键盘、远控点击目标；退出后才卸载。
4. 逐一迁移实际调用点 → 验收：后台短暂失败不刷屏，持续失败仍可发现；单任务失败不阻断无关功能；不可逆行为必须确认。

设计阶段列出的测试重点（实施结果见下节）：

- 后台重试多次只有一个持续状态；恢复后不补播旧消息。
- 普通成功不能覆盖未解决的关键问题。
- 输入未完成不报错；提交非法输入准确关联字段并阻断该提交。
- 保存失败保留内容，离开时不静默丢失；结果未知时不重复创建。
- 7 项传输有 2 项失败，只显示一个批量摘要，5 项成功不被判失败。
- 活跃 Sheet、键盘弹出、横屏、小屏、字体放大时反馈和动作可见。
- 后台与遮挡暂停阅读时钟；减少动态效果仍保留状态；关键消息不会自动过期。
- 连接画面失效后暂停相关输入，不把旧输入排队到恢复后执行。
- 新的 bug 守卫必须先用坏实现确认红，再保留修复后的绿证据。
- 跑相关组件/策略测试、TypeScript 和 `npm run lint:ui`；最后真机验证动态效果与性能。

所有方案均不包含版本升级、exe/APK 构建或 git 提交。

## 10. B 方案实施与验收记录

2026-10-11，用户选择 B、确认设计稿并授权「开工」后实施。

- `MobileNotice`：统一图标底色、文字对齐与语义色；默认温和播报，紧迫性由 `urgency` 单独指定。连接画面失效和输入发送失败保留紧迫反馈，普通局部失败不打断读屏。
- `MobileToast` / `MobileToastProvider`：普通结果浮动显示，不推挤正文；同时显示一条、最多等待三条。相同纯文字结果合并；带恢复操作的不同来源保留独立入口。等待结果超过 20 秒在队列操作时清理，不增加轮询。错误、警告和等待状态不会按普通成功自动过期。
- 阅读时钟：简短结果 4 秒；带说明或操作 6 秒。后台、被面板遮挡、悬停与聚焦时暂停，后续结果从实际显示时开始计时。
- 动效：浮层进入复用项目的定参弹簧；内容变化淡入 150ms，高度变化与退场 200ms。`MobileFeedbackSlot` 保留退出内容并禁用旧动作，重新出现会取消旧退场；原生诊断详情展开也触发高度过渡。减少动态效果时即时完成，隐藏时停止动画。
- 消费入口：普通复制/配对/文件操作成功改用浮层；开关结果留在开关附近；字段校验等待失焦，继续编辑会清除旧错误；拒绝与取消使用中性反馈；阅读页非关键提示聚合；更新失败留在设置与发起面板，不弹跨页错误横幅。
- 保护决策：历史清空使用统一确认面板，默认聚焦「保留记录」。新建、修改两个编辑器共享离开保护：草稿落盘失败保留输入，默认「继续编辑」，重试成功才离开；提交期间避免重复调用。横屏确认动作并排显示，保持可达。
