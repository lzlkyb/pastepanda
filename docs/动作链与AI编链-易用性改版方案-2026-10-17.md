设计稿：`design/动作链-一用即懂-2026-10-17.html`。

## 本次核对范围

`TransformHubDialog.tsx`、`useTransformHub.ts`、`ChainRunnerDialog.tsx`、`ChainEditor.tsx` 及对应 CSS；`chains/registry.ts`、`planner.ts`、`planRequest.ts`、`dialogStore.ts`、AI 编链后端 `commands/ai/plan.rs`。

## 已确认的缺陷

| 优先级 | 缺陷与证据 | 对用户的影响 | 改动要求 |
|---|---|---|---|
| P1 | `openChain` 不关闭 `hubItem`；编辑器又单独开启 `chainEdit`，三个组件各自渲染 backdrop / FocusTrap | 连续叠窗、上下文被压暗、返回层级难理解，键盘焦点与 Esc 处理分散 | 一个活动面板、同层前进返回，保留输入与草稿 |
| P1 | 运行器初始化选 `PRESET_CHAINS[0]`，与输入类型无关 | 普通问题描述也默认选“网页转纯文本”，容易误跑 | 无可靠匹配时先选流程；用户主动选择才预填 |
| P1 | 步骤列表只在 `result &&` 后出现，运行前只展示步数 | 点运行前不知道会做什么、是否联网 | 运行前列出全部步骤、顺序和数据发送边界 |
| P1 | AI 入口直接执行 `planChain`，请求只有内容和动作清单；没有目标输入；还自动拼入工作记忆 | 用户不能表达需求，也不容易知道额外上下文被带入 | 先填写目标、核对输入，再显式发送；会话内容改为默认不附加 |
| P1 | `runChain` 只返回最终 Promise，没有逐步事件或停止信号 | 长任务只有“运行中”，关闭弹窗仍可能继续调用后续步骤 | 增加真实步骤进展、协作式停止与运行代际隔离 |
| P1 | 运行器在打开时异步加载全部链，保存后只失效缓存，当前列表不会立即刷新 | 新建后找不到刚保存的流程，容易以为保存失败 | 保存成功即更新列表并选中，直接回到步骤预览 |
| P1 | `loadUserChains` 捕获加载错误后退回缓存或空数组 | 读取失败容易被看成“还没有保存流程” | 有独立错误与重试状态，同时允许使用内置流程 |
| P1 | 失败后的 `result.final` 仍使用普通复制 / 粘贴按钮；匹配 `***` 就显示“可放心粘贴” | 半成品可能被误当最终结果；脱敏提示承诺过度 | 区分部分结果；改为“复制已完成部分”；要求核对脱敏结果 |
| P2 | 模板是一条横滚胶囊条；说明主要在 title；长副标题与主标题同排 | 隐藏选项难发现，标题挤压；截图已有横向滚动条 | 纵向可搜索列表，名称与用途常驻；副标题独立排版 |
| P2 | 输入为 `pre`，`max-height:84px;overflow:hidden` | 看不全、无法修正输入，JSON 失败不易恢复 | 可展开全文并修改，注明不改原记录 |
| P2 | 编辑器单行放操作下拉、风险、条件、排序、删除 | 小窗拥挤，常用操作难点；高级概念暴露过早 | 主操作一行；排序 / 删除带文字；条件按需展开 |
| P2 | 成功后默认展开所有步骤、结果排在步骤之后 | 最关心的结果和复制入口需要翻找 | 结果优先，过程按需展开，底部操作固定可达 |

这是具体交互问题清单，不将截图或源码推断包装成已经完成的用户实验。

## A：同面板分步引导（推荐）

适合当前以快速处理剪贴板内容为主的小窗口。

1. “动作链 / AI 编链”改为“用现成流程 / 让 AI 设计流程”，进入后用“多步处理”解释用途。
2. 取代叠窗：沿用同一面板尺寸、主题与关闭位置；左上返回上一级，保留选择、输入和编辑草稿。
3. 现成流程：选择想得到的结果 → 看具体步骤 / 输入 → 运行 → 核对结果 → 复制或粘贴。
4. AI 流程：填写目标 → 核对将发送内容 → “生成步骤并发送” → 检查 / 调整步骤 → 手动运行。生成和执行分开。
5. 每个模板常驻展示名称、用途；不做横向滚动。长列表按名称查找，不默认渲染全部步骤预览。
6. 手动编辑仍使用当前变换注册表，不引入画布；新建只需名称与步骤，条件收在高级项内。
7. 完成后首先显示结果。复制与粘贴常驻底部；处理过程按需展开，失败步骤默认可见。

优点：小白决策少、当前内容始终在场、适配现有 480 px 小窗口。代价：需要收拢当前分散的弹窗路由与会话状态。

## B：独立流程工作台

进入时收起原“变换为”面板，打开一个单独工作台；宽窗左侧保留流程列表，右侧展示输入、步骤与结果。AI 设计同样先目标、后生成、再执行。窄窗将列表置于上方。

优点：管理、比较多个自定义流程更快。代价：需要更大空间；窄窗需要为常驻列表分配高度；偶尔使用的人承担更多管理界面。

两种方案均不保留截图中的多层模态框，也不削减发送前确认。

## 反馈与恢复契约

- **运行前**：选了什么、用哪段输入、会做哪几步、哪些步骤需要发送内容，一屏内可理解。
- **运行中**：使用真实步骤事件，不伪造百分比 / 剩余时间。步骤未回报就不标完成；UI 不人为延长本地任务。
- **停止**：文案为“停止后续步骤”，阻止新的步骤启动并保留已完成结果。现有 AI 请求不支持可验证的全链取消；已发出的内容无法撤回，也不承诺不计费。后端接通真正取消之前，不写“请求已取消”。
- **关闭 / 返回**：运行中先进入停止后的结果态，已完成内容不丢；再次返回才离开流程。编辑时先回到流程预览；草稿应有明确保留 / 放弃策略，不静默清空。
- **失败**：定位到具体步骤和原因，给“修改输入 / 调整步骤 / 从头重跑”；未实现断点重跑前，不提供“从失败步骤继续”。
- **部分完成**：明确为中间结果，主操作“复制已完成部分”，不与最终结果粘贴同级混用。
- **无变化 / 全部跳过**：报告“内容未变化 / 条件不满足，已跳过”，不将空跑包装成转换成功。
- **AI 未启用或无可用 key**：不展示 AI 设计入口、候选 AI 步骤与含 AI 的预置流程；保存数据不删除。所有真实请求继续遵守统一 AI 门控、预算和敏感内容检查。
- **AI 计划部分可用**：丢弃步骤、截断、不完整计划使用常驻说明；不只弹转瞬即逝的 toast。
- **脱敏**：只报告已执行的替换，不承诺“可放心分享”；原文与结果均可核对。

## 实施边界与结构

- 保留已有变换与链结构；先将当前超 300 行组件拆为流程会话 Hook、模板选择、步骤预览、运行结果、步骤编辑等小组件。
- 同一会话保存 source / goal / selected chain / draft / run id / outputs，返回不重建草稿；只有活动路由有焦点陷阱和 Escape 接管。
- `runChain` 添加可选的步骤事件与停止检查，兼容既有调用点；启动、等待确认、完成、跳过、失败分别回报。迟到结果必须被 run id 隔离。
- AI 目标须作为明确字段传过 API、后端与 prompt，不能只在前端画一个不生效的文本框。敏感检查覆盖实际发送的目标和输入；附加会话内容须显式选择并预览。
- 模板适用性作为提示，不能让个性化权重把不匹配模板升为自动默认；手动使用仍可达。
- 保存成功刷新当前列表并选中；加载失败不能落到空态。常用列表只渲染名称，选择后才挂载步骤和预览。

## 性能与动效

- 沿用全局已确认的动效令牌；交互反馈用 150ms，面板内部切换约 200ms，外层面板沿用当前系统，不层层叠加进场动效。
- 不为每个步骤添加模糊、玻璃层或常驻装饰动画；进度由执行事件驱动，不轮询后台。
- 大文本只按需展开，结果与中间产物设置清晰的滚动容器；固定操作区不随正文滚走。
- 页面隐藏或关闭后停止 UI 更新与演示计时；正式执行的取消语义仍按上面的停止契约处理，不能因隐藏把真实后台请求当作已取消。
- HTML 稿的步进计时仅为状态演示，不是生产性能测量或实现承诺。

## 验收点

1. 400 / 480 / 720 px，长流程名、8 步、长原文：无横向溢出，关闭 / 返回 / 主操作始终可达。
2. 从变换进入流程、再编辑：最多一个活动面板，不存在多重遮罩与焦点陷阱。
3. 初次打开便能解释当前输入、将做什么、下一步在哪里；不读帮助也能用内置流程完成一次处理。
4. 普通文本不盲选网页流程；无效 JSON 给修改入口，原文不改变时给真实解释。
5. AI 入口不自动请求；目标真正进入计划，发送内容可核对；生成后不自动运行；关闭 AI 后无 AI 入口或请求。
6. 流程进行时可查看真实阶段、停止后续步骤；关窗重开不会混入旧运行结果。
7. 成功、失败、部分完成、跳过、无变化、加载失败都有对应反馈；保存后立即可见可选。
8. 鼠标 / Tab / Enter / Esc 全流程可达；输入法组合阶段 Enter 不误触；减少动效时仍有静态状态。

已按 A 实施，并为新增逻辑补回归用例；不升级版本、不自动构建安装包、不提交推送。
