# 远程电脑 · 画质与链路调度对标 p2wlan（2026-10-15）

> 结论先行：**p2wlan 没有「画质」调度**——它是虚拟局域网（TUN 组网）软件，
> 不传输视频流，远程桌面走 RDP over 虚拟 IP，本身无编码器与画质档位。
> 它真实领先的是**网络路径层的调度/降级/恢复**体系。本方案把这部分学过来，
> 叠在我们已成熟的画质自适应之上。

---

## 1. 事实澄清（术语红线）

| 用户预期 | p2wlan 实际 |
|---|---|
| 原画质 / 自动升画质 / 画质降级 | ❌ 不存在。无视频编码器，无画质档位，无码率控制 |
| 延时调度 | ❌ 无主动延时调度；只有**路径选择**（直连 vs 中继）决定延时 |
| 网络调度 / 分配 / 降级 / 恢复 | ✅ **真实存在且做得很重**：路径状态机 + 候选排序 + PLPMTUD + 健康观测 |

「直连优先、断了回退加密中继、网络改善后自动恢复直连」是它 README 的核心卖点，
这套**路径级降级/升级**就是用户感受到的「画质/延时自动变好变坏」的全部来源。

## 2. p2wlan 可学的 5 项（源码证据）

### 2.1 路径状态机：降级/恢复是一等状态（最值得学）

`client/daemon/src/peer/path_state_machine.rs`（2665 行）

- `PathRecoveryState`（:594）：`Stable / Degraded{from, fallback} / Recovering{target, attempt}`
  —— 注释原话 *"Degradation and recovery are first-class state, not log-only side effects"*。
  我们现状：链路状态散在 `link.rs` 的观测字段里，没有「已降级、正在恢复」这种**有生命周期**的状态。
- 三代世代 fencing（`PathEpoch`，:22）：`network_generation / peer_session_generation /
  remote_candidate_epoch` 三个世代同时校验，**旧世代的事件永远污染不了新世代**
  （断线重连、换网络、对端换候选都不可能把陈旧观测灌进当前状态机）。
- Direct-first 窗口（:13，`DIRECT_FIRST_WINDOW = 5s`）：新会话先给直连 5 秒机会，
  到点未成则放行 relay 承载业务——不无限等也不秒切。
- 幂等事件 + revision：`PathTransitionDecision` 区分 Applied/AcceptedObservation/Duplicate/
  Rejected* 十种判定，重复事件与非法迁移显式拒绝（:631）。

### 2.2 后台升级不毁健康 relay（关键安全判据）

测试 `relay_background_direct_upgrade_never_destroys_healthy_relay`（:2579）钉死的行为：
relay 正在承载业务时，后台直连探测照跑，直连 commit 成功才切换，**探测失败不影响 relay**。
我们未来的直连恢复必须带同款守卫单测。

### 2.3 候选排序：静态优先级 + 动态成功率学习

`client/daemon/src/peer/candidate_ranking.rs`

- 静态源优先级（:15）：`PeerReflexive(0) > Learned(1) > Host(2) > UpnP(3) > Pcp(4) >
  NatPmp(5) > StunObserved(6) > Signaled(7) > Predicted(8) > Birthday(9)` ——
  「认证包实测出的端点」最高（它已证明对端能达我们）。
- 动态成功率学习（:4）：每源成功率 per-mille 排序 + 冷却（`source_in_cooldown` → 1100 惩罚分）。
- 新鲜度分级（:63）：≤3s/10s/30s 四档年龄 rank。

映射到我们：R2 自建打洞路线的候选（stun 观测/预测/生日）将来需要一个排序器，这套可直接借鉴。

### 2.4 DPLPMTUD 包尺寸探测（对我们有直接收益）

`client/daemon/src/dplpmtud/`（state_machine.rs:14-26）
基线 1200B → 二分探测至 1472(v4)/1452(v6) 上限，粒度 8B、重试 2 次、
成功后每 30s 复确认、每 10min 才允许重升，完整状态机 + 探测身份（nonce+path_cookie 防串线）。

对照我们：`vid_dgram.rs:38` 单片 1034B（+34B 头 < 1200B 安全线）。
链路 MTU 实际吃满时可到 ~1472：**每帧包数 −30%**，同码率下丢包敏感度直接下降。

### 2.5 Relay 健康观测身份化

`path_state_machine.rs:215` `RelayHealthObservationIdentity`：每次健康采样分配 token，
带身份的消费/拒绝（`RejectedRelayConnectionIdentity`）——防旧连接的健康样本
污染新连接。我们的 pong 活性目前只存 `last_pong_ms` 单值，无身份区分。

## 3. 我们现状盘点（诚实对账）

| 域 | 我们的现状 | 对标结论 |
|---|---|---|
| 画质档位自适应 | `auto_quality.rs`（570 行）：梯子 + 超额延迟 + 丢包 + 帧龄 + 迟滞/冷却，A-甲/A-乙 修正 | **已超过 p2wlan（它没有）**。无可学 |
| 码率控制 | `media_flow.rs` Flow：backlog 定容量、降速线、探测、G2 连拍定罪 | 同上，无可学 |
| 链路观测 | `link.rs`：path_kind（lan/direct/relay）+ pong 活性 + 半开踢人 | 观测够，**但纯被动** |
| 路径调度 | ❌ 无 Degraded/Recovering 状态、无后台直连重探测、无世代 fencing | **核心差距**（学 2.1/2.2） |
| 包尺寸 | 固定 1034B 单片 | **可白捡 30% 包数**（学 2.4） |
| 候选排序 | 无（打洞在 iroh 内部） | R2 路线储备（学 2.3） |

## 4. 分阶段方案

| 阶段 | 内容 | 成本 | 收益 | 依赖 |
|---|---|---|---|---|
| **P1 链路调度状态机** | 新模块 `rc/link_sched.rs`：Stable/Degraded/Recovering 一等状态 + 三代世代 fencing（网络世代=本机网卡变更代、会话世代、对端候选世代）+ 幂等事件 reducer；`link.rs` 观测喂事件，诊断卡/RcNetDiagCard 消费状态 | 低（纯内部 + 单测） | 中：半开/切换场景有明确用户语义；P2/P3 的地基 | 无 |
| **P2 后台直连重探测** | relay 会话期间周期探测直连候选（探测≠切换）；成功 commit 才无缝切换，**守卫单测：探测失败永不影响健康 relay**（对标 2.2） | 中 | **高：直连恢复 = 延时从 600ms 级掉回 20ms 级**，是用户最大痛点 | 打洞探针 E1/E2 补跑（n0 relay 网络恢复后） |
| **P3 包尺寸探测（PMTUD 式）** | `vid_dgram` 单片 1034 → 双端探测协商至实测 MTU 上限（~1472）；探测报文带身份（nonce+path 代），30s 复确认 | 中（需双端 capability 协商） | 中：同码率包数 −30%，弱网丢包敏感度下降 | P1 的世代 fencing 复用 |
| 储备：候选排序器 | 2.3 的静态优先级 + 成功率学习，落 R2 自建打洞候选 | — | — | R2 启动时 |

### 推荐顺序：P1 → P3 → P2

- P1 无依赖且是另外两项的地基（P2 切换、P3 探测都要世代 fencing 防串线）；
- P3 独立可先行，收益直接落在画质链路上；
- P2 依赖打洞探针（punch-inject E1/E2 待 relay 网络恢复补跑），地基好后接入。

## 5. 明确不学的

- p2wlan 的 WireGuard/TUN 数据面：我们视频流走 QUIC，引入 TUN 是负 ROI；
- 它的 relay 协议与 Control 服务器：自建 relay 是另一条线（R1b，决策文档已覆盖）；
- 画质侧：无物可学。
