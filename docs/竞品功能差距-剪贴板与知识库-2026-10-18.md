# 竞品功能差距：剪贴板 × 知识库（2026-10-18）

> **这份稿子回答三个问题**：同类软件现在都做到哪了、我们差多少、哪些值得抄进 PastePanda。
> **取证边界**：GitHub 仓库元数据为 2026-10-18 实测（`gh api`，star 数 / 最近 push / 许可证）；
> 功能项来自各仓 README 与官方文档原文；我方能力逐条 grep 过源码，反例（"没有"）附检索方式。
> **知识库侧不重复造轮子**：4 天前的 `docs/知识库-行业对标-2026-10-14.md` 已经把 PKM 赛道写透，本稿只补它对剪贴板赛道没覆盖的部分与新增观察。

---

## 0. 一句话结论

**不是"落后一个身位"，是"两条腿各有一块短板"**：

| 维度 | 我们的位置 | 差距体感 |
|---|---|---|
| 剪贴板**功能面**（采集 / 编辑 / 加工 / 同步） | 与 CopyQ、Ditto、EcoPaste、PasteBar 的**并集**相比只缺 9 项（3 项弱 + 6 项无） | **不落后，局部领先**（14 个专用编辑器、OCR、二维码、局域网同步、Android、动作链，竞品没有一家同时有） |
| 剪贴板**细节与生态** | 6 项"没有"里 3 项是薄层（拖出 / 粘贴恢复 / 单次忽略），另 2 项是应用锁与多语言，条目备注已否决（见 §4）；3 项"弱"里加密备份最该补 | **落后 1 档**，但薄层那 3 项每项一到两天 |
| 知识库**功能面** | 缺采集入口深度、视图层、块级引用、AI 在场 | **落后 1 个身位**（10-14 稿已量化） |
| **剪贴板 → 知识库总线** | 竞品里**没有第二家**做这件事 | **独有，且在正确的位置** |

所以真正该焦虑的不是"剪贴板功能被抄走了"，而是**我们独有的那条链路（复制即沉淀）没有做到"复制的东西能自动归位"** —— 竞品在"采集后的自动整理"这一层（karakeep 的规则引擎、自动抓标题/封面、全页归档、高亮）反而走在我们前面。

## 3. 知识库侧：只补 10-14 稿没有的三条

`docs/知识库-行业对标-2026-10-14.md` 的结论仍然有效（采集入口 2/5、本地 embedding 缺失、问答质量、AI 在场度、视图层）。这里补三条**与剪贴板入口直接相关**的新观察：

### 3.1 采集之后的"自动归位"，我们一层都没有

karakeep 的做法（README 原文）：`Automatic fetching for link titles, descriptions and images` / `Rule-based engine for customized management` / `LLM-based automatic tagging and summarization`。

我们现状：`commands/url_summary.rs` 能抓标题摘要，`commands/kb_inbox.rs` 有"待沉淀"，`src/lib/chains/conditions.ts` 有本地条件判定（is-json / contains-secret / is-code）——**零件齐了，但没有"入库路由"这一层**：复制了一条 GitHub 链接、一条公众号文章、一段 SQL，三者都只落到"待沉淀"里，靠人再分。

这条差距的修复不需要新架构：把 `chains/conditions.ts` 的判定能力扩展到"来源域名 / 关键词 / 内容类型 → 目标文件夹 + 标签 + 是否直入（跳过待沉淀）"，就是 karakeep 的 rule engine 的本地版，**零 AI、零出网、不触红线**。

### 3.2 链接会烂，我们只存了文字

karakeep 用 monolith 做 `Full page archival (to protect against link rot)`，还有 `Auto video archiving using yt-dlp` 和 `Mark and store highlights`。

我们 `fetch_url_article` 抓正文 + 图片本地化（`docs/手机知识库-微信文章收藏方案-2026-10-09.md`），已经比"只存 URL"好，但**没有整页快照**：原文删了、改版了，我们只剩抽出来的那半截正文，也没有"当时页面长什么样"的证据。对"个人知识库"来说，这是保真度问题，不是功能问题。

### 3.3 知识库软件的加密粒度，比我们细

Trilium：`Strong note encryption with per-note granularity`；Joplin：E2EE + WebDAV/S3/OneDrive 多后端；SiYuan：E2EE Sync。
我们：SQLite 明文落盘 + P2P 传输加密（iroh）。**传输安全 ≠ 静态安全**。这条不是要现在做（DB 加密会牵动 FTS5、MCP、同步、备份全链路），但"我们有加密"这句话在对外叙事上目前只对传输成立，别说过头。

## 4. 值得抄的清单（按 ROI 排序）

> **已否决：条目备注**（原列 P0，2026-10-19 用户否掉）。理由成立：剪贴板里绝大多数内容是一次性的，没人会给它写注解；真要"留一句话"，我们的「转笔记」已经覆盖——备注本质是转笔记的半成品，两者功能重叠。竞品有这项不代表要抄：CopyQ / Ditto 的用户把剪贴板当**片段库**，我们的模型是**复制即沉淀**，沉淀动作应该是转笔记，不是加备注。
> 连带结论：§2 里"条目备注 ❌"仍是事实，但**不是差距**——是我们有意不做。

成本口径：S ≈ 半天~1 天、M ≈ 2~4 天、L ≈ 1~2 周以上。条目均不触碰三条红线；涉及出网的只有"链接整页快照"，且只在用户显式操作时发生，不涉及 AI。

| 优先级 | 功能 | 学自 | 为什么实用 | 落点 | 成本 |
|---|---|---|---|---|---|
| **P0** | **粘贴后恢复原剪贴板**（可选开关，默认开） | Maccy | 从历史里粘一条旧内容，会把用户当前剪贴板顶掉。恢复后"借用一下"不破坏工作现场 | `paste_engine.rs` 注入前快照 → 注入后回写；开关进设置「粘贴」区 | S |
| **P0** | **单次忽略下一次复制** | Maccy（`⌥+点击菜单图标`） | 临时复制一次密码/隐私内容，不必改全局规则、不必事后删记录 | `clipboard_monitor.rs` 加 one-shot 标记 + 托盘菜单项 + 可选热键 | S |
| **P0** | **按来源应用筛选** | EcoPaste | 来源徽章（`SourceBadge.tsx`）已经在记来源，但只能看不能筛。"只找从 VS Code 复制的"是高频诉求 | `SearchBox`/`NoteFilterPanel` 加来源 facet，复用 `source-mappings.ts` | S |

| **P2** | **高亮保存** | karakeep highlights | 从网页/笔记选中一段 → 存成带出处的引用块。与"复制即沉淀"是同一动作的两种粒度 | 笔记编辑器选区 + `quote` 块 + `source_url` | M |
