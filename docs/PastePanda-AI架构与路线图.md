## 1. 当前 AI 架构现状（3 分钟看懂）

> 以下现状全部基于代码实测结论（非文档推测），供任何人快速对齐认知。

**Provider 抽象层**：`ai/provider.rs` 定义 16 家服务商，支持 OpenAI 兼容 / Anthropic 两种协议。内置免费服务商 `builtin-agnes`，密钥用 DPAPI 加密存储在本机，**密钥绝不回传前端**。

**AI 能力**：
- 15 个内置动作（`ai/actions.rs`）通过 `ai_run` 执行——**单次 prompt-response，无状态**
- `ai_plan_chain` 只生成多步方案供人工确认，**不自动执行**——规划与执行是断开的两段
- 语义检索（`semantic.rs`）：M5-2 云端 embedding + 本地余弦相似度，已落地
- URL 摘要（`url_summary.rs`）：含 SSRF 防护，已落地
- 全文检索：FTS5 中文索引（`history_fts` + bigram 分词）已落地，语义检索作为增强层

**记忆系统**：四层记忆均已落地，且**纯本地统计，不存原文**：
| 层 | 表/模块 | 存什么 |
|---|---|---|
| 内容层 | `content_memory.rs` | 检索摘要 + 语义向量 |
| 偏好层 | `pref_signals.rs` | 动作级偏好（攒够 3 次同方向才写入） |
| 程序层 | `sequence_memory.rs` | 动作序列挖掘 |
| 语义层 | `profile.rs` | 六类角色概率分布 `role_scores` |

**反馈闭环——半通半断**（这是全文档的核心矛盾，P0 就是修它）：

```
已通的部分：
用户改 AI 产物 → 提取特征标签 → ai_feedback_add → ai_feedback_stats(算 edit_rate)
  → 攒够 3 次同方向 → 提议「记住」→ pref_signal_accept → 写入 action_prefs
  → run.rs 把 action_prefs 拼进 system prompt → 下次该动作输出真的变了 ✅

断的部分：
① 画像级特征（role_scores 等）从未进入 system prompt
   —— 不存在 profile_prompt.rs，翻译不知道你常处理代码，总结不知道你偏好要点
② profile_action_boosts 从未读取 edit_feedback.edit_rate
   —— 一个产物被改得再狠，推荐权重也不会降
```

**Agent 循环完全没有**：`ai_plan_chain`（规划）与 `ai_run`（执行）之间没有"执行 → 观察结果 → 再决策"的循环。动作链（`chains.rs`）是人工搭建的静态线性流程，不是"AI 动态生成方案后自动逐步执行"。

**配额系统**（`quota.rs`）：签到送 token、离线兑换码（HMAC 签名）、单锁原子扣减，**仅服务 `builtin-agnes`**，与用户自配服务商的金额预算体系完全隔离。

**综合定位**：六维能力栈判定——感知强、记忆有但未变现、规划弱（只生成不执行）、工具中等、循环无、学习信号采集了但未接入推荐权重 → **"L0.5 LLM 增强工具"**，还不是 Agent。

## 2. 与行业对标的差距：为什么 PastePanda 现在不是 Agent

> 整合《AI 应用集成趋势调研》《终极剪贴板-现状评估与改进》《终极蓝图》的核心论点，不是列功能清单，是讲清楚本质差距。

**行业判断（2026）**：AI 产品已从"附加聊天框"进入"**可托付智能体**"阶段——具备任务理解、计划分解、工具调用、跨应用执行、持续记忆、结果校验的完整能力。战场从"回答质量"转向"工作流执行"。

PastePanda 与这个阶段的本质差距，不是功能数量，是五条结构性缺口：

**① 规划与执行断开，没有闭环**——`ai_plan_chain` 生成方案后就结束了，剩下全靠人手动一步步点。这不是"缺一个功能"，是缺"感知→思考→行动→观察"这个 Agent 定义本身要求的闭环结构。动作链（`chains.rs`）看似是雏形，但那是**人工预先搭好**的静态流程，不是"AI 现场规划、现场执行、现场根据结果调整下一步"。

**② 记忆存得住，但用不上**——四层记忆存储扎实（17 张表，分层清楚），但两个最该被用起来的信号都没接进决策：画像特征没进 AI 输出的 system prompt（D1 断点），反馈算出的 `edit_rate` 没进推荐权重（D2a 断点）。存储层评分能打 7/10，但"记忆能改变行为"这条链路是断的——**这就是为什么"越用越懂你"目前只是半真**。此外，跨条目的**事件聚合**能力缺失：现在的记忆只能"找一条内容"，不能"想起一件事"（比如"上周三你调那个接口时用过的那几段"），这是比"存不存内容"更本质的记忆能力缺口。

**③ 学习系统看不见半个产品**——`AiQuickBar`（首页常驻 AI 动作主入口）和卡片右键菜单执行变换**没有行为埋点**，这两个高频入口的使用完全不会进入 `action_events`，等于推荐排序系统对用户最常用的操作路径是瞎的。同时，56 个变换里只有能表达"单输入→单文本输出"的才进了 registry，`ExtractDialog`（多结果提取）、`ConfigDiffDialog`（双输入对比）等因为契约表达不了而被排除在外，学习范围永远小于产品实际能力范围。

**④ 没有可解释性**——推荐列表给出顺序，但从不说"为什么排第一"。用户不知道系统的判断依据，就永远只敢把它当"辅助工具"使，托付不出去更复杂的决策。这是"记忆/环境智能/可托付执行"三层之上一个贯穿性的缺失前提：**没有可解释，就没有信任，没有信任，"可托付"三个字无从谈起**。

**⑤ AI 能力"藏在后台"，用户前台无感**——四层记忆、画像、意图识别、动作链全部是真实存在的能力，但大多在设置页/后台运行，用户日常使用感知不到。剪贴板品类目前行业水位仍停留在"OCR 搜索 + 语义搜索"，"可托付的剪贴板智能体"仍是空白——这恰是 PastePanda 差异化的空间所在，但要拿到这个位置，必须先把①②③④解决。

## 3. 产品愿景/长期蓝图

> 整合《终极蓝图-懂用户自进化有思想》（2026-08-10）与《终极剪贴板-三支柱方案》（2026-08-11）。两份文档表述路径不同但核心主张一致，以更晚的三支柱方案为主干框架，蓝图的细节（三层记忆定义、闭环图、红线兼容表）作为补充嵌入，不重复两套体系并列。

### 3.1 北极星

> **终极剪贴板 = 个人记忆（记得住）+ 环境智能（主动想到）+ 可托付执行（替你办成）**
> 云端大模型为引擎、本地优先为前提、脱敏前置为底线。
> 让"复制-粘贴"这个每天几百次、被认为毫无技术含量的动作，变成用户和数字世界之间真正智能的接口。

两份文档共同强调的核心主张（去重后保留）：

1. **本地优先不是"懂用户"的障碍，而是它唯一的合法前提**——红线②（使用日志永不出本机、可见可删）约束的是"数据去向"和"用户控制权"，不是"能不能存内容"。纯本地内容记忆与红线完全兼容，反而是相对云端竞品的结构性优势：别人做用户画像有隐私包袱，PastePanda 本地做名正言顺。
2. **三个词都是可度量的，不是口号**：
   - 懂用户 = 三层用户模型都要成立——你常用什么（行为层，已做）/ 你处理过什么（内容层）/ 你喜欢什么风格（偏好层）
   - 自进化 = 每次交互的接受/修改/拒绝都要真正回写模型，不是只统计不使用
   - 有思想 = 不只识别"这是一段 JSON"，而是推断"你在调 bug"，能预判下一步
3. **闭环结构一致**：感知 → 记忆 → 推断 → 建议/动作 → 反馈 → 回写记忆 → 下一次更准。三支柱方案里的"个人记忆"对应蓝图的行为层+内容层，"环境智能"对应蓝图的推断层（意图识别+预判），"可托付执行"是蓝图闭环的落地出口。

### 3.2 三支柱现状与要补的事（整合自三支柱方案原文，保留细节不做单句概括）

**① 个人记忆（Personal Memory）**——所有复制的东西被统一编码成带"意图+来源+时间戳"的记忆碎片，能回答"我上周给客户整理的那段报价在哪"。已具备：四层记忆、用户画像、语义搜索、统一历史表（五型 + md5 智能合并）。要补：跨模态统一编码（图片 OCR 文本接入 FTS5）、记忆快照趋势（周/月趋势线让记忆可解释）、可解释召回 `recall`（跨四层检索并说明"为什么推荐"）、跨设备 RAG。

**② 环境智能（Ambient Intelligence）**——从"等你粘贴"到"主动在场"：粘贴瞬间已把最可能对的那条顶到候选区第一位，不是搜索结果，是预判。已具备：来源 App 信号（复制时记录）、目标 App 信号（粘贴时记录）、候选区雏形。要补：重排序（源 App→目标 App+当前内容语义，走本地 FTS 相似度控成本）、意图标签（云端语义标签供推送/动作使用）、适时提示（源→目标映射的轻量规则，不强制打断）。

**③ 可托付执行（Trustworthy Execution）**——从"原样粘贴"到"智能执行"：一句自然语言指令自动拆步、调工具、跨应用执行、每步可预览可回滚。已具备：动作/链/计划骨架（`actions.rs`/`chains.rs`/`plan.rs`）、脱敏守卫（粘贴前识别密钥/PII）、流式输出+可回滚改写。要补：Agent 智能粘贴链（`plan.rs`+`chains.rs` 真正串联执行）、跨应用动作（填表/发请求/写文件类真实操作）、脱敏前置（出云前而非仅粘贴前）、闭环体验（执行可见+回执+一键回滚）。

> **"可托付执行"的精确定义**（消解与红线③的字面冲突）：可托付 ≠ AI 自己决定干什么，而是"你授权过的事，它能替你连着做完，且每一步可预览、可中断、可撤销"。这是路线图 P1 的设计前提。

### 3.3 红线兼容设计（贯穿三层，不随功能变化）

| 红线 | 内容记忆/执行如何遵守 |
| --- | --- |
| ① 学习只影响排序，永不自动执行 | 内容记忆只影响推荐/改写参数；动作链/计划永远由用户手动触发确认 |
| ② 使用日志永不出本机、可见可删 | 内容层纯本地存储；设置提供"记忆管理"：查看摘要、一键清空 |
| ③ shell 命令永不自动执行 | 不新增任何 shell 能力；跨应用动作走应用层 API，非命令执行 |
| 敏感内容防护 | 密钥/凭证入库前拦截；出云前脱敏前置（三支柱方案的隐私底线升级） |

## 4. 重新梳理的路线图

> 本节是全文重点。汇总 11 份文档（AI-Agent 升级路径/演进分析、v6.x AI 功能升级方案、断点修复规划、画像驱动规划、记忆系统规划、v6.x 整合规划、v7.0 升级规划、用户粘性规划、签到送 Token 规划、终极剪贴板可执行路线图、终极剪贴板现状评估与改进）里的全部具体待办，去重后按优先级重排，**不按文档原顺序**。

### P0 · 直接解决"反馈闭环是假闭环"

> P0 的判定标准：不做这两项，"越用越懂你"这句话就是假的——数据存了、算了，但从未真正改变系统行为。

#### P0-1：画像 → prompt 注入（D1）

**做什么**：在 `run.rs:283` 现有 `action_prefs` 拼接点旁，新增一段由画像生成的 system 片段（新文件 `ai/profile_prompt.rs`，纯函数 `profile_to_prompt(&ProfileRawStats) -> String`），与 `action_prefs` 叠加、各自 ≤300 字。

映射表（纯本地规则，不调模型）：

| 画像信号 | 触发条件 | 注入片段 |
|---|---|---|
| 角色特征 | code 内容占比 > 40% | "用户经常处理代码，遇代码优先解释思路而非翻译" |
| 内容类型 | json/sql 占比高 | "用户常用 JSON/SQL，格式化时保持结构完整" |
| 时段活跃 | **当前时刻落在长期统计的高峰区间内** | "当前处于用户高频使用时段，输出保持精炼" |
| 反馈倾向 | 某动作 edit_rate > 0.4 且样本 ≥10 | "用户经常手动修改本动作输出，请贴合常见偏好" |
| 语言倾向 | 中文内容占比高 | "默认使用中文表达" |

**三个必做配套**（缺一不可，来自最终版方案的纠正）：
1. **默认关 + 一次明确告知 + 原样展示**——设置项默认关；开启时把即将注入的那段文字原样展示出来，设置页随时可预览
2. **粗粒度离散化 + 进 `cache_id`**——画像先映射到几个离散档位算出 `profile_sig`，拼进 `cache::make_key`，避免 24h 缓存因画像细微变化而失效
3. **脱敏复用 `sanitize_profile`，不是 prefLearn 模式**——`commands/profile.rs` 已有的出网清洗管线（`sanitize_profile` + `display_action_name`）才是正确复用对象，因为片段可能带出自定义动作名（用户自由输入，可能混入密钥）

**当前状态**：规划中未落地。**取代了《断点修复-画像注入与反馈闭环-规划》的早期方案**——该文档最初把 D1 排在最后、建议先不做，理由是"成本最高会作废缓存"；复盘后发现这混淆了隐私成本与开发成本（D1 开发成本其实最低），且缓存问题有解（见配套②），已被《画像驱动-懂用户与风格趋同-规划》纠正为**第一梯队**。同时纠正了原文档"高峰在 9-11 点→注入'当前时段'"的逻辑错误（触发条件是长期统计，文案却写"当前"，导致用户高峰在上午、晚上十点用也会被错误注入）。

**必须同步修改的代码注释**：`commands/profile.rs` 现有注释写"这是全项目唯一把用户画像发往云端第三方的路径"，D1 上线后不再成立，需同步改为说明两条出网路径（`profile_refine` 手动不缓存 / `run.rs` 注入需显式开启默认关）共用 `sanitize_profile`。

**验收标准**：不是"代码写了"，而是**A/B 自比**——开启 D1 后每次 AI 调用随机 50/50 决定带不带画像片段（本地记录分组，且分组必须进 `cache_id` 防止两组互相命中缓存），用户改产物后算归一化编辑距离，对比两组平均编辑距离：
- 降幅显著 → D1 转默认开，本地风格规则（P2 的 S1）降优先级
- 降幅不明显 → D1 保持默认关，力气转投 P2 的 S1 本地风格规则
- 反而变差 → 下线重做映射表
跑 1-2 周即可出结论，这个结论反过来决定后续本地风格方案值不值得重投入。

#### P0-2：反馈 → 推荐降权（D2a）

**做什么**：`ai_feedback_stats` 已算出的 `edit_rate`（被改比例）接入推荐权重——`roleBoost × (1 - edit_rate × 0.5)`，样本 <5 时不参与计算（噪声太大）。建议拆成独立乘数而非塞进 `roleBoost` 字段，避免名不副实。

**当前状态**：规划中未落地。`profile_action_boosts` 目前只遍历 `role_scores`，全程没碰 `feedback`——这是全系统信号最强的一个反馈，却一处未用（《终极剪贴板-现状评估与改进》通过独立代码查证得出同一结论，与《画像驱动规划》互相印证，两份文档从不同路径查到同一断点，可信度高）。

**验收标准**：故意造 3 次高编辑率反馈后，权重是否真的下降。工作量约半天，是本次整合中确认的"性价比最高的单项改动"。

**⚠️ 需向用户确认的关联发现（不确定是否要一并处理，明确标出）**：《终极剪贴板-现状评估与改进》独立指出，`AiQuickBar`（首页常驻 AI 动作主入口）和卡片右键菜单执行变换**没有行为埋点**，不会写入 `action_events`。这意味着即使 D2a 落地，如果用户主要通过 `AiQuickBar` 使用 AI 动作，这些动作的使用次数/编辑率统计可能因为埋点缺失而不准确，D2a 的降权效果可能测不出来或测出来是错的。这个埋点缺口本身工作量很小（把已有的 `useActionEventLog` 推广到这两个入口），但**是否要和 D2a 打包一起做**，还是先做 D2a 验收看效果再决定，需要你和用户确认——本文档暂不把它算进 P0，放在 P2 里单列，但建议在做 D2a 验收测试前先检查这个缺口是否会干扰验收结果。

### P1 · 建立最小 Agent 循环

**核心思路**：把 `ai_plan_chain`（规划）和 `chains.rs`/`ai_run`（执行）真正串起来，做成"AI 生成多步方案 → 用户确认 → 执行器逐步跑 → 每步结果反馈进下一步决策 → 遇到分支/失败可调整"，而不是现在"生成方案后交给人肉去点"。

**要新增的能力**（与《终极剪贴板-三支柱方案》《终极剪贴板可执行路线图》Phase 3 提出的"Agent 智能粘贴链"是同一件事，本文档把它列为独立优先级项而非某个版本的子任务）：
1. 执行器：接收 `ai_plan_chain` 输出的方案，逐步映射到 `chains.rs` 的执行原语，每步执行完把结果作为下一步的输入/决策依据（可能需要调整参数、跳过某步、或提前终止）
2. 执行前整体预览：一眼看完这条链会对这段内容做什么（《终极剪贴板-现状评估与改进》指出这是"可托付"缺失的三样东西之一）
3. 中途失败回滚：某一步失败时，前面步骤的副作用如何撤销
4. 结果差异对比：每步改了哪些地方，可展开可验证

**复用的现有地基**：`chains/registry.ts` 的 `runChain`、`ai/actions.rs`、粘贴脱敏守卫（出网前脱敏前置）、v6.10 已有的流式输出+可回滚改写交互。

**红线对齐**：整条链仍需用户手动触发确认才开始执行（红线①不变）；每步可预览/中断/撤销，不是"AI 自己决定后台跑完"。

**当前状态**：规划中未落地。现有 `chains.rs` 只是人工预先搭建的静态动作链框架，`ai_plan_chain` 只生成方案不执行——两者从未打通，这正是《AI-Agent 演进分析》里"行动循环 0/10"的原始诊断，两年内没有变化。

**验收标准**：不是"链能跑"，而是给一个真实多步场景（例如：复制报错 → 解释 → 生成修复建议 → 生成回复草稿），人工确认整条方案后，执行器能自动跑完全程；中途人为让某一步失败，能正确回滚前序步骤的副作用；且每一步的输出与下一步输入之间的因果关系能在 UI 上展开查看（不是黑盒跑完只给最终结果）。

### P2 · 其余功能性规划

> 按主题分组，不逐条罗列成流水账。每项标注状态；已完成/已废弃的项直接注明，不重复展开论证过程。

**记忆与检索增强**
- `sequence_memory` 接入推荐排序（目前是孤岛功能，`SequenceDiscover.tsx` 有独立入口但从不参与 `recommend.ts` 的决策；连续行为聚类"过去 20 分钟连续复制 5 段 SQL+2 条报错=在调数据库"比"现在是上午 10 点"信息量大得多）——规划中未落地
- 跨条目事件聚合（"想起一件事"而非"找一条内容"）——规划中未落地，属新能力非缺陷
- 跨设备 RAG（云端 embedding + `lan_sync.rs`）——规划中未落地
- 图片 OCR 文本接入 FTS5（图片可按图中文字搜索，对标 Paste 5.0 但走本机/云端视觉模型）——规划中未落地

**变换系统结构性缺口**
- `kind` 增加"多结果"与"双输入"类型，收编 `ExtractDialog`（多结果提取）、`ConfigDiffDialog`（双输入对比）进 registry——目前两者均为独立 lazy 弹窗，不在变换系统契约内，学习系统天然看不到它们——规划中未落地

**可解释性**
- 推荐结果加"为什么排第一"的说明——规划中未落地，是解决"用户不敢深度托付"问题的最小切口

**风格趋同（本地优先，视 P0-1 的 A/B 结果决定投入力度）**
- S1 本地风格规则：从 (before, after) 编辑对挖掘标点/句长/词汇替换等确定性规则，本地执行、零出网、100% 可靠；含数字/链接/专名的替换不学；配自愈机制（规则被改回去 ≥2 次自动停用）——规划中未落地，**若 P0-1 的 A/B 测试显示画像注入效果不显著，此项应转为主力投入**
- S2 输出要求枚举化：把能本地做的从 `action_prefs` 自由文本分流出去，剩下改用枚举模板句——规划中未落地
- S3 授权样本（few-shot，默认关）：用户主动粘贴 1-3 段自己写的文字作范例，仅用于改写/润色/总结类动作，硬约束"不从剪贴板历史自动挖样本"——规划中未落地，泄露量低于直觉（发送用户自己主动挑选的内容，知情结构比 D1 更清晰，但被早期文档误排在 D1 之前，已纠正）

**推荐质量度量**
- 推荐评测集：`eval/recommend-samples.jsonl` 20 条标注样本 + `npm run eval:recommend` 跑分，只管推荐排序命中率，**不测 AI 输出质量**（输出质量由 P0-1 的 A/B 编辑距离测量，两者是互补而非替代关系，早期文档曾把评测集当作"越用越聪明"的唯一证明手段，已纠正为"两把不同的尺子测不同的东西"）——规划中未落地
- 自进化区展示：把当前静态数字换成周趋势曲线——规划中未落地

**画像可移植导出（把"懂用户"变成可移植资产）**（来自《记忆系统与可移植用户画像规划》，独立主题，此前版本遗漏未纳入，现补齐）
