# 手机控制端交互重做方案

日期：2026-10-02。范围：手机控制电脑的会话页优先，以及键盘、剪贴板、连接状态、配对/无人值守等辅助页面。延续已确认 C 方案的苹果简洁风、桌面主题色和 Lucide 图标；本轮为方案，不修改应用代码。

## 当前问题（依据真实源码）

1. 手势需要记忆：单指移动是移动远端鼠标；长按原地抬起是右键，长按移动是拖拽；双指由算法判断滚动或缩放。缺少明确的鼠标模式和左右键入口。
2. 有一个可疑的“点了没反应”来源：touchClassifier 中，按住 220–550ms 后原地抬起不会产生点击。它是既有防误触设计，但可能拒绝正常偏慢的点击。需用手势测试和真机复现确认，不能仅靠外观调整解决。
3. 画面缩放与电脑滚动没有明确分工：PinchViewport 仅提供捏合/复位，没有独立“移动手机视野”工具。用户放大以后寻找窗口边缘会困难。
4. 软键盘使用隐藏输入框；修饰键、功能键和输入模式同时展开，多行控件挤压视频。组合键是否挂起需要更显著反馈。
5. 横屏工具栏自动隐藏，依赖 24px 顶缘热区唤回，缺少持续可见的把手。横竖屏切换目前还要进入“画面”弹层。
6. 画面区有等待/异常文字，但连接状态、等待首帧、画面暂停、恢复连接尚未组成统一流程。收到本地输入不等于电脑实际完成操作。

参考源码：RcMobileSession.tsx、SessionToolbar.tsx / RcMobileSession.module.css、ModifierKeyBar.tsx、SoftKeyboardBridge.ts、touchClassifier.ts、useImmersiveCapsule.ts、PinchViewport.tsx / PinchViewport.module.css、VideoSurface.tsx / VideoSurface.module.css。辅助页面基线为 RcPairCard、RcUnoJoinCard 及当前文件/设置页。

## 三个方案

### R1 · 画面优先，直接触摸

- 默认点哪里操作哪里；放大镜用于小按钮，双指捏合缩放。
- “移动画面”明确切换为本地视野调整，退出后恢复电脑操作，模式常驻可见。
- 右键/拖拽可用显式按钮，不要求用户记长按。
- 工具栏保留键盘、鼠标操作、横竖屏、更多，折叠后留把手。
- 优点：轻、直观、观看空间大，适合简单确认与浏览。
- 缺点：电脑小控件仍难点；手指会遮挡目标。精细办公改善有限。
- 相对工作量：较小；仍需调整手势、缩放边界与键盘布局，不能只换 CSS。

### R2 · 精准触控板，双模式（推荐）

- 控制电脑默认“触控板”：手指划动移动鼠标，点击作用于当前鼠标位置；可以切换“直接点击”。记住每台电脑的选择。
- 可展开一行“左键 / 右键 / 拖拽 / 滚动”。拖拽有明确按住态，再点释放；切模式、转屏、失焦或会话中断都释放按键。
- 指针本地反馈立即显示。若后端没有真实光标回传，不把本地指针宣称为电脑的实测光标；区分操作反馈与远端画面确认。
- 放大时指针靠近边缘才移动本地视野；明确“适应屏幕 / 实际大小 / 回到指针”，限制视野不被拖到空白。
- 工具栏常驻“鼠标模式 / 键盘 / 横竖屏 / 更多”。剪贴板与画质放更多；辅助鼠标行可展开，高频动作不弹大面积遮挡画面的模态框。
- 横屏展开工具栏可以收起，但保留窄小的“工具”把手，可选左右侧停靠；不用猜顶缘热区。
- 键盘打开后，主工具栏替换为单行快捷键，不再与完整导航叠加。常用 Ctrl、Alt、Tab、Esc、Enter 与扩展键分层；中文输入默认，按键模式进入扩展。
- 优点：适合多数电脑远控，能精确点击、右键、拖拽，延续现有 C 方案。
- 缺点：首次需要解释“点击发生在指针处”；涉及本地鼠标坐标与视野逻辑，工作量中等。

### R3 · 画面与操控区分开

- 竖屏上方显示电脑画面，下方展开独立触控板，左右键与滚轮可见；操控区可收起。
- 横屏采用窄侧栏操控区，画面与控制区域分开；输入时切换为单行快捷键和系统键盘。
- 优点：手指不遮挡电脑内容，适合持续办公和精细拖拽，学习成本低。
- 缺点：会占用屏幕空间；小手机/横屏开键盘时视野较窄，建议只作为 R2 的可选增强模式。
- 相对工作量：较大；必须验证各种屏幕尺寸、画面比例与控件可达性。

## 推荐的完整会话流程

连接申请 → 等待电脑确认（可取消）→ 等待画面（只给真实状态，不捏造百分比）→ 控制/只看 → 异常恢复或返回设备。

- 等待过久解释当前卡在哪一步，保留取消；只看模式在画面页持续标明。
- 确认失联或画面异常时避免在冻结画面上继续输入；恢复状态优先复用共享会话/帧/连接状态判据，不另造一套“在线”判断。
- 横屏不强制锁定；一次点击可切换，系统拒绝时在原处说明。
- 返回先收键盘/辅助控件，再退出会话确认；远端 Esc 与退出手机页面是两个可见动作。
- 成功、等待、失败使用实际业务返回与画面状态；动画只表示本地按钮按下或面板开合。
- 150ms 按压/色彩反馈，200ms 小控件变化，300ms 面板；减少动态效果时取消位移，实时控制路径不等动画结束。
- 点击目标至少 44px，主按钮建议 48px；亮暗主题、320px 窄屏、刘海/手势安全区都验收。

## 其它手机页面

| 页面 | 重点优化 |
|---|---|
| 配对 | “扫一扫 / 输入配对码 / 出示我的码”明确分入口；核对设备名与码，到期和相机权限失败在当前页说明 |
| 无人值守 | 先选电脑，再选接入码或密码；默认呈现最常用方式，完整凭证/高级输入折叠；失效时给下一步 |
| 连接中 | 当前目标、等待阶段、取消；超时/拒绝给原因与重新尝试，避免泛泛“连接失败” |
| 剪贴板 | 显示发送方向、文字预览或字符数；读取手机内容只在明确操作后；等待和拒绝可见，不自动同步 |
| 文件 | 从设备进入时预选目标；系统选择、上传、等待对方、实际传输分阶段；失败可重试并保留已有任务 |
| 会话记录 | 设备、结果、时间、时长先展示；失败说明可展开；清空独立确认 |
| 手势帮助 | 就地一页图解和可交互练习；首次连接出现短提示，可跳过/重看，不在每次连接强制教学 |

## 实施顺序与验收

1. 确认 R1/R2/R3；生成控制中、键盘展开、横屏收起、鼠标辅助、连接异常等 HTML 设计稿，再进入实现。
2. 优先处理手势误判、工具入口、键盘挤压和按键释放；随后做精确指针/视野、辅助页面与反馈。
3. 保持原共享帧泵、会话、文件与权限能力；拆分工具条、鼠标辅助控件、键盘行及输入/视野 Hook，组件规模遵守项目要求。

验收任务：在小屏电脑画面点小按钮、完成右键和拖拽、滚动长页面、中文输入与一次组合键、放大后找回目标、横屏收起后找回工具、处理断流/失败/取消。模式切换和失焦不能留下远端按住的键；只看模式零输入；隐藏页面没有新增常驻动画或无用计时器。

需要真机核对：软键盘/中文候选、Android 系统返回、横竖屏拒绝、触控精度和实际链路延迟。研发时应分别记录手势分类、输入发送和画面到达，避免把网络或坐标错误误判为视觉问题。
