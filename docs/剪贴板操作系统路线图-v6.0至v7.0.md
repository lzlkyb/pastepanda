## 一、核心洞察

### 1. “理解用户习惯”不需要遥测

剪贴板工具的独特之处在于：**用户的行为数据本来就全在本地**。他复制了什么、选了哪个动作、粘到哪个应用——这些不需要传到任何服务器就能学。

所以“自我净化学习”不但不违背隐私优先，**它恰恰是本地优先才做得成的东西**。这一点上相对 Raycast 有结构性优势：他们很多能力必须走云，我们的核心学习循环可以完全离线。

### 2. 一个正在被浪费的信号

现在每次用户在变换中心选了某个动作，这个选择**用完就丢了**。而它是天然的标注数据：

> 「这段内容 + 这个来源应用 + 这个时间点 → 用户要的是这个动作」

还有一个更值钱但目前完全没记的信号：**粘贴**。复制可能是误操作，**粘贴才说明内容真的有用**。`paste_text` 目前只管执行，没有回写使用记录。

### 3. “推荐排序”与“垃圾清理”是同一个判断

现在的自动清理是「按天数删」——不管这条内容有多重要。真正的净化是**按价值删**，而判断价值需要的恰好是同一份使用日志。

## 二、路线图

### v6.0 · 复制即执行（纯本地，零依赖）

**目标**：把“复制即动作”从口号变成字面实现。

> **进度（2026-08-09）**：前三项 ✅ 已落地（v5.7.0）：`action_events` 表 / 执行类动作（URL、路径、邮箱、IP域名查询）/ 卡片动作条 / `Transform` 契约 `kind` 扩展。**shell 动作**（打开终端并填入不回车）因 Windows 无标准“填入不回车”API + 红线③要求高，单独评估后再做。

| 交付物 | 说明 | 状态 |
|---|---|---|
| **`action_events` 表** | 记录每次动作选择，后续所有学习能力的燃料 | ✅ v5.6.7（log/stats/clear 命令就绪，枢纽复制/粘贴已埋点） |
| **执行类动作** | URL→浏览器、路径→资源管理器、邮箱→mailto、IP/域名→查询；**shell→打开终端并填入（不自动回车）** | 🟡 前 4 个 v5.7.0 完成；shell 动作待评估 |
| **卡片上的动作条** | 不用打开枢纽就能看到 top-N 推荐——这是“复制即动作”与“复制后再找工具”的分界线 | ✅ v5.7.0（hover 显示 action 类 top-3，点即执行） |
| **`Transform` 契约扩展** | 新增 `kind: "text" \| "action"`（前者产出文本，后者产生副作用） | ✅ v5.7.0 |

**需要新建的表**：

```sql
CREATE TABLE action_events (
  id INTEGER PRIMARY KEY,
  action_id TEXT NOT NULL,      -- 'sql-in' / 'ai-translate' / 'act-open-url' ...
  content_type TEXT,            -- 来自现有 ContentClassifier
  source_app TEXT,              -- 来自现有 SOURCE_MAP 规范化后的应用名
  hour INTEGER,                 -- 0-23，时段特征
  outcome TEXT,                 -- copied / pasted / abandoned
  created_at TEXT NOT NULL
);
```

**隐性成本（必须先付）**：`Card.tsx` 当前 **929 行**，远超项目规则 #7 的 300 行上限。往里加动作条之前必须先拆。这是本版最大的一笔开销，不在动作逻辑上。

**为什么排第一**：不需要 Key、不需要网络、不花钱，而且它验证的是整个方向最不确定的假设——**动作前置到眼前，用户到底买不买账**。如果这个交互是错的，后面全白搭。

### v6.1 · 从“推荐”到“记住”（本地学习，仍无模型）

**目标**：让排序从“对所有人一样”变成“对你一个人对”。

```
最终排序 = detect() 静态分 × 个人使用频次权重
```

> 例：你在 VSCode 里复制 JSON，过去 20 次有 18 次选了「格式化」→ 下次它自动排第一。

> **进度（2026-08-09）**：v6.1 **全部完成** ✅（v5.8.0 核心闭环 + v5.8.1 自我净化）：
> 个性化权重排序（`src/lib/recommend.ts`，冷启动阈值 20 次）/ 「不再推荐这个」（`action_dismissals` 表 + 枢纽 ✕）/ 粘贴信号回写（`paste` 哨兵 + history_id）/ 设置页「系统学到了什么」（红线②）/ **自我净化**（`VALUE_PRESERVE_SQL`：有标签 OR 被粘贴过 OR 搜索命中过 → 永久保留，统一应用于过期清理与计数，保证"计数=清理数"）。

配套（✅ v5.8.0）：

- **「不再推荐这个」**——负反馈。没有它，推荐只会越来越吵
- **冷启动策略**——前两周数据不够时退回全局默认分。不能让新用户面对一个“还没学会”的产品
- **粘贴信号回写**——`paste_text` 执行后记一笔 `outcome='pasted'`（主列表 + 卡片右键粘贴）

**自我净化（按价值清理）**（✅ v5.8.1）：

| 信号 | 处置 |
|---|---|
| 从没被粘贴过 + 从没被搜索命中 + 来源是临时窗口 | 优先清 |
| 被反复粘贴 / 被打过标签 / 被搜索命中过 | 永久保留，不参与过期 |

### v6.2 · 主动建议（风险最高的一步）

**先说风险**：主动建议就是打断。做错了就是第二个 Clippy。三条硬约束：

1. **绝不弹窗**。只在用户已经打开界面时出现
2. **只给 top-1，不给列表**。给列表说明你不确定，那就别主动
3. **一眼可否决**，且否决被记住

> **进度（2026-08-09）**：**v6.2 全部完成** ✅（v5.9.0 + v5.9.1）：
> 主窗口 inline 建议条（SuggestionBar：top-1 ≥0.75 + 序列识别 3 个 IP/邮箱 → 合并 SQL IN，
> 「使用」定位/执行、✕ 记住、8s 自动收起，三条硬约束落实）；
> **托盘弹窗建议条（v5.9.1）**（TrayPopupSuggestion：复用同一引擎，「使用」直接粘贴前台）；
> **来源+时段感知（v5.9.1）**（`action_scene_weights` 场景权重 + 前端场景加成，SCENE_MIN_EVENTS=5 退化）。

具体形态：

- 复制后托盘弹窗直接显示**一个**最可能的动作，而不是历史列表 — ✅ v5.9.1（TrayPopupSuggestion，最新记录 top-1，使用即粘贴）
- **序列识别**：连续复制了 3 个 IP → “要合并成 SQL IN 吗”。变换本身早就有了，缺的是“注意到你在做一件多步的事” — ✅ IP/邮箱序列
- **来源+时段感知**：工作时间在 IDE 里复制→偏工程类动作；晚上在浏览器里复制→偏阅读类 — ✅ v5.9.1（hour_bucket × source_cat 场景权重）

### v6.3 · AI 深化

建在已完成的 B0–B2 上，**不是新范式**：

- **自然语言动作**：“把这个改得正式一点” → 路由到 `ai-rewrite` 并带上语气参数 — ✅ v5.10.0（`nlActionParser` 本地关键词解析，零 AI 成本；枢纽顶部 NlCommandBar 定位 + 预填参数；门控规则 15：AI 未启用提示先配置）

## 三、三条写死的红线

### ① 学习只影响排序，永不自动执行

剪贴板是高频低容错场景。一次错误的自动执行（比如自动打开了不该打开的链接），用户会**永久关掉**这个功能，而且不会再打开。

> 理解习惯 → 调整顺序；**绝不** → 替用户按下按钮。

### ② 使用日志永不出本机，且用户可见可删

设置里要能看到“系统学到了什么”并一键清空。这是“本地优先”的可信度来源——说了不上传没用，得让用户能查。

### ③ shell 命令永不自动执行

只做“打开终端并填入”。剪贴板内容可能来自任何网页或聊天窗口，一键执行等于把远程命令执行权交给任何能往剪贴板塞东西的人。

**这条不给开关**——给了开关就是把责任推给用户，而用户不理解这个风险。

## 四、关于验证：你就是第一个数据源

仓库现状（2026-08-08 实测，见下方事实基线）：**6 star、347 次累计下载**，没有用户群可以做 A/B。

所以——**你自己就是第一个也是唯一的数据源。** 这不是坏事：`action_events` 一旦上线，你每天用它，两周后就能看出“哪些动作我从来不点”“哪个排序是错的”。这比 20 个访谈更真实，而且**明天就能开始积累**。

反过来说：先做遥测、先定 30k star 目标都是本末倒置。**先让它对你自己变得不可替代**，这是 1Password 和 Raycast 早期真正走过的路。

---

## 五、建议的第一步

**从 `action_events` 那张表开始，而不是从执行类动作开始。**

理由：表先建好，现在每天用变换中心的选择就开始被记录。等 v6.1 做个性化排序时，已经有两三周真实数据可用——**否则那时候才建表，又要空等两周**。

改动很小：一张表 + 在 `TransformCard` 的 copy/paste 回调里各写一行。
