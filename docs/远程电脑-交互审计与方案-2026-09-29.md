## 0. 结论先说

「交互不友好」不是几十个点状 bug，而是**四类结构性缺口**，每一类能一次性解释一批症状：

| 代号 | 结构性缺口 | 一句话 |
|---|---|---|
| **S1** | 反馈与触发不在同一可见性域（AGENTS 规则 15.1 / 15.3） | 按钮在浮条里，结果却渲染在一个会被**条件卸载**的面板里 |
| **S2** | 状态机只做了 happy path | 断连 / 超时 / 降级 / 权限被拒这四种终态没有常驻表达 |
| **S3** | 输入接管没有交接协议 | 谁在拿键盘、什么时候还、怎么抢回来，既没明示也没开关 |
| **S4** | 会话在系统层「不存在」 | 窗口一藏，被控端没有任何系统级信号知道自己正被看着 |

## 1. 控制端（我在远控别人）

### C1 🔴 P0 · S1 「⋯」面板一关，操作结果和重试入口一起消失
- 证据：`src/components/rc/RcSessionCapsule.tsx:240` 用 `{moreOpen && <RcCapsuleMore/>}` 条件渲染；面板内的反馈全部内联在子件里——`RcClipboardBar.tsx:131-135`（自动同步失败/正常两行）、`RcFileBar.tsx:106-109`（进度与失败，空闲时整条不渲染）、`RcAudioBar.tsx:78-90,110-114`（「对方已静音」等）。

- 这是规则 15.2（容器卸载带走子组件状态）+ 15.3（失败只 setState 不弹 toast）的**同时命中**。

### C2 🔴 P0 · S1 全屏时错误面板挂在全屏元素之外，完全不可见

- 后果：全屏远控正是最容易出错的场景（链路断、被拒、编码失败），而此时**唯一的错误出口不在屏幕上**。

### C3 🟠 P1 · S1+S2 断连只剩「最后一帧 + 一枚会淡出的 pill」
- 证据：胶囊隐藏即 `aria-hidden` + `tabIndex=-1`（`RcSessionCapsule.tsx:126-128,137`），显隐由 `useRcCapsuleReveal.ts:27-31`（首显 15s、淡出 2.5s）驱动；链路死的常显微光条只有一条线（`RcSessionCapsule.tsx:139-143`）。自动重连 2/4/6s **只对被控端免确认设备生效**（`src-tauri/src/rc/service/lifecycle.rs:447-477`），控制端没有自动重连，只有 `RcCapsuleAlerts.tsx:48` 一个手动按钮，且 busy 时与「结束」同时禁用无解释（`RcCapsuleAlerts.tsx:52`）。断链判死要等 ping 陈旧 12s（`src/lib/rcSessionStats.ts:65-67`）→ 最长约 12.5s 才变红。
- 后果：画面冻住 ≠ 用户知道断了；`RcReconnectBanner.tsx` 在**另一个窗口**（主窗），会话窗永不告知「第 N/M 次重连」。
  > 已改掉的部分（乙-③/⑥，2026-09-29）：链路死的**微光条不再随浮条淡出**（提到 `.capZone` 直系子元素），
  > 且异常那一刻自动展开一次 + 把手整枚染红 ⇒「断了」这条告知现在常驻可见。
  > **仍未改**：没有断连遮罩/大字、控制端没有自动重连、判死仍要等 ping 陈旧约 12s。

### C4 🟠 P1 · S3 点一下浮条，就把按住的所有键释放掉

### C5 🟠 P1 · S3 中文输入法在远控下全程失真

## 3. 方案（三档，可分开拍板）

> 三档不是互斥备选，是**同一批问题的三个深度**。建议按甲→乙推进，丙单独立项。
>
> **落地进度（2026-09-30，别把这张表当已完成度）**：
> 甲 1–4 **全部落地**（1 = `RcCapsuleOutlet` 常驻出口，2+3 = 错误条进全屏元素 + 断连遮罩，
> 4 = 三条原因码跨端），记录在 §12；浮现带那四条在 §8。
> 甲-5 的重连**落成「条件键」**（链路异常时光标级常驻的「立即重连」+ 二级行都在），
> 只有一级 Ctrl-Alt-Del 没做，理由与核对见 §12.2 甲-5 条。
> 乙 1–6 **全部落地**（§12），C3/C4/C5/C6/H4 的对应缺口按各自条目标注闭合。
> 丙-①② 落地（同一块置顶窗口 `rc-ask` 的两种形态，理由见 §12.3）；
> 丙-③ 落地（**按「停止推流」那一档**，被控端一键暂停对方看到的画面，机制否决见 §12.6）。
> 已提交：`e4bfe56`（浮现带那一批）+ `8aadac5`（本轮甲-1..5 补齐、乙-1..6、丙-①②③）
> + `a83553d`（`rc-ask` 补登记进 `TOOL_WINDOW_LABELS`），全部**未升版**。

### 甲 · 「可见性收口」——纯前端，不动协议（解 C1/C2/C3展示/H2前端/H3/H5展示）
把散落在会卸载面板里的反馈，提到与按钮同一可见性域：
1. **会话结果走常驻出口**：`RcCapsuleMore` 内的四类结果（码率/声音/剪贴板/文件）不再只内联；失败一律同框 toast，成功在胶囊上留一枚可淡出的状态字符。文件进度单独一条常驻细条（面板关着也走完）。
2. **错误面板搬进全屏元素内**（`wrapRef` 子树），全屏不再零提示。
3. **断连遮罩**：画面加一层半透明遮罩 + 大字「连接已中断」+ 手动重连按钮 + 倒计时；`linkLocked` 期间警示 pill 不参与淡出。
   > 现状拆两半：后半条**换了形态才落地**——`linkLocked` 这个 flag 已不存在（乙-⑥ 起
   > 不永久锁显，改成「异常那一刻自动展开一次」+ 把手整枚染红 + 微光条常驻，§10.2）；
   > 前半条那层**断连遮罩没做**（控端断连仍只有「最后一帧 + 会淡出的 pill」，=C3）。
4. **被拒/超时/满员丢弃**都有各自的中文原因文案，控制端「拒绝」补 else 分支。
5. **胶囊一级项按对标重排**（§6.4）：一级留 断连 / 画质 / Ctrl-Alt-Del，把「重连入口」也提到一级；文件、剪贴板、声音、码率收进二级——但二级的**结果**必须有常驻出口（甲-1）。我们现在是分级放反了。
- 代价：改的文件正好压在 **A2 在途改动**边上（见 §4），要先协调；不涉跨端协议，风险低、见效最快。

### 乙 · 「输入交接与状态机」——前端 + Rust 小改（解 C3语义/C4/C5/C6/H4）
1. **IME 守卫 + 键盘模式做成会话内显式开关**：`useRcInput` 加 composition 起止闸（候选期间一律不发键，Enter 属候选则吞），并提供「打字模式（按字符翻译）/直传模式（按 scancode）」两档切换。`rcKeyMap` 的 Meta 不转发保留，但补一次「Win 键不转发」的可关闭说明。
2. **焦点/释放解耦**：`onBlur` 不再无条件 `releaseTracked()`——只释放修饰键，保留焦点恢复；点浮条不该等于松手。
3. **输入权交接协议（新增原语）**：被控端「夺取控制」（临时屏蔽对端输入，快捷键+横幅按钮双入口），控制端「锁定对方键鼠」开关；跨端要加 1 条消息类型 + 两侧按钮。对标 Quick Assist `Cancel control`。
4. **Esc 语义收敛**为两种（收面板 / 退出会话），指针锁与键盘改用可点击的显式 chip。
5. **自动重连补控制端**：对齐 `lifecycle.rs:447-477` 已给被控端的 2/4/6s 退避；**按 §6.6 只暴露结果**（「已恢复」/「需重新授权」+ 一行原因），不做「第 N/M 次」的过程计数。
6. 顺手修 `useRcFrames.ts:348-350` 的同码分支（真 bug，一行级）。
- 代价：动了输入/协议语义，改完**双机手测必须重跑**；`RcSessionCapsule.tsx`（264）、`useRcInput.ts`（419）体量接近或超项目线，需要拆。

### 丙 · 「系统级存在与信任」——被控端安全语义升级（解 H1/H5/H6）
> 落地情况（2026-09-30）：① 落成 `rc-ask` 独立置顶窗（确认卡 + 隐私角标两形态，§12.3）；

## 6. 对标补强（六家横查，带出处；这节会改写上面几处形态）

出处编号见文末链接。**已标「推测」的条目不当结论用。**

### 6.1 入站请求的载体（影响 H1/H2/丙-1）
- 主流是**置顶确认窗 + 超时自动拒绝**，不是系统通知：Parsec 应用内弹窗、无人响应自动拒绝；Chrome RD 支持模式弹框（含对方邮箱）点「共享」，且**每 30 分钟要求再确认**；RustDesk `approve-mode=click/password-click`；Moonlight/Sunshine 只在配对时批准，之后免逐次同意。
- ⇒ 我们 120s 人工同意窗 + 逐台免确认**已同构主流**，丙档不需要把「系统通知」当主载体，只需要保证**置顶确认窗在主机窗口隐藏时一定浮出来**（=甲/乙的可见性问题，不是新原语）。
- **值得抄的一条**：Quick Assist 与 RustDesk 都把「看屏幕」与「拿键盘鼠标」**分成两次授权**。这直接支持 H5 的分级授权，且比我们现在「一个 capability 一档全给」更细。

### 6.2 隐私指示（影响丙-1 的形态选择）
- **六家都没有常驻全屏水印**。Parsec 是被控端窗口左下常驻「在线用户列表」，并按鼠标/键盘/手柄图标**红/绿闪烁**区分「有权限且正在操作」vs「无权限却试图操作」；RustDesk 是隐私模式（黑屏遮盖物理显示器，仅 Windows，可按 peer 默认开）；CRD 是「停止共享」入口；Moonlight 文档明确**无活动中指示**。
- ⇒ 丙档正确形态＝**小面积常驻指示 + 一键终止**，并把 Parsec 的「谁正在动你的鼠标」红绿语义借来做 H4；托盘变色是我原先的猜测，无先例支撑，降级为可选。

### 6.3 输入权交接（影响乙-3）
- **没有任何产品在「本地用户动了鼠标」时自动断开控制方**——要么共享竞争（RustDesk 默认），要么显式开关（TeamViewer/RustDesk 的 block-input，且**需被控端授权、仅 Windows**）。共同底线是「权限可随时一键撤回 + 被控方永远能物理抢占」（Quick Assist 的 `Cancel control`、Parsec 的 Ctrl+F3 踢人）。
- ⇒ 乙-3 按「显式开关 + 一键撤回」做是对的；**不要**做成「本地一动就自动放手」的智能抢占。

### 6.4 会话工具栏（影响 C1/C6 的目标形态）
- 三种形态并存：TeamViewer 常驻四 Tab、RustDesk 可自动收起顶栏、Parsec 角标点开。**共识是一级项＝断连 / 画质 / Ctrl-Alt-Del，二级＝文件 / 聊天**；且全屏时都不常驻占高。
- ⇒ 我们现在把「重连、剪贴板、文件」全塞进会卸载的「⋯」，同时一级缺 Ctrl-Alt-Del——**分级放反了**。甲档的常驻出口应按这个共识重排，而不是简单加 toast。

### 6.5 质量反馈（影响 C8）
- Parsec 在角标**旁边**挂异常警告图标（网络拥塞/解码跟不上），即使面板收起也在；RustDesk 有 `show-quality-monitor` 浮层 + `enable-abr` 自适应码率。
- ⇒ 甲档「链路异常警示不参与淡出」有直接先例（我们现在是 `RcCapsuleAlerts.tsx:34-47` 随浮条一起藏）。另外我们的四段延迟归因（采集/编码/网络/解码）**已经比单一 ping 的业界基线好**，只缺档位色码。
- 「卡顿/重连时冻结画面+进度+预估」六家均未找到官方描述 ⇒ **别指望抄，自己定**（甲档遮罩是唯一先例缺失处，需在 HTML 稿里单独点验）。

### 6.6 重连（影响乙-5）
- 各家把自动重连当**默认体验而非用户决策点**：文档里可查的只有 RustDesk `auto-disconnect-timeout`（默认 10 分钟无操作断）与 CRD 30 分钟续确认。
- ⇒ 暴露给用户的应只有**结果**（「已恢复」/「需重新授权」），而不是「第 N/M 次重连」的过程计数。我原先的方案偏过程，应改为偏结果 + 一行原因。

### 6.7 键盘模式（影响乙-1）
- RustDesk 三档（map/scancode/translate）+ 触摸模式；TeamViewer 自动 + 直接键盘两档；**六家无一实现「自动判定成功」**，都做成会话内可切换的显式开关。Quick Assist 明文「布局/鼠标设置以被控方为准」。
- ⇒ 只要做到「打字模式 / 直传模式」两档显式切换就**达到业界基线**；IME 是所有产品的公开短板，做半档就能拉开差距。

### 6.8 我们已领先的项（不要为了对标而改掉）
双端同显 6 位 SAS 防 MITM（强于全部六家）／四段延迟归因 HUD／被控横幅 + 能力范围变更即时通知／剪贴板自动同步的「开启瞬间建基线、必须用户主动改动才首发」（`useRcClipboardAuto.ts:5-8`）。

### 8.1 缺陷机制（先说清楚是谁挡住谁的）

控端浮条的可见遮挡带与唤出热区原本**同深**，这就是「点不到远端标签 ✕」的根源：

| 量 | 修前 | 出处 |
|---|---|---|
| 胶囊离画面顶缘偏移 | 12px | `.capCapsule { margin-top: 12px }` |
| 胶囊高度 | 34px（+上下描边 ⇒ 遮挡带 y 12–46） | `.capCapsule { height: 34px }` |
| 顶缘唤出热区 | 12px（= 遮挡带同深） | `REVEAL_BAND_PX = 12` |
| 唤出后何时可点 | **立刻**（`pointer-events: auto` 常驻） | `.capCapsule` |
| 隐藏态能否当悬停目标 | **能**（比胶囊矩形，不看可见性） | 2026-09-27 审查改用 `capRef` 矩形 |

远端浏览器标签 ✕ / 地址栏正好落在 y 12–46。指针从画面内部往上够它，路径先经过 12px
热区（或隐形胶囊矩形）→ 浮条弹出且立刻可点 → 落点变成浮条按钮。

### 8.2 落地的四条（各堵一段，全在 `useRcCapsuleReveal.ts` + 一条 CSS + 一处挂载）

| # | 措施 | 值 | 堵掉哪一段 |
|---|---|---|---|
| ① | 顶缘热区收到画面最上缘 | 12px → **3px** | 从内部往上点不再经过热区 |
| ② | 隐藏态不以胶囊矩形为悬停目标 | `overCap` 仅在 `shown` 时算 `hold` | 飘过 y 12–46 不再弹出 |
| ③ | 进带后 dwell 才唤出 | **180ms** | 快速穿过顶缘不算意图 |
| ④ | 唤出后不参与命中测试 | **200ms**（`.capZoneThru .capCapsule, .capZoneThru .capCapsule *, .capZoneThru .capHandle { pointer-events: none }`，末条是乙档把手落地时补的） | 已经触发了的那一下点击仍落到远端 |

🔴 ④ 里那条 `*` 不是装饰：`.capBtn` / `.capReq` / `.hudPanel` 各自重申了
`pointer-events: auto`，父级置 `none` 对它们只是**可覆盖的继承值**——只写父选择器的话，
穿透窗口对「真正会吃掉这一击的按钮」完全失效，而计算样式看上去是对的。守卫单测现在同时
钉这两条选择器与「子规则仍重申 auto」这个前提。
（对照：隐藏态安全是因为 `.viewToolsHidden` 带 `visibility: hidden`，它直接取消命中测试。）

判断收口成纯函数 `rcRevealGestureOf({overCap, inBand, shown}) → hold|keep|dwell|idle`
（规则 11.1：四档一处判定，守卫单测钉住）。指针离开画面（stage `mouseleave`）作废在飞
dwell；`pointerLocked` 时整条唤出照旧不生效；**F10 与「已显示后悬停本体」是显式意图，
不走穿透窗口**（`setThru(true)` 在源码里恰好一处，多一处就是「看得见却点不动」的新 bug）。

### 8.3 对标依据（本节只留结论，横查全文见 §6）

- **Fitts 定律**：屏幕边缘是无限大目标——顶缘本就该让给内容，浮条是客人。热区取 3px 而非
  0，是保留「顶到底再停一下」这条明路。
- **RustDesk 新 UI 干脆没有 hover 唤出**（issue #1842：「New ui does not have this problem
  because it does not have hover」），折叠钮还被横向钳在 35–65%（#3842 / PR #3881）——
  同属「让边 + 让开内容热点区」思路。我们没有做到零 hover，是把 hover 变成
  「需要 3px × 180ms 的刻意手势」。
- **dwell 180ms** 参考 Windows `SM_MOUSEHOVERTIME`（默认 400ms）的量级往下压：会话内
  唤出是高频动作，400ms 会被眼睛判成卡顿。
- **穿透窗口（hit-test delay）** 是 Chrome RDP 连接条 / Moonlight 浮现工具条的常规做法：
  浮现动画先给视觉反馈，短暂不吃输入，把这一击让给原本的目标。

**数值未经真机实测**：180/200ms 是按「一眼看不出卡、又足够让一次点击穿过」定的起点，
`REVEAL_DWELL_MS` / `REVEAL_THROUGH_MS` 是两个常量，实测手感不对就直接改数（守卫单测只
断言「大于 0」和「3 < 12」，不锁死具体毫秒）。

   dwell 时，飘过隐形胶囊仍会弹出。这条改了唤出心智模型（想知道浮条在哪 → 顶到底停一下，
   而不是移到它该在的位置），实机点验要专门看这条顺不顺手。

### 10.6 落地后自查（2026-09-29，用户「检查一下这次改动有没有 bug」）

逐条读了 `.capZone/.capFloat/.capHandle` 一族与 `useRcCapsuleReveal` 的四个 effect，
按「层叠与命中盒」重算了一遍几何。三处**是 bug、已修**（A 让位写法无效、B 重挂不作废
dwell、E 收起态瞬隐——E 是存量，用户点头后本轮一并修），三处**是设计代价、当轮只申报**
（C 命中盒吃进遮挡带、D 把手不吃 dwell、F 外挂徽标被窗缘裁），
这三处已在**同日第二轮**由用户「一起动手」拍板：C 收下探、D 只改口径不动代码、F 整枚染橙。
下面的 C/D/F 三段就是拍板后的定稿口径。

**A 已修：展开态把手的「让位」写法无效（正数 z-index 压不过 `z-index:auto`）**

`.capZone`（z-index:5）是层叠上下文；里面的 `.capCapsule` 是 `position:relative` +
`z-index:auto` ⇒ 画在第 8 步，而**任何正数** z-index 在第 9 步。原先
`.capHandleBehind { z-index: 4 }` 想让它退到胶囊后面，实际和 6 一样把胶囊压着。
可见的 24×12 本就止于 y 12、与胶囊（y 12–46）不相交，所以难看不是问题；
真正被抢的是 `::after` 下探那 9px（命中到 y 20）：胶囊上沿 y 12–17 是本体留白
（点下去不该有动作，但也归浮条），**y 17–20 正是那排 `.capBtn`（高 24、垂直居中 ⇒
占 y 17–41）的顶部 4px**，浮条展开后往胶囊上移鼠标、落在这条带里的那一下被把手接住 =
「点按钮却把浮条收起来了」，与单测标题「不抢同一击」正好相反。
修法把让位落在命中盒上：`.capHandleBehind::after { bottom: 0 }`（展开态命中 40×12），
`z-index: 6` 保留（否则胶囊那圈向上的投影会糊住把手）。设计稿 §3 那两行同批改口——
稿子本身也带着这个错（演示页没测这条点击路径，探针测不出来）。

**B 已修：顶缘 effect 重挂时不作废在飞的 dwell**

`mousemove` 那条 effect 的依赖里有 `shown / pointerLocked / hoverReveal`，任一变化都重挂；
原 cleanup 只摘监听、不 `cancelDwell()`，于是那 180ms 的计时器还活着，到点照样
`revealThrough`——「关掉顶缘悬停唤出后浮条又自己弹一次」是用户能看见的。已在 cleanup
里补 `cancelDwell()`，并加一条守卫（`useRcCapsuleReveal.test.ts`）。

**C 已拍板落地（2026-09-29 第二轮，用户「一起动手」）：收起态把手多吃的像素收到 4px**

稿 §3 写「可见 24×12 落在遮挡带之外」，这句对**可见**部分成立；但命中盒是 40×20，
收起态下 y 12–20、正中 40px 这一段归把手，不再是远端内容——这是常驻把手的必然代价，
不是漏算。全屏时把手从屏幕 y 0 起，远端浏览器标签栏顶那一条正中 40px 同样归把手。

判下来的改法是收下探：`.capHandle::after { bottom: -9px → -4px }`（命中 40×20 → 40×15，
吃进遮挡带 8px → 3px），`left/right: -9px` 与可见 24×12 都不动。
理由：那 8px 正落在远端标签 ✕ 那一行，而甲方案整轮修的就是「别在用户往上够标签的路上
吃点击」；它换的可达性接近零——全屏时屏幕顶缘按无限大目标算，窗口态上面紧挨着我们
自己的 36px 顶栏。**说清代价**：15px 和原来的 21px 都不满足 WCAG 2.5.8 的 24 见方，
往上扩才合规、但全屏态往上是窗缘外，等于扩到指针到不了的地方，所以这条按
「遮挡带让给远端」判，不按目标尺寸档判；键盘兜底仍是 F10。
守卫：样式表那条新增「收起态吃进遮挡带 ≤4px」，同时钉住下探不许被删成 0（把手只有
12px 高，一点容错不留就点不着）。

**D 已拍板（2026-09-29 第二轮）：不改代码，改验收口径——把手那一列不吃 dwell 是刻意的**

`.capZone` 与 `fakeScreen` 是**兄弟**（胶囊挂在 `.sessionWrap`，不在画面容器里），
所以指针停在把手上时，画面容器的 `mousemove` 收不到事件 → 顶缘正中那一条内
dwell 不会起算。

判下来**不去修**：常驻按钮再叠一层「悬停即唤出」，等于把甲刚删掉的「隐形悬停目标」
搬回原位——用户往上够远端标签时手上一停，胶囊就展开盖住 y 12–46，比现在
「什么都不发生、点一下才展开」更侵人；而这一列本来就有一颗看得见、点得着的按钮。
**验收口径按这句判**（§10.5 第 4 项同口径）：顶缘 dwell 覆盖的是

**E 已修（用户点头「另发现一处存量问题要修复」）：隐藏态其实一直不「淡出」**

`.viewToolsHidden` 把 `visibility` 延迟到 200ms（淡出结束后再隐），但承载它的
`.capFloat` 自己声明了 `transition: … visibility 0s linear 0s`——**同特异性、写在后面**，
整条覆盖了前者 ⇒ 收起是**瞬隐**，只有淡入有动画。HEAD 上的 `.capZone` 就是这个值
（注释还写着「visibility 延迟到淡出结束再切」），甲/乙两轮都没改变这个行为，
所以文档里那句「2.5s 淡出」严格说是「2.5s 后瞬隐」。

修法只在收起态加一条更高特异性的 `.capFloat.viewToolsHidden`（延迟 200ms），
显示方向保持 `0s`（淡入第一帧就得可见）——不能用「把基准值改成 200ms」那种省事写法，
那会让淡入头 200ms 处于 `visibility:hidden`，等于没有淡入。

**浏览器实测**（不是 jsdom，也不是估的）：在同层叠结构（`.pa-disc` 在前、`.pa-host` 在后、
修复条为 `.pa-host.pa-disc`）的探针页里，给元素加收起类后采样 `getComputedStyle`：

| 采样时刻 | 修前 | 修后 |
| --- | --- | --- |
| t=100ms | `visibility: hidden`、`opacity: 0.121`（看不见淡出） | `visibility: visible`、`opacity: 0.122`（淡出正在被看见） |
| t=320ms | `hidden` / `0` | `hidden` / `0`（该隐的还是隐了） |

守卫：`RcSessionCapsule.test.tsx` 样式表一档读 `.capFloat` 的淡出时长，要求收起态那条
复合规则的 `visibility` 延迟**等于**它，并反向钉住基准态必须是 `0s`（防止有人「顺手统一」）。
浮条在真机上的观感（2.5s 后那一下现在是否有 200ms 的滑出）仍归 §10.5 点验。

## 11. 下拉方向修好（2026-09-29，用户「悬浮胶囊画质点开往上打开到屏幕外被截断了，给我方案」→「按你推荐做」）

### 11.1 根因是一行坐标，不是一处样式

`RcDropdown.tsx` 旧的手算定位：

```ts
setPos({ left, bottom: window.innerHeight - b.top + MENU_GAP, minWidth: b.width });
```

`bottom:` 锚意味着菜单**永远往上长**。这行在 2026-09-22 是对的（那时它的宿主是贴着窗口
下沿的 `.sessionBar` 底栏，向下弹会被底边裁）；但 2026-09-28 浮条统一（窗口态与全屏态

同类病灶一起查（规则 11.1）：`.capMore` 面板自己也是「往下挂、无封顶」，矮窗口里
最后一段（会话/重连）会掉出画面下沿。两处一起修。

### 11.2 三档里选的那一档

- 甲（只改 CSS：`.menuPop` 改成往下 + `max-height`）：改动最小，但方向仍然写死，

### 12.6 丙-③ 暂停对方观看：**已按「停止推流」落地**（2026-09-30 拍板）

设计稿原话是「遮盖本机屏幕（对方仍在看，但看到的是黑）」，这句在两种机制下含义正好相反：

1. **每屏一块黑色置顶窗**（RustDesk privacy-mode 的字面同款）——本机物理屏被盖住，
   旁观者看不见。不调 `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)` 则黑窗一并进帧
   ⇒ 对方看到的也是黑；调了则只有房间里的人看到黑。两种都是真产品行为，但**语义相反**。
2. **停止推流 / 冻结出帧**——对方看到停帧，本机屏幕照常用。

用户拍板选 **2（停止推流）**，落地形态：

- **判据与闸门**：`src-tauri/src/rc/service/video_pause.rs`（`VideoPauseGate` 两位原子量 +
  `set_video_pause` / `emit_video_pause` / `*_begin` / `*_reset`）。出帧闸门插在
  `rc/inbound/video_run.rs` 的 `should_pause_stream()` 之后、提帧 `select!` 之前——
  暂停就 `sleep(PAUSE_POLL_MS=300ms)` + `continue`，**整圈跳过**（采集/编码/发送/
  `maybe_send_cursor` 全不跑：光标形状也是画面的一部分）。出帧只有 `run()` 这一条路
  （`try_hardware_path` → 数据报 / `send_pkt_via_stream` 回退，以及 `jpeg_path`），
  都在闸门之后，没有第二条口绕过它。
- **拦画面不拦会话**：心跳、输入读取、剪贴板、文件通道、音频链路照常——「挡眼睛」不挡
  「手」，与乙-③ 收回键鼠正交。恢复后立刻出一帧：暂停分支在 `frame_start` 之前就
  `continue`，`next_tick` 保持旧值，不需要额外唤醒管道。
- **每场会话有效**：`inbound_accept.rs` 建会话时 `video_pause_begin()` 双清位，
  `session/lifecycle.rs` 收口 `video_pause_reset()`。刻意与 `audio_local_mute`
  （跨会话的隐私意愿）**相反**——暂停是一时的动作，不该跨场生效，也就不会被
  无人值守路径「带着上膛」。
- **跨端告知**：`{"t":"vpause","on":bool}` 复用乙-③ 那条控制流（`inbound_send` +
  `write_frame`，与 `emit_input_state` 同款）。旧版对端未知类型落 `_ => {}` 自动忽略 ⇒
  **无需版本门控**；发起端投影用 `bool` 而非 `Option`（这条没有「未授权/未生效」三态）。
  发起端解出这帧后**主动 `notify.emit_changed()`**（乙-③ 的 `input_state` 没这条待遇）：
  不推就得等下一拍 status 轮询（会话中约 2s），而那 2s 里胶囊挂着的是「操作后 Ns 无画面」，
  等于把「他在挡着」误诊成「链路不行」。
- **机制否决记录**：黑色置顶窗那档**不做**——它必盖住丙-② 那颗「结束」角标与主窗，
  角标要在黑窗之上得靠 `SetWindowPos` 顺序/owner 关系，一旦排错用户只剩 Alt+Tab 可逃；
  而「接电话/拿文件」那个使用场景里，本机屏幕是要看的，挡的从来不是旁观者。

### 12.7 对稿偏差申报（本轮累计，验收时按这几条看）

1. 设计稿画的是**两块独立窗口**（丙-① 确认卡 + 丙-② 角标各一块），落地是一块 `rc-ask`
   换几何（内存理由见 §12.3）。窗口标签仍叫 `rc-ask`。
2. **不申请 DWM 圆角**（栈浮标/托盘弹窗/快速粘贴都调了它）：`todo_island.rs` 的实测结论
   是显式申请会压掉 layered alpha、四角露白；圆角与阴影全交给 CSS。
3. 字号被 lint 阶梯改口：卡片 12.5→13（标题）、角标 11.5→12，关闭键圆角 6→4px。
4. **分两次授权只做在浮层**：主窗 `RcJoinRequests` 仍是单按钮，两处措辞同源但档位不同。
5. 多条申请**一次只答一条**（其余折成「另有 N 条在等」），设计稿的列表连点没做。
6. 主窗 `RcReconnectBanner` 与新浮层**并存**（同一件事两个可见性域，靠 §15.1 判定可接受：
   主窗那条是历史位置，浮层是「主窗没开」时的兜底）。
7. Rust `AutoReconnect.attempt/max` 仍然投影，但 UI 不读（待拍板⑤ 的口径）。
8. 设计稿 §丙-② 那条「托盘图标带红环（可选）」**不做**（待拍板⑥）。
9. **丙-③ 只挡画面，不挡声音**：暂停期间音频链路照常推（声音另有「不发送声音」那一票
   否决）。设计稿那句没区分这两件事，验收时别把「没静音」当成 bug。
10. **暂停期间压掉「操作后 Ns 无画面」那枚 pill**（`RcCapsuleAlerts` 里
    `!pausedPill` 才渲染）：一条说「他在挡着」、一条说「链路怕是不行」同时挂出来 = 互相
    打脸。旧版对端不认 `vpause` ⇒ 两枚都不出，回落成原来那条无画面提示，不误报。
11. 胶囊行由此多了**第二枚琥珀徽标** `.pillPause`（与乙-③ 的 `.pillHold` 同级、共用同一条
   CSS 声明——「本机此刻收回了一样东西，点此交回去」），刻意**不**并进 `hasNotes`
    橙点：暂停不是「待处理」，没有需要对方回答的东西。
12. 恢复后**首帧不等节拍**（`next_tick` 在暂停圈里没被推进），最坏 300ms 出画面；
    设计稿没写这条口径，实机点验时按「点下恢复立刻续上」看。
13. `RcControlDrawer.tsx` 现在 **294 行**，距 300 红线只剩一次改动（本轮只加了两行
    透传）。`ctrlNotes` 那一块最该拆，本轮**刻意未拆**（越范围），下次动这个文件先拆。
