# PastePanda 沉浸式皮肤升级方案 v2

> **代号**：Immersive Panda
> **基线**：PastePanda v5.4.5（commit `c6d80f5`，2026-07-31）
> **目标**：把现有"换色级皮肤"升级为"沉浸式体验皮肤"
> **承诺**：Apache 2.0 永久免费开源；不引入 Pro/付费；不动剪贴板核心
> **版本**：v2（在 v1 草案基础上回应"用户实际觉得差在哪" + 重新核对现有皮肤系统）

---

## 0. 一句话定位

**"不是换色，是沉浸。"**

把 PastePanda 从"7 套配色 + 玻璃 + 静态粒子场景"，升级成"启动 → 使用 → 切换 → 退场"全链路的沉浸体验。视觉/动效/声效/交互/材质 **5 个维度同步联动**，而不是换一层皮就完事。

## 1. 用户原话与真相

**用户原话**："我们软件现在的皮肤做的很差，看一下复制粘贴最新版本的皮肤，基本上只有颜色，我想要全部沉浸式体验的那种皮肤。"

**用户感知 vs 实际现状**（基于源码级审计）：

| 用户感知 | 实际真相（v5.4.5 源码） | 差在哪 |
|---|---|---|
| "只有颜色" | 已有 7 套主题 + 完整玻璃拟态变量 + SkinScene 粒子层 | 玻璃变量定义全了，**实际应用到 UI 的覆盖只有 30-40%**；大量卡片仍是 `--card-bg` 实色 |
| "没有沉浸感" | 已有 6 个 keyframes + 主题切换过渡 | **没有**：启动动画、视差、滚动弹性、hover wave、tab 切换、跨窗口一致 |
| "没声音" | 0 个音频文件 | S7 提示音在 v6.3+ 探索阶段（已规划未实现） |
| "换皮就完事" | 主题切换是 0.3s linear 渐变 | 没有 morph（颜色变化的中间帧） |

**结论**：**不是从零做，是把已有玻璃系统用满 + 补 5 个缺失维度**。这正是用户说的"沉浸"。

### 2.2 用户说的"差"具体指什么

读完用户原话 + 实际代码，**真实问题清单**（按优先级）：

1. **玻璃拟态定义全但没用满** —— `--glass-card-bg` 只用在主卡片，很多二级卡片仍是实色
2. **场景层是"飘"但不是"沉浸"** —— 樱花/星是平移，没有 z-depth 视差
3. **主题切换是 fade 不是 morph** —— 颜色直接渐变，没有中间插值动画
4. **没有启动/退场动画** —— 应用打开就是直接显示
5. **没有跨窗口一致体验** —— 主窗口、Popup、QuickPaste、SettingsDialog 各自一套背景逻辑
6. **没有声音** —— 复制/粘贴/收藏/失败都是静默
7. **没有鼠标交互** —— hover 只是变色，没有 wave
8. **没有动态主题** —— 主题固定，不会跟系统时间/壁纸/活动变化

## 3. 沉浸式 8 大维度（重点规划）

按"用户能立刻感受到"的顺序，**8 个维度同步做**：

### D1. **玻璃拟态用满**（先做，影响最大）

**现状**：--glass-* 变量齐全，但实际使用覆盖率 30-40%。很多组件仍是实色背景。

**目标**：把所有"卡片/面板/对话框/侧边栏/工具栏/弹窗"统一用玻璃变量，包括：

| 位置 | 现状 | 目标 |
|---|---|---|
| 主历史卡片 | 实色 `--card-bg` | `--glass-card-bg` + `--glass-card-blur` |
| 设置面板 | 实色 `--dialog-bg` | `--glass-popover-bg` |
| 弹窗 / 浮层 | 实色 | `--glass-dialog-bg` + 22px blur |
| 顶栏 | 渐变 `--header-bg-*` | 透明 + 玻璃 + 滚动时增加 blur |
| 侧边栏 | 实色 `--sidebar-bg` | 玻璃透明（30%） |
| Toast | 实色 | 玻璃 popover |
| 编辑器浮层 | 实色 | 玻璃 dialog |
| QuickPaste 面板 | 实色 | 玻璃 card |

**关键决策**：
- ✅ **完全复用** 现有 `--glass-*` 变量，不引入新设计层
- ⚠️ 对比度必须 ≥ WCAG AA（4.5:1），不达标处继续用对比度变量（`text-primary` / `accent-strong`）
- ❌ 不在 popup 弹窗用强玻璃（必须保持文字可读，用 `--glass-popover-bg` 0.85 而非 0.66）

**工作量**：**5-7 天**（逐组件迁移 + WCAG 校验）
**风险**：低；纯样式迁移，不动业务逻辑

---

### D2. **场景层 z-depth 视差**（让"飘"变成"沉浸"）

**现状**：`SkinScene.tsx` 已有粒子，但都是 2D 平移。鼠标移动时背景不动 → 静态感强

**目标**：根据鼠标位置做视差分层：
- **背景层**（樱花/星/气泡）：跟随鼠标轻微反向偏移（max 8px）
- **场景层**（SkinScene 现有）：跟随鼠标中度偏移（max 16px）
- **前景层**（卡片）：跟随鼠标正向偏移（max 4px）
- 形成 3 层 parallax

**关键决策**：
- ✅ 用 `mousemove` 事件 + `requestAnimationFrame` 节流
- ✅ 用 CSS `transform: translate3d` 走 GPU
- ⚠️ **低性能设备自动关闭**（`prefers-reduced-motion: reduce` 已检测，新增 `navigator.hardwareConcurrency < 4` 自动降级）
- ❌ 不做陀螺仪/加速度传感器（剪贴板不需要）

**工作量**：**3-5 天**
**风险**：低；纯前端，已成熟方案

---

### D3. **主题切换 morph 动画**（告别 fade，迎来 flow）

**现状**：主题切换是 `transition: 0.3s` 线性过渡 → 颜色直接跳

**目标**：类似 iOS 控制中心切换的"流体"动画：
- 颜色变化走 **色彩空间插值**（HSL 而非 RGB）
- 装饰元素（边框/阴影/玻璃透明度）按"层次"分组同步切换
- 关键元素（卡片背景、强调色）走 0.4-0.6s 弹性曲线
- 次要元素（文字）走 0.2s 快速
- 切换时主卡片"按下去再回弹"（spring scale 0.96 → 1.02 → 1）

**关键决策**：
- ✅ 使用 Framer Motion `layout` / `animate`（项目已有）
- ✅ 复用 `applyTheme` 现有切换逻辑
- ⚠️ 切换中途取消要正确收尾（避免颜色卡在中间帧）
- ❌ 不做主题切换声效（太花）

**工作量**：**5-7 天**
**风险**：中；色彩插值在边缘色（接近黑色）容易出现中间灰，需测试

---

### D4. **启动/退场动画**（让"打开"也有戏）

**现状**：应用启动直接显示主界面，没有 splash 也没有退场

**目标**：两层启动：

**第一层：Splash 窗口（200-400ms）**
- Tauri 启动时显示极简 logo + 进度环（PNG/WebP，不需要 Lottie）
- 只显示项目 logo + 单色背景（与所选主题的 `--app-bg` 一致）
- 加载完成自动 fade out

**第二层：主界面渐入**
- 顶栏从顶往下 fade + slide 12px（200ms）
- 侧边栏从左 slide 16px（300ms，延迟 50ms）
- 卡片列表逐条 stagger fade（每条 30ms 延迟，最多 800ms 全部完成）

**退场**：
- 关闭窗口时整体 fade out（180ms）+ scale 0.98
- 不阻塞用户实际操作（直接接受新输入，不等动画）

**关键决策**：
- ✅ Splash 不显示任何 UI 控件（仅 logo + 进度）
- ⚠️ **启动动画不能拖慢感知性能** —— 主界面渐入 ≤ 800ms，否则用户感觉"卡"
- ⚠️ Splash 只在**冷启动**显示（用户主动重启才看），热激活跳过
- ❌ 不做"开机动画"（剪贴板不需要开机 lottie）

**工作量**：**5-8 天**
**风险**：中；Tauri 多窗口启动顺序需要小心，避免 splash 闪现主界面

---

### D5. **沉浸声效**（S7 提前 + 重新设计）

**现状**：完全静音

**目标**：分层声效（**v6.3+ 探索**的 S7 提前做 + 重新设计）：

| 触发 | 声音 | 时长 | 音量 |
|---|---|---:|---|
| 复制 | 极轻"咔哒"（高频） | 60ms | 15% |
| 粘贴 | 软"嗡"（中频） | 80ms | 20% |
| 收藏 | 上升"叮"（高→超高） | 200ms | 25% |
| 删除 | 下降"噗"（中→低） | 120ms | 18% |
| 主题切换 | 短"沙"（白噪音滤波） | 300ms | 12% |
| AI 完成 | 提示音（双段） | 180ms | 20% |
| 错误 | 低频"嘟" | 240ms | 25% |

**关键决策**：
- ✅ **默认关闭**，用户主动开启（设置里"沉浸音效"开关）
- ✅ 音量上限 30%（绝不刺耳）
- ⚠️ 提供"系统音量" / "应用音量"双层控制
- ⚠️ 所有音频 ≤ 100KB，CC0 / 自制音效
- ❌ 不做"个性化音色"
- ❌ 不做"语音反馈"

**工作量**：**3-5 天**（音效文件 + 触发点）
**风险**：低；可完全关闭

---

### D6. **鼠标交互沉浸**（hover wave + 点击涟漪）

**现状**：hover 只是变色（`--hover`）

**目标**：所有可点击元素添加：
- **hover wave**：从鼠标进入点扩散的半透明波纹（圆环 12px → 0px，200ms）
- **点击涟漪**：按下时圆环涟漪扩散（200ms）
- **悬停浮起**：卡片 hover 时 translateY(-2px) + shadow 加深（150ms ease-out）

**关键决策**：
- ✅ 用纯 CSS `::before` + `transition`，不引入 Framer Motion（性能）
- ✅ 主卡片/按钮/图标按钮都启用
- ⚠️ **低性能设备自动降级**（D2 同条件检测）
- ❌ 不做"光标跟随特效"（剪贴板不需要炫）

**工作量**：**3-4 天**
**风险**：低；纯样式

---

### D7. **动态主题感知**（让皮肤"活"起来）

**现状**：主题固定

**目标**：3 档动态感知（用户可选开关）：

**D7-1. 时间感知**：根据系统时间自动切换深浅
- 6:00-18:00 浅色（ocean/forest/blossom）
- 18:00-22:00 过渡色（ocean-dark / midnight）
- 22:00-6:00 深色（midnight / terminal / sunset）

**D7-2. 系统壁纸感知**（仅 Windows + macOS）
- 检测系统当前壁纸 → 主色提取 → 自动调色
- 复用 S1 的图片配色逻辑
- 用户关闭后回到手动主题

**D7-3. 活动感知**（剪贴板内）
- 检测复制内容如果是"图片/代码/聊天" → 自动切到对应主题（图片→forest，代码→terminal）
- 仅作为"建议"，用户可关闭

**关键决策**：
- ✅ D7-1 时间感知**默认开启**（对所有人有用）
- ⚠️ D7-2 系统壁纸感知**默认关闭**（性能 + 隐私）
- ⚠️ D7-3 活动感知**默认关闭**（避免反复跳变）
- ❌ 不做"位置感知"（剪贴板不需要地理位置）
- ❌ 不做"音乐感知"（剪贴板不需要听歌）

**工作量**：**5-7 天**（D7-1 1 天 / D7-2 3-4 天 / D7-3 2 天）
**风险**：中；D7-2 需要 macOS / Windows API 调用，注意权限

---

### D8. **跨窗口一致性**（所有窗口同套体验）

**现状**：主窗口、Popup、QuickPaste、SettingsDialog 各自一套背景逻辑

**目标**：所有窗口共用 `SkinScene` + 玻璃变量：
- 主窗口：完整背景 + 完整场景粒子
- Popup（Alt+V 唤起）：**只显示玻璃卡片 + 简化的背景渐变**，**不显示粒子**（避免性能 + 视觉混乱）
- QuickPaste（Alt+V 网格）：**只显示玻璃卡片 + 顶部渐变**
- SettingsDialog：玻璃 dialog（0.66 + 22px blur）
- 编辑器全屏：保留当前样式，不强制套主题

**关键决策**：
- ✅ Popup / QuickPaste 用简化背景（粒子数量减半或隐藏）
- ⚠️ 跨窗口主题切换要同步（设置里改主窗口主题，Popup 立即同步）
- ❌ 不做"主窗口和 Popup 用不同主题"（用户会很乱）

**工作量**：**2-3 天**
**风险**：低

## 5. 必砍清单（明确不做）

| 候选 | 不做理由 |
|---|---|
| Lottie 大型启动动画 | 启动动画 ≤ 800ms 即可，剪贴板不需要 30 秒 logo 秀 |
| 自定义字体全套（10+ 字体） | 跟随系统字体即可；用户不喜欢"非系统字体"的违和感 |
| 视频背景 / WebGL 着色器 | 性能 + 不必要；现有 CSS 渐变已足够 |
| 鼠标光标自定义 | 干扰操作系统一致性；违反 Windows 11 设计语言 |
| 3D 透视 / 倾斜鼠标跟随 | 视觉疲劳 + 用户会晕 |
| 桌面宠物（"伴侣"包装） | 之前已砍；不复活 |
| AI 自动生成皮肤描述 | v6.1 已定 S2 硬编码 24 套预设够用 90% |
| 主题社区市场 / 商店 | 避免审核 / 法律 / 服务器成本 |
| "Glassmorphism Pro" 付费版 | 破坏 Apache 2.0 永久免费承诺 |
| 个性化提示音 / 音色混音 | 花活 |
| 主题定时任务（X 时切到 Y） | 太细；D7-1 时间感知已经覆盖 |
| 跨设备同步主题 | 用户多设备用不同主题是合理诉求，不应强制 |

### 6.2 Tier 10（X1-X11）的关系

本方案**不重复** Tier 10。X1-X11 是功能串联，本方案是体验升级。

| 维度 | 提升哪些已有功能 |
|---|---|

## 附录 B：核心设计原则（铁律）

1. **不复造轮子**：现有 --glass-* 变量、SkinScene 粒子、6 个 keyframes 必须复用，**禁止重写**
2. **默认不打扰**：所有沉浸功能（D5/D7-2/D7-3）必须默认关闭，**不能自动激活**
3. **性能优先**：D2/D6 必须检测 `hardwareConcurrency` 和 `prefers-reduced-motion`，低端机器降级
4. **对比度硬指标**：玻璃迁移必须保证 WCAG AA（4.5:1），不达标处用对比度变量（已有）
5. **跨窗口一致**：D8 是基础约束，**Popup 简化场景但保持玻璃**
6. **开源不动**：Apache 2.0 永久免费；任何沉浸功能都不能进 Pro 付费墙
