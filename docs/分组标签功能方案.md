# 分组+标签功能方案

## 现状分析

项目已有功能：
- 时间轴（Timeline）：左侧按时间分组导航（今天/昨天/本周/更早）
- 搜索筛选：关键词搜索 + 类型Tab + 时间筛选 + 来源筛选
- 内容提取：自动提取 URL/邮箱/电话/IP/代码块
- 片段库：手动收藏的文本模板（API/SQL/配置/模板/命令）
- 右键菜单：复制/粘贴/置顶/编辑/删除

**当前数据模型**：HistoryItem 没有分组/标签字段，只有 `type`、`source`、`pinned`、`workspace`。

---

## 核心原则

1. **不增加使用负担** — 默认不显示，不需要的用户完全感知不到
2. **自动优先** — 优先利用现有 `source` 字段做自动分组，再考虑手动
3. **轻量交互** — 标签操作不弹窗，不离开主界面
4. **不影响性能** — 数据字段向后兼容，筛选逻辑增量叠加

---

## 方案对比

### 方案 A：自动来源分组（推荐 ⭐）

**思路**：利用已有的 `source` 字段（VS Code、Chrome、企业微信等），在侧边栏自动生成分组列表。

```
侧边栏（默认折叠）
├── 全部 (526)
├── VS Code (180)
├── Chrome (120)
├── 企业微信 (80)
├── Terminal (45)
├── 截图工具 (95)
└── 其他 (6)
```

**优点**：
- 零维护成本，全自动
- 利用现有数据字段，后端无需改动
- 分组数由实际使用产生，不会空分组

**缺点**：
- 不如手动分组灵活（不能把不同来源的记录归到一起）
- 来源名称依赖操作系统返回，可能不准确

**实现量**：前端 ~200 行 + 后端 0 行（纯前端聚合）

---

### 方案 B：轻量标签系统

**思路**：只加标签（Tag），不加分组。在卡片上快速打标签，通过标签筛选。

```
标签交互方式：
1. 卡片上显示已有标签徽标（1行，最多显示3个 + "+N"）
2. 点击徽标 → 按该标签筛选
3. 右键 → "添加标签" → 内联输入框（非弹窗）→ 输入 + 回车
4. TopBar 筛选栏 → 已选标签 chip（带 × 删除）
```

**优点**：
- 一条记录可以有多个标签（比分组灵活）
- 交互轻量（无弹窗，内联操作）
- 标签颜色自动分配

**缺点**：
- 需要手动维护
- 需要后端存储标签数据

**实现量**：前端 ~300 行 + 后端 ~100 行（数据迁移 + API）

---

### 方案 C：混合方案（分组+标签，默认折叠）

**思路**：A + B 的结合，但分组改为**自动来源 + 手动收藏**两种，标签保持轻量。

```
侧边栏（默认折叠）
├── 内置分组
│   ├── 全部 (526)
│   ├── 收藏 (32)     ← 已有 pinned
│   └── 未标签 (xxx)   ← 自动计算
├── 来源分组（自动）
│   ├── VS Code (180)
│   ├── Chrome (120)
│   └── ...
└── 标签筛选区
    ├── #JavaScript (45)
    ├── #API (28)
    └── ...
```

**优点**：功能最全；**缺点**：实现量最大、UI 复杂度最高、可能过度设计

**实现量**：前端 ~500 行 + 后端 ~150 行

---

## 推荐方案：A → B 分阶段

### 第一阶段：自动来源分组（1-2 天）

**目标**：侧边栏默认折叠，展开后按来源应用自动分组。

**具体改动**：

| 层级 | 改动 |
|------|------|
| **数据** | 不改动 HistoryItem，纯前端从 `source` 字段聚合 |
| **Store** | 新增 `sidebarCollapsed: true`、`sourceGroups: {source: string, count: number}[]`、`activeSourceFilter: string \| null` |
| **UI** | 1. TopBar 标题旁新增 ☰ 按钮（切换侧边栏）2. 侧边栏组件（200px，默认隐藏）3. 侧边栏自动按 source 分组 + 计数 |
| **筛选** | 点击来源分组 → 等同于设置 `sourceFilter`，与现有筛选逻辑无缝对接 |
| **持久化** | `sidebarCollapsed` 存 localStorage |

**用户路径**：
1. 默认看不到侧边栏 → 无感知
2. 点击 ☰ → 侧边栏滑出 → 看到来源分组
3. 点击"VS Code"→ 列表只显示 VS Code 的剪贴记录
4. 再次点击 ☰ → 侧边栏收起

---

### 第二阶段：轻量标签（1-2 天，视反馈决定做不做）

**触发条件**：用户对第一阶段有正面反馈，且提出标签需求。

| 层级 | 改动 |
|------|------|
| **数据** | HistoryItem 新增 `tags: string[]`，后端 SQLite 新增 `tags` 列（TEXT，JSON 数组） |
| **API** | 新增 `update_tags(id, tags)` 接口 |
| **Store** | 新增 `tagFilter: string[]`、`allTags: {name: string, count: number}[]` |
| **UI** | 1. 卡片上显示标签徽标（已有设计稿）2. 右键 → "添加标签" → 内联输入 3. 侧边栏底部显示标签列表 |
| **筛选** | 点击标签 → 多标签 AND 筛选 |

---

## 第一阶段详细设计（自动来源分组）

### 数据流

```
HistoryItem.source → 前端聚合 → sourceGroups[]
                                  ↓
                           侧边栏渲染 → 点击 → sourceFilter
                                                  ↓
                                         getFilteredItems() 筛选
```

### 组件结构

```
Sidebar/
├── Sidebar.tsx           # 侧边栏容器（动画展开/收起）
├── Sidebar.module.css
└── SidebarItem.tsx       # 分组项（图标 + 名称 + 计数）

App.tsx 改动：
├── TopBar（☰ 按钮）
├── Sidebar + CardList（flex 布局）
```

### 侧边栏内容

| 分组 | 图标 | 数据来源 |
|------|------|---------|
| 全部 | 📋 | `history.length` |
| 收藏 | ⭐ | `pinned.count` |
| VS Code | 💻 | source 聚合 |
| Chrome | 🌐 | source 聚合 |
| 企业微信 | 💬 | source 聚合 |
| Terminal | ⚡ | source 聚合 |
| ... | ... | 动态生成 |

### 与现有功能的关系

- **不影响时间轴**：时间轴在 CardList 内部左侧，侧边栏在整个窗口左侧
- **不影响搜索**：搜索和来源筛选可以同时生效（AND 关系）
- **不影响筛选栏**：侧边栏点击来源 = 自动设置来源筛选下拉的值
- **不影响快捷键**：不新增快捷键

---

## 不做的事情（避免过度设计）

1. ❌ 手动创建分组（增加维护负担，来源分组已经覆盖主要场景）
2. ❌ 分组嵌套（太复杂，实际不需要）
3. ❌ 拖拽卡片到分组（交互重，使用频率低）
4. ❌ 标签颜色自定义（用自动分配的颜色）
5. ❌ 分组排序拖拽（按计数自动排序即可）

---

## 总结

| | 方案 A | 方案 B | 方案 C |
|---|---|---|---|
| 用户负担 | 零 | 中等 | 中等 |
| 实现量 | 小 | 中 | 大 |
| 实用性 | 高 | 中高 | 高但过度 |
| 推荐 | ⭐ 先做 | 视反馈 | 不推荐 |

**建议**：先做方案 A（自动来源分组），上线后观察使用数据，再决定是否做标签。
