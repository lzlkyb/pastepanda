# 晾衣绳桌面显示与拖拽接力修复

用户反馈：鼠标靠近才显示绳子，照片拖离一点即自动结束并回到绳子。版本保持 7.2.11，分支 `codex/clothesline-interactions`。

## 根因与改动

1. 本机依赖 Tao 0.35.3 的 `IGNORE_CURSOR_EVENT` 会同时设置 `WS_EX_TRANSPARENT | WS_EX_LAYERED`。此前仅在鼠标靠近后移除该标志，没有初始化分层透明度。微软说明分层窗口需要调用 SetLayeredWindowAttributes 或 UpdateLayeredWindow 才可显示：[Window Features / Layered Windows](https://learn.microsoft.com/en-us/windows/win32/winmsg/window-features#layered-windows)。项目原生贴图已有同类初始化，绳层遗漏了这一步。
2. 所有绳层穿透出口统一进入 `set_pointer_passthrough`；在 UI 线程依次设置样式、初始化 alpha=255，避免跨线程排队导致初始化先于样式变化。alpha=255 不使用颜色键；CSS 透明背景保持原样。失败向主窗口报告。
3. 前端 `blur` 原先无条件取消捕获，导致原生准备引起焦点变化时取消取下。现在失焦只停止动画；真实窗口隐藏、页面隐藏、pointercancel、主动拖回、Esc 和鼠标取消入口仍可取消操作。
4. 原生命中轮询增加“原区域内开始且仍按住左键”的保护，防止前端 dragging IPC 尚未到达时，指针离开原区域就被切成穿透。原生 OLE 接力、截图和暂停门控仍优先让出鼠标。

## 红绿验证

- `.cache/clothesline-pointer-visibility-red.log`：失焦接力用例与分层初始化机制守卫改前均失败。
- `.cache/clothesline-held-press-red.log`：原生按住捕获保护用例改前失败。
- `.cache/clothesline-pointer-visibility-green.log`：修复后 10 文件、70 条前端回归通过，包含原有拖回、Esc、提前松手、可见性和桌面边界回归。
- `.cache/clothesline-held-press-green.log`：11 条原生晾衣绳用例通过，包含按住保护及 OLE/暂停让出鼠标。
- TypeScript、修改文件 ESLint 通过；UI lint 阻断 0，保留 4 条既有间距建议。前端未修改布局、版本号或发布配置。
- Tauri dev 已自动编译载入，独立开发实例继续使用 localhost:1424；无需手动重启。

## 验证边界

分层初始化使用源码机制守卫，拖拽失焦使用延迟注入的回归用例，按住命中使用原生纯逻辑用例。本环境没有可用的 Windows 原生 UI 自动化，因此未取得修复后真实桌面显示、鼠标跨窗口接力的实机录像，不能把这些用例当成微信实际接收验证。
