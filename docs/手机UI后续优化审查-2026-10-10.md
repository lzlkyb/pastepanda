# 手机 UI 后续优化审查

日期：2026-10-10。

## 审查范围与限制

- 基线：当前工作目录的 `master` 手机前端；另对照 `codex/mobile-article-ui` 的文章剪藏改动。
- PR #12 尚未合并；Rust Tests、Frontend Tests、Cloudflare Pages 均已通过。
- 本次是源码与布局规则审查，没有读取当前手机截图，没有实测触摸帧率、系统字体缩放或各机型表现。以下区分已确认的结构问题和需要真机验收的体验风险。
- 本次只记录发现与建议，不修改产品代码，不增加版本号，不提交审查文档。

## 优先处理

### 1. 阅读、编辑、文章预览仍占用主导航空间

证据：`src-mobile/App.tsx` 的主导航仅随整个远程会话/沙盒隐藏；知识库内部进入阅读、编辑或文章预览，没有向应用壳声明专注模式。`KnowledgeReader.module.css` 还设有独立的常用/目录底栏。

结果：手机竖屏阅读同时保留主导航和阅读底栏；宽屏主导航改成侧栏，仍占据内容宽度。键盘出现后主导航隐藏，收起键盘又恢复，编辑区域高度也会改变。

建议：列表页保留主导航；全文阅读、编辑、文章预览使用完整任务页，由明确返回入口恢复列表、筛选和滚动位置。阅读工具合并为一条紧凑工具栏。此处需要确认导航设计后实施。

验收：返回顺序稳定；任务页可恢复列表位置；未保存内容仍保留；横竖屏转换不丢输入或阅读位置。

### 2. 知识库首页的状态卡可连续叠加

证据：`KnowledgeView.tsx` 分别渲染新建草稿、修改草稿、分享处理、分享错误、收集提示、待收集入口。同步入口在列表之前的独立区域；PR #12 没有统一这些状态卡。

结果：多种状态并存时，用户先看到一串状态，再看到搜索和笔记。源代码确认允许叠加，具体占屏比例仍需截图测量。

建议：把可继续处理的草稿/收集内容集中为一个紧凑的“待处理 N 项”入口；普通成功反馈短暂显示，失败保留明确恢复动作。不能把重要失败只藏在数量角标里。

验收：同时有新建草稿、修改草稿和分享内容时，搜索与笔记仍容易找到；每份内容独立恢复、独立关闭，不丢草稿。

### 3. 横屏远控“收起”没有释放侧栏宽度

证据：`RcMobileSession.module.css` 横屏始终采用 `minmax(0, 1fr) var(--session-rail-width)`，侧栏宽度为 `max(68px, 4.25rem)`；`SessionToolbar.tsx` 收起只隐藏导航按钮，延时、工具入口、鼠标辅助和退出仍可留在侧栏。

结果：收起工具后画面不会扩展到该列。独立触控板模式还额外分配 144–184px 操作区域，这是该模式需要的操作空间，应与常规模式区别处理。

建议：常规模式提供展开、紧凑、专注三级可见状态；专注状态保持可找回的控制入口，并明确保留退出路径。重要错误仍可见；工具恢复不能与远程点击争用同一手势。

验收：工具收起真正释放空间；展开前后指针仍指向同一电脑坐标；延时与反馈不挡操作目标；切换方向、键盘开关不会误触电脑。

### 4. 文件页主操作和说明压在待处理任务之前

证据：`RcFilesView.tsx` 先渲染传输对象、发送/取回、说明、操作反馈和接收位置，再渲染请求与任务；`RcDevices.module.css` 竖屏传输按钮最小高度 92px。`RcFileTaskList.tsx` 直接逐条显示传入任务，没有在本组件中按处理中/已结束折叠分组。

结果：有待接收请求、失败或正在传输的文件时，用户仍需要经过操作区找到它们；记录多时信息密度增大。

建议：待接收请求、正在传输优先呈现；发送/取回使用紧凑操作区；接收目录收进更多；已结束记录可折叠。保留失败任务的恢复说明。

验收：新请求可发现；当前传输进度容易定位；多条已结束记录不淹没处理中任务；清记录与删文件语义仍清晰。

## 第二批处理

### 5. 远控画质面板的高频操作需要经过多段内容

证据：`SessionToolbarPanels.tsx` 中，适应屏幕、旋转、回到指针位于画质之前，四档画质逐条排列，并有锁档规则、当前状态和手势说明。画质反馈已经接入，不能再把“没有回执”当作未完成项。

建议：当前画质与档位选择靠前；短说明常驻，编码策略与详细手势折叠。普通手机可用两列选项，大字体时转单列。保留申请中、电脑接受、失败/未确认的真实状态。

验收：短横屏快速找到档位；选项与结果在同一面板可见；不把电脑接受误写成画面已生效。

### 6. 同步摘要表达授权状态，没有表达最近同步结果

证据：`KnowledgeSync.tsx` 首层摘要使用“已授权知识库同步”等文案；最后成功时间、失败、待处理资料在详情中。

建议：首层显示授权状态与最近一次结果的简短摘要，异常提供直接恢复入口；详情保留授权范围和暂停说明。未经后端支持，不能声称某篇笔记已到电脑。

验收：本机已保存、已授权、设备同步成功三者含义清楚；离线也能读写；普通用户不必展开技术报告才知道发生了什么。

### 7. 手势说明落后于四种操作方式

证据：`RcSettingsView.tsx` 的指南只解释触控板、直接点击，并引用“触控板／直接点击”入口；`pointerModes.ts` 已有触控板、直接点击、独立触控板、浮动鼠标。会话切换会写入同一偏好存储。

建议：按当前模式显示对应手势，四种方式均有可理解的示意；切换后明确说明是否记为下次默认。新手引导由模式变化触发，不必反复阅读整份指南。

验收：指南与真实入口一致；独立触控板、浮动鼠标下，本地移动视野与远程输入的区别清楚；不增加每次连接的强制教学。

### 8. 按钮体系与局部字号仍有重复定义

证据：`MobileUi.module.css` 的 primary/secondary 与 `RcDevices.module.css` 的 primaryBtn/ghostBtn 重复定义相似行为；阅读器再单独定义整套按钮。文件取回按钮、通用次按钮存在不同字重；`MobileNotice.module.css` 的技术详情入口、远控模式提示仍有固定 13px。

建议：提取已有按钮尺寸/字重/间距令牌，并按语义复用；保留远控工具与正文操作各自的合适密度。统一标题、说明、错误和选项的排版角色。不能机械地让所有按钮一样大。

验收：浅色/深色和字体放大下，文字可读、按钮不截断、点击区域足够；特殊布局差异由明确组件变体表达。

## 动效优化范围

已有：页面淡入、按钮按压、可拖动面板、等待图标、减少动态效果支持。

后续重点：建立列表→阅读→编辑的空间连续性；返回恢复状态；加载完成保留内容尺寸；面板拖动与内容滚动不争抢手势；普通反馈退场不造成明显跳动。仅在触发动作时播放，不添加常驻装饰动画。

这些属于体验方向，尚未验证为动画故障；应在 UI 布局收敛后用真机测试决定实现。

## 建议实施顺序与统一验收矩阵

1. 第一批：任务页主导航、知识库状态聚合、横屏远控侧栏、文件任务层级。
2. 第二批：画质面板、同步摘要、手势指南与偏好说明。
3. 第三批：组件样式收口、转场和细节反馈。

统一验证：320/360/390/430 CSS px 竖屏；568×320、667×375、844×390 横屏；系统大字体、深浅色、软键盘、网络离线、慢加载、失败重试、多任务并存。浏览器宽高模拟不等于 Android 字体与系统栏验收。

导航或明显布局变化需按项目规则先生成 HTML 设计稿确认；明确文案纠错及已确认方案的 bug 修复可直接处理。后续真实 bug 修复必须保存改前失败、改后通过的回归用例。
