## 0 · 一页结论

**待办应当做成「知识库的第二个视图」，不是第二个存储。**

| | 结论 |
|---|---|
| 数据落在哪 | **笔记正文的 `- [ ]` 行**（GFM 任务复选框），不新开表 |
| 为什么 | `notes` 已经接好了同步（`sync/engine.rs` 的增量只搬 notes + 墓碑）、版本快照、回收站、MCP、审计；新表要把这五套**各复制一份**，而它换来的只有「截止日期 + 提醒」 |
| 第一版交付线 | 内置项「待办」+ 聚合列表 + **点勾选写回正文** |
| 分期 | C1 视图与勾选 → C2 行内元数据（截止/优先级）→ C3 到期提醒（可选） |
| 成本 | C1：后端 1 读 1 写 + 前端 1 内置项 1 列表 1 交互改动 |
| 最大风险 | 不是技术，是**落点**（新待办写进哪篇笔记）与**语法边界**（`- [ ]` vs `- [todo]`）——见 §6 |

## 1 · 定位：待办在 PastePanda 里是什么

PastePanda 是「内容进得来、找得到」的 hub。待办天然属于**出口侧**：

- 剪贴板里一条内容常常就是「要做的事」（报错、工单号、地址、一句需求）→ 一键转待办；
- 反过来，待办正文本身也是文本 → 可复制、可进粘贴栈（复用本行能力）；
- 知识库正文里已经存在任务复选框 → 待办视图是**读它们**，不是另起一套。

**判断依据（不是感觉）：**

| 事实 | 证据 |
|---|---|
| AI 动作模板**已经在产出** `- [ ]` 行，但没有地方收拢 | `src/components/settings/ai/actionTemplates.ts:25-35`：「提取待办」模板输出格式写死 `- [ ] 事项（负责人，截止时间）` |
| 后端**已经会解析**正文里的方括号行内标记，且 `kind=todo` 可搜 | `src-tauri/src/markdown/annotate.rs`（`parse_observations` / `kinds_of`）；`src-tauri/src/mcp/tools/mod.rs:224`（`kb_search` 的 `kind` 参数） |
| 但前端**没有任何**待办视图 / 勾选交互 | 全仓 grep `待办` 只命中注释与 AI 模板文案；预览里的复选框**只读**（见 §2） |

⇒ 缺口不在「采集」也不在「解析」，在**呈现与回写**这一段。这是低成本高回报的位置。

## 3 · 三个方案

### A · 任务视图（纯 GFM 复选框 + 勾选写回）

- **存储**：零新表，正文 `- [ ]` 即数据，唯一真相。
- **后端**：新增 `list_tasks`（扫活笔记）+ `toggle_task`（改一行，走 `note_update`）。
- **前端**：内置项「待办」+ 新列表组件 + 预览复选框可点 + 卡片右键「加为待办」。
- **免费继承**：同步 / 备份 / 版本快照 / 回收站 / 审计 / MCP 读写。
- **能力上限**：无截止日期、无优先级、无提醒、无重复任务。

### B · 独立 `todos` 表 + 工具箱独立窗口

- **存储**：新表 + 迁移，**同步必须扩协议**（`Delta` 加 todos 与墓碑、HLC 游标、冲突策略）。
- **入口**：按工具形态开独立窗口（先例：`editor.html`、`rc.html`、`stackhud.html`）。
- **能力上限**：最高（due / 优先级 / 提醒 / 看板 / 跨端一致）。
- **代价**：把同步、快照、回收站、审计、MCP 五套机制各复制一份；MCP 还要新工具（挤 §2#10 的字节闸）。
- **结论**：**不做第一版**。只有在「待办成为核心场景」时才值得，且必须先解决同步协议。

### C · A + 行内元数据（推荐）

- C1 = A 的全部能力；
- C2 给任务加**行内元数据**（截止 / 优先级），解析仍收口在 `annotate.rs` 同一出口，与 AM-3「时效标记」同族（`规划与排期.md:218`，AM-3 未做）；
- 视图按「今天 / 本周 / 无期 / 已完成」分组，逾期标红；
- C3 到期提醒（新窗或通知插件）。

### 对比

| 维度 | A · 任务视图 | B · 独立待办表 | **C · 视图 + 元数据** |
|---|---|---|---|
| 新表 | 0 | 1（+迁移） | 0 |
| 同步改动 | **0** | 🔴 扩协议（引擎 + 墓碑 + 游标 + 冲突） | **0** |
| 回收站 / 快照 / 审计 / MCP | 免费继承 | 各复制一份 | 免费继承 |
| 截止日期 / 优先级 | ❌ | ✅ | ✅（C2，行内标记） |
| 到期提醒 | ❌ | ✅ | 🟡 C3 |
| 数据可移植 | ✅ 纯文本，导出即用 | ⚠ 需导出器 | ✅ 纯文本 |
| 认知成本 | 最低（GFM 标准语法） | 最低（表单） | 中（要学会写标记，但不写也能用） |
| 后端成本 | 1 读 1 写 | 新表 + 同步 + 命令层 | A + 解析扩展 |
| 前端成本 | 内置项 + 新列表 + 复选框交互 | 独立窗口 + 表单 + 分组 | A + 分组渲染 |
| 与既有路线一致性 | 高（AM-7 已经在解析正文） | 低（另起存储） | 高（AM-3 同族） |
| 主要风险 | 大库扫正文成本 | **静默数据丢失点**（同步侧），与既有红线冲突 | 语法约定需要文档与提示 |

**推荐 C，且按 C1 → C2 → C3 走**：C1 本身是完整可用的产品（能看、能勾、能同步），C2/C3 是加法，任何一步都能停在原地。

## 4 · C1 详细设计（第一版交付线）

### 4.1 解析层（Rust，收口一处）

- 新 `parse_tasks(content) -> Vec<Task>`，与 `parse_observations` **并列放在 `markdown/` 下、共用 `is_kind_label` 与 `fence_at`**：
  - 复用 `fence_at` 跳过代码块（`annotate.rs:80-98` 已有先例口径）——否则代码块里的 `- [ ]` 会造出幽灵待办；
  - `- [ ]` / `- [x]` / `- [X]` 三种写法；**不支持** `- [todo]`（§6 待拍板 #2）。
- 产物：`{ note_id, line, text, done }`；`line` 是**行号**，用于回写定位。

### 4.2 读：`list_tasks`

- 只扫**活笔记**（`deleted_at IS NULL`），排除回收站；
- 内存缓存按 `notes.updated_ms` 失效（大库成本见 §5）；
- 返回按「所属笔记 + 行号」稳定排序，未完成在前。

### 4.3 写：`toggle_task`

🔴 **必须走既有的 `note_update` 路径**，不许写裸 SQL：只有走它才会触发版本快照（`note_revisions`）、`updated_ms` 推进（同步游标依赖）、MCP 审计（`mcp_audit`）。

- 回写策略：按 `line` 取行、只替换方括号里的一个字符（` ` ↔ `x`），**其余字节不动**——避免整篇重写带来的格式漂移；
- 行号失配（笔记刚被改过）→ **明确报错并刷新列表**，不猜、不静默改别的行（规则 #15.3）。

### 4.4 前端

| 位置 | 改动 | 说明 |
|---|---|---|
| 侧栏 | `FolderTree` 加内置项「待办」（未完成计数） | 位次建议：全部 / 未分类 / 今日速记 / **待办** / 回收站 |
| 主区 | **新文件** `NoteTaskList.tsx`（≤300 行） | 两组：未完成 / 已完成；每条显示文本 + 所属笔记名（可点回笔记） |
| 预览 | `MarkdownRenderer` 复选框可点 | ⚠ 该组件是**共享**的（hover 弹窗 / 笔记预览 / 全屏预览都在用）→ 必须用 prop 显式开启，默认保持只读 |
| 剪贴板卡片 | 右键菜单「加为待办」 | 落点复用 `noteAppendDaily`（§6 待拍板 #1 的备选） |
| 编辑器冲突 | 勾选前检查编辑器脏状态 | ⚠ 分屏编辑时用户未保存的改动会被覆盖——必须先落盘或提示 |
| 空状态 | 复用 `NoteListEmpty` 的口径给一句引导 | 别只说「暂无待办」 |

**纯展示层无 AI**（遵循既有红线注释惯例）。

### 4.5 不做

- 提醒 / 重复任务 / 看板 / 甘特（甘特在文件编辑器是后置项，不混进来）；
- 独立待办表与独立同步协议；
- AI 自动抽取待办并落库（红线 1：绝不自动执行）；
- 第四个顶栏模式（§2#5）。

## 5 · 风险与对策

| 风险 | 说明 | 对策 |
|---|---|---|
| 大库扫正文 | `kind` 已是取回后扫正文（§2#9），全库聚合是 O(总字节) | ① 只扫活笔记；② 按 `updated_ms` 内存缓存；③ **开工前先在真实库量一次**，别凭感觉（规则：不写没测过的性能结论） |
| 行号漂移 | 外部（MCP / 同步）改动正文后，前端持有的行号会错位 | 回写时校验该行仍是同一任务文本，不符就报错刷新 |
| 编辑器覆盖 | 勾选写库 vs 编辑器未保存内容 | 见 §4.4 表格末两行 |
| 代码块误命中 | 代码里的 `- [ ]` | 复用 `fence_at` |
| 复选框语义混淆 | 笔记里的 `- [ ]` 忽然变成「待办」 | UI 文案要说明「这是笔记里的任务行」，并提供「不显示已完成」等视图级开关 |
| MCP 侧无结构 | 模型看到的是纯文本 `- [ ]` | 复用现有 `kind` 口径（`- [todo]` 行）；**不新增工具**（§2#10） |
