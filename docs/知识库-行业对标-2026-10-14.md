## 0. 一句话结论

**功能面我们已经是「完整的个人 PKM」，差的是两件结构性的事**：

1. **AI 只在被点名时在场**（手动摘要 / 手动标签 / 手动问答），而我们自己的红线「无自动 AI 行为」被理解成了「AI 默认关闭」。行业 2026 的共识是「AI 默认在场」——**这两者不冲突**，正确解法是「提议—批准」（§4.1）。
2. **语义检索是云端 embedding**（摘要出网换向量），与「本地优先 / 隐私」这条我们自己打了三年的招牌**互相拆台**；而 2026 年本地 embedding + 混合检索已是标准栈，硬件门槛（16 GB）早就不是问题（§4.2）。

另一件「有独特性但零验证」的事：**AI 记忆库**（`- [kind]` 观察行 + 归属 + 时效）机制齐备，但库里 AI 写的笔记是 **0 篇**（`docs/知识库作为AI记忆库-三项规划.md:14-24`）。而这条赛道今年正在被商品化（§4.3）。

**两条贯穿性判断（行业口径一致）**：
- AI 已从「加分项」变成**基线预期**；2026 的分水岭不再是「有没有 AI」，而是「AI 是否理解你的知识结构」（`trendix.tech/best-pkm-tools`）。
- **采集（capture）是瓶颈，不是检索**。多数知识在手机上到达（网页 / 截图 / 语音 / 转发），没有移动端采集路径的栈无论检索多好都会积灰（`promptquorum.com` 本地 AI PKB 2026 指南）。

## 4. 四条战略级差距（写透）

### 4.1 「AI 默认在场」与红线不冲突，我们理解偏了

**事实**：`src/lib/transforms/aiTransforms.ts` 的 `aiAvailable` 默认 `false`（红线「无自动 AI 行为」）；语义检索开关 `mem_enhance_enabled` 默认关；所有 AI 动作（摘要 / 标签 / 问答）都是**手动点名**才发生。

**行业的解法不是「偷偷自动改」，而是「提议—批准」**：
- Tana：AI 从会议里提取的内容**以 proposal 形式出现，人点了才落地**，且重跑会**更新已有条目、去重**，而不是每次都新建一页。
- Notion 3.8：连到外部工具的写操作，**没批准前什么都不会变**。

**这两件事完全兼容我们的红线**。红线要禁的是「未经用户知情的自动 AI 行为」，不是「AI 主动」。把现在的模型从「用户点名 → AI 干活」改成「AI 提议 → 用户批准 → 落地」，就同时拿到了行业的核心体验与我们的红线。

**这条差距的具体形态**（都落在已有能力上，不是新架构）：
- flomo 式的**每日回顾**：从旧笔记里挑几条值得重温的推给用户 → 我们有 `last_access_at`（且**故意不被 MCP 污染**，是干净的人类注意力信号，见 `知识库作为AI记忆库-三项规划.md:163-168`）+ `pinned` + 收藏，选材数据是现成的。
- 「今日蒸馏」目前**纯词面离线**（`DailyDistillSection.tsx`），P3 的「AI 成文」还没接。
- 会话结束时的「回顾一下有什么该记的」：**协议层做不到主动提醒**（`知识库作为AI记忆库-三项规划.md:432-448`），只能靠客户端 hook 或一个显式的收尾工具。

🔴 **风险提示**：这一改动会触碰红线 ①，必须先明确「提议」的存储与展示位置（不能静默写盘，红线 ②）。建议先做只读的「每日回顾」验证接受度，再考虑可写入的「提议」。

### 4.2 语义检索该本地化（架构自洽问题，不是功能缺失）

**事实**：`src-tauri/src/commands/semantic.rs:1` 头注释写着「摘要 → **云端 embedding** → 本地向量 → 余弦检索」；出网的是摘要，本地只存向量。

**行业在 2026 已把本地 embedding 做成标准栈**：
- Obsidian：Smart Connections 用 `transformers.js` 跑 BGE-micro-v2 / nomic-embed-text，嵌入存 `.smart-env`，零配置、零 API key、全离线。
- 通用栈：Ollama + `nomic-embed-text`(768d) / `bge-m3`（多语）/ `mxbai-embed-large`，向量进 `sqlite-vec`，**BM25 + 向量混合检索**。
- 硬件门槛：16 GB RAM 起步；mini 模型（384 维）CPU 可跑。

**为什么这条对我们特别重要**（三条理由叠加）：
1. **叙事自洽**：我们对外的核心卖点是「本地优先 / 隐私」。一个 384 维的本地小模型能解决的事，却把用户摘要发出本机，这在隐私叙事上是自相矛盾的——而且是**每一个新用户都会问到的那个问题**。
2. **规划本来就打算这么做**：`个人知识库与笔记-规划.md:1732` 写明 C 阶段的本地 embedding **选型从未实测**（fastembed 会带进第二个 ONNX 运行时，还是复用现有 MNN，都还没量）。也就是说这不是方向变更，是**把已规划的事提前并做完**。
3. **顺带解决 #4 与 #5**：本地 embedding 一旦到位，混合检索（BM25 + 向量 + 重排）与问答召回质量是**同一次改动**的收益，而不是三件独立的事。

🔴 **必须先做真探针**（照 `A-47` 的做法）：模型体积 / 首启加载时间 / 索引 1k 篇耗时 / 内存峰值 / 中文效果。**不要照体积表排期**（规划原话）。

### 4.3 AI 记忆层：我们占了一个独特位置，但一次都没被验证

**事实**（都来自真库测量，非估算）：
- 在库笔记 26 篇 → 手工 24 / 剪贴板 2 / **AI 0**；历史上 AI 写过的 5 篇**全部已删**。
- MCP 调用 109 条，其中**来自真实客户端只有 2 条**，且只调了 `kb_folders` + `kb_list` 就停了。
- `- [kind]` 观察行：解析 ✓ 筛选 ✓ 展示 ✓ 报错校验 ✓ —— **唯独没教怎么写**，`kind` 至今 0 命中。

**结论**：`知识库作为AI记忆库-三项规划.md:24` 那句话仍然成立 ——「**通道修好了，车没开过。**」

**行业今年的变化**：会话记忆独立成了一个赛道（Mem0 / Zep + Graphiti / OpenMemory / PLUR / Memory Store / agentmemory），且开始出现**我们还没做的语义**：
- **时间感知**：Zep/Graphiti 明确区分「现在为真」与「上季度为真」——我们规划里的「已被推翻」（`②丙`）是同一件事，仍在缓。
- **选择性遗忘**：保留策略与隐私删除成为标配——我们只有回收站与版本剪枝。
- **可读可版本化**：PLUR 的 engram 是可 `git diff` 的 YAML——**这一点我们更彻底**（观察行直接住在人类可读的 Markdown 笔记正文里）。

**我们的差异是真实的**：别家把记忆做成**独立存储**（人看不见、要专用 UI 看），我们把记忆做成**笔记里的一行**（人在自己的库里就能看见、能删、能改；红线③「学习日志可见可删除」天然满足）。这个位置在 2026 没人占。

**但它的价值完全取决于第 0 步**：接一个真实客户端跑一周，读审计表（四个判据在规划 §7.5 已预先定死）。在这之前，任何关于「记忆层该长什么样」的讨论都是空转。

**顺带一条**：我们的 MCP 写侧（16 个写工具 + 门控 + 范围白名单）在业内是少见的——多数产品的 MCP 只读写自家云工作区。这是 §3 里第 13 项给 5 档的原因，值得**主动讲**，而不是等用户发现。

### 4.4 中文入口（微信）——已被占位，但我们有半个地基

**事实**：`fetch_url_article` 已能抓公众号 `#js_content` 正文并把图片本地化（`docs/手机知识库-微信文章收藏方案-2026-10-09.md:5-13`）；手机端已能接收系统分享。用户当时选了方案 **B（手机文章剪藏）**，但**详细稿待确认，未动生产代码**。

**行业**：ima 把「微信公众号 / 聊天文件一键入库」做成了独家壁垒并围绕它建了知识库广场与变现；Cubox 的微信支持也明显好于 Readwise Reader。

**判断**：这不是「要不要做」的问题，是**已经在做但停在中途**。桌面抓取 + 手机分享两个半成品之间差一个闭环。按 `knowledgeCollection` 那条「采集是瓶颈」的行业共识，这条 ROI 高于任何检索优化。

## 5. 值得补 vs 不必补（ROI 建议）

| 优先级 | 动作 | 为什么现在 | 成本 | 前置 |
|---|---|---|---|---|
| **P0** | **接真客户端跑一周，读审计表** | 零代码；§4.3 与所有「AI 该怎么用」的问题都卡在它后面 | 零代码 | 只有用户能做 |
| **P0** | **本地 embedding 真探针**（体积/加载/索引耗时/内存/中文效果） | 决定 §4.2 是否能做；`A-47` 已定的做法 | 小（探针） | 无 |

## 7. 建议

1. **先做两件零/低成本的事**：接真客户端跑一周（§5 P0）+ 本地 embedding 真探针（§5 P0）。前者解锁「AI 记忆库」这个独特方向，后者解锁隐私自洽。
2. **「AI 默认在场」用「提议—批准」重构**，不要改红线。第一步只做**只读的每日回顾**——它不写库，因而不触碰红线 ① 与 ②，但能立刻测出用户对「AI 主动」的接受度。
3. **微信剪藏闭环收口**：把已有的桌面抓取 + 手机分享接起来，这是中文场景里性价比最高的一条。
4. **把 MCP 写侧当卖点讲**：23 个 `kb_*` 工具 + 门控 + 范围白名单，这是业内少见的能力，现在只体现在文档里。
5. **视图层重估但不要全量跟进**：要的是「一个轻量视图」，不是 Dataview 查询语言——避免重复旧稿里「被带偏」的错误。
