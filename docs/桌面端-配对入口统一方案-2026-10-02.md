# 桌面端配对入口统一方案（2026-10-02）

## 当前问题及源码依据

截图中的杂乱来自能力在多处重复呈现，而不只是间距。

- `RcDevicesPane` 常驻挂载 `RcNearbyPairPane`，让附近设备空态也占据主区。
- `RcA2SelfCard` 在侧栏挂 `RcA2PairExchange`，同时展示本机短码、对方码输入、出示/输入两个角色按钮、二维码入口与更多方式。
- `RcPairDialog` / `RcPairModeSelect` 又拥有附近设备、生成码与粘贴码向导；不同地方的流程主次不同。
- `RcPairLayer` 统一了挂载点，但长期配对、协助、无人值守仍由不同组件承载；工作台与设置页各有入口。
- 手机已具备扫描 `PP-XXXX-XXXX` 短码二维码的能力，桌面 `RcShortCodeQr` 可以生成相同凭证的可扫形态。不需为扫码另造一套配对协议。

## 三个可选方案

| 方案 | 布局 | 优点 | 取舍 |
|---|---|---|---|
| A 单一添加入口 | “我的设备”标题旁仅“添加”；进入后选择扫码、配对码、附近设备 | 首页最简洁，入口只有一个 | 常用手机扫码多一次点击 |
| B 高频直达（推荐） | “我的设备”旁“附近设备”；侧栏“这台电脑”下“手机扫码 / 输入配对码” | 高频动作一步进入，附近列表仅点击后出现；设备详情回到主区 | 首页有三个明确连接入口 |
| C 顶部连接工具栏 | 主区顶部横排扫码、配对码、附近设备、更多方式；侧栏仅设备与本机状态 | 所有方式易发现，侧栏轻 | 常驻多一行工具，详情主次更弱，窄窗口需处理换行 |

三个方案共享同一套弹窗、组件、文案和状态系统。交互预览：`design/桌面端-配对入口统一-三方案对比-2026-10-02.html`，默认显示 B，可切换 A/C、深浅主题及弹窗状态。

## 推荐 B 的具体流程

1. **手机扫码**：点击后打开“添加设备”的扫码页，拟在生成本机凭证后自动以出示方开始等待。只展示大二维码、同一凭证的 8 位数字、真实有效期、等待状态和复制/刷新。不要求用户选择协议角色；关闭时取消等待但不删除既有已配对设备。
2. **输入配对码**：点击后直接进入输入页。输入对方 8 位数字 → 开始配对 → 等对方确认 → 成功。次级“出示本机配对码”切换到出示页；两端角色由入口固定。粘贴只在明确点击后读取。
3. **附近设备**：点击打开同一个弹窗的附近页。展示可配对邻居，或加载、空、失败状态；失败不是没有设备，保留重新检查与配对码替代入口。按现有协议核对两端数字后确认。
4. **成功**：关闭配对弹窗、选中新设备，提示“已配对”；查看、控制、文件仍走现有权限，不承诺扫码后无确认控制。
5. **更多连接方式**：原协助、无人值守、完整凭证/设备号按语义组织在同一视觉壳中；它们不与短码或长期配对混用，不擅自改变连接后是否保留设备的既有规则。

## 所有入口的收敛范围

| 当前入口 | 调整后 |
|---|---|
| 工作台常驻附近卡 | 删除常驻列表，B 的“附近设备”按钮打开弹窗 |
| 侧栏换码区 | 收成扫码、输入码两个动作；首页不生成/出示凭证或放输入框 |
| 设置中的配对 | 打开同一个配对弹窗，不维护另一套首屏 |
| 设备为空的引导 | 指向同一个添加入口；不嵌入第二个配对面板 |
| 帮助中的连接 | 统一视觉、方向选择、返回和反馈；保留协助语义 |
| 无人值守与高级凭证 | 保留能力，按需进入对应页面，不挤占日常配对页面 |

“已允许本机接收远程请求”的开关继续常驻；设备管理、连接并控制/只看/传文件、最近会话保留。图标使用现有 Lucide 同一笔画，配常驻文字，避免只靠图标猜功能。设计稿设备详情为结构示意，实施时保留未涉及的真实详情组件与既有插画。

## 状态、取消和性能

- 分开显示凭证生成中、等待扫码/输入、找到对方、等待确认、完成、过期、失败；只有真实后端结果可显示成功。设计稿反馈全部为模拟。
- 所有成功/失败在弹窗当前页可见；关闭后结果由全局反馈或设备列表承接。保持配对状态在统一会话控制层，不依赖折叠内容挂载。
- 进行中的配对取消/关闭收口取消等待；不会撤销此前已经完成的配对。Esc 先回当前步骤或取消确认，再关闭弹窗。
- 关闭附近页停止前台列表刷新；后台必要的发现和入站配对确认监听按现有协议保留，入站待确认请求必须及时显示，不因附近页关闭而丢失。
- 二维码仅在出示页生成；数字倒计时遵循真实有效期，离屏停止无用刷新；不引入常驻装饰动画或重复玻璃层。
- 附近核对码与短码按各自协议展示，不能因外观相似把它们当作同一凭证。
- 设计示意二维码编码的是预览说明，不是可连接凭证；不读取剪贴板、调用配对服务或建立真实连接。

## 实施与验收

确认布局后，先收敛配对弹窗与状态控制，再替换工作台、设置、空态和帮助调用点。复用现有短码 API、二维码格式、配对状态和权限逻辑；组件按页拆分，遵守 300 行限制。

验收：首页不显示附近列表或大段配对表单；三个入口直达；扫码/输入码完成后设备只新增一次；失败、过期、取消可恢复；邻居请求仍能到达；设置与工作台是同一界面；窗口 900px/1400px、浅深主题、键盘焦点和减少动态效果均检查。正式后端协议保持原样；B 方案已于 2026-10-02 落地，详见下文。

## 设计稿验证

浏览器检查三种入口布局、扫码弹窗、附近设备空/失败状态、无效配对码、等待与完成、900px 窗口及深色主题均通过，页面异常为 0。检查的是设计示意，没有进行真实配对。截图位于 `design/desktop-pairing-2026-10-02/`。HTML 稿复用桌面主题变量；常规 UI 检查不覆盖该 HTML，不把它当作正式组件测试通过。


## B 方案实施结果

- 首页撤下常驻附近列表和短码表单；设备标题旁“附近设备”，本机卡“手机扫码 / 输入配对码”，次级“更多连接方式”。原有设备详情、插画、权限和会话操作保留。
- 统一添加设备弹窗按入口直达扫码、配对码、附近设备三个页签。扫码自动注册出示方等待，输入码在明确提交后使用输入方角色；仅明确点击粘贴才读取剪贴板。二维码编码 PP-XXXX-XXXX，与数字来自同一后端码。
- 重新等待复用仍有效的码，避免把已发送的码作废；到期自动获取新码。取消、切换、关闭使旧结果失效，上一轮取消完成后才允许注册下一轮。握手完成先刷新设备、选中新设备，再关闭并提示。
- 首页保留不可见的来访请求观察（空闲 5 秒），只有收到请求才弹出核对；添加设备弹窗接手后暂停首页观察，弹窗非附近页也是 5 秒来访观察，附近页/核对时 2 秒。窗口不可见沿用现有暂停策略，没有新增装饰常驻动画。关闭前台列表不等于关闭必要的配对请求监听。
- 帮助、无人值守、完整凭证复用同一尺寸、焦点和 Esc 外壳，业务授权语义保持独立。完整凭证只放在更多方式中。
- 900×680 窗口采用较小二维码和紧凑间距，等待反馈与取消按钮可见；深浅主题均复核。组件按页与 Hook 拆分，新增组件均低于 300 行。

验证：7 个相关测试文件、99 条用例通过；TypeScript、所改业务组件 ESLint、UI 规则检查通过。浏览器使用真实组件和仅在测试页面注入的模拟后端数据，检查首页、扫码、输入码、附近空/失败、更多方式、深色窄窗口，页面异常为 0；二维码解码为 PP-1234-5678，与测试显示码一致。浏览器截图以 implemented- 开头，数据为测试示例，不是用户的连接凭证。双设备真实网络握手还需真机验收。

桌面前端生产构建通过（vite build）。保留现有大分块与动态导入提示，未修改无关打包架构；本次未构建 exe、升级版本或提交 Git。
