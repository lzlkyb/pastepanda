## 2. Implementation Integrity 结论（先看这条）

**通过吗？——结构层通过，样式层不通过。**

结构层是本仓最好的部分之一：`RcWorkbench` 299 行（贴着 300 红线）、rc 目录 10 个测试文件（`RcA2Workbench.test.tsx` 749 行）、跨层判据一律收口成纯函数带守卫单测（`hidesWorkbenchTitleBar`、`resolveRcA2Surface`、`resolveRcA2Selection`）、`rcA2ThemeTokens.test.ts` 甚至把「A2 不许出现 hex / 渐变字面量 / `!important` / `[data-theme]`」和六套主题的令牌齐全性、`--accent-solid` on `--text-on-accent` ≥ 4.5:1 全部钉住了。文件头注释里记着「portal 而不是 absolute」「z-index 压不过 DOM 靠后的兄弟块」这类踩过的坑——这是被同一批 bug 反复教育出来的产物。

样式层则是**两代人的代码并置**：

| 文件 | 行数 | `lint:ui` block 级违规 | 谁在用 |
|---|---|---|---|
| `RemoteComputerA2.module.css` | 2,051 | 0（只有 4 处动效时长） | 设备优先工作台外壳（TitleBar / Sidebar / DeviceList / DeviceDetail / Settings） |
| `RemoteComputer.module.css` | 3,188 | **全部 281 处** | **会话态全部**：HUD、浮条、文件面板、被控横幅、无人值守弹层、配对向导 |

也就是说：**产品最值钱的那一屏（远程会话）恰好是唯一没有设计系统的那一屏**。A2 的干净不是巧合，是那条守卫单测逼出来的；会话侧没有对应的守卫，所以 2026-09-24「浮条收编」这类改动只保证了新加的类好看，没保证老类被清掉——下面的 P1-1 就是这个缺口的直接后果。

## 3. 问题清单（按严重度）

### P1

#### P1-1 · 会话浮条的「适应 / 1:1 / 填充」三键完全没有样式（实测确认）

- **位置**：`src/components/rc/RcSessionCapsule.tsx:203-216`；样式 `src/components/rc/RemoteComputer.module.css:1404`（`.capFit`）
- **类别**：Implementation Integrity / Theming
- **事实**：`className={fit === k ? styles.capBtnOn : undefined}` —— 只有**当前档**拿到 `capBtnOn`，另两颗的 `className` 是 `undefined`。而 `.capFit` 只声明了 `display:inline-flex; gap:4px`，全仓（含 `dist` 编译产物）**没有任何规则匹配 `.capFit` 里的裸 `button`**，也没有全局 `button` 重置（`globals.css` 只有 `*{margin:0;padding:0}`）。
- **实测**（Edge headless + CDP，加载 `dist/assets/useRc-ljC_VhZO.css` + `theme-*.css`）：

  | 元素 | class | 盒子 | border | radius | background | 字体 |
  |---|---|---|---|---|---|---|
  | 适应 | （无） | 31×21 | `2px outset rgb(0,0,0)` | `0px` | `rgb(240,240,240)` | `13.3333px Arial` |
  | 1:1（选中） | `capBtnOn` | 23×21 | `2px outset rgb(0,0,0)` | `0px` | `rgba(107,147,255,.28)` | `13.3333px Arial` |
  | 填充 | （无） | 31×21 | `2px outset rgb(0,0,0)` | `0px` | `rgb(240,240,240)` | `13.3333px Arial` |
  | 全屏（同类控件，正常） | `capBtn` | 28×24 | `0px none` | `8px` | `transparent` | `12px` |

  截图看得很直白：三颗浅灰带 2px 黑立体边框、Arial 13.33px、黑字的**原生按钮**，紧挨着一颗透明圆角的项目按钮，压在深色玻璃浮条上。连选中档也一样是原生外观，只是刷了一层 28% 蓝底。
- **影响**：这是会话态的常驻控件，用户每次远程都在看。观感上等于把「设计系统」这件事当场证伪；同时也说明 2026-09-24 那次浮条收编**没有看过未选中态**。
- **为什么没被发现**：`tsc` 看不见（`undefined` 是合法 className）；`lint:ui` 看不见（不是硬编码色、不是字号圆角越界）；`lint:css:unused` 看不见（`.capFit` 确实被引用了）；测试看不见（无视觉断言）。
- **建议**：三颗按钮统一用现有 `.capBtn`，选中项再叠 `capBtnOn`（`capBtnOn` 现在只有 background/color，本来就必须靠 `.capBtn` 提供尺寸与圆角）；顺手补一条守卫测试：`FITS` 里每个按钮的 className 必须含 `.capBtn`（对着渲染出的 class 断言，不是对着源码字符串）。
- **建议命令**：`$impeccable polish`

#### P1-2 · rc 的三个弹层按 Esc 无反应，在主窗口里还会连带关掉整个设置页

- **位置**：`src/components/settings/RcPairDialog.tsx`（Esc 数 0）、`RcUnoDialog.tsx`（0）、`RcAdhocDialog.tsx`（0）
- **类别**：Accessibility
- **事实**：项目里存在明确约定——`src/hooks/useDialogEscape.ts` 头注释写着「所有自己接 Esc 的弹窗都走这一份（规则 #11）」，15 个组件遵守（`ProfileDialog` / `LearningsDialog` / `DiffDialog` / `TransformHubDialog` …）。该 hook 用**捕获期 + stopPropagation**，目的正是抢在 `lib/keyboardActions.ts` 的全局 Esc 链前面。
  rc 这三个弹窗一个都没接。后果分两处：
  - **在 rc 独立窗口**：rc-main 不加载 `App.tsx` 的按键链 → 按 Esc **什么都不发生**（只能点遮罩或 ✕）。违反交互范式 §17 的「两级取消」。
  - **在主窗口**（`RcPairLayer` 同时被 `src/components/settings/sections/RcSection.tsx:304` 渲染在设置页里）：`keyboardActions.ts:215-240` 的 Esc 分支依次判断已知弹窗，rc 弹窗不在名单里，于是继续往下走到 `state.showSettings → close_dialog: settings` ⇒ **按下 Esc 关掉的是整个设置页**，正在进行的配对（已生成的配对码、正在核对的 6 位数字）随组件卸载一起丢。
- **影响**：这正是 `useDialogEscape` 头注释里记录的 2026-09-06 事故（「从设置页打开的弹窗 → 整个设置页跟着没了」）的同型复现——那次修法是加这个 hook，但 rc 的三个弹窗是后来新增的，没跟上。
- **建议**：三个弹窗各加一行 `useDialogEscape(onClose)`；补一条守卫单测把「rc 弹层 ↔ useDialogEscape」两侧对账（照 `src/__tests__/windowCloseCapability.test.ts` 的监听点↔权限写法）。
- **建议命令**：`$impeccable harden`

#### P1-3 · 4 处 `aria-label` 挂在没有 `role` 的普通容器上 → 名称被读屏丢弃

- **位置与类别**：Accessibility
  - `src/components/rc/RcWindowControls.tsx:132` — `<div className={styles.winControls} data-tauri-drag-region="false" aria-label="窗口控制">`
  - `src/components/rc/RcHud.tsx:246` — `<div className={styles.hudPanel} aria-label="连接详情">`
  - `src/components/rc/RcPageFiles.tsx:69` — `<div className={styles.fileTargets} aria-label="选择目标设备">`
  - `src/components/rc/RcA2Sidebar.tsx:166` — `<span className={styles.toolBadge} aria-label={`${transferBadge} 个传输进行中`}>`
- **事实**：`aria-label` 在 `role="generic"`/无 role 的元素上是不被允许的（ARIA 规范：generic 不可命名），浏览器/读屏直接忽略。实测探针确认这 4 个元素 `getAttribute("role") === null`。
- **影响**：自绘窗口三键所在的组无名（读屏用户听到 3 颗孤立按钮）；HUD 面板无名；「选择目标设备」这组按钮无名；**传输角标只剩一个裸数字「3」**——最终用户听到的是「3」，没有任何上下文，这条最贵。
- **建议**：① 给 `winControls` / `fileTargets` 加 `role="group"`，`hudPanel` 加 `role="region"`（或改用 `aria-labelledby` 指向面板抬头）；② 角标改成常驻 `role="status"` + 视觉隐藏文字（`.sr-only` 已有），或把 aria-label 移到承载它的按钮上。
- **建议命令**：`$impeccable harden`

#### P1-4 · 「连接详情」HUD 面板的 10px 文字对比度不达标（实测 2.51–3.3:1）

- **位置**：`src/components/rc/RemoteComputer.module.css:498`（`.hudRowLabel`）、`:510`（`.hudRowHint`）、`:483`（`.hudPanelHead`）
- **类别**：Accessibility（WCAG 1.4.3 普通文字 4.5:1）
- **事实**：面板底 `rgba(9,17,28,.86)`，文字 alpha 很低。实测（两种极端背景各算一次，数值为合成后对比度）：

  | 元素 | CSS | 字号 | 叠在黑底屏 | 叠在白底屏 |
  |---|---|---|---|---|
  | `.hudPanelHead` | `rgba(200,208,220,.62)` | 10px | 5.28 ✅ | 4.21 ❌ |
  | `.hudRowLabel` | `rgba(200,208,220,.45)` | 10px | 3.30 ❌ | 2.94 ❌ |
  | `.hudRowHint` | `rgba(200,208,220,.38)` | 10px | 2.69 ❌ | 2.51 ❌ |
  | `.hudRowVal` | `rgba(220,227,238,.92)` | 10px | 12.67 ✅ | 8.70 ✅ |

- **影响**：面板浮在**远端画面上**，底色不可控——用户看的正是「编码 / 丢包 / 分段 / 码率」这些排障数字，而承载它们的行标签和补充说明恰是读不清的那两个。10px + 2.5:1 在 4K 屏缩放下基本靠猜。
- **建议**：行标签提到 `.72`、行提示提到 `.68`。🔄 **2026-09-27 修正**：本条初稿写的是「行提示提到 ≈`.6`」，按叠加后的合成色实算**不达标**（白底仅 4.04:1）—— 白底场景的最小达标 α 是 `0.654`，取 `.68` 留裕量（白底 4.74）。抬头 `.62`（白底 4.21）与趋势抬头 `.50`（白底 3.28）同病，一并提到 `.72`。改完把面板底与这几处 α 一起纳入会话侧对比度断言（目前**没有**对比度守卫）。方案对比与实测表见 `design/远程电脑-P1修法-设计稿.html` §2。
- **建议命令**：`$impeccable polish`

### P2

#### P2-1 · `RcA2ConnectSplit` 的档位菜单：`role="menu"` 但不支持键盘

- **位置**：`src/components/rc/RcA2ConnectSplit.tsx:80-99`
- **类别**：Accessibility
- **事实**：容器 `role="menu"`、子项 `role="menuitem"`，但**没有** Esc 关闭、没有方向键在项间移动、打开时不把焦点移进菜单；触发键也没有 `aria-haspopup="menu"`；选中态是用文本 `●/○` 表达的（读屏念「实心圆 可控」）。
- **对照**：同一个页面里的浮条下拉 `RcDropdown.tsx:148-162` 是**做对了**的——Esc 收起自己 + 向 `rcPanelFocus` 登记 + `stopPropagation` 防穿透到会话兜底。两套浮层的键盘纪律不一致，说明这条纪律还没收口。
- **建议**：菜单加 Esc（走 `rcPanelFocus` 登记，避免与会话 Esc 兜底打架）、`aria-haspopup`、选中态改 `role="menuitemradio"` + `aria-checked`；打开时 `focus()` 首项。
- **建议命令**：`$impeccable harden`

#### P2-2 · 设备行的关键差异信息只存在于 `title`，键盘与触屏都拿不到

- **位置**：`src/components/rc/RcA2DeviceList.tsx:166`（`shortLabel` + `tip`）、`:154-163`（属性徽章）
- **类别**：Accessibility / UX
- **事实**：行上只留短状态词，**「将以哪档连接」「检查时间」「备注」「标签」全部拼进 `title`**（`tip` 变量，87-96 行）。默认档位预告是「发起前唯一能看到的档位信息」。
- **影响**：`title` 只对鼠标悬停生效——键盘用户（Tab 到该行）和触屏用户看不到；读屏也不保证念 `title`。等于把「连上去是可控还是只看」的预告变成了鼠标特权。
- **建议**：把档位与检查时间做成行内常驻 meta（项目 L2 的原则是「图标标签应始终可见」），备注/标签可继续走悬停。
- **建议命令**：`$impeccable clarify`

#### P2-3 · 全站 px 字号 + WebView 无缩放路径 ⇒ 用户无法放大文字

- **位置**：`src/styles/globals.css`（`body { font-size:13px }`）、两个 rc 样式表全部 px 值
- **类别**：Accessibility / Responsive（WCAG 1.4.4 需支持到 200% 而不丢内容）
- **事实**：没有任何 `rem`/`em`，字号、间距、行高全是 px；Tauri WebView 里也没有浏览器缩放菜单，Windows「使文本变大」不作用于 WebView 内容。
- **影响**：视力偏弱的用户在这扇窗口里**没有任何放大手段**。10px 的 HUD 行、11px 的 meta 会直接不可读（与 P1-4 叠加）。
- **建议**：至少给 rc 窗口提供 `Ctrl + = / Ctrl + -` 之类的缩放入口（Tauri 可对 webview 设 `zoom`），或把最关键的排版量改成 `rem` 并抬 `html` 根字号。
- **建议命令**：`$impeccable adapt`

#### P2-4 · 680px 断点在 960px 最小窗宽下永不触发；1403 行注释与被采纳的决策相反

- **位置**：`src/components/rc/RemoteComputer.module.css:1558`（`@media (max-width:680px)` 隐藏 `.capWho/.capKb/.capKbOff`）、`:1403`（注释「窄窗整组隐藏」）
- **类别**：Responsive / Implementation Integrity
- **事实**：会话浮条只存在于 rc 窗口，而该窗口 `min_inner_size(960, 640)`（`src-tauri/src/commands/rc.rs:1380`）⇒ 永远够不到 680px。同时 `.capFit` 的注释写着「窄窗整组隐藏，见下方媒体查询」，而下方 1556 行的注释写的恰好相反：「视图三键保留——宽度小」。**注释与被采纳的决策打架，且两块媒体查询里的那块是死代码。**
- **建议**：删掉死断点，把 1403 行注释改成真话。（640px 那块是活的：主窗 `minWidth 320`，设置页里的 `.steps/.pairPane` 会用到。）
- **建议命令**：`$impeccable distill` + `$impeccable adapt`

## 4. 系统性模式

1. **两代样式表并存，守卫只覆盖新一代。** A2 有 `rcA2ThemeTokens.test.ts` 三件套（禁 hex/禁渐变/禁 `!important`；六套主题令牌齐全；主按钮对比度 ≥4.5），会话侧一条都没有。凡是没有守卫的文件，债就全积在那里（281 处 block 违规 100% 落在 `RemoteComputer.module.css`）。
