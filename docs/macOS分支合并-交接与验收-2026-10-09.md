## 2. 四处冲突的解法口径

### 2.1 `sync/attach.rs` + `sync/attach_tests.rs` — 唯一的真坑

基点只有 `pub fn scan_local_refs()`。双方**各自独立新增**了同名私有 helper `local_refs`，签名不同（add/add 冲突）：

- 分支侧：`fn local_refs(content) -> Vec<(usize, usize, AssetRef)>`，两个调用点 `for (_, _, asset)`、`for (start, end, asset)`
- master 侧：`fn local_refs(content) -> Vec<(std::ops::Range<usize>, AssetRef)>`，并另有 `pub fn scan_refs()`、`app_relative_context()`（`dfde3c86` 知识库二期手机端后端），配套守卫测试在 `attach_tests.rs`

**采用 master 的签名为唯一版本**：`for (_, _, asset)` → `for (_, asset)`；`for (start, end, asset)` → `for (range, asset)` 后取 `range.start`/`range.end`。`attach_tests.rs` 双方新增用例取并集，断言按 master 签名整理。保留分支版会让 `scan_refs` 及其守卫测试编译失败或语义跑偏。

这是规则 11.1 的典型场景：同一件事（扫描本地附件引用）出现两个实现，必须收口成一个，第 7 个调用点才不会走错。

## 4. 流程约束

- 方向：**master 合进分支**（`git merge origin/master`），禁止 rebase/force push（`allow_force_pushes=false`）。
- 合并方式：**merge commit**，不 squash——跨平台整笔功能，历史保真优先。
- 不得 `--no-verify`：pre-push 跑全量三段（密钥守卫 + vitest + cargo），本仓最近一轮自报累计 347s；绕过只是把红推给 CI。
- 版本号由 Windows 侧发版时统一递增。
