## 一、中危（4 条，全部复核为真）

### M2 帮助浮层贴顶不翻转，确认条靠近屏顶时被裁（UI）

- **位置**：`src/components/recsel/RecHelpHint.tsx:15-44` + `RecOffice.module.css:26-40`
- **证据**：`.helpBox` 恒为 `position:absolute; bottom: calc(100% + 8px)`（渲染在 `?` 上方约 100px 高），组件无位置感知；同条画质浮层有 `flipBelow={top < 150}`（`RecOverlayParts.tsx:115` → `RecSettingsCluster.tsx:23`），HelpHint 三处使用（`RecOverlayParts.tsx:126/205`、`RecPreview.tsx:248`）都没有。
- **触发面（v2 修正，比初版更宽）**：初版写「选区贴屏顶」不准确。实际是**确认条顶部距屏顶约 100px 以内**即被裁：
  - 选区靠屏幕上沿 → 条挂在选区下方（`top = rect.y + rect.h + 14`），条本身就在顶部；
  - 或选区很高 → 条翻到上方并被钳到 `top = Math.max(8, rect.y - 130)`（`RecOverlayParts.tsx:94`）。
  - 浮层 `bottom: calc(100% + 8px)` ⇒ 盒子整体落在 `top ≈ 条顶 − 100px`；`recsel.css:14-23` 的 `html/body/#root { overflow: hidden; height: 100% }` 会把超出部分裁掉。预览条固定在屏下方 8%（`RecOverlayParts.tsx:177`）所以没事，问题只在确认条。
- **建议**：HelpHint 增加 `flipBelow`（或 top 阈值）prop + CSS `.below` 变体，与 SettingsCluster 同模式。

### M3 文章编辑脏数据无生命周期 flush，切后台/被杀静默丢失（数据丢失）

- **位置**：`src-mobile/knowledge/useKnowledgeArticle.ts:31,51`
- **证据**：脏数据仅 500ms 防抖（`:51`）；卸载清理（`:31`）只 `clearTimeout` 不 flush；全文无 `visibilitychange`/`pagehide`。消费方 `KnowledgeArticleView.tsx` 也无此监听（`useMobileBack` 只管返回键）。姊妹钩子 `useKnowledgeDraft.ts:66-67`、`useKnowledgeEdit.ts:66-67` 都有。
- **边界（复核补充）**：正常关闭走 `close()` → 会 flush（`:96`），安全；暴露面是「最后一次输入后 500ms 内切后台/进程被杀」以及**卸载路径**（`:31` 直接清定时器不 flush）。
- **建议**：补 `visibilitychange`(hidden→flush) + `pagehide` flush，与姊妹钩子对齐。

### M4 「停止本次下载」成功后误报红色错误

- **位置**：`src-mobile/knowledge/KnowledgeAssetSheet.tsx:54-60`
- **证据（v2 已打通到 Rust 端，闭环确认）**：
  - 前端 `cancel()` 成功后不清 `request.current`；
  - Rust `mobile_knowledge_asset_cancel` → `sync/service.rs:1372-1374` → `sync/asset_requests.rs:60-72`（置 watch 信号 + 记 tombstone）；
  - 在途 `fetch_asset` 的 `tokio::select!` 分支 `cancelled(&mut request_cancel) => return Err(AssetError::cancelled())`（`service.rs:1352-1358`）**明确以 Err 收场**；
  - 前端 catch 里 `if (request.current === id)` 仍成立 → feedback 被覆盖为红色「图片未能取得」；`MobileNotice` 无 onDismiss，错误常驻。
- **场景**：用户主动停止下载（成功）→ 界面从「正在停止下载…」翻成红色错误，无法区分真失败与主动取消。
- **建议**：`cancel()` 成功分支清 `request.current`（或专设 canceled 标记），让在途 reject 被静默吸收。

### M5 ChainRunnerDialog / ChainEditor 退场动画永不可达（UI）

- **位置**：`src/components/ChainRunnerDialog.tsx:26,66`、`ChainEditor.tsx:18,65`、挂载点 `CardList.tsx:858-860`

### 8.6 时序 flake 的修法（不放宽断言）

`test_连续写入会把窗口顶回去` 的下界（≥90ms）依赖「四次写入各被观察一次」，真等待下受调度影响：许可会塌陷，实测出现过 79.39ms / 136.9ms。修法是**换时钟、不换语义**：

- `dev-dependencies` 增加 `tokio = { features = ["full", "test-util"] }`（只影响测试构建）；
- 该用例改为 `#[tokio::test(start_paused = true)]`，虚拟时间零真实耗时；
- 断言**加强**为 `>= QUIET + 120ms`（=180ms：4×30 + 60，四次全吸收），比原来的「至少顶回一次」更强；
- 防假绿：把 `coalesce_writes` 里 `wrote.notified()` 那一路临时摘掉 → 实测 **60ms** 变红，还原后连跑 3 次 4/4 通过；
- 另外两处曾写「`features = ["full"]` 不含 test-util、所以不开」的注释（`service.rs:1008`、`tests.rs:2352`）同步改正，避免文档与实现相悖。

### 8.7 `rec-discarded` 无消费者的来历（结论：不是缺陷，是注释过期）

- `1bb4b01c` 时前端**确实监听**：`RecSelectOverlay.tsx:145`、`rec-control-main.tsx:53`；
- 后来收尾改为「后端权威」：`rec/session.rs:112-121` 在会话线程里固定先 `super::close_windows` 再 `clear_active`，注释写明「收尾绝不依赖覆盖层自己的 JS」；`rec/mod.rs:504-512` 的 `close_windows` 无条件 `destroy()` 选区窗与控制条；
- 于是两个监听被删、事件失去消费者，而 `session.rs` 里那句「必须清槽 + 发事件，否则覆盖层和控制条都会卡死」留了下来 —— **前提已经不成立**（清槽由 `clear_active` 负责、关窗由 `close_windows` 负责）。
- 处置：改正该注释，说明清槽/关窗都不依赖此事件、事件保留仅作排障信号。若要彻底清死代码，可把这 4 处 `emit` 一起删（当前无任何消费者），属独立清理项。
