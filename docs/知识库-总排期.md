## 4. 排期（五波）

分波的判据只有一条：**这一项做错了，能不能从行为上看出来。**
看得出来的先做；只能靠量的，等基准。

```
第 0 波  止血与拆线（不做新功能）
   │     P0 note_create 接受外来 id ← 现存 bug，不是前置
   │     四处重复规划落到单一出处（已在各文档标注）
   ▼
第 1 波  地基（不改排序、做错看得见、便宜）
   │     AM-2 节级命中 ← 三份文档的共同地基，必须最先
   │     AM-1a folder/tag 传参 · AM-6 库简介
   │     M6-P2 updated_ms(+单调保证) · M6-P3 补时间戳
   ▼
第 2 波  量（唯一的闸门）
   │     AM-5 召回基准（三条验收项）
   ▼
第 3 波  有了数才动的
   │     AM-3 时效 · AM-7 类型 · AM-8 近重复 · AM-9 排序
   │     O-2 + M3-④ 合并后的 note_links + 反链面板
   │     M6-P4 墓碑表 · M6-P5 图片核实
   ▼
第 4 波  大件
         O-4 切片层定案 →（若 AM-5 支持）M3-① + AM-10 向量层
         M6 主体（sync_engine + iroh）
         M3-③ digest / 抽取式草稿
```

### 第 0 波 · 止血与拆线

| 项 | 出处 | 为什么排最前 |
|---|---|---|
| **P0** `note_create` 接受外来 id | M6 §4.1 | **不是 M6 的前置，是已发功能的现存 bug**。今天把 vault 导出到 A、在 B 机导入，就已经在铸新 UUID、分裂身份。而 P4 墓碑传播整个建在它上面——P0 不修，那条链是空的 |
| 四处重复规划归口 | 本文 §2 | 不归口，两个会话会各写一遍同一张表 / 同一处排序 |
| r8 与探针措辞更正 | 本文 §3 | 虚前提留着，后面每一次决策都会继续引用它 |

**验收**：导出 → 另一个空库导入 → 两边 `notes.id` 完全相同。

### 第 1 波 · 地基

| 项 | 为什么在这一波 |
|---|---|
| **AM-2 节级命中** | 🔴 **必须最先**。它是 O-4 / M3-① / AM-10 **三者共同的地基**；不先定节级切分口径，切块层会被切三次。而且它本身价值最大：实测平均 **9,043 字/篇**，命中一篇 9,000 字的笔记只回 200 字摘要 ≈ 什么都没给 |
| **AM-1a** folder/tag 传参 | 底层 `note_search_relevant(query, folder, tag_ids, opts, limit)` 早就收这些参数，`source.rs:310` 传的是空串和空数组——**纯遗漏，改一行** |
| **AM-6** 库简介 | 新增一个配置项，不碰排序。⚠ 硬约束：**永远不能实现成一篇笔记**（否则 `kb_update` 能改它 = AI 拿到改自己系统提示的通道）|
| **M6-P2** `updated_ms` + 单调保证 | 「必须在同步代码前加列回填」是 M6 自己的硬约束；且 P2 要求**抓全 `updated_at` 调用点**，而 AM-9 会新增调用点——**P2 必须在 AM-9 之前，否则要扫两遍**。顺带把 §7.5 的「单调保证」一起做（几行代码）|
| **M6-P3** 补时间戳 | 与上同批，早做早便宜 |

### 第 2 波 · AM-5 召回基准

**它是唯一的闸门**，同时回答两个问题：排序改动有没有变好、**向量层值不值得做**。

三条验收项：

1. 含「**带系统提示污染的查询**」用例（MemPalace 实测该场景向量召回从 89.8% 掉到 1.0%；我们走 BM25 不会崩那么难看，但会被停用词稀释——先量）
2. **按查询类型分组报**，不报一个平均值（平均值会把崩掉的那一类盖住）
3. 🔴 单独统计「**关键词对不上、但语义对得上**」那一类 —— **这是 AM-10 唯一可证伪的存在理由**

**口径**：库只有 25 篇时 R@5 无区分度（= 返回全库的 20%），所以用**节级 R@10**，
且 **库 <100 篇时结果只归档、不作决策依据**——
否则「没基准就不改排序」会退化成「样本永远不够 → 排序永远不改」。

### 第 3 波 · 有了数才动的

| 项 | 备注 |
|---|---|
| **AM-3** 时效标记 | 双形式：`- superseded_by [[X]]` + `- valid_until <ISO>`。**不能做成布尔**——布尔表达不了「这个报价到年底就不算了」，而改约定语法比改数据库麻烦得多 |
| **AM-7** 记忆类型 | 行内 `- [类别]`，零 schema 改动。⚠ 正则**必须排除** `- [ ]` / `- [x]`（实测库里 3/3 全是任务复选框）|
| **AM-8** 近重复检测 | 标签/标题。⚠ 长度 ≤4 的串只报归一化后相等（`NC65`/`NC66` 距离 1 但是两回事）；**绝不在写入路径拦截** |
| **AM-9** 排序融合 | 先做零风险的「破同分」；多信号加权等 pin/引用有数据。⚠ `bm25()` 是**负数、越小越相关、ASC**——写成 `DESC` 会完全倒排 |
| **O-2 + M3-④** | 同一张 `note_links`，建一次；反链面板 + `[[` 补全跟着上 |
| **M6-P4** 墓碑表 | 依赖 P0 完成 |
| **M6-P5** 图片核实 | 确认截图插入是否让正文含图片链接；若含，vault 路线会**静默丢图** |

### 第 4 波 · 大件

| 项 | 前置 |
|---|---|
| **O-4 切片层定案** | 必须在向量入库之前——否则「等于全库重建一次」 |
| **M3-① + AM-10 向量层** | ① O-4 已定；② AM-5 验收项③ 的数支持；③ **真跑探针通过**（当前只有符号预筛）。路线 = 复用 vendored MNN；模型走**按需下载**，不打进安装包 |

## 5. 每项开工前先跑这一条

> 这张表本身是教训的产物：本轮反复犯的错是**把「应该存在」写成「存在」**
> （第三方分析当一手材料、自己的代码当已知、agent 记忆当规则文件）。
> 所以每一项开工前，先把前提变成**一条可执行的核查**。

| 项 | 核查 |
|---|---|
| P0 | `grep -n 'fn note_create_from' -A10 src-tauri/src/data_store/note.rs` 确认仍是 `new_v4()` |
| AM-1a | `grep -n 'note_search_relevant(query' src-tauri/src/mcp/source.rs` 确认空串还在 |
| AM-2 | 统计 `LENGTH(content)` 分布，确认长笔记占比仍高 |
| AM-3 / AM-7 | 统计含 `- [ ]`/`- [x]` 与含 `[[` 的笔记数，确认冲突面 |
| AM-4 | 统计 `source_agent<>''` 的笔记数，**>10 篇才有意义**（当前 1 篇）|
| AM-5 | 统计笔记数与总节数，确认节级口径的样本量 |
| AM-8 | 统计标签重名率（`tag.rs` 只 `trim()`，归一化后有多少组）|
| AM-9 | `PRAGMA table_info(notes)` 逐个确认要用的列真的在 |
| AM-10 / M3-① | 真跑探针：最小 Rust demo → `Express::Module` → 一次中文 embed |

## 7. 两条贯穿全局的约束

**① 三条红线**（来自主规划，任何一项不得违反）：

1. 学习只影响排序，**永不自动执行**
2. 使用日志**永不出本机**，且用户可见可删
3. shell 命令**永不自动执行**

**② 预筑与现状的关系**（AI 记忆库 §0.8 已拍板）：

实测 AI 写入仅 **1/25**、wiki 链 **0/25**、库 **25 篇**，
而 AM-3 / AM-7 / AM-9 是按「AI 会大量写」的未来状态设计的。
结论是**为未来预筑**，据此定三条：

- 预筑 ≠ 抢当前刚需的位置（所以 AM-2 在前、AM-4 降后）
- 预筑项的验收口径 = **机制可用 + 写入路径通**，而非「已大量命中」
- 多信号加权**等数据起**，不预填权重
