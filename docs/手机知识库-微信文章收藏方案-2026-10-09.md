# 手机知识库：微信文章收藏方案

状态：用户已确认 B 设计稿，并于 2026-10-10 授权实施和创建 PR。正文收藏、任务恢复、仅链接后补正文、缺图恢复已接入生产代码；本轮不构建安装包。具体范围与验证见 [实施验收记录](手机文章剪藏-B实施与验收-2026-10-10.md)。目标是用户在微信发现好文章后，以很少的操作将有用内容保存到手机知识库，随后可以离线阅读、搜索和同步到电脑。

## 1. 已核对的真实基础

- 手机已经接收 Android 系统分享的文字、链接和图片，有持久待处理队列、预览、快捷保存、草稿保护、去重及失败清理重试。
- 当前收集预览明确说明“链接网页不会自动下载”。分享文章链接并不等于已经得到正文。
- 桌面已有 `fetch_url_article`：抓取网页、识别微信公众号 `#js_content`、提取标题与公众号名、图片本地化；前端 `fetchArticleDraft` 共用 `htmlToMarkdown` 清洗。
- 手机阅读器支持安全 Markdown、本机图片 `pp-asset:`、目录、常用、阅读位置和知识库同步。
- 可复用抓取、正文定位、清洗与图片校验；不能直接搬桌面弹窗编排、`file:///` 图片引用和剪贴板历史依赖。需要适配手机任务生命周期、本机资产引用和保存回执。

源码：`src-tauri/src/commands/url_summary.rs`、`src-tauri/src/html_images.rs`、`src/lib/notes/article.ts`、`src/lib/notes/htmlToMd.ts`、`src-mobile/knowledge/KnowledgeCollectionSheet.tsx`、`useKnowledgeCollection.ts`、`KnowledgeReader.tsx`。

## 2. 方案比较

| 方案 | 用户得到什么 | 优点 | 代价 |
|---|---|---|---|
| A：收藏链接 | 原链接、可取得的标题、用户备注 | 最轻、断网也可先存、易落地 | 阅读仍依赖原网页；正文不能离线阅读或完整搜索 |
| B：手机文章剪藏（推荐） | 本机正文、可保存图片、原链接、来源及收藏时间 | 手机独立完成，收藏后可读、可搜、可同步；价值最直接 | 需要正文提取、图片持久化、失败恢复和设备实测 |
| C：手机先存，电脑补全 | 手机保留链接，由用户选择让已配对电脑补正文 | 能利用已有桌面能力，减轻手机任务 | 电脑离线时无法补全；不能假设电脑一定能读取手机微信登录态 |

建议 B 为主，A 是显式保底，C 后续作为可选补全方式；普通收藏不要求先连接电脑或建立远控会话。

## 3. 用户操作路径

### 可靠入口：复制链接

微信文章菜单复制链接 → PastePanda 的“知识库 → 新建 → 收藏文章” → 点击“粘贴链接” → 提取正文预览 → “保存文章”。

“新建”沿用原有入口，展开“写笔记 / 收藏文章 / 收集图片”。不在页头、空态和列表底部再重复添加同一个收藏按钮。粘贴由用户触发，不以持续监听剪贴板作为主路径。

### 更短入口：系统分享

当微信或浏览器提供 Android 系统分享时，选择 PastePanda → 直接进入同一文章预览。微信公众号自己的转发菜单不能被假定为 Android 分享面板，也不能保证 PastePanda 必然出现在其中。实际微信版本的入口在真机设计验收时核对。

### 补救入口：正文或截图

无法获取公开网页时，仍可保存链接，或将用户能够复制的正文/截图加入同一条笔记。截图明确标注为截图，不显示“已保存全文”。正文粘贴继续使用现有文字收集能力；图片继续使用现有相册/分享能力。

## 4. 文章预览与阅读

进入链接收藏即开始读取，不要求再点一遍“识别链接”。提交正文读取即表示用户请求访问该链接。

预览采用内容优先布局：标题 → 公众号/作者（取得时才显示）→ 正文预览。链接、分类、标签和收藏原因属于可展开的辅助信息。页头只有返回和标题，底部保留“保存文章”和次级“仅存链接”。不会先强制填写分类或再进入一套相同编辑表单。

保存后默认进入该篇阅读页，普通结果通过现有短反馈显示；继续操作不被常驻成功横幅占位。用户仍能查看原文、修改、加入常用、使用目录和同步。

横屏重排为内容区加窄操作区；小屏/大字体时正文滚动，保存操作保持可见。键盘只在添加备注或修改标题时出现。沿用 MobileSheet、MobileNotice、MobileToast 和现有字号/主题令牌，不创建另一套文章 App 的外观。

## 5. 状态与反馈

| 真实状态 | 用户看到的结果 | 下一步 |
|---|---|---|
| 链接已进入收集队列 | 链接已接收，正在读取正文 | 可返回处理别的内容；队列不丢失 |
| 已获得正文，尚未保存 | 文章预览 | 保存文章、仅存链接或取消 |
| 本机笔记提交完成 | 文章已保存到手机 | 阅读；同步状态单独查看 |
| 正文保存完成，部分图片失败 | 正文已保存，还有 N 张图片未保存 | 同一篇笔记中补齐图片，不重新创建笔记 |
| 无网络 | 当前无法读取正文，链接仍保留 | 仅存链接、稍后重试 |
| 登录、验证、已删除或未取得可读正文 | 暂时无法读取这篇文章 | 仅存链接、打开原文、补充可复制内容 |
| 手机存储不足 | 文章未保存，已取得的内容仍保留 | 清理空间后重试；不得显示成功 |
| 已收藏同一文章 | 已收藏过这篇文章 | 查看已有笔记，不默认重复创建或覆盖备注 |

“只有链接”“有正文”“正文与图片已保存在本机”使用不同状态。正文提取是否完全仍需预览和样例验收，不能因为 HTTP 成功就显示全文已保存。图片未全部本地化时不显示“已完整离线保存”。

不能获取的正文不会用 AI 生成替代品。基础收藏不调用模型；以后若增加 AI 摘要，仍须受现有 AI 开关与密钥门控控制。

## 6. 保存与任务边界

- 原链接先进入持久队列，成功提交本机笔记后才消费该条收藏。离开面板不会丢链接，也不会覆盖正在写的普通草稿。
- 单次收藏绑定原收集 ID、目标笔记 ID 与版本；失去提交回复时重试核对同一笔记，禁止保存当前另一份草稿。
- 图片作为同一篇文章的附件处理，使用 `pp-asset:`；统一校验格式、大小、像素与目录边界，增加单篇总量预算。暂存与已提交资产分别清理。
- 文章图片不能直接套用相册“每次最多 8 张”的用户操作限制，长文章的预算与分批下载要单独设计。
- 正文和用户备注分开记录。补图不覆盖正文；重新读取文章不得自动覆盖用户修改与批注。
- 重复识别基于原链接、最终地址和能可靠取得的微信文章身份。保留必要查询参数，不能把所有参数去掉；不能只按标题去重。
- 延续公开 URL 抓取、重定向及内网访问防护。提取网页只产生安全 Markdown，不把原网页脚本搬进阅读器。
- 手机独立保存；同步失败不会让本机保存变成失败，电脑接收成功也不会被伪装成手机完整离线成功。
- 首版采用持久待处理任务、前台执行与再次进入时恢复。若要承诺退后台或进程被杀后仍自动完成，另做 Android 系统任务调度；不能只靠页面组件里的 Promise 做承诺。

## 7. 分期范围

**第一批：有价值的闭环**

复制链接/系统分享 → 公开微信公众号和普通文章提取 → 内容预览 → 本机保存正文和可取得图片 → 同一笔记补图 → 原文入口、重复判断、既有草稿保护与失败恢复。未能读取时可明确选择仅存链接。

**后续增强**

稍后读状态、重点摘录/批注、可选择的电脑补全、在合法可访问的当前网页中辅助采集，以及完善后台调度。先确认真实需求再加入口，不一次铺开所有桌面管理功能。

公众号专用收藏助手不纳入首版：它需要独立公众号、账号绑定及服务端接收流程，不能仅凭手机本地 App 实现，也没有解决受限文章一定能读取的问题。

## 8. 验收与参考

设计前后使用真实组件结构验证：竖屏、小屏、短横屏、大字体、浅/深主题。真机样例包括公开纯文字、多图长文、短/长微信链接、重复分享、无网络、验证页、原文删除、图片部分失败、存储失败、既有草稿、离开/重启和提交回复丢失。

验收底线：保留已接收链接与用户输入；不把验证页当文章，不误覆盖笔记；成功回执准确；重试不重复笔记/图片；本机可读且可搜索保存下来的正文，附件缺失有明确入口。
