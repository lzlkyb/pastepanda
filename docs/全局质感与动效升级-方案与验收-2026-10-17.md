## 1. 方向选择

目标：在性能不退化的前提下，把动态效果做到准确、连贯、可打断；空闲时安静，高频操作利落，复杂状态也能看懂。

| 方案 | 核心做法 | 优点 | 取舍 |
| --- | --- | --- | --- |
| A 原位精修 | 保留布局，统一颜色、透明度与原位反馈；基本无空间位移 | 变更少，兼容验证范围较小 | 状态之间的空间关系表达较弱 |
| **B 克制流动，推荐** | 固定外壳；内容、滑块并行响应；局部补位；弹层短距离进出；反馈靠近触发点 | 兼顾速度、连续感和全局一致性，适合办公软件 | 需要统一现有 CSS/Framer Motion 配置并保护列表与焦点 |
| C 轻弹表达 | 在 B 上给模式滑块及少量形态变化使用现有定参弹簧 | 表达更鲜明 | 弹簧视觉尾部更长，原生浮窗需额外核对裁剪和边界；不适合每张卡片 |

C 档示例滑块使用既有 `--ease-spring`，800ms 为完整视觉尾部，动作立即响应、可以中断；其余颜色、文字和透明度不回弹。B 不追求让所有元素都运动，而把质量集中在发生变化的位置。

## 3. 推荐 B 的动效语言

下列数值是 **PastePanda 提案**，不是 Apple、Linear 或 Notion 的内部规范。优先对齐项目 UI 规则 U2；实施时消除源码和文档漂移，避免同时存在多套时长。

| 场景 | 建议时长 | 运动/反馈 |
| --- | --- | --- |
| 按下、选中、开始请求 | 同一事件内响应 | 先变状态，不等动画；实际异步任务与视觉过渡独立 |
| 悬停、原位成功、菜单 | 150ms | 颜色/透明度为主；小按钮按压最多 .98；菜单最多 3px |
| 模式、侧栏、局部补位 | 200ms | 外壳不动，模式内容与滑块并行；内容入场最多 4px |
| 对话框、详情层级 | 进入 300ms，退出 200ms | 面板进入最多 12px、scale .985；背板透明度 150ms 并行；无动态模糊 |
| 大范围变化 | 400ms 上限 | 限必要的大范围衔接，不用于普通点击，不延迟输入 |
| 拖拽、选区、光标、远程画面 | 无插值延迟 | 指针与内容直接跟手，辅助提示单独过渡 |

常规曲线：`cubic-bezier(.2,0,0,1)`；进入曲线：`cubic-bezier(.05,.7,.1,1)`。反复触发从当前视觉状态转向最新目标，不跳回初始姿态，不叠加动画、不排队。

空间层级：固定标题栏/模式入口 → 当前内容层 → 锚点菜单 → 模态背板与对话框。背景层不随着前景一起平移；不在每次打开应用时让整屏内容逐行飞入。

## 4. 状态与上手体验

- **复制**：按钮原位对勾与“已复制”，正常情况下不反复弹通知。保留原复制/粘贴语义，原型按钮不改变产品行为。
- **加载**：请求开始即展示明确状态；短任务不闪骨架，超过 1 秒才展开静态占位。已有结果继续可读，不能清空后假装空态；可取消的真实任务提供取消。
- **成功**：高频/可预期结果局部确认；产物保存要持续可找回；不靠绿色或短暂 toast 单独表达。
- **错误**：解释影响，保留输入/旧内容，给出重试；错误不会自动消失，也不能藏在收起的区域。
- **删除**：可恢复操作优先撤销，撤销 6 秒并在悬停/聚焦时停表；破坏性恢复默认保留确认、默认焦点到取消。
- **菜单与弹层**：Tab/方向键/Esc 可用；关闭后焦点回到触发点；快速开关不留下不可点遮罩或透明点击区。
- **录屏**：保留当前小浮条，只显示必要状态与控制；详情按需展开；计时不逐秒弹跳，录制点不持续呼吸。新增“小计时”形态是原型中的可选提案，若实施还需确认停止控制可达与误触成本。
- **设置**：控件立即确认，异步保存状态在同一可见域；六主题沿用语义色，不借动效重做品牌。
- **减少动态**：尊重系统设置和应用开关；取消空间运动、回弹、周期装饰，但保留文字、颜色、加载/保存/错误状态。不能只把 CSS 改成 1ms 而继续等待 JS 定时器。

## 5. 性能实现边界

1. 使用现有 CSS 与 Framer Motion。CSS 处理控件状态，Framer Motion 处理必要的存在/退出与共享元素；一个元素的同一属性只有一个动画控制者。不引入 GSAP 等新引擎。
2. 优先 transform/opacity；不动画大面积 blur、阴影或渐变，不使用全局 `transition: all`；不永久给大量元素 `will-change`。
3. 不为 1,000/10,000 条历史建立 layout 测量或监听。局部补位只处理当前可见变化；虚拟列表复用不是“新增”。不得以动效破坏搜索、滚动锚点、估高和动态测量。
4. 侧栏确实影响布局，不能宣称 transform 能免费解决所有宽度变化。HTML 使用有限示例行的宽度过渡；产品实施必须比较“布局提交一次后的视觉衔接”和有界布局动画，按实测选择；不把原型实现直接套到完整虚拟库。
5. 不增加常驻 rAF、装饰定时器、周期扫光/呼吸。真实任务中的进度/忙碌可运动，完成或隐藏即停止；系统通知、录制时钟等原业务定时机制不因动效重构被改坏。
6. 视图退出、窗口隐藏/最小化时释放新增监听和 observer、取消无用动画；不能后台继续整屏测量。恢复时以真实状态更新，不补播旧动画。
7. 录屏浮条先保留现有内容驱动尺寸测量和捕获排除，验证系统窗口边界、显示缩放、阴影裁剪、鼠标命中；网页预览不能证明原生窗口行为。

## 6. 实施顺序与验收

仅在用户确认设计后实施，每批保持可回退。

1. **动效参数与核心控件** → 统一时长/曲线、应用开关、系统偏好；覆盖按钮/开关/菜单/弹窗/通知的焦点、取消和退出。用相关行为测试和手工键鼠操作验证。
2. **主窗与列表** → 改串行切页、侧栏及可见行变化；不重做列表数据架构。验证连续 30 次切换、筛选、插入、删除、撤销；确认最终视图与最后点击一致、输入不丢失。
3. **知识、设置与工具** → 局部内容更新、就地保存与失败恢复；核对折叠/卸载后的草稿、缓存和错误可见性，不新增虚构功能。
4. **浮窗、录屏与编辑器** → 共用交互节奏，保留跟手与真实 IO；原生 Tauri dev 验证命中、焦点、捕获排除与多 DPI。只开 dev，不未经许可打 exe。
5. **性能和全局回归** → 同机同数据对比改前/改后，留原始轨迹和结果；运行相关测试、TypeScript 检查和 `npm run lint:ui`。发现 bug 按仓库规则先获得红用例再修复，不以反复重跑到绿代替证据。

| 验收项 | 目标与取证 |
| --- | --- |
| 输入响应 | 点击到首次视觉反馈目标 ≤50ms；实际环境不达标时定位主线程任务，不靠缩短动画掩盖 |
| 帧稳定性 | 动画活跃区间在 60Hz 的 16.7ms 预算下记录 p95、掉帧及新增 >50ms 长任务；120Hz 单独按 8.3ms 预算记录。以帧耗时轨迹判断，不只报平均 FPS |
| 空闲/隐藏 | 统计新增 animation/rAF/observer，目标空闲零装饰循环、隐藏无新增动画轮询；CPU/GPU/内存与改前同机对照，原有动态主题单独列出 |
| 虚拟列表 | 1,000/10,000 条数据下只操作可见变化；检查滚动锚点、行复用、内存、测量数量；不对全库 FLIP |
| 竞态和打断 | 连续切页、开关和开关弹层各 30 次；最后意图正确，无幽灵遮罩、残留位移或累积的动画/监听器 |
| 可访问性 | 系统减少动态与应用开关都测；键鼠全流程、焦点返回、错误不只依赖颜色、对比度符合 AA |
| 视觉适配 | 六主题、常用紧凑窗、100%/125%/150% 系统缩放；检查遮挡、文本截断、窗口裁剪和点击区域 |

这些是待实施验收目标，**本轮没有测得产品 CPU/GPU/帧率结果**。设计稿只验交互表达、布局、链接和脚本可运行。

## 7. 官方参考

- [Apple HIG · Motion](https://developer.apple.com/design/human-interface-guidelines/motion)：动效应有目的、短且准确；高频操作避免额外运动，并允许取消。
- [Apple HIG · Feedback](https://developer.apple.com/design/human-interface-guidelines/feedback)：反馈强度与重要性匹配；状态在上下文中解释；错误应帮助恢复。
- [Linear · How we redesigned the Linear UI](https://linear.app/now/how-we-redesigned-the-linear-ui)：借鉴层级、密度、对齐与应用外壳的处理，不推断其内部动效参数。
- [Notion · Designing Synced Blocks](https://www.notion.com/blog/designing-synced-blocks)：借鉴围绕用户心智、发现与上下文的交互表达；不是 Notion 全局动效规范。
