## 已确认的问题和范围

当前 App 的新入站请求会自动导航设备页；自定义分页在松手时提前切换业务页，视觉吸附仍在执行；模拟 PointerEvent 测试不能覆盖 Android WebView 的真实滚动接管。具体手机异常需在真机上记录确认，不把源码风险或预览表现当作已经复现的真机结论。

设计阶段仅新增设计稿，未替换 App.tsx、useMobileTabSwipe 或正式 App 样式。图标、页面标题、分组、底部导航和弹层均以现有源码为基线。直接复用 MobilePage、MobileNotice、MobileSheet、RcPairCard，以及已有 App、设备、文件、设置样式。

## 拟采用的交互

1. 横向分页使用真实滚动容器和 CSS Scroll Snap；不再用自写 PointerMove 位移与弹簧完成分页。竖向内容继续由各页面独立滚动容器承载。
2. 导航指示背景跟随实际滚动位置，整页落定后提交当前业务页；隐藏页保持实例但不可交互。滑动中的页面点击被拦截，底部导航可发起新的目标切换。
3. 相邻页点击由浏览器平滑滚动；跨两页点击直接到目标，不扫过中间页。系统减少动态效果时点击采用即时切换。
4. 新后台请求仅显示提示和设备角标；点击查看才导航，不强制打断当前页。正式远控会话进入仍需按业务规则单独协调。
5. 页面切换保留选中电脑与滚动位置。弹层继续使用现有模态容器，背景分页不可操作。
6. 只有实际宽度变化才重新对齐页面，提示和内容高度变化不触发分页复位。旧版 WebView 的停止滚动确认使用有限的延迟检查，不运行空闲动画循环。

## 接入与验收顺序

遵循 AGENTS.md 第 4 条，先确认此 HTML 交互稿，再替换正式分页实现。

1. 将分页状态和所有点击、业务跳转统一到一个导航入口；重审后台申请、前往设备、设备传文件等全部导航调用点。
2. 接入真实页面，验证分页落定期间的加载、错误归属、模态焦点、返回键、键盘和状态保存。
3. 当前手机逐项验证快滑、慢拖、斜滑、反向、连续翻页和滑动中点击；每组 30 次，目标是零错页、误触和状态丢失。
4. 真机检查列表滚动、弹层、文件传输及后台请求并发，记录响应与掉帧；条件具备后覆盖不同刷新率、WebView 版本。
5. 若原生滚动分页不能达到真机验收，记录证据后重新评估承载方式，不宣称达到 Android 原生手感。

## 正式接入结果

- `src-mobile/ui/useMobilePager.ts` 统一管理设备、文件、设置导航。删除原自定义 PointerMove/弹簧分页 Hook 及其旧测试，保留弹层仍使用的弹簧工具。
- App 使用真实横向滚动和 CSS Scroll Snap；指示背景跟随 `scrollLeft`，整页落定后才更新业务激活、无障碍与 inert 状态。相邻点击平滑、跨页即时，减少动态效果时即时切换。
- 三个页面保持单一实例和独立竖向滚动。输入控件限制横向分页，滑动期间拦截内容点击；远控、后台隐藏和弹层打开时取消未完成分页。
- 通知和键盘导致的高度变化不复位横向分页；宽度变化按已提交页面对齐。弹层内“传文件”通过统一入口排队，在背景解锁后导航，目标电脑保留。
- 后台新连接请求显示统一提示和设备角标，用户点击“查看连接请求”才导航。
