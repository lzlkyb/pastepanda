# PastePanda 宣传片播放与配音连续性排查

对象：`videos/pastepanda-demo/out/PastePanda-完整介绍-180s-中文配音音乐版.mp4`。用户反馈发生在聊天视频播放器中。本次只定位原因，未修改成片。

## 已确认的制作问题

### 1. 解说按章节独立拼接，停顿过长、语速变化

`scripts/add-narration.py` 分别合成 19 段 TTS，然后固定在每章开始后 0.4 秒放入；较长段落被单独加速适应章节。段落之间缺少连续解说的节奏安排。18 个接缝均存在 0.789 秒以上的人声停顿；其中 7 处超过 1 秒。音乐在这些位置仍存在，不是整个音轨掉线。

| 人声停顿区间 | 时长 |
|---|---:|
| 3.665–6.400 秒 | 2.735 秒 |
| 27.026–28.400 秒 | 1.374 秒 |
| 48.866–50.400 秒 | 1.534 秒 |
| 80.928–82.400 秒 | 1.472 秒 |
| 139.091–140.400 秒 | 1.309 秒 |
| 151.159–152.400 秒 | 1.241 秒 |
| 164.988–166.400 秒 | 1.412 秒 |

实际语速从 1.000 倍到 1.113 倍不等，会进一步影响整体一致性。每个 TTS 段落分别生成，语气也会在段落边界重新起句。

### 2. 原 UI 的动画被视频展示层移除，状态变化成为硬切

`source/source.css:10` 禁用所有 CSS animation 和 transition；`source/frameMotion.tsx:4` 丢弃 Framer Motion 的 initial / animate / exit / transition / layout 属性，`AnimatePresence` 变为 Fragment。除少量卡片入场外，没有把这些动画完整转换成视频帧驱动的动画。

`source/SourceApp.tsx` 在固定帧号改变状态，并以章节和阶段为 key 重新挂载弹窗。结果是界面直接从状态 A 跳到状态 B。`src/compositions/Film.tsx` 也根据当前按钮坐标重新计算鼠标整条路径；当目标改变时，鼠标可能直接换位置。

## 编码与独立播放检查

- 5400 个解码视频帧的 PTS 从 0 到 2764288，每步均为 512 ticks；time base 为 1/15360，即连续、恒定的 30 fps。未发现文件中漏帧、重复时间戳或时间跳变。
- 8438 个解码音频块的采样时间戳逐块连续，没有采样缺口。
- 坏帧与亮度检测复跑通过。BGM 在 48、96、144 秒的循环接缝样本跳变均为 0。
- 文件为 H.264 High / 720p / 30 fps，AAC LC / 48 kHz / 立体声，总码率约 697 kbps，文件有 faststart。
- 独立 Edge 浏览器通过本机 HTTP 地址，以正常速度播放完整 180 秒：播放中没有 waiting / stalled 事件，也没有音视频时钟停止；HTTP 正常返回 206 Range。
- 浏览器记录了 21/5400 帧的呈现丢帧，并在 135.233 秒处记录一次约 216.6 ms 的帧回调间隔。因此不能声称播放器完全无抖动；但这些呈现丢帧不等于源文件漏帧。

没有直接采集聊天播放器的日志，不能把聊天内多次停顿全部断言为播放器 bug、缓冲问题或硬件问题。独立播放结果只排除了源文件时间戳断裂和普遍解码失败。

## 检查盲点与修复方向

原有验证覆盖坏帧、亮度跳变、响度、削波和章节时间范围，未覆盖 UI 的状态衔接、鼠标轨迹衔接、配音长停顿及连续播放体验。之前“逐帧检查通过”不代表这些维度通过。

修复应把 UI 入场、退出与阶段切换转换为帧驱动动画，并保留鼠标原位置再移动至新目标；将解说按连续旁白重新安排，统一语速、缩短段间停顿，允许短的跨章节衔接。随后检查实际运动和完整播放体验，再用聊天播放器与独立播放器对照。
