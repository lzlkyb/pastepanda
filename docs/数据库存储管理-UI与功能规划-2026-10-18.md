# 数据库存储管理：已实施方案

日期：2026-10-18。图表方案经用户确认实施；随后按截图反馈删除「文件占用明细」「数据库表」两个技术明细区。

## 最终界面

入口为「设置 → 数据管理」顶部。沿用使用统计的组件语言：

- 四格指标：总占用、数据库、图片与截图、缓存。
- 占比环图：常驻图例展示名称、大小与百分比，默认突出最大来源，点击图例切换关注分类。
- 表占用排行：默认前五项，按占用降序，以中文用途、横条、大小、占主库百分比展示。
- 「展开全部 N 项」直接展开完整图形排行，支持收起；排行本身不再跳转到技术详情。
- 数据位置：当前实际目录、复制路径、打开文件夹，操作反馈与按钮同层可见。
- 原有保留策略、深度清理、导入导出继续使用；完成清理或导入后通知存储区刷新。
- 使用统计页原有的主文件 KB 数字改为「查看存储占用」入口，避免两处统计口径混淆。

不再展示文件清单、原始数据库表清单、字段、索引定义或逐表记录数；对应查询命令和组件已移除。首版不包含数据库整理、删表或新的清理机制。

## 统计口径

- 文件合计为应用数据目录内实际文件长度的合计，不是运行内存或安装包体积。
- 数据库包含主文件及存在的 WAL、SHM、journal 文件；图片与截图、缓存、其他文件按不重叠目录归类。
- 统计覆盖全部工作空间；外部原始文件、用户自行导出的目录不递归扫描。
- 表占用包含表本体及所属索引；SQLite 实际声明的全文搜索内部表合并到所属搜索表。
- 表排行百分比以逻辑主库大小为分母，环图以完整文件合计为分母，两者不重复相加。
- 业务表动态发现；中文名称映射不控制表是否进入统计。当前已知表提供中文名称，新表保留原名，不漏算。
- 未完整扫描的分类不冒充 0，不绘制虚假的完整环图；刷新失败保留旧值及时间，提供重试。
- 单位使用 B / KiB / MiB / GiB，复用公共字节格式化计算，仅将单位标注为 IEC。

## 实现

- `src-tauri/src/data_store/storage/`：文件扫描与只读 SQLite 页统计，独立连接，不持有剪贴板共享连接锁。
- `src-tauri/src/commands/storage.rs`：后台任务、请求取消和命令入口。
- `src/lib/api/storage.ts`：存储读取 API 与完成操作后的刷新事件。
- `src/hooks/useStorageStats.ts`：可见时按需加载、先主文件元数据后目录扫描、旧请求隔离与失败状态。
- `src/components/settings/storage/`：图表、总览、主题样式、中文用途映射。
- `src/lib/utils.ts`：共用单位显示与表本体/索引合计函数。

无常驻轮询或动画。目录遍历使用与深度相关的 ReadDir 栈，不跟随符号链接或 Windows 目录联接。目录扫描及数据库页查询均可取消。剪贴板新增只提示统计可能过期，不在每次复制时重扫目录。

## 验收

- 文件合计涵盖 WAL 与库外附件、未知目录归入其他、缺失主库报告错误。
- 新表仍被发现；普通索引只归属一次；FTS 影子表合并且不误吞同前缀业务表。
- 空库保留结构大小；取消不让旧响应覆盖新结果；隐藏区域不主动扫描。
- 图表比例正确；完整排行就地展开/收起；设置搜索能找到图表区。
- 界面不再出现用户要求删除的两个明细区，也不再存在表字段/计数查询路径。
- 检查相关前后端测试、TypeScript、ESLint、CSS 引用及 UI lint；Tauri dev 用项目规定的 `npm run tauri dev` 启动。

技术口径参考 SQLite 官方 [DBSTAT](https://www.sqlite.org/dbstat.html)、[WAL](https://www.sqlite.org/wal.html)；实际 bundled SQLite 的 DBSTAT 能力已由 Rust 测试验证。
