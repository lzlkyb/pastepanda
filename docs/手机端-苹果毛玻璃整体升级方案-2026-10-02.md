# 手机端苹果毛玻璃整体升级方案

## 已有基线

源码：App、MobileUi、设备 / 文件 / 设置视图及样式、配对卡和控制会话。已有浮动玻璃导航、实底分组、系统字号、48px 主按钮、跟手弹层和 B 触控语义。本轮是整体视觉与交互统一提案，不修改生产代码。

保留已确认 C 布局、现有设备图标与真实名称规则、桌面语义色、连接权限、扫码 / 短码能力和 B 手势逻辑。HTML 中名称、状态和进度均为示例；扫码与发送不产生真实请求。

## 三个方向

| 方向 | 特征 | 优点 | 取舍 |
| --- | --- | --- | --- |
| A 经典磨砂 | 实底内容、低强度磨砂导航与弹层 | 稳定清晰，变化少 | 材质变化偏保守 |
| B 分层毛玻璃，推荐 | 导航轻透、弹层厚透、实底内容；柔和底色和浮动层次 | 苹果感明显，也适合远程控制和文件操作 | 需统一所有弹层与状态 |
| C 通透玻璃 | 更低不透明度、更明显边缘高光 | 材质存在感强 | 动态背景下对比度与 WebView 性能更难保证 |

三套都不对每一行或每张内容卡片施加独立模糊；差异在操作层材质。

## B 的页面方案

- 全局：保留设备 / 文件 / 设置三栏。选中底片平移，文字常驻；顶部大标题随滚动收拢，内容与导航保留安全间距，顶部和底部共用玻璃令牌。
- 设备：减少通道状态的视觉重量，设备名称、类型、连接状态突出；主入口添加电脑，扫码突出、短码备用。设备操作弹层统一控制 / 只看 / 传文件，配对与连接阶段明确可取消。
- 文件：先看目标设备，再选文件；进度与取消集中在任务区域。文件请求保持明确接受 / 拒绝，失败保留重试路径，目标设备和接收目录显示不靠猜。
- 设置：继续分组列表。图标尺寸、行高和开关统一；历史、外观、手势帮助共用厚玻璃弹层，不增加无关设置项。
- 控制：画面层不模糊，浮动工具层透光；鼠标辅助状态持续可见。横屏沉浸保持工具把手；键盘打开时缩减重复工具，不遮输入框与发送反馈。低频功能集中到更多。
- 配对 / 扫码：进入、识别、等待确认和失败都有明确信息；摄像头仅在扫码期间运行，权限失败能返回短码输入。二维码不自动隐藏，沿用已确认策略。
- 弹层 / 提示：标题和关闭位置一致；拖动跟手、短拖回位，内容可滚动。成功与失败与触发处在同一可见层，危险操作确认，系统返回先退当前层。

## 统一动作语言

| 动作 | 建议 |
| --- | --- |
| 按下与松开 | 立即开始响应；150ms 底色 / 透明度恢复，轻微形变。滑出与取消结束按压态 |
| 导航与状态 | 200ms 选中底片位移，切页保持列表位置与草稿。横向切页手势仅在普通页论证，不绑定到控制画面 |
| 弹层 | 300ms 进入；拖动直接跟随，不加缓动；取消回位与退出接续当前位置 |
| 会话进入 | 画面就绪后再开放输入；短过渡说明从设备到控制的空间关系，不延迟操作 |
| 指针 / 滚动 | 保持实时，不做弹簧或惯性来修饰远端输入 |
| 网络结果 | 加载 / 失败 / 可取消保持可见，不能用动画假装远端成功；触觉仅在平台支持时补充 |

## 材质、兼容与验收

字重、字号、图标和语义色复用现有体系；圆角层级收敛到按钮 / 分组 / 浮动面板，桌面端继续用同一品牌色与交互文案。手机强调触控尺寸和层次，桌面保持更紧凑密度。

单屏通常顶部、底部两个模糊面；弹层打开时停用其下的模糊，目标是不超过三个活跃材质面。不能在远程画面上叠加整屏模糊，也不加常驻折射或光效动画。浏览器方案采用毛玻璃近似，不能宣称等同原生 Liquid Glass 光学渲染。

减少动态效果取消位移装饰，减少透明度改实底；相关能力在 Android / iPhone WebView 是否暴露需真机确认。滚动背景下文字满足 WCAG AA；320px、390px、平板、横屏、软键盘、深浅色以及长设备名都需检查。测试覆盖导航保留状态、弹层返回层级、忙态取消和手势互斥；性能通过代表性手机滚动与远程会话测量后再下结论。

实施顺序：统一材质与动作令牌 → 导航 / 顶栏 / 弹层 → 设备与配对 → 文件与设置 → 控制页 → 真机与性能验收。先确认本次设计稿，再改生产组件。
