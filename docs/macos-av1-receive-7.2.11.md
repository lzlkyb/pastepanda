# macOS AV1 原生软件接收（7.2.11）

用户确认使用 dav1d 软件解码。新增接收链路加载应用自己的可替换 AV1 动态库；编码 ABI 1 保留，接收符号为兼容扩展。缺库、坏包、超出软解预算仍沿原有 AV1 → H.264 → JPEG 恢复路径处理。

## 接收边界

- dav1d 1.5.3 来自 VideoLAN 官方发行包，SHA-256 对照官方清单固定；FFmpeg/SVT 的原有来源、签名校验保留。新增 BSD 许可证、原始源码和接收桥源码随包交付。
- 软件接收最多 1920×1080 像素，单边最多 1920，支持竖屏；压缩单包最多 8 MiB。FFmpeg/dav1d 在分配图像前限制像素数量，固定两个解码线程和一帧延迟。
- 解码器归远程会话所有；换会话、换尺寸、编解码错误、会话结束均释放或重新等待关键帧。取队列与解码串行；异步返回前再次校验会话，旧窗口不能取走新会话帧。
- 每个参考帧都解码，同一连续 AV1 段只返回最后一张 RGBA，避免一次取帧返回几十张未压缩画面。合并时保留全部压缩字节统计及解码耗时。
- 网络协议不变。只在本机 RCF2 IPC 使用 `0x83`，载荷为压缩字节数、解码微秒数、RGBA；前端检查尺寸与字节数并直接取 ArrayBuffer 视图。新取帧在阻塞工作线程运行，可见窗口才请求，后台不新增循环。
- 全部预测编码（H.264／HEVC／AV1）共用队列断链保护。连接详情、编码通知与等待提示共用编码名称，AV1 不再冒充 JPEG。

## 本机测量与限制

自有合成像素，30 帧完整流及 15 帧强制关键帧恢复流；独立 libaom 解码器交叉验证。两种架构的库均已编译，当前测量在 Apple Silicon 上运行。

| 测试 | 结果 |
|---|---|
| 720p dav1d 解码＋RGBA 转换 | 平均 3.07 ms，最大 10.30 ms，CPU 3.70 ms／帧 |
| 1080p dav1d 解码＋RGBA 转换 | 平均 4.21 ms，最大 12.87 ms，CPU 5.49 ms／帧 |
| 1080p 原始 IPC 像素量 | 7.91 MiB／帧；不是网络发送量 |
| 1080p Rust 批次序列化＋字节验证 | 平均 0.455 ms／帧，30 次自有数据 |
| Chromium 本机 HTTP 二进制＋真实解析器＋Canvas | 平均 8.33 ms，P95 13.10 ms；30 次，前台，预热 5 次 |

Chromium HTTP 测量**不代表 Tauri WebKit IPC**，更不代表双电脑真实远控帧率。不能将这些时间简单相加后宣称实机 FPS。Intel CI、旧系统 GUI、双设备 AV1 网络及输入联动仍需对应验收；当前没有第二台设备。

## 回归证据

未实现版本先失败，修复后通过：

- `rcNativeFrame.test.ts`：六个用例先红后绿（像素类型、尺寸、长度、未知编码）。
- `useRcFrames.native.test.ts`：旧 hook 没有画面上屏，新 hook 无 VideoDecoder 仍上屏；隐藏时零取帧。
- 原生 `av1_receive_probe.c`：旧库缺解码符号时失败，新库解出连续画面、强制关键帧独立恢复、时间戳、透明通道、颜色与坏包边界。
- `all_interframe_codecs_wait_for_key_after_outbox_overflow`：旧 HEVC 分支先失败，统一预测编码保护后通过。
- `viewer_drain_serializes_queue_consumption_before_native_decode`：新增异步路径缺串行守卫时先失败，串行消费＋解码后通过。
- `pending_viewer_waits_without_consuming_frames_or_reporting_decode_failure`：连接／等待批准阶段返回空批次而不报解码故障；先红后绿。
- HUD／被控通知的 AV1 文案：两项先显示 JPEG 而失败，单一名称源修复后通过。未知编码不会读取对象原型属性。

红／绿日志保存在本机 `.cache/av1-receive-*.log`。源代码测试不能替代真实权限、设备或听音验收。

## 实机权限回归

在未改签名的 `outputs/macos/mcp-codex-7.2.11/PastePanda.app` 完成录屏：开始、暂停、恢复、停止、应用内预览、裁剪与 GIF 导出通过。录像 33.40 秒，完整解码 884 帧，时间戳严格递增；暂停段不计入时长。裁剪约 29 秒，GIF 480×270、343 帧可解码。

这一验收属于旧冻结包，不能自动延用到新 AV1 包。当前包麦克风操作明确提示未授权；最终包签名固定后再统一确认录屏、麦克风和钥匙串。不得用编译或静态源码检查冒充权限验收。

## 已确认的编码菜单

用户确认 `design/macos-av1-codec-menu.html` 后实施：远程会话「更多 → 视频编码」提供 H.264／JPEG，以及对方上报支持时的 HEVC／AV1；另显示真实帧的实际接收编码。切换请求、失败与未确认结果走会话常驻出口条，全屏或收起菜单也可见；菜单卸载不丢失请求状态。

切换使用已有 `rc_apply_setting` 的会话绑定、序列号回执与 8 秒超时。旧端不回执时显示「未确认」，不能把写入通道成功当成接收成功。Mac 请求 AV1 且当前为自动、4K 或高帧率档时，先要求对方确认「均衡」画质，再发送 AV1 请求；失败或未确认时明确说明，实际编码始终来自画面。

生产组件浏览器实测还发现亮主题下深色更多面板的当前值落到深字色，修复为继承面板按钮亮字色，并对齐深色悬停反馈；新增样式守卫先红后绿。浏览器菜单几何验证在视口内，IAB 没有进入真实全屏，因此没有把此测试记作全屏实机通过。

新增回执用例先复现会话入口拒绝 AV1（配置路径支持，但 `set_codec` 仍只接受 JPEG／H.264／HEVC）；修复后同一用例覆盖四种编码、只看权限、旧会话拒绝与未知值拒绝。前端覆盖能力门控、请求中防重复、降档顺序、拒绝／未确认反馈及会话切换／卸载的迟到结果。

## 接收标签边界补审

`useRcFrames` 的旧自动回退函数会在只发出 H.264 请求时先改编码标签。新增用例在仍收到 AV1、WebCodecs 不可用的条件下复现（先失败）；修复后标签只随接收数据变动，未收到首帧时菜单显示等待画面。此前冻结的0575276安装包不含此补丁；保留其签名用于已经请求的权限回归，本补丁进入源码及CI，不静默替换已授权包。
