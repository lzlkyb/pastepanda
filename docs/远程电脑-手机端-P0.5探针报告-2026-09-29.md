## 1. 探针 A · 可移植性（判据达成）

### 1.1 判据复核

> 规划原文判据：`net / protocol / link / pin / file_* / outbound` 的非 Windows 段能编译过。

**达成。** `cargo check --target aarch64-linux-android` 全流程实测：

| 层 | 结果 |
|---|---|
| 全依赖树（iroh / rustls / tokio / tauri 2 / reqwest…） | ✅ 编译通过 |
| `rc` 客户端半（net / protocol / link / pin / file_proto / file_state / file_transfer / outbound / clipboard / history / session / discovery / video） | ✅ 零错误 |
| 唯一依赖树拦截 | ❌ `arboard 3.6.1`——无 Android 实现（见 1.2） |

### 1.2 arboard：唯一的结构性缺口

它有**两条引入路**，P1 门控时两条都要收：

1. 直接依赖：`src-tauri/Cargo.toml:47` `arboard = { version = "3", features = ["image-data"] }`
2. 传递依赖：`tauri-plugin-clipboard-manager 2.3.2`（还要 `wayland-data-control` feature）

修法与仓库既有模式一致：照 `Cargo.toml:210` 的 `[target.'cfg(not(any(target_os = "android", target_os = "ios")))'.dependencies]` 段把两条都收进去。

### 1.3 工具链前提（探针实测出的两个环境门槛）

| 门槛 | 现象 | 解法（已验证） |
|---|---|---|
| `ring` 的 C 编译 | `cc-rs: failed to find tool "clang.exe"` | 设 `CC/CXX/AR_aarch64_linux_android` 指 NDK 27.2 的 clang 包装器 |
| `ocr-rs`（vendored）的 bindgen | `'stddef.h' file not found` | `BINDGEN_EXTRA_CLANG_ARGS_aarch64_linux_android` 指 NDK sysroot + clang 18 builtin headers |

完整命令模板见 `docs/dev-运行手册.md` 新增的 Android 一节。

### 1.4 arboard 接管后的错误普查（app 壳层工作量实测）

用临时 stub 接管 arboard 让 check 走进自家 crate，一次成功运行的错误普查：**93 个错误，全部落在 app 壳层与宿主侧，无一落在 rc 客户端半**。分布：

| 类别 | 错误数 | 涉及文件 | 性质 |
|---|---|---|---|
| tauri 移动端缺失 API | ~45 | `decorations`(7) `set_ignore_cursor_events`(6) `set_always_on_top`(4) minimize/unminimize/maximize/unmaximize `hwnd` `tray` `global_shortcut` 插件 | 桌面壳能力，cfg 门控即可 |
| `windows` crate 直调 | ~15 | screenshot.rs / pinned_window.rs / clipboard_monitor.rs / paste_engine.rs | 已大量有 cfg 守卫，收尾即可 |
| 宿主侧 audio/encode cfg 缝隙 | ~15 | rc/inbound.rs / rc/inbound_tasks.rs / rc/inbound/video* / service/inbound_accept.rs / session/lifecycle.rs | `super::audio` 等 windows-gated 模块被无守卫引用 |
| 其他杂项（OsStr 扩展、str 大小） | ~18 | todo_island_probe / quick_paste 等 | 同上，逐条收 |

> 注：普查是探针级快照（stub 是假 API，只做类型检查），精确到「哪些文件、哪类错」，不精确到行。P1 照此清单门控即可。

### 1.5 so 体积：探针拿不到，如实说明

check 不产出 so；so 体积要等 app 壳层门控做完后的 `cargo build --release --target aarch64-linux-android`。**这是 P1 第一周内的第一个副产物**，规划里的「探针顺带量」改到 P1 早期兑现。

### 1.6 Android 工程已生成

`tauri android init` 成功（tauri-cli 2.11.3 + NDK 27.2.12479018 识别正常，自动补装 armv7/i686/x86_64 三个 rust target）。产物在 `src-tauri/gen/android/`（完整 gradle 工程）。**是否入库未定**：Tauri 惯例是 gen/android 提交（内含签名配置），当前 `.gitignore` 只忽略了 `gen/schemas`——等你拍板。

## 2. 探针 B · 解码（判据达成·桌面端；真机复测待做）

### 2.1 判据复核

> 规划原文判据：H.264 至少一档 + AAC-LC 通过。

**桌面 Chromium 实测（Electron 41 / Chrome 146，与 Android System WebView 同为 Chromium 家族）：**

| 项 | 结果 |
|---|---|
| H.264 avc1.640028/2a/33/34（720p→4K60 全档） | ✅ 全支持，且 `prefer-hardware` 硬解可用 |
| HEVC hev1（1080p60 / 4K60） | ✅ 支持，硬解可用 |
| AAC-LC `mp4a.40.2`（48k/44.1k/单声道 + ASC） | ✅ 全支持 |
| AV1 | ❌ 不支持（桌面端也不用它兜底，无影响） |
| Opus（未来降级备选） | ✅ 支持 |

⚠ **注意**：这是桌面参考值。Android 真机的硬件解码器（MediaCodec）各机型不同，**判据最终以真机为准**——探针页就是为真机准备的。

### 2.2 探针页与真机复测路径

- 探针页：`design/远程电脑-手机端-WebCodecs探针页-2026-09-29.html`（单文件零依赖，`rcH264.ts` 三个串生成函数原样移植，保证与桌面端字节级同源；自动运行，右上角复制 JSON 报告）
- 真机两条路（都写在 `design/远程电脑-手机端-WebCodecs探针-serve.mjs` 头注释里）：
  1. 把 HTML 单文件直接发到手机（微信/QQ），Chrome 打开——`file://` 即安全上下文，WebCodecs 可用，零基础设施；
  2. 同一 WiFi 下跑 `node design/远程电脑-手机端-WebCodecs探针-serve.mjs`（https 自签，手机点「高级→继续访问」）。
- 复测判据同规划：H.264 ≥1 档 + AAC-LC；不满足则视频走原生 MediaCodec 插件（规划既定回退）。

1. **`service.rs` 2531 行已不存在**——已拆成 `rc/service/` 10 个文件（最大 566 行）。规划 §3.5 的「拆 `rc::host`/`rc::client` 前置工序」在模块层面**基本已完成**，不再需要单独立项。
