## 0. 调研参照：别人怎么做（2026-08-13 调研）

为让方案准确，调研了三类产品。核心发现：**主流剪贴板管理器普遍不做日报/周报，只做记录+检索**——PastePanda 做「日整理」是差异化蓝海；「日报周报」做得最成熟的是时间追踪类与 AI 回顾类。

### 0.1 四类产品
- **① 剪贴板管理器（CleanClip / Paste / Mac 系）**：能力集中在自动记录、搜索、收藏列表（书签）、智能列表（按条件过滤）、粘贴栈、跟随当前 App。**均无聚合日报/周报** → 竞品空白，即差异化切入点。
- **② 时间追踪类（RescueTime / Rize / Dayflow）**：日报/周报结构最成熟——总时长+生产力分、按类别/应用/时段分解、最高效日、目标进度、每周邮件推送。Rize 可设追踪时段（非工作停追护隐私）；Dayflow 时间轴卡片+环形图/热力图/周对比+导出 HTML 报告。
- **③ AI 回顾类（MineContext 字节 / SelfManager / Taskade）**：本地存储、主动交付。MineContext 自动生成**日报+待办**、周五推周报、关联相关聊天/资料，并可**基于总结追问对话**（"我这周时间分配合理吗？"）；SelfManager 走「review → 对话 → 下一步行动」闭环。
- **④ 周回顾方法论（Notion / Obsidian / Todoist）**：Notion 可组合周控制面板，AI 把长笔记总结成行动清单；"Friday Packet"范式：亮点 + 决策 + 未决项，tag 到项目。强调回顾要影响「下周三大要务」才有效。

### 0.2 横向对比（决定该做什么、不做什么）

| 维度 | 剪贴板管理器 | 时间追踪 | AI 回顾 | PastePanda 取法 |
|---|---|---|---|---|
| 数据粒度 | 复制内容/来源App | 窗口/应用时长 | 上下文+聊天 | **内容类型+来源App+主题簇**（无时长，不硬凑） |
| 日报 | 无 | 有 | 有 | 做（蓝海） |
| 周报 | 无 | 有 | 有 | 已有（v6.4） |
| AI 洞察 | 无 | 弱 | 强 | 行为级（默认）+ 授权读原文的内容级（语义准确） |
| 隐私 | 本地 | 本地/云端 | 多本地 | **本地 + 默认不读 + 授权才读 + 可审计** |
| 推送 | — | 邮件周报 | 主动弹 | 托盘推送+手动+随启补报 |

### 0.3 对本案的修正
1. **差异化而非跟风**：剪贴板赛道无人做整理，重点是变成可行动洞察，而非再做个统计。
2. **不硬凑生产力分**：没有窗口时长数据，日报聚焦内容类型占比/来源 App/主题簇，不做效率分。
3. **加"关联待办/延伸"**：参照 MineContext，从碎片识别待办、关联工作区。
4. **加"可追问对话"**：参照 SelfManager，简报支持后续追问，而非一次性总结。
5. **推送而非仅被动**：参照 Rize/RescueTime，托盘定时推送主动交付。
6. **护隐私的时段开关**：借鉴 Rize「可设追踪/整理时段」，非工作时段不纳入。

## 1. 背景与问题

PastePanda 一直在**被动记录**用户每天的工作碎片：

- 剪贴板历史：复制的每一条文字 / 图片 / 文件都进历史，可搜索可筛选；
- 工作区：用户可手动按项目 / 场景把碎片分组；
- 片段库：用户可手动固定常用碎片（支持 `{{date}}` 等变量）；
- 每日复制计数：后端一直在记"今天复制了多少"，供周报柱状图使用。

但**记录 ≠ 整理**。目前缺少一条关键链路：**把一整天散落的碎片，自动聚合成一份可回顾、可沉淀的"今日总结"**。

用户的真实诉求是：

> 我每天复制粘贴了几十上百条东西，下班前能不能帮我**自动理一遍今天都干了啥 / 攒了啥**，而不是让我自己翻历史？

现状对比：

| 能力 | 状态 | 粒度 | 是否读内容 |
|---|---|---|---|
| 剪贴板历史 / 工作区 / 片段库 | ✅ 已落地 | 单条碎片 | 是（本地） |
| 周报（E，行为统计） | ✅ 已落地（v6.4） | 按周 · 行为级 | 否（仅统计） |
| AI 单条总结（ai-summarize） | ✅ 已落地 | 单条 | 是（仅该条，用户选中） |
| **每日整理 / 日记 / 日报** | ❌ 未落地 | 按天 · 聚合 | 需设计（默认不读，授权读原文） |

> 注：原 `PastePanda-AI架构与路线图.md` 第 229 行把"E 剪贴板周报"标为"规划中未落地"，与当前源码（v6.4 已实现 `WeekReportDialog` / `src/lib/weekReport.ts`）不符，本文档以源码为准——**周报已落地**。

## 2. 目标

### 2.1 产品目标
让用户**每天结束（或随时）**能一键看到一份"今日工作碎片整理"：
- 自动归类今天复制 / 粘贴的内容主题；
- 提炼今天高频处理的任务 / 项目 / 关键词；
- 生成一段口语化"今日小结"——**既要有行为层概览，也要在用户授权后达到内容层语义准确**（产品已决策：内容层也要准）；
- 支持把整理结果**沉淀进工作区 / 片段库**，成为长期资产。

### 2.2 非目标（明确不做）
- ❌ 不做"宠物养成 / 情感陪伴 / 聊天式对话"（见架构文档 H 系列边界）。
- ❌ 不做跨设备云端内容同步（仅局域网加密同步，见现有同步机制）。
- ❌ 不做"自动替用户执行动作"——只整理、不行动（守红线③可托付执行边界）。

| 角色 | 场景 | 期望 |
|---|---|---|
| 职场白领 | 一天在多个群 / 文档间复制需求、链接、表格 | 下班前看"今天主要在处理 X 项目，复制了 32 条，含 8 个链接、2 份表格"，并自动归好类 |

## 4. 功能定义

### 4.1 核心概念：「日整理」
**日整理 = 自动聚合当天（默认 00:00–now）的全部工作碎片 + 生成一份结构化"今日简报"。**

一份"今日简报"包含两层：

1. **行为层（永远可用，零内容出网）** —— 复用周报的统计能力：
   - 今日复制 / 粘贴次数、按小时分布；
   - 内容类型占比（文本 / 图片 / 文件 / 链接）；
   - 来源 App TopN、高频时段、常用动作；
   - 自动聚类出的"主题标签"（基于来源 + 关键词本地提取，非 LLM）。

2. **内容层（按需授权读原文 · 做到语义级准确）** —— 产品已决策"内容层也要准"，故主路径为用户**显式授权后读取原文**（参照 MineContext / SelfManager），从"行为描述"升级到"内容理解"：
   - **行为级小结（默认兜底，零原文）**：仅喂元信息 / 摘要 → "复制 X 次、60% 来自 VS Code"；
   - **内容级小结（授权后，语义准确）**：点"用全文生成今日小结"或"深入总结这簇"后，临时读取该范围原文送 AI → 能说出"今天在对接支付接口、修了 Y bug、与 Z 在对接需求"；
   - "行动建议"：基于工作区归属，提示"这 5 条可整理进『周会』工作区"；
   - "关联待办"：从原文识别待办生成清单（参照 MineContext）；
   - "可追问对话"：支持"就今天这些，我下周该优先做什么？"等后续追问（参照 SelfManager）。

### 4.2 触发方式
- **定时**：默认每天 20:00 在托盘弹"今日整理好了"提示（可关）；
- **手动**：顶栏「工具箱」→「今日整理」；全局热键（如 `Ctrl+Shift+D`）；
- **随启**：软件启动若发现"昨天没整理"，补一份"昨日简报"。

### 4.3 隐私红线（硬约束）
守现有 AI 架构文档的红线②（`redlineGuard` 测试覆盖），并明确"内容级准确"的边界：
- 行为层**绝不读取剪贴板原文**，只统计类型 / 次数 / 来源；
- 内容层**默认不读原文**；仅在用户**显式授权**后才读取指定范围（某簇 / 全天）原文送 AI，且须满足：
  - 授权前**明示**"将把 N 条内容发送给已配置的 AI 提供商"，用户勾选同意；
  - 原文**仅本次调用发送，不留存、不进局域网同步流**；
  - 设置内含"允许读原文"**总开关（默认关）** + **审计日志**可查每次读取；
  - 不读原文时自动**降级**为行为级小结，功能不中断；
- 日整理结果默认**仅本地**，除非用户显式分享。

> 红线②从"绝不读"修正为"默认不读、授权才读、全程可审计"——这是 2026-08-14 产品拍板"内容层也要准"后的对应调整。

## 5. 技术方案

### 5.1 数据来源（复用现有，零新增采集）
| 数据 | 来源 | 备注 |
|---|---|---|
| 当日碎片列表 | `data_store` 历史表（按 `created_at` 过滤当天） | 已有 |
| 每日复制计数 | 后端 `stats_sticky` / 每日计数 | 已有（喂周报柱状图） |
| 来源 App | 历史记录 `source` 字段 | 已有，后端 GROUP BY |
| 工作区归属 | 工作区表 | 已有 |
| 类型占比 | 历史 `type`（text/image/file/url） | 已有 |

### 5.2 整理引擎（本地，无出网）
- **聚类**：基于 `source` + 本地关键词提取（`ExtractDialog` 已有的信息提取能力可复用），把当天碎片分成 3–8 个松散"主题簇"，每个簇给一个自动标签；
- **去噪**：过滤掉纯密码、一次性验证码、明显敏感项（复用 `mask-sensitive` 逻辑）；
- **摘要**：每条碎片生成 ≤40 字本地摘要（取首行 / 标题 / 文件名），不送 AI。

### 5.3 AI 接入（两种模式 · 内容级准确走授权读）
- 复用 `Provider` 抽象层 + `ai-weekly-report` 动作的既有模式，新增动作 `ai-daily-brief`；
- **模式一 · 行为级（默认）**：输入「当日统计数字 + 各簇标签与摘要」，输出 ≤200 字小结，零原文出网；
- **模式二 · 内容级（授权后）**：用户授权后，读取指定范围（某簇 / 全天）的**原文**送 AI，输出含具体项目 / 任务 / 待办的语义级总结；
  - **授权流程**：点击"用全文生成" / "深入总结这簇" → 弹窗明示"将把 N 条内容发往已配置 AI 提供商" → 用户勾选确认 → 仅本次发送、不留存；
  - 复用 `ai-summarize` 对"选中单条生效"的授权模式，扩展为"选中簇 / 全天生效"；
- 复用 `aiQuick` 的意图匹配与 `scoreAiAction` 门槛（如 >200 字才建议总结），避免短文本瞎总结；内容级模式可放宽门槛以纳入更多上下文。

### 5.4 展示与沉淀
- 新增 `DailyBriefDialog`（仿 `WeekReportDialog` 组件）：
  - 上半：行为层图表（复用周报的图表组件）；
  - 下半：主题簇卡片 + 本地摘要 +（"AI 小结" / "用全文生成"按钮）；
  - 每张卡片可「存入工作区 / 加入片段库 / 忽略」；内容级小结可展开"追问"输入框。
- 日整理结果存本地表 `daily_brief`，供周报、年度报告「我的复制人生」复用为素材。

### 5.5 与现有模块关系
```
剪贴板历史 ──┐
工作区     ──┼──▶ 日整理引擎(本地聚类) ──▶ DailyBriefDialog
片段库     ──┘            │
                          ├─▶ 行为统计（喂周报 / 年度报告）
                          └─▶ ai-daily-brief（模式一 零原文 / 模式二 授权读原文）
```

## 7. 验收标准

- [ ] 用户当天复制的内容，在「今日整理」里能被聚合成可阅读的简报；
- [ ] 行为层统计**不读取任何原文**，通过 `redlineGuard` 类隐私测试；
- [ ] **内容级小结在用户授权后能产出语义级准确总结**（含具体项目 / 任务名，非仅行为描述）；
- [ ] 每次读原文前**明示授权弹窗** + 用户确认，且原文仅本次发送、不留存；
- [ ] 设置内含"允许读原文"总开关（默认关）+ 审计日志记录每次读取；
- [ ] 用户未授权时**自动降级**为行为级小结，功能不中断；
- [ ] 简报中的主题簇可一键存入工作区 / 片段库；
- [ ] 日整理结果可被周报、年度报告复用；
- [ ] 定时提醒、手动触发、随启补报三种入口均可用；
- [ ] 冷启动（当天记录 < N 条）时提示"再攒攒"，不硬出空报告。

## 8. 风险与开放问题

1. **授权合规与隐私（已决策走 B）**：产品要求内容级准确 → 采用"按需授权读原文"。落地须保证：① 每次读取前**明示**发送范围与去向 + 用户勾选同意；② 原文**仅本次发送、不留存、不进同步流**；③ 设置内含"允许读原文"总开关（默认关）+ **审计日志**可查每次读取；④ 不同 AI 提供商的数据出境合规（尤其境外模型）；⑤ 用户拒绝 / 未授权时自动**降级**行为级，功能不中断。红线②从"绝不读"修正为"默认不读、授权才读、全程可审计"。
2. **聚类质量**：纯本地关键词聚类的主题簇可能不准，是否需要轻量本地小模型（架构文档提到的"小模型"方向）？先上线规则版，AI 增强版后置。
3. **通知疲劳**：定时提醒可能被嫌烦，默认关 / 仅首次引导开启。
4. **与周报重叠**：日整理的行为统计与周报高度重合，需抽公共统计层，避免两套实现。
5. **存储膨胀**：日整理结果长期留存，需定义清理策略（如保留 90 天，或仅留统计不留摘要）。

## 9. 附：用户当前可走的"变通方案"（功能上线前）

在日整理落地前，用户可用现有能力手动凑出类似效果：
1. 一天相关碎片复制进同一**工作区**；
2. 工作区内 `Ctrl+A` 全选 → 变换面板用 `ai-summarize` 汇总成一段（即现有的"选中单条/批量 → AI 读原文"模式，已是内容级）；
3. 或导出工作区，丢给任意 AI 写"今日日报"。

> 说明：现有 `ai-summarize` 本就是"用户选中内容 → 读原文 → 总结"，已证明内容级准确可行；日整理只是把它从"手动选"升级为"自动聚类 + 一键授权读"，复用同一授权信任模型。
