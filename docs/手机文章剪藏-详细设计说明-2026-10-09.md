# 手机文章剪藏 B：详细设计说明

2026-10-09 设计，2026-10-10 实施。用户已确认推荐 B 并授权创建 PR；生产功能及验证范围见 [实施验收记录](手机文章剪藏-B实施与验收-2026-10-10.md)。本 HTML 仍是独立模拟原型，不能用它证明真实抓取和保存成功。

设计入口：[HTML 预览](../design/mobile-article-collection-2026-10-09.html)。页面中的文章、来源、图片数量和操作结果均为模拟数据，左侧场景是独立测试样例，不是实际网络环境。只有点击“粘贴链接”才请求读取浏览器剪贴板；不发起文章网络请求，不写入真实笔记。

## 1. 基线与具体变化

基于真实 `KnowledgeView.tsx / KnowledgeView.module.css`、`KnowledgeCollectionSheet.tsx / KnowledgeMaintenance.module.css`、`KnowledgeReader.tsx / KnowledgeReader.module.css` 和 `MobileSheet / MobileNotice / MobileUi`。

- 保留知识库标题、搜索、全部/常用/最近阅读、同步入口及底部页面导航。沿用 `src/styles/theme.css` 的主题令牌和现有移动端字号、48px 目标、实底圆角控件。
- “新建”新增轻面板：写笔记 / 收藏文章 / 收集图片。正式实施时原列表末尾重复图片收集入口收拢至这里，不同时保留两处同等入口；已有草稿入口继续可达。
- 原“收集内容预览”仍用于普通文字和图片。可识别的文章链接进入文章预览，同一个入口不要求用户先选多种导入类型。
- 正文预览采用可返回的全页；长文不挤进半屏表单。头部只保留返回和页面名，辅助属性默认折叠。底部一个主要动作“保存文章”，次级“仅存链接”。
- 保存后使用现有阅读器。常用、目录、分享、修改和同步沿用现有能力；阅读更多中保留原文。仅存链接页隐藏或禁用无意义的正文操作，明确原因。

## 2. 路径与返回

主路径：微信复制链接 → 知识库新建 → 收藏文章 → 粘贴 → 自动读取 → 核对正文 → 保存文章 → 本机阅读。

手动输入时按“读取文章”；粘贴后立即读取，避免多一次确认。字段失效就地说明，支持 HTTP/S 网页地址；基础收藏不依赖 AI。

系统分享带文章链接时直接进入相同预览，省去新建与粘贴。只有来源提供系统分享时才成立，不假设微信自带转发菜单支持第三方目标。

- 面板返回：先回来源步骤，关闭只退出当前面板；不会消费未完成收集。
- 读取/预览返回：回知识库，链接与用户输入单独保留，首页呈现“待收集文章 → 继续收藏”。
- 阅读返回：回知识库列表，恢复原滚动位置；保存结果不用用户手动关闭才能继续。
- 取消/返回不丢原草稿。不强制“放弃原草稿”来收藏；文章任务与普通笔记编辑分别持久化。
- 进程退出后的自动下载不是首版承诺。首版前台执行、任务持久化、重新进入恢复；暂停状态不显示“正在后台下载”。

## 3. 页面与状态

| 页面/状态 | 内容区 | 操作与回执 |
|---|---|---|
| 链接入口 | 一句来源引导、完整地址字段 | 粘贴/读取；格式失败关联字段，不弹全屏错误 |
| 正在读取 | 任务状态、正文骨架、已保留原链接 | 可返回继续处理别的任务，或明确仅存链接；不编造进度百分比 |
| 正常预览 | 标题、取得的来源、正文、折叠属性 | 保存文章；未提交前明确“尚未保存” |
| 正文失败 | 无可读正文的原因、来源链接 | 重新读取/仅存链接/查看原文，普通文字或截图补充入口 |
| 图片部分失败 | 正文先读，缺图位置保留 | 正文先保存；逐张或剩余图片补齐到原笔记 |
| 重复收藏 | 已有笔记及原备注摘要 | 查看已有笔记；无默认重复保存或覆盖正文 |
| 本机提交失败 | 保留全部预览和输入 | 保存区同时显示原因与重试；不能假成功 |
| 仅链接阅读 | 标题、来源、备注、没有本机正文的说明 | 打开原文/读取并补充正文；补充更新原笔记 |
| 正文阅读 | 本机正文、常用/目录/更多等既有能力 | 短暂保存反馈；图片完整前不声称整篇离线可用 |

普通成功信息在现有工具区上方短暂呈现，不浮盖正文，也不会关闭时让阅读位置跳回开头。部分失败提示在内容区，可滚动离开；恢复按钮与结果同域。正式版仍使用共享 Notice/Toast，不另造反馈系统。

## 4. 属性与正文边界

分类、标签、收藏原因均非必填，不强制先分类。标题可修改；空标题使用取得的标题或来源地址，不丢提交。

公众号名、作者、日期只有确实取得时显示，未知不虚构。收藏时间与文章发布时间分别记录。原链接保留必要参数；去重由可靠文章身份和最终地址支撑，不能只按标题或无差别删查询参数。

来源正文和用户备注分别存储。重新读取、补图仅更新原任务绑定的目标笔记；遇到已修改正文要选择，不自动覆盖。单张图片恢复有自己的忙碌、失败和成功反馈；失败时占位及恢复入口继续存在，成功后替换为可点击本机图片。设计稿只模拟数量变化。

## 5. 响应式与动效

- 常规竖屏：正文弹性滚动，操作区固定在页面底部并计入系统安全区，不能压住段落。
- 原型短横屏 ≥600px：正文占余下宽度，约184px窄操作区放右侧；生产版在可用高度≤500px、宽度≥520px时启用侧栏，以覆盖小横屏大字体。正文和长反馈分别滚动，操作按钮保持可达。首页延续现有侧边导航。
- 小屏与窄横屏：布局按实际可用宽高调整，不能只依据设备方向；正文与反馈可滚动，主要动作不被挤出视口。
- 大字体：正文/输入按用户字号增长，行数自然增长，按钮允许换行；不能用整体缩小 App 的办法塞入屏幕。
- 键盘出现：输入区应被移到可见范围，折叠次要属性避免正文被遮；正式实施须用现有移动视口/键盘布局能力和真机验证。
- 按压150ms、页面200ms、面板300ms，遵循既有曲线。支持减少动态效果；无常驻装饰动画、无循环进度假象。
- 本稿的手机尺寸不含系统栏，不声称真机沉浸式或状态栏已经验证。文章阅读沿用普通 App 安全区，远控的沉浸式规则独立处理。

## 6. 实施边界与验收

复用既有公开文章抓取和 Markdown 清洗的纯能力，不引入桌面弹窗编排。手机资产转为 `pp-asset:`；抓取结果需要可读正文判定和图片本地化结果报告，不能 HTTP 成功就给“全文已保存”。

验收必须覆盖正常/验证或登录/删除/断网/图片部分失败/空间不足/重复/原草稿/重新进入/本机提交回执丢失。重试绑定任务和笔记身份，成功提交后再清理待收集。

设计预览检查范围：390×760竖屏、320×568小屏、740×360短横屏、20px大字体及浅/深主题。目标是主要动作始终在手机容器中、正文不横向溢出、长反馈可滚动、面板可关闭、可仅存链接并继续补正文；这属于浏览器原型检查，不替代生产测试与 Android 真机验收。

后续稍后读、批注、电脑补全及完整后台任务调度独立规划，首版不新增这些常驻入口。
