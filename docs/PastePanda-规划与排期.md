## 3 · 还没做的

### 3.1 自动蒸馏：记录 → 知识库

> 🔴 **本节 2026-09-08 重写。** 原版结论（「不缺能力、缺供给」）是从**这台开发机的库**
> 推出来的——26 篇笔记、2 次转化、收藏 0。那是一台天天在跑测试和复制代码的机器，
> 不是产品的真实使用。**开发机数据不能用来定产品方向**，本节改用宏观判据。

#### 为什么 1:1 转笔记注定量不起来

现在的形态是**一条剪贴板 → 一篇笔记**。那不是蒸馏，是**搬运**。

一条剪贴板是个**片段**：半个命令、一段报错、一个链接。它很少自成一篇笔记。
用户要的从来不是「把这条存下来」，而是「这件事我以后要找得到」。

❗ 所以「转化率低」这个现象**未必说明知识库没用，更可能说明 1:1 这个形态没用**。
这两个结论指向完全相反的动作，别把它们混成一个。

#### 蒸馏的本质是 N:1，而聚合依据全都现成

| 依据 | 现状 |
|---|---|
| 时间窗 | `history.time` |
| 来源应用 | `history.source`，且 `SOURCE_MAP` 已归类 |
| 内容类型 | `history.content_type`，19 类已自动分好 |
| 任务分组 | 🔴 **`history.group_id` 已存在，但知识库从没用过** |
| 文本相似 | `AM-8` 的 `similar` 纯函数已落地 |

**一件都不用新建。**

#### 三条管线（按复用了多少现成东西排）

| | 管线 | 内容 | 依赖 |
|---|---|---|---|
| **P1** | **每日蒸馏** ← 先做 | 复用**已上线**的每日整理行为层（`DailyBriefDialog`）。从「看统计」变成「出草稿」：当天 N 条 → 按 `source` × `content_type` 聚成 3–5 簇 → 每簇一篇候选草稿 | 就是 §3.4 的 **G14/C3**。行为层已在跑，缺的只是内容层 |
| **P2** | 主题簇蒸馏 | 不按天、按相似度聚：「你三天里复制了 7 段关于 X 的内容，要不要合成一篇？」 | 🔴 **本格原写「依赖 AM-8 similar（已有）」，2026-09-08 当天核实为错**：`similar.rs` 是**编辑距离**做的近重复判定，专为标题/标签这类短串设计（还有 `SHORT_LEN=4` 门槛），它找的是「几乎同一个字符串」而不是「同一个主题」——拿去聚摘录只会把 `NC65` 和 `NC66` 归一组。**P2 需要一个新的相似度原语**（词重叠），不是复用 AM-8。也**不需要** O-4 切片：切片解决的是检索粒度，不是短片段聚类 |
| **P3** | AI 成文 | 用户在草稿卡上点一下，把这一簇写成一篇 | 🔴 **原写「AI 在 MCP 对话里提议」，2026-09-09 改**：走本机**已有的** AI 子系统，不碰 MCP。详见本节末《P3 详细设计》|

**为什么 P1 先做**：复用最多；而且它天然是**每天一次**的节奏，自带产出上限。

#### 🔴 三条红线

1. **不自动落库** —— 守 D13「静默不写」。永远出草稿、等采纳
2. **不做全文搬运** —— mem0 哲学：只对已有卡片抽，不把原文整段搬进去
3. **必须有产出上限** —— 每天最多 N 条草稿，**不是有多少出多少**

第 3 条是防 **Collector's Fallacy** 的唯一有效机制。Evernote / Pocket 都栽在这上面；
Readwise 的答案是 **Daily Review（限量重现）**，不是更多收集。
⚠ 靠调阈值去压产量是补丁，**产出上限才是机制**——通路#5 就是被这一条判掉的（见下）。

#### 怎么判断成不成（宏观口径，不看任何一台机器的库存量）

**看草稿采纳率，不看笔记数量。**

- 采纳率高 → 选材对，可以放宽产出上限
- 采纳率低、但忽略率也低（草稿被晾着）→ **呈现时机**不对，不是选材不对
- 采纳率低且大量被忽略 → 选材错了，回去调信号

#### P3 详细设计（2026-09-09，走本机已有的 AI 子系统）

🔴 **P3 原写「AI 在 MCP 对话里提议」。2026-09-08 我据此判断它卡在「剪贴板内容出不出本机」

2026-09-09 核实：本项目**早已有完整 AI 子系统**（`src-tauri/src/ai/`，8 个模块 4268 行），

##### 形态：草稿卡上的一个「AI 成文」按钮

P1/P2 已经把散片聚成了簇（本地词面聚类，离线、瞬时、零成本）。
P3 只做最后一步：**用户点了，才把这一簇写成一篇**。

不点 = 完全是今天的行为，一分钱不花、一个字节不出网。

##### 复用了什么（以下均于 2026-09-09 读代码核实存在）

| 要素 | 现成的东西 |
|---|---|
| 调用入口 | `aiRun(actionId, text, opts, force)` → `ok / needsConfirm / budgetExceeded` 三态 |
| 动作注册 | `src-tauri/src/ai/actions.rs` 的 `ACTIONS` 表 + `build_prompt` 分支 |
| 不进变换中心 | `INTERNAL_ACTION_IDS`（先例：`ai-kb-qa`，理由一模一样——输入是拼好的专用格式）|
| 出网闸 | `is_sensitive_for_egress`：摘录里有密钥/手机号/邮箱/身份证/IP 就先拦下来问 |
| 本地厂商豁免 | `spec.is_local()` 时跳过出网闸——**用户配的是本机模型时，P3 全程不出机器** |
| 成本控制 | `budget.rs` 预算 + `cache.rs` 缓存 + 用量日志，全部自动接上 |
| 输入上限 | `MAX_INPUT_CHARS = 8000` |

**一件都不用新建。**

##### 出网面积 = 用户已经在界面上看到的那些字，不多一个

P1/P2 拿到的摘录，在 Rust 接口层就被 `DISTILL_EXCERPT_CHARS = 60` 夹死了
（故意夹在接口层而不是 UI 层，这样未来任何调用方都拉不到全文）。
**P3 不新开取全文的口子**：发出去的就是待沉淀卡片上已经渲染给用户看过的那几行。

##### 三条红线（P3 版）

1. **必须手动触发，绝不后台批量跑** —— 后台批量 = 烧用户的钱 + 无声出网，两条都踩
2. **不自动落库** —— 模型返回的仍然是草稿，进 `openNote({title, content})`，与 P1/P2 采纳路径同一条
3. **三态必须全接** —— `needsConfirm` 要弹确认、`budgetExceeded` 要说清、`truncated` 要在界面上标出（否则用户会把「断在半句」当成模型水平差）

##### ⚠ 一个诚实的风险：60 字 × N 可能不够写出有内容的正文

6 条簇 = 360 字碎片。模型能**组织**它们，但补不出原文里没有的实质。
所以 P3 第一版的输出应当被理解为**一篇结构化的线索笔记**，不是**一篇内容完整的笔记**。

要更实的正文，唯一的办法是给 P3 单独放宽摘录长度（比如 200 字）——
**那是红线变更，见 §5 ⑪，不擅自改**。
建议：**先按 60 字做完并试跑一次真实簇**，用结果说话，而不是现在凭感觉放宽。
