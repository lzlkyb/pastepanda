## 4 · 明确不做的

> 每条一行，**不展开**。完整论证在 git 历史里（见 §7 那批文档的最后一个版本）。
> **重新提议其中任一项前，先把括号里的理由驳掉。**

### 产品范围
- 知识图谱（Obsidian 实证 >200 条变毛线团；我们年化 ~670 条，正踩在区间上）
- 图谱视图 / 自动建链 / 链接建议（同上）
- 屏幕录制 / GIF（D-2 2026-09-05 拍板：不进赛道）
- 库加密 / 文件夹锁 B3（D-8 2026-09-05 作废：工程大、个人库收益存疑。反向条件：用户真实提出加密诉求）
- 体积红线（D-5 2026-09-05 拍板不立：立了就要维护，而体积不紧张）
- 「靠数据自动学」做冷启动（D-1 2026-09-05：不砍方向，但改成「预设 + 需确认的建议」——推荐的冷启动来源从学习数据换成预设 + 内容特征，不再等 `action_events` 积累）
- 插件市场（用 MCP 代替）
- iOS / 移动端
- 块级模型
- 宠物养成 / 情感陪伴 / 聊天式对话
- 会话历史自动解析（JSONL 噪音密度高 + 抽取烧 AI + 隐私敏感）

### 存储与同步
- 纯文件 vault 作存储（只作**导出目标格式**）
- 路线 B「数据库级同步协议」（时区/墓碑/自增主键/FTS rowid/附件/冲突——**每条都是静默数据丢失点**）
- D10 云同步 / 中心服务器（opt-in 延后，不预研）
- 外部来源的反向写回（单向快照 + 幂等 upsert）
- CRDT / Yjs（收益代价比不划算）
- 哑存储 transport（**零第三方**，2026-09-07 拍板）
- 置顶（`pinned`）跨机同步（收益远小于代价，且结构未定）

### 🔴 已「关闭」但其实是接受风险的

- **MCP 安全处置（D-6，2026-09-05 关闭）**：关闭方式是**接受风险**，不是「已重置 / 已轮换」——**凭证未做任何变更**。别把它当成已处置的依据。

### 实现层
- `daily_brief` 建表（任何时候都能从 history 重算，存下来只会与源数据不一致）
- 按内容类型置顶的 UI（操作成本高，先验全局置顶够不够）
- MCP 开 daily note 写入（会撞 `idx_notes_daily` 唯一约束）
- `--amber*` token 一族（与 `--orange` 重，且摘不干净）
- 自动打标签的关键词规则扩充（格式/来源已被 `content_type` 与 `SOURCE_MAP` 覆盖；语义必须要模型）
- AM-5 篇级 R@5 口径（25 篇库里 = 返回 20% 全库，无区分度；改节级 R@10）
