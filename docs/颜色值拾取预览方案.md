# #10 颜色值拾取预览 — 设计方案

> 状态：设计已定稿，待写实施计划
> 关联设计稿：`design/color-preview.html`

## 目标

剪贴板内容如果整体就是一个颜色值（Hex/RGB/HSL），在卡片上直接显示色块预览，并支持三种格式互转复制。方便前端/设计相关用户一眼认出历史记录里的颜色，减少手动查格式转换工具的步骤。

## 范围界定（brainstorming 阶段已确认）

- **触发条件**：`trim()` 后整段内容严格匹配颜色格式才触发，不识别嵌入在大段文本/代码里的颜色值。
- **不识别 CSS 命名颜色**（red/dodgerblue 等 140 种），只做 Hex/RGB/HSL，避免英文单词误判。
- **格式互转复用现有"粘贴并变换"菜单**，不做点击色块循环切换的新交互。
- **不接入 Rust 端 content_classifier.rs**，纯前端实现，不产生新的可筛选自动标签类型。

## 架构

纯前端、零依赖，不改动 Rust 后端 / 数据库。复用项目现有两套体系：
1. `detectTextType`（`src/lib/utils.ts`）驱动的卡片图标/子类型系统。
2. `buildTransformMenu`（`src/components/ContextMenu.tsx`）驱动的"粘贴并变换"子菜单。

## 检测规则

新建 `src/lib/color.ts`，导出：

```ts
export interface ParsedColor {
  format: "hex" | "rgb" | "hsl";
  r: number; g: number; b: number; a: number; // 统一的 RGB(A) 中间表示，a ∈ [0,1]
}

export function detectColor(text: string): ParsedColor | null;
export function toHex(c: ParsedColor): string;   // #rrggbb 或 #rrggbbaa（a<1 时）
export function toRgb(c: ParsedColor): string;   // rgb(r,g,b) 或 rgba(r,g,b,a)
export function toHsl(c: ParsedColor): string;   // hsl(h,s%,l%) 或 hsla(h,s%,l%,a)
```

正则规则（均要求 `trim()` 后整段严格匹配，大小写/内部空白容错）：

| 格式 | 正则 |
|------|------|
| Hex 3/4/6/8 位 | `/^#([0-9a-f]{3}|[0-9a-f]{4}|[0-9a-f]{6}|[0-9a-f]{8})$/i` |
| RGB/RGBA | `/^rgba?\(\s*(\d{1,3})\s*,\s*(\d{1,3})\s*,\s*(\d{1,3})\s*(,\s*(0|1|0?\.\d+)\s*)?\)$/i` |
| HSL/HSLA | `/^hsla?\(\s*(\d{1,3})\s*,\s*(\d{1,3})%\s*,\s*(\d{1,3})%\s*(,\s*(0|1|0?\.\d+)\s*)?\)$/i` |

非法值（如 rgb 分量 >255、hsl 百分比 >100）视为不匹配，`detectColor` 返回 `null`，回退为普通文本。

`detectTextType`（`src/lib/utils.ts`）新增分支，位置：在现有 URL/email/file/code 判断之后、默认 fallback（返回 `"text"`）之前，新增：

```ts
if (detectColor(t)) return "color";
```

## 展示设计（对应 design/color-preview.html）

`Card.tsx` 的 `ICONS` 表新增 `color` 项。与其它固定色系图标不同，`color` 子类型的图标槽位不用 lucide `Icon`，而是渲染一个真实颜色填充的圆点（`.colorDot`，22px，圆形，白色/黑色描边保证在浅/深色背景下都有轮廓）。外层 `cardIcon` 容器背景沿用现有 `bgPurple`/`bgPink` 的配色规律——用当前颜色本身的低透明度（0.12）作为底色/边框（0.22）/内阴影，而不是写死某个固定色系，因为每条记录的颜色都不同。

`cardSub` 行新增一个小徽标（`colorFormatTag`，复用 `accent-light`/`accent` 配色，仿照现有 `cardPin` 徽标样式）显示 `HEX`/`RGB`/`HSL`，紧跟在来源应用（SourceBadge）之前。

## 格式互转

`ContextMenu.tsx` 的 `buildTransformMenu` 函数，`itemType === "text"` 分支下新增 `subType === "color"` 分支：

```ts
} else if (subType === "color") {
  children.push(
    { icon: <span className={styles.ctxTextIcon} style={{background:"...",color:"..."}}>#</span>, label: "复制为 HEX", onClick: () => onTransform("color_hex") },
    { icon: ..., label: "复制为 RGB", onClick: () => onTransform("color_rgb") },
    { icon: ..., label: "复制为 HSL", onClick: () => onTransform("color_hsl") },
  );
}
```

`Card.tsx` 的 `handlePasteTransform` 新增三个 case（`color_hex`/`color_rgb`/`color_hsl`），逻辑：`detectColor(content)` 解析出中间表示，用对应 `toHex`/`toRgb`/`toHsl` 转换后调用现有 `pasteText`。若 `detectColor` 返回 `null`（理论上不该发生，因为菜单项只在 subType === "color" 时出现），静默跳过（不弹错误 toast，容错即可）。

## 边界情况

- Alpha 通道全程保留：hex 输出为 8 位（`a<1` 时），rgb/hsl 输出为 `rgba(...)`/`hsla(...)`（`a<1` 时），`a===1` 时输出不带 alpha 的简写形式（`#rrggbb`/`rgb(...)`/`hsl(...)`）。
- Hex 3/4 位（如 `#fff`/`#0f08`）转换时先展开为 6/8 位再参与后续格式转换。
- 非法颜色值（分量超范围）不触发预览，按普通文本处理，无错误提示。

## 测试计划

`src/lib/color.ts` 是纯函数，vitest 直接覆盖：
- 检测：hex3/hex4/hex6/hex8、rgb/rgba、hsl/hsla 各自的合法与非法边界（分量越界、格式错误）、大小写与内部空格容错、非颜色文本（含代码/URL/普通句子）不误判。
- 转换：hex↔rgb↔hsl 三向互转的往返一致性（转换后再转回，数值误差在合理范围）、alpha 保留、hex3/4 展开为 6/8 位。

`detectTextType` 新增分支的现有测试文件（`src/__tests__/utils-extended.test.ts` 或 `utils.test.ts`）补充用例，确认颜色值优先于其它分支被正确分类，且不影响现有分类结果。
