## 1. P0 — 功能性破损（用户直接看不到内容 / 功能完全不可用）

### 1.1 深色主题下 tooltip 白字压白底，完全不可见
`src/components/Settings.module.css` `.sSegOpt::after`：`background: var(--text-primary); color: #fff`。
`--text-primary` 在 4 套深色主题里本身就是近白色 → 对比度 **1.13–1.27**。设置面板 5 个分段按钮的 tooltip 在所有深色主题下都是空白色块。
**修**：`background: var(--card-bg); color: var(--text-primary); border: 1px solid var(--border-color);`

### 1.2 OCR 全文面板深色主题下正文隐形
`src/components/CardList.module.css` `.ocrFullTextBody`：底色硬编码浅黄 `#fffbeb`，文字用 `var(--text-primary)`（深色主题近白）→ 对比度 **1.09–1.22**（sunset 主题几乎完全隐形）。
**修**：`background: var(--orange-bg)`（深色主题该变量已是 `#431407`，正好是同语义深色对位值）。

### 1.3 图片裁剪「还原」按钮同类问题
`.cropRestoreBtn`：`background: rgba(255,255,255,0.9)` + `color: var(--text-primary)` → 深色下 **1.01–1.08**，hover 时 `background:#fff` 更糟。

### 1.4 `--border` 变量名手滑，20 处边框静默消失
`--border-color` 被误写成 `--border`，且**无 fallback** → 整条声明失效。影响：`TopBar.module.css` 标签选择器分隔线、`BatchReplaceDialog.module.css`（×6）、`ConfigDiffDialog.module.css`（×8）、`EncodingDialog.module.css`（×4）的**全部边框**在 7 套主题下都不存在。
**修**：全部改 `--border-color`，或在 theme.css 加一行别名 `--border: var(--border-color)` 一次性兜住。

### 1.5 `--z-*` 层级令牌在独立窗口未定义，Toast/遮罩层级失效
`--z-base`…`--z-fullscreen` 只在 `app.css` 的 `:root` 定义，但 `editor-main.tsx` 和 `popup-main.tsx` **刻意不引入 app.css**（注释写明「主窗口专属」）。而这两个窗口加载的 `dialog.css`、`Toast.module.css`、`FullscreenEditor.module.css` 都在用这些令牌 → `z-index` 声明失效退化为 `auto`。全屏编辑器窗口里的 Toast 和确认框遮罩失去层级保证。
**修**：把 `--z-*` 定义从 `app.css` 移到 `theme.css` 或 `globals.css`（三个入口都加载）。

### 1.6 全应用只有 1 个 `:focus-visible`，键盘导航几乎没有焦点指示
`app.css:145-152` 的焦点样式块用的是 **kebab-case 全局类名**（`.icon-btn` `.seg-item` `.fab-btn` `.ctx-item` `.batch-btn`），但组件早已迁到 CSS Modules 的 camelCase + hash 类名 → 全部匹配不到。唯一生效的是 `CardList.module.css` 的 `.card:focus-visible`。
后果：顶栏、侧边栏、设置面板、右键菜单、对话框里 **60+ 个交互元素有 hover 但完全没有键盘焦点指示**；多处还主动 `outline: none` 且无替代（`.snippet-search`、`.inlineInput`、`.settingsSelect`）。
**修**：`globals.css` 加零特异性兜底
```css
:where(button, a, input, select, textarea, [tabindex]):focus-visible {
  outline: 2px solid var(--accent); outline-offset: 2px; border-radius: inherit;
}
```

### 1.7 快捷键设置：清除快捷键功能对 3/4 个热键完全失效
`src/components/settings/GeneralTab.tsx:775,796,817`：`value={config.sequential_hotkey || "ctrl+alt+q"}` —— 把默认值 fallback 直接烧进传给 `HotkeyRecorder` 的 prop。用户点「×」清除后，config 确实存成了 `""`，但组件立刻重新渲染出**默认组合**，看起来像没清掉。
更糟：同一个 fallback 表达式被复用在其它 recorder 的 `taken=[...]` 冲突检测数组里 → `ctrl+alt+q` 被永久视为已占用，用户想把主热键设成它会被拒绝「与其他快捷键冲突」，尽管实际没人在用。
**修**：`value={config.sequential_hotkey ?? ""}`，`taken` 数组同样去掉 fallback。

### 1.8 一个手动标签就能永久废掉一整个 AI 分类类别
`data_store/tag.rs:223-266` `ensure_auto_tags` 用 `INSERT OR IGNORE` 种入 29 个自动标签；`resolve_auto_tag_ids` 按 **name + source='auto'** 查找。而 `tags.name` 有 UNIQUE 约束。
用户手动建一个叫 `Python`（或 `代码`/`链接`/`日志`/`密钥` —— 都是种子名，都是合理的用户命名）的标签后：下次启动种子插入被 `OR IGNORE` 静默吞掉 → `resolve_auto_tag_ids(["Python"])` 永远返回空 → 之后复制的 Python 代码分类正确但**标签永远写不进去**，侧边栏「智能分类 / Python」永不出现，无日志无报错，**重启也修不回来**。
**修**：种子查找改为按 id 而非 name+source；或种子插入冲突时把已有同名标签升级为 auto。

### 1.9 空列表引导指向一个不存在的按钮
`CardList.tsx:665`：`💡 按 ? 查看所有快捷键 · 点击右上角 ❓ 打开帮助`。顶栏图标依次是 `☰` 侧边栏、收集模式、工具箱、⚙设置、分隔线、最小化、`EyeOff` —— **没有 ❓ 按钮**。新用户看到的第一个屏幕就在教他点一个不存在的控件。
**修**：文案改「点击右上角 ⚙ → 帮助」，或真加一个 `?` 按钮。

### 2.1 事务与数据一致性（Rust）

| # | 位置 | 问题 |

| 2.1.1 | `data_store/*.rs` 共 8 处手写 `BEGIN;`/`COMMIT;` | **COMMIT 自身失败时不 ROLLBACK** → 事务永久挂在共享连接上。磁盘满/SQLITE_BUSY 触发后，后续所有事务操作报「cannot start a transaction within a transaction」，所有非事务写入静默加入悬空事务并在退出时丢失，**直到重启才恢复**。`lock_conn()` 还刻意恢复中毒的 mutex，会把开着的事务交给下一个调用方。修：改用 `conn.unchecked_transaction()`（RAII 自动回滚） |

## 3. UI/UX 设计体系问题

### 3.1 对比度：跨主题严重不一致（浅色主题语义色系统性差两档）

**规律**：浅色主题的语义色用 Tailwind「500 on 100」配对（对比度 ~3.0），深色主题用「400 on 950」（~8.5）。整套浅色语义色都不达 AA。

| 项 | 实测 | 达标? |
|---|---|---|
| 侧边栏分区标题 `--sidebar-section-label` on `--sidebar-bg` | **1.80–3.71**（7 套全部） | 全部不达标，最差 blossom 1.80 |
| `--text-muted`（用于时间戳/设置说明等**正文级**信息） | 2.13–4.45 | 7 套里 6 套不达标，forest 仅 2.52 |
| 白字压 `--accent`（所有主按钮） | **2.28–4.10** | 7 套全部不达标，terminal 最差 2.28 |
| `--accent` 当文字用（激活标签页/置顶徽标/侧边栏选中） | 3.53–4.10 | 浅色三套不达标 |
| Toast 四种语义色 | 1.93–2.41 | 浅色主题全部不达标（且**没用主题令牌**，见 3.2） |
| `--green` on `--green-bg` 等语义配对 | 3.00–3.35 | 浅色三套不达标 |
| blossom 的 `--text-secondary` vs `--text-muted` | 互相对比度 **1.06** | 三级文字层级实际塌成两级，肉眼无法区分 |
| 全局 `button:disabled { opacity: .4 }` | 1.50–2.29 | 禁用态到了「看不出这里有按钮」的程度；且 `pointer-events:none` 与 `cursor:not-allowed` 互相抵消，光标和 title 提示永远不出现 |

### 3.2 令牌体系：196 条死代码 + 5 个"用了但没定义"

- **`--toast-*` 9 个变量 × 7 套 = 63 条声明从未上屏** —— `Toast.module.css` 完全绕过它们用硬编码色（正是 3.1 里不达标的那批）。精心调过的浅/深配色躺着没用，实际生效的是不适配的硬编码值。

## 4. UX 流程与信息架构

### 4.1 工作区（Workspaces）是完全不可达的功能
`AppConfig` 有 `current_workspace`/`workspaces`，每一条历史查询和计数查询都按它过滤，`SettingsDialog` 还刻意在「恢复默认」时保留它。但全仓库搜索 `workspaces`/`setWorkspace` **只有类型声明、默认值、测试、和那行保留逻辑**——没有切换器、没有增删改、设置六个分区里一个字都没提。而 README 把它列为标题功能：「🏷️ Workspaces | Isolate history per workspace」。
**修**：顶栏标题旁加一个工作区 chip（下拉列出 `config.workspaces` + 新建/重命名/删除）。后端 `fetchSidebarCounts`/`searchHistory` 已经接受 workspace 参数，约 40 行的活。或者从 README 删掉这个宣传并清理死配置。

### 4.2 片段变量语法只存在于源码注释和一个零消费者的导出里
`lib/snippetVariables.ts:19-30` 导出 `SNIPPET_VARIABLES` 并注明「用于 UI 提示/文档」，**全仓库 0 个消费者**。片段编辑框 placeholder 只是「片段内容...」，没有任何提示存在 `{{date}}`/`{{clipboard}}`/`{{uuid}}`；快速预览显示的是原始 `{{date}}` 而不是解析结果（解析只在复制时发生）。规划文档写的还是单花括号 `{date}`，实现是双花括号 —— 猜都猜不中。**这个功能实际上是死的。**

### 4.3 唯一教用户怎么建标签的那句话，在结构上永不可显示
`TopBar.tsx` 把整个标签筛选栏包在 `{allTags.length > 0 && (...)}` 里。而「暂无标签，右键卡片 → 编辑标签 来创建」这句提示位于 `TagPickerPopover` 内部——那个 popover 只能从这个被 gate 住的块里打开。**没有标签时打不开选择器，所以这句话永远看不到。** 真实创建路径是「右键 → 更多操作 → 编辑标签」，藏在子菜单一层下。

### 4.4 同一个功能四个名字
`收集模式（栈模式）`（顶栏 tooltip）/ `收集模式开关`（设置）/ `收集模式 开/关`（快捷键面板）/ `栈模式 · 剩余 N 条`（横幅标题）/ `粘贴栈`（帮助页）/ `Paste Stack Mode`（README）。用户读帮助里的「粘贴栈」无法对应到设置里的「收集模式」开关和屏幕上的「栈模式」横幅。

主题数量同样三个说法：`theme.ts` 注释说 6 套、`THEMES` 实际 7 个、tooltip 写「6种」、README 写「4 Themes: Light/Dark/Azure/Azure Dark」（这四个名字与实际 7 个 displayName 一个都不匹配）。

### 4.5 收藏 vs 置顶是同一个东西的两个名字两个图标
筛选 tab 叫 `⭐ 收藏`、侧边栏内置项叫 `⭐ 收藏`，但产生它的动作叫 `置顶` + `<Pin>` 图标 + toast「已置顶」。用户想加星标，找星星图标，找到的是图钉。

### 4.6 同一份状态两套矛盾的交互模型
`selectedTagIds` 从顶栏标签选择器进入是**多选累加**，但侧边栏「智能分类」行 `handleSelectGroup` 会先 `clearTagFilters()` 再 toggle → **静默摧毁用户在顶栏建立的多标签选择**。`sourceFilter` 同理：侧边栏点来源会连带 `setGroupFilter("all")` + `setFilterType("all")` 清掉分组和类型筛选，而顶栏下拉选同一个来源什么都不清。
用户体验：「我选了 3 个标签 + 今天，点了下侧边栏的来源，全没了。」

### 4.7 分组 vs 标签的区别 UI 上从未说明
两者都是用户创建、都有颜色、都能筛选，唯一区别是基数（一条记录只能属于一个分组 vs 可以有多个标签），而这个事实**在 UI 里一个字都没写**，且两者物理上在不同面板，选择从未被并列呈现。「智能分类」更混乱——它本质就是标签（`source='auto'`），却在侧边栏被当作第三种容器展示。

### 4.8 帮助页教的路径有 4 条是错的
`HelpTabContent.tsx` 的 `FEATURES[]` 每项带 `path`：
- 正则替换 → 写「设置 → 正则规则 → 启用」，但设置里**没有**正则规则分区（真实入口是右键 → 正则替换 → 管理正则规则…，两层子菜单深）
- 配置工具箱 → 写「工具箱 → 配置转换 / 配置对比」，工具箱只有 5 项且没有「配置转换」
- 数据导出 → 写「工具箱 → 导出」，实际在设置 → 数据管理
- 全屏编辑器 → 写「双击记录」，但只在 `double_click_action === "preview"` 时成立

**在应用内的帮助文档里，把用户往不存在的菜单里带，比没有帮助更糟。**

### 4.9 快捷键面板只能靠已经知道快捷键才能打开
`ShortcutPanel` 本身做得不错（18 行、实时读 config、自带搜索），但唯一触发方式是按 `?`。而唯一告知 `?` 存在的地方是空列表引导页脚——那个页脚在用户第一次复制后（约 5 秒）就永久消失了。之后这个面板在 UI 上完全不可发现。

另外 `Ctrl+H` 被标为「打开帮助」，但 `SettingsDialog` 每次打开都强制 `setActiveTab("general")` → 和 `Ctrl+S`（打开设置）行为完全一样，两个快捷键一个行为，其中一个标错了。`select_all_hotkey` 在面板里展示但**设置里没有对应录制器**，且 `handleKeyDown` 硬编码 `Ctrl+A` 无视配置值。

### 4.10 LAN 同步：状态是假的，最容易失败的功能给出永久乐观提示
`LanSyncPanel.tsx:83` 固定渲染「监听中 — 等待其他设备连接」，不读任何实际监听状态（`get_lan_status` 命令存在但没用），也反映不出 5007 端口被占用导致监听线程直接 return 的情况。设备列表包在 `{devices.length > 0 && ...}` 里**没有 else 分支** → 零设备时就是一片空白 + 一个绿点 + 一句永远乐观的「监听中」。用户分不清「还在找」和「坏了」。

### 4.11 空状态：主列表做得很好，其它全都不行
`CardList.tsx:589-670` 三种情况（搜索中/无结果带清除CTA/空历史带四卡引导）处理得很完整。但侧边栏的「分组」「智能分类」「来源」三个分区**空时整个消失**（连标签都不见）→ 首次运行侧边栏只有 全部/收藏/未分组，用户完全不知道后两个分区将来会出现、是什么。`TagEditor`「暂无标签」、`Timeline`「暂无记录」、`TransformHub`「此内容暂无可用变换」、`ConfigDiff`「无数据」全是光秃秃的标签没有下一步。

### 4.12 首次运行提示总共只有 4 条
`useFirstTimeTip` 是个裸 localStorage set（无锚定、无定位，只触发 toast）。全部调用点：`first_copy`、`seq_paste_tip`（还要等安装满 3 天）、`hide_window`、`MdAssocBanner`。**分组、标签、栈模式、片段库、片段变量、OCR、变换中心、图片置顶、LAN 同步、工作区、工具箱全都没有任何引导。**

## 5. 已有功能的完备性缺口

### 5.1 批量操作：后端全齐，前端没接线
`move_to_group(ids[])`、`add_item_tags(ids[], tagIds[])`、`remove_item_tags(...)` 全部按数组设计、有单测、前端 API 也封装好了，但**除测试外零调用者**。批量栏（`CardList.tsx:690`）只有 全选/合并复制/导出/对比/删除 —— 规划文档明确画了的「移动到分组 ▼」「添加标签 ▼」都没做。批量置顶键盘能用（Ctrl+D）但栏里没按钮。`reorder_groups` 同样只有测试引用，侧边栏完全没有拖拽 handler。

### 5.2 标签系统：根本没有管理界面
`update_tag`/`delete_tag` 后端+前端 API 都在，唯一调用点是单测。用户一旦建了错别字标签或选错颜色，**既不能重命名、不能改色、也不能删除**，只能永久留在列表里。`SidebarCounts` 已经返回每个标签的使用计数，但 `TagEditor` 不显示，也没有「清理 0 引用标签」。

### 5.3 数据可移植性（最薄弱的一环）
- **导入丢掉全部标签、留下悬空 group_id**：导出的 `HistoryItem` 包含 tags 和 group_id，但 `import_history` 的 INSERT 只写 13 列，**完全忽略 `item.tags`**，也不创建缺失的分组。帮助页教的迁移路径（导出 JSON → 新电脑导入）必然丢掉所有标签。
- **「数据导出」其实只是「历史记录导出」**：CSV/XLSX 只有 6 列（连分组都没有）。分组表、标签表、片段库（只有导出无导入）、自定义正则规则、主题与全部 config 都不在任何导出范围。
- **没有一键备份/恢复**，FAQ 直接让用户手动备份 db 文件。
- **图片/文件资源不随导出走**，FAQ 自己承认要手动迁移 → 图片类历史实际不可迁移。
- 导入无冲突策略（`INSERT OR IGNORE` 静默跳过）、无「将导入 N 条其中 M 条已存在」预览。

### 5.4 AI 智能分类
- **单标签互斥**：每条规则命中即 `return`，最多两个标签。含链接的 Markdown、含邮箱的日志都只拿到一个标签，与「标签多对多」的数据模型定位矛盾。
- **所有单值识别都是 `^...$` 全文锚定**（EMAIL/PHONE/COLOR/FILE_PATH/URL）→「联系我 zhang@x.com」被判纯文本，带一句说明的 URL 不打链接标签。用户对「智能分类」的第一直觉就是「内容里含链接就该标链接」。**这是投入产出比最高的一条修复。**
- **历史记录无法重新分类**：分类只发生在捕获时，没有 reclassify 命令。版本升级新增类别（Markdown/HTML/配置子格式都是后加的）后，存量记录永远拿不到新标签。
- **分类规则不可扩展**（29 个自动标签是硬编码常量），而**正则替换规则是可自定义的** → 用户会自然预期分类具备同等能力。
- 明显缺失的开发者高频类别：IP/MAC、Unix 时间戳（应用内置了时间戳↔日期变换却不识别）、UUID、XML（有 HTML 无 XML）、diff/patch、身份证/银行卡（未实现的「内容脱敏」也依赖这两个）。
- **前后端颜色识别口径不一致**：前端 `color.ts` 支持 140 种 CSS 命名色，后端 `classify` 只认 hex/rgb/hsl → 复制 `dodgerblue` 有色块预览但没有「颜色」标签。
- 图片/文件不参与分类，已有的 OCR 文本不拿去分类（截图里是代码/链接/表格极常见）。

### 5.5 局域网同步
- **只广播新复制，没有历史回填**：纯 UDP 组播 fire-and-forget，首次配对时两端既有历史互不可见，也没有「同步全部历史」动作，断线期间错过的条目永久丢失。用户配对成功后第一个问题就是「我另一台机器上的东西呢」。
- **文件同步只传路径不传内容**，目标机上路径通常不存在 → 打开必失败。而帮助页明确宣传「同步文本/图片/文件」。
- 图片超 2MB 静默丢弃，发送端完全无感知。
- **标签/分组/置顶不同步，且 workspace 被硬编码成"默认"** → 用户在「工作」工作区时同步来的条目落在「默认」里，看起来像同步失效。
- 设备列表每项固定显示「在线」（`last_seen` 就在手边可判），map 只增不淘汰，没有「移除设备/取消信任」。
- 无同步方向控制、无内容过滤 → **密码管理器里复制的明文密码会被自动广播给所有配对设备**。

### 5.6 片段库
- **有导出无导入** → 换机迁移链断裂（`add_snippet` 后端已具备，接个读文件循环即可）。
- 缺交互式变量 `{{input:提示语}}`（粘贴时弹框填值）、`{{cursor}}` 光标定位 —— 「模板」类功能用户对填空式变量的预期几乎是默认项。
- **零内置模板**（规划的 Git commit / 邮件签名 / 时间戳 / UUID / 随机密码 一个都没有），新用户打开是空列表。
- 片段分类硬编码 5 个（`["API","SQL","配置","模板","命令"]`），不能自定义，且与主标签系统完全平行不互通。
- **无全局热键唤出片段选择器** → 窗口驻留托盘时片段功能完全不可达，而「一键插入并粘贴」恰恰是主场景。
- 批量模式只能删除，不能批量改分类；「导出」导出的是全部而非选中项。

### 5.7 搜索/筛选
- 只有 all/today/7天/30天，**无自定义日期范围**，「上个月那条」无法定位。
- 标签筛选只有 AND（`every`），**无 OR、无排除**。
- 组合筛选缺可视化面包屑（逻辑正确但 UI 上没有「当前在【分组X】+【标签Y】内搜索」的提示，空态只给「清除全部筛选」）。
- 无保存筛选/智能分组（侧边栏已有 builtin/user/auto/source 四个分区，加「已存视图」是自然延伸）。
- 主列表没复用 `DeepCleanDialog` 已有的「时间×类型×来源」组合条件 + 实时计数能力。

### 5.8 统计面板
- **完全没有「粘贴/使用」维度**：history 表只记复制时间，无 `paste_count`。规划里的「粘贴次数趋势」「最常复制 Top 10」都无数据支撑。反差是**片段库有 `copy_count`/`last_used_at`** —— 用户最想知道的「我在重复复制什么」答不了。
- 趋势固定 7 天（规划要求 30 天），来源只 Top 5（规划 Top 10）。
- `SidebarCounts` 已经算好了 group/tag 计数，仪表盘完全没用。
- 统计与清理不联通（能看出某来源占 60%，但没有「一键清理该来源」跳转，而 DeepClean 支持按来源清理）。

### 5.9 数据生命周期
- **自动清理无预警且刻意不可撤销**（`auto_cleanup.rs` 注释明确「不写撤销栈」）。用户把保留天数从 30 改成 7，下一小时静默删掉一批，Ctrl+Z 救不回。而 `count_expired_history` 命令已存在（手动清理正用它显示计数+确认框），**改天数时不做同样的二次确认**。
- 只有按天清理，**没有条数/体积上限策略**（`max_history` 只在一个单测里出现，后端无强制逻辑；`db_size_kb` 有展示无阈值告警）。
- 清理粒度不含分组/标签 → 用户手工整理过（打标签、归组）的条目仍会被按天清掉，只有置顶能豁免。

### 5.10 撤销覆盖面
`undoStack: HistoryItem[][]` 的类型本身就限定了范围。以下全部**不可撤销，且多数连确认框都没有**：

| 操作 | 确认框 | 可撤销 |
|---|---|---|
| 删除分组 | ❌ | ❌ |
| 删除标签 | ❌ | ❌ |
| 删除片段 | ✅（文案写明不可撤销） | ❌ |
| 分组/标签 重命名·改色 | ❌ | ❌ |
| 移动到分组 | ❌ | ❌ |
| 覆盖式改标签 | ❌ | ❌ |
| 自动清理 | ❌ | ❌（刻意） |

## 6. 可规划的新功能

按「投入产出比 × 与现有能力的契合度」排序。

### 6.1 强烈建议（补齐核心体验）
| 功能 | 理由 | 依托的现有能力 |
|---|---|---|
| **粘贴使用统计** | history 表加 `paste_count`/`last_pasted_at`，解锁「最常用 Top N」「智能排序（高频靠前）」「统计面板粘贴趋势」三个功能。片段库已有同样字段可参照 | 片段库的 `copy_count` 模式 |
| **一键备份/恢复（含图片资源）** | 现在导出丢标签丢分组丢图片，等于没有真正的迁移能力。打包 db + images 目录为 zip | 已有 export 命令框架 |
| **标签管理面板** | 后端 CRUD 全齐，只差一个设置页 Tab | `update_tag`/`delete_tag` + SidebarCounts 计数 |
| **保存的筛选视图（智能分组）** | 「来源=VSCode + 标签=SQL + 近7天」存成侧边栏一项。侧边栏已有四分区结构 | 现有筛选管道 |
| **自定义日期范围筛选** | 「上个月那条」是真实高频需求 | Timeline 组件已按日期分桶 |

### 6.2 值得做
| 功能 | 说明 |
|---|---|
| **交互式片段变量** `{{input:xxx}}` / `{{cursor}}` | 模板功能的默认预期，纯前端 |
| **内置模板包** | Git commit / 邮件签名 / UUID / 随机密码 / 时间戳，降低片段库空状态门槛 |
| **片段库全局热键** | 托盘驻留时的主场景，现在完全不可达 |
| **用户自定义分类规则** | 正则替换已经可自定义，分类却硬编码 —— 补齐一致性 |
| **历史重新分类命令** | 让升级后新增的类别能应用到存量数据 |
| **LAN 同步历史回填** | 需要 TCP 拉取 + 差异协议，工作量较大但是「配对后第一个问题」 |
| **LAN 同步内容过滤** | 排除敏感内容/指定来源不同步（当前密码明文会被广播） |
| **剪贴板内容脱敏** | 规划里已有（功能 #8），依赖分类器补上身份证/银行卡识别 |

### 6.3 可选（差异化）
- **OCR 文本参与分类**：截图里是代码/链接/表格极常见，OCR 结果已经有了，白扔。
- **图片相似度去重**：连续截图大量近似图片，现在按 MD5 只能去完全相同的。
- **粘贴目标应用感知**：记录「这条内容通常粘贴到哪个应用」，粘贴时智能排序。
- **内容过期提醒**：验证码/临时链接类内容标记短时效，到期提示清理（分类器已能识别密钥类）。
