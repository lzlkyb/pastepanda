## 试用

### 首次显示问题修复

桌面试用发现开启后复制图片、截图仍不显示绳子：统一事件中 `HistoryItem.item_type` 序列化为 `type`，原监听器却读取 `item_type` / `itemType`，把真实图片事件忽略。现在复用 `HistoryItem` 反序列化协议，测试使用生产 `ClipboardChanged` 序列化器生成输入。另一处启动问题是隐藏 WebView 等待两帧后才回报 ready，而原生窗口等待 ready 才显示；现在 DOM 初始化完成即握手，不依赖隐藏窗口的动画帧。

- 图片事件用例：修复前解析结果 `None`，期望 `Some("capture-1")`，1 条失败；修复后包括图片、文字与非法输入过滤在内的 6 条 Rust 用例通过。
- 隐藏窗口用例：禁止派发动画帧，修复前 ready 超时，1 条失败；修复后 ready 正常完成，18 条相关前端回归通过。
- 类型、ESLint、UI 阻断检查及前端生产构建通过。取证日志保存在 `.cache/clothesline-event-{red,green}.log`、`.cache/clothesline-hidden-red.log` 与 `.cache/clothesline-visibility-green.log`。桌面 dev 自动编译后重新启动。

此修复不自动补挂之前被忽略的历史图片，需在更新后的 dev 中新截图或新复制一张图片触发。

## 实机仍需核对

### 图片预览展开与外部关闭

预览打开时以照片位置为起点，用 300ms 位移、等比缩放与淡入展开；系统减少动态时即时显示。点预览内部保持，点外部关闭；原生窗口点穿透桌面时由已有前台切换事件关闭，并把焦点交给实际点击的底层窗口，不增加全局鼠标轮询。绳层隐藏、关闭或卸载都清理预览动画与原图 DOM，晚到的读取结果不会重新打开。展开结束刷新最终矩形的原生命中区域，避免命中仍停在动画第一帧。

### 从绳上连续拖入应用

- 主路径：先让目标输入区露出来，回桌面按住绳上照片，拉离绳带后保持按住，直接拖到输入区松开。目标未露出时可用 Alt+Tab 切换；任务栏拖动唤起取决于 Windows 版本。空白桌面松手只落成原尺寸贴图，禁止向桌面复制文件。
- 次路径：原尺寸贴图顶部「拖入应用」手柄再次交付；图片本体继续用于移动位置。太小而无法容纳手柄的原尺寸贴图仍可右键复制。
- 不承诺某个聊天客户端一定接收：接收格式由对方决定；成功文案是「图片已交给应用处理」，不等同于发送消息。拒绝、取消和失败保留贴图，右键复制可备用。
- `pinned_transfer.rs` 封装 OLE、数据对象、原图快照和缩略反馈；`pinned_transfer_ui.rs` 统一手柄绘制与 DPI 命中。贴图线程交接前释放原捕获，不跨 DoDragDrop 重入循环持有 WindowState 引用。关闭窗口通过取消标记终止交付，HWND 代际校验保留。
- 交付期间绳层保留桌面画面，独立交付计数关闭命中；原生 HWND 暂停接收输入，让出 OLE 接收区。进入其它应用仍由原来的桌面门控隐藏；截图继续使用独立隐藏计数。原生显示兜底在交付期间不能提前亮出大贴图挡住输入区。
- 红绿证据：`.cache/clothesline-continuous-red.log` 中「拉离后应立即交接」失败，其余两条已通过；修改后 `.cache/clothesline-continuous-green.log` 全绿。最终 42 条相关前端回归见 `.cache/clothesline-transfer-regression.log`；5 条原生格式/取消/DPI 测试见 `.cache/clothesline-transfer-native.log`。

类型、ESLint、UI 阻断和 diff 检查通过；浏览器模拟一次拖入及拒绝回退已验证。Tauri dev 自动编译更新，无安装包构建或版本递增。Rust dev 重编会清空内存中的绳上会话，验证时需重新采集一张图片。真实微信、企业微信、任务栏唤起、混合 DPI 跨窗口交付尚未通过自动化实机手势验证。

### 2026-10-13 加载与取下连续性修复

- 冷启动先读样式、设置照片尺寸和绳形，再回报窗口就绪；不再等待所有缩略图，也不在首次恢复时播放挂入动画。缩略图逐张解码后替换同尺寸占位，单张失败提供重试，不拖住整条绳。
- 缩略图及原图预览读盘/编码移至后台；缩略图最多两个解码任务。Windows 缩略图复用现有优化卷积模块，仍用 Lanczos3；其它平台保留原路径，不引用 Windows 专属依赖。缓存用源文件纳秒时间及长度寻址，复用原子写入工具，防止并发读取半张图片。
- 连续取下分为准备与接管两步。浏览器在原图解码、独立快照及 OLE 数据准备期间保留捕获，照片继续跟手；原生贴图 STA 准备完成才确认，再释放捕获并启动交付。准备期间松手只落成原尺寸贴图，取消立即归绳，晚到窗口关闭且恢复原照片顺序。
- 拖动起止即同步原生命中状态，避免移出旧区域失去拖动、松手后整屏仍挡住底层应用。交付结束重置命中采样并刷新绳形；短拖动也能恢复点击。禁用 HWND 的依据见 [Microsoft WindowFromPoint 文档](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-windowfrompoint)：该查询跳过 disabled 窗口；实际聊天客户端的接收兼容性仍需实机验收。
- 准备期间跨屏松手记录当时的指针位置，经桥接统一换算为物理坐标，按目标显示器工作区钳位置；不使用绳层的源屏幕，也不读取准备结束后已移走的鼠标位置。
