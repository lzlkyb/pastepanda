## 🥇 Tier 1：强烈建议（v6.2 核心 · AI / 协议方向）

### F1. **剪贴板知识图谱**（graphify 思路）

**用户场景**：
> 用户 1 年下来剪贴板有几万条历史，**全是死数据**——搜不到关联。
> 同一个项目复制过 5 个 URL、3 段代码、1 张架构图，**用户根本想不起来这里还有**。
> 想要"找出去年做那个 Spring Boot 项目时复制过的 Redis 配置"——现在只能模糊搜，搜不到。

**功能**：

- **复制时自动打 tag**：
  - URL → 域名 + 标题（HTTP HEAD 拉 `<title>`，缓存避免重复请求）
  - 代码 → 语言 + 关键函数名（tree-sitter 或正则）
  - 图片 → OCR 文字 + 主题标签（复用现有 OCR）
  - 文件路径 → 父目录 + 文件类型
- **节点之间建边**：
  - **同项目**（基于本地 cwd 检测，最近 1 分钟内复制的归一组）
  - **同时间窗口**（5 分钟内复制的归一组，类似 Paste 临时工作区）
  - **同关键词**（NLP 简单分词后共享 token 关联）
- **UI**：左侧历史列表（已有）+ 中间**图谱视图**（react-force-graph 或 d3-force）
- **搜索升级**：从"全文匹配" → "语义关联"——查"Redis"自动引出"去年那个 config + 同一会话的相关 URL"

**实现路径**：

```text
后端：
  src-tauri/src/tagging/
    mod.rs           // 暴露给 commands
    url_tagger.rs    // HEAD 标题抓取（reqwest + 缓存）
    code_tagger.rs   // tree-sitter-rust 复用（也可正则 fallback）
    path_tagger.rs   // 路径解析
    clustering.rs    // 时间窗口 / cwd 分组
  src-tauri/src/commands.rs
    add_history 后自动调 tagging::tag(item) -> tags: Vec<String>
    新增 get_graph(center_id, depth=2) -> {nodes, edges}
  src-tauri/src/data_store.rs
    history_items 加 tags JSON 字段
    新增 edges 表 (from_id, to_id, relation, weight)

前端：
  src/components/GraphView.tsx   // react-force-graph-2d（~50KB gzipped）
  src/stores/appStore.ts
    graphSlice: {nodes, edges, centerId}
  src/components/CardList.tsx
    卡片右下角加 tag chip 列表
```

**复用**：
- `data_store.rs` 已有的 history_items + `add_history` 入口
- `clipboard_monitor.rs` 已有的 cwd 上下文（如果还没存，建议顺手补）
- OCR 模块（`src-tauri/src/ocr/` 或类似）已有的图片文字识别

**不做的**：
- ❌ **不接 LLM 做实体识别**——成本高、慢、不可预测，规则 + 缓存够用
- ❌ **不做语义嵌入向量**——SQLite FTS5 + tag 关联够覆盖 95% 检索需求
- ❌ **不做图谱导出 / 分享**——v1 私域使用

**竞品证据**：
- graphify（99k ⭐）：把代码库转知识图谱的思路被验证
- Maccy / CopyQ：都没有知识图谱，**这是空白**

**开发量**：4 周
- 第 1 周：tagging 后端（4 个 tagger + clustering）
- 第 2 周：SQLite schema + 数据迁移 + get_graph 命令
- 第 3 周：GraphView 组件 + 卡片 tag chip
- 第 4 周：搜索升级 + 测试 + 性能压测

**用户收益**：⭐⭐⭐⭐⭐（**形成壁垒**——剪贴板从流水账升级为个人知识库，市场空白）

### F2. **粘贴体积优化器**（caveman 思路）

**用户场景**：
> AI 把 50KB 的 stacktrace 复制进来 → 调 AI 工具再发出去 → 50KB 又走一遍。
> AI 把 100 行 JSON 复制 → 用 JSON.stringify 后再粘贴 → 多 30% 字符。
> 大日志、序列化数据：**粘出来不必要那么"完整"**。
> 直接花用户钱（API 费用）+ 花时间。

**功能**：

| 触发条件 | 优化策略 |
|---|---|
| 文本 > 10KB | 自动折叠（头 200 字符 + `… [省略 N 字符] …` + 尾 200 字符） |
| JSON > 5KB | 解析后按字段路径剪裁，保留关键字段，丢弃 `metadata`/`debug`/`__v` 等 |
| 代码 | 检测重复行，连续重复 3+ 行折叠成 `# ... ×N` |
| HTML | 转 Markdown 再贴（去标签噪声，省 60-80%） |
| Base64 长串 | 检测出"很可能是图片"，转存文件，贴 `![文件名](path)` |
| 多行日志 | 去重连续相同级别日志（`INFO ... INFO ... INFO` → `INFO ×3`） |

**UI 反馈**：
- 粘贴前弹窗"压缩了 X% 字数（约 N 字符），是否采用？"
- 设置开关：自动采用 / 每次询问 / 不压缩
- 历史里**保留原始版本**，压缩版本作为新条目单独存

**实现路径**：

```text
后端：
  src-tauri/src/optimizer/
    mod.rs
    detector.rs      // 检测类型（JSON/HTML/code/log/...）
    compressors/
      json_trim.rs   // jq 风格的字段剪裁
      html_to_md.rs  // pulldown-cmark 或 html2md
      log_dedup.rs
      code_fold.rs
      base64_to_file.rs
    pipeline.rs      // detect → compress → 报告 savings
  src-tauri/src/commands.rs
    新增 optimize_for_paste(text) -> {original, compressed, ratio, type}
    paste_text 之前调用

前端：
  src/components/PasteConfirmDialog.tsx  // "采用压缩版本？"弹窗
  src/components/SettingsDialog.tsx
    新增 "粘贴优化" 卡片
```

**复用**：
- `paste_engine.rs` 入口（优化器作为 paste 前的可选步骤）
- 现有"敏感内容屏蔽"正则（**先屏蔽后优化**，避免 API key 折叠后被 AI 误读）
- `data_store.rs` 已有的"原始/压缩"双存模式（参考之前 v6.0 设计的 0/1 标志位）

**不做的**：
- ❌ **不接 LLM 做"智能压缩"**——规则 + 简单算法够用，0 延迟
- ❌ **不做 Markdown→HTML 反向**（单向够）
- ❌ **不做截图→图片重新编码**（已有 OCR 链路）

**竞品证据**：
- caveman（95k ⭐）：AI 客户端省 token 是热门方向
- Text Workflow for Mac：已有"压缩空白/去重行"基础版

**开发量**：2 周
- 第 1 周：5 个 compressor + detector
- 第 2 周：UI 弹窗 + 设置 + 集成 paste_engine

**用户收益**：⭐⭐⭐⭐（**直接省钱 + 省时间**，且每次复制都能用）

### F3. **AI 上下文桥（MCP server）**（cc-bridge 联动）

**用户场景**：
> 远程 Claude Code 接入（cc-bridge 已有 17 个工具）→ 用户复制本地文件内容 → AI 必须**重新调 `read_files` 一次**才能用。
> 等于**剪贴板的数据没传到 AI**，白白浪费一次文件读 + 一次往返。

**功能**：

- PastePanda 后端**实现一个 MCP server**（Streamable HTTP，绑 `127.0.0.1:<随机端口>`）
- 暴露工具：
  - `pastepanda_get_recent(n=10, since=timestamp)` → 最近 N 条
  - `pastepanda_search_history(query, limit=20)` → 搜索（拼音/全文/regex）
  - `pastepanda_get_item(id)` → 单条详情
  - `pastepanda_get_today_context()` → 最近 1 小时 + 同一 cwd 的所有项
- cc-bridge 客户端（已经在 v2.3.13 升级了 MCP 2026-07-28）**自动检测 PastePanda MCP server** → 注入到每个 Claude Code 会话的 system prompt：

```text
用户剪贴板上下文（来自 PastePanda）：
- [10:23] 用户复制了 /src/foo.rs 第 45-60 行
- [10:25] 用户复制了"TypeError: cannot read property 'map' of undefined"
- [10:30] 用户复制了 https://github.com/anthropics/...
```

- AI 引用时自动加 `[来自剪贴板历史 #1234]` 标记 → 用户回头能在 PastePanda 里找到原文

**实现路径**：

```text
后端：
  src-tauri/src/mcp/
    mod.rs
    http.rs          // axum + Streamable HTTP transport
    tools/
      get_recent.rs
      search_history.rs
      get_item.rs
      get_today_context.rs
  src-tauri/src/lib.rs
    启动时随机端口，spawn MCP server
    端口写到 ~/.pastepanda/mcp-port.json
  src/components/SettingsDialog.tsx
    "AI 集成" Tab 显示端口 + 提供"复制 URL 到 cc-bridge"

cc-bridge 端（独立 PR）：
  desktop/src-tauri/src/mcp/client/auto_discover.rs
    启动时扫 ~/.pastepanda/mcp-port.json → 自动连 PastePanda
  desktop/src/lib/systemPrompt.ts
    会话开头注入"剪贴板上下文"块
```

**复用**：
- cc-bridge 已有 2026-07-28 双协议适配经验（避免重复踩坑）
- PastePanda 现有 SQLite 历史查询逻辑（`get_history` / `search`）
- 现有"敏感内容屏蔽"规则（**MCP server 也必须过滤 API key**）

**不做的**：
- ❌ **不做"AI 主动写入剪贴板"**（v1 只读，安全性更好）
- ❌ **不做云同步**（沿用项目"本地优先"原则）
- ❌ **不做双向通知**（v1 够用，订阅机制 v2）

**竞品证据**：
- **市场空白**：CopyQ / Maccy / Ditto 都没做 MCP
- MCP 2026-07-28 让 server 端实现门槛降低（无状态化）
- cc-bridge 已升级，可直接消费

**开发量**：1 周（在 PastePanda 这边）；cc-bridge 端再 1 周
- 第 1 周：PastePanda MCP server + 4 个工具 + 端口注册
- 第 2 周（cc-bridge 端）：自动发现 + system prompt 注入

**用户收益**：⭐⭐⭐⭐⭐（**两个 NAS 项目联动**，市场唯一）

## 🥈 Tier 2：可做（v6.1 顺手 · AI / 协议方向 · 1 周内）

### F4. **剪贴板统计**

## 🧠 Tier 4：设备端小模型（必做 3 + 待观察 2 + 已砍 1）

> **来源核实**：2026 年设备端 LLM 生态**已成熟**（GitHub 直查核实）：
> - `ggerganov/llama.cpp` **122k⭐** —— 事实标准，C/C++ 推理，CPU/Metal/CUDA/ROCm/Vulkan 全支持
> - `jmorganca/ollama` **177k⭐** —— 本地 LLM 一键装
> - `openai/whisper` **106k⭐** —— 语音转文字
> - `tesseract-ocr/tesseract` **75k⭐** / `PaddlePaddle/PaddleOCR` **86k⭐** —— OCR 引擎
> - `mem0ai/mem0` **62k⭐** / `supermemoryai/supermemory` **28k⭐** —— 2026 AI Memory 路线
>
> **核心原则**：**小模型 ≠ 零成本**。本地推理的"成本"是用户耐心（启动 3-30 秒）+ 内存占用（200-800MB）+ 模型下载（国内 1GB 模型 ~10 分钟）。所以**只做"必须本地"的场景**，其余交给云端。
>
> **分发策略**（混合）：
> - **< 100MB → 内置**（嵌入/分类/NER）
> - **100MB-2GB → 按需下载**（代码/翻译/whisper），首次用时弹窗引导
> - **> 2GB → 只接 Ollama**（让用户自己装），绝不内置

### C7. **AI 记忆层**（⭐ 必做 · 2 周 · 长期壁垒）

**用户场景**：
> 复制了 1000 条内容，半年后想回忆"我 3 月份是不是研究过 Rust 异步运行时" → 不用翻历史 → AI 自动把历史压成 **"长期记忆摘要"**：你研究过 Rust Tokio / 用 Claude Code 改过 bug / 复制过 3 个 GitHub repo URL……

**功能**：
- **后台定时任务**：每周末（默认周日 21:00）自动跑
- **触发条件**："本地最近 7 天 ≥ 100 条" 才触发（避免空跑）
- **生成摘要**：把最近 N 条历史（已过滤敏感内容）喂给云端 LLM → 生成 200-500 字"用户记忆摘要"
- **存到 SQLite** 新表 `memories`（id, summary, period, generated_at, source_item_ids）
- **前端"AI 记忆"标签页**：按时间倒序显示，可点击展开原始历史
- **自然语言查询**：「你 3 月研究过 Rust 吗？」 → LLM 在 memories 表里搜 → 给出引用

**实现路径**：

```text
后端：
  src-tauri/src/memory/
    mod.rs
    summarizer.rs       // 调云端 LLM 压缩历史
    scheduler.rs        // tokio 定时任务
    query.rs            // 自然语言查 memories
    filter.rs           // 敏感内容屏蔽（API key / 邮箱 / 身份证）
  src-tauri/src/data_store.rs
    新增 memories 表 (id, summary TEXT, period_start, period_end, source_ids TEXT, generated_at)
  src-tauri/src/commands.rs
    新增 query_memory(question) -> Answer
    新增 force_summarize_now()
    新增 list_memories(offset, limit)

前端：
  src/components/MemoryView.tsx
  src/components/SettingsDialog.tsx
    "AI 记忆" Tab：开关 + 频率 + 摘要长度
```

**复用**：
- 现有 SQLite 历史表（聚合查询）
- 现有敏感内容屏蔽正则（v6.0 已规划）
- 现有 C1 的 AI 配置（API Key / 模型）

**关键决策**：
- ⚠️ **摘要前先过滤敏感内容**（API key / 邮箱 / 身份证 / 手机号）
- ⚠️ **摘要触发条件**："本地最近 7 天 ≥ 100 条" 才触发
- ⚠️ **每日预算从 C1 的 dailyBudgetUsd 共享**
- ❌ **不做"实时每条都摘要"**（太贵）
- ❌ **不做云端记忆同步**（隐私第一）

**参考实现**（借鉴 `mem0ai/mem0` 设计）：
- **L0/L1/L2 三层**：原始 history_items → 7 天聚合摘要 → 月度核心记忆
- **冲突解决**：新摘要 vs 旧记忆 → LLM 判断"更新/合并/保留"
- **可删除**：用户可标记某条记忆"这条不准确" → 加权重，下次摘要时倾向忽略

**用户收益**：⭐⭐⭐⭐⭐ — **从"剪贴板工具"升级为"个人知识助手"**，长期留存大增。

| 不记录 | 完全跳过（现状已有） | 临时密码、一次性 token |
| **加密记录、默认遮罩** | 密文落盘，默认不显示 | API key、客户资料、私人密钥 |
| 普通记录 | 明文（现状） | 普通文本、URL、代码 |

- 加密字段：`history.encrypted_payload`、`history.preview_mask`、`history.encryption_version`
- 密钥来源：
  - Windows：DPAPI（`CryptProtectData` / `CryptUnprotectData`）
  - macOS：Keychain Services
  - Linux：Secret Service（D-Bus）
- **解密只发生在内存**，搜索索引不存敏感项明文
- 敏感项默认不参与导出、LAN 同步、AI、通知预览
- 提供"立即清除内存明文"操作
- 历史标签变更后**后台重新对齐加密状态**（借鉴 Tiez 的 `sensitive_align`）

**实现路径**：

```text
后端：
  src-tauri/src/security/
    mod.rs
    encryption.rs        // 跨平台抽象（Windows DPAPI / Keychain / Secret Service）
    history_class.rs     // 数据模型：normal / sensitive / secret
    aligner.rs           // 后台对齐 worker
  src-tauri/src/data_store.rs
    history_items 表结构迁移：encrypted_payload BLOB, preview_mask TEXT, encryption_version INT
  src-tauri/src/lib.rs
    添加 encryption 初始化 + 启动时迁移未加密历史
  src-tauri/src/commands.rs
    新增 unlock_sensitive(scope) / lock_sensitive() / wipe_memory_plaintext()

前端：
  src/components/SensitiveBadge.tsx
    卡片角标显示 🔒 加密
  src/components/UnlockDialog.tsx
    查看敏感项时弹解锁（二次确认）
  src/components/settings/PrivacyTab.tsx
    三档策略切换 + 默认遮罩开关
```

**复用**：
- 现有密钥识别（`src-tauri/src/content_classifier.rs:531 is_secret`）
- 现有密钥遮罩（`src/lib/secret.ts`）
- 现有 LAN 加密基础设施（AES-256-GCM，`lan_sync.rs`）

**关键决策**：
- ✅ Classifier 只决定**建议等级**，用户可覆盖
- ✅ 加密数据**永不进搜索索引**（除非解锁后内存索引）
- ❌ **不照搬** Tiez 的 GPL-3.0 实现代码（clean-room 重写）
- ❌ 不在 Tauri capabilities 里给敏感数据非必要权限
- ❌ 不做"自动备份加密历史到云端"

**反证 / 边界**：
- Tiez 非 Windows 分支曾回退明文 → 不能照搬；必须使用三平台原生接口
- "强密码"启发式会误判构建 ID、license key、同前缀长文本 → 只能建议分类，不能默认破坏性丢弃
- 加密历史一旦忘记系统登录密码就**无法恢复**（必须文档化）

**用户收益**：⭐⭐⭐⭐⭐ — 让"敏感内容保护"从"一刀切丢弃"升级为"分层存储"。
