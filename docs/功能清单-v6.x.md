### 这张表里最值得记住的一条规律

**M1/M3/M5/C2/C6 五条原本都计划上模型（本地 GGUF/ONNX 或云端 LLM），实际全部用
本地规则 + 现成引擎解决了**，且效果够用、成本为零、体积为零（exe 现 8.35MB）。

这不是巧合。写 backlog 时容易把“上模型”当成能力的同义词，而实际开发时会发现：
**很多需求的 80% 可以用规则拿到，剩下 20% 才需要模型——而那 20% 往往不值一个 250MB 的依赖。**
下面 §2.3 砍掉 M4/M6 用的就是同一条理由。

## 3. 仍然值得做（7 条，已按 AI 路线图三支柱归位）

### 3.1 → ② 环境智能（主动想到）

#### X3. 目标应用感知粘贴建议 · **最高优先**

这是 AI 路线图 §2.2 明确列出的 ② 最大缺口，而且**信号已经在采**（`paste.rs` 的 `target_app`），
只是只用在脱敏提示、没参与排序决策。

保留原方案的五类预设（这部分设计很完整）：

| 类别 | 检测 | 推荐排序 | 风险提示 |
|---|---|---|---|
| 终端 | cmd.exe / WindowsTerminal / iTerm2 | 优先命令/路径/纯文本 | 多行命令风险提示 |
| IDE | vscode / intellij / cursor | 优先代码/JSON/错误栈 | — |
| 邮件 | outlook / thunderbird / mail | 优先签名/回复片段 | — |
| 聊天 | wechat / slack / discord | 优先最近文本/图片 | 默认隐藏 secret |
| 浏览器地址栏 | 焦点元素 + URL bar 特征 | 优先 URL + 去跟踪参数 | — |

规则优先级：`安全硬规则 > 用户应用规则 > 内容类型规则 > 使用历史排序 > 默认排序`

**首版只做建议排序，不自动篡改内容**（红线①）。

> **实现上的一条纠正**：原方案要新建 `src-tauri/src/context/` 目录 + `app_rules` 表。
> 但现在已经有 `source_cat`（ide/browser/terminal/chat/other，前后端各一份且取值一致）
> 与 `cleanSourceName()`。**应该复用这套分类，不要另建一个 app_rules 体系**——
> 否则同一个“这是个 IDE”的判断会有两套真相。

#### X7. 参数化片段表单

**不是从零开始**：`src/lib/snippetVariables.ts` 已支持 `{{date}}/{{time}}/{{datetime}}/{{clipboard}}/{{uuid}}`，
本项是给它**加类型与表单**：

```text
客户：{{customer:text|required}}
环境：{{env:select(dev,staging,prod)}}
工单号：{{ticket:number|required}}
原始内容：{{clipboard:multiline|masked}}
Token：{{token:secret|no-persist}}
```

类型：text / number / select / multiline / secret；必填校验、默认值、最近使用值、结果预览。
**`secret` 类型默认不写入模板使用历史**（这条很关键，与红线一致）。

### 3.2 → ① 个人记忆（记得住）

#### C5. 云端 OCR fallback

现状：`commands/images.rs:323` 的 `ocr_image` 走**本地引擎**。本地识别不准时没有退路。
做法：置信度低于阈值时提示“试试云端识别”（**手动触发，不自动上云**）。
变换中心已有“本地识别结果（可修改）+ 重新识别”的 UI（`ocrBox`），接入点已就绪。

#### C13. 多语言 OCR + 文档抽取（结构化输出）

**建议与 AI 路线图 §3.3 的“结构化输出约束”一起做**——两者都需要
`response_format: json_object`，分开做是重复搭脚手架。

### 3.3 → 数据安全（独立于三支柱）

#### X4. 敏感记录“保留但加密” + AI 数据授权层

核实结论：**未做**。现有的 DPAPI 加密只用于 API Key（`ai/secret_store.rs`），
剪贴板里的敏感内容目前是**拦截不入库**（`is_secret` 判定），不是加密保留。

两种语义要先分清楚（原文没分）：
- **拦截不存**（现状）：安全，但用户会丢东西——“我刚复制的密码呢？”
- **加密保留**（本项）：不丢，但多了一份密文资产要管（密钥轮换、备份、跨设备同步全部变复杂）

所以这一项**不是单纯的功能添加，是一个产品取舍**，开工前得先拍：敏感内容到底该丢还是该存？

### 3.4 低成本顺手项

#### S2. 扩充主题预设

现状：`src/lib/theme.ts` 只有 **6 套**（经典白 / 深海 / 午夜 / 森林 / 美乐迪 / 晨曦），
远不是原规划的“20-30 套”。加预设是纯数据活（每套几行 CSS 变量），零风险。
**但先确认皮肤体系还推不推**（见 §4）。
