## 2. 从零到能跑 dev

### 2.1 宿主机依赖（脚本装不了，必须先有）

| 依赖 | 版本 | 检查 |
|---|---|---|
| Node.js | ≥20 LTS（维护机 v24.13） | `node -v` |
| Rust | ≥1.70 **MSVC** 工具链（维护机 1.96.0） | `rustc -V` / `cargo -V`；必须是 `x86_64-pc-windows-msvc` |
| VS 2022 Build Tools | 勾选「使用 C++ 的桌面开发」+ Windows SDK | 能编任意 Rust cdylib |
| Git | 带 Git Bash | `git --version` |
| **Windows 开发者模式** | 设置 → 隐私和安全性 → 开发人员模式 | 🔴 只在要打 Android 时是硬前提：不开则 Rust 全绿后 tauri 死在「symlink so 到 jniLibs」 |

### 2.2 clone + 装依赖

```powershell
# 必须 SSH。HTTPS 在这套网络下经常超时（维护机实测）
git clone git@github.com:lzlkyb/pastepanda.git
cd pastepanda
npm install          # prepare 脚本会装 husky 钩子
```

🔴 **不要从 Gitee clone 源码**：`gitee.com/lzul/pastepanda` 是**下载镜像，只有发版产物**（安装包/签名/manifest），没有源码。GitHub 是唯一源码源。两边 owner 名不同（`lzlkyb` / `lzul`）是刻意的，不是笔误。

国内网络拉 GitHub 不稳时，重试或换时段，**别去 Gitee 找源码**。

### 2.3 把 SSH 公钥加进 GitHub 账号

新机器要能 push，得把它自己的公钥加到该 GitHub 账号（Settings → SSH and GPG keys → New SSH key）。多机器各挂一把 key 是账号级设置，**不影响任何提交归属**，也不影响 CI。

```powershell
ssh -T git@github.com        # 期望输出 Hi lzlkyb! You've successfully authenticated
```

### 2.4 一键补齐「不在 git 里」的构建资产

```powershell
powershell -ExecutionPolicy Bypass -File scripts\setup-dev.ps1
```

幂等，可重复跑。它做：查 Node/Rust → `npm install` → 找 `libclang.dll` 并拷进 `src-tauri\.libclang\` → 预下载 MNN 预编译 → 校验 OCR 模型 → 打印下一步。可选参数 `-LibclangPath`、`-SkipNpm`、`-SkipMnn`。

**为什么必须跑**：这两样被 `.gitignore` 忽略（体积超 GitHub 限制），缺任一样**前端能跑、Rust 编不过**。

| 资产 | 路径 | 缺了会怎样 | 补法 |
|---|---|---|---|
| libclang.dll | `src-tauri\.libclang\libclang.dll` | 编到 **841/904** 才报 `Unable to find libclang`（`ocr-rs` 的 bindgen 阶段，很靠后，容易误判成代码问题） | `setup-dev.ps1` 自动找；或装 LLVM；或 `pip install libclang` 后手动拷 |
| MNN 预编译（~170MB） | `src-tauri\vendor\ocr-rs\3rd_party\prebuilt\mnn-dev-windows-x86_64\` | 无缓存时首次 cargo 会联网自动下；断网则编不过 | `setup-dev.ps1`；或手动下 [mnn-dev-windows-x86_64.zip](https://github.com/zibo-chen/MNN-Prebuilds/releases/download/dev/mnn-dev-windows-x86_64.zip) 解压到该目录 |

OCR 模型（`src-tauri\resources\ocr_models\`，~15MB）**已在 git 里**，clone 即有。

### 2.5 设 `LIBCLANG_PATH` 并启动

项目**不**持久化 `.cargo/config` 里的这个变量，所以**每个新终端**都要设（或 `setx` 一劳永逸）。

```powershell
# PowerShell（当前会话）
$env:LIBCLANG_PATH = "$(Get-Location)\src-tauri\.libclang"
Test-Path "$env:LIBCLANG_PATH\libclang.dll"    # 必须 True
setx LIBCLANG_PATH "$(Get-Location)\src-tauri\.libclang"   # 新开终端生效

npm run tauri dev
```

```bash
# Git Bash：🔴 必须 pwd -W，裸 pwd 展开成 /d/... ，bindgen 是原生程序不认 MSYS 路径
export LIBCLANG_PATH="$(pwd -W)/src-tauri/.libclang"
npm run tauri dev
```

```cmd
:: cmd：set 不加引号；跨盘切目录用 cd /d
set LIBCLANG_PATH=D:\你的路径\pastepanda\src-tauri\.libclang
```

- **必须 `npm run tauri dev`**，不要裸 `npx tauri dev`——前者跑 `prebuild` 并用本地 Tauri CLI，后者可能拉到 registry 上的废弃 `tauri@0.15.0`，报 `could not determine executable to run`。
- 首次 Rust 编译约 1 分钟起（727 个 crate，视是否现场下 MNN），之后 Vite HMR，**改前端不用重启 dev**。
- 日志里 `tauri_plugin_updater ... update endpoint did not respond` 是 dev 连不上更新服务器，**无害**。

## 3. 换机器必须动手的 4 处（不做会有静默后果）

### 3.1 提交身份 —— 必须与维护机**完全一致**

```powershell
git config user.email "43698433+lzlkyb@users.noreply.github.com"
git config user.name  "lzlkyb"
git config user.email    # 回读确认
```

为什么这条不只是「归属好看」：pre-push 的**覆盖守卫**（`scripts/prePushTier.mjs` 的 `decideOwnership`）认作「我的」的地址 = **本机 `git config user.email`** + 历史 legacy `dev@clipboard-manager.local`。两台机器邮箱不一致时，A 机 rebase / force-push B 机写的提交会被判成「这次 push 会抹掉别人的提交」→ **退出码 9，在跑任何测试之前就拒绝**。而误判的出路只有 `git push --no-verify`，那等于把守卫整个废掉。

（维护机历史上 616 笔提交用的是 `dev@clipboard-manager.local`，那是不可验证地址，贡献图归属为零——见 `CONTRIBUTING.md` §3.6 / `AGENTS.md` 规则 21。**别把那种地址带进新机器。**）

### 3.2 remote 必须是 SSH

```powershell
git remote get-url origin        # 期望 git@github.com:lzlkyb/pastepanda.git
# 若显示 https：
git remote set-url origin git@github.com:lzlkyb/pastepanda.git
```

### 3.3 `.cargo/config.toml` 的并行度 —— 按新机器硬件重估

仓里写死 `jobs = 6`，注释记录了取证：维护机 16 逻辑核 / 8 物理核 / 15.8GB，用 cargo 默认 `-j16` 起 16 个 rustc（每个 0.5–1.5GB）叠链接峰值 + 并行 git push，**把机器跑蓝屏**。

- 新机器核数/内存**更强**→ 可以适度上调；**更弱或内存更紧**→ 往下调。宁可慢，别蓝屏。
- 同一文件里的 `replace-with = "rsproxy-sparse"`（rsproxy.cn crates 镜像）是按国内网络选的：直连 `static.crates.io` 实测 30s 超时、卡 145 个 crate 不动十几分钟。**新机器在境外就反过来**，按文件里的注释把它盖掉。校验和一致，不影响 `Cargo.lock`。

### 3.4 只在要打 Android 时：改 `scripts/android-build.mjs` 的 `ENV_DEFAULTS`（第 42 行起）

里面硬编码了维护机的 `JAVA_HOME` / `ANDROID_HOME` / `NDK_HOME` / CC/CXX/AR/BINDGEN/LINKER 绝对路径。新机器装齐 JDK 17 + Android SDK + NDK **27.2.12479018** 后，只改这一处（`AGENTS.md` 规则 20）。打完记得：Android 构建一律走 `npm run android:*` 脚本（它把 target 目录隔离到 `src-tauri/target-android`，与桌面 dev 并行不抢锁），**禁止**为了腾出编译锁去杀桌面进程。

## 4. 开工前自检（全绿再动代码）

```powershell
Test-Path node_modules                                          # True
Test-Path src-tauri\.libclang\libclang.dll                      # True
Test-Path src-tauri\resources\ocr_models\PP-OCRv6_small_det.mnn # True
$env:LIBCLANG_PATH                                              # 非空 + 带盘符的 Windows 路径
npx tsc --noEmit
npm run lint                                                    # --max-warnings=0
npx vitest run                                                  # 遇 thread pool 崩溃加 --pool=forks
cargo check --manifest-path src-tauri/Cargo.toml                # 有 Rust 改动时；先设 LIBCLANG_PATH
```

**钩子有效性单独验一次**（容易静默失效）：第一次 push 特性分支，输出里必须有 `耗时 判档：Ns`、`耗时 守卫：Ns`、`耗时 tsc：Ns` 这类分段行。**没有 = husky 没装好、守卫根本没跑**（`.husky/_` 缺失时是静默不跑，不报错），重跑 `npm install` 再验。

`npx tsc --noEmit` 若报满屏 TS2307（找不到模块），或 `npx tsc` 提示下载 `tsc@2.0.4`，那不是代码问题，是 `node_modules` 坏了——**别直接 `npm ci`**：如果这台机器上还有别的工作树/vite 进程加载着主树的 `esbuild.exe`，unlink 必 `EPERM` 而且已经先删掉大半。用 `npm install --no-save`。

## 5. 工作流硬规则（违反任意一条 PR 打回）

1. **不直接推 master**。`master` 是 `enforce_admins=true` + required checks（`Rust Tests` / `Frontend Tests`，`strict=true`）+ 审批数 0，直推会被 GitHub 拒。一律 `分支 → PR → 合并`。
2. **分支命名**：`feature/** fix/** refactor/** chore/** agent/<会话标识>/**`，纯文档用 `docs/**`。🔴 **哪些前缀有 CI 由 `.github/workflows/test.yml` 的 `push.branches` 单独决定**——它是唯一裁判，不是口头约定：`docs/**` 故意**不在**名单里（推上去一次都不跑，本地 lint 即可），名单外任何分支都等于裸推；加新前缀要同时改 `CONTRIBUTING.md` §3.1 和那份名单。仓库已开 `delete_branch_on_merge`，PR 合入时 GitHub 自动删头分支（关掉不合并的 PR 不删；开关打开前已合入的要手删）。
3. **版本号不自动递增**（`AGENTS.md` 规则 2）。唯一来源 `src-tauri/tauri.conf.json`，升级时同步 `src-tauri/Cargo.toml`；`package.json` 的版本号永远是占位 `0.1.0`，不要碰。可以**建议**升，由维护者拍板。
4. **不主动 `npm run tauri build`**（规则 3），等维护者明确确认。
5. **不自动 commit / push / tag**（规则 5）：等维护者说「提交 / commit」。发版只在维护者那台机器上做（`docs/发版流程.md`），**接手机器不打 tag**。
6. **单组件 `.tsx` ≤300 行**（规则 7）：超了先拆（`hooks/useXxx.ts` / 子组件 / `lib/xxx.ts`）；目标文件接近 300 行时默认新建文件而不是追加。
7. **公共纯函数收口到 `src/lib/utils.ts`**（规则 11）；「某类 X 要特殊处理」的分支逻辑要 grep 全同类取值点、收口成一个函数、补守卫单测（规则 11.1）。验收标准：第 7 个调用点新写出来时若仍会走错，就是还没收口。
8. **修 bug 先让它变红**（规则 23）：改前红、改后绿，两份输出都写进 commit/PR 描述。**重跑到绿不算修复**，加压/负载也不算证据。
9. **AI 功能红线**（规则 16）：任何调用模型/云端的路径必须受 `ai_enabled` 门控（前端 `aiAvailable` + 后端 `cfg.enabled`，默认关）。未启用 = 零可见、零请求、零费用。本地 OCR、本地正则打标签不算 AI。
10. **改 UI 先读真实源码**（规则 12）：`.tsx` + `.module.css` 都读，HTML 稿以现有结构为基线，不虚构现有能力。
11. **文件存放**（规则 13）：`.md` → `docs/`，HTML 设计稿 → `design/`（索引由 `npm run gen:design-index` 生成）。
12. **`git add` 只加自己改的文件**（规则 22）：禁止 `git add -A` / `git commit -a`。`pre-commit` 的 `lint-staged` 会 stash 整棵树。
    - 跨机器时这条变成：**每台机器各自的工作树**互不影响，但**远端分支是共享的**。开工先 `git pull`；小步提交、频繁 push；`strict=true` 要求分支头包含 master 尖端才能合，所以合前先 `git merge master` 进自己的分支。
    - 高冲突风险文件（改前先 pull，尽量只改自己负责的区段）：`src/components/screenshot/ScreenshotOverlay.tsx`、`appStore.ts`、`hotkey_manager.rs`、`src/lib/utils.ts`、`lib.rs`、`.gitignore`。
    - 🔴 最坏的不是「两人改了同一段」而是 **add/add**：两人各自发明一个同名 helper。动手前先 `git grep` 同名函数；要改共享函数的签名/语义，先在主干单独提一小笔再让功能分支 merge 主干。
13. **提交前缀**影响 Release 自动分类：`feat:` / `chg:` 或 `change:` / `fix:` / `refactor:` / `docs:`。
14. 行尾：仓库已有 `.gitattributes`（`* text=auto`，源码/配置/文档一律 `eol=lf`），新机器不需要额外配 `core.autocrlf`。⚠️ `CONTRIBUTING.md` §3.5 里那句「仓库没有 .gitattributes」是**旧文**，以文件实际存在为准。唯一例外：`src/__tests__/recommend.test.ts` 故意标 `-text`（fixture 里有裸 NUL），别去「顺手统一」。

### 5.1 push 的耗时与 timeout（别误判成「测试挂了」）

pre-push 按目标分两档（判据 `scripts/prePushTier.mjs`）：

| 档 | 触发 | 跑什么 | 维护机实测 |
|---|---|---|---|
| `light` | 远端 ref 只是特性分支 | 覆盖守卫 + 密钥守卫 + `npx tsc --noEmit`（**tsc 恒跑，别挪进 full**：CI 的 frontend-test 没有 tsc 这一步，全仓唯一查类型的地方就是这个钩子） | ~48s（tsc 冷启动量到过 73s） |
| `full` | 远端 ref 是 `master`，或掺了任何 tag；以及读不到 stdin / node 不可用 / ref 行读不懂 | 上面三项 + 全量 Vitest + `cargo test` | ~566s（**同机不同负载差 5 倍**，Vitest 段 100/269/517s 都全绿过） |

- **一次 push 留 timeout ≥1800s**。太短会在钩子跑完前被掐死，现象像「测试挂了」。
- 钩子自己打印每段耗时——**文档里不再抄常数**，以钩子输出为准。新机器第一轮普遍比维护机慢（冷 cargo 编译），别据此判回归。
- 「这一轮比上一轮慢」通常不是回归证据，先查这台机器上有没有别的会话在跑。

## 6. 需要知道但**不需要搬**的东西：密钥与本机数据

| 项 | 位置 | 新机器怎么办 |
|---|---|---|
| 桌面更新签名私钥 `TAURI_SIGNING_PRIVATE_KEY` | 维护机的 `.env.secrets`（**已 gitignore**，不进仓） | **不用搬**。CI 从 GitHub Secrets 取，桌面发版在维护者机器外还能走 CI。只有本机要打带 updater 产物的安装包才需要它（`npm run updater:check-key` 会告诉你缺）。🔴 任何时候都**不要**把密钥值写进 `.md` / 提交 / PR 描述——pre-push 的密钥守卫会拦，但别去试。 |
| Android 长期签名库 | `~/.pastepanda/pastePanda-release.keystore` + `keystore.properties`（仓库外） | **不用搬**。缺了 `npm run android:apk:release` 直接红灯，**不回落 debug key**。🔴 绝不许在新机器上「重新生成一把」——换签名 = 全体老用户 `SignatureMismatch`，必须卸载重装。要搬只能由维护者走安全通道（非网盘明文 / 非邮件）。 |
| GitHub Secrets（`GITEE_TOKEN`、`PP_APK_KEYSTORE_*` 等） | GitHub 仓库设置里 | 账号/仓库级，新机器不需要重配；有 admin 权限的 AI 用 `gh api` 能读元数据，**读不到值**，这是正常的。 |
| 应用运行数据 | `%APPDATA%\com.pastepanda.app\`（`clipboard.db`、`config_backups/`、`ai_key_*.bin`、`mcp_token.bin`、`rc.log`） | 新机器是**干净空配置**，正常现象，按需重新配置即可。 |
| 🔴 `sync_node_key.bin` | 同上目录 | **绝对不要拷到第二台机器**。那是 P2P/远程电脑（iroh）的**节点身份**。两台同 key = 同一网络里两个「同一台电脑」互相冒充；手机侧配对与会话都会错乱。正确做法：新机器首次启动**自己生成**一把，手机把它当新电脑**重新配对一次**。 |

## 8. 排障速查（照现象查，别猜）

| 现象 | 根因 | 处理 |
|---|---|---|
| `Unable to find libclang ... invalid: []` | 没设 `LIBCLANG_PATH`，或 Git Bash 用了裸 `pwd` 得到 `/d/...`。末尾 `invalid: []` 的意思是「变量拿到了但当成空目录」，**不是没设** | 见 §2.5；Git Bash 一律 `$(pwd -W)`。可能编到 841/904 才崩 |
| `could not determine executable to run` | 裸用了 `npx tauri dev`，拉到废弃包 `tauri@0.15.0` | 用 `npm run tauri dev` |
| `Port 1420 is already in use` | 上次的 **Vite 子进程**没杀干净（只 `taskkill PastePanda.exe` 不够），现象是 Rust 起来了但窗口空白 | `netstat -ano \| findstr :1420` 取 LISTENING 那行 PID，一并 `taskkill /F` |
| 卡在 `Building [===>] 910/912` 反复重启、窗口迟迟不出来 | 有别的进程在**持续写 `src-tauri/`**，watcher 每次在编译收尾时打断重来 | 别盲目重启（会回到同一个循环）。`find src-tauri/src -type f -newermt "HH:MM" -printf "%TH:%TM  %p\n" \| sort` 找写入方，让它停手 |
| `update endpoint did not respond` | dev 连不上更新服务器 | 无害，忽略 |
| push 输出里没有「耗时 …」分段行 | husky 钩子没跑（`.husky/_` 缺失时静默失效） | 重跑 `npm install`；确认 `git config core.hooksPath` → `.husky/_` |
| push 被拒 `exit 9` | 覆盖守卫判定这次 push 会抹掉「不是本机身份写的提交」 | 先核对 `git log old..new`；十有八九是 §3.1 的邮箱没对齐，或目标分支真是协助者的。确认要覆盖才用 `--no-verify`（它同时跳过测试） |
| 满屏 TS2307 / `npx tsc` 要下载 `tsc@2.0.4` | `node_modules` 损坏，**不是代码问题** | `npm install --no-save`；**别 `npm ci`**（见 §4） |
| cargo 长时间 `Blocking waiting for file lock on build directory` | 有别的构建在共用 target（Android 走 `target-android` 才隔离） | 等放锁；确认没在裸跑 `npm run tauri android build` 抢桌面 target |
| GitHub 拉代码/推送超时、`Connection was reset` | 系统代理不稳 | 改走 SSH（§3.2）；仍不行按 `CONTRIBUTING.md` §7 求助顺序，**不要去 Gitee 找源码** |

## 9. 「这台机器接手成功」的判据（四条都要满足）

1. `npm run tauri dev` 起来后 **PastePanda 主窗口真的出现**（不是只有 vite 在 LISTENING；判据是 `netstat` 里 1420 既有 `LISTENING` 又有 `ESTABLISHED`）。
2. §4 自检全绿：`tsc --noEmit` / `npm run lint` / `npx vitest run` 全过。
3. 在一条**特性分支**（前缀在 CI 名单里）上提了一个 PR，`Rust Tests` + `Frontend Tests` 双绿。
4. 第一次 push 的钩子输出里**有分段耗时行**。

没跑起来之前不要开始改功能代码；改出来也验证不了。
