# 录屏办公清晰版 B：实施与验收

2026-10-16。用户已确认方案 B，并要求录制中尽量缩小控制条后授权开工。产品代码已实施，正在完成真实 Windows 录制验收；未升级版本、构建安装包或提交 Git。

## 已实施与当前验证

- 录制控制条正常态 260×36、收起态 80×28（逻辑像素）；原生窗口同步调整，详情按需展开。准备中不显示假计时，暂停由后端确认，停止保存独立反馈。真实 125% 缩放环境已观察到对应尺寸、收起与恢复，以及暂停计时冻结。
- 音源常驻文字开关，录前检查可取消，切换范围会作废旧检查；完成结果卡常驻，声音与采集异常进入结果摘要并保存在 sidecar。最近列表区分读取失败、空列表与加载。
- 预览有文字播放入口、播放位置和键盘可调起止点；裁剪为可查询/取消的后台任务，另存文件且保留源录像。GIF 查询失败保留恢复入口，不把未知状态当作完成。
- 后端修复时间尺度裁剪、固定尺寸样本表、分包重采样、真实编码格式封装、旧会话收尾、GIF 颜色/稀疏时间戳以及临时产物发布。最小反例已进入正式测试。
- 自动验证：录屏相关前端 16 文件 / 161 项通过；Windows Rust `cargo test --lib rec::` 88 项通过、1 项忽略；TypeScript、改动文件 ESLint、`lint:ui` 通过。`git diff --check` 通过。新增/拆分的产品 TSX 组件均未超过 300 行。
- 第一轮真实录制保存为 `屏幕录制_2026-10-16_204825.mp4`，874×390、约 2:44、22.7 MB；结果卡与最近列表可找回，内置播放器时间能正常推进。实录发现边框污染，随后补充「开录前隐藏原生选区窗」「录制态卸载边框动画」的红绿回归并修复。
- 捕获排除改为读取 Windows API 的真实结果，不能以 Tauri 消息入队成功代替系统生效。本机在窗口显示、DWM 合成后仍返回 `0x80070008`；失败时控制条和保存结果均明确提醒可能进入成片，最近列表及裁剪 sidecar 均能保留这条提醒。没有将 Windows 拒绝错误转成假成功；全屏录制仍可能录到控制条，这是本机已确认的限制。
- 最后一轮 `屏幕录制_2026-10-16_211433.mp4` 的初始真实预览已确认无红色边框；总长约 37.466 秒、3.5 MB。鼠标选终点后另存 `屏幕录制_2026-10-16_211433_剪.mp4`，返回实际区间 0–11166ms、702108 字节，源 MP4 保留。预览产物时复现旧窗口关闭与新窗口同名创建竞态，已加有界等待及并发开窗串行化，红绿守卫通过，等待真实复核。

## 目标与边界

服务 Windows 办公演示、问题反馈和简单教程。保留快捷键进入、轻覆盖层、悬停预览、拖拽框选、倒计时、暂停、停止即保存与最近录制。目标是让用户知道录哪里、录哪些声音、是否仍在录、成片是否完整、文件在哪里。

不扩成视频编辑工作台；不引入摄像头、字幕、多轨编辑、云上传或窗口跟随捕获。当前的窗口选择按桌面固定坐标工作，要在直启和确认路径同样说明移动、遮挡的影响。具体音源状态须来自后端，不能以按钮开关代替采集成功。

设计基线：`RecSelectOverlay.tsx`、`RecOverlayParts.tsx`、`RecSettingsCluster.tsx`、`RecControlBar.tsx`、`rec-hud-main.tsx`、`RecPreview.tsx`、`RecRecentList.tsx` 及 `recsel.css`、`RecRecentList.module.css`。沿用主题语义色、玻璃浮层、系统字体及选区视觉；HTML 的导航和示例桌面仅为评审外壳，不加入产品。

设计稿：`design/录屏-办公清晰版-B-2026-10-16.html`。交互、数据、文件和声音检查均为模拟；保存位置文案不虚构用户配置。

## 拟实施交互

1. **录前**：一枚开始主按钮；范围读数与「电脑声音 开/关」「麦克风 开/关」常驻，可直接切换；画质继续渐进披露。单击采纳窗口，拖拽始终自选区域；录前音源失败可重试或明确关闭该音源，不能静默继续。倒计时可用鼠标取消或 Esc 返回选区。
2. **录制中**：按用户反馈改为单行小浮条，常驻只有状态点、后端权威计时、暂停/继续、停止、更多。声音详情、画质、丢弃进入更多；正常态不显示说明行，不铺满屏宽。暂停冻结计时；停止即保存，丢弃二次确认，有明确保留出口。浮条可拖动，可主动收起为小计时，单击恢复。异常时临时弹出同域提示，收起详情后仍保留异常入口，并将声音异常写入保存结果。
3. **完成**：文件名、真实时长、保存位置、声音异常摘要与操作放在同一层；结果卡主动关闭，不依赖短时自动消失。主窗隐藏与可见时复用同一结果模型，最近录制始终能找回。系统关闭/重启后是否还保留异常摘要，须通过已保存 sidecar 的兼容读取实现，不能仅存在 HUD 内存。
4. **预览/裁剪**：明确播放按钮与播放位置；起止点能用鼠标及键盘调整，显示对齐后的实际保留区间。另存新文件，原录像保留。保存中锁定范围；关窗继续后台任务并留下完成/失败入口，Esc 不伪装为取消。长任务提供真实处理进度或可取消；取消只清理本次临时产物。
5. **最近录制/GIF**：加载、空、错误分开；错误提供重试，不显示假空态。现有动作改为可识别文字；GIF 任务有进度、取消、失败重试和成功后的打开入口。预览关闭后仍能找回裁剪产物。

## 实施顺序与架构

1. 先修已经复现的裁剪与重采样，以及会阻碍稳定测试的会话归属和编码器类型问题。每项最小复现先红后绿；请求的质量档和实际编码格式分别建模。
2. 统一录制状态/结果载荷，收口时长字段、实际音源状态、失败原因与保存产物；前端只投影后端状态，避免控制条、HUD、最近列表各自猜测。复用现有事件和 IPC 分层，不新建另一套录制引擎。
3. 实施设计稿确认后的录前、控制条、结果、预览和最近列表交互。接近 300 行的 TSX 先按 Hook/子组件拆分；多个组件共用的纯工具函数仍放 `src/lib/utils.ts`。
4. 修导出可靠性并完成故障矩阵。临时文件成功后原子完成；取消、重试只影响本次任务；任务结束事件不依赖预览窗一直挂载。
5. 先测性能基线，再针对瓶颈处理脏帧合成、最近列表扫描、预热请求去重、预览更新频率。静态桌面的稀疏帧是既有策略，不以样本数少判定丢帧。

## 验收清单

- 新手不读说明能说清录哪里、录哪些声音，纯鼠标完成录制、预览并找回文件；键盘能完成预览与裁剪。
- 最大化窗口内拖拽局部选区，松手保留该区域；窗口预览直启同样显示固定区域说明。小框、贴边、窗口重画、取消均不意外开录。
- 麦克风不可用、录制中拔设备、暂停/停止失败、文件列表失败、GIF 轮询失败均有可见解释和恢复入口；音源缺失不能报成完整成功。
- 正常停止、丢弃、重录、连续热键、晚到会话收尾都不串状态；完成文件可播放，原始录像不因裁剪/导出失败受损。
- 预览另存期间关窗/重开、Esc、取消、磁盘写失败后，任务状态与真实产物一致；成功后能直接核对裁剪文件。
- 浅色/深色主题，125%/150% 缩放，屏幕四角、窄可用区域与混合 DPI 多屏不遮挡或截断主动作；减少动画、焦点、点击目标和文字对比度人工复核。
- 录制小浮条：正常态只占自身一行；原生窗口大小及鼠标命中范围与可见浮条同步，禁止留下透明大窗口拦截桌面操作。优先放选区外，验证系统支持的捕获排除，实录核对浮条与展开菜单不进入成片；不能只凭 HTML 原型宣布已排除。拖动、收起、恢复、更多展开与异常提示都不抢走正在演示的软件焦点。
- 性能记录：开录分段耗时、静止/滚动/视频三场景、1080p/4K/双屏、小选区与全屏、30 分钟内存走势、音画偏移、1000 文件目录首开时间、隐藏/暂停时开销。用基线设预算，不提前承诺 CPU 或内存降幅。

本轮 `lint:ui` 通过，但只扫描产品 `src/`，设计稿不在其扫描范围；不能以零命中宣称设计稿已完成无障碍合规。
