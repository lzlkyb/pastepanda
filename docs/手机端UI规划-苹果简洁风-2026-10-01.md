# 手机端 UI 规划：苹果简洁风与桌面一致性

日期：2026-10-01。状态：方案提案，尚未确认；本文不代表已实现能力。

## 1. 范围与现状

按现有客户端规划设备、文件、设置及全屏远控。是否扩展独立剪贴板、笔记模块待用户决定，不纳入本轮默认范围。现有技术方案为 Tauri mobile + React，Android 先行；采用苹果式视觉与交互原则，同时尊重 Android 返回行为、系统选择器和权限流程。

本次读取了 src-mobile 的 App、设备/配对/无人值守、文件任务、设置、会话工具栏及对应样式；对照桌面远程电脑工作台组件、theme.css，以及项目交互、UI、性能规则。以下为源码分析，尚未进行手机真机视觉和性能验收。

现有能力：三页签、配对码/扫码、远程控制/只看画面、无人值守接入、独立双向文件传输、会话历史、触摸缩放/滚动/长按、软键盘/修饰键、剪贴板推取、音频开关、横屏沉浸。

现有问题：普通页面容器居中，缺少稳定的页标题和信息层级；操作按钮的视觉权重接近；部分提示过于技术化；会话工具栏字符与 emoji 混用；部分局部状态随页签卸载丢失；连接等待和文件接收提示目前主要在各自页面，切页后难以感知。

## 2. 三个可选方向

| 方向 | 结构与风格 | 优点 | 代价 |
|---|---|---|---|
| A：原生分组列表，推荐 | 浅冷灰底、白色分组、紧凑设备卡、图标与文字底栏；远控使用沉浸画面 | 苹果式清晰层级、列表扩展自然、与桌面浅色主题相近 | 需重排页面层级及弹层，不是单改颜色 |
| B：设备卡片首页 | 最近设备作为首页焦点，其余设备以轻卡片排列，连接按钮直接可见 | 一两台电脑时连接直观、品牌感更强 | 多设备时占屏，需解决排序与首页焦点变化 |
| C：轻玻璃导航 | 内容保持实底，浮动导航与会话胶囊采用局部半透明材质 | 更强调材质感，与桌面胶囊呼应 | 对比度、背景采样、键盘和小屏适配成本最高 |

推荐 A，吸收 B 的明确主动作和 C 的局部浮层材质。区别主要在布局和导航，不建立三套品牌配色。方向需确认后再生成 design/ 下的 HTML 设计稿。

## 3. 视觉语言

- 共用：PastePanda 品牌、Lucide 图标体系、主题强调色、成功/警告/危险语义、设备状态和传输文案、150/200/300/400ms 动效档位。
- 手机专用：系统字体、触控尺寸、页面留白、分组圆角、安全区、底部弹层；桌面侧栏映射为底部导航，桌面详情区映射为详情页或动作面板。
- 建议默认浅色，提供深色适配。浅色以冷灰底与白色内容面为主，品牌蓝沿用桌面 ocean；深色沿用桌面现有深色主题的语义色。移动端背景可收敛桌面氛围渐变，避免大面积装饰抢内容。
- 颜色从现有语义变量派生；移动差异放在移动端作用域，不直接修改桌面主题取值。卡片用实底，仅导航或会话胶囊按需要使用局部玻璃。
- 起始规格：页面左右留白 20px，分组间距 24px；页标题 28–32px，正文 16px，说明 13–14px；内容圆角 16–20px。这些是设计稿起点，需小屏实测，不是 Apple 官方尺寸。
- 常规触控目标至少 48×48 CSS px，主按钮高度 48–52px。小图标扩大点击区，相邻危险与常用动作留足间隔。图标旁保持文字，状态不只靠颜色。

## 4. 页面规划

### 设备

从顶部开始布局：页标题“设备”与“添加电脑” → 简短通道状态 → 已配对设备列表 → 次要入口。

设备行显示设备图标、名称、状态、必要的辅助信息。连接路径必须区分“上次连接”与当前实测，不能把历史数据显示成实时状态；指纹放到详情。

建议常用设备区域提供明确的“远程控制”按钮，点设备主体打开详情/动作面板。主按钮与卡片主体分离，避免嵌套点击和误触；“只看画面”“传文件”作为次动作，无人值守和解除配对位于较低层级。若希望完全保持现有“点设备 → 动作面板”语义，则省略行内连接按钮；这是待选的高频路径取舍。

不依赖长按、滑动或双击发现功能。下拉刷新可作为便捷方式，同时保留可点的刷新入口。

空状态只提供一条清楚主路“添加电脑”，说明电脑端在哪里进入配对。加载状态和真正没有设备必须区分。

### 添加与配对

“添加电脑”打开独立流程，沿用已有扫码、配对码、无人值守能力。不要把全部输入框与本机信息长期摊在首页。

扫码为手机上方便的入口，手动输入始终可达；权限拒绝后显示原因和输入入口。数字码支持系统粘贴和数字键盘，显示已有有效期与遮罩规则，不新增配对协议。

小屏或键盘弹出时使用可滚动的近全屏流程，避免把输入与确认按钮挤进固定半屏。成功后就地反馈并回到设备列表，高亮新增设备；失败保留输入，允许修改后再试。

### 文件

顺序：标题 → 当前目标设备 → “发到电脑 / 从电脑取回” → 待接收请求 → 进行中任务 → 已完成记录。

目标设备选择用单行选择入口，多台时打开列表；从设备页进入则沿用预选。单台自动选中，零台给出到设备页的配对入口。

“取回”说明电脑端还需选择文件；不会虚构远端文件浏览器。接收目录收为次要说明，保留查看位置，不把长路径作为首屏中心。

任务行显示文件名、方向、对方、实际阶段、进度和取消。明确区分“手机准备文件”“等待电脑确认”“传输中”“已完成”，本地上传完成不能呈现为对方已收到。没有后端能力时不展示暂停、续传、打开或分享等按钮。

文件接收请求和连接等待由全局状态提示承载，跨页签仍能感知并返回处理；多个事件集中呈现，避免互相覆盖。未读数量必须来自真实待处理请求。后台继续和后台通知需单独验证平台能力，不做默认承诺。

### 设置

采用分组列表：远程通道、会话历史、使用帮助；联调入口降低层级。远程通道使用标准开关语义，等待后端结果期间显示处理中，失败回滚并在同一行给出原因。

本机身份与技术详情收进二级页。会话历史从首页长列表变为独立页面，清空采用明确确认；不沿用“再点一次”这种容易留存确认状态的模式。

文案按手机角色核对，不直接沿用“可被连”等桌面宿主表述。外观选项若需新增，属于后续功能，设计稿须标为拟新增。

### 远控

保留现有触摸语义与输入链路，先改会话壳与反馈。竖屏使用简洁设备标题、画面和底部工具条；横屏沿用桌面胶囊语言，默认尽可能让出画面。

建议将现在六个同权重按钮收为“键盘、画面、剪贴板、更多”四个文字入口；更多内放画质、声音与独立危险区的断开。声音仍默认关闭。画质改为明确选项，避免循环点击时猜下一个档位。若用户更常用声音，可在设计稿阶段调整常驻入口。

显示当前观看/控制状态，观看态禁止远端输入入口。弹出软键盘后画面与修饰键条适配实际可视高度，重要按钮不被遮挡。

横屏唤出沿用已有本地热区；提供可见的小把手或明确“工具”入口，并避开系统顶部手势区。不用任意点击画面唤出工具，因为那会与远端点击冲突。控制 UI 的触摸必须本地消费，不能同时传给远端。

点击显示短暂定位环，长按显示已有充能提示，拖拽和右键状态清楚区分。提示不要追求持续炫光或大面积波纹。

返回按“关闭键盘/子面板 → 离开会话确认”逐级处理，不因误触返回直接断开。暂不引入悬浮小窗或最小化会话，以免改变现有会话生命周期。

## 5. 点击反馈与动画

| 触发 | 即时反馈 | 最终结果 | 建议动效 |
|---|---|---|---|
| 普通按钮 | 按下即变底色；独立按钮可轻缩放到 0.98 | 根据动作更新页面或文字 | 150ms |
| 设备行 | 整行高亮，不在长列表中逐行回弹 | 打开详情/动作面板 | 200ms |
| 底部页签 | 图标和文字即时选中，保留各页滚动位置 | 原地切换页面 | 150–200ms，轻淡入 |
| 底部面板 | 遮罩与面板同步出现 | 可下拉收回，也有明确取消 | 300ms |
| 全屏流程 | 清楚展示进入/返回关系 | 返回原设备与位置 | 400ms |
| 连接请求 | 按钮变为连接中，防重复提交 | 等待确认、成功或失败 | 状态过渡 200ms |
| 文件传输 | 出现真实任务和阶段 | 终态与原因留在任务行 | 真实进度；不伪造百分比 |

按下反馈在 100ms 内启动；超过 1s 提供等待提示，超过 10s 提供取消或可解释进度。触摸反馈只证明输入已收到，不代表远端动作已成功。

只使用项目已有动效档位与曲线；需要弹簧时采用规则 U2 的统一参数，限于位移/形变。减少动态效果时取消缩放、长位移和回弹，但保留状态变化。触觉是可选增强，必须检查当前平台桥接能力；iOS/WebView 不能靠 navigator.vibrate 视为已支持。

## 6. 必须覆盖的边界与性能

- 360px 小屏、常用 390/430px 宽度、横屏、挖孔安全区、软键盘、较大字体、长设备名/文件名。
- 加载、空列表、离线、通道关闭、等待确认、配对码失效、权限拒绝、连接失败、会话意外中断、文件失败/取消。
- 页面切换保留选中设备、滚动位置与必要草稿；状态提升到不会卸载的层级，不以全部页面常驻换取保留。
- 连接与文件任务继续用共享 store 的实际结果；成功/失败提示与触发在同一可见域，全局事件在全局展示。
- 卡片不逐个做 backdrop-filter。前后台切换时停止装饰性动画，现有帧泵/会话行为按平台现有纪律处理。
- 动效优先 transform/opacity，避免列表布局反复计算；不要为了动效触发帧画面整树重渲染。
- 列表按实际数据规模判断是否需要虚拟化，设计阶段不承诺未经测量的帧率和耗电。

## 7. 实施顺序与验收

1. 确认 A/B/C、范围及设备主动作 → 交付有明确导航和流程边界的确认方案。
2. 在 design/ 生成可点击 HTML 稿 → 覆盖设备列表/空态、配对、文件/请求/失败、设置、竖屏远控、横屏及键盘状态；展示浅深主题与桌面对照，所有新增能力标明。
3. 用户确认 HTML 稿后实施共享基础控件和移动布局 → 不影响桌面样式；所有 TSX 遵守 300 行限制，复用共享判据。
4. 完成设备/配对、文件/设置、远控壳 → 每组补关键行为测试，包括重复提交、取消、错误反馈、切页状态及本地工具触摸不透传。
5. 运行相关测试和 npm run lint:ui，做真机验收 → 覆盖上述尺寸/状态、返回行为、中文输入、横屏、减少动态效果；用录屏与性能数据判断实际手感。

本轮仅输出规划，不修改业务代码、不升级版本、不执行构建或提交。
