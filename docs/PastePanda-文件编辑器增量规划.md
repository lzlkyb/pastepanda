# PastePanda 文件编辑器增量规划

> 2026-08-12 · 基于现有编辑器矩阵(20+ 编辑器已覆盖)的增量规划
> 原则:编辑器为「复制来的内容」服务,不替代独立软件;每类必须有粘贴入口。

---

## 0. 现状盘点(先看清已有的,避免重复)

**editorRegistry.ts 已注册**(内容类型 → 编辑器):

| 族 | 已覆盖 | 状态 |
|---|---|---|
| 文本族 | 文本 / Markdown / 富文本(图文混排)/ 代码(CodeTextArea) | ✅ 成熟 |
| 结构化 | JSON / HTML / CSV / 日志 / 密钥 | ✅ 成熟 |
| 原子型 | 颜色 / 数字 / 链接 / 路径 | ✅ 成熟 |
| 媒体 | 图片 / 文件 | ✅ 成熟 |
| 全屏模式 | 编辑 / 分屏 / 预览 三态(fullscreen/registry.tsx) | ✅ 成熟 |
| 文档流水线 | doc 清洗三态(原文/清洗/Markdown) | ✅ 成熟 |
| 流程图 | diagram 编辑器(React Flow) | 🔄 规划中 |

**结论**:通用编辑器骨架已很全。增量方向不该是"再加一类原子编辑器",而是**补三类高价值缺口**。

---

## 1. 方向 A · 代码/数据类(最高优先级,与 AI 生成工具批咬合)

### A1. SQL 编辑器(⭐ 首推)
- **场景**:v6.7 已有 `ai-sql-generate` 动作(生成 SQL),但生成结果直接给文本——用户要复制去别处测。缺"生成→预览→回填"闭环(测试规划里点过名)。
- **做什么**:SQL 语法高亮编辑器 + 「执行预览」——用本地 SQLite 跑 `EXPLAIN` 或建临时表验证语法,错误标红。
- **AI 联动**:SQL 生成动作的结果直接送进 SQL 编辑器 → 用户改 → 复制/粘贴前台。生成工具批闭环补上。
- **技术**:CodeMirror 6 + sql 语言包(项目已用 CodeMirror,零新增学习);执行用后端 SQLite `:memory:` 只读校验。
- **工作量**:3-4 人日。

### A2. 正则测试器(⭐ 次推)
- **场景**:v6.x 有 `ai-regex-generate`(生成正则),同样缺"生成→试跑"闭环。
- **做什么**:正则输入 + 测试文本双栏,实时高亮匹配位,显示匹配数/捕获组。
- **AI 联动**:正则生成结果直接进测试器试跑;试跑满意才复制。
- **技术**:已有 RegexPreviewDialog 雏形(记忆里有),升级为独立编辑器 + 全屏模式。
- **工作量**:2-3 人日。

### A3. 代码 Diff 对比
- **现状**:已有 `DiffPane.tsx`(动作链步骤对比用),可升级为独立编辑器。
- **做什么**:粘贴"修改前/修改后"两段 → 并排 diff 高亮;或从链结果自动打开。
- **工作量**:2 人日。

### A4. Python/JS 快速运行面板
- **场景**:复制一段脚本 → 本地跑一下看输出(安全沙箱,无网络)。
- **技术**:Rust 侧 spawn 进程 + 超时 + 只读沙箱;风险较高(任意代码执行),**建议后置或仅 JS(deno_core 嵌入)**。
- **工作量**:5-8 人日(安全成本高)。

## 2. 方向 B · 可视化/结构类(中优先级,复用 mermaid 基建)

### B1. 表格增强(在 CSV 编辑器上加)
- **现状**:CsvEditor 已有表格视图(CsvTablePreview)。
- **增量**:列排序 / 过滤 / 公式预览(只读计算,不引入 Excel 引擎)。
- **工作量**:3-4 人日。

### B2. 思维导图(Markdown 大纲 ⇄ 图)
- **场景**:复制一段 Markdown 大纲 → 渲染成思维导图;可编辑节点回写 Markdown。
- **技术**:mermaid mindmap 子集 + 轻交互(点击展开/收起);与流程图共用 mermaid 解析基建。
- **工作量**:4-5 人日。

### B3. 时间线/甘特图
- **场景**:复制计划/排期文本 → gantt 图;只读为主,编辑回写 mermaid。
- **技术**:mermaid gantt,复用 P0 渲染。工作量小。
- **工作量**:2-3 人日。

### B4. 画板(白板 + 手绘批注)—— 后置
- 与流程图编辑器技术栈(React Flow)同源,但"自由白板"场景对剪贴板工具低频,建议最后做。

## 3. 方向 C · 剪贴板原生(差异化,别人没有)

### C1. 粘贴历史对比
- **场景**:同一位置两次复制的内容(如改过的报错),并排对比"上次 vs 本次"——排错场景极高频。
- **实现**:历史表相邻同源条目 diff;复用 A3 的 Diff 组件。
- **工作量**:2 人日。

### C2. 脱敏预览编辑器
- **场景**:粘贴敏感内容前,编辑器里高亮所有敏感位(手机号/密钥/身份证),点一下脱敏,再决定粘贴。
- **实现**:复用 ContentClassifier 敏感识别 + mask 高亮;与 pasteGuard 联动。
- **工作量**:3-4 人日。

### C3. 会话上下文查看器(工作记忆可视化)
- **场景**:v6.1 有 sessionContext(工作记忆),但只在后台。编辑器里可视化"这个会话攒了什么上下文",AI 建议可解释。
- **工作量**:3 人日。

### C4. 链结果回放
- **场景**:动作链跑完后,每一步的输入/输出展开回放(现状只显示最终结果)。
- **实现**:ChainRunnerDialog 已记录 stages,升级为独立回放编辑器。
- **工作量**:2 人日。

## 4. 优先级排序(建议)

| 批次 | 项目 | 理由 |
|---|---|---|
| **P1(v6.11)** | A1 SQL 编辑器 + A2 正则测试器 | 直接补上两个 AI 生成动作的"生成→试跑→回填"闭环,高频且独立 |
| **P2(v6.12)** | B1 表格增强 + C1 粘贴历史对比 + C4 链回放 | 复用现有组件,性价比高 |
| **P3(v7.x)** | B2 思维导图 + B3 甘特图 + C2 脱敏预览 + C3 会话查看器 | 依赖 mermaid/流程图基建成熟后做 |
| **后置** | A4 代码运行面板 + B4 画板 | 安全成本高 / 场景低频 |

## 5. 与现有架构的接入方式

- **编辑器注册**:全部走 `editorRegistry.ts` 的 `EDITOR_REGISTRY` / `TYPE_EDITORS` 注册,零架构改动
- **content_type 扩展**:SQL/正则 → 新增 content_type(sql / regex),由 ContentClassifier 识别后自动路由
- **AI 联动**:SQL/正则生成动作的 `run()` 结果 → 打开对应编辑器(复用 openEditor + 预填),形成工具批闭环
- **红线**:执行类(A4)必须沙箱;脱敏类(C2)本地;全部内容不出本机
