# 迷你 PRD · 「我的设备」区域重规划

2026-09-24 · ui-designer 流程 Step 3 产物（区域级，非全产品）

## Elevator pitch
远程电脑主页左侧的设备面板：一眼看清「哪台能连、哪台在连、哪台连不了」，一步发起连接。

## 问题
A 稿现行形态是单列表平铺 + 每行长 meta：设备多了（8~20 台）后在线/离线混排，
用户要逐行读文字才知道可连性；「正在被连接/正在连接」的进行态没有行上表达；
选中态（1px 描边+阴影）在玻璃底上对比弱。

## 目标用户
零基础求助场景（连一次就走）+ 长期双机用户（每天连办公室机）。

## USP
状态说人话（rcDeviceStatus 单源）+ 一步直达连接钮，比 UU 的纯视觉点更不靠猜。

## 功能清单（本区域）
1. 行：状态点 + 首字头像 + 备注名 + 一行 meta（状态字 · 档位提示）
2. 在线优先组织：显式分组（在线/离线）或排序，二选一（变体实验）
3. 选中态：左缘 3px 蓝竖条 + 白底（UU 学）
4. 活会话徽标：行尾小胶囊「连接中 / 被控 N」（补被控横幅进标题栏后的定位缺口，规则 15.1）
5. 离线灰：整行降饱和，但**由显式 `offline` 字段驱动**（`rcDeviceStatus` 返回值补字段 + 守卫单测，规则 11.1）——`unknown` tone 不得直接当离线（「未实测」≠「连不了」）
6. 头部：标题 + 计数 + ＋（连接新设备）+ ⟳ 重新检查

## UX 红线（不随变体妥协）
- 行内一步直达「连接」钮保留（规则 17.2），不学 UU 零按钮
- 状态文案常驻可见，不学 UU 纯视觉（L1/L6）
- 一屏一个强调色（V3）：蓝 = 可连接性家族（竖条/钮/徽标同族）

## 验收
黑话测试：新人看列表 5 秒内说出「哪几台现在能连、哪台正在被用」。
