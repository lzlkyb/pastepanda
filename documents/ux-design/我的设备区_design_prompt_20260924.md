# 实施 Prompt · 「我的设备」区域重规划

2026-09-24 · ui-designer 流程 Step 4 产物（{项目设计指南}=documents/designs/我的设备区_design_system.md；{项目MVP PRD}=documents/prd/我的设备区.md）

## 介质适配声明（覆盖模板默认）
本项目是 Tauri + React + CSS Modules 存量应用，**不用** create-react-app / Tailwind / lucide 新建工程。
按项目规则 4/12/13：产出物是 `design/` 下的 **HTML 对比设计稿**（沿用 A 稿 :root token 与 .dev 行体系），
用户选定变体后再以 CSS Modules + 真实组件落地（≤300 行/文件，规则 7）。

## 设计美学原则（从设计系统提炼）
1. 层级靠 留白 > 背景对比 > 边框；边框是最后一手（V1）——行不用描边堆叠，选中用「左缘 3px 蓝竖条 + 白底」。
2. 一屏一个强调色（V3）：`--blue/--blue-deep` 家族 = 可连接性（竖条、连接钮、活会话徽标同族）；
   ok 绿只给状态点，warn 橙只给暂时性异常，err 红只给错误行。
3. 状态说人话：文案全部来自 `rcDeviceStatus()` 单源，不学 UU 纯视觉点；
   离线灰由**新增显式 `offline` 字段**驱动（`unknown` ≠ 离线），落地配守卫单测（规则 11.1）。
4. 行密度：两行式（名字 12px/600 + meta 10px），行高 ~46px；分组标题 10.5px/700 灰 + 计数。
5. 反馈与触发同可见性域（规则 15.1）：进行中的会话必须在**行上**有徽标（连接中… / 被控中），
   标题栏横幅负责总量、行徽标负责定位是哪台。

## 任务
在同一页里出 **3 个变体**（同一批设备数据、同一 token 表，只差组织形态）：
- 变体 A · 单列表在线优先：不分组，在线排前、离线沉底灰；改动最小。
- 变体 B · 显式分组：「在线 · 2」/「离线 · 1」组标题；离线组可折叠（默认展开）；行结构同 A。
- 变体 C · 紧凑单行：行高 30px，名字 + 点 + 行尾钮一行排，meta 进 title 悬浮——
  **标注其 L1/L6 风险**（状态文字不常驻），仅供对照，不默认推荐。
每变体附：选中态、连接中徽标、离线灰、hover 态；稿尾给对比表（扫读效率/设备数扩展/实现成本/风险）与推荐。

## 验收
黑话测试（PRD）：新人 5 秒说出哪几台能连、哪台正在被用；lint:ui 可判定项预检（U5 刻度/U6 语义色/V3 单强调色）。
